# EXP-2026-11-20-M5.49: P1 — one contained factory tile copied verbatim into a card

- **Status:** done (L1 `cardcheck --root` and `cardcheck --image` PASS; the patched
  card is byte-identical to the factory image; not read by the unit, rule 13)
- **Date:** 2026-11-20
- **Sample:** EU 2011 image
  `archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img`, SHA-256
  `105e2032e480e8ba162a2a9d4b6624cb1dafee380379a9908f3f101b15076307`
  (8,057,257,984 B). The factory root is
  `~/projekty/leafre-work/m5.29-factory-root` (480 files); its P1 tile
  `MAPAL001/B48R058R.DAT` is 289,319,168 B, SHA-256
  `e9c9cb2236f6b53ad4fe9687a18a351afe80a46a63c0a1f18dc46d6c8af3ff52`, and its
  `DRSTR001.DAT` is 11,968 B, SHA-256
  `2b7f2fb8901bf18a2ad48334154a6d604c23a775083cb84754626d64417b25f6`.
- **Tools:** Python 3.15.0 (`zlib 1.3.1.zlib-ng`; no recompression happens in
  this task — the tile is copied byte for byte, so the zlib-ng caveat does not
  apply). Repo tools: `tools/one_tile_pipeline.py` (this branch: the new
  `--preserve-tile MESHTAG` mode), `tools/rebuild_manifests.py`,
  `tools/cardcheck.py`, `tools/imgpatch.py`, `tools/mesh_grid.py` (Precheck),
  `tools/selftest.py`, `tools/gate.py`, `tools/claims_check.py`. `7z` 26.04
  (`/usr/bin/7z`) for the independent archive check on the P0 card only.
- **Claims:** C-5380–C-5389
- **Supersedes:** none (answers the P1 rung that EXP-2026-11-18-M5.46
  (containment) and EXP-2026-11-19-M5.30 (one-variable card) set up)
- **Superseded by:** none

## Question

Can P1 — the single contained factory tile `B48R058R` copied **verbatim**
(no OSM ingest, no `tilewriter`, tile delta 0) — become a card whose only diff
from the factory image is that tile (and, because the tile does not move, in
practice nothing), passing `cardcheck --root` and `cardcheck --image`, and
which display-only checks does it deliberately skip?

## Hypothesis

The tile is the factory file; `rebuild_manifests` regenerates the directory
entries from the copied tree. On a factory root that rebuild is a no-op
(the entries already describe the factory tile), so the P1 tree is
**byte-identical** to the factory root and the patched image is byte-identical
to the factory image. The relocation work M5.30 did for a +138,994 B tile does
not apply here: the tile size and cluster chain do not change.

**Falsifier:** the P1 tree reports 480 files but `cardcheck --image` on the
patched copy fails, or the diff touches any cluster outside
`DRSTR001.DAT`/its directory entry and the tile (the tile's clusters must be
identical to factory), or the whole-tree diff against the factory root is not
empty on the pristine factory root.

## Method

1. **Sample and hash.** Image, factory tile and `DRSTR001.DAT` hashed above.
   The factory root contributes `MAPAL001/B48R058R.DAT`, `DRSTR001.DAT`,
   `MMAIN001.DAT`, `VER_INFO/HDD_INFO.TXT` and the 194 `REFER001` pairs.

2. **Commands.** Run from the repository root. `S` is a scratch directory
   outside the repo; `FAC` the factory root. `--preserve-tile` reads the
   factory root from `--factory-root` or `$OSM2LEAF_FACTORY_ROOT`.

```bash
FAC=$HOME/projekty/leafre-work/m5.29-factory-root
IMG=archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img
S=$HOME/projekty/leafre-work/scratch/m5.49
mkdir -p $S/tmp; export TMPDIR=$S/tmp

# Precheck: containment census, factory root, and the verbatim tile's delta-0.
python3 tools/mesh_grid.py cover profiles/dolnoslaskie-test.json $FAC/MAPAL001 | tail -1
python3 tools/cardcheck.py --root $FAC --fast | tail -1
python3 tools/imgpatch.py --image $IMG --file MAPAL001/B48R058R.DAT \
  --from $FAC/MAPAL001/B48R058R.DAT --allow-resize --dry-run --json \
  | python3 -c "import sys,json;d=json.load(sys.stdin);print(d['old_size'],d['new_size'],d['start_cluster_before'],d['clusters_before'],d['extra_clusters'])"

# The P1 tree (this task's new flag), then count the files.
python3 tools/one_tile_pipeline.py --preserve-tile B48R058R --factory-root $FAC \
  --out $S/p1 --json $S/p1-report.json
find $S/p1 -type f | wc -l
python3 tools/cardcheck.py --root $S/p1

# The card: copy the factory image, patch tile then manifest (M5.30 recipe).
cp $IMG $S/p1.img
python3 tools/imgpatch.py --image $S/p1.img --file MAPAL001/B48R058R.DAT \
  --from $S/p1/MAPAL001/B48R058R.DAT --json > $S/patch-tile.json
python3 tools/imgpatch.py --image $S/p1.img --file DRSTR001.DAT \
  --from $S/p1/DRSTR001.DAT --json > $S/patch-drstr.json
python3 tools/imgpatch.py --check-diff --image $S/p1.img --reference $IMG \
  --file MAPAL001/B48R058R.DAT --file DRSTR001.DAT --allow-metadata
python3 tools/cardcheck.py --image $S/p1.img
cmp $S/p1.img $IMG && echo "card_byte_identical_to_factory=YES"
```

3. **Controls.**
   - *Positive (the flag exists):*
     `python3 tools/one_tile_pipeline.py --help | grep -c '^  --preserve-tile MESHTAG'`
     prints `1` (M5.50's EXP asserted `0` before this task and handed the row to
     M5.49; C-5389). The report's `tile_delta` is `0` and
     `tile_sha256_matches_factory` is `true` (C-5380).
   - *Positive (the card):* the dry run on the factory tile is a delta-0
     no-op — same size, same start cluster, no extra clusters (C-5385); the
     patched card is byte-identical to the factory image and `--check-diff`
     reports `0 range(s)` (C-5383); `cardcheck --image` PASS (C-5384).
   - *Negative (a missing cell):* `--preserve-tile B48R059R` is refused with
     `real_image_run=blocked`, exit 1, and no `--out` left behind (C-5387).
   - *Negative (the zero diff is not vacuous):* flipping the last byte of a
     copy of the P1 tile makes the tree diff name exactly
     `MAPAL001/B48R058R.DAT`; patched onto the image it becomes
     `diffs: 1 range(s)` while the untouched P1 card reports `0` (C-5388). So
     "0 ranges" is a measured result, not a check that cannot fail.
   - *Self-test:* `tools/one_tile_pipeline.py --selftest` covers the same
     positive and both negatives on a synthetic factory root
     (`_preserve_fixture_root`), and `tools/selftest.py` is green (C-5380).

4. **Scope.** The 480-file card tree and the map partition of one EU 2011
   image: the tile and its directory entry are the factory bytes, so the
   patched image writes nothing. Excluded: OSM ingest and `tilewriter` (P1 is
   display-only, no generated road), section 2/4 generation, routing, names,
   and firmware acceptance (rule 13). L5 (car/bench) is the final oracle and is
   not run.

5. **Falsifier.** Stated in the Hypothesis, before the result.

The gates P1 must pass and does: `tile_roundtrip_structure` PASS (tile sha

### 5. `l2check` is run, not assumed — and it fails on a pre-existing regression

`map_signals.card_step` prints P0 from `cardcheck_ok and l2check_ok`, so a bare
`l2check_ok: true` would be a false P0. The P1 path runs the targeted command
on the real tree and reports the result:

```text
$ python3 tools/l2check.py --root $S/p1 --no-golden \
    --tiles B48R058R.DAT --semantic-tiles B48R058R.DAT --cmp-limit 20
  [tile_roundtrip] OK …  [tile_semantic] OK …  [tile_mutation] OK …
  [refer_mutation] OK …
  [refer_rename_resize] FAIL (file=POINT032.DAT; … got 84 bytes, expected 84)
RESULT: FAIL                                                    # rc=1
$ python3 -c 'import json;r=json.load(open("$S/p1b-report.json"));print(r["l2check_ok"],r["counts"]["l2check_rc"],r["counts"]["l2check_tile_checked"])'
False 1 True
```

So `p1-report.json` carries `l2check_ok=false` with `counts.l2check_rc=1` and
`counts.l2check_tile_checked=true`. This is the pre-existing M5.52
`refer_rename_resize` regression (C-5543, filed M5.55), which fails on the
untouched factory root identically (`l2check_ok=false` is the honest value, not
a P1 defect); the tile gates above are unaffected. A synthetic fixture root is
not a card, so the report there is `l2check_ok: null` with
`l2check_partial: true` and a `l2check_not_run` reason — never a bare `true`.

## Interpretation

- **FACT:** `--preserve-tile MESHTAG` builds a 480-file P1 tree whose tile is
  the factory file byte for byte (`counts.tile_size=289319168`,
  `sha256_matches_factory=true`, `tree_diff.differing_files=[]`); the P1 tree
  passes `cardcheck --root`.
- **FACT:** Patching the factory image copy with that tree is a delta-0
  operation: the tile keeps size, start cluster and chain, the manifest is
  unchanged, and `$S/p1.img` is byte-identical to `$IMG`
  (`105e2032…76307`); `--check-diff` reports `0 range(s)`, `cardcheck --image`
  PASS.
- **OBSERVED:** the display-only rung passes the L1/structural and manifest
  gates and deliberately leaves routing/class/names/firmware as
  NOT-APPLICABLE/CANNOT-VERIFY-OFFLINE; the split is in the report and in §4.
- **FACT (honest negative):** the real P1 report carries
  `l2check_ok=false` / `counts.l2check_rc=1` with `l2check_tile_checked=true`
  — the full `l2check` command is run, not assumed, and it fails only on the
  pre-existing M5.52 `refer_rename_resize` regression (C-5543/M5.55), which
  fails identically on the untouched factory root. The tile gates
  (`tile_roundtrip_structure`, `section4`, `manifests`,
  `drstr_mmain_cmplst_ind`) all PASS, so P1's own claim does not depend on it;
  a synthetic fixture reports `l2check_ok=null` / `l2check_partial=true`
  (not-run), never a bare `true` (§5).
- **HYPOTHESIS:** the same delta-0 property holds for every contained tile the
  profile selects while its factory file is on the root; P1 is a `contained=1`
  region today, so the single-tile copy is the whole rung.
- **UNKNOWN:** whether the unit displays the card (L5, rule 13) — nothing here
  runs the firmware.

## Conclusion

P1 is a card that is the factory image to the byte: `one_tile_pipeline
--preserve-tile B48R058R` copies the contained factory tile verbatim (delta 0,
no `tilewriter`, none of M5.30's relocation), rebuilds only the directory
entries (a no-op on a factory root), and produces a 480-file tree that passes
`cardcheck --root`; patched onto a copy of the factory image it passes
`check-diff` with `0 range(s)` and `cardcheck --image`, and the card is
byte-identical to factory. The display-only/routing split is recorded (routing
and names are M5.16/M5.36/M5.37/M4.36, firmware is L5). The Falsifier did not
fire. The `docs/format/card-ladder.md` P1 rows are now runnable and green; its
P0 `l2check` row still fails on the pre-existing M5.52 `refer_rename_resize`
regression (C-5543, filed M5.55), which fails on the untouched factory root
too and is outside this task.
