## Question

Can a one-vertex geometry edit be applied to a US tile (B18R100R, Hawaii/Maui area) on the proven M4.4 in-place path — preserving section 4 and file size, passing tile checks — and can the result be written as S3 via `imgpatch.py` with diffs only in that tile's clusters/dir entry?

## Hypothesis

Following M4.4 (mutate one vertex inside its parcel, rebuild the background record, recompress with zlib level 9, NUL-pad to the original compressed stream length, patch only those bytes): `tile_diff.py` shows exactly 1 changed stream (that vertex), section 4 stays byte-identical, `harness.py verify` passes, and `imgpatch.py` produces S3 whose image diff lies only in `MAPAL001/B18R100R.DAT` clusters and its directory entry. **Falsifier:** any second changed/moved stream in `tile_diff`, a section-4 hash change, a `harness verify`/`cardcheck` failure, or any `check-diff` range outside the tile's clusters/dir entry.

## Method

1. **Sample and hash.** Factory US image and derived artifacts as in Sample (outside repo). Tile `B18R100R.DAT` covers 16.0–21.333°N, 156.0–148.0°W (east Maui/Hawaii; `coord.py cell 20.7564 -155.9881` → `B18R100R`).
2. **Commands.** Target selection and patch (M4.4 in-place method, reproduces `/tmp/m5_14_patch.py`):
   ```bash
   # identify tile for Hana, Maui (recognisable S2 area)
   python3 tools/coord.py cell 20.7564 -155.9881
   # -> B18R100R (16.0–21.333°N, -156.0–-148.0°E)

   # patch: dir (30,65280) row 8 slot 8 rec k=17, layer 8 shape 1 vertex 2
   # (1851,52) -> (1891,52), dx=+40,dy=0; rebuild with clarion_bg (strict),
   # zlib.compress(...,9), word-pad, NUL-pad to original compressed length 288,
   # overwrite only bytes at 0x1150c0..0x1151e0 in a copy of the original tile.
   python3 /tmp/m5_14_patch.py
   # old (1851,52)->(1891,52) plain 420->420 comp 288->286, sec4 same True (484),
   # diff bytes 117, size same True

   # tile checks
   cd tools/ze0-viewer && python3 harness.py verify \
     /home/marek/projekty/leafre-work/m5.14/B18R100R-patched.DAT
   cd /home/marek/projekty/OSM2Leaf-wt-M5.14
   python3 tools/tile_diff.py \
     /home/marek/projekty/leafre-work/m5.12-us/root-factory/MAPAL001/B18R100R.DAT \
     /home/marek/projekty/leafre-work/m5.14/B18R100R-patched.DAT

   # S3 image
   python3 tools/imgpatch.py \
     --image /home/marek/projekty/OSM2Leaf/archive/sd-images/LEAF_2011-2012_US.img \
     --file MAPAL001/B18R100R.DAT \
     --from /home/marek/projekty/leafre-work/m5.14/B18R100R-patched.DAT \
     -o /home/marek/projekty/leafre-work/m5.14/us_S3.img --allow-resize --json
   python3 tools/cardcheck.py --image /home/marek/projekty/leafre-work/m5.14/us_S3.img
   python3 tools/imgpatch.py --check-diff \
     --image /home/marek/projekty/leafre-work/m5.14/us_S3.img \
     --reference /home/marek/projekty/OSM2Leaf/archive/sd-images/LEAF_2011-2012_US.img \
     --file MAPAL001/B18R100R.DAT --json
   ```
3. **Controls.** *Positive:* factory B18R100R passes `harness.py verify` (byte-identical rebuild OK, 5730 records ok, 3757 background rebuild ok, roundtrip OK) — recorded before patching; `tile_diff` factory vs factory = IDENTICAL by construction. *Negative:* a compressed stream that does not fit its original length is refused by the patch script (`COMP TOO BIG`, exit 1) — exercised by the length check (resulting comp 286 ≤ 288, so the positive path ran; the guard is the negative control logic).
4. **Scope.** One US tile `B18R100R.DAT` (1,994,496 B, 5730 streams, sec1 level 1 edit) in the US 2011 factory image. One vertex moved (+40,0 in the record's local 0–2047 point space) in one background geometry record. Section 4 (484 zlib payloads) preserved verbatim. No OSM ingest, no road-name extraction, no other tile/file changed. The moved segment is a background geometry segment (layer 8, shape 1) — its road-name partner record was not resolved (M4.4 path edits the odd geometry record; road names come from the partner names section and are out of scope).
5. **Falsifier.** Stated above and before the run: any content change beyond that one vertex, any section-4 byte change, any harness/cardcheck/check-diff failure, or a diff outside the tile's clusters/dir entry refutes the claim.
