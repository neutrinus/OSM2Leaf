## Question

How many `MAPAL001` `BxxRyyR` tiles a Dolnośląskie P1 card needs, which of
them cover the whole region, and what the same census says for `poland-full`?

## Hypothesis

`profiles/dolnoslaskie-test.json` (`region.bbox [14.0, 49.9, 17.9, 51.9]`)
selects exactly one tile, `B48R058R` (`48.00..53.33 N, 12.00..20.00 E`),
because that one factory tile already covers the whole voivodeship; the P1
card is that tile copied verbatim, no edge tile. `poland-full`
(`[14.12, 49.0, 24.15, 54.84]`) selects four tiles, all edge tiles, because
no single 8° × 5.333° tile covers Poland.

**Falsifier:** the census selects a tile whose `mesh_grid.py cell` box does not
touch the profile bbox, or reports P0's tile as anything but `contained`.

## Method

1. **Sample and hash.** No vendor sample; the two profiles hashed above. The
   factory directory contributes tile **names** only (`collect()` globs
   `B*R*R.DAT`).

2. **Commands.** Runnable as written from the repo root:

   ```bash
   python3 tools/mesh_grid.py cover profiles/dolnoslaskie-test.json \
       /home/marek/projekty/leafre-work/m5.29-factory-root/MAPAL001
   python3 tools/mesh_grid.py cover profiles/dolnoslaskie-test.json
   python3 tools/mesh_grid.py cover profiles/poland-full.json \
       /home/marek/projekty/leafre-work/m5.29-factory-root/MAPAL001
   python3 tools/mesh_grid.py --selftest
   python3 tools/selftest.py --only mesh_grid
   ```

   The first argument is the profile; the optional second is the factory
   `MAPAL001` directory, which only sets the `factory` column (present as a
   file / not). Without it the census still runs (the 63-cell lattice is the
   universe, not the 45 shipped files), printing `factory_tiles=0`.

3. **Controls.**
   - **Positive:** `profiles/dolnoslaskie-test.json` must select `B48R058R` and
     only `B48R058R` as `contained`; the run prints `contained=1` and the one
     non-`outside` row is `B48R058R`.
   - **Negative:** a box in the Atlantic (`[-30, 30, -20, 40]`) selects nothing
     — `--selftest` asserts `contained=0 intersects=0` and
     `outside == lattice` (63).
   - **Edge:** a box `[15.0, 50.0, 21.0, 51.0]` (crossing `B48R058R`'s `20°E`
     edge into `B48R050R`) makes `B48R058R` `intersects`, not `contained`, and
     `contained=0` — `--selftest`.
   - **Missing field:** a profile with no `region.bbox` exits 1 with
     `profile has no region.bbox` (never a guessed box).

4. **Scope.** Two shipped profiles (`dolnoslaskie-test`, `poland-full`) against
   the 63-cell EU lattice (`B28..B68` × `R048..R078`), plus the 45-file factory
   inventory for the `factory` column. Excluded: `europe-motorways.json` and
   `dolnoslaskie-detail.json` (not named by the task; `dolnoslaskie-detail`
   was run once as a spot check and gives the same `contained=1` as the test
   profile). No tile bytes, no OSM extract, no image.

5. **Falsifier.** Stated in the Hypothesis: a selected tile that does not
   touch the bbox, or `B48R058R` not `contained`, would refute it.

## Interpretation

- **FACT:** For `dolnoslaskie-test` (`14.0–17.9 E, 49.9–51.9 N`), exactly one
  lattice tile — `B48R058R` (`48.00..53.33 N, 12.00..20.00 E`) — has the
  region box inside it; the other 62 are `outside`. There is **no edge tile**
  at this profile's 0.09° buffer: `intersects=0`.
- **FACT:** For `poland-full`, no tile contains the whole region
  (`contained=0`); four tiles are `intersects` (`B48R050R`, `B48R058R`,
  `B50R050R`, `B50R058R`), the same four `profile_validate.resolve_tiles`
  selects and `profiles/README.md` lists.
- **OBSERVED:** All four `poland-full` tiles exist as factory files
  (`factory yes`), so a P1-style whole-tile Dolnośląskie card is a **copy**
  of `B48R058R`, not a splice.
- **HYPOTHESIS:** For a larger region every non-`contained` selected tile is
  a fresh splice (or a factory copy if unchanged), which is what M7.1's file
  count and size budget would multiply — stated as a hypothesis because this
  task enumerates, it does not write.
- **UNKNOWN:** whether the firmware accepts a partly-populated edge tile
  (`map-tiles.md` key question 6, still open).
- **DECISION (semantics of `contained`):** the block's `Hints` line reads "a
  tile is `contained` when its box lies inside bbox ± `border_buffer_deg`",
  which would make the P0 tile an *edge* tile (`B48R058R` is far larger than
  the region box) and make every `poland-full` tile `outside` — that reading
  contradicts the `Done when` line, which requires `contained=1` for
  `B48R058R`. I implemented the direction the `Done when` requires: a tile is
  `contained` when the **whole region box lies inside the tile**, and the
  buffer only widens the overlap test that yields `intersects`. Rejected
  alternative: treating the buffered box as the containment target (it flips
  the DS answer to `contained=0`, which would be a P1 card of one *spliced*
  tile — the opposite of "one whole factory tile"). A navigator should
  confirm or overrule this reading.

## Conclusion

`mesh_grid.py cover` is a read-only census that quotes its own numbers. It
confirms the Done-when: the repeated census on `profiles/dolnoslaskie-test.json`
prints `contained=1` (`B48R058R`) and `intersects=0`, so the P1 Dolnośląskie
card is **one whole factory tile, copied verbatim** — P0's tile is already the
whole region for this profile. `poland-full` needs four tiles, all edge tiles.
The census moved from a hand bbox test in `docs/format/map-tiles.md` to a
reproducible subcommand; that paragraph now cites the command. Nothing is
written to a tile and no OSM data is read.
