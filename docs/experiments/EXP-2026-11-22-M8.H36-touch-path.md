- **Status:** done

## Question

In the EU2011 unit, which code path carries a finger tap from the panel to the
UI, what is one sample's format, how are coordinates mapped to the 800×480
screen, and where is the cheapest emulator injection point?

## Hypothesis

The candidate in row M8.C20 "display-unit frames on `SCI3:`" is true:
`lcddrv.dll` decodes them and `kepdrv.dll` posts mouse messages to the UI;
the CE `TouchPanel` DDI, an ADC in `kepdrv`, and the audio microcontroller are
not the touch source. **Falsifier:** no code path delivers coordinates to a UI
process, or the `SCI3:` frames carry only brightness/status while touch comes
from a CE touch driver or a USB HID digitizer.

## Interpretation

- **FACT:** Touch samples reach the UI from the display unit over `SCI3:`, via
  `lcddrv.dll` → `EVENT_LCD_TOUCH_KEY` + `LCD1:` IOCTL `0x800b205c` →
  `kepdrv.dll` → `PostMessageW` of `WM_MOUSEMOVE`/`WM_LBUTTONDOWN`/
  `WM_LBUTTONUP`. Every hop has a VA in `docs/firmware/touch.md`.
- **FACT:** One decoded sample is 6 bytes: `u16 x`, `u16 y`, `u8 status`
  (ASCII `'0'` = up, `'1'` = down), `u8 unused`. Status other than `'0'`/`'1'`
  takes an error branch.
- **FACT:** Coordinates are clamped to 800/480, normalised to 16.16, Y-flipped
  and multiplied by calibration factors whose defaults are exactly 800 and
  480; the UI receives `lParam = (y_px<<16)|x_px`.
- **FACT:** Row M8.C20 candidate "display-unit frames on `SCI3:`" is the
  correct one. The stock CE `TouchPanel`/`touch.dll` path is present as code
  in `gwes.exe` but unconfigured (no registry key, no DLL in ROM).
- **OBSERVED:** `kepdrv.dll` also imports `mouse_event`, but no call site was
  found in its code; message injection, not `mouse_event`, is what the
  decoded path uses.
- **HYPOTHESIS:** the 6-byte block copied at `0x03a066c0` is the payload of
  the touch command (the size and field layout match the IOCTL output); the
  command byte and full SCI3 frame grammar are M8.H35's scope.
- **UNKNOWN:** runtime source of the calibration factors; SCI3 command number
  and checksum; the AUI HWND value at run time (readable with a breakpoint on
  `0x03a1b154` during M8.H39).

## Conclusion

`docs/firmware/touch.md` now carries the complete chain with VAs, the 6-byte
sample, the 800×480 mapping, press/release/drag semantics, the rejection of
the CE DDI path, and two emulator injection points (message level at
`PostMessageW`, device level at `IOCTL 0x800b205c` + `EVENT_LCD_TOUCH_KEY`).
Claims C-7330–C-7339 record the individual facts. No L3/L4 run was done — the
task is a static reader task, and L4 injection is M8.H39.
