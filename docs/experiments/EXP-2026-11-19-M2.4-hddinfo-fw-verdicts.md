## Question

For each of the 89 length-preserving `HDD_INFO.TXT` variants of the EU 2011
factory file, what does the firmware's own map-code compare (`AppLaunch.dll`
`fn 0x03bd2ad8`, EU2011 build B, check 1 / error `0x50`) return, and does it
agree with `tools/hddinfo.py classify` check 1?

## Hypothesis

The M2.15 model says check 1 is an 11-byte equality of line-1 bytes 0..10 with
the unit record `+0x60`, so the firmware should give 69 ACCEPT / 20 REJECT,
exactly the `classify` split (C-2086): REJECT for the 14 line-1 edits, the 5
swaps that move another line into line 1 and `reverse`; ACCEPT for the rest.
The legacy M0 numbers (66 ACCEPT / 23 DIFFERENT, C-751) should not match.

**Falsifier:** any variant where the firmware verdict differs from the model
check-1 verdict; or the factory control not ACCEPT; or the no-file control not
REJECT; or any run BLOCKED. Each of these fails the run (`hddinfo_fw_matrix.py
run` exits 1 or 4).

| Image | `archive/head256.img`, SHA-256 `92aa525d…a007f9` |

## Method

### 1. Sample and hash

`sha256sum archive/head256.img` → `92aa525d…a007f9`. The factory file is
taken from the card FAT by `mapcode_l3.py extract`, which prints its hash.

### 2. Commands

```bash
W=/home/user/OSM2Leaf.task-m2.4-hdd-info-predict
S=/home/user/scratch/m2.4
CARD=/home/user/OSM2Leaf/archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img
IMG=$W/archive/head256.img
mkdir -p $S
sha256sum $IMG
python3 $W/tools/mapcode_l3.py extract $CARD -o $S/HDD_INFO.TXT
python3 $W/tools/hddinfo_variants.py $S/HDD_INFO.TXT $S/variants

# done-when: firmware verdict for each of the 89 variants vs hddinfo.py classify
python3 $W/tools/hddinfo_fw_matrix.py run $IMG $S/HDD_INFO.TXT $S/variants --tsv $S/m2.4-fw.tsv

# cross-check one row through the registered target (same code path as M9.6)
python3 $W/tools/l3_harness/runner.py run applaunch_mapcode_compare --image $IMG \
  --input $S/variants/swap_1_5.HDD_INFO.TXT --unit-from $S/HDD_INFO.TXT --expect REJECT
python3 $W/tools/l3_harness/runner.py run applaunch_mapcode_compare --image $IMG \
  --input $S/variants/swap_2_3.HDD_INFO.TXT --unit-from $S/HDD_INFO.TXT --expect ACCEPT

# edge probes (parser cases the 89 do not cover)
python3 $W/tools/hddinfo_fw_matrix.py edges $S/HDD_INFO.TXT $S/edges
python3 $W/tools/hddinfo_fw_matrix.py run $IMG $S/HDD_INFO.TXT $S/edges --tsv $S/m2.4-edges.tsv

# offline model alone (C-2086 numbers)
python3 $W/tools/hddinfo.py matrix $S/HDD_INFO.TXT $S/mtx

python3 $W/tools/hddinfo_fw_matrix.py --selftest
python3 $W/tools/mapcode_l3.py --selftest
```

`hddinfo_fw_matrix.py run` reads the image once, resolves the 8 import thunks
once (`mapcode_l3.resolve_thunks`), and calls `mapcode_l3.run_compare` per
variant, i.e. the same function `runner.py run applaunch_mapcode_compare`
calls. For each file it also runs `hddinfo.classify` check 1 with the factory
file as `sys`, maps `PASS`→`ACCEPT` and `DIFFERENT MAP CODE`→`REJECT`, and
records agreement.

### 3. Controls

- **Positive:** the factory file in every run must be ACCEPT (`control
  factory`).
- **Negative:** no file served (`CreateFileW` fails) must be REJECT (`control
  no_file`, C-5143).
- **The comparison can fail:** in the self-test a fake "firmware" that
  compares line 2 instead of line 1 produces 2 disagreements and
  `matrix_ok=False`, and an accept-everything fake fails the no-file control.
  The edge-probe run below is a real-image run in which the comparison does
  report disagreements (exit 1).

### 4. Scope

One function (`fn 0x03bd2ad8`, check 1, error `0x50`) of one module in one
build (EU2011 build B); 89 variants + 2 controls + 10 edge probes = 101
firmware runs on IMG256. Not covered: check 2 (`fn 0x03bd2ce4`, `0x51`,
MapDBVer range; needs the unit bounds `+112/+114`), the router
`fn 0x03bd2ecc`, the cached second-call path, build C (`0x03bb2858`), the US
build (different `AppLaunch.dll`, H51), and the `Navi.exe` reader
`0x004e7b8c`. A firmware ACCEPT here means "passes check 1", not "the unit
accepts the card".

### 5. Falsifier

Stated before the results (Hypothesis).

## Interpretation

- **FACT (C-5290):** on the 89 length-preserving variants the firmware check 1
  (`fn 0x03bd2ad8`, EU2011 build B) gives 69 ACCEPT / 20 REJECT, and agrees
  with `hddinfo.py classify` check 1 on all 89 (69/69 ACCEPT, 20/20 REJECT).
  The M2.15 model of check 1 is confirmed by execution on the whole corpus.
- **FACT (C-5291):** the legacy M0 counts (66 ACCEPT / 23 DIFFERENT, C-751)
  do not match the firmware (69/20); the M2.15 counts (C-2086, C-3033) do.
  M0 is refuted as a predictor of check 1.
- **FACT (C-5292):** the line is matched by position, not by content: every
  permutation that keeps line 1 in place passes (10/10), every one that moves
  it fails (6/6, including `reverse`). Lines 2–6 never influence check 1.
- **OBSERVED (C-5293):** the runs are consistent with a byte-exact,
  case-sensitive compare of bytes 0..10 only (10 probes + 14 line-1 edits): characters after byte 10 (up to 21-char line 1) and trailing
  spaces do not matter; lower case, a leading space and a UTF-8 BOM fail. A
  generator must write line 1 as plain ASCII without a BOM.
- **OBSERVED (C-5294):** check 1 does not need CRLF or six lines: an LF-only
  file and an 11-byte line-1-only file pass. `hddinfo.py` refuses both
  (`PARSE_ERROR`), so the model is stricter than check 1 there. Other readers
  (the `Navi.exe` reader `0x004e7b8c`, check 2) may still need the full form;
  this is not tested here.
- **HYPOTHESIS (C-5146, unchanged):** a real EU 2011 unit returns
  `QSD-302-100` at `+0x60`. All verdicts are relative to that declared unit
  record.
- **UNKNOWN:** check 2 (`0x51`); 12 of the 89 variants change MapDBVer
  (C-3034), so their full accept/reject is still open. New task M2.19.

## Conclusion

M2.4's done-when holds: each of the 89 variants has a firmware verdict from
`fn 0x03bd2ad8` and it is compared with `hddinfo.py classify`; they agree on
89/89 (C-5290). `reader-coverage.md` row 23 now cites the 89-variant run.
Check 2 remains unrun; M2.19 is added for it. `hddinfo.py` is unchanged: its
stricter parse is safe for a writer, and the difference is recorded
(C-5294) rather than "fixed".
