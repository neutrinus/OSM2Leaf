## Question

Which VAs in build A are the LCTBL001 record walker and the name-string decoder,
and what encoding does the code assume (M3.15 done-when)?

## Hypothesis

Starting from the verified descriptor switch `fn 0x004125a8` (C-880, C-2122),
the walker and decoder are reachable by static calls in decodable (plain)
sections, and the code contains the inflate table of the zlib streams that
LCTBL uses (C-100, C-1830).

Falsifier: the walker or decoder is found by a static call or a literal-pool
load from plain code, with its body in plain bytes. Equally, a zlib inflate length
table found in plain bytes would give a decoder VA. Either observation would
confirm the hypothesis; both absent is the negative reported here.

## Method

2. **Commands.** Runnable as written from the repo root:

```bash

    --va 0x004125a8 0x0017a1f8 0x0055d924 0x0055d954 0x003bc960 \
    --expect-ascii 0x0017a1f8 LCTBL001.DAT
python3 tools/lctbl_probe.py $IMG --image-start 0x200200 --scan-inflate
```

3. **Controls.** *Positive, mapping:* `LCTBL001.DAT` is expected at the VA
   from C-880 (`0x0017a1f8`); the probe must find those bytes in plain sections
   (`--expect-ascii`). A wrong mapping gives MISMATCH. *Positive, scan:* the
   selftest plants the 29-entry table in a synthetic buffer and must find it at
   the planted offset. *Negative, scan:* unrelated bytes give no hit; the
   big-endian layout must not match (LE-only decoder assumption, AGENTS). *Negative,
   classification:* a VA outside all sections gives no section.
   The real-bytes scan has no known-present positive control; the synthetic
   control is the only check that the scan can succeed. This is stated as a limit.
4. **Scope.** IMG256 covers the first 256 MiB, which holds the whole CE image
   (image start `0x200200`, physlast `0x8e233c88`). Modules: 149 (all of
   `cerom.py modules`). Sections: 527 total, 282 plain (133 uncompressed data +
   149 uncompressed code, 23,559,542 plain bytes), 245 compressed (30,212,810
   vsize). Excluded: compressed sections, which the scan cannot read (rule 14;
   the sec1 call targets below are inside one). The `Navi.exe` sec0 map is
   decodable; sec1 and sec2 are compressed.
5. **Falsifier.** Stated above. The hypothesis fails if no walker/decoder is
   reached from plain bytes and no inflate table is in plain bytes.

## Interpretation

- **FACT:** The LCTBL001 descriptor `fn 0x004125a8` and the file name
  `LCTBL001.DAT` (ASCII, VA `0x0017a1f8`) are in plain bytes; the mapping
  checks out against the positive control.
- **OBSERVED:** The descriptor switch and the TMC record decoder both call
  into `Navi.exe` sec1 at `0x0055d924` and `0x0055d954`. Sec1 is COMPRESSED and
  its section flags lack the MEM_EXECUTE bit (`0x20000000`). The callee bodies are
  unread. Many functions share these callees (29 and 663 load sites). The two
  call targets are shared helpers, not stubs of one walker.
- **OBSERVED:** No zlib inflate length-base table is in plain bytes of any of
  the 149 modules (282 sections, 23.56 MB). This does not rule out a decoder in
  compressed sec1.
- **HYPOTHESIS:** The LCTBL record walker and string decoder live in compressed
  `Navi.exe` sec1 (or another compressed section), and are reached through the
  shared helpers above. This matches why M3.11 and M3.2b found no reader in
  decodable code.
- **UNKNOWN:** The record-walk VA, the string-decode VA, and whether the name
  encoding is decided in code (C-1799 gives CP1252/Latin-1 from the bytes). Done
  when needs these VAs.

Precheck verdict under rule 14: the target is in compressed bytes. The M3.15
walk cannot be placed in decodable code, so the task is blocked on M1.2f (the
`DECOMP_BLK` port), which makes sec1 readable. This also corrects the rule-14
premise that compressed sections hold only data: the LCTBL open path calls
into sec1 (C-2206).

## Conclusion

No record-walk or string-decode VA is named; `docs/research/claims.md` gets
C-2200–C-2206 (the sec1 call edges, the zlib table negative, the mapping control,
and the blocked done-when). `docs/format/rdstm.md` gets the descriptor and
helper VAs. M3.15 is `Status: blocked`, `Unblock: M1.2f`. The done-when is not
met, so no `[x]`. Open: the sec1 bytes (M1.2f) and the LCTBL decoder VA.
