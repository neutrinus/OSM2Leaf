## Question

Does the KIWI Road Data Frame (chapter 7.2: distribution header, display-class management records, multilink header, road type) describe the even (road) records of ZE0 tile section 1 on EU2011 and US2011, and can it name the road class codes our writer currently treats as provisional?

## Hypothesis

Given M4.63's "common concepts, different container" verdict and M4.70's negative for the background frame, the expected result is negative; the prior `class_code` remains a hypothesis (C-1825). **Falsifier:** a real road record whose `SWS(u16@0)` header length is inside the record, whose display-class offsets point inside it, and whose multilink headers satisfy the KIWI size/road-type fields — on both cards.

3. **Controls.** *Positive:* a synthetic KIWI 7.2 frame built from the quoted field lists (header + 1 display class + 1 multilink with road type 3) returns `fit`; three mutations (header size out of range, display offset outside the block, road type 9 outside KIWI's 0..7) are rejected. *Negative:* the 6,000 real records must return 0 fits. *Prior control:* `kiwi_probe.py words 9b8f d3ff 00fa …` already rejects the same header as `roadhdr_t` (C-8105). The first words of a ZE0 road record are `9b8f d3ff 00fa 347a 2aef`; KIWI reads `SWS(0x9b8f)=83,992` bytes and `ninter=0xd3ff=54,271`, neither of which fits a 208–2,644-byte record. The synthetic positive control passes all four checks.

## Interpretation

- **FACT (tool, negative):** 0 of 6,000 section-1 road records on EU2011 and US2011 fit the KIWI 7.2 frame; all stop at the first field, the distribution header size word. The first two words of the ZE0 record are `w0/w1` (parcel code), not a KIWI size and intersection count.
- **OBSERVED:** the failure family is identical on both cards and on records from 208 B to 2,644 B, so it is not a tile-size or market artefact.
- **UNKNOWN:** no display-class record, multilink header or road-type code could be reached, so M4.69 produces **no** KIWI road-type table; the `class_code` hypothesis (C-1825) and the provisional OSM→class mapping in `map-tiles.md` stay unchanged. This is the task's Stop branch.
- **HYPOTHESIS (not tested):** the shared vocabulary comes from a common design heritage; no causal claim, no firmware VA and no renamed `docs/format/` field.

## Conclusion

M4.69's Done-when is met in its negative branch: an EXP table (below) maps every KIWI 7.2 structure to its nearest ZE0 counterpart and records a byte test with a counted corpus. The KIWI road frame is not a reader for section 1; no type-code table is added. `reader-coverage.md` row 17 notes the result.

| KIWI 7.2 structure | Nearest ZE0 structure | Byte test on 6,000 records | Verdict |

| 7.2.1 distribution header (`SWS`, intersections, display classes) | 22-word `0x00fa` record header, `w0/w1` parcel code, `w7/w8` unit table | `hlen=83,992` vs record 208–2,644 B | NO FIT |
| 7.2.1.1 display-class management record (`D` offset, 11-bit polylines) | unit table `(offset,length)` pairs in `w7..w20` | not reached (header fails) | UNTESTED |
