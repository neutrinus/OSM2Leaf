## Question

The `ze0` series was kept twice, for QEMU 8.2.10 (default) and 11.1.3.
Can the 8.2 series be dropped without losing anything a boot or a tool
depends on?

## Hypothesis

Yes: both builds give the same boot. **Falsifier:** a boot stage or a repo
tool that works only on the 8.2.10 build.

## Inputs

`tools/qemu-ze0/patches/*.patch` and `patches/11.1/*.patch` as merged with
M8.C1b (13 files each), EXP-2026-11-21-M8.C1b runs A (11.1.3) and D (8.2.10).

## Method

Scope, counted: 13 patches, one QEMU version, one scratch tree.

1. For each of the 13 names: new `patches/NAME` = the explanatory header of
   the old 8.2 file + one paragraph saying so + the diff of
   `patches/11.1/NAME`. `patches/11.1/` is removed, its README becomes
   `patches/PORT-11.1.md`.
2. `build.sh`: default and only pin 11.1.3, one patch directory,
   `--disable-fdt` always; selftest cases rewritten.
3. Checks:

```bash
runuser -u bld -- bash tools/qemu-ze0/build.sh --selftest            # as a non-root user
runuser -u bld -- bash tools/qemu-ze0/build.sh --check-version 11.1.3 --srcdir CACHE
# positive control: the tree the checker patched equals the tree the M8.C1b binary was built from
for d in hw/sh4 include/hw/sh4 hw/sd target/sh4 configs/devices/sh4-softmmu hw/char hw/timer; do
  diff -rq -x '*.orig' -x '*.rej' CACHE/check-11.1.3/qemu-11.1.3/$d BUILT-TREE/$d; done
# negative control: the removed version is refused
bash tools/qemu-ze0/build.sh --dry-run --version 8.2.10 --srcdir /tmp/x; echo $?
grep -rn 'patches/11\.1' tools --include=*.sh --include=*.py --include=*.md
```

## Observations

- `build.sh --selftest`: `78 passed, 0 failed` (before the selftest rewrite
  the same script failed 3 cases that expected `patches/11.1`).
- `build.sh --check-version 11.1.3`: tarball hash ok, every patch `APPLIES`,
  last line `check: QEMU 11.1.3: 13 applied, 0 failed, 0 unpinned-tarball`.
- `diff -rq` over the seven directories the series touches: no output. The
  scratch tree made from the unified `patches/` is the tree behind binary
  `d60fa115…79c6`, whose boot (run A of M8.C1b) reaches F3 with 47 DMA
  transfers and 42/42 block reads equal to the card.
- Runs A (11.1.3) and D (8.2.10) of M8.C1b have identical counts in
  `ze0_sdhost.py serial` and `dmatrace` (C-6873). No tool in `tools/` takes
  a QEMU version; `run.sh` only tests for the `unimp` log item, which 11.x
  has.
- `--version 8.2.10` exits 2 with `no verified tarball pin for QEMU 8.2.10`.
- `grep 'patches/11\.1' tools`: only the selftest line that checks the
  directory is gone. Older EXP records and claims keep the old path as
  history.

## Interpretation

- **FACT (C-6890):** `tools/qemu-ze0/patches/` is one series of 13 patches
  for QEMU 11.1.3; `build.sh` builds 11.1.3 by default and refuses 8.2.
- **FACT (C-6891):** the unified series reproduces, file for file, the
  source tree of the binary that reaches F3.
- **FACT (C-6892):** nothing in the measured boot or the repo tools is
  specific to 8.2.10; the falsifier did not fire.
- **OBSERVED (C-6893):** one behavioural difference remains on record from
  the port (C-4322: 8.2 aborted on an ITLB data-array write, 11.x performs
  it); the measured boot does no such write.
- Not done here: a from-scratch `build.sh` run of the unified series (about
  20 minutes); the tree identity above stands in for it.

## Conclusion

The 8.2 series is removed. A new patch is now written, built and booted
once.
