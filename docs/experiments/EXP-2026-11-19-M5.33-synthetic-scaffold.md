## Question

Why do `cardcheck` and targeted `l2check` fail on the M5.29 synthetic tree,
and can the scaffold and OSM tile be made coherent (no vendor bytes, no
weakened gate) so both pass?

## Hypothesis

The failures are scaffold defects, not gates that cannot apply offline:
(1) `tilewriter.py` synthetic mode authors the **X08-03-00** (2014+,
`ZENRIN`/`CLA-NAVI06-01`) header with `tile_header.author`, which a ZE0 card
rejects; (2) the scaffold `MMAIN001.DAT` lists only section 1 levels 6/5, so
every other (section, level) of the OSM tile is "not in MMAIN"; (3) the
scaffold `B30R060R.DAT`/`LEV3456R.DAT` are 1,024-byte header stubs, not
containers, so `tile_semantic`/`tile_mutation` hit `struct.error`; (4) the
pipeline passes `--tiles <cell>` (0 tiles, now exit 2 after M5.39).
**Falsifier:** after fixing the four, either tool still fails on the synthetic
tree; or the ZE0 header layout used for the fix does not rebuild the real
EU 2011 tile headers byte-exactly from their variable fields.

## Interpretation

- **FACT:** the four M5.29 synthetic failures were scaffold defects: wrong
  header generation (X08-03-00 on a ZE0 tree), an MMAIN level table with 2 of
  the 11 ZE0 rows, header-only stub tiles, and a bare cell name. None was a
  gate that cannot apply offline (C-3420, C-3423).
- **FACT:** the ZE0 X08-02-00 tile header is fully determined by its level
  table, box table, database bounds, DATA VERSION and section-table entries
  on all 46 EU 2011 tiles (C-3421); the X08-03-00 author rebuilds none (C-3422).
- **OBSERVED:** after the fix both validators pass with every gate check
  running (no SKIP turned into PASS); `hdd_info_map_code` and `section4`
  stay non-PASS for the stated reasons (C-3424, C-3425).
- **HYPOTHESIS:** US 2011 tile headers follow the same layout (untested here:
  the US image was not yet downloaded).
- **UNKNOWN:** whether the firmware reads this synthetic tile: rule 13,
  `mapping=provisional-v0`, L3/L4/L5 unknown. Passing L1/L2 on a synthetic
  tree says nothing about factory parity.

## Conclusion

The M5.29 synthetic path now builds a validator-coherent tree: the OSM tile
and the two baseline tiles carry an exact ZE0 X08-02-00 header
(`tools/ze0_tile_header.py`, new, tested 46/46 on EU 2011), `MMAIN001.DAT`
lists all 11 ZE0 (section, level) rows, the baseline `B30R060R.DAT` is a real
vendor-free container (`tilewriter.make_factory`), `LEV3456R.DAT` is an
empty two-section container, and the targeted `l2check` gets `B48R058R.DAT`.
`cardcheck` and targeted `l2check` PASS; the tilewriter body is unchanged
(only the 0x1000-byte header is re-authored). Changed:
`tools/one_tile_pipeline.py` (`_synth_mmain`, `_synth_tile`, new `_synth_lev`,
`_ze0_container`, `_scaffold_tree`, `build_synthetic_out`, `selftest`), new
`tools/ze0_tile_header.py`; reader-coverage row 17 notes the header; claims
C-3420–C-3426. `mapping=provisional-v0`; rule 13: L3/L4/L5 acceptance unknown.
