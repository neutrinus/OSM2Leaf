## Question

Can the divergent REFER POI page slot/refit logic in `slot_budget.py` (M5.21)
and `mutate_refer_poi.py` (main, M1.16-migrated) and the unmerged M5.12c
branch be reconciled into one safe path that applies the M5.21 slot budget,
uses factory params from M1.13/M1.16, refuses pages that cannot fit, and
preserves M5.12c's "find every copy" goal without guessing M5.12c intent?

## Hypothesis

The slot rule itself is already unified in `cmpind_codec.inner_stream_slot`
(M1.16). The remaining divergence is the budget decision (M5.21 headroom /
refuse-and-list vs legacy fits-in-slot) and `FitError` shape/encoder search.
Reconciling `mutate_refer_poi.py` to use `slot_budget`'s M5.21 budget
implementation, with a wide reproduction encoder search (M5.12c intent:
unchanged name round-trips to the same stream bytes when reproducible), keeps
existing selftests green and adds over-budget refusal + fitting refit
coverage. **Falsifier:** any existing selftest of the touched tools fails, or a
synthetic over-budget edit is accepted / mutates bytes outside the slot, or a
synthetic fitting refit fails to produce the edited name.

## Interpretation

The slot/refit API reconciliation is complete and safe under synthetic controls:
one entrypoint (`tools/mutate_refer_poi.py`, with M5.21 budget helpers in
`tools/slot_budget.py`) performs same-length and refit edits using factory
params (M1.13/M1.16), applies the M5.21 headroom budget, refuses and reports
every unfit page with a budget row, and never overflows a slot (over-budget
control). M5.12c's "find every copy" goal is preserved structurally via
`tools/poi_copies.py --inner` and `--copies-report`; the actual uncompressed-
files copy enumeration is still blocked on M5.27 (M5.12c blocker) and was not
fabricated. No format claims; no vendor bytes.
