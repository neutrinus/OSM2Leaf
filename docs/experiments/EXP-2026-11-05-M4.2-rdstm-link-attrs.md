# EXP-2026-11-05-M4.2: RDSTM001 link attributes against OSM (blocked)

Task: M4.2. Done when: attribute values correlate with at least 5 known roads
(OSM tags) in an EXP table.

## Method

1. Check whether OSM ground truth can be fetched from the agent sandbox.
2. Check whether RDSTM link rows can be placed on the map (coordinates).

## Observations

1. Outbound requests to `overpass-api.de/api/status` and
   `api.openstreetmap.org/api/0.6/capabilities` return no HTTP status (code `000`).
   No OSM extract is present in the sandbox, so no road has OSM tags here.
2. `docs/format/rdstm.md` gives only a grid hypothesis for tile names
   (`BxxRyyR`, lat/lon by hex), and says the tile and mesh-code encoding are not
   decoded. Row `src`/`dst` nodes (M4.1) have no coordinates, so no row can be
   matched to a known road.
3. M4.1 decoder (`tools/rdstm_record.py`) gives field values for each row, but
   field meanings are still HYPOTHESIS, so the candidate attributes
   (`code`, `tail`, `pad2`) are unverified.

## Result

Negative and blocked. Nothing was correlated. The table of at least 5 known roads
cannot be built from this sandbox, because there is no OSM access and no row-to-coordinate mapping.

## Blocker (one line)

No OSM ground truth reachable from the sandbox, and RDSTM rows have no decoded coordinates.

## Follow-up (suggested)

- Provide an OSM extract of the Dolnośląskie tile area (a file path or a permitted
  download), so the ground truth stays out of the repo and off the image.
- Decode a row-to-coordinate mapping for one `BxxRyyR` tile (M4.8 coordinate tool first).
