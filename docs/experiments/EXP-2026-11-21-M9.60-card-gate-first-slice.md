## Question

Can the firmware's own mount and file sweep be one command,
`tools/l3check.py --card-gate --card IMG --factory IMG [--position LAT,LON]`,
whose **exit code** is the verdict — `PASS` on the factory and P0 cards, `FAIL`
on a card whose tile is short and on a card with a corrupted `DRSTR001.DAT`,
`NOT RUN` without a card and on a US card — without a single synthetic-only
pass?

## Hypothesis

`vcard_l3.py boot` (mount verdict, `0` error-log calls) and `sweep` (every
file read back through the firmware) and `datask_l3.py mount` (no tile read
with a negative status, error-log count equal to the factory run) already run
on a whole card (C-4630/C-4651, M9.13). Wrapped in one command that turns their
results into `PASS`/`FAIL`/`NOT RUN` rows and a single exit code, they gate P0
and P1 at L3 now, without the POI row that M9.12 still waits for.

**Falsifier:** a card that fails in the factory-compared mount but passes the
gate; or a card the rows call `PASS` that the firmware in fact fails to read;
or a US card reported `PASS`; or a missing card reported `PASS`.

## Method

1. **Sample and hash.** Above; every card is hashed by its command block and
   the printed value is quoted in Observations.

2. **Commands.** Run from the repository root; `S` is a scratch directory
   outside the repo. The cards are copied first and patched in place.

```bash
L=$PWD
EU=archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img
US=archive/sd-images/LEAF_2011-2012_US.img
S=$HOME/projekty/leafre-work/scratch/m9.60
mkdir -p $S && cd $S

# P0 card (M5.30/M5.49 recipe): factory copy, patch tile then manifest
cp $L/$EU p0.img
python3 $L/tools/imgpatch.py --image p0.img --file MAPAL001/B48R058R.DAT \
  --from $HOME/projekty/leafre-work/m5.44/out-nav/MAPAL001/B48R058R.DAT \
  --allow-resize --hash --json > patch-tile.json
python3 $L/tools/imgpatch.py --image p0.img --file DRSTR001.DAT \
  --from $HOME/projekty/leafre-work/m5.44/out-nav/DRSTR001.DAT \
  --hash --json > patch-drstr.json
sha256sum p0.img     # expect b0faf119…33237

# negative: the M5.56 padded tile cut at 0x9100, into a factory copy
python3 $L/tools/osm_ingest.py $L/tools/fixtures/m5.56-krotoszyn.osm -o krot.imf
python3 $L/tools/mesh_split.py krot.imf -o ksplit
python3 $L/tools/roadclass_v0.py --class-table-out ctab.json
mkdir -p syn
python3 $L/tools/tilewriter.py ksplit --out syn/B48R058R.DAT --cell B48R058R \
  --class-table ctab.json --country 616 --level 1 --no-names \
  --data-version 26/11/21/01 --json > Gsyn.json         # 37,376 B
head -c 37120 syn/B48R058R.DAT > B9100.DAT              # cut at 0x9100
cp $L/$EU neg9100.img
python3 $L/tools/imgpatch.py --image neg9100.img --file MAPAL001/B48R058R.DAT \
  --from B9100.DAT --allow-resize --hash --json > patch-9100.json

# negative: corrupted DRSTR001.DAT (M9.14 E3: +0x24 xor 0x40)
cp $HOME/projekty/leafre-work/m5.29-factory-out/DRSTR001.DAT drstr-bad.DAT
python3 -c "d=bytearray(open('drstr-bad.DAT','rb').read());d[0x24]^=0x40;open('drstr-bad.DAT','wb').write(d)"
cp $L/$EU negdrstr.img
python3 $L/tools/imgpatch.py --image negdrstr.img --file DRSTR001.DAT \
  --from drstr-bad.DAT --hash --json > patch-badd.json

# the gate, one call per card; the exit code is the verdict
python3 $L/tools/l3check.py --card-gate --card p0.img --factory $L/$EU \
  --position 51.70,17.45
python3 $L/tools/l3check.py --card-gate --card $L/$EU --factory $L/$EU \
  --position 51.70,17.45
python3 $L/tools/l3check.py --card-gate \
  --card $HOME/projekty/leafre-work/scratch/m5.49-nav/p1.img --factory $L/$EU \
  --position 51.70,17.45
python3 $L/tools/l3check.py --card-gate --card $L/$US --factory $L/$EU \
  --position 51.70,17.45
python3 $L/tools/l3check.py --card-gate --card negdrstr.img --factory $L/$EU \
  --position 51.70,17.45
python3 $L/tools/l3check.py --card-gate --card neg9100.img --factory $L/$EU \
  --position 51.70,17.45
python3 $L/tools/l3check.py --card-gate --card /no/such.img --factory $L/$EU

python3 $L/tools/l3check.py --selftest
python3 $L/tools/selftest.py --only l3check
```

3. **Controls.**
   *Positive:* the factory card and the P1 card (byte-identical to it) must
   pass all three rows; the P0 card must pass all three rows (`b0faf119…33237`,
   the same card M5.30/M5.50 gate on the host side). *Negative:* the `0x9100`
   cut tile must fail `sweep` and `mount` and name `MAPAL001/B48R058R.DAT`; the
   corrupted `DRSTR001.DAT` must fail `boot` (`REJECT`); the US card must be
   `NOT RUN (build)`; a missing card must be `NOT RUN` with exit 3.

4. **Scope.** EU2011 build A only (the gate's `CARD_GATE_BUILD`); cards are
   the factory image, P0, P1, the US image and two factory-derived negatives (6
   cards). Mount is run at one position (`51.70,17.45`, the P1 tile's own), the
   same position M5.56/M9.13 use; the `--position` flag is repeatable but one
   position is enough to gate P0/P1. Not covered: the POI row (M9.12/M9.31),
   routing, names/search, the renderer, US2011 execution (M9.61), the launcher's
   map-code check (M2.5/M2.15), L4 (M8), the car (L5).

5. **Falsifier:** stated above, before the runs.

## Interpretation

- **FACT:** the factory card, the P1 card and the P0 card `b0faf119…33237`
  pass all three rows and exit 0; P0's `sweep` compares `8876604` bytes (the
  factory `8874828` plus the grown tile's extra bytes), and its `mount` is
  `SAME as factory` at 28 reads, 18 tile reads, state 2.
- **FACT:** a card whose `MAPAL001/B48R058R.DAT` is the M5.56 tile cut at
  `0x9100` fails `sweep` and `mount` naming `MAPAL001/B48R058R.DAT`, exit 1: the
  `mount` row reports the read the firmware refused,
  `pos 0x1100 len 0x8100 status 4294967295` (that is the `0xffffffff` the M5.56
  EXP records as `-1`), and the `boot` row still passes because the mount of the
  layer's directory tables is not the tile read.
- **FACT:** a card with a corrupted `DRSTR001.DAT` fails `boot` with
  `mount REJECT ... 2 error-log call(s)`, exit 1 -- M9.14's E3 rejection now
  reaches the gate through `vcard_l3.py boot` inside it.
- **FACT:** a US2011 card is `NOT RUN (build)`, exit 3, never `PASS`; a card
  with no image is `NOT RUN`, exit 3.
- **FACT:** the build is named from the card's first 96 MiB (the firmware
  region, below the 100 MiB map partition): P0's whole 256 MiB head differs from
  the factory head (its map partition edit is inside it) but its 96 MiB prefix
  does not, so the prefix is the stable key.
- **OBSERVED:** the negative `neg9100` shows and names **two** `ErrorLogMsg`
  calls at the mount, but the gate fails the row on the negative read status
  first, so the read is what the verdict names; the error-log comparison is the
  secondary check.
- **UNKNOWN:** which firmware function reads `DRSTR001.DAT`'s size for the
  directory-read clamp (M5.56 leaves this open); the gate does not need it --
  it asks the firmware, not the model.

## Conclusion

`tools/l3check.py --card-gate --card IMG --factory IMG [--position LAT,LON]`
runs `boot` (`vcard_l3.py boot`: ACCEPT, 0 error-log calls), `sweep`
(`vcard_l3.py sweep`: every file of the volume table read back), `mount`
(`datask_l3.py mount`: no tile read with a negative status, error-log count equal
to the factory run, `SAME`) and makes the exit code the verdict: 0 all three
`PASS`, 1 a row `FAIL`s naming the read, 3 nothing runnable (`NOT RUN`; no card,
a US card, or an unexpected stop). `--selftest` covers the verdict table,
per-row verdicts, missing inputs and the build prefix without vendor data (29
checks). The factory, P1 and P0 cards exit 0 with three `PASS` rows; the `0x9100`
cut and the corrupted `DRSTR001.DAT` cards exit 1 naming the failing read; the
US card and a missing card exit 3. `docs/format/card-ladder.md` names the
command as the L3 gate of P0 and P1 and says what its three rows do not reach.
Claims C-6720–C-6729; the POI row is still M9.12/M9.31.
