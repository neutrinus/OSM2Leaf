# EXP-2026-11-20-M8.A3 — Built-in CE loader: `-M ze0 -kernel SD-IMAGE` boots with no `-device loader`

- **Status:** done
- **Date:** 2026-11-20
- **Task:** TODO **M8.A3** (built-in loader)
- **Sample:** EU 2011 image head `archive/head256.img` (268 435 456 B),
  SHA-256 `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`
  (image B = `nk.exe` image at `0x3e00200`, image C at `0x5200200`, image A
  at `0x200200`). Every VA below is **EU2011**.
- **Tools:** QEMU **8.2.10** (`v8.2.10` git tag, build tree of
  EXP-2026-11-19-M8.A6, `ninja -C build -j2 qemu-system-sh4`) with the eight
  `tools/qemu-ze0/patches/*.patch` (new: `ze0-0004`), binary kept as
  `qemu-system-sh4.a3`, SHA-256
  `bfe3b293c84f2976cca7fdc3642ba42420d551a2e3a6aea57a39debb3381e34f`; gcc
  13.3.0; Python 3.13.18. Repo tools: `tools/ze0_ceload.py` (new,
  `--selftest`), `tools/qemu-ze0/run.sh`, `tools/ce_qemu_probe.py`.
- **Claims:** C-1250, C-1251, C-1252, C-1253
- **Supersedes:** none
- **Superseded by:** none

## Question

Can the `ze0` machine load the CE images from the SD image itself, so the
kernel boots with no `-device loader` lines, and does that boot behave
exactly like the one with hand-cut files?

## Done-when (made concrete for this run)

The TODO line "Done when booting needs no `-device loader`" says nothing
about *what* must boot, so the block now says (written before the runs):
`-M ze0 -kernel archive/head256.img` with no `-device` option (1) puts
bytes in RAM that are identical to the physfirst..physlast cuts of images B
and A, (2) starts at PC `0x8800ebd0`, (3) gives, over 60 s, the same
ordered non-interrupt exception sequence as the `-device loader` boot of
those cuts; and (4) a wrong offset fails loudly instead of booting.

**Deviation from the block's wording:** the options are `kernel-off=` and
`app-off=`, not `kernel=`/`app=`, because `kernel` is already
MachineState's `-kernel` file-name property (QEMU aborts with "attempt to
add duplicate property 'kernel'"; observed on the first build).

## Hypothesis

The CE image header is enough to place each image: `ECEC` at +0x40, pTOC at
+0x44, the ROMHDR offset at +0x48, so physfirst = pTOC − offset;
physfirst..physlast is the image; the `nk.exe` TOC entry gives
`e32_vbase + e32_entryrva`. **Falsifier:** RAM differs from the cuts, the
PC is not `0x8800ebd0`, or the 60 s exception sequence differs from the
`-device loader` boot.

## Interpretation

- **FACT (C-1250):** `ze0-0004` loads a CE image from the header alone:
  `ECEC` +0x40, pTOC +0x44, ROMHDR offset +0x48 (physfirst = pTOC −
  offset, checked against ROMHDR +0x08), physfirst..physlast to
  `physfirst & 0x1fffffff`, entry = `e32_vbase + e32_entryrva` of the
  `nk.exe` TOC entry. For EU2011 image B that is 7 215 268 B at
  `0x08000000` and entry `0x8800ebd0`; image C gives 6 718 424 B and
  `0x8800ebb0`. A second implementation in Python agrees on every number.
- **FACT (C-1251):** `-M ze0 -kernel archive/head256.img` with no
  `-device` option puts bytes in RAM identical to the reference cuts, starts
  at `0x8800ebd0`, and its 60 s boot has the same 30-event non-interrupt
  exception sequence as the `-device loader` boot (twice each). The
  falsifier did not fire. Done-when met.
- **FACT (C-1252):** `run.sh --image` now passes `-kernel` on ze0 and sizes
  the `-M none` cuts from the ROMHDR (7 215 268 / 24 456 328 B instead of
  589 833 / 53 512 B, C-1283). The old short cuts boot to 0 exceptions and
  1 unmodelled access (C-4311's numbers), so the trace comparison can tell
  the two apart.
- **OBSERVED (C-1253):** the loader refuses a wrong offset, a non-kernel
  image and a short file (rc 1, one line each), and does nothing without
  `-kernel`.
- **Caveat:** the timer-interrupt count is not reproducible run to run on
  either path (host timing); a bit-exact comparison needs `-icount`, which
  M8.B2 can decide on.

## Conclusion

M8.A3 is done: booting needs no `-device loader` lines, and the built-in
boot matches the hand-cut boot in RAM content, entry PC and fault
sequence. The option names are `kernel-off=`/`app-off=` (see Deviation).
`run.sh` uses it, and its `-M none` fallback no longer cuts the images
short.
