## Question

With a working `-M ze0` display, can at least three distinct card errors from the M2.9 catalogue be reproduced at L4, each tied to its card mutation, its exact serial log line and a screenshot kept in `archive/` — so that a reader who later sees one in the car has a reference?

## Hypothesis

The launcher errors that M2.21 and M2.23 reached as log verdicts also draw an AUI error screen after FailSafe starts: `DIFFERENT MAP CODE` (code `0x50`, card line 1 mismatch), `MAP DATA BASE UNMATCH` (code `0x51`, card MapDBVer out of the unit window) and `SD UNLOCK NG` / the security-lock screen (code `0x81`, never-locked card). Each card mutation gives a distinct error string in the log and a distinct drawn screen. **Falsifier (task):** an error in the catalogue is unreachable by any card mutation tried — operationally, an error card boots like the factory control (no error marker), or the screen never draws (`Draw Error Message End` absent), or two errors give the same screenshot as the factory. A second falsifier from the navigator: no AUI screen renders for the third error, in which case only two screens may be counted and the task is `blocked`, not `done`.

```bash
python3 -c '

open("/home/marek/projekty/leafre-work/scratch/m2.24/HDD_INFO.factory.TXT","wb").write(h)

# produced: wrote 72 bytes; SHA-256 9f014643…bc650a (hddinfo.py parse --json)
cp "$S/HDD_INFO.factory.TXT" "$S/C_line1.HDD_INFO.TXT"
cp "$S/HDD_INFO.factory.TXT" "$S/F_mapdb.HDD_INFO.TXT"
python3 - <<'PY'
from pathlib import Path
S=Path('/home/marek/projekty/leafre-work/scratch/m2.24')
for name,old,new in [('C_line1.HDD_INFO.TXT', b'QSD-302-100', b'QSD-301-100'),
                     ('F_mapdb.HDD_INFO.TXT', b'02-110100-00', b'02-110050-00')]:
    p=S/name; b=p.read_bytes(); assert b.count(old)==1,(name,b.count(old))

cd "$S/cards"
cp --reflink=auto "$W/$FACTORY" C_line1.img
cp --reflink=auto "$W/$FACTORY" F_mapdb.img
cp --reflink=auto "$W/$FACTORY" SD_lock.img
cd "$W"
python3 tools/card_mapcode.py set --image "$S/cards/C_line1.img" --code QSD-301-100 --in-place

    --file VER_INFO/HDD_INFO.TXT --from "$S/F_mapdb.HDD_INFO.TXT" \
    --update-version-copy --json > "$S/cards/F_mapdb.patch.json"

    --target-line1 QSD-302-100 --mapdbver-min 16 --mapdbver-max 16 --json
```

- **Negative (per error):** each error card gives a distinct `Error Proc<0x50|0x51|0x81>` code and a distinct AUI-plane PNG hash; the three hashes differ from each other (O3).
- **Negative (screenshot oracle):** `screen` prints 384000 non-black pixels for every error card but the PNGs are byte-identical (the opaque blue plane), so `screen`'s count alone is not an oracle here; the AUI text lives on the keyed plane 1 (M8.C1t). The cited hash is the `plane -n 1` output, which differs per error.
- **Mandatory (navigator round 2):** the table in `docs/format/validation.md` is the committed artifact; mutating a cited hash or log line breaks the tie to this EXP and the claim rows (O6).
