## Question

Is the original M4.16 done-when met with the tools that M4.16b, M4.16d and
M4.16e merged: "≥ 20 rows are matched to tile road segments with
coordinates, with the join key named and a random-key control showing ~0
matches"?

## Hypothesis

The earlier negative (C-1810–C-1812) tested the M4.1 16-byte row framing,
which is not the record framing. With the decoded field directory (C-5130–
C-5136), the link-group rule (C-5137–C-5139) and the all-table placement
(C-5400–C-5403), the done-when should hold without new code.

**Falsifier (stated before the run):** `place-all` places fewer than 20
records, or the shuffled-neighbour control at < 1 km is not ≪ the real count
(more than 1 % of pairs), or the per-record examples do not name a tile,
parcel, node, link and coordinate, or the numbers differ from C-5400/C-5401
on the same sample (the earlier record would then not be reproducible).

## Method

1. **Sample and hash** as above (`sha256sum`).
2. **Commands** (repo root; `E=/home/user/scratch/factory-eu`):

   ```bash
   E=/home/user/scratch/factory-eu
   sha256sum $E/RDSTM001/RDSTM001.DAT $E/RDSTM001/LCTBL001.DAT $E/MAPAL001/B48R058R.DAT
   python3 tools/rdstm_place.py --selftest
   python3 tools/rdstm_links.py --selftest
   python3 tools/rdstm_place.py place-all $E/RDSTM001/LCTBL001.DAT $E/RDSTM001/RDSTM001.DAT $E/MAPAL001
   python3 tools/rdstm_links.py place $E/RDSTM001/LCTBL001.DAT $E/RDSTM001/RDSTM001.DAT $E/MAPAL001 --table-pair 0 --examples 20
   ```

3. **Controls.** *Positive:* named TMC junctions of the CZ D5 motorway
   (table 0) must land at their known places (Stříbro ≈ 49.70 N 13.0 E,
   Plzeň ≈ 49.7 N 13.3 E, Rokycany ≈ 49.75 N 13.6 E). *Negative:* (a) random
   refs drawn from the same group/entry space, tested for the table's
   country; (b) each record's TMC positive neighbour replaced by a shuffled
   record, tested for < 1 km node distance; (c) level-4 vs level-2 distance of
   a shuffled record.
4. **Scope.** EU 2011 only; all 14 set-1 RDSTM location tables (243,838
   LCTBL records, 158,473 with a link record, 110,795 joined by code with
   neg/pos agreement); level-2 parcels 31,711 in 31 tiles, level-4 parcels
   263. US 2011 (`XMD`, no TMC) and the firmware reader (M4.49) are out of
   scope.
5. **Falsifier:** as stated under Hypothesis.

## Interpretation

- **FACT:** ≥ 20 RDSTM rows (records) map to tile road segments with
  coordinates: 110,788 records at level 2, each to a (tile, parcel, node,
  link) section-2 element with lat/lon; 20 are listed with their tile.
- **FACT:** the join key is the TMC location code (LCTBL record index →
  RDSTM link record → `u32` ref `(group, entry)` → section-2 `(node, link)`;
  C-5134, C-5139, C-5402).
- **OBSERVED:** the random-key control that can be near zero is: shuffled
  neighbours < 1 km 129/95,176 (0.14 %) against 94,551 real; shuffled
  cross-level 256/60,321. The country control is a share by construction
  (random refs 2,048/27,998 land in the table's country), as noted in
  C-5400.
- **HYPOTHESIS:** none new. The firmware reader of the link groups is still
  unlocated (M4.49), so the placement is data-side: rule 13 *confirmed* is
  not claimed.

## Conclusion

The M4.16 done-when is met on the EU 2011 card with the tools already on
`main`; the re-run reproduces C-5400/C-5401 exactly. C-1812 (the
"blocked" consequence) is superseded by C-5950. M4.16c (the `INTER`/`FRWAY`
lead) and M4.2 (link attributes, waits on a road key and OSM) no longer wait
on this task. No `docs/format/` change: `rdstm.md` already carries the
M4.16e rule.
