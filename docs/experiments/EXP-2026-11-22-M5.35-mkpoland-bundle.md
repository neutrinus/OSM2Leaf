## Question

Can one reproducible command turn a named OSM extract + a factory card image into an evidence bundle whose per-stage verdicts are the real exit codes of the compiler, `cardcheck --image`, `l2check --root` and `l3check --card-gate`, with SKIP/BLOCKED never promoted to PASS and a negative control that exits non-zero?

## Hypothesis

`tools/mkpoland.py --osm EXTRACT --factory IMAGE -o OUT.img` can wrap the existing M5.11/M5.29 compiler (`one_tile_pipeline.py`), the M5.10 card builder (`mkcard.py`) and the L1/L2/L3 validators so that the synthetic committed fixture produces a complete bundle without vendor data, and the factory EU image produces a bundle with L1/L2 PASS and an honest L3 row list. The falsifier is any L3 `NOT RUN`/`NOT RUNNABLE` row reported as PASS, or a forced L2 failure that still exits 0 / records PASS.

## Plan (written before coding, for navigator review)

**Approach.** `tools/mkpoland.py` is a thin, stdlib-only stage runner. It never re-implements a validator: each stage calls an existing tool as a subprocess and takes the verdict from that tool's **exit code**, never from its prose. The stages are

| Stage | Command (exit code is the verdict) | Verdict mapping |
| --- | --- | --- |
| `fixture` | `cardcheck.py --generate-fixture DIR` + `--generate-fixture-image IMG` | 0 -> PASS, else FAIL (synthetic mode only) |
| `compile` | `one_tile_pipeline.py --osm OSM --factory-root ROOT --out TREE --cell ... --parcel ... --json R` | 0 -> PASS, else FAIL; if the CLI is not callable, `NOT_IMPLEMENTED` and block on M5.11 |
| `card` | `mkcard.py --from-image FACTORY --tree TREE -o OUT.img` | 0 -> PASS, else FAIL |
| `l1` | `cardcheck.py --image OUT.img --json R` | 0 -> PASS, else FAIL |
| `l2` | `l2check.py --root EXTRACTED_TREE --json R` | 0 -> PASS, else FAIL |
| `l3` | `l3check.py --card-gate --card OUT.img --factory FACTORY --position ... --json R` | exit 0 + `result=PASS` -> PASS; exit 1 / `FAIL` -> FAIL; exit 3 / `NOT RUN` or no firmware head -> `NOT_RUNNABLE` |

`EXTRACTED_TREE` is `OUT.img` unpacked with `7z x -o<workdir>/card-tree`, so L2 validates what is actually on the card, not only the compiler's staging tree. The compiler report's `changed_set` and `mkcard`'s byte diff (mapped to FAT clusters via `mkcard.open_map_partition` / `FatGeo.cluster_offset`) become the manifest's changed-file and changed-cluster lists.

**Honesty rules.** A stage's status is one of `PASS`, `FAIL`, `SKIP`, `NOT_RUNNABLE`, `NOT_IMPLEMENTED`. `SKIP`/`NOT_RUNNABLE` are terminal: the overall verdict is `PASS` only when every non-skipped stage is `PASS` **and** no stage is `FAIL`; a `NOT_RUNNABLE` L3 never contributes to a PASS. The per-L3-row verdicts come straight from the gate JSON (`rows[].status`), and `NOT RUN` rows are copied verbatim. Rule 13 is quoted in `report.md`.

**Files.** New `tools/mkpoland.py` only (plus this EXP, claim rows, TODO block). No edits to `selftest.py`, `mkcard.py`, `l2check.py`, `l3check.py`, `cardcheck.py` or any other task's files. Scratch and generated cards live in `~/projekty/leafre-work/scratch/m5.35/` (never `/tmp`); TMPDIR is pinned there for subprocesses because the default 3.8 GiB `/tmp` tmpfs returned `Errno 122 Disk quota exceeded` on `mkcard --selftest`.

**Intended Done when.** (1) one command emits `manifest.json` + `report.md` on the committed synthetic fixture; (2) on the factory EU image L1/L2 are PASS and L3 names its runnable/blocked rows; (3) `--selftest` proves a forced L2 failure exits non-zero with `manifest.json` recording `FAIL`, plus a positive control that exits 0. The falsifier is an L3 `NOT RUN`/`NOT RUNNABLE` row promoted to PASS.

## Method

A **spec**, not a narrative.

1. **Sample and hash.** Synthetic: the committed fixture above (`a6300b161d…af25`) plus a no-vendor factory generated by `cardcheck --generate-fixture(-image)`; both recorded by SHA-256 in the manifest. Real: factory EU2011 `105e2032…76307`; both recorded.
2. **Commands.** All run from the worktree root with `TMPDIR=$HOME/projekty/leafre-work/scratch/m5.35`:
   ```bash
   python3 tools/l2check.py --help | grep -- --cmp-limit
   TMPDIR=$HOME/projekty/leafre-work/scratch/m5.35 python3 tools/mkcard.py --selftest
   python3 tools/mkpoland.py --selftest
   python3 tools/mkpoland.py --synthetic --osm tools/fixtures/m5.37-splice.osm \
       -o ~/projekty/leafre-work/scratch/m5.35/synthetic-out.img \
       --bundle ~/projekty/leafre-work/scratch/m5.35/bundle-synthetic
   python3 tools/mkpoland.py --osm tools/fixtures/m5.37-splice.osm \
       --factory archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img \
       -o ~/projekty/leafre-work/scratch/m5.35/eu-out.img \
       --bundle ~/projekty/leafre-work/scratch/m5.35/bundle-eu \
       --position 51.70,17.45
   python3 tools/selftest.py
   python3 tools/gate.py
   ```
3. **Controls.** *Positive*: the same synthetic fixture without any injection must give `compile/card/l1/l2 = PASS` and exit 0. *Negative*: `--force-l2-fail` flips one byte in the generated tile body before `mkcard`; the real `l2check.py --root` must FAIL, the command must exit non-zero and `manifest.json` must record `stage=l2, status=FAIL`. *Falsifier control*: a bundle whose L3 rows are all `NOT RUN` must not be reported as overall PASS.
4. **Scope.** Stages: compiler, card builder, L1 image check, L2 extracted-tree check, M9.60 L3 card gate. Synthetic run uses the no-vendor fixture and generated factory only; real run uses one factory EU2011 image and one firmware head. Not covered: L4/QEMU, L5/car, non-EU2011 builds. Counts (files compared, clusters changed, rows) are quoted from the commands.
5. **Falsifier.** An L3 `SKIP`/`NOT RUN`/`NOT RUNNABLE` promoted to PASS, or the forced-L2 run exiting 0 / recording L2 as PASS.

## Interpretation

- **FACT:** one command produces both bundles; the synthetic bundle is honest (`overall=NOT_RUNNABLE`, all three L3 rows `NOT RUN`), and the factory bundle passes all six stages including the M9.60 card gate. No SKIP or NOT RUN was promoted to PASS.
- **FACT:** the forced L2 failure exits 1 with `l2=FAIL` while L1 stays PASS — the negative control is isolated to L2 and comes from the real `l2check.py` exit code, not a fabricated verdict.
- **OBSERVED:** the synthetic compiler uses its built-in `SYNTHETIC_OSM`; the named fixture is hashed and passed for provenance. The factory run compiles that named fixture against the EU2011 root at parcel `(76,940)` (10 IMF records). The reason is recorded in the manifest notes: the no-vendor fixture tile's only `0x2046` directory is `(72,936)`, which cannot hold the fixture geometry.
- **OBSERVED:** `mkcard --selftest` on this host needs a home-tree `TMPDIR`; the tool now pins TMPDIR to its workdir, so the wrapper does not depend on the operator's environment.
- **UNKNOWN:** L4/QEMU and L5/car acceptance; rule 13 still applies even though L3 PASS. The non-stock zlib runtime (`1.3.1.zlib-ng`) was used, so no byte-identical claim is made.

## Conclusion

`tools/mkpoland.py` delivers the one-command L1→L2→L3 evidence path for M5.35. Its six stage verdicts are the called tools' exit codes (L3 also checks the gate JSON `result`), the manifest carries input/tool hashes, per-stage statuses, L3 rows and a FAT-derived changed-cluster list, and `report.md` quotes rule 13. The committed synthetic fixture produces a bundle without vendor data; the factory EU image produces a bundle with L1/L2/L3 PASS. Claim rows C-3680–C-3689 record the measured facts; follow-ups cover L4/L5 and the synthetic compiler-input caveat. No format doc changed.
