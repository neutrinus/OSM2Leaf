## Question

Can the four Poland tiles (`B48R050R`, `B48R058R`, `B50R050R`, `B50R058R`)
be filled from one OSM snapshot into a display-only card that passes
`cardcheck --image`, the `imgpatch --allow-metadata` diff gate,
`l2check --semantic-tiles` and the L3 mount, and if not, what is the largest
subset that does?

## Hypothesis

The batch chain (`osm_ingest --bbox` → keep single-cell ways → `tilewriter
--factory`) writes a level-1 tile whose size is governed by the parcel/record
capacity, not by the card. A card patched with such a tile and its
`DRSTR001.DAT` passes the four display-only gates. The falsifier is the task's
own: the gate passes on a card where one directory was written with the ways of
the neighbouring directory, or a tile that cannot hold its data is reported as
built.

The external cut (`$S/cut4.py`, pyosmium; not a repo tool because it only
bounds memory for one cell):

```python
import osmium, sys, time
src, out, idxbase = sys.argv[1], sys.argv[2], sys.argv[3]
W, S, E, N = map(float, sys.argv[4:8])
def inside(lon, lat): return W <= lon <= E and S <= lat <= N
class H(osmium.SimpleHandler):
    def __init__(self, w): super().__init__(); self.w = w; self.n = 0; self.wc = 0
    def node(self, o):
        if inside(o.location.lon, o.location.lat): self.w.add_node(o); self.n += 1
    def way(self, o):
        try:
            if any(inside(nd.location.lon, nd.location.lat) for nd in o.nodes):
                self.w.add_way(o); self.wc += 1
        except osmium.InvalidLocationError: pass
    def relation(self, o): pass
t0 = time.time()
w = osmium.SimpleWriter(out)
h = H(w); h.apply_file(src, locations=True, idx="sparse_file_array," + idxbase)
w.close()
print("written", out, "nodes", h.n, "ways", h.wc, "secs %.1f" % (time.time() - t0))
```

### 6. Why the other three tiles are not built

- **`B48R050R` (level 1) — RAM in `tilewriter`.** The split is 1,837,383,144 B
  with 1,641,585 single-cell ways; `tilewriter.read_jsonl` reads the whole text
  (`_read_text()`, `tools/tilewriter.py:410,421`), `/usr/bin/time -v` records
  `Maximum resident set size (kbytes): 5224528` and the kernel kills it
  (`Command terminated by signal 9`) after `5:00.13` on a 7,735 MB host. A
  gzipped split (295,545,500 B) peaked at `5,226,136` kB and was killed too.
- **`B50R058R` (level 1) — pair splice in `tilewriter`/`verify_factory`.**
  With 429,120 single-cell ways, 63 dense ways dropped, 0 parcels left dense,
  the writer stops at `tilewriter: check failed: section-1 record at
  (81, 941, 22, 59) changed but was not regenerated` (rc 1, peak 4,685,336 kB;
  `tilewriter` raises at `tools/tilewriter.py:1182`). The same key with
  `c = 0` alone is clean; `c >= 1` changes the adjacent odd pair `2c+2`, i.e.
  the writer rewrites an in-place slot region whose trailing bytes belong to
  the partner pair.
- **`B48R058R` — not built.** Its cut has 15,471,143 ways (1,054.3× the
  `B50R050R` cut's 1,253,993), so it needs both the streaming reader and the
  splice fix; the ingest was stopped at 152,068,314 B (`osm_ingest_rc: -15`)
  and no writer run was made.

### 8. Sample-integrity incident and repair (not a card result)

`cp -a` (no `-l`) made `$W/MAPAL001/B50R050R.DAT` a **hardlink** of
`$FAC/MAPAL001/B50R050R.DAT` (link count 2, same inode); `rebuild_manifests.py`
then wrote the 90,251,560 B tile **through that link** at 13:22, so the
template file became the generated tile. `imgpatch` read `$W` (correct bytes)
and wrote `p1.img` before the damage was noticed; the image is intact (the
read-back in §4 matches). Repair: `cp --remove-destination` the generated tile
into the card and the pristine 79,221,504 B file (`m5.4/card-factory`, SHA-256
`5205f779…15ae`) and the pristine `DRSTR001.DAT` (`2b7f2fb8…25f6`) into the
template; `diff -rq $FAC <pristine>` is now `IDENTICAL` and `stat` shows link
count 1 on both. The card's own `DRSTR001.DAT` (`3b087ae8…`) is now a separate
file. This is why the Method copies (`cp -a`) and then breaks the tile link with
`--remove-destination` before `rebuild_manifests`, and why the corpus above is
built **from the pristine template**, not from the working root.

## Interpretation

- **FACT:** a level-1 `B50R050R` tile generated from the 2026-11-21 Poland
  extract (185,472 single-cell ways, 5,806 parcels, 0 dense, 0 dropped) is
  90,251,560 B and, patched with `DRSTR001.DAT` into the EU 2011 image, passes
  `cardcheck --image`, `check-diff` `outside: 0`, `l2check --semantic-tiles`
  and `7z t`; the L3 mount reads the tile with 28 reads and no negative status;
  the tile read back out of the patched image is byte-identical to the build.
- **OBSERVED:** the largest passing subset of the four tiles is **one tile**
  (`B50R050R`), **level 1 only**. Three tiles are stopped by two separate
  `tilewriter` causes: the whole split is held in RAM (`B48R050R` 1.64 M
  single-cell ways, 5.22 GB peak, killed; `B48R058R` larger), and the in-place
  pair splice corrupts a partner pair (`B50R058R`, `verify_factory` at
  `(81,941,22,59)`). Level 2 is a third, separate limit: the factory has 1,313
  level-2 parcels with no even slot and the writer cannot create one.
- **HYPOTHESIS:** a streaming `read_jsonl` and a pair-splice fix (write the even
  and odd pair together, or never rewrite a slot region in place) would let the
  other three tiles build at level 1; none of the three is a card/format
  question.
- **UNKNOWN:** whether the unit displays the card (L5); whether the
  defect-free directories of a failed tile would show if the build were
  isolated per directory (the follow-up's design); and whether the level-2
  even slot is a factory gap that other cells share.

## Conclusion

The display-only card machinery works end to end for one Poland tile:
`B50R050R` level 1 passes every gate in the task's Done-when, with the image
`7fee5d3ba10f86104d22981f5979dce11643072e8168ddabe07b05e7926b5e66` kept
outside the repo. The task's Stop rule fires for the other three tiles and for
level 2: `B48R050R` exceeds this host's RAM in `tilewriter` (5.22 GB peak,
killed), `B50R058R`/`B48R058R` hit a `tilewriter` pair-splice defect, and level
2 has no even slot. The largest passing subset is **one tile, level 1**; three
