## Question

Can `tools/fn_audit.py` widen its corpus to the l3 layers the M9/M3 board
cites — the L3 harness targets, `docs/format/firmware.md`, the append-only EXP
records and the code citations (`fn`/`sub_` labels, documented corrections and
pins) in an open task block — freeze **that** set to its own committed
snapshot, and become a standing gate that applies H69's
`moved`-warns/`new`/`gone`/verdict-fails policy **to each source separately**
while the docs base keeps its post-H52 `INSIDE 0`?

## Hypothesis

The l3 corpus is a deterministic function of four files/globs plus the
image's `.pdata`, so it can be frozen once and audited back. Because EXPs are
append-only, the overlay will contain real `INSIDE` rows that cannot be
corrected; the gate must therefore freeze them as the register rather than
fail on its own baseline, and must catch the *change* (a new citation, a class
change, a candidate-set change). The docs base and the l3 overlay are separate
sources and must get separate live comparisons, so l3 line churn cannot
fail the gate or silently inflate the docs `moved` count.

**Falsifier:** a `--scope l3` run whose summary is not reproducible from a
second `--write-snapshot`; a moved-only l3 drift that exits 1; a new/gone l3
row, or an `AMBIGUOUS` candidate set that gains `INSIDE`, that exits 0; an l3
overlay row reported as a docs-base row; a correction line counted as
`INSIDE`; or the docs `--scope docs` summary moving at all.

## Method

### 1. Sample and hash

`archive/head256.img`, first 256 MiB, SHA-256 above. The overlay snapshot
stores the same `image_sha256`; `--overlay` refuses a different hash. No
vendor bytes are stored in the repo or the snapshot (only offsets, VAs,
classes and hashes).

### 2. Commands

Run from the repo root. `--scope l3` is the new corpus; `--write-snapshot`
freezes it; `--corpus … --overlay …` is the gate.

```bash
sha256sum archive/head256.img
python3 tools/fn_audit.py --selftest
python3 tools/fn_audit.py archive/head256.img --scope docs --quiet
python3 tools/fn_audit.py archive/head256.img --scope l3 --quiet
python3 tools/fn_audit.py archive/head256.img --scope l3 --fix-list | wc -l
python3 tools/fn_audit.py archive/head256.img --scope l3 \
    --write-snapshot docs/research/fn-audit-l3-corpus-2026-11-16.json --quiet
sha256sum docs/research/fn-audit-l3-corpus-2026-11-16.json
python3 tools/fn_audit.py archive/head256.img \
    --corpus docs/research/fn-audit-corpus-2026-11-16.json \
    --overlay docs/research/fn-audit-l3-corpus-2026-11-16.json --quiet
python3 tools/fn_audit.py archive/head256.img \
    --corpus docs/research/fn-audit-corpus-2026-11-16.json \
    --overlay docs/research/fn-audit-l3-corpus-2026-11-16.json \
    --no-live-check --quiet
python3 tools/selftest.py --only fn_audit_l3,fn_audit_l3_image,fn_audit
python3 tools/selftest.py
python3 tools/claims_check.py
python3 tools/todo_check.py
```

### 3. Controls

* **Positive (docs base unchanged).** `--scope docs --quiet` is still
  `17 file(s) scanned, 313 citation(s), 112 unique VA(s)` and
  `START 229, INSIDE 0, CORRECTED 23, GAP 29 (leaf 29), AMBIGUOUS 0, UNMAPPED
  32`, exit 0 — the M1.30/H69 base was not moved by this task.
* **Positive (the gate is green on the frozen tree).** `--corpus … --overlay
  …` exits 0, with `CORPUS DRIFT: DOCS BASE: 0 new / 0 gone / 125 moved` and
  `CORPUS OK: L3 OVERLAY: 0 new / 0 gone / 0 moved` — the 125 docs moves are
  H69 prose drift (warn), and the l3 overlay matches its live scan exactly.
  The frozen rows are a function of the image's bytes: `--corpus` and
  `--overlay` compare the image SHA-256 (and the overlay's `scope`), not the
  path, so the gate runs from any `head256.img` with the same `92aa525d…`
  bytes.
* **Positive (the block discipline is not a bare-hex counter).** Appending the
  documented sec1 DATA address `0x00d53500` to an open block leaves the gate
  green (`L3 OVERLAY: 0 new`, exit 0); a live `fn` label whose VA is `0x0041c7e8` instead is
  `CORPUS STALE`, exit 1. A bare or `fn`-labelled US-build start
  (`0x00444540`, and a `fn` label whose VA is `0x004446f4`) is likewise green, and the committed overlay
  contains neither the data address nor any `US_BUILD_STARTS` member.
* **Negative (a synthetic l3 INSIDE fails).** `fn_audit --selftest` builds a
  synthetic `.pdata` table, cites `0x401048` (an `INSIDE`) from a fake l3
  document and asserts the gate exits 1; the same run with `0x401040` (the
  `START`) exits 0. `selftest.py --only fn_audit_l3` reproduces this with no
  image.
* **Negative (moved-only l3 drift warns, exit 0).** The `--selftest` overlay
  fixture moves the l3 row's `line` and asserts
  `CORPUS DRIFT: L3 OVERLAY: 0 new / 0 gone / 1 moved`, exit 0.
* **Negative (an `AMBIGUOUS` candidate change fails).** The overlay fixture
  freezes an `AMBIGUOUS` row with two benign candidates; a live pass that adds
  an `INSIDE` candidate is `CORPUS STALE`/`verdict change`, exit 1 (H72's
  comparison exercised through the l3 live pass, not just the docs one). A new
  l3 row and a gone l3 row each exit 1 in the same fixture block.
* **Negative (a docs-base failure is still a failure).** The same fixture
  changes a docs-base row's verdict while the overlay is clean and asserts
  `CORPUS STALE: DOCS BASE`, exit 1 — per-source results are ANDed.

### 4. Scope

Corpora counted: **targets 1 citation** (1 firmware_call target),
**firmware.md 59 citations** (46 unique VAs, 0 failing citations), **EXPs 770
citations** over 69 files with rows / 292 EXPs on disk (174 unique, 21 unique
`INSIDE`), **open TODO blocks 61 citations** over 18 contributing blocks (35
citation lines of 134 open blocks; 32 unique, 0 `INSIDE`). The run prints the
open-block split as `fn_audit: open blocks 134, contributing 18, citation lines
35`. Total 891 citations / 179 unique VAs, 295 files.

An open block is scanned with the **docs discipline**, so it contributes only
a live `fn`/`sub_` label, a documented correction `ctx` (its own arrow pair) or
a `CORRECTION_ONLY` pin — not every `0x…`. A data address, path offset, range,
string pointer or US-build VA is skipped: it is not a code citation a task can
"fix", and counting it was the round-1 false-positive storm (see
`docs/research/fn-audit-2026-11-13.md`, "Review fixes"). Out of scope: closed
`TODO.md` blocks, `docs/research/todo-history-*`, `docs/format/*.md` other than
`firmware.md`, and `tools/*_l3.py` (all in the docs base).

### 5. Falsifier

Stated in the Hypothesis: a non-reproducible summary; a moved-only l3 drift
that fails; a new/gone/candidate change that passes; an overlay row attributed
to the docs base; an l3 correction line counted `INSIDE`; or any movement in
the docs `--scope docs` summary.

## Interpretation

- **FACT:** `--scope l3` covers four corpora with parsers (targets,
  `firmware.md`, 292 EXPs, 134 open blocks / 18 contributing) and exits 1 on
  `INSIDE`; its
  snapshot is reproducible byte-for-byte.
- **FACT:** the docs base is unchanged. `--corpus … --overlay …` exits 0 on
  the unchanged tree, a moved-only drift in either layer warns and exits 0,
  and a new/gone row or a verdict change in either layer exits 1.
- **OBSERVED:** the l3 overlay's frozen `INSIDE` is the append-only register,
  not a baseline failure: the gate would be permanently red if EXPs counted as
  correctable, so the overlay freezes them and the gate protects the *change*
  (new citations and class changes still exit 1). This differs from the docs
  base by design, and is the only reading of the block's "exit 1 on `INSIDE`"
  that keeps an append-only corpus gate green without hiding a new mid-function
  citation: a new `INSIDE` arrives as a `new` citation and fails.
- **OBSERVED:** H72's candidate-set gate is exercised on real l3 rows (all six
  `AMBIGUOUS` rows hold an `INSIDE` candidate) and its synthetic control
  (candidate gain → exit 1) is in `--selftest`.
- **FACT:** the open-block corpus uses the docs discipline: a bare data
  address, path offset, range, string or US-build VA is not a citation, so the
  gate cannot go red on a reference no task can fix.
- **OBSERVED:** the 21 EXP-only `INSIDE` VAs are historical labels; the
  register records each as `accepted data/append-only` in
  `docs/research/fn-audit-2026-11-13.md`, so Done-when's "task ID that fixes
  it" names an append-only note, never a `done` task.
- **UNKNOWN:** whether the M8.E1 flag test is a function start in build B or
  C; the docs discipline no longer cites it as code, and M1.20's all-module map
  decides.

## Conclusion

`--scope l3` is implemented and wired into `tools/selftest.py` as two units:
`fn_audit_l3` (image-free synthetic INSIDE must fail, START must pass) and
`fn_audit_l3_image` (the real gate on the committed overlay, `SKIP` when the
image is absent). The overlay is frozen to
`docs/research/fn-audit-l3-corpus-2026-11-16.json` (`6adb8d5b…`), the gate
applies H69 per source, and the register
`docs/research/fn-audit-2026-11-13.md` lists every remaining
`INSIDE`/`GAP`/`UNMAPPED` with its true start and disposition. The docs base
and its snapshot are untouched; a fresh docs snapshot is **not** needed. The
open follow-up is the 21 EXP-only `INSIDE` labels' append-only correction
notes (the gate sees each as a deliberate class change and requires a
re-freeze); every open-block code citation is already correct/`CORRECTED`.
