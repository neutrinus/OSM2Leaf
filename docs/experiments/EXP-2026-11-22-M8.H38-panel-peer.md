## Question

Can one host peer expose `tap`, `drag` and `key` behind a single control
socket, encoding events in the format the EU2011 firmware actually consumes,
with a self-test and a working negative control?

## Hypothesis

Yes: the decoded 6-byte `IOCTL 0x800b205c` record and the KeyType 3 VK table
are enough to build a peer without any QEMU patch; out-of-range input must be
refused. **Falsifier:** the peer's sample bytes differ from the documented
example, the control socket does not answer `OK`, or a bad coordinate is
silently accepted.

## Method

1. **Sample and hash.** Tool-only task; no vendor bytes read or written. The
   upstream firmware image hash that backs the contract is quoted above.
2. **Commands.**

```bash
python3 tools/ze0_peers/panel.py --selftest
python3 tools/selftest.py --only ze0_peers.panel
python3 tools/ze0_peers/panel.py tap 400 240 key MAP
python3 tools/ze0_peers/panel.py tap 900 240
S=$HOME/projekty/leafre-work/scratch/m8.h38-panel
mkdir -p "$S"
rm -f "$S/panel.sock" "$S/events.txt" "$S/panel.log"
python3 tools/ze0_peers/panel.py --control "$S/panel.sock" --out "$S/events.txt" --forever >"$S/panel.log" 2>&1 &
for i in $(seq 1 30); do [ -S "$S/panel.sock" ] && break; sleep 0.1; done
python3 -c "import socket; p='$S/panel.sock';
for line in [b'tap 400 240\n', b'tap 900 240\n']:
 s=socket.socket(socket.AF_UNIX,socket.SOCK_STREAM); s.connect(p); s.sendall(line); print(s.recv(1024).decode().strip()); s.close()"
sleep 0.3
cat "$S/events.txt"
kill %1
```

3. **Controls.** *Positive*: `encode_sample(400, 240, '1')` equals the record
   read from `kepdrv.dll` (`0x9001f0003100` = `x=400`, `y=240`, status `'1'`);
   `key MAP` resolves to VK `0x17` from the verified table. *Negative*: x=900,
   y=481, negative/float coordinates, status `'2'`, unknown key and a bad
   drag all raise `PanelError`; the control socket answers `ERR x 900 out of
   range 0..800` and emits **no** event. A wrong example byte or an accepted
   out-of-range tap would have refuted the claim.
4. **Scope.** One new stdlib tool, 32 selftest checks, one auto-discovered
   suite, one AF_UNIX control-socket exchange (2 commands, 1 connection each),
   one CLI batch and one rejected CLI batch. No QEMU run, no firmware bytes
   read by the tool, no vendor data written. The SCI3 frame grammar (M8.H35)
   and the live gdb/QMP bridge (M8.H39) are out of scope.
5. **Falsifier.** Different sample bytes, `ERR` for a valid tap, or an
   accepted out-of-range coordinate. None occurred.

## Observations

- `panel.py --selftest`: `selftest: PASS (0 failure(s))`, 32 `ok` lines.
- `tools/selftest.py --only ze0_peers.panel`:
  `tool:ze0_peers.panel PASS 0.03s`, `passed=1 failed=0 skipped=0`.
- Documented sample reproduced byte for byte:
  press `9001f0003100`, release `9001f0003000` (6 bytes each).
- `tap 400 240 key MAP` stdout:
  `touch 9001f0003100 0`, `touch 9001f0003000 100`,
  `key 0x17 down 0`, `key 0x17 up 80`; exit 0.
- `tap 900 240`: `panel: tap 900 240 -> ERR x 900 out of range 0..800`, exit 1.
- Control socket: first connection `OK tap 400 240 2 events`, second
  connection `ERR x 900 out of range 0..800`; `events.txt` contains only the
  two valid `touch` lines.
- Key table: `MAP 0x17`, `ENTER 0x0d`, `ESC 0x1b`, raw `0x0d` accepted;
  `--long` hold 600 ms vs 80 ms default.

## Interpretation

- **FACT:** The peer emits the firmware's exact 6-byte touch record with
  ASCII status and refuses inputs outside 0…800 / 0…480.
- **FACT:** The control socket matches `tools/ze0_ui.py`'s `peer_command`
  contract: one command per connection, answer starting with `OK` or `ERR`.
- **FACT:** `tools/selftest.py` auto-discovers `tools/ze0_peers/*.py`, so the
  new peer is in the standing gate without a parser edit (Done when satisfied).
- **HYPOTHESIS:** A drag is press → repeated press samples at moving
  coordinates → release; the driver's `MOUSEMOVE` after the button is down is
  not yet confirmed at L4 (M8.H39).
- **UNKNOWN:** The SCI3 frame grammar and the runtime AUI HWND; the peer's
  event stream is the contract for H39's gdb/QMP bridge, not a serial frame.
- **Deviation from precheck:** `docs/firmware/lcddrv.md` is absent from this
  checkout, so the "three documents exist" precheck cannot be satisfied as
  written. `docs/firmware/touch.md` §3.1 covers the display-unit ingress
  needed here and `docs/firmware/keys.md` covers key names, so the work
  proceeded; this is not a blocker because Done when does not depend on that
  file.

## Conclusion

`tools/ze0_peers/panel.py` implements `tap`, `drag` and `key` with one control
interface, emits the documented touch sample and the verified VK table, and
passes 32 self-test checks including the out-of-range negative control.
Claims C-7350–C-7359 record the facts; M8.H39 will consume the event stream
to inject at L4.
