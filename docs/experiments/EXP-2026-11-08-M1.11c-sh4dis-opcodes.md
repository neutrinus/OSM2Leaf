## Question

Can `tools/sh4dis.py` decode MOVT (`0x0n29`), SHAR (`0x4n21`), SHLD
(`0x4nmC`) and SHAD (`0x4nmD`) in little-endian SH-4 code, so that the five
M4.16b instruction addresses in the RDSTM directory walk functions
(`0x003f51e0`, `0x003f56bc`, `0x003f5e10`) are no longer `.word`?

## Hypothesis

The four opcodes can be added to the existing pinned-LE decoder without
changing any previous decode, and the five M4.16b instruction sites named by
C-2302 (the code gaps, not pool/after-rts `.word`s) will decode to the
expected mnemonics on the real Navi.exe image. `0x014a` at `0x003f52e2` in the
`fn 0x003f51e0` window is not one of these opcodes and should remain `.word`.

**Falsifier:** any of the five M4.16b instruction sites still decodes as
`.word`; any pinned M1.11/M1.14 check (`--selftest`, `nk.exe --check-real`,
the existing `Navi.exe --check-real` pins) regresses; or a BE reading of the
same bytes decodes MOVT/SHAR/SHLD/SHAD as the LE meaning (the convention
remains pinned through `read_u16`/`ENDIAN_STRUCT`).

## Method

1. **Sample and hash.** `IMG256` as above, SHA-256
   `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`,
   268,435,456 bytes. VA binding is through `cerom.py` (image A,
   `--image-start 0x200200`, `Navi.exe` sec0 uncompressed), not a fitted delta.
2. **Commands.** Run from the repository root (image path adjusted to the local
   archive):
   ```bash
   IMG=/home/marek/projekty/OSM2Leaf/archive/head256.img
   python3 tools/sh4dis.py --selftest
   python3 tools/sh4dis.py "$IMG" Navi.exe --image-start 0x200200 --check-real
   python3 tools/sh4dis.py "$IMG" nk.exe --image-start 0x3e00200 --check-real
   for va in 0x003f52dc 0x003f56fe 0x003f5746 0x003f5e1a 0x003f5e1e; do
     python3 tools/sh4dis.py "$IMG" Navi.exe --image-start 0x200200 --va $va --count 1
   done
   python3 tools/sh4dis.py "$IMG" Navi.exe --image-start 0x200200 --va 0x003f52e2 --count 1
   python3 tools/claims_check.py
   python3 tools/selftest.py
   ```
3. **Controls.** *Positive*: `--selftest` pins `movt r0` (`0x0029`, `0x0n29`),
   `movt r3` (`0x0329`), `shar r2` (`0x4221`, `0x4n21`), `shld r0,r0`
   (`0x400c`, `0x4n0c` form), `shld r0,r3`/`shld r1,r3`, `shad r0,r0`
   (`0x400d`, `0x4n0d` form), `shad r1,r3` (`0x431d`), `shad r3,r2` (`0x423d`);
   `Navi.exe --check-real` pins the five M4.16b sites as `(word,text)` and
   asserts each is not `.word`; `nk.exe --check-real` and all prior selftest
   cases (BE trap, M1.8/M1.14 pins, 65,536-halfword totality) still pass.
   *Negative*: the BE-trap selftest case still fails the prologue check on
   swapped bytes (LE convention unchanged); `0x014a` at `0x003f52e2` decodes as
   `.word 0x014a` (outside the four-opcode scope, not silently mis-decoded as
   MOVT/SHAR/SHLD/SHAD). The full 65,536-halfword decode-without-raising
   invariant still holds (the new cases narrow `.word` coverage, they do not
   add exceptions).
4. **Scope.** Decode-only change to `tools/sh4dis.py` (four opcodes) plus
   selftest/check-real pins. Real-image scope is five instruction VAs in
   uncompressed `Navi.exe` sec0 of the EU 2011 build A IMG256 head; no
   compressed section is read as code. The RDSTM directory walk itself, the
   `0x00d53500` schema table, and any record-to-coordinate join are not run and
   are not claimed. Corpus for the real pin: 5 instruction addresses (a
   targeted, named set from C-2302), not a population sweep.
5. **Falsifier.** Any of the five addresses still `.word`; any regression in
   `sh4dis --selftest`, `nk.exe --check-real`, or the pre-existing
   `Navi.exe --check-real` pins; or `0x014a` mis-decoded as one of the four
   new opcodes.

## Interpretation

- **VERIFIED (synthetic/encoding):** `sh4dis.py` decodes MOVT `0x0n29`, SHAR
  `0x4n21`, SHLD `0x4nmC` and SHAD `0x4nmD` with the pinned little-endian
  convention (`read_u16`/`ENDIAN_STRUCT` unchanged). The SHLD/SHAD forms take
  `(Rm,Rn)` with `m` in bits 4–7 and `n` in bits 8–11 (C-2650).
- **VERIFIED (real image):** on IMG256 Navi.exe build A, the five M4.16b code
  gaps named by C-2302 decode to the expected mnemonics and are not `.word`;
  `0x014a` at `0x003f52e2` remains `.word` (C-2651).
- **OBSERVED (scope):** this removes the C-2302 decoder-coverage blocker for
  those instruction forms. It does not run the RDSTM directory walk, does not
  decode the `0x00d53500` schema table, and does not establish a
  record-to-coordinate join. M4.16b's done-when (≥20 records mapped, named join
  key, random-key control) remains unmet; M4.16d remains the join path
  (C-2652).

## Conclusion

`tools/sh4dis.py` now decodes the MOVT/SHAR/SHLD/SHAD opcodes used by the
RDSTM directory functions, pinned by `--selftest` and by real-image checks at
the five M4.16b addresses on IMG256 Navi.exe A. `nk.exe` pinned checks and the
full 65,536-halfword totality invariant are unchanged. `docs/research/claims.md`
gains C-2650–C-2652. The decoder-coverage part of C-2302 is closed for these
forms; the directory walk and join questions stay with M4.16b/M4.16d.
