## Question

Does the registered `cmp_ind` firmware path — the `runner.py` targets, not
only the stand-alone tool — return page `0x840ba0` byte-identical to
`cmpind.decode` for the factory, S1 and S2 `POINT010` pairs, and reject the
corrupt-`.ind` and swapped `+4`/`+8` controls, on each build it is registered
for?

## Hypothesis

M9.11's closeout (EXP-2026-11-09) ran `cmp_ind_reader` on the EU2011 head;
that should reproduce. The US target `cmp_ind_reader_us2011` (M1.22) should
do the same on the US2011 head.
**Falsifier:** any of the 3 pairs not PASS through a registered target on its
own build, or a control that passes as a decode.

## Observations

**First pass, before the runner change** (`663a19d`): `cmp_ind_reader` on
EU2011 PASS for all three pairs; `cmp_ind_reader_us2011` on US2011 **BLOCKED
for all three**: `no mapped region covers 0x00000000..0x00000004 (text,
sec@00581000, sec@013bc000, …)`. `_run_firmware_call_target` called
`chunk_decoder_l3.run_firmware` without `tgt=`, so every target ran the EU
engine and EU helper VAs whatever its `build` and `entry.va` said; the US
target could only block.

## Interpretation

M9.11's done-when holds through the registered path on the build it was
closed on (EU2011, `cmp_ind_reader`), re-measured from the US card here. The
US target registered by M1.22 had never run its own engine through the
runner — C-3538 counted it as a registered target and the `--build-corpus`
row is `BLOCKED` by design (no inputs), so nothing showed it. With the
target's build routed, the US engine passes the same three pairs and two
controls, and a wrong `entry.va` is refused. The S2 page here is an
equivalent instance of M5.13b's edit (same rename, same page, different
deflate bytes from a different zlib), not the pinned file; the decode
verdict does not depend on which deflate produced the chunk, since the
reference is `cmpind.decode` of the same pair.

## Conclusion

M9.11 stays `done`: factory/S1/S2 page `0x840ba0` byte-identical and both
controls behave, through `cmp_ind_reader` (EU2011) and now also through
`cmp_ind_reader_us2011` (US2011); sec1 table declared, and equal to the
image's own table (C-4181). `runner.py` routes a `firmware_call` target's
build (fix in this task).
