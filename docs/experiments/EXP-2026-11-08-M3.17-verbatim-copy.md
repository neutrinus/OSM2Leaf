## Question

For a Poland map card, which of the files named by M3.17 (`BICON001`,
`OPNG`, `SPEECH`, `TMC`, `REFER002`, `RDSTM001`) can be copied verbatim, and
which carry region- or market-specific content that must be emptied or
generated instead?

## Hypothesis

Asset containers (`BICON001`, `OPNG`) and voice (`SPEECH`) are vendor/market
assets, not map data, so they copy verbatim for an EU-base Poland card.
`REFER002` and traffic config (`TMC`/`XMD`) are market- or region-bearing and
need market-aware handling. `RDSTM001` (`RDSTM001.DAT` + `LCTBL001.DAT`)
carries region-specific TMC/location/name content and must be generated for the
target region (writers already tasked).

**Falsifier:** any of these files is shown by the firmware/format record to
embed map-geometry, per-tile routing, or country-shard content that a Poland
card must rewrite, which would flip its verdict from `copy` to `generate` (or
`empty`, only if a safe empty form is evidenced).

3. **Controls.** *Positive (must generate):* `RDSTM001.DAT`/`LCTBL001.DAT` are
   region-specific (TMC location records + place/street names for the covered
   area; C-882–C-886, C-889, `rdstm.md`) — the same decision class as
   `POINT`/`ADDRE` content that M5.18 must generate, and it already has writer
   tasks M5.19/M5.17. *Negative (must not be mis-classified as generate without
   evidence):* `BICON001`/`OPNG`/`SPEECH` are rendering/voice assets, not map
   records (`assets.md`, C-213, C-980–C-989, C-1027 context) — a "generate"
   verdict for them would require an evidenced map dependency, which the cited
   records do not show. Cross-market control: US vs EU uses `XMD` vs `TMC` and
   different `REFER002`/shard content (C-070, C-138/C-143/C-156) — so "copy
   verbatim" is scoped to the *same market family*; a cross-market copy is not
   safe.
4. **Scope.** The six M3.17 files/dirs (`BICON001`, `OPNG`, `SPEECH`, `TMC`,
   `REFER002`, `RDSTM001` = `RDSTM001.DAT` + `LCTBL001.DAT`) plus the

   files; decoding `OPNG`/`SPEECH`/TMC payloads; the EV schema needed to rebuild
   `REFER002` (schema OBSERVED, undecoded); any hardware/L3 claim.
5. **Falsifier.** Verdicts are retracted if: `REFER002` is shown to be required
   absent/empty for map boot (reader evidence), if `SPEECH`/`BICON001` are shown
   to gate routing/map display (firmware reader), or if an EU-base Poland card
   is shown to need country-shard remapping of `COORD`/`ZCODE`/`ICODE` (they
   cover the EU region set; Poland is shard 021 within it).

## Interpretation

- **VERIFIED (from cited records):** `BICON001`/`OPNG`/`SPEECH` are
  assets (icons/images/voice), not map/routing data, so a verbatim copy does
  not inject wrong map content (assets.md, C-213, C-980–C-989, C-1027). `RDSTM001`
  records are TMC/location attributes (no speed/one-way/restrictions) and
  `LCTBL001` is a regional name database — both are region-specific and must
  be generated for a Poland/target-region card (C-882–C-886, C-889,
  C-1790–C-1839). US/EU market split exists for traffic/config (`XMD` vs `TMC`)
  and card contents (C-070).
- **OBSERVED:** `REFER002` is a separate EV layer with a longer, undecoded
  schema (C-138, refer.md); EU 2011 ships it with 15 POINT shards. `SPEECH`
  language sets vary by image and EU 2011 lacks `PL` (assets.md).
- **HYPOTHESIS:** An empty/absent `REFER002` would boot safely on firmware that
  does not require the EV layer — untested (no reader evidence locating a hard
  requirement). Therefore "empty" is not chosen without evidence; market-correct
  copy is the safe verdict.
- **UNKNOWN:** TMC/`reception.dat` internal semantics; whether any
  `REFER002`/asset file is opened unconditionally by a reader that rejects a
  missing file (no located reader VAs for these copy assets in the matrix).

## Conclusion

For an **EU-base Poland card** (same market family as EU 2011): `BICON001`,
`OPNG`, and `SPEECH` **copy** verbatim (assets, not map data); `TMC/reception.dat`
**copy** (EU market traffic config); `REFER002` **copy** the EU `REFER002`
(region-appropriate EV layer; do not copy US `REFER002` across markets, and do
not empty without reader evidence because the EV schema is undecoded);
`RDSTM001.DAT` and `LCTBL001.DAT` **generate** for the target region (tasks
M5.19, M5.17 already exist). `COORD001`/`ZCODE0nn`/`ICODE001` are
**copy-eligible** for an EU-base Poland card (G6 scoping). No new "generate"
task is required beyond M5.17/M5.19 (and M5.18 for POINT/ADDRE).

`docs/research/reader-coverage.md` rows 7–9, 21–22, 24–28 are updated with the
M3.17 verdicts and reasons; `docs/research/claims.md` gains C-2220–C-2229.
