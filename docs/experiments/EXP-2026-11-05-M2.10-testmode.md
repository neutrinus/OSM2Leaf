## Question

Which diagnostics in `TestMode.exe` (image C) are relevant to map data
(version screens, SD tests, map-code display, log dumps), and how is test mode
entered?

Version screen reads (from `CVersionReadFunction`): `GetMainTestVersion`,
`GetSubTestVersion`, `GetBootIplVersion`, `GetBootBaseVersion`,
`GetBootEtherVersion`, `GetBootEnhanceVersion`, `GetNk1Version`,
`GetNk2Version`, `GetMapVersion`, `GetAudioSoftwareVersion`,

`GetDisplayVersion`, `GetBluetoothVersion`, `GetXmVersion`, `GetVcanVersion`,
`GetOpeningImageVersion`, `GetUpdateNkVersion`, `GetSkin1..4Version`, plus the
matching `Get*Pno` parts-number reads. These call `CApi_GetSoftwareVersion` /
`CApi_GetPartsNumber` / `CApi_GetDeviceVersion`.

SD test path (`CAgingManager`): `RUNNING [SD R/W (%s)]`, `INSERT TEST DISC`,
`SD ERR`, `MECHA ERR`, `SLOPE ERR`, `SDCARD_*_STATUS`, reads/writes
`\UserSD\AGING.csv`, `\SystemSD`, `\SystemSD2`. Log writing uses
`CreateFile`/`SetFilePointer`/`WriteFile` with error logging.

Entry into test mode: `TestMode.exe` is listed in image C's launch table at
file offset `0x55559cc` (VA `0x883557cc`) as `\windows\TestMode.exe`
(inside `commctrl.dll`'s module list). `TestMode.exe` imports
`CApi_GetBootMode` / `CApi_SetBootMode` / `CApi_GetBootModeEx`, so entry
appears to be gated by a boot-mode flag set before/around launch; no
key-combination string was found in the binary, so the exact physical trigger
(service-mode menu vs. boot flag) is not determinable from static strings.

## Interpretation

- **OBSERVED:** `TestMode.exe` exposes a menu dispatcher (`0x0002b17c`),
  a title/status screen (`0x0002bd04`), an ageing/SD R/W test
  (`0x0002d8b8`…), a version screen reading software/parts numbers including
  `GetMapVersion`/`GetMapPno`, a log writer (`0x0002e678`/`0x0002ea94`),
  SD folder/version helpers (`0x00041294`) and flash access
  (`0x00043030`).
- **HYPOTHESIS:** map-code / map-version diagnostics on the bench can use the
  `GetMapVersion`/`GetMapPno` version screen and the `SD R/W` ageing test;
  exact menu numbers and screen layouts require a running unit or emulation.
- **UNKNOWN:** exact menu numbers, key sequence to enter test mode, and the
  compressed sections (`0x0004f000`, `0x0005b000`) which may hold additional
  menus (decoder unsupported).

## Conclusion

Test mode in image C provides version (incl. map version/parts number), SD
R/W ageing, log dump and flash diagnostics usable on the bench. Entry is via
the image C launcher list plus a boot-mode flag; physical trigger unknown.
No tool change.
