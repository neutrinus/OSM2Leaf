## Question

Does the existing ingest tool, run unchanged on the real Dolnośląskie
extract, produce an IMF v1 file that `tools/imf_check.py` accepts, and what
are the ways and nodes per `highway=*` class in it?

## Hypothesis

The M5.1 synthetic fixture (C-1030) and the PBF reader already cover the
framing a Geofabrik extract uses, so the region run needs no code change.
The region is about 1.8° × 3° and all of it lies in one `BxxRyyR` cell
(`B48R058R`, C-2344 scope), so the output should have one tile and
`imf_check` should report 0 errors. Failure mode expected: a decoder detail
that the fixture does not exercise (for example a blob or string-table layout
only a real file has). **Falsifier:** `imf_check` reports any error on the
region IMF; or a recount of the emitted IMF disagrees with the ingest report's
way counts; or the downloaded PBF's MD5 differs from Geofabrik's published
`.md5`.

   `count_hw.py` (save as `$P/count_hw.py`) recounts the emitted IMF
   independently of the ingest tool's own counters:

```python
import json, sys
from collections import Counter, defaultdict

path = sys.argv[1]
types = Counter()
ways_by_hw = Counter()
nodes_by_hw = defaultdict(set)
all_way_nodes = set()
node_records = set()
restrictions = Counter()
with open(path, encoding="utf-8") as fh:
    for line in fh:
        rec = json.loads(line)
        kind = rec.get("type")
        types[kind] += 1
        if kind == "node":
            node_records.add(rec["id"])
        elif kind == "way":
            hw = rec["tags"]["highway"]
            ways_by_hw[hw] += 1
            nodes_by_hw[hw].update(rec["nodes"])
            all_way_nodes.update(rec["nodes"])
        elif kind == "relation":
            restrictions[rec.get("tags", {}).get("restriction", "?")] += 1
print("records:", dict(types))
print("node records with way membership:", len(node_records & all_way_nodes),
      "node records total:", len(node_records))
print("way nodes referenced but no node record:", len(all_way_nodes - node_records))
print("%-16s %10s %10s" % ("highway", "ways", "nodes"))
for hw in sorted(ways_by_hw, key=lambda h: -ways_by_hw[h]):
    print("%-16s %10d %10d" % (hw, ways_by_hw[hw], len(nodes_by_hw[hw])))
print("TOTAL ways", sum(ways_by_hw.values()), "distinct way nodes", len(all_way_nodes))
print("relation restriction values:", dict(restrictions))
```

   `drop_node.py` (save as `$P/drop_node.py`) is the negative control: it
   copies the IMF and removes the first node record that the first way
   references.

```python
import json, sys

src, dst = sys.argv[1], sys.argv[2]
# Negative control: drop the first node record that a way references.
first_ref = None
with open(src, encoding="utf-8") as fh:
    for line in fh:
        rec = json.loads(line)
        if rec.get("type") == "way":
            first_ref = rec["nodes"][0]
            break
dropped = 0
with open(src, encoding="utf-8") as fin, open(dst, "w", encoding="utf-8") as fout:
    for line in fin:
        if not dropped and f'"type":"node","id":"{first_ref}"' in line:
            dropped += 1
            continue
        fout.write(line)
print("dropped", first_ref, dropped)
```

3. **Controls.** *Positive (synthetic):* `python3 tools/selftest.py` must
   list `tool:osm_ingest PASS` and `tool:imf_check PASS`. *Positive (real):*
   `imf_check` on the untouched region IMF must report `ok: true`. *Negative
   (real):* the copy with one referenced node removed must fail with E011 on
   every way that references that node. A negative without the positive
   control is not a result; both are below.
4. **Scope.** Corpus: the whole Dolnośląskie PBF, 2,602,961 ways in total
   (362,811 kept + 2,240,150 dropped as not drivable). The tool does not count
   PBF nodes, so there is no "all nodes" figure. Excluded by design (the
   tool's filter, not by this EXP): footways, cycleways, paths, steps and
   pedestrian zones; all node tags (POI and address records are M5.1c);
   `type=restriction` relations whose members did not survive. Not covered:
   a cell border (C-2344), POI/address/place data (C-2347), and any
   compile/route/render step (out of scope for M5.1b).
5. **Falsifier.** Stated above under Hypothesis: any `imf_check` error on the
   region IMF, a recount that disagrees with the ingest report, or an MD5
   mismatch with Geofabrik.

## Interpretation

The existing ingest tool, unchanged, reads the real Dolnośląskie PBF and writes
an IMF that `imf_check.py` accepts with no errors (C-2343). The counts are
independently reproduced by the recount (C-2342), and the same bytes come out
of a second run (C-2346, M-confidence because the other tool hash is missing).
The negative control fails loudly with the expected E011 on exactly the three
ways that reference the removed node (C-2345), so the validator is not
passing trivially. The hypothesis holds: no code change was needed.

Two limits. (1) This extract lies in one `BxxRyyR` cell, so the splitter at a
border (M5.2) is still covered only by the synthetic fixture (C-2344). (2) The
IMF has no POI or address records (C-2347), which is the M5.1c gap. Warnings
are the expected missing-name and missing-maxspeed notices, not errors.
