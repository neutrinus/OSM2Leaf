# EXP-2026-11-23-M4.95: Road `ref`/shield writer

- **Status:** done
- **Date:** 2026-11-23
- **Sample:** EU 2011 factory `MAPAL001/B48R058R.DAT` and OSM IMF
  `dolnoslaskie.imf.jsonl`; hashes in O1.
- **Tools:** python3 3.15.0, `zlibinfo.py` stamp in O2; `tools/tilewriter.py`
  (this task), `tools/ze0-viewer/tools_ze0/fa_encode.py`,
  `tools/ze0-viewer/ze0_decode.py` (`parse_names_section`, the oracle),
  `tools/ze0-viewer/harness.py`, `tools/drstr_ze0.py`, `tools/l2check.py`,
  `tools/selftest.py`, `tools/zlibinfo.py`.
- **Claims:** C-8560–C-8569
- **Supersedes:** none
- **Superseded by:** none

## Question

Can a generated EU 2011 `B48R058R` carry Polish OSM road references as the
factory's `2=REF` name part, with the M4.90 shield family preserved, while a
no-`ref` build stays byte-identical to the pre-change writer on the same runtime?

## Hypothesis

A pure `road_label(tags)` function in `tools/tilewriter.py` can compose the
factory's `1=NAME;2=REF` text (or a bare `2=REF` for nameless ways) using M4.90's
mapping, and `fa_encode.names_section` already writes the length word, so no
byte hand-patch or new grammar is needed. The E-route suffix must be
**family-scoped**: appending `E 67` to `S8` would yield `2=S8:E67`, which M4.90's
table calls `other-alpha` (no `S\d+:E\d+` family). Falsifier: a written `2=REF`
decodes to a different family than the factory road with the same ref, or the
no-ref build differs by one byte from the pre-change build.

## Method

1. **Sample and hash.** O1 quotes `sha256sum` of both inputs and the IMF header
   (source, timestamp, ODbL-1.0). No vendor bytes enter the repo.
2. **Commands.** `S` is `~/projekty/leafre-work/scratch/M4.95`; run from the
   worktree root. The pre-change reference build used a detached worktree at
   commit `9fa14593` under `$S/pre-change` (same runtime, same factory, same
   `no-ref` IMF).

   ```bash
   S=/home/marek/projekty/leafre-work/scratch/M4.95
   T=/home/marek/projekty/leafre-work/m5.29-factory-root/MAPAL001
   I=/home/marek/projekty/leafre-work/osm/dolnoslaskie.imf.jsonl
   sha256sum "$T/B48R058R.DAT" "$I"; head -n 1 "$I"
   python3 tools/zlibinfo.py
   python3 tools/tilewriter.py --selftest
   python3 tools/ze0-viewer/harness.py info "$T/B48R058R.DAT" | grep -c '2='

   # re-quote IMF counts and the M4.90 factory query (scripts in Method of
   # EXP-2026-11-22-M4.90-road-shields and navigator-method.md in scratch)
   python3 - "$I" <<'PY'
   import json, sys, collections
   p = sys.argv[1]
   refs = collections.Counter(); irefs = collections.Counter(); both = collections.Counter()
   tile = collections.Counter()
   for line in open(p, encoding='utf-8'):
       o = json.loads(line)
       if o.get('type') != 'way' or o.get('tile') != 'B48R058R':
           continue
       t = o.get('tags', {}); r = t.get('ref', ''); ir = t.get('int_ref', '')
       tile['ways'] += 1
       if r: refs[r] += 1; tile['with_ref'] += 1
       if ir: irefs[ir] += 1; tile['with_int_ref'] += 1
       if r and ir: both[(r, ir)] += 1
       if r in ('A4', 'S8', '94'):
           tile['%s_named' % r] += bool(t.get('name'))
   print('TILE B48R058R', dict(tile))
   print('REF', {k: refs[k] for k in ('A4', 'S8', '94', 'DK94')})
   print('INT_REF', {k: irefs[k] for k in ('E 40', 'E 67')})
   print('BOTH', {k: both[k] for k in (('A4', 'E 40'), ('S8', 'E 67'), ('94', 'E 40'))})
   PY
   python3 "$S/m4_90_probe.py" "$T/B48R058R.DAT"

   # stream-filter a tiny one-variable IMF (ref in {A4,S8,94}); keep only node
   # records those ways reference; make a name-stripped ASCII-positive variant
   python3 - "$I" "$S/with-ref.imf.jsonl" "$S/no-ref.imf.jsonl" <<'PY'
   import json, sys
   src, withp, nop = sys.argv[1:4]
   want = {'A4', 'S8', '94'}
   ids = set(); keep = []
   for line in open(src, encoding='utf-8'):
       o = json.loads(line)
       if o.get('type') == 'header': keep.append(o)
       elif o.get('type') == 'way' and o.get('tile') == 'B48R058R':
           t = o.get('tags', {})
           if t.get('ref') in want:
               keep.append(o); ids.update(str(n) for n in o.get('nodes', []))
   node_lines = []
   for line in open(src, encoding='utf-8'):
       o = json.loads(line)
       if o.get('type') == 'node' and o.get('tile') == 'B48R058R' and str(o.get('id')) in ids:
           node_lines.append(json.dumps(o, ensure_ascii=False))
   way_lines = [json.dumps(o, ensure_ascii=False) for o in keep if o.get('type') == 'way']
   for path, strip in ((withp, False), (nop, True)):
       with open(path, 'w', encoding='utf-8') as f:
           f.write(json.dumps(next(o for o in keep if o.get('type') == 'header'), ensure_ascii=False) + '\n')
           f.write('\n'.join(node_lines) + '\n')
           for line in way_lines:
               o = json.loads(line)
               if strip:
                   o.get('tags', {}).pop('ref', None); o.get('tags', {}).pop('int_ref', None)
               f.write(json.dumps(o, ensure_ascii=False) + '\n')
   print('tiny IMF nodes=%d ways=%d header=1 referenced_ids=%d' % (len(node_lines), len(way_lines), len(ids)))
   PY
   # ASCII-positive variant: drop the OSM `name` tag from both IMFs (writer
   # UTF-8 / reader latin-1 mojibake in the 1= part is pre-existing, M5.7).

   # pre-change baseline (in $S/pre-change worktree), then both current builds
   python3 tools/tilewriter.py "$S/no-ref.imf.jsonl" --cell B48R058R \
       --factory "$T/B48R058R.DAT" --country 616 --out "$S/pre-change-no-ref.DAT"
   python3 tools/tilewriter.py "$S/with-ref.imf.jsonl" --cell B48R058R \
       --factory "$T/B48R058R.DAT" --country 616 --out "$S/with-ref.DAT" --json > "$S/with-ref.json"
   python3 tools/tilewriter.py "$S/no-ref.imf.jsonl" --cell B48R058R \
       --factory "$T/B48R058R.DAT" --country 616 --out "$S/no-ref.DAT" --json > "$S/no-ref.json"
   sha256sum "$S/pre-change-no-ref.DAT" "$S/no-ref.DAT" "$S/with-ref.DAT"

   # oracle: read-only probe over clarion_tile/clarion_bg/parse_names_section
   # (complete $S/dump_refs.py is in navigator-method.md, Method part 2)
   python3 "$S/dump_refs.py" "$S/with-ref.DAT" "$S/no-ref.DAT" "$T/B48R058R.DAT"

   python3 tools/ze0-viewer/harness.py info "$S/with-ref.DAT"
   python3 tools/ze0-viewer/harness.py verify "$S/with-ref.DAT"
   # $S/card: symlink tree of m5.29-factory-root with MAPAL001/B48R058R.DAT
   # pointing at $S/with-ref.DAT; the tile grew, so rebuild DRSTR from that tree
   python3 - "$S/card" <<'PY'
   import sys; from pathlib import Path
   sys.path.insert(0, 'tools'); import drstr_ze0
   card = Path(sys.argv[1]); dr = card/'DRSTR001.DAT'
   assert dr.is_symlink(), 'refusing to overwrite a non-symlink'
   dr.unlink(); built = drstr_ze0.build(card); dr.write_bytes(built)
   print('rebuilt DRSTR in scratch card:', len(built), 'bytes')
   PY
   python3 tools/l2check.py --root "$S/card" --no-golden --no-cmp --skip-mutation \
       --tiles B48R058R.DAT --semantic-tiles B48R058R.DAT --json "$S/l2.json"
   python3 tools/selftest.py
   ```

   The mapping selftest (inside `tools/tilewriter.py --selftest`) asserts these
   rows; they are quoted from its output in O3.

   | OSM tags | label | M4.90 family |
   | --- | --- | --- |
   | `name='', ref='A4', int_ref='E 40'` | `2=A4:E40` | motorway+E |
   | `name='', ref='S8', int_ref='E 67'` | `2=S8` | S-road |
   | `name='', ref='DK94'` | `2=94` | numeric (synthetic) |
   | `name='', ref='94'` | `2=94` | numeric (real positive) |
   | `name='', ref='', int_ref='E 40'` | `''` | none |
   | `name='X', ref='A4', int_ref='E 40'` | `1=X;2=A4:E40` | motorway+E |

3. **Controls.** *Positive*: the re-run M4.90 factory query (O5) shows `A4:E40`
   129, `S8` 4, `94` 19 and `DK94` 0, proving each ref exists in the factory
   grammar; the oracle (O8) re-reads our written labels through the committed
   reader; the selftest mapping rows pass. *Negative*: the no-ref build equals
   the pre-change build byte for byte (O7); `ZZZ999` and `S8:E67` are absent
   (O8); `DK94` maps to `2=94`, never `2=DK94` (O3). A negative is reported only
   with these positives present.
4. **Scope.** EU 2011 level-1 names sections of the odd road partner in
   `B48R058R`; tiny IMF with 2,079 ways whose OSM ref is `A4`, `S8` or `94`.
   Excluded: levels 2–6 and `LEV3456R`, section 4 (the `section4_places.py`
   in-place-splice pattern only; no edit), other cards/years, and the firmware
   glyph reader / VA (rule 13). `harness.py` is unchanged; its `info` still has
   0 `2=` lines (O2/O9) and is context only, not the oracle.
5. **Falsifier.** Stated before the result: the task fails if a written `2=REF`
   maps to a different M4.90 family than the factory road with the same ref, if
   `no-ref.DAT` differs by one byte from the pre-change rebuild, if any of the
   three refs fails to appear, if a nameless ref-only way produces no label, or
   if `ZZZ999`/`2=S8:E67` passes. The `fa_encode.names_section` Stop condition
   is not triggered: it computes `len(text)` itself, so a composed label needs
   no hand-patch. **No claim of byte-identical reproduction of factory bytes**:
   the no-ref control is an A/A comparison on one recorded runtime, stamped in
   O2.

## Interpretation

- **FACT:** `road_label` composes the factory's names-section text; the six
  mapping rows, the family negative and the bare-`2=REF` reader round-trip all
  pass, and the oracle re-reads `2=A4:E40`, `2=S8`, `2=94` from our generated
  tile through `ze0_decode.parse_names_section`. `fa_encode.names_section`
  needs no change: it writes `>HHHHH` with `ln=len(text)`.
- **FACT:** the no-ref build is byte-identical to the pre-change writer on the
  same runtime (both SHA `2fb553ba…`, and both ASCII variants `b244448f…`).
  This is an A/A falsifier, not a claim about factory-compressed bytes: the
  runtime is zlib-ng, not stock zlib 1.3.1.
- **FACT:** the family-scoped suffix rule is necessary. All 180 `S8` ways carry
  `int_ref='E 67'`; an unconditional append would produce `2=S8:E67`, which
  M4.90's regex table classifies `other-alpha`, while the factory stores bare
  `S8` (4 occurrences). `A4` + `E 40` is stored colon-joined (129 occurrences).
- **OBSERVED:** nameless ref-only ways are written: all 681 A4 ways have no OSM
  name (O4), and the oracle's new `A4:E40` entries all have `name=''` (O8).
- **OBSERVED:** with non-ASCII OSM names the `1=` part shows mojibake
  (`Trasa BohaterÃ³w…`) because the writer encodes UTF-8 and the reader
  decodes latin-1; this is pre-existing M5.7 behaviour, not a ref defect. The
  name-stripped variant keeps the positive control clean.
- **HYPOTHESIS:** the firmware selects the shield glyph from the `2=` syntax as
  M4.90 proposed. No firmware VA or L3/L4 run is claimed (rule 13).
- **UNKNOWN:** which glyph each family draws; L3/L4 remains open.

## Conclusion

`tools/tilewriter.py` now emits M4.90's `2=REF` into the odd road partner's
names section, including bare refs for nameless ways, with a family-scoped
`int_ref` rule. The generated `B48R058R` decodes to `2=A4:E40`, `2=S8`, `2=94`
via the committed reader; the no-ref control is byte-identical to the
pre-change build; L2 semantic passes after the scratch card's DRSTR is rebuilt
for the grown tile. `docs/research/osm-pipeline.md` records the implemented
mapping. Firmware acceptance is not claimed.
