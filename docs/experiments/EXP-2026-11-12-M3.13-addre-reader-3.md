## Question

Can the `0xc000`-class header consumer `fn 0x003f56bc` be extended — downward
through its call graph and through a second signature family — to consuming
instructions for the ADDRE grammar fields (C-970–C-979), and does the L3 probe
on the mapped `0x14e8`/`ADDRE0` route fault in a classifiable way?

## Hypothesis

Exploratory. Falsifier for a positive result: if the `fn 0x003f56bc` family
contains no consumer of the M4.9 record-stream tokens (name/point/range/
trailer) and no L3-reachable ADDRE binding, the done-when stays unmet and the
correct outcome is a scoped negative per field.

## Method

1. `python3 tools/nk_decomp.py pdata IMG256 --module Navi.exe <VA>` on every cited
   VA (all VAs cited resolve to function records with sensible prologue/length;
   output leads with `Navi.exe sec2: 7596 function records, 0x32ed9c..0x558300`,
   i.e. the pdata table; it does not claim where the bytes live).
2. `tools/sh4xref.py --calls/--to` on the family; `tools/sh4dis.py` windows;
   `tools/va_class.py --resolve-with 0x3e00200` on the L3 faulting address.
3. Second signature family scoped to Navi.exe sec0 literal pools and the
   `0x003f5000`–`0x003f7000` REFER dispatch-callee window: `0x0000ff00`
   literal loads, `cmp/eq #0x40/#0xff/#0x03` after a byte-class load, `:;:`
   (`0x3a 0x3b 0x3a`), trailer marker (`0x0000f401` LE / `0x01f40000` BE),
   index magic (`0x0000204e` LE / `0x4e200000` BE), `0x1f4` literal.
4. `tools/l3_harness/runner.py --selftest`, then bounded PySh4 runs of
   `0x0040b358`, `0x0040114e`, `0x003f56bc`, `0x003f5d98`, `0x003f61bc` with
   zeroed globals.

- `fn 0x003f56bc` → **only direct call** `jsr 0x003f51e0` (`0x003f56cc`).
- `fn 0x003f51e0` → indirect `jsr @r3` at `0x003f51ec` via slot `0x0055d8f0`
  (`va_class --resolve-with 0x3e00200`: **IAT `OSMDLL.dll!taskIdSelf`**, not a
  reader) and `jsr 0x003f3a10` at `0x003f5298` (slot-vs-state compare against
  `0x00d5e4e4`/`0x00d5e474`, returns 0/-1; sec0, CODE).
- `fn 0x003f57a8` → `fn 0x003f51e0` only; returns `u16@(ctx+26)`.
- `fn 0x003f5a98` → `fn 0x003f51e0` only; returns `u16@(ctx+24)`.
- `fn 0x003f5e10` (called by `0x003f5eec`/`0x003f5f48` and `0x003f61bc`):
  pure arithmetic accumulator — parity-adjusted `r5+1` count, loops over a
  `u16` array selecting high/low bytes by index parity, returns `shll` of a
  running sum. No immediate, no token marker, no grammar constant; an
  index/offset checksum, not a token walker.
- `fn 0x003f5ac4` (dispatched via `fn 0x003f5870`/`0x003f580c`): parallel
  structure to `fn 0x003f56bc` — same `w>>13` type extraction, same sub-table
  walk (`u16@(r4+24)` limit, `u16@(r4+22)` base, 2-byte stride,
  `u16@(entry+12)` compare), returns `r8 + 2*(r3+1)` or -1. It is the `0xa000`-
  class/type≤4 sibling, not a token consumer (its window contains no
  `#0x40`/`#0xff`/`#0x03` compares at all).
- `fn 0x003f5810` (target of `fn 0x003f5870`'s table): walks `0x00d53500` at
  `+56` (`0x003f5820`) against arg `r4`, bounds `u16@(e+20)`/`u16@(e+24)` —
  another slot-family resolver, no record bytes.

## Interpretation

- The mapped family (`fn 0x003f5d98` ↔ `fn 0x003f61bc`) is an **indexed
  record accessor**: resolve slot → locate entry by index via `u16@(entry+12)`
  → read a parity-selected byte at an offset derived from the entry (calls
  `fn 0x003f57a8` for count/limit and `fn 0x003f5e10` for an element checksum).
  It consumes the **tag class** of the record header, never the record-stream
  token bodies.
- Second signature family is a clean **negative** for the M4.9 token grammars
  in code: no literal pool references the range (`:;:`), trailer (`01 f4 00
  00`), or container (`4e 20 00 00`) markers, and no family instruction
  byte-loads-then-compares `#0x40`/name markers. Combined with pass-1 byte
  grammar and pass-2 mask/stride results, the ADDRE *record-stream* reader —
  if any — is reached only through runtime state (`0x00d53500` slots fed by
  sec1 BSS code, whose writer is unlocated) or not present in sec0 at all.
- **Honest bottom line**: done-when is NOT met. C-973 tag-class remains the
  only mapped field. C-975/C-977/C-970 may now be marked "never read (sec0
  literal-pool search, exhaustive for those literal families)". C-971/C-972/
  C-974/C-976 are "not found", not proven absent — different encodings
  (e.g. computed compares, table-driven dispatch) cannot be excluded by
  literal search; absence in the family window is scoped, not universal.
