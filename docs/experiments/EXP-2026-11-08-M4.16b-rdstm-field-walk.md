## Question

Can the C-884 per-record length/offset directory walk be reproduced from bytes on EU 2011 IMG256 (Navi.exe build A) to recover true TMC field boundaries (functions `0x003f56bc`, `0x003f5e10`, schema `0x00d53500`), and then re-run `tools/rdstm_place.py` on decoded fields (location/area/front/rear/inter-section) to map **≥20 decoded records** to tile/mesh/coordinates with a **named join key** and **~0 random-key control**?

## Hypothesis

After M1.11c (MOVT/SHAR/SHLD/SHAD pinned), the C-884 walk functions in readable Navi.exe sec0 can be statically reproduced and the walk executed to produce true per-record field boundaries, enabling placement testing on decoded TMC fields. **Falsifier:** if the schema table consulted at `0x00d53500` is not in a readable/extractable section with current inputs (e.g. in compressed `.data` with no verified sec1-byte path), or walk-site code cannot be reproduced, the walk cannot be instantiated to recover true boundaries and `rdstm_place` cannot be re-run on decoded fields — done-when not met (blocked). An observation that `0x00d53500` resolves to uncompressed readable bytes and the walk sites decode/execute to yield boundaries would refute the blocked conclusion.

## Interpretation

- **FACT (VERIFIED):** C-884 functions and call graph are in readable Navi.exe sec0 (build A), and M1.11c `--check-real` confirms no `.word` gap at the named M4.16b walk pins (decoder-coverage for MOVT/SHAR/SHLD/SHAD at those sites closed, consistent with C-2651/C-2652).
- **VERIFIED:** Schema target `0x00d53500` is consulted by `0x003f51e0` but resolves by `cerom va2file` as unmapped and lies inside **Navi.exe sec1 COMPRESSED `rw-` `.data`** (`va 0x55d000`, covering `0x00d53500`). With current inputs/tooling (M1.2f blocked; no verified sec1-byte decompression/oracle path here), schema bytes and the field lengths/counts the walk consumes are **unreadable**.
- **OBSERVED (negative):** The C-884 walk is **not reproduced from bytes to recover true TMC field boundaries** on the available inputs, and `rdstm_place.py` cannot be re-run on decoded fields; therefore no ≥20 decoded-record mapping, no named join key, and no ~0 random-key control were produced. This is **impossible with current inputs / blocked by compressed `.data` (sec1)**, not a proof of impossibility in general.
- **HYPOTHESIS (unchanged in substance):** Decoded TMC record fields carry no coordinate field; any coordinate placement likely routes through the TMC location table chain (M4.16d). Join remains open.

## Conclusion

M4.16b done-when is **not met**. The static route to the C-884 code is open (readable sec0, call graph and M1.11c opcodes confirmed), but the schema descriptor at `0x00d53500` is in **Navi.exe sec1 COMPRESSED `rw-` `.data`**, so schema bytes/field lengths are unreadable with current inputs and the directory walk cannot be instantiated to recover true per-record field boundaries or to re-run `rdstm_place.py` on decoded fields. Status is **blocked (impossible with current inputs / blocked by compressed `.data` sec1)** with a negative EXP recorded. `docs/research/claims.md` C-2300–C-2309 updated (partial, no field boundaries/record offsets/join key).
