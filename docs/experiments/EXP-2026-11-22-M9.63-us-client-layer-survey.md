## Question

Which layer of the US2011 map client (file layer, POI record, tile mount,
section-2/record-block path) already has an L3 run on `main`, on what input and
with which verdict — so that M9.61 can be reduced to the layers that do not?

## Hypothesis

Half of the surface already runs (C-4651 `vcard_l3.py boot --build us2011` and
M9.10 `runner.py run poi_record_decode`), while `datask_l3.py mount` was
expected to have no `--build` (the task Precheck said `grep -c -- --build` = 0).
**Falsifier (set before the runs):** a layer marked NOT RUNNABLE that has a
runnable tool on `main`, or a RUNNABLE row whose US run disagrees with its EU
control.

## Plan

1. **Approach.** Survey, not implementation. One run per layer: (a) file layer
   `vcard_l3.py boot`/`sweep` with the US build on the US card and the EU card;
   (b) POI record `runner.py run poi_record_decode` on `archive/us256.img` with
   `--expect-name`; (c) tile mount `datask_l3.py mount --build us2011`;
   (d) section-2/record-block path (M9.53 record read + M9.58 `LOC_map` shape
   walk). EU2011 `Navi.exe` = positive control, US2011 = subject. Record tool,
   input, exit code, verdict and missing entry point by name per layer.
2. **Source of each layer's signature/verdict.**
   - (a) the build switch and the `40 directories, 285 files` / `20 dirs,
     189 files` volume-table verdict come from M9.14 (EXP-2026-11-20-M9.14,
     C-4651) and reader-coverage row 4; no new firmware search.
   - (b) the `point_name_v1` target, `HANA HEALTH CENTER` (US factory) and the
     wrong-name/wrong-build refusals come from M9.10
     (EXP-2026-11-20-M9.10, C-2140–C-2147) and reader-coverage row 10; the EU
     control for position arithmetic comes from M3.34 `poi_position_l3.py`.
   - (c)/(d) the US data-access VAs and read shape come from M9.61
     (EXP-2026-11-21-M9.61, C-6362–C-6368) and reader-coverage rows 17–20;
     the M9.58 shape walk VAs come from M9.66 (C-6770–C-6779). No VA is
     rediscovered here.
3. **Files.** Write only this EXP and one sentence per layer in

4. **Intended Done when.** Four-row table `layer / tool / US2011 input /

   any run (output in Observations). POINT010 `.cmp`/`.ind` pairs are read in

   Observations.

   `$S` the scratch directory.

   python3 tools/datask_l3.py mount archive/head256.img --card-image "$EU" --position 51.70,17.45 --request 0xa6cdd6be --bytes
   python3 tools/datask_l3.py mount archive/us256.img --build us2011 --card-image "$EU" --position 51.70,17.45 --request 0x26c18ab2 --bytes

3. **Controls per layer.**
   - (a) positive EU: EU build on EU card → the same `40 dirs, 285 files` and

4. **Scope.** Four layers, one card position (51.70,17.45) for (c)/(d), one POI
   page per card for (b). No new firmware search, no VA attribution, no new
   `--build` implementation, no card recompression. Excluded: the launcher

5. **Falsifier.** As in Hypothesis. In particular the task's `(c)==0` Precheck
   is re-measured; if it is >0 the NOT RUNNABLE expectation is refuted and the

## Interpretation

- **FACT:** all four rows have a positive EU control and a negative control.
  Every RUNNABLE row's US run agrees with its EU control on the
  build-independent keys: (a) volume SHA-256 `58835fc7…6aad0` identical;
  (b) 1000/1000 names and addresses equal display text on both builds;
  (c) 28 reads at the same file/position/length, `state 2, progress 1`, 46 tile
  files, `0x802`; (d) 29 reads, sub-5/sub-3 reply (sub-3 pointer differs by
  build's buffer address, `0xcb913c` vs `0xd8b53c`, as in M9.61).
- **FACT:** the task's `(c)` and `(d)` expectation is **refuted**. M9.61 merged
  (PR #426, `441fe96d`) before this survey: `datask_l3.py` has `--build
  {eu2011,us2011}` and `tools/datask_l3.py mount --help | grep -c -- '--build'`
  prints `2`, not `0`. Both the tile mount and the M9.53 record-block read are
  RUNNABLE on US2011. The falsifier fired: M9.61 is smaller than the task
  believed.
- **OBSERVED:** the one genuinely NOT RUNNABLE remainder is the M9.58 half of
  layer (d): `tools/locmap_l3.py` has no `--build`, refuses the US image with
  exit 3, and holds only the EU2011 chain VAs (`0x00425f40`, `0x0042613c`,
  `0x00421548`, `0x0041f3dc`); no US pair is in `build_targets.py`.
- **HYPOTHESIS:** the remaining US-client surface that is still unexercised is
  the downstream shape/link walk, not the data-access layer.
- **UNKNOWN:** whether the US build's router/renderer accept the EU card's
  data; this survey does not run them.
