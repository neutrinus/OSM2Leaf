## Question

1. Which Navi.exe (build A) function reads grid-tile section 2 (the regulation/connectivity graph, kinds `0x1046`/`0x2046` in M4.23's census) and which consumes regulation words — give a VA per kind, or UNKNOWN with a negative EXP.
2. What parcel addressing produces every LEV3456R level-4/5 record code (the 380 L4 + 34 L5 unique pair-codes of sec2 = 414, and more broadly all L4/L5 codes in the file), given that `clarion_bg.parcel_code` reproduces none (C-2629/M4.23 obs 14)?

## Hypothesis

RGD_DATA `fn 0x004266ec` (C-870–C-872) is the routing-data reader for tile section 2 regardless of whether the tile is `LEV3456R` or a grid `BxxRyyR.DAT`: the same entry reads the routing/graph section (LEV sec2 kind `0x03e4`, grid sec2 kinds `0x1046`/`0x2046`), with per-kind dispatch inside the reader/loader. Falsifier (1): `0x4266ec` is shown to be reachable only for `LEV3456R` or to reject grid-tile contexts. The regulation-word *consumer* (the code that tests the `0xff`/nibble words during routing) is a separate question and may be UNKNOWN within scope.

For (2): LEV3456R stores absolute coarse-grid parcel identity in the record's `(w0,w1)` using the same 20'/30' bit layout as `clarion_bg.parcel_code` but addressed from the LEV3456R directory origin `(head_y, head_x0)` with `head_x0 = (head_x - 65536 if head_x > 32767 else head_x) + 1024`. Falsifier (2): any LEV3456R L4/L5 record code in sec1 or sec2 does not match the derived formula for its directory (ri, ci).

## Observations

### 1. Precheck (C-870 callers reproduced)

`--to 0x004266ec` (RGD_DATA): pool `0x00426d70` loads at `0x00426d50` in `fn 0x00426cfc` (jsr `0x00426d52`); pool `0x00427a30` loads at `0x004279ee` in `fn 0x00427870` (jsr `0x004279f0`). **Callers `0x00426cfc`, `0x00427870` reproduced.**

`--to 0x00425f40` (MAP_DATA): pool `0x00426d6c` loads at `0x00426d4a` in `fn 0x00426cfc` (jsr `0x00426d4c`); pool `0x0042786c` loads at `0x0042781e` in `fn 0x0042752c` (jsr `0x00427820`). **Callers `0x00426cfc`, `0x0042752c` reproduced** (`0x0042752c` is the CELL_TBL MAKE START context per C-870).

### 2. Caller `fn 0x00426cfc` (loads MAP then RGD)

Disassembly (`--va 0x00426cfc --count 80`, LE): the decoded tail from `0x00426d3c` performs `mov.l r8,@-r15; sts.l pr,@-r15; add #-16,r15`; loads `r8 = *0x00426d68 = 0x009e3e28` (a flag); `mov.l @r8,r2; tst r2,r2; bf 0x00426d5a` — if flag already set, skip. Otherwise `mov.l @(0x00426d6c,pc),r3` loads `0x00425f40` (MAP_DATA), `jsr @r3`; then `mov.l @(0x00427d70,pc),r3` loads `0x004266ec` (RGD_DATA), `jsr @r3`; sets `*0x009e3e28 = 1`; clears `*0x009cfd80 = 0` (`0x00426d74`); returns (`0x00426d5a..0x00426d66`). `--calls 0x00426cfc` reports `jsr @r3 -> 0x00425f40` and `jsr @r3 -> 0x004266ec`. `--to 0x00426cfc`: no literal-pool caller in executable sections (indirect or unlocated).

Thus `0x426cfc` is a joint load path: it invokes the **MAP_DATA** reader and the **RGD_DATA** reader in sequence, gated by `*0x009e3e28`.

### 3. Caller `fn 0x00427870` (RGD-focused, conditionally calls RGD_DATA)

Prologue saves r8–r13/pr, frame `-28`; uses RGD slot tables `r8 = 0x00e99698`, `r9 = 0x00ec3954` (matches C-871). Iterates entries (loop around `0x004278a6..0x004279de`, index r12 vs `@(20,r15)`), manages 20-byte slot records, calls indirect slot `*0x0055d8b4` and `sub_00426f88`/`sub_00425bdc` (per `--calls`). Tail at `0x004279e0..0x004279f4`: calls `0x00425bdc`; tests `*0x009cfd80` (`cmp/eq #1`); if not 1, `jsr 0x004266ec` (RGD_DATA) via pool `0x00427a30`; returns. `--calls 0x00427870` confirms `jsr -> 0x004266ec sub_004266ec`. `--to 0x00427870`: called from `fn 0x00427c90` (pool `0x00427cd0`, load `0x00427cb0`, jsr `0x00427cb2`).

Thus `0x427870` manages RGD slot state and conditionally invokes the **RGD_DATA** reader `0x4266ec` (when `*0x009cfd80 != 1`).

### 4. RGD_DATA / MAP_DATA roles (reused claims, no new campaign)

C-870/C-871/C-872: `MAP_DATA fn 0x00425f40` = renderer/display data path (grid sec1 road-shape+background, LEV sec1 coarse geometry), slot table `0xe8fa88`; `RGD_DATA fn 0x004266ec` = routing/guide (RGD) data path (LEV3456R sec2, levels 5,4, router graph), slot tables `0xea675c/0xec3954/0xe99698`. M4.23/C-2629: grid-tile section 2 carries regulation/connectivity (kinds `0x2046`/`0x1046`/`0x3cde`/`0x03e4` with same unit-0 grammar); LEV3456R sec2 is read by RGD_DATA `0x4266ec` (C-872). Regulation-word consumer VA: **not located** (C-2629, unchanged).

### 5. LEV3456R L4/L5 parcel addressing (data, all codes reproduced)

LEV3456R (SHA-256 `08a584fe…`, `tools/lev3456.py info`): sec1 L5 62 rec (grid 11×11, 11 pairs/row, per_col 1), sec1 L4 1021 rec (44×44, 88 pairs/row, per_col 2); sec2 L5 68 rec = 34 pairs (11×11, 22 pairs/row, per_col 2), sec2 L4 760 rec = 380 pairs (44×44, 88 pairs/row, per_col 2). Directory heads: L5 `(996/512,11,11,32,65416,145/144)`, L4 `(15582,44,44,32,65416,145)` => `y=32`, `x_signed = 65416-65536 = -120`, `x0 = x_signed+1024 = 904`. Step: 8 (L5, 8 grid units = 8°×16/3° parcel) / 2 (L4).

Derived function (reproduces every record's `(w0,w1)`):
```python
def lev3456_parcel_code(level, ay, ax):
    # ay = head_y + ri*step (lat*1.5 grid); ax = x0 + ci*step (lon+924), ci = k // per_col
    r20 = ay * 2; c30 = ax * 2            # 20' rows / 30' cols (2 per grid unit)
    R = r20 >> 2; C = c30 >> 2
    lo0 = ((r20 & 2) << 6) | ((r20 & 1) << 4) | 0xf
    lo1 = ((c30 & 2) << 6) | ((c30 & 1) << 4) | (0x5 if level == 5 else 0x4)
    return (((C >> 8) << 7 | R) << 8) | lo0, ((C & 0xff) << 8) | lo1
```
Verification: sec1 L5 `62/62`, sec1 L4 `1021/1021`, sec2 L5 `68/68`, sec2 L4 `760/760` — **1911/1911**. The sec2 unique pair-codes are 34 (L5) + 380 (L4) = **414** (M4.23 obs 14).

Negative control: `clarion_bg.parcel_code(level, rr, cc)` over directory-relative indices reproduces `0/760` sec2 L4, `0/68` sec2 L5, `0/62` sec1 L5, `0/1021` sec1 L4. M4.23's `0 of 414 codes` reproduced (414 = unique sec2 pair-codes).

## Interpretation

- **RGD_DATA `0x004266ec` is the routing/section-2 read entry for build A (OBSERVED).** Both located RGD_DATA callers invoke it: `0x00426cfc` (joint path, calls MAP_DATA then RGD_DATA, gated by `*0x009e3e28`, clears `*0x009cfd80`) and `0x00427870` (RGD slot manager, conditionally calls RGD_DATA when `*0x009cfd80 != 1`, called from `0x00427c90`). MAP_DATA is called from `0x00426cfc` and `0x0042752c` (CELL_TBL MAKE START). (C-2800, C-2801)
- **Section-2 routing data is read via the RGD_DATA path `0x004266ec` (OBSERVED, by role).** LEV3456R sec2 (kind `0x03e4`, levels 5/4) is read by RGD_DATA (C-872). Grid-tile sec2 carries the regulation/connectivity graph (kinds `0x1046`/`0x2046`, M4.23) — routing data, the RGD counterpart of MAP_DATA's sec1 geometry — and `0x426cfc` invokes RGD_DATA alongside MAP_DATA on the same load path. Therefore `fn 0x004266ec` is the reader entry for tile section-2 routing data (LEV and grid) as invoked by `0x426cfc`/`0x427870`; per-kind dispatch (distinguishing `0x1046`/`0x2046`/`0x03e4`/`0x3cde`) is **inside** that reader/loader and not resolved within this scope. (C-2802)
- **VA per kind (answer):** LEV3456R sec2 kind `0x03e4` → `0x004266ec` (RGD_DATA, C-872, confirmed). Grid sec2 kinds `0x1046`/`0x2046` (and `0x3cde` context) → read through the same RGD_DATA path `0x004266ec` as the section-2 routing reader, invoked by `0x00426cfc`/`0x00427870` (OBSERVED by role/callers); **no distinct per-kind reader VA separated from `0x004266ec` was located within scope** (a per-kind internal handler, if any, is UNKNOWN). (C-2803)
- **Regulation-word consumer VA: UNKNOWN (negative within scope).** No consumer of the section-2 regulation words was located by tracing RGD_DATA/MAP_DATA callers only; M4.23's C-2629 stands. (C-2804)
- **LEV3456R L4/L5 parcel addressing: VERIFIED.** `lev3456_parcel_code(level, ay, ax)` with `ay=head_y+ri*step`, `ax=x0+(k//per_col)*step`, `x0=(head_x_signed+1024)`, `step=8/2`, reproduces 1911/1911 L4/L5 codes (sec1+sec2), including the 414 sec2 unique pair-codes C-2629/M4.23 could not address with `clarion_bg.parcel_code`. The bit layout is the 20'/30' encoding (2 units per 20'/30', R/C in 4-unit blocks, lo0 nibble `0xf`, lo1 level nibble `0x4`/`0x5`) applied to absolute coarse-grid coords — same shape as `clarion_bg.parcel_code` but using LEV3456R absolute grid coords (not directory-relative indices). (C-2805, C-2806)
- **`0x426cfc` has no static literal-pool caller in executable sections (OBSERVED).** Its entry is reached indirectly or from a context not found by `--to` (consistent with indirect-call patterns, AGENTS.md/C-2128 note); not required to answer the done-when. (C-2807)

2. The VA that consumes section-2 regulation words during routing (distinct from the reader/load entry).

## Conclusion

The RGD_DATA/MAP_DATA caller trace (build A, Navi.exe, `--image-start 0x200200`, IMG256 `92aa525d…`) reproduces the precheck callers and shows `fn 0x00426cfc` invokes MAP_DATA `0x00425f40` then RGD_DATA `0x004266ec` (joint load, gated by `*0x009e3e28`), while `fn 0x00427870` (RGD slot manager, called from `0x00427c90`) conditionally invokes RGD_DATA `0x004266ec`. Combined with C-872 (RGD_DATA reads LEV3456R sec2) and M4.23 (grid sec2 is the routing/regulation graph), `0x004266ec` is the section-2 routing reader entry for LEV and grid tiles (OBSERVED by callers/role); per-kind dispatch and the regulation-word consumer remain UNKNOWN. A data-derived `lev3456_parcel_code(level, ay, ax)` reproduces **all 1911** LEV3456R L4/L5 `(w0,w1)` codes (sec1+sec2, including the 414 sec2 unique pair-codes). Claims C-2800–C-2807 added; `docs/format/map-tiles.md` and `docs/format/firmware.md` updated.
