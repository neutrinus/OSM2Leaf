## Question

Does `mac.w @Rm+,@Rn+` (`0x4nmF`) run in PySh4 with the SH-4 manual's
semantics after `rm` is defined in `_exec_system`, and does the decoder audit
now notice a host exception instead of counting it as MODELLED?

## Hypothesis

The arm's only defect is the undefined `rm` (M9.48 side observation).
**Falsifier:** after the fix, a distinct-register `mac.w` row with mapped
memory does not give the manual's MACH:MACL and post-increments; or the same
row passes on the unfixed engine; or `isolate` against the pre-fix engine
names any form other than `mac.w`; or `compare` reports a disagreement or
drift on any of the three corpora.

## Observations

Engine diff (`engine.py`, `_exec_system` `mac.w` arm):

- `rm = regs["r%d" % m]` is now defined (Rm = bits 7-4, the `m` argument).
- While writing the selftest a second defect in the same arm appeared: it
  read the words with `_load_signed()`, which returns the 32-bit register
  image (`& M32`), so a negative word was multiplied as `0xFFFFxxxx`. With
  only `rm` defined, the row gives `mach = 0x1235` instead of `0x1`. Now
  `_sx(self._load(addr, 2), 16)`.
- Transcribed from the manual's `MACW` C code: `@Rn` first, then `@Rm`; with
  n == m the second word is at Rn+2 and Rn ends +4 (the old arm read the same
  address twice and added 2). S = 1 (SR bit 1) adds into MACL only,
  saturating at `0x7FFFFFFF`/`0x80000000`, MACH unchanged (the old arm
  ignored S). Both loads happen before any register write, so a fault on
  `@Rm` leaves Rn unchanged.

Self-tests: `engine.py --selftest` → `selftest: OK (23 checks, 2 skipped,
quick)`. Scratch copy without `rm`: `FAILED (1/25 checks)` —
`distinct registers …: name 'rm' is not defined`.
`decode_audit.py --selftest` → `OK` (includes `classify host NameError is not
MODELLED`, `classify mac.w modelled (M9.49)`, `compare: host crash is
executor drift`, and the 65,536-halfword drift loop on the new probe).
`div1_l3.py --selftest` → `OK`.
`selftest.py --only tool:l3_harness.engine,tool:l3_harness.div1_l3,tool:l3_harness,tool:l3_harness.watch`
→ `passed=4 failed=0`.

`decode_audit.classify()` now runs each opcode with a zeroed 4 KiB data page
at `0x0..0x1000` (registers start at 0) next to the 4 code bytes at
`0x1000`, and buckets a non-`EngineError` exception as IN_SCOPE_UNMODELLED.
On the pre-fix engine, old vs new `classify()` over all 65,536 halfwords
differ on exactly 256 opcodes, all `mac.w` (MODELLED → IN_SCOPE_UNMODELLED);
pre-fix vs fixed engine under the new `classify()` also differ on exactly
those 256.

Side observation (not changed here): `engine.py`'s `0x0nmF` arm is
`mac.l Rm,Rn` — a 32×32 multiply of the *register values*. The SH-4 opcode
`0000nnnnmmmm1111` is `MAC.L @Rm+,@Rn+`: two memory longs and post-increment
(there is no register-form `mac.l`). The census counts 4,164 EU2011 Navi,
189 EU2011 nk and 4,839 US2011 Navi `mac.l` instructions as modelled with the
wrong semantics. The new probe page does not expose it (the arm never loads).

## Interpretation

- **FACT:** `mac.w` now runs per the manual's `MACW` code (distinct
  registers, n == m, S = 0/1, fault ordering), and the row fails on the
  pre-fix arm.
- **FACT:** against the pre-fix engine only `mac.w` changed outcome (224
  halfwords that differ under `isolate`'s register states); `compare` is 0 / 0
  on all three corpora.
- **FACT:** C-3593's "models `mac.w`" was wrong: every `mac.w` with a
  readable `@Rn` raised `NameError`, and with a negative word the product
  would also have been wrong. The decoder audit could not see it because its
  probe faulted first; it now maps a data page and treats host exceptions as
  unmodelled.
- **FACT (code reading, manual encoding):** the engine's `mac.l` is not the
  SH-4 `mac.l @Rm+,@Rn+`. **UNKNOWN:** whether any L3 target ran a `mac.l`;
  4,164 EU2011 Navi halfwords `0x011f` (= `mac.l @r1+,@r1+`) look like data.

## Conclusion

The `mac.w` `NameError` is fixed together with two more defects in the same
arm (sign of the words, n == m / S handling); `isolate` lists only `mac.w`;
`compare` stays 0 / 0 on EU2011 Navi, EU2011 nk and US2011 Navi;
`decode_audit` now reports a host crash as drift (17 / 1 / 14 opcodes on the
pre-fix engine). New task M9.51: `mac.l` is modelled as a register form.
