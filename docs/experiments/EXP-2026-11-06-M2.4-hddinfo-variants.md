## Question

For each of the 89 length-preserving `HDD_INFO` variants
(`tools/hddinfo_variants.py`), does the firmware accept or reject it, and how
does that compare with `tools/hddinfo.py classify` (model M0)?

## Method

Generated 89 variants (content edits + line permutations) of the factory file.
Ran `hddinfo.py classify <sys_copy> <variant>` (model M0, HYPOTHESIS) on each:
offline result = 66 ACCEPT / 23 DIFFERENT MAP CODE. Full table in the commit
(`m2.4-results.tsv`, not committed — vendor-derived; summary counts only).

Firmware verdicts require executing `Navi.exe` `fn 0x004e7b8c` (reader) and the
comparator `sub_004e84c4`/`sub_004e989c` (M2.2) on each variant, i.e. the
first real L3 target (M9.6), which is not available in this session.

## Blocker

No L3 real target for the HDD_INFO comparator exists yet (M9.6 open). The
offline model-M0 classification is the best available prediction.

## Claims

- C-750: `hddinfo_variants.py` generates 89 length-preserving variants of the
