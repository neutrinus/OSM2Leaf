## Question

Can the VCAN sub-microcontroller be represented as a host peer with a small
vehicle state, the five requested setters and a control socket — without
pretending that the unresolved UAT3 wire grammar is known?

## Hypothesis

Yes: a decoded-layer record (`u32 LE CAN id` + 8 data bytes) with the 17 ids
of `can.md` supports the state model and a byte-exact wire claim is *not*
needed for a selftest. **Falsifier (task):** the encoder disagrees with a
documented example frame. **Second falsifier:** `selftest.py` does not
discover the tool, or a wrong input (unknown id, oversized payload, bad
enum/range) is silently accepted.

## Method

1. **Sample and hash.** No image is read. The frame ids and the fact that
   field offsets are unknown come from M8.H49, which did read
   `archive/head256.img` (SHA-256 `92aa525d…a007f9`).
2. **Commands.**

   ```bash
   python3 tools/ze0_peers/vcan.py --selftest
   python3 tools/selftest.py --only ze0_peers.vcan
   python3 tools/ze0_peers/vcan.py --selftest-only       # no QEMU, no socket
   ```
3. **Controls.** *Positive:* `encode_frame(0x280, u16(1234))` produces the
   id `0x280` with `1234` tenths of km/h, and all five setters change the
   emitted frames. *Negative:* an unknown id, a 9-byte payload, a 12-byte
   frame with an unknown id, speed `999`, and `ignition maybe` are all
   refused (5/5), plus a separate decode check of id `0x777`.
4. **Scope.** Tool only. No boot, no chardev traffic, no firmware bytes. The
   UAT3 wire framing stays UNKNOWN (C-7469): the 12-byte record is an
   explicit **decoded-layer model**, and the bit/byte placement of each
   signal is marked HYPOTHESIS in the source and in `can.md`.
5. **Falsifier.** A wrong example frame, an accepted bad input, or no
   auto-discovery would have failed the run above.

## Interpretation

- **FACT:** the tool exists, is stdlib-only, is auto-discovered, and its
  examples and negatives reproduce with the two commands above (O1, O2).
- **OBSERVED:** the 17-id set and the decoded-frame shape come from M8.H49.
- **HYPOTHESIS:** every field offset and bit placement used to build the
  five example frames (speed tenths at bytes 0-1, R/N gear code, low-beam
  flag, ignition bit, SoC byte). They are editable models, not claims about
  the firmware.
- **UNKNOWN:** the UAT3 wire framing; M8.H51 cannot claim that this peer's
  bytes were accepted by `CAN.dll` until an L4 trace exists.
