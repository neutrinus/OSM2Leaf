# EXP-2026-11-06-M4.7: Renaming a POI to a different-length name

## Summary

A REFER001 `POINT` record whose name text changes length stays structurally
valid: the page is a chain of self-describing records, so only that record's
`len2` byte has to be updated and the rest of the page shifts. The renamed
catalogue passes `tools/l2check.py`, and every byte outside the one name page
stays unchanged.

- **Status:** done (offline); hardware pending
- **Date:** 2026-11-06
- **Sample:** EU 2011 image
  `105e2032e480e8ba162a2a9d4b6624cb1dafee380379a9908f3f101b15076307`
  - `REFER001/POINT032.DAT.cmp`
    `1dac3ae6d330414686a69df6749b3bb8b563029ce00ecefad1bba02170f1bba7`
  - `REFER001/POINT032.DAT.ind`
    `5108c90b7d9aaab2dfe9b8486f59f1f99161937a6f92cb7a14e47e25a771ca9e`
  - `DRSTR001.DAT`
    `2b7f2fb8901bf18a2ad48334154a6d604c23a775083cb84754626d64417b25f6`
  - Cross-year check: 2014 EU image
    `4a8a21f477e9fc511f94406976b8d67037842f9c043f49ab24e1adc82d6da89b`
    (extracted root `_root2014`)
- **Claims:** C-950–C-958
- **Supersedes:** the "same length only" limit stated by

- **Superseded by:** none

## Question

Can a POI name be renamed to a **different byte length** and still pass L2,
without rebuilding the file, its index or the directory?

## Hypothesis

The POINT name page is not a table of fixed slots: each record starts with a
one-byte length (`byte[1] = size/2`) and the next record begins right after
it. If the name is the last field of the record, a name-length change only
needs that length byte rewritten; the following records shift inside the same
inner zlib stream, and nothing outside the stream refers to their absolute
positions. Then `.DAT` logical size, `.ind` chunking and the DRSTR entry stay
unchanged.

## Inputs

| Item | Value |
| --- | --- |
| Route | `REFER001/POINT032.DAT` (Vatican shard), page `0x4200` |
| Record | record 8 at page `+0x2a0`, 80 bytes, `tag=0x68`, `len2=40` |
| Old text | `VATICAN MUSEUM` (14 bytes) |
| New text | `OSM2LEAF PROBE POI` (18 bytes, delta +4, even) |
| Page space | compressed 655 B, next stream at `0x4500`, 768 B reserved |
| Tools | `tools/mutate_refer_poi.py --resize`, `tools/validate_mutation.py`, `tools/l2check.py` |
| Vendor data | EU 2011 root outside the repo; nothing committed |

## Method

```bash
# 1. tool self-test (no vendor data)
python3 tools/mutate_refer_poi.py --selftest

# 2. framing census (read-only; source is quoted below)
python3 - <<'EOF'
import sys, zlib
sys.path.insert(0, "tools")
import cmpind_writer, mutate_refer_poi
from pathlib import Path
root = Path("/home/marek/projekty/leafre-work/root/REFER001")
pages = records = 0
for cmp_path in sorted(root.glob("POINT*.DAT.cmp")):
    blob = cmpind_writer.CmpFile.from_files(cmp_path, cmp_path.with_suffix(".ind")).decode()
    pos = 0
    while (page := blob.find(b"\x78\x9c", pos)) >= 0:
        d = zlib.decompressobj()
        inner = d.decompress(blob[page:])
        used = len(blob[page:]) - len(d.unused_data)
        pages += 1
        try:
            mutate_refer_poi.parse_page(inner)
            records += 1
        except mutate_refer_poi.PageError:
            pass
        pos = page + max(used, 1)
print(f"{records} of {pages} POINT zlib pages are record chains")
EOF

# 3. resize the name (writes a new pair + decoded .DAT to /tmp/opencode/mut-resize)
python3 tools/mutate_refer_poi.py \
    REFER001/POINT032.DAT.cmp REFER001/POINT032.DAT.ind /tmp/opencode/mut-resize \
    --page 0x4200 --resize --old "VATICAN MUSEUM" --new "OSM2LEAF PROBE POI"

# 4. offline acceptance
python3 tools/validate_mutation.py REFER001 /tmp/opencode/mut-resize POINT032.DAT \
    --page 0x4200 --page-len 0x300 --drstr DRSTR001.DAT --drstr-dir REFER001 \
    --inner-page 0x4200

# 5. L2 (full)
TMPDIR=/home/marek/projekty/leafre-work/tmp \
  python3 tools/l2check.py --root /home/marek/projekty/leafre-work/root
```

Controls:

* the same pair with the original same-length rename
  (`VATICAN MUSEUM` → `OSM2LEAF PROBE`) must still produce `.cmp` 5,119 B;
* a shorter rename (`VATICAN MUSEUM` → `VATICAN MUSE`, −2) must also pass;
* an odd delta (`VATICAN MUSEUMS`, +1) must be refused;
* the 2014 root must pass the same new L2 check with its own fixture.

Parsing both pages with `mutate_refer_poi.parse_page` and zipping the record

renamed record is exactly

## Interpretation

- **FACT:** a POINT name page is a chain of `tag,len2` records of `2*len2`
  bytes, packed without gaps, each ending `ff ff`; the text is the printable
  suffix before that marker (some records end the text with NUL, some at the
  marker).
- **FACT:** a +4 name rename needs only record 8's `len2` byte changed; all
  39 records still parse, record 8 is the only changed record, the other 38
  are byte-identical, and the page plain size grows by exactly 4.
- **FACT:** the `.DAT` logical size (20,224), the one-chunk `.ind` and the
  `DRSTR001.DAT` entry are unchanged; all 664 changed decoded bytes are inside
  `0x4200`–`0x4500` (the page's 768-byte reservation).
- **FACT:** the same construction passes on 1,000-record 2014 and 2016 pages,
  and an odd delta is refused because the framing stores `size/2`.
- **FACT:** a same-length rename still reproduces the historical 5,119-byte
  `.cmp`; the resized `.cmp` is 5,126 bytes because the whole single chunk is
  re-encoded with stock zlib level 6, not because the payload grew.
- **HYPOTHESIS:** the unit finds a POI record by the record chain (or by the
  `(page, slot)` id), not by a byte offset inside the page. This is consistent
  with the page having no offset table, but only hardware (or a decoded
  reader) can confirm it.
- **UNKNOWN:** whether the unit accepts a recompressed page or a changed POI
  name at all; whether the name must be NUL-terminated in every record; the
  `body` grammar of a record; the `ADDRE`/`LCTBL` side of the rename path
  (C-957, C-958).
- **NOT CLAIMED:** that the renamed name is displayed, that a street/address
  rename works, or that the card still boots.

## Conclusion

`REFER001` POI display names can be renamed to a different length with a
one-byte framing update. `tools/mutate_refer_poi.py --resize` does it,
`tools/l2check.py` now proves it on every run (`refer_rename_resize`), and
`docs/format/refer.md` documents the page framing. The offline side is
complete; display and boot remain hardware questions.
