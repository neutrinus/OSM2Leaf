## Question

H112 asked for a rebuilt graph before use. With the rebuilt graph and M3.24's
table edges, which functions below each REFER family's access path read memory
in a loop and are not shared with the other families? Take the top ten per
family: `POINT`, `ADDRE`, `LCTBL`, `INTER`/`FRWAY` and `ZCODE`/`ICODE`/`COORD`.
Also, does the graph close the `.cmp` chain from `0x0041c044` up to the file
open?

## Hypothesis

A family's reader lies in the subtree of its access path. It has a backward
branch around a data load, and the other families do not reach it. Ranking by
(shared-with-others, loops, byte/word loads, depth) puts the known readers in
the top ten.

**Falsifier:**
- (a) The rebuilt graph loses one of the three known edges, or loses edges of
  the old graph.
- (b) A dynamically confirmed reader (M9.38 / C-3607 for `LCTBL`, C-4694 for
  `ICODE`) ranks below ten in its own family.
- (c) More than 30 % of calls in the REFER subtree are unresolved (task Stop
  rule).

## Method

1. **Graph fix (`tools/callgraph.py scan_function`).** The old scan tracked
   register literals in one linear pass. A `jsr @Rn` after a join, where `Rn`
   was loaded on two paths (`bra`/`bt`/`bf` and their delayed forms),
   resolved to whichever load came last in address order, or to nothing.
   The new scan:
   - saves the register state (literal set and IAT-name set per register) at
     every forward branch, taken after the delay slot;
   - joins the saved states as a union at the target. The fall-through state
     is joined too, unless the previous instruction was `bra`/`rts`/`jmp`;
   - keeps the linear state at a block that only a backward branch enters;
   - emits every literal and every import a register can hold at a `jsr`/`jmp`;
   - counts a call as unresolved only if the register holds neither.

   It also records three features per function, leaves included:
   - `bw`: byte or word data loads;
   - `loops`: backward branches whose body holds a byte or word load;
   - `lloops`: the same with any data load.
2. **Queries (new).**
   - `loops graph VA [--depth N] [--edges E]` lists the subtree with its
     features.
   - `rank graph --family NAME=VA[,VA] … [--depth N] [--top 10] [--edges E]`
     ranks the candidates of each family. The candidates are the functions
     within depth N that have `loops` or `lloops`. `share` is the number of
     other `--family` root sets that also reach the function within N. The
     sort key is `(share, -loops, -lloops, -bw, depth, va)`. The output also
     gives the subtree size and its unresolved calls.
3. **Commands.**

```bash
S=/home/user/scratch/m3.23; mkdir -p $S
python3 tools/callgraph.py --selftest
python3 tools/callgraph.py build archive/head256.img -o $S/g.json
python3 tools/callgraph.py stats $S/g.json
python3 tools/nk_decomp.py section archive/head256.img --module Navi.exe --index 1 -o $S/sec1.bin
python3 tools/fptables.py scan archive/head256.img --sec1 $S/sec1.bin --graph $S/g.json --json $S/t.json --edges $S/e.json
python3 tools/callgraph.py path $S/g.json 0x0041c044 0x00542250
python3 tools/callgraph.py path $S/g.json 0x00413a6c 0x00412ac0
python3 tools/callgraph.py path $S/g.json 0x003f5cdc 0x003f5194
python3 tools/callgraph.py path $S/g.json 0x00419df8 0x00542250
python3 tools/callgraph.py callers $S/g.json 0x0041c044
python3 tools/callgraph.py callees $S/g.json 0x0041b780 --depth 1
python3 tools/callgraph.py loops $S/g.json 0x004125a8 --depth 2
R="python3 tools/callgraph.py rank $S/g.json --edges $S/e.json"
# QA
$R --depth 4 --family LCTBL=0x004125a8 --family ICODE=0x003f2cc0 --family REFER=0x003fbed8
# QB
$R --depth 5 --family POINT=0x003ffe80 --family LCTBL=0x004125a8 --family ICODE=0x003f2cc0
# QC
$R --depth 6 --family REFER=0x00400014,0x004000e8,0x004001bc,0x004003f4,0x004005f8 --family POINT=0x003ffe80 --family LCTBL=0x004125a8 --family ICODE=0x003f2cc0
# stop check
$R --depth 99 --top 0 --family REFER=0x00400014,0x004000e8,0x004001bc,0x004003f4,0x004005f8,0x003ffe80,0x004125a8,0x003f2cc0,0x003fbed8
```

4. **Controls.**
   - *Regression:* rebuild the graph with the `main` version of the tool. Every
     old edge must still be present.
   - *Positive:* `0x0040de98` must rank in `LCTBL`'s top ten (C-3607). The
     C-4694 loaders must appear in `ICODE`'s top ten.
   - *Weak/negative:* the POINT walker `0x003f5194` (C-2129/C-2540) and the
     read issuer `0x003fc518` (C-4666 note). Their ranks are reported as
     they fall.
5. **Scope.**
   - EU2011 `Navi.exe` only. The map DLLs and US2011 are not covered.
   - Static only. No candidate is called a reader here; M9.38 confirms them.

## Interpretation

- **Falsifier (a) did not fire.** All three known edges are present, one of
  them new, and no old edge was lost.
- **Falsifier (b) did not fire.** The only dynamically confirmed `LCTBL` reader
  is rank 2, and 3–4 of the ten `ICODE` candidates are confirmed loaders.
  C-4694 mixes `ICODE001` and `ICADM001` loads, so this precision is an upper
  bound for `ICODE` alone.
- **Falsifier (c) did not fire** (2.9 %).
- **Static ranking cannot separate `ADDRE`, `INTER`/`FRWAY`, `ZCODE` and
  `COORD`.** They share the opener `0x003fbed8` and the same handlers. The
  family is the ctx +124 value at run time (C-4666). `COORD001` has no name
  reference at all (C-4677). The only static list for these families is the
  shared QC `REFER` list. Splitting it needs a run per family, with ctx +124
  set and M9.38's read watch on.
- **POINT.** QC's top three are known POINT record functions. QB, which does
  not subtract the shared handlers, ranks generic functions higher. The ranked
  list stands for record consumers. For the walker itself, M9.38 is still
  needed: recall is weak for small leaf walkers.
