## Question

Does zooming out in the full-system emulator make the firmware read
`FRWAY0nn`/`INTER0nn`, and can the consuming code be attributed?

## Hypothesis

Yes — M5.100 proved that the NK1 zoom sequence reaches level-2 map loading,
so generating the request through the UI should expose the REFER family reader
that L3 never issued. Falsifier: no UI screen is reachable, or the SD trace
shows no read of a `REFER001` file.

## Method

1. **Sample and hash.** The three files above. The flash is deliberately
   synthetic: the owner's 8 MiB dump (SHA-256 `dc2b30df…e2cbb8b8`, M8.C1m) is
   not present on this host and is never committed.

2. **Commands.** `S` is the scratch directory, `Q` the patched QEMU, `C` the
   card image, `Z` the worktree; the wrapper adds QEMU options that
   `ze0_launch.py` does not expose:
   ```bash
   S=/home/marek/projekty/leafre-work/scratch/M3.43
   truncate -s 8M "$S/flash-zero.bin"
   cat > "$S/qemu-trace3.sh" <<EOF
   #!/bin/sh
   exec $Q "\$@" -trace "sdcard_read_block,file=$S/sdtrace-boot3.log" \\
        -qmp "unix:$S/run3/qmp.sock,server,nowait"
   EOF
   chmod +x "$S/qemu-trace3.sh"
   python3 tools/ze0_launch.py --card "$C" --flash "$S/flash-zero.bin" \\
       --qemu "$S/qemu-trace3.sh" --gdb 1240 --ui-start \\
       --workdir "$S/run3" --timeout 330 &
   python3 tools/ze0_ui.py run "$S/scenario3.txt" \\
       --qmp "$S/run3/qmp.sock" --hmp "$S/run3/mon.sock" \\
       --log "$S/run3/serial.log" --panel-sock "$S/run3/panel.ctl" \\
       --shot-dir "$S/shots3" --guest-clock 0x09e41888 \\
       --wait-timeout 180 --poll 2
   python3 tools/ze0_sdtrace.py "$S/sdtrace-boot3.log" --card "$C" --json
   ```
   `scenario3.txt` starts with `wait-log SRT_COLD_I_AGREE`, then the M5.100
   consent taps `tap 277 98`, `tap 277 98`, `tap 403 98`, then six
   `tap 765 200` ZOOM OUT steps with `sleep-guest 20` between them, and a
   final `shot afterzoom`.

3. **Controls.** *Positive (from the literature, not this run):* M5.100's
   factory card with the owner's flash prints `SRT_COLD_I_AGREE` at 50–60 s
   and reaches `MAP_MAPOPERATION_NORMAL_MAP`; its ZOOM OUT steps 2–3 draw
   level 2. *Positive (this run's tool chain):* patched QEMU accepts
   `-trace sdcard_read_block` (trace event listed, 98,676 lines written) and
   the card FAT is parsed by `ze0_sdtrace.py` (480 files, 79,294 extents).
   *Negative:* zero flash boots NK1 but never prints `SRT_COLD_I_AGREE`, so
   the scenario fails at step 1 and no tap is injected.

4. **Scope.** Boots 1–3 were the task's own Stop budget (≤3): boot 1 used a
   QEMU build without the `flash=` property (`Property 'ze0-machine.flash'
   not found`, 0 trace lines); boots 2 and 3 used the patched QEMU with zero
   flash (120 s and 330 s wall time). Boot 4 is a **re-run after a new
   enabling artifact landed concurrently** (M6.24's anonymous flash), not a
   fourth attempt at the same premise: it used the same patched QEMU, the
   same EU card and the same 330 s budget with `--flash flash-anon.bin`.
   Panel peer and `ze0_ui.py` were used in boots 3–4; no OSM input, no card
   writes, no firmware-image changes. No L3 rerun and no byte-signature
   search (H51).

5. **Falsifier.** A mapped `REFER001` read in `ze0_sdtrace.py`, or
   `SRT_COLD_I_AGREE` followed by a successful zoom scenario, would have
   refuted this negative.

## Interpretation

- **FACT:** with a zero-filled flash the emulator boots NK1 from the committed
  kernel, but the UI never reaches the consent screen within 330 s; the
  scripted scenario fails at its first step and injects **zero** taps.
- **FACT:** the SD trace contains 98,676 reads, **none** mapped to a FAT file;
  `FRWAY0nn`/`INTER0nn` were not read, so the user's zoom-out hypothesis is
  **untested**, not refuted.
- **OBSERVED:** the blocker is no longer the flash — M6.24's anonymous image
  fixed `Target ID Code` and `Area` — but the **consent state**
  `SRT_COLD_I_AGREE` on the EU 2011 card. `ze0_ui.py` and the patched QEMU
  worked at the tool level; M8.C1n reaches the *US* consent screen with
  `--ui-start`, while M8.C1p is exactly the open task for porting the skip to
  the ZE0 2011 card.
- **HYPOTHESIS:** with the M8.C1p consent patch the UI reaches the map and the
  M5.100 zoom taps then generate the REFER family request.
- **UNKNOWN:** whether zoom-out itself would read INTER/FRWAY once the map is
  reachable; route preview remains the next trigger to try.

## Conclusion

M3.43 is `blocked`, not `done`: the acceptance command (`ze0_sdtrace.py` maps
a `REFER001` read) could not be reached, with either a zero flash or M6.24's
anonymous flash. No claim row is upgraded; `docs/format/refer.md` is
unchanged. `Unblock: M8.C1p` (consent-screen patch for the 2011 card) — a
live task, not an archived ID.
