## Question

Can the duplicated `.cmp`/`.ind` outer-container chunk codec and inner
complete-zlib-page helpers be unified into one shared module with pinned factory
compression parameters (M1.13/C-2570–C-2579: stock zlib level 6, memLevel 8,
wbits 15, default strategy), without changing the behavior of the high-risk
writer tools?

## Hypothesis

A stdlib-only shared module can expose decode/encode, changed-chunk repack,
inner complete-zlib-page iteration, and `factory_params`/`factory_compress`
helpers; migrating `cmpind_writer`, `slot_budget`, `mutate_refer_poi`/`page` and
`poi_copies` to it will keep their existing selftests green and remove conflicting
hardcoded factory-parameter defaults. **Falsifier:** any migrated tool's existing
selftest fails, full `tools/selftest.py` reports a regression, `claims_check.py`
fails, or a migration produces different bytes for an equivalent synthetic case
covered by those selftests.

## Method

1. **Sample and hash.** None (tool-only task). The precheck duplication count is
   `grep -rn 'CHUNK = 0x10000\|decompressobj\|compressobj' tools/*.py | wc -l` →
   28 occurrences across tools before migration; after migration the six
   highest-risk/migrated files named in scope contain 4 remaining occurrences
   (selftest/fit-fallback contexts, not conflicting factory defaults for the
   shared container codec contract).
2. **Commands.** Runnable as written from the repository root:

```bash
# precheck (duplication surface)
grep -rn 'CHUNK = 0x10000\|decompressobj\|compressobj' tools/*.py | wc -l

# new shared module
python3 tools/cmpind_codec.py --selftest

# migrated high-risk writer tools
python3 tools/cmpind_writer.py --selftest
python3 tools/slot_budget.py --selftest
python3 tools/mutate_refer_poi.py --selftest
python3 tools/mutate_refer_page.py --selftest
python3 tools/poi_copies.py --selftest
python3 tools/cmpind.py --selftest
python3 tools/lev3456.py --selftest

# repo suites
python3 tools/selftest.py --only cmpind
python3 tools/selftest.py
python3 tools/claims_check.py
```

3. **Controls.** *Positive:* `cmpind_codec --selftest` includes a changed-chunk
   repack case where chunk 0's logical payload changes and chunks 1/2 must keep
   their compressed bytes verbatim (asserted byte-equal) and a bad offset that
   must be rejected; `slot_budget --selftest` covers abutting slots, no-op
   byte-identical refit, a fitting edit that leaves the neighbour page untouched,
   refusal when an incompressible page overruns its slot, headroom behavior,
   zero-padding slot growth, and name/edit invariants; `mutate_refer_poi
   --selftest` covers record parsing/resize invariants, same-length edits,
   malformed-page rejection and batch edit constraints; `selftest.py --only
   cmpind` exercises the builtin synthetic `.cmp`/`.ind` decode/extract/verify
   path through the migrated reader. *Negative:* `cmpind_codec` rejects a bad
   chunk offset, rejects a stream that does not fit its slot, and its
   changed-chunk test asserts the changed chunk's compressed bytes differ from
   the original; `mutate_refer_poi`/`slot_budget` refuse malformed/non-fitting
   edits; the bad-offset/reject cases fail loudly in selftests.
4. **Scope.** Source files in `tools/` only; no vendor image, `.DAT`, `.cmp`,
   `.ind`, `.AGM` or `.TTS` bytes. Covered: `cmpind_codec.py` (new),
   `cmpind.py`, `cmpind_writer.py`, `mutate_refer_poi.py`,
   `mutate_refer_page.py`, `slot_budget.py`, `poi_copies.py`, `lev3456.py`.
   Excluded/deliberate: `ind_mutate.py` (mutates `.ind` index fields only, no
   compression/chunk codec; has a custom raw-bytes `read_ind` shape), `l2check.py`
   (consumes `cmpind_writer` rather than reimplementing the codec), and
   `decompressobj`/`zlib.compress` uses that remain in selftests or non-default
   fit fallbacks without defining conflicting factory container defaults.
   Migration was not run against a real factory sample in this session; the Stop
   condition (real-factory byte change) was not triggered.
5. **Falsifier.** The claim is refuted if the shared module cannot reproduce the
   synthetic container round-trip or changed-chunk-preservation property, if any
   listed migrated tool's `--selftest` fails, if `selftest.py` reports a failure,
   or if a real-factory sample produces different bytes after migration with the
   same inputs/params (before/after SHA-256 would be required and the migration
   stopped for that tool).

## Interpretation

- **FACT:** `tools/cmpind_codec.py` provides the shared outer `.cmp`/`.ind`
  helpers and inner complete-zlib-page helpers, with factory params pinned to
  L6/memLevel 8/wbits 15/default strategy (C-2730–C-2732).
- **FACT:** The named migrated writer/reader tools pass their existing selftests
  and the full repository selftest/claims suites after migration (C-2733–C-2735).
- **OBSERVED:** `ind_mutate.py`, `l2check.py`, and remaining selftest/fit-fallback
  `zlib` calls were left out of scope by the migration decision recorded in the
  claims/this EXP (C-2736).
- **UNKNOWN:** No real factory `.cmp`/`.ind` sample was re-encoded in this
  session to compare byte-for-byte before/after at the tool level beyond
  selftest coverage; the Stop condition was not triggered because no such
  comparison was performed, and migrated compression sites use the same pinned
  factory params.

## Conclusion

M1.16 adds `tools/cmpind_codec.py` as the shared stdlib-only codec for the
`.cmp`/`.ind` outer container and inner complete-zlib-page helpers, pinning
`FACTORY_LEVEL=6, FACTORY_MEM=8, FACTORY_WBITS=15, FACTORY_STRATEGY=default`
(M1.13/C-2570–C-2579). The high-risk writer tools `cmpind_writer`,
`slot_budget`, `mutate_refer_poi`, and `mutate_refer_page` were migrated to it,
with `poi_copies`, `cmpind.py`, and `lev3456.py` also using shared primitives;
all migrated selftests pass, `python3 tools/selftest.py` reports 67 passed / 0
failed / 15 skipped, and `claims_check.py` is OK. `docs/research/claims.md`
gains C-2730–C-2736 in the M1.16 block. Low-risk/read-only or index-only
duplications (`ind_mutate`, `l2check`, selftest fixtures) remain documented as
out of scope.
