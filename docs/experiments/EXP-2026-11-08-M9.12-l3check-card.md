## Question

Can one command act as the software gate before any car test by diffing a candidate card image against a factory image and reporting, for every file that differs and has a relevant L3 target, `pass` / `fail` / `not-yet-available`, exiting non-zero on any fail, without synthesizing a pass for an unavailable reader?

## Hypothesis

Yes for the files/targets currently reachable: `7z` listings plus targeted content comparison identify differing card-relevant files; differing REFER001 `.cmp/.ind` pairs can be checked via the M9.11 firmware chunk-decoder path (`chunk_decoder_l3.py`); targets whose reader is not runnable (POI/M9.10, tile/M9.13, DRSTR/M9.14, and blocked `targets.json` entries) are reported as `not-yet-available`. Falsifier: a corrupted/modified pair that cmpind/firmware would reject reports `pass`, or an unavailable reader is reported as `pass`, or S2's differing POINT010 pair is not detected.

3. **Controls.** Positive: S2's differing `POINT010.DAT.cmp/.ind` pair is detected and checked by the M9.11 firmware path; result is `pass` with `byte-identical to cmpind.decode` (matches M9.11's acceptance criterion for a correct pair). Negative (synthetic, in `--selftest`): missing `--factory` is usage error (exit 2); missing images produce problems and no fake pass (exit 1/3, result != PASS); identical small files short-circuit to no diffs; POI reader mapping is always `not-yet-available` citing M9.10. A real corrupt-pair control is exercised by M9.11/`chunk_decoder_l3.py` (corrupt `.ind` rejected, swapped `+4/+8` fails); the card gate delegates to that adapter and would report `fail` on exit 1/FAIL.
4. **Scope.** Card-relevant diff scope: `VER_INFO/HDD_INFO.TXT`, `DRSTR001.DAT`, `REFER001/*`, `MAPAL001/*`. Detection: 7z listing size compare for all relevant paths; content compare for REFER001 `*.ind`, `HDD_INFO.TXT`, `DRSTR001.DAT`, and size-matched relevant files extracted for comparison (so same-size content changes in that set are caught). Excluded: files outside those prefixes; FAT/directory-entry-only diffs not surfaced as file diffs; per-file runner wiring for runnable `targets.json` targets (not yet implemented — reported as `not-yet-available` rather than guessed). S0/S1/S2 runs use 8.06 GiB US images (245 files in 7z listing each); diff completed via listing/hash short-circuit/content compare as reported.
5. **Falsifier.** Stated above: missed S2 POINT010 diff, fake pass for POI/M9.10, or corrupted pair reported as pass.

## Interpretation

- **FACT:** `l3check.py --card OUT.img --factory IMG` detects differing card-relevant files and reports per-target `pass`/`fail`/`not-yet-available` with exit 1 on any fail (C-2160, tool). S2's POINT010 `.cmp/.ind` diff is detected and the M9.11 firmware chunk-decoder path returns PASS (byte-identical to `cmpind.decode`, `r0=42848 copied=42848`).
- **FACT:** The POI reader is reported as `not-yet-available` with M9.10 named, never as `pass` (done-when/dependency requirement). `l3_claim` is false for adapter/card rows.
- **OBSERVED:** S0 and S1 are byte/SHA-256 identical to the US factory image, so a diff-based gate finds no differing files. The tool reports `NO_DIFFS` (exit 3) plus POI `not-yet-available`; it does not claim a runnable pass because nothing was verified. This is honest but means "S0/S1 all pass" cannot be demonstrated as runnable L3 passes until targets can run on unchanged baselines or a no-diff baseline mode is defined — a narrow gap relative to the literal done-when text.
- **OBSERVED:** `cmp_ind_reader` is exercised through `chunk_decoder_l3.py` (M9.11 firmware path) because registration in `targets.json`/runner is M9.11b scope; `hddinfo_compare`/`drstr_parser`/`tile_reader` are blocked in `targets.json` and reported `not-yet-available` when applicable.
- **HYPOTHESIS:** When M9.11b registers `cmp_ind_reader` and M9.10/M9.6/M9.13/M9.14 provide runnable/card-wired targets, the same `--card` gate will produce runnable pass/fail verdicts on S0/S1/S2-style corpora.
- **UNKNOWN:** No firmware verdict for generated tile/DRSTR/POI-name acceptance on a real card; S2's cmp/ind PASS is container decoding evidence (M9.11), not full card acceptance.

## Conclusion

M9.12 delivers the `--card` software gate skeleton and proves it on the available S1/S2 corpora: S2 exits 0 with `cmp_ind_reader` PASS (M9.11 firmware path) and POI `not-yet-available` (M9.10). S0/S1 are factory-identical and produce `NO_DIFFS` (no fail, but no runnable pass to claim). The POI reader is never faked. The remaining gap to the literal "S0/S1 all pass" done-when is the absence of runnable no-diff/baseline target execution for those corpora under current target availability; recording this honestly makes the task **blocked on target availability/wiring (M9.11b/M9.10/M9.6 context)** rather than falsely `done`.
