## Goal

Find the checks the firmware applies to `DRSTR001.DAT` and `CMP.LST` (count, order, sentinel, leading `u32 = 0x2f`) which M5.6 must satisfy. For each M3.4 function: file API calls (named via C-1710/M1.9), buffer it reads into, and every compare on the read data, with VAs.

## Method

1. Resolved M3.4 VAs to build A `Navi.exe` `.text` (uncompressed, rva `0x00001000`, file `0x00c8f200`, VA base `0x00011000`): `va2file 0x00419684`→`0x01097884`, `0x0041ba90`→`0x01099c90`, `0x00419d24`→`0x01097f24`, `0x00419ca0`→`0x01097ea0` (C-530: code never compressed).
2. `sh4xref.py ... --calls <fn> --resolve-with 0x3e00200` for `0x00419684, 0x0041ba90, 0x00419d24, 0x00419ca0` and key callees (`0x0041b3bc, 0x0041b650, 0x00419350, 0x0041b4f8, 0x0041b470, 0x0041ba28, 0x0041b69c, 0x004191d0, 0x00418dfc, 0x00418748, 0x0041bd88, 0x0041bc98, 0x0041b780, 0x0041b954`) to name file/CRT API calls through coredll thunks (M1.9/C-1710).
3. SH-4 disassembly (capstone) of each function and literal-pool reads from `IMG256` to recover arguments, constants and every compare/test. Mapped wrapper thunks to coredll ordinals by reading thunk slot pointers: `0x53a3cc`→slot `0x0055d1a0`=#1120 `fread`, `0x53a3c0`→`0x0055d1a4`=#1126 `ferror`, `0x53a3d8`→`0x0055d19c`=#1127 `clearerr`, `0x53a3a8`→`0x0055d1ac`=#1131 `ftell`, `0x53a3b4`→`0x0055d1a8`=#1130 `fseek` (cross-checked with `cerom.py --image-start 0x3e00200 ... exports coredll.dll`).

### `0x00419684` — DRSTR001 handler (`Navi.exe`)

- **Caller:** `0x00419d24` (`jsr` at `0x00419d2c`, pool `0x419dc8`).
- **Path build:** `memset` 260-byte buf at global `0x009cfbd0` (`0x4196be`→`COREDLL!memset` #1047, `0x003d13c4`, `r11=260`); `wcstombs(0x009cfbd0, UTF16 \SystemSD@0x00049fd4, 260)` (`0x4196c8`→`COREDLL!wcstombs`, `0x003d14cc`); `strncat` `\`@`0x0017a9ec` (`0x4196de`→`COREDLL!strncat`, `0x0053a384`), copy to stack `sp+52`, `strncat` `DRSTR001.DAT`@`0x0017ab24` length 12 (`0x419738`).
- **Path/length compares (not file-data):** `0x4196ce` `cmp/hs r0, 0x102` (wcstombs result vs 258) `bt 0x4196d8` else error; `0x4196ec` `cmp/ge r9,r11` (260 >= converted_len+1) `bt 0x419702`; `0x41971c` `cmp/ge r9,r11` (260 >= path+12) `bt 0x419732`.
- **Open/read/close:** `0x419740` `sub_0041b3bc(path, "rb"@0x0017ab20)` → `COREDLL!fopen` #1113/`strcmp`; on nonzero fd `0x41974c` `sub_00419350(fd)` (r4=fd, result `r13`); `0x419754` `sub_0041b650(fd)` → `COREDLL!fclose` #1118. On open failure/parse failure reports via `sub_0041bbec` and returns error.
- **Post-parse loop:** iterates parsed records calling `sub_00418dfc` at `0x4197b0` (checks return `cmp/eq #7` at `0x4197b4`, then `tst r13`/`cmp/gt r0,r11` buffer bound at `0x4197ba,0x4197c4`) and `sub_00418748` at `0x4197dc`; these operate on in-memory parsed structures (36/28-byte strides) and read/copy via `strlen`/`strncpy`/`memset`/`strncat` — no file `fread` and no 0x2f/40/324 file-content sentinel compare observed.

### `0x00419350` — DRSTR file parser (called by `0x00419684`)

`0x00419350(r4=fd)`. Reads the whole file, then reads the first 40-byte node again from offset 0, parses via `sub_004191d0`/`sub_00418dfc`/`sub_00418748`/`sub_00418a10`/`sub_00418d9c`/`sub_00418a18`/`sub_00419fbc`/`sub_00419f08`. No data is handed to another module (all callees are `sub_0041xxxx`/`sub_00418xxx`/`sub_00419xxx` in `Navi.exe`); allocator is indirect via `*0x0055d8fc` (`0x41936e`), free via `*0x0055d93c`.

- **Buffers:** heap whole-file buffer `*gptr@0x009cfcdc` (r9), allocated `0x77220` bytes (`0x419368` pool `0x4195b8`, call `0x41936e`); stack 40-byte node/header buffer `sp+36` (r10 set `0x4193c8/0x41941a`, frame -336 via `mov.w 0x419440,r1` = `0xfeb0` at `0x41935e`). Global/path bases: `0x009cfbd0`, parsed record bases `0x00e25420`/`0x00e27040` (`0x419664,0x41966c`), count globals `0x009cfcd4,0x009cfcd8`.
- **File API calls (all via wrappers):** `sub_0041ba28(fd)` at `0x41937e` → `ftell` #1131 / `fseek` #1130 (size); `sub_0041b4f8(fd, *buf, size)` at `0x4193a2` → `clearerr` #1127, `fread` #1120, `ferror` #1126 (whole file); `sub_0041b470(fd,0,0)` at `0x4193c4` → `fseek` #1130/`ftell` #1131 (rewind to 0, SEEK_SET); `sub_0041b4f8(fd, sp+36, 40)` at `0x4193d6` → `clearerr`/`fread`/`ferror` (first 40 bytes).
- **Compares/tests on size / read counts / read data:**

| VA | Instruction / test | Compared value | Meaning |
| --- | --- | --- | --- |
| `0x419374` | `tst r0,r0` after alloc | heap alloc result | allocation failed → error 27 (`0x419408`) |
| `0x419382` | `cmp/pz r0` (file size) | `sub_0041ba28` result | size < 0 → error path |
| `0x419388` | `cmp/ge r8,r10` (r10=`0x77220`) | file size vs max buffer | **reject if file size >= 488,992** (error 26, `0x41938c`) |

| `0x4193e4` | `cmp/eq r2,r8` | whole-file read count vs file size | **whole file must read exactly `size` bytes** (error 23, `0x4193e8`) |
| `0x419444` | `cmp/pz r2` | read count | read count < 0 → error 23 |
| `0x419462-0x419468` | `COREDLL!_modlu` (`0x003d1484`, pool `0x419658`) of `(file size from sp+72, 40)` then `tst r0,r0`; `bt 0x419496` | `size mod 40` | **file size must be a multiple of 40** (error 20 at `0x41946a` if nonzero remainder) |

- **No 0x2f / node-count / entry-count / order check in `sub_00419350`:** the 40-byte first record is read into `sp+36` and copied out (`strncpy` 18 bytes at `0x4194dc`→`COREDLL!strncpy` `0x003d1538`; passed to `sub_004191d0` at `0x419500` and later parsing), but **no `cmp`/`tst` on the first byte or first `u32` of that buffer against `0x2f` (`/`) is present in `sub_00419350`**. No compare against 40 (node count) or 324 (entry count) appears in `sub_00419350`. A targeted scan of delegate compares found no `cmp/eq #47`/`#0x2f` sentinel: `sub_004191d0` has only `tst`/`cmp/hs`/`cmp/ge` (entry-count bound, see below), `sub_00419fbc`/`sub_00419f08` compare indices/pointers, `sub_00418a10` is a stub with no compares.

### `0x004191d0` — node/entry record reader (delegate, reads from fd)

Called from `sub_00419350` at `0x419500` (r4=fd, r5=first-node buffer `sp+36`, r6=`0x00e27040+28`, r7=1). Reads/parses directory entry records from the file via `sub_00418b00`/`sub_00418bbc` (not COREDLL file APIs directly; they take the fd/buffer context) in a loop of `entry_count` iterations, advancing 28 bytes per in-memory entry (`0x41926e`).

- **Compares on node-header/read data:** loads `entry_count` from node at offset 24 (`mov.w @(24,r9),r0`, `0x419200`), computes `total = entry_count + r7`; `0x41920a` `cmp/hs r2,r1` with `r1 = 0x3a98` (15000, pool `0x4192aa`) — **rejects if `entry_count + r7 > 15000`** (error 11, `0x41920e`). `0x41926a` `cmp/ge r3,r8` loops while `r8 < entry_count`. **No check of `entry_count` against 324, no 0x2f sentinel compare, no name/order validation observed.** Entry stride used in-memory is 28 bytes (vs 32-byte on-disk DRSTR entries); node `entry_count` is read from offset 24.

### `0x0041ba90` — CMP.LST handler (`Navi.exe`)

- **Caller:** `0x00419ca0` (`jsr` at `0x00419cae`, pool `0x419d04`). `0x00419ca0` is the media-mount state machine row (status 0, handler table `0x0017ab38` context per M3.8/drstr.md): it sets `sub_0041a388(1)`, calls `sub_0041ba90`; on nonzero return it takes an error/reset path (`sub_0041a110`, `sub_0041a28c(2)`, `sub_004178d0(0,-1)`, stores 3 to `*0x009cfce0`); on success it proceeds to `sub_0041a438` (MMAIN001, C-1780–C-1789) and sets `*0x009cfce0=1`-family state (`sub_00419a9c`/`sub_00419bc0` or reset).
- **Path build/open:** `memset` 260-byte stack buf (`sp+76`), `wcstombs` of `\SystemSD`@`0x00049fd4` (`0x41bab6`→`COREDLL!wcstombs`), `strncat` `\CMP.LST`@`0x0017b25c` length 8 (`0x41bad6`→`COREDLL!strncat`). Path bound `0x41bac2-0x41bac6` `cmp/ge r3,r9` (260 vs converted_len+9). Opens `sub_0041b3bc(path,"rb"@`0x0017ab20`) at `0x41bade` → `COREDLL!fopen` #1113.
- **No content read:** on open success `0x41baea` calls `sub_0041b650(fd)` → `COREDLL!fclose` #1118 immediately. **There is no `fread`/`sub_0041b4f8`/`sub_0041b954` read of CMP.LST contents and no compare on file data bytes.** The check is open/existence only (plus global `*0x009cfd18` gate at `0x41baca`: if nonzero, returns 0 without re-running the init loop).
- **Post-close init:** fills a 4-entry descriptor (stack `sp+20..`) and calls `sub_0041bd88` four times (`0x41bb2a-0x41bb4e`, r9 0..3, `cmp/gt #3,r9` loop) with table base `0x00d995e0+0x82c60` entries and callbacks (`sub_0041b470/0x41b4f8/0x41b5a4/0x41ba28/0x41b650/0x41b69c`, pool `0x41bbcc-0x41bbdc`). `sub_0041bd88` (`0x0041bd88`) calls `COREDLL!NKDbgPrintfW` (`0x0032ef78`), `COREDLL!InitializeCriticalSection` (`0x0053a294`), `COREDLL!EnterCriticalSection` (`0x0053a2ac`), `sub_0041bc98`, `COREDLL!LeaveCriticalSection` (`0x0053a2a0`) — a synchronized init/allocator path, not CMP.LST content validation.

### `0x00419d24` / `0x00419ca0` callers

- `0x00419d24`: calls `sub_00419684` (DRSTR001, `0x419d2c`); on its result branches through `sub_00419a9c/0x41a42c/0x41a304/0x41a388/0x41a28c/0x4178d0/0x4186fc/0x419f84` and stores state to `*0x009cfce0` (`0x419dec`). No direct file-data compare.
- `0x00419ca0`: calls `sub_0041ba90` (CMP.LST, `0x419cae`) then `sub_0041a438` (MMAIN001, `0x419cd0`) and state handlers; gates on return values (tst/bt at `0x419cb2,0x419cdc`). No direct file-data compare.

## Interpretation

1. **CMP.LST:** firmware validates **existence/openability only** (`fopen("rb")` then `fclose`) in `0x0041ba90`; it does **not** read or compare the 19-byte content (`\SystemSD\REFER001\`). M5.6 must keep the file present and openable; the exact content is not checked by this path (content correctness remains an M5.6/data-contract concern, not a firmware compare found here).
2. **DRSTR001:** firmware reads and parses the file (`sub_00419350`). Enforced structural checks found: file size `< 0x77220`, whole-file read exact, first 40-byte read exact, `size mod 40 == 0` (`_modlu`), and `(size/40) >= 200` records. Delegate `sub_004191d0` bounds `node.entry_count(+24) + 1 < 15000` and reads that many 28-byte in-memory entries. **No check was found for the leading `u32 = 0x2f` (`/`) root sentinel, no check for node count == 40 or directory-entry count == 324, and no name/order/sentinel validation of DRSTR record content** in `0x00419684/0x00419350/0x004191d0` or the scanned delegate compares. The leading-0x2f question (C-859) remains **unverified/no-check-found** (strengthened: parser path examined). M5.6 should still satisfy the offline invariants (C-030–C-039: 40 nodes, 324 entries, ordering, leading `/`) because they are the data contract, but this EXP does not tie them to a firmware compare.
3. **`size % 40 == 0` vs real format:** the EU 2011 DRSTR001 is 11968 bytes = 40×40 + 324×32 (not a multiple of 40; 11968 % 40 = 8). `sub_00419350` computes `size % 40` via `_modlu` on the value loaded at `0x41945e` (`@(72,r15)`) and requires remainder 0 / count >= 200 (`0x419466-0x4194a6`). This is recorded as an OBSERVED code path; reconciling it with the on-disk mixed 40/32-byte layout requires tracing which size/value is at `sp+72` through the allocator/read path or L3 confirmation (not resolved here). `sub_004191d0` reads node `entry_count` from offset 24 and iterates entries with a 28-byte in-memory stride, indicating an in-memory representation distinct from the on-disk 32-byte entry.
4. **No cross-module handoff of file data:** parsing stays within `Navi.exe` helper functions; CMP.LST post-open init uses critical sections and callbacks but no content read. No evidence that raw DRSTR/CMP.LST bytes are passed to OBJDLL/NaviMapCC/etc. for validation in these paths.

## Limits / follow-ups

- Capstone disassembly used instead of `sh4-linux-gnu-objdump` (not installed); instruction/VA evidence is equivalent but the environment lacks the named tool.
- Delegate parse functions `sub_00418b00/0x418bbc/0x418dfc/0x418748/0x418a10/0x418d9c/0x418a18/0x419fbc/0x419f08` were not fully decoded; a targeted compare scan found no `0x2f` sentinel, but a full decode could reveal subtler ordering/count invariants.
- The `size % 40` / `count >= 200` check's source value (`sp+72`) vs the 11968-byte mixed-format file needs stack-frame/L3 reconciliation before stating it as a hard M5.6 byte-size constraint.
- `sub_0041b780/0x0041b954` (C-1783 style wrappers) wrap the same open/read layer; DRSTR uses `sub_0041b3bc/0x0041b4f8` directly.
