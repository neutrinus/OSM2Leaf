## Question

Can a level-3/4/5 set for `LEV3456R.DAT` be built from a mesh-split synthetic OSM extract so that `lev3456.py verify` accepts it and an unchanged input rebuilds byte-identically (M5.16 / H11 G4)?

## Hypothesis

Yes, for the road-shape grammar that `lev3456.decode_shape`/`encode_shape` and the level-5/4/3 record encoders already round-trip (C-996, C-998): synthetic roads quantized into the template's parcel grid, encoded with `lev3456`'s encoders and `cmpind_codec.factory_compress`, produce records that decode without `opaque` (L5 strict) and whose level regions `lev3456.rebuild_level` can reproduce. **Falsifier:** generated records decode as `opaque`, `encode_record(decode_record(p)) != p` for a generated record, `lev3456.py verify` returns non-zero on the generated file, or a second generate from the same input differs in bytes.

## Method

2. **Commands** (runnable as written, python3.13 for stream-identity claims):

```bash
cd /home/marek/projekty/OSM2Leaf-wt-M5.16
python3.13 tools/lev3456gen.py --selftest
python3.13 tools/lev3456.py --selftest

# generate L3/4/5 from synthetic extract into factory template and verify
python3.13 - << 'PY'
import sys, tempfile, os, subprocess; sys.path.insert(0,'tools')
import lev3456gen
ext = lev3456gen._synthetic_extract()
tpl = '/home/marek/projekty/leafre-work/root/MAPAL001/LEV3456R.DAT'
with tempfile.NamedTemporaryFile(suffix='.DAT', delete=False) as tf: out=tf.name
try:
    o1,s = lev3456gen.generate(tpl, ext, out, levels=(3,4,5))
    o2,_ = lev3456gen.generate(tpl, ext, out, levels=(3,4,5))
    print('stats', s, 'deterministic', o1==o2, 'bytes', len(o1))
    r = subprocess.run([sys.executable,'tools/lev3456.py','verify',out,
                        '--level','3','--level','4','--level','5'],
                       capture_output=True,text=True)
    print(r.stdout.strip().splitlines()[-1]); raise SystemExit(r.returncode)
finally: os.unlink(out)
PY
# expected: deterministic True, verify exit 0, "OK (section 1 level 5 strict; levels 3/4 best-effort)"
```

3. **Controls.** *Positive:* `lev3456gen --selftest` builds shapes/records that `decode_shape`/`decode_record` accept and `encode_*` round-trips for levels 3,4,5, and an unchanged template round-trip through `container_to_sections`+`write_container` is byte-identical to the 76,066,304 B factory file (control for the container writer). *Negative (grammar):* a record that fails decode becomes `opaque` (lev3456.verify counts it; L5 would fail strict verdict) - the selftest asserts `not rec.get('opaque')` for generated records. *Negative (determinism):* the generate-twice equality assert fails if output differs.
4. **Scope.** Section 1 levels 3,4,5 of the EU 2011 LEV3456R container, template-spliced (factory backgrounds/names/opaque records preserved; road slots replaced where the synthetic extract maps). Level 6 and section 2 preserved verbatim from template. Synthetic extract = 3 roads mapping to L5 1 cell (7 shapes), L4 1 cell (7 shapes), L3 (27 shapes). Geographic placement uses proportional grid mapping over template bounds (structurally valid; exact parcel-code/row-order fidelity vs firmware geography not proven). Excluded: level-3 point index (M4.11 open, 1677 factory opaque preserved), level-4 names subtable, 2-6-word L5 segment generation, real OSM coastline/landuse backgrounds, 2014/2016 files. 1 template file, 1 synthetic extract, 3 levels.
5. **Falsifier.** Any generated L5 record `opaque`; `lev3456.py verify` exit != 0; `generate()` twice != byte-identical; unchanged template round-trip != original bytes.

## Interpretation

- **VERIFIED (tool/grammar, this corpus):** `tools/lev3456gen.py` generates road-shape records for levels 3/4/5 from a mesh-split synthetic extract using `lev3456`'s encoders; generated records decode without `opaque` and re-encode byte-identically at the plain level; the generated container is accepted by `lev3456.py verify` (exit 0, L5 strict 62/62, L3/4 best-effort consistent with factory preserved records). (C-2400, C-2401)
