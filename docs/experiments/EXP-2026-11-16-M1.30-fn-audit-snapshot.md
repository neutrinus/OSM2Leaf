## Question

Can `tools/fn_audit.py` freeze its `--scope docs` corpus and verdicts to one
committed, vendor-free JSON snapshot that (a) is re-derivable byte-for-byte,
(b) re-classifies every row against the image so a hand-edited `class` fails,
and (c) fails loudly when the live source lines have moved since the snapshot —
so the M1.26 gate and H63's `Pin:` re-check cannot drift *or* silently rot?

## Hypothesis

Every `--scope docs` citation is a deterministic function of the scoped files
plus the image's `.pdata`. A snapshot of the frozen row identities
(`file/line/va/kind`, plus a `ctx` row's paired `correction` start) and the
image SHA-256 can be audited back by re-classifying each `va` on the same
image, and a live-scan comparison can tell a stale snapshot from a current
one. The stored `class` is a convenience copy, never the verdict source.

**Falsifier:** the snapshot's re-classified summary differs from the live
run's; a second write on the same corpus is not byte-identical; a hand-relabelled
`CORRECTED` row still passes; or a snapshot whose source line moved/added/
removed still exits 0.

## Method

1. **Sample and hash.** `archive/head256.img`, first 256 MiB, SHA-256 above;
   builds selected by CE image start via `cerom.py`, never a fitted delta.
2. **Commands.** Run from the repo root. The snapshot is written on the commit
   named below and is re-derived, not refreshed, by `--corpus`:

   ```bash
   sha256sum archive/head256.img
   python3 tools/fn_audit.py --selftest
   python3 tools/fn_audit.py archive/head256.img --scope docs --quiet
   python3 tools/fn_audit.py archive/head256.img --scope docs \
       --write-snapshot docs/research/fn-audit-corpus-2026-11-16.json --quiet
   sha256sum docs/research/fn-audit-corpus-2026-11-16.json
   python3 tools/fn_audit.py archive/head256.img \
       --corpus docs/research/fn-audit-corpus-2026-11-16.json --quiet
   python3 tools/fn_audit.py archive/head256.img \
       --corpus docs/research/fn-audit-corpus-2026-11-16.json --fix-list
   python3 tools/selftest.py --only fn_audit
   python3 tools/claims_check.py
   python3 tools/todo_check.py
   ```

   Staleness negative control (no repo file is edited; the appended probe is
   restored before any commit):

   ```bash
   cp TODO.md /tmp/TODO.bak
   printf '\n- [ ] **H99 — synthetic staleness probe**\n  - Status: open · Owner: — · Critical: no · Goal: fn 0x0041c7e8 probe\n' >> TODO.md
   python3 tools/fn_audit.py archive/head256.img \
       --corpus docs/research/fn-audit-corpus-2026-11-16.json --quiet   # exit 1
   cp /tmp/TODO.bak TODO.md
   ```

   Hand-mutation negative control (rewrite one row's `class` in a **copy**,
   including its `class_sha256` so only the image can catch it):

   ```bash
   python3 - <<'EOF'
   import hashlib, json
   d = json.load(open('docs/research/fn-audit-corpus-2026-11-16.json'))
   for r in d['rows']:
       if r['class'] == 'CORRECTED':
           r['class'] = 'INSIDE'
           r['true_start'] = r['true_start'] or '0x0041c7dc'
           r['class_sha256'] = hashlib.sha256(
               ('INSIDE|%s' % r['true_start']).encode()).hexdigest()
           d['summary']['inside'] = 1
           d['summary']['corrected'] = 22
           break
   json.dump(d, open('/tmp/fa-mut3.json', 'w'), indent=1)
   EOF
   python3 tools/fn_audit.py archive/head256.img \
       --corpus /tmp/fa-mut3.json --quiet   # exit 1
   ```

3. **Controls.**
   * Positive (round-trip): after `--write-snapshot`, `--corpus` on the same
     image prints the identical two summary lines and exits 0.
   * Positive (re-derivable): writing twice on the same corpus gives identical
     bytes (`cmp` clean, same SHA-256); re-running `--write-snapshot` on the
     final commit reproduces the same file.
   * Negative (hand-mutated `class`): a `CORRECTED` row relabelled `INSIDE`
     with a re-signed `class_sha256` and adjusted summary exits 1 because the
     image re-classifies it back to `CORRECTED`.
   * Negative (stale row): one synthetic citation added to `TODO.md` after the
     snapshot makes `--corpus` print `CORPUS STALE: 1 new / 0 gone / 0 moved`
     and exit 1.
   * Negative (integrity/summary/foreign file): a `class_sha256` that no
     longer matches its class, or a foreign `tool` value, fails; all covered
     in `--selftest`.
   * Synthetic: the selftest runs the same checks on an injected table plus a
     monkeypatched live corpus (moved + new + gone = `1 new / 1 gone / 1 moved`).

4. **Scope.** Same corpus M1.25/M1.29 counted: `TODO.md` + 13
   `docs/format/*.md` + `tools/l3_harness/targets.json` +
   `tools/chunk_decoder_l3.py` + `tools/point_walk_l3.py` = **17 files, 313
   citations, 112 unique VAs**. `docs/research/*.md`, `docs/experiments/*.md`
   and `tools/README.md` are outside the glob. The snapshot stores no image
   bytes — only file/line/VA/kind/class/true-start/class_sha256, the summary
   and the image SHA-256. **Frozen part:** `file/line/va/kind` (and a `ctx`
   row's `correction` start). **Not frozen:** the `class` — `--corpus`
   re-derives it from the image, so the image is required and always consulted.

5. **Falsifier.** Stated above, before the result.

## Interpretation

- **FACT:** The snapshot's row identities plus the named image determine the
  verdicts; `--corpus` re-derives `START 229, INSIDE 0, CORRECTED 23, GAP 29
  (leaf 29), AMBIGUOUS 0, UNMAPPED 32` from the image and the rows alone.
- **FACT:** A `CORRECTED` row relabelled `INSIDE` — even with a re-signed
  `class_sha256` and a matching summary — exits 1, because the image
  re-classifies it. A stale source line (`new`, `gone` or `moved`) exits 1
  with `CORPUS STALE`.
- **OBSERVED:** The corpus is written from `1202054` (the branch tip); running
  `--write-snapshot` there with the identical tool reproduces the committed
  file byte-for-byte. A write at `eb95498` (`todo: start M1.30`) gives the same
  summary and verdicts but 76 different `TODO.md` line numbers, because the
  `Status: done` line moved citations below it.
- **UNKNOWN:** whether M1.26's `--scope l3` overlay keeps the same staleness
  semantics on top of this snapshot (M1.26's task).

## Conclusion

`tools/fn_audit.py` gained `--write-snapshot PATH` (one sorted
`{file,line,va,kind,class,true_start,class_sha256}` row per citation, `GAP`
rows with `leaf`, `AMBIGUOUS` rows with candidates and `ctx` rows with their
paired `correction`, plus the exact summary, the scoped file list and the image
SHA-256) and `--corpus PATH` (requires the image; re-classifies every row from
`.pdata`; fails on summary/integrity/class disagreement; compares the live
`--scope docs` scan and prints `CORPUS STALE: n new / n gone / n moved` on any
moved/added/removed line; `--fix-list` prints only snapshot-`INSIDE` rows).
The committed corpus is `docs/research/fn-audit-corpus-2026-11-16.json`
(`4606aa2a…78fe38`, 313 rows). `classify`, `is_failure` and the live
`--fix-list` are unchanged; `audit()` now keeps `UNMAPPED` const/ctx rows so
the snapshot can re-render `UNMAPPED 32` (the printed report still hides them).
`docs/research/claims.md` gains C-3860–C-3865, `tools/README.md` documents the
flags. M1.26 can now run its gate on the snapshot.
