# EXP-2026-11-06-M4.20-us-drstr-roundtrip — US `DRSTR001` round-trip: name case at `0x1ae0`

- **Date:** 2026-11-06
- **Task:** M4.20
- **Claims:** C-2100–C-2105
- **Supersedes:** clarifies C-1982 (OBSERVED diff was real; cause now explained)

## Goal

M5.6 writes `DRSTR001.DAT` for generated cards, so the model must round-trip
on both markets. On the untouched US factory tree `l2check.py` `drstr_roundtrip`
failed at `0x1ae0` (C-1982, EXP-2026-11-06-M5.12-us-poi-rename).

## Method

Round-tripped each factory root with `tools/drstr_ze0.build()` (preserves
order from the existing `DRSTR001.DAT`) and compared byte-for-byte. Located
the diff with `tools/drstr.py parse`/raw offsets. Added a synthetic self-test
(`drstr_ze0.py --selftest`) for the case-preservation form.

## Raw observations

US rebuild vs factory (before fix), 7456 B vs 7456 B, 9 differing bytes:

```
first diff 0x1ae0: ref=6c built=4c
ref  00 00 00 00 2c a2 00 00 6c 74 6e 74 62 6c 2e 64 61 74 00 ...
buil 00 00 00 00 2c a2 00 00 4c 54 4e 54 42 4c 2e 44 41 54 00 ...
diff count 9 ranges 0x1ae0..0x1ae9
affected: XMD/ltntbl.dat @0x1ae0: b'ltntbl.dat' -> b'LTNTBL.DAT'
```

`drstr.py parse` of the factory US file: `XMD` (node index 4 in the listing)
entry index 2 is `ltntbl.dat`, type 0, value 320, raw name bytes
`ltntbl.dat` at `0x1ae0`. The on-disk file is `LTNTBL.DAT`.

Reconciling DRSTR order (`_read_order`, 20-byte name view) with `listing()`
(disk names) before the fix:

```
XMD order: ['bsaidxtbl.dat','bsatbldata.dat','ltntbl.dat']
disk:      ['bsaidxtbl.dat','bsatbldata.dat','LTNTBL.DAT']
ordered ['bsaidxtbl.dat','bsatbldata.dat'] missing ['ltntbl.dat'] extra ['LTNTBL.DAT']
```

The exact-name lookup missed the case-mismatched entry; the builder appended
the disk name, producing uppercase.

US factory also stores `bsaidxtbl.dat`/`bsatbldata.dat` lowercase in `XMD`
(same case on disk there → no diff). `bsatbldata.dat` is 14 chars: stored
across the 13-byte name field and `unknown[9]` (NUL-terminated before `type`),
so `drstr.py`'s 13-byte name view truncates it to `bsatbldata.da`; the
factory node `unknown[12]`/reserved/entry `unknown[9]`/reserved are otherwise
zero (EU: all zero).

EU rebuild vs factory: **BYTE-IDENTICAL** (11968 B), before and after fix.

## Fix

`tools/drstr_ze0.build()`: when reusing an existing DRSTR's order, match
directory entries case-insensitively and **emit the DRSTR-stored name**
(`ref_name`), preserving factory case that differs from the on-disk/FAT name.

## Interpretation

`0x1ae0` is the start of the 32-byte entry record (index 2) in the `XMD`
directory listing of the US factory `DRSTR001.DAT`; bytes `+0x00..+0x0c` of
that record are the entry name field holding `ltntbl.dat` (lowercase). The
diff was not a model error in offsets/sizes but a **case-normalization** error
in `drstr_ze0.build()`: it replaced the DRSTR-stored name with the on-disk
name when the exact-case lookup failed. Preserving the stored name makes the
rebuild byte-identical for both markets and is the safe default for any
existing-tree round-trip.
