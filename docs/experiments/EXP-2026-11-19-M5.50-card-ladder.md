## Question

Can the P0 and P1 rungs of the card ladder each be stated as one command whose
output must contain an exact string, with a `NOT RUN` placeholder for P2, so
that "P1 = one tile or many?" and "which gate does a rung pass?" stop being
re-derived in prose?

## Hypothesis

Every rung gate that exists today is already a command with a stable token:
`mesh_grid.py cover` prints its census line, `fit_census` its relocation line,
`check-diff` its range/outside counts, `cardcheck` `RESULT: PASS`, `l2check`
`RESULT: PASS`, `7z t` `Everything is Ok`. P1 has no card yet (M5.49 is open;
`one_tile_pipeline.py` has no `--preserve-tile` flag), so its card rows must be
`NOT RUN — M5.49`, and P2's routing/class gates `NOT RUN — M5.16`/`M5.36`.

**Falsifier:** a row's command exits 0 but does not print the token the row
names, or the page states a number that no command in the page prints.

## Method

1. **Sample and hash.** The image is the `--reference` of the `check-diff` rows
   and the source of the P0 card; the P0 card is rebuilt from scratch by the
   block in the page (delete `p0.img`, run, the `sha256sum` row reproduces
   `b0faf119…33237`). No sample is written by this task.

2. **Commands.** The page is *executed*, not read: the block below `## One
   block` is copied verbatim out of `docs/format/card-ladder.md` into
   `~/projekty/leafre-work/scratch/m5.50/doc-block.sh` and run with the card
   deleted first, so the block's own build path is exercised. Extraction (the
   block is the text between the `cd "$(git rev-parse …)"` line and the final
   `card-ladder: all rows OK` line):

```bash
cd /home/marek/projekty/OSM2Leaf.task-m5.50-card-ladder-page   # worktree root
S=$HOME/projekty/leafre-work/scratch/m5.50
awk '/^cd "\$\(git rev-parse --show-toplevel\)"$/{p=1} p{print}
     /card-ladder: all rows OK/{if(p) exit}' docs/format/card-ladder.md > $S/doc-block.sh
rm -f $S/p0.img
bash $S/doc-block.sh          # expect: 15 OK lines, then "card-ladder: all rows OK", exit 0
```

3. **Controls.**
   - *Positive:* the unmodified block on a clean scratch dir prints all 15 `OK:`
     lines and `card-ladder: all rows OK` with exit 0; the P0 card it builds is
     byte-identical to M5.30's (`b0faf119…33237`).
   - *Negative (the page's own falsifier — exit 0, wrong token):* mutate one
     expected token in a copy of the block (`contained=1` → `contained=2`) and
     run it; the row must print `FAIL … got [census: contained=1 …]` and the
     block must exit 1. This is the exact case the falsifier names.
   - *Negative (a `NOT RUN` row cannot be reported as passing):* mutate the P1
     row's assertion from `0` to `1` (pretending M5.49's flag exists); the row
     must print `FAIL: want [1] got [0]` and the block exit 1.
   - *Negative (a tool whose exit 1 is intended):* `fit_census` on a tree that
     needs relocation and `check-diff` without `--allow-metadata` both exit 1
     while printing their token; the block asserts token **and** exit code, so
     neither a crash (exit 2) nor a silent pass (exit 0) satisfies them.

4. **Scope.** `docs/format/card-ladder.md` has 21 rung rows (10 P0, 5 P1, 6
   P2); 7 are `NOT RUN — <task>` and 15 are asserted by the page's block (10 P0,
   the P1 absence assertion, 4 P2). This EXP runs on this host: the factory
   tree, the EU 2011 image and the derived P0 card, two profiles, `TODO.md`
   status lines for M5.16/M5.36, and `tools/l2check.py`'s source for the absent
   class check. Excluded: any P1 card (does not exist), any P2 tree (does not
   exist), and any firmware/emulator run (rule 13: M3.25/M8/L5). The page's own
   statements about *what a rung contains* are M5.38's; this page only decides
   them.

5. **Falsifier.** Stated before the result: a row that exits 0 without printing
   its token, or a number on the page that no page command prints, refutes the
   page.

### 4. A P2-adjacent check that does not belong in a row yet

`tools/lev3456.py verify` on the factory `LEV3456R.DAT` under `python3` (3.15,
zlib-ng) exits **3** with `UNVERIFIABLE … the compressor, not the data,
differs`; under `python3.13` (stock zlib 1.3.2) it exits **0** (`OK (section 1
level 5 strict; levels 3/4 best-effort)`). This is the known zlib-ng caveat, not
a P2 gate: a P2 row must name the interpreter, which M5.16 owns. The page
therefore leaves the whole LEV3456 step `NOT RUN — M5.16` instead of quoting a
token that depends on which Python runs it.

## Interpretation

- **FACT:** the P0 rung is a runnable gate today: 10 commands, eight exit 0 and
  two exit 1 by design, every one printing the token the page names; the block
  reproduces the M5.30 card from scratch (`b0faf119…33237`).
- **FACT:** P1 has no card gate — `one_tile_pipeline.py` has no
  `--preserve-tile` (M5.49 open) — so the page prints its card rows as
  `NOT RUN — M5.49`, and that absence is itself a passing assertion (`0`).
- **FACT:** P2's routing and class gates do not exist: M5.16 is `blocked`
  (M9.18), M5.36 is `open`, and `l2check.py` has no `tile_class_roundtrip`.
- **OBSERVED:** the page's value is the exit-code assertion: `fit_census` and
  `check-diff` exit 1 when the answer is "this does not fit / bytes are outside
  the class", a red row, and the block treats a 0 there as a failure (control
  A's class).
- **UNKNOWN:** whether P1's verbatim tile will be *displayed* by the unit
  (rule 13; L5). The ladder page says so in each row's "does not prove" cell.

## Conclusion

`docs/format/card-ladder.md` states the ladder as checks: P0 (10 commands, one
OSM-derived tile, card `b0faf119…33237`), P1 (factory tile verbatim, tiles

`NOT RUN — M5.16`, class golden `NOT RUN — M5.36`). All 15 runnable rows print

No separate navigator ran this pass: the subagent router returned the
upstream-protocol error on every launch, so the TL reviewed in-process. The
self-review below is recorded as such, not as an APPROVE.

- **Verified:** the page's 40-line block was re-run from a clean scratch dir
  (card rebuilt from the recipe) and printed 16 x `OK:` plus
  `card-ladder: all rows OK`, exit 0 — matching the driver's claim.
- **Negative control A (re-run):** one token changed to

  fails loudly on a wrong token, not just on a wrong exit code.
- **Negative control B (re-run):** the P1 `NOT RUN` row (the absent
  `--preserve-tile` flag, expected `0`) changed to expect `1` ->
  `FAIL: want [1] got [0]`. A missing gate cannot be asserted as present.
- **Defect fixed:** the page said the P0 card is "8 GiB on disk"; it is
  7.50 GiB (`8057257984` B, the image size — the copy is not sparse). Corrected
  to the quoted byte count; the EXP already had the right number.
- **Not changed:** rows 3 and 8 are expected exit 1 (`fit_census` "does not
  fit", strict `check-diff` "outside 9"); their tokens are still asserted, so a
  regression to exit 0 with the same text would pass — acceptable because the
  token itself is the negative result ("needs relocation", "outside: 9") and a
  clean run prints the opposite text.
