# EXP-2026-11-08-M9.13-reader-run: L3 run of the M3.5 tile reader is blocked on the module entry kind

- **Status:** failed
- **Date:** 2026-11-08
- **Sample:** `archive/head256.img` (first 256 MiB of the EU 2011 image, build A,
  image start `0x200200`), SHA-256
  `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`.
  Full EU image SHA-256 `105e2032e480e8ba162a2a9d4b6624cb1dafee380379a9908f3f101b15076307`
  (not used here; the `Navi.exe` section lies within the first 256 MiB).
- **Tools:** `python3 3.x` (stdlib only), `tools/cerom.py`, `tools/l3_harness/runner.py`
  (PySh4 engine, `targets.json` schema `osm2leaf.l3.targets/v1`).
- **Claims:** C-2230, C-2231, C-2232
- **Supersedes:** none
- **Superseded by:** none

## Question

Does `tools/l3_harness/runner.py run tile_reader` execute the M3.5 tile reader
entry (`Navi.exe` VA `0x0041f26c`) on a factory tile, and does its result match
`clarion_tile.read_tile`?

## Hypothesis

Falsifier: the runner executes `0x0041f26c` (or any module VA) and returns a
level table, or the validator accepts a module-VA entry. Hypothesis (from the
M9.13 Depends line and the M9.5 result): the runner cannot yet take a module VA
as entry, because `entry.kind = "module"` is the M9.20 follow-up.

## Interpretation

- **FACT:** The three M3.5 reader VAs attribute to `Navi.exe` section 0, an
  uncompressed section, at file offsets `0x0109d46c`, `0x010a3bbc`,
  `0x010a577a` (C-2230).
- **FACT:** `runner.py` accepts only `synthetic` and `blocked` entry kinds. A
  module VA cannot be declared as an entry, so the runner has no way to call
  `0x0041f26c` (C-2231).
- **FACT:** The `tile_reader` result is `BLOCKED` with the stale reason from
  before M3.5, because `targets.json` still says no entry was recovered.
- **OBSERVED:** The runner harness works on its synthetic probe, so the BLOCKED
  result is not a broken harness (C-2232).
- **HYPOTHESIS:** Once M9.20 adds `entry.kind = "module"` (and the argument
  registers the reader needs via `engine_hook`), `runner.py run tile_reader`
  can execute the reader. Not tested here.
- **UNKNOWN:** Whether the reader returns the `clarion_tile.read_tile` level
  table; no run reached it.

## Conclusion

M9.13 is **blocked** on M9.20. No `docs/format/` change: the reader's behaviour
on a tile is still unobserved. Claims C-2230 to C-2232 are added to
`docs/research/claims.md`. The reader VAs themselves are unchanged from M3.5.
