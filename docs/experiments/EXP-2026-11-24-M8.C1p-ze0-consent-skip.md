## Question

Can a small patch to `ScreenStateCC.dll` in the 2011 (ZE0) card's ROM image A
make the state machine leave `SRT_COLD_I_AGREE` (EU) / `SRT_COLD_I_AGREE_NAM`
(US) without any touch, and is that visible as a `ScreenState` log transition
with zero `SK_SCT_AGREE_CLICK` on `-M ze0`?

## Hypothesis

The ZE0 consent state's event handler can be retargeted to an event the skin
already raises without a tap. Expected: patched card logs `ForwardState` out of
the consent state with `grep -c SK_SCT_AGREE_CLICK` = 0; tool `--selftest`
passes. **Falsifier (task):** the consent state has no timer or transition site
that a small patch can redirect — then `blocked` with the sites and blocker
named, not `done`.

### 3. Controls

- *Positive (tool):* `ze0_consent.py --selftest` PASS (0 failures);
  `selftest.py --only ze0_consent` PASS; `find` prints one (EU) / two (US)
  unique sites per copy with matching stored/computed SUM4 (O3, O4).
- *Positive (L4, US):* patched US card reaches `SRT_COLD_I_AGREE_NAM` (8 log
  lines), logs `TELEMA_NOTIFY_AGREE`, `VAR_I_AGREE_STATUS = "true"` and
  `ForwardState [MAP_RELAY]`, then `ForwardState
  [MAP_MAPOPERATION_NORMAL_MAP]`; `grep -c SK_SCT_AGREE_CLICK` = 0 and no panel
  tap is sent (O6).
- *Negative (attribution):* unpatched US card with the **same** `--ui-start`
  recipe reaches the same consent state and logs the same automatic
  `SK_OTH_SCREEN_UNLOCK`, but `grep -c TELEMA_NOTIFY_AGREE` = **0** (it stays in
  consent — only `UpdateScreenLock` follows); the patched card logs **1**
  (O8). The zero-click clean exit is therefore attributable to the card patch,
  not to `--ui-start`.
- *Negative (mutation):* selftest's mutated-site case is **refused** and its
  corrupted-SUM4 case is detected (O8a); injecting one literal click line into
  a copy of the log moves `grep -c SK_SCT_AGREE_CLICK` from **0** to **1**
  (O8b), so the assertion can fail (H69).
- *Companion negative (prior record):* `agree_qy7` stops with "cannot find
  SRT_COLD_I_AGREE_TELEMA" on the EU card (C-8359); no Companion code/bytes
  were copied.

### 4. Scope

ROM image A only, both copies (NB00 `0x200000`, NB01 `0x2000000`), of the two
2011 cards. Name tables read from `ScreenStateCC.dll`'s decompressed sections
(EU sec1 `0x001fa000`, sec2 `0x0021d000`; US sec1 `0x001f8000`, sec2
`0x0021b000`): 800 state-pointer slots and 5,200 event-pointer slots scanned
per card, with the target names found at EU state indices 610/611 and event
indices 2190/2211 and US state 608/609 and event 2182/2203 (O3, O9). The
patch changes one 16-bit literal per copy on EU (`0x13ebf3e`,
`0x31ebf3e`) and two per copy on US (`0x1479a9a`, `0x147a1b4`, and the NB01
equivalents), plus each copy's SUM4 u32 at `+0x34`. Excluded: GPS time fix
(M8.C1m), from-zero card (M8.H79), AZE0 states, Companion implementation,
car/bench L5, firmware image B/C. Firmware traps enforced: SH-4 code is
little-endian; every address came from `cerom.py`/`sh4dis.py` and the card's own
name tables (no fitted signature, no Companion byte grammar); all executable
sections are readable (C-2128).

## Interpretation

- **FACT:** the ZE0 consent handler has a redirectable event-comparison site on
  both 2011 cards (O3, O9); the task's own falsifier ("no site a small patch
  can redirect") does not fire. The patch is small (one 16-bit literal per
  image-A copy plus the header SUM4 u32) and uses no Companion bytes.
- **FACT:** on the US card the patch works as designed — with no tap and zero
  `SK_SCT_AGREE_CLICK`, the state machine takes the already-arriving
  `SK_OTH_SCREEN_UNLOCK` into `TELEMA_NOTIFY_AGREE`,
  `VAR_I_AGREE_STATUS=true` and `ForwardState(MAP_RELAY)` (O6). The unpatched
  control, with the identical `--ui-start` recipe, does not (O8c).
- **FACT:** the per-build unlock id differs (US `0x0889`, EU `0x0891`); the
  first EU patch attempt used the US id and would have hit
  `SK_OTH_IPOD_UPDATE`. The committed tool fixes this before the final EU run
  (O3, O9).
- **FACT:** the EU Done-when is not met. On this machine the EU card never
  creates AuiApp/ScreenState under anon flash, zero flash, object-store IPL,
  micon peer, map-code file-only or both-copy map code (O7). The consent state
  is therefore never entered, so no transition out of it can be logged.
- **HYPOTHESIS (from M1.57/M3.43, not re-measured here):** the EU card needs the
  owner's real unit flash (VSram navigation state) to create AuiApp; that dump
  is not on disk this session (M1.57's 8 MiB dump was reaped). Anon flash
  reports `Area:20 >> USA` and the EU card fails its launcher gate; zero flash
  reports Euro but process creation fails.
- **UNKNOWN:** whether the corrected EU patch also produces a zero-click exit
  once a flash configuration that creates AuiApp is available. The US result
  is strong evidence but is not the EU assertion the task demands.

**Rule-13 limit:** the US L4 run is an L4 acceptance of the *patch mechanism*,
not M8.E4 acceptance of rendered OSM roads. The EU L4 transition log remains
the acceptance oracle for this task's Done-when and is unmet.

## Conclusion

`tools/ze0_consent.py` is added with `find`, `patch` (both NB copies, SUM4
`+0x34` fixed), `verify`, `--dry-run` and a passing `--selftest`; the derived
sites are unique on both cards. On the US 2011 card the patch delivers the
task's user-visible assertion exactly: the state machine leaves
`SRT_COLD_I_AGREE_NAM` with zero `SK_SCT_AGREE_CLICK`, and the same recipe on
the unpatched card does not. On the **EU** card the Done-when cannot be
verified here because AuiApp/ScreenState never start on any available flash
configuration; the blocker is the same one that blocks M3.43 and M8.H79. The
task is therefore `blocked` with a one-line blocker and `Unblock:`, not `done`.
No format doc was changed; no vendor byte or patched ROM was committed.

## Blocker

EU 2011 card does not create AuiApp/ScreenState on `-M ze0` with any available
unit-flash configuration (anon, zero; with/without object-store IPL, micon
peer, map-code fix), so `SRT_COLD_I_AGREE` is never entered and the patched-EU
transition-with-zero-clicks assertion cannot be observed.
