# EXP-2026-11-19-M5.48: a refused run leaves no `--out` tree

- **Status:** done (tool change + real-root refused run; not read by the unit, rule 13)
- **Date:** 2026-11-19
- **Sample:** EU 2011 image
  `archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img`, SHA-256
  `105e2032e480e8ba162a2a9d4b6624cb1dafee380379a9908f3f101b15076307`.
  Factory root extracted read-only to `/home/marek/projekty/leafre-work/m5.29-factory-root`
  (480 files, 12 top-level entries); the tile under test is `MAPAL001/B48R058R.DAT`
  289,319,168 B, SHA-256 `e9c9cb2236f6b53ad4fe9687a18a351afe80a46a63c0a1f18dc46d6c8af3ff52`.
  Generated trees live in `~/projekty/leafre-work/scratch/m5.48/` (outside the repo,
  deleted after this record). No vendor bytes or OSM extract committed.
- **Tools:** the refused-run artifacts were produced by **`python3.13` 3.13.17
  `/home/marek/.local/bin/python3.13`, `zlib 1.3.2` (stock)**; the selftests and
  `gate.py` were run with `python3` 3.15.0 and `TMPDIR` pointed at the disk scratch
  (the default `/tmp` is a 3.8 GiB tmpfs; see the `/tmp` failure control). Repo tools:
  `tools/one_tile_pipeline.py` (this branch), `tools/tilewriter.py`,
  `tools/selftest.py`, `tools/gate.py`.
- **Claims:** C-4570–C-4579
- **Supersedes:** none (extends EXP-2026-11-18-M5.44-level2 §5/§6 and
  EXP-2026-11-18-M5.45-idempotence, both of which record a partial `--out`)
- **Superseded by:** none

## Question

After a `tilewriter` refusal, does `tools/one_tile_pipeline.py` leave the copy of the
factory root at `--out`, so that a later `os.path.isdir(out)` reads a failed run as a
built card (M5.35 bundle, M7.1 mass run)?

## Hypothesis

The pipeline copies the factory root (`_copy_factory_root`) **before** `tilewriter` runs,
and `main()` returned without touching `--out`, so a non-zero run leaves a full 480-file
tree at `--out` that differs from factory only by the manifest bytes (M5.44 §6, M5.45 §2).
The fix is to remove a tree **this run created** on a non-zero exit (a directory that
already existed before the run is never deleted), with `--keep-partial` to keep a failed
tree for inspection, and to record the state in the `--json` report so a later task can
assert "removed" without guessing.

**Falsifier:** a refused run still leaves a 480-file `--out` with no `--keep-partial`.

## Method

1. **Sample and hash.** Factory root and tile as above; `sha256sum` on the tile.

2. **Commands.** Run from the repository root; `$S` is the disk scratch directory
   (not `/tmp`). The refused run uses the real factory root and a real `--parcel`, so
   the failure is `tilewriter`'s own (`C-4463`), not a synthetic gate.

```bash
S=~/projekty/leafre-work/scratch/m5.48
R=/home/marek/projekty/leafre-work/m5.29-factory-root
mkdir -p $S
sha256sum $R/MAPAL001/B48R058R.DAT

# two-node way inside the aliased level-2 directory (72,936)
cat > $S/l2-72-936.osm <<'OSM'
<?xml version="1.0"?><osm version="0.6">
<node id="1" lon="12.2000" lat="48.6000"/>
<node id="2" lon="12.2010" lat="48.6010"/>
<way id="10"><nd ref="1"/><nd ref="2"/><tag k="highway" v="residential"/></way>
</osm>
OSM

# refused run: exit 1, no --out
rm -rf $S/post
python3.13 tools/one_tile_pipeline.py --factory-root $R --cell B48R058R \
  --parcel 72,936 --level 2 --osm $S/l2-72-936.osm \
  --out $S/post --json $S/post-report.json
echo "exit=$?"
ls -d $S/post
python3 -c "import json; r=json.load(open('$S/post-report.json')); \
  print('tilewriter_rc', r['counts'].get('tilewriter_rc')); \
  print('partial_out', r.get('partial_out'))"

# opt-in: --keep-partial keeps the partial tree
rm -rf $S/keep
python3.13 tools/one_tile_pipeline.py --factory-root $R --cell B48R058R \
  --parcel 72,936 --level 2 --osm $S/l2-72-936.osm \
  --out $S/keep --keep-partial --json $S/keep-report.json
echo "exit=$?"
echo "top-level $(ls $S/keep | wc -l) files $(find $S/keep -type f | wc -l)"
python3 -c "import json; r=json.load(open('$S/keep-report.json')); \
  print('partial_out', r.get('partial_out'))"
```

3. **Controls.**
   - *Positive (success keeps the tree):* the same real root and a **spliceable**
     level-2 directory `(76,940)` (`lon 16.2 lat 50.9`) completes with `exit=0`,
     `partial_out.state = kept-success`, `files_left = 480`. Its `l2check` and
     `cardcheck` return 0, so the tree is a real card copy, not a partial one.
   - *Positive (a pre-existing `--out` is not deleted):* `mkdir $S/pre` then the
     refused run into `$S/pre` reports `partial_out.state = kept-existed` and leaves the
     directory (the removal rule applies only to a tree this run created).
   - *Negative (removal disabled mutant, the red control):* a scratch copy
     `$S/toolsmut/` with `_remove_failed_out` short-circuited to `return "nothing"` (one
     inserted line, the tree copy **not** touched) leaves a **480-file** `$S/mutout`
     after the same refused run, with `partial_out.state = nothing`, and makes
     `one_tile_pipeline --selftest` FAIL on four M5.48 checks (incl. the falsifier line
     "a refused run leaves no --out").
   - *Negative (guard refusal):* a preserve-only `--parcel` is refused before any copy
     (exit 2, no `--out`); this was already true before the change and is asserted so the
     fix does not silently remove the early-refusal path.
   - *Negative (pre-fix behaviour, same command):* the pre-fix branch (`pre2`) left a
     480-file tree on the same command — this is the M5.44 §6 observation, re-run on the
     driver's machine; the post-fix `post` leaves nothing. The `pre2` tree is deleted by
     this record, as the fix prescribes.

4. **Scope.** `tools/one_tile_pipeline.py` only: `_remove_failed_out`, the
   `out_existed_before` capture in `main()`, the `partial_out` report field and the
   `--keep-partial` flag, plus one `--selftest` block. One tile (`B48R058R`), the
   `tilewriter`-refusal path (exit 1) and the early usage-refusal path (exit 2).
   Excluded: `mkcard.py`, `build.sh`, the M5.35 bundle and the M7.1 mass run's own
   `isdir` tests (they consume this behaviour, they are not changed here); every other
   tile and every other pipeline stage.

5. **Falsifier.** Stated above, before the result.

## Observations

### 1. Refused run leaves no `--out` (real factory root, stock zlib)

```text
$ python3.13 tools/one_tile_pipeline.py --factory-root $R --cell B48R058R \
    --parcel 72,936 --level 2 --osm $S/l2-72-936.osm --out $S/post --json $S/post-report.json
zlib: 1.3.2 / 1.3.2 via /home/marek/.local/bin/python3.13 (python 3.13.17)
report: …/scratch/m5.48/post-report.json
exit=1
ls: cannot access '…/scratch/m5.48/post': No such file or directory
tilewriter_rc 1
partial_out {'removed': True, 'state': 'removed', 'keep_partial': False,
             'existed_before_run': False, 'files_left': 0}
```

The refusal message is `tilewriter`'s own (C-4463): the run reached the copy and the
tile splash, then `tilewriter` refused and the copied tree was removed. The `--json`
report stays intact (it is written after the cleanup), and `tilewriter_rc = 1` is still
recorded — the failure is not hidden.

### 2. `--keep-partial` keeps the failed tree for inspection

```text
$ python3.13 tools/one_tile_pipeline.py … --out $S/keep --keep-partial --json $S/keep-report.json
exit=1
top-level 12 files 480
partial_out {'removed': False, 'state': 'kept', 'keep_partial': True,
             'existed_before_run': False, 'files_left': 480}
```

The kept tree is exactly the factory copy the pipe made (480 files, 12 top-level), so a
later diff of a failed run still works.

### 3. The success control keeps the tree

```text
$ python3.13 tools/one_tile_pipeline.py --factory-root $R --cell B48R058R \
    --parcel 76,940 --level 2 --osm $S/l2-76-940.osm --out $S/succ --json $S/succ-report.json
exit=0
top-level 12
tilewriter_rc 0  l2check_rc 0  cardcheck_rc 0
partial_out {'removed': False, 'state': 'kept-success', 'keep_partial': False,
             'existed_before_run': False, 'files_left': 480}
```

The `(76,940)` splice is the M5.45 accepted directory (C-4463), so this is a real card
copy that also passes the L2 and L1 checks; only a failed run loses its tree.

A pre-existing `--out` on the refused command gives `state=kept-existed`, not `removed`:

```text
$ mkdir -p $S/preexist
$ python3.13 tools/one_tile_pipeline.py … --out $S/preexist --json $S/preexist-report.json
exit=1
top-level 12
tilewriter_rc 1
partial_out {'removed': False, 'state': 'kept-existed', 'keep_partial': False,
             'existed_before_run': True, 'files_left': 480}
```

The four red lines are exactly the behaviour the task adds; the "tilewriter rc not

### 5. Pre-fix behaviour on the same command

The branch before this change (`pre2`) left the tree:

### 6. `/tmp` is not the failure

`python3 tools/selftest.py` and `gate.py` first failed on `mkcard --selftest` with
`OSError: [Errno 28] No space left on device` (the 3.8 GiB `/tmp` tmpfs, 94 % full,
AGENTS.md). With `TMPDIR=$S/tmp` (disk scratch) the same commands are green. This is an
environment constraint, not this task's result; no tool was changed for it.

## Interpretation

- **FACT:** a `tilewriter` refusal (exit 1) leaves **no** `--out` when the tree did not
  exist before the run: `state=removed`, `files_left=0`; the `--json` report is intact and
  records `tilewriter_rc=1` (C-4570).
- **FACT:** `--keep-partial` keeps the 480-file failed tree for inspection and still
  exits 1 (`state=kept`, `files_left=480`) (C-4571).
- **FACT:** a pre-existing `--out` directory is never deleted by the cleanup
  (`state=kept-existed`); the rule is "only a tree this run created" (C-4572).
- **FACT:** a successful run (`tilewriter_rc=0`, `l2check_rc=0`, `cardcheck_rc=0`) keeps
  its 480-file tree (`state=kept-success`), so the cleanup does not touch good runs
  (C-4573).
- **FACT:** the removal-disabled mutant leaves a 480-file `--out` and makes the
  `--selftest` M5.48 block red on 4 checks (the falsifier is one of them), so the
  selftest can fail (C-4574).
- **OBSERVED:** the pre-fix branch left a 480-file `pre2` on the same command; the fix
  removes it (this is the M5.44 §6 follow-up, closed here) (C-4575).
- **OBSERVED:** the earlier guard refusal (preserve-only `--parcel`) already left no
  `--out` on this branch; the change does not regress that early path (C-4576).
- **UNKNOWN:** whether any later M7.1 caller passes `--keep-partial` on purpose; the
  current default (remove) is what the M5.35/M7.1 `isdir` tests want.

## Conclusion

`tools/one_tile_pipeline.py` now removes a `--out` tree it created when the run exits
non-zero, unless `--keep-partial` is given; a directory that existed before the run is
never deleted, and the `--json` report gains a `partial_out` block
(`removed`/`state`/`keep_partial`/`existed_before_run`/`files_left`). On the real EU
factory root a `tilewriter` refusal (the C-4463 aliased `(72,936)` directory) leaves no
`--out` and the report is intact; `--keep-partial` keeps the 480-file tree, and a
successful `(76,940)` run keeps its 480-file card copy. The `--selftest` gains a case that
asserts the refused-run / `--keep-partial` / pre-existing / guard states; it is red on a
removal-disabled mutant. Rule 13 unchanged: nothing here is read by the unit.
