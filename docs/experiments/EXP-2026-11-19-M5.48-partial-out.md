## Question

After a `tilewriter` refusal, does `tools/one_tile_pipeline.py` leave the copy of the
factory root at `--out`, so that a later `os.path.isdir(out)` reads a failed run as a
built card (M5.35 bundle, M7.1 mass run)?

## Hypothesis

The pipeline copies the factory root (`_copy_factory_root`) **before** `tilewriter` runs,
and `main()` returned without touching `--out`, so a non-zero run leaves a full 480-file
tree at `--out` that differs from factory only by the manifest bytes (M5.44 §6, M5.45 §2).
The fix is to remove a tree **this run created** on a non-zero exit (a directory that
already existed before the run is never deleted), with `--keep-partial` to keep a failed
tree for inspection, and to record the state in the `--json` report so a later task can
assert "removed" without guessing.

**Falsifier:** a refused run still leaves a 480-file `--out` with no `--keep-partial`.

## Interpretation

- **FACT:** a `tilewriter` refusal (exit 1) leaves **no** `--out` when the tree did not
  exist before the run: `state=removed`, `files_left=0`; the `--json` report is intact and
  records `tilewriter_rc=1` (C-4570).
- **FACT:** `--keep-partial` keeps the 480-file failed tree for inspection and still
  exits 1 (`state=kept`, `files_left=480`) (C-4571).
- **FACT:** a pre-existing **non-empty** `--out` is refused before the copy (exit 2,
  `KEEP.ME` byte-identical, no report written) unless `--force-overwrite`; a pre-existing
  **empty** `--out` is allowed and restored to empty on failure (`state=removed-contents`,
  the directory stays). The copy step no longer `rmtree`s a directory this run did not
  create, so a user file it never wrote cannot vanish (C-4572).
- **FACT:** a successful run (`tilewriter_rc=0`, `l2check_rc=0`, `cardcheck_rc=0`) keeps
  its 480-file tree (`state=kept-success`), so the cleanup does not touch good runs
  (C-4573).
- **FACT:** the removal-disabled mutant leaves a 480-file `--out` and makes the
  `--selftest` M5.48 block red on 5 checks (the falsifier is one of them), so the
  selftest can fail (C-4574).
- **OBSERVED:** the pre-fix branch left a 480-file `pre2` on the same command; the fix
  removes it (this is the M5.44 §6 follow-up, closed here) (C-4575).
- **OBSERVED:** the earlier guard refusal (preserve-only `--parcel`) already left no
  `--out` on this branch; the change does not regress that early path (C-4576).
- **UNKNOWN:** whether any later M7.1 caller passes `--keep-partial` or `--force-overwrite`
  on purpose; the current defaults (remove on failure, refuse a non-empty `--out`) are what
  the M5.35/M7.1 `isdir` tests want.

## Conclusion

`tools/one_tile_pipeline.py` now refuses a non-empty pre-existing `--out` before any copy
(`--force-overwrite` is the opt-in), lets an empty pre-existing `--out` stay empty after a
failure, and removes a `--out` tree it created when the run exits non-zero unless
`--keep-partial`; the `--json` report gains a `partial_out` block
(`removed`/`state`/`keep_partial`/`force_overwrite`/`existed_before_run`/`state_before_run`/`files_left`).
On the real EU factory root a `tilewriter` refusal (the C-4463 aliased `(72,936)`
directory) leaves no `--out` and the report is intact; a non-empty `--out` is refused with
`KEEP.ME` byte-identical; `--keep-partial` keeps the 480-file tree; and a successful
`(76,940)` run keeps its 480-file card copy. The `--selftest` gains cases for the
refused-run / `--keep-partial` / non-empty-refusal / `--force-overwrite` / empty-`--out` /
guard states; it is red on a removal-disabled mutant. Rule 13 unchanged: nothing here is
read by the unit.

## Corrections after navigator review

Round 2 (navigator, 2026-11-19) — a real data-loss path, all three blocking points applied:

1. **The copy step destroyed a pre-existing `--out`.** `_copy_factory_root` did
   `if dst.exists(): shutil.rmtree(dst)` then `copytree`, so a pre-existing `--out` with
   `$S/pre/KEEP.ME` survived as a **directory** but `KEEP.ME` was replaced by the factory
   copy — while C-4572 / §3 said only "a user-passed tree is not rolled back", implying a
   file safety that was false. Fixed at the copy side: `_copy_factory_root` now calls
   `_refuse_nonempty_out` and refuses a **non-empty** pre-existing `--out` before any copy
   (`--out … is a non-empty existing directory; refusing to overwrite it. Pass
   --force-overwrite …`, exit 2, no report written); `--force-overwrite` is the explicit
   opt-in. `build_synthetic_out` and `build_factory_out` both refuse, and `main()` checks
   `_out_dir_state` so the synthetic fallback cannot bypass it.
2. **The selftest fixture was misleading.** The old case wrote `(pre_out/"KEEP.ME")` but
   only asserted `pre_out.is_dir()` and `state=="kept-existed"`, so `KEEP.ME` could vanish
   unnoticed. The fixture now asserts `KEEP.ME` survives **byte-identically** (SHA-256
   equal) after the refused run, that exit is **2**, and that no report is written; plus
   `--force-overwrite` replaces the tree and an empty pre-existing `--out` stays empty
   (`removed-contents`).
3. **The EXP success control did not run as written.** It cited `--osm $S/l2-76-940.osm`,
   which Method only created for `72,936`. The `76,940` heredoc (`lon 16.2000 lat 50.9000`;
   `16.2010/50.9010`, the same fixture as EXP-2026-11-18-M5.45-idempotence) is now in the
   Method block, and the Method/Reproduction commands are runnable as written (no
   ellipsis; the success command uses `TMPDIR=$S/tmp`, see §6).
