# EXP-2026-11-23-M4.98 — Section-2 link fields read off the decompiled route search (Ghidra)

- **Status:** done. Direction, turn restrictions, cost, length, boundary
  links and header counts are named from firmware and checked on the whole
  London tile; level-2 unit 1 is decoded (second pass). In L4 closing one
  link of the factory route (`w2 >> 14` = 3 at both ends) gives a detour,

## Question

M9.75 found which code reads section 2 but not what the link words mean.
With the code decompiled, which words carry direction (one-way), turn
restrictions, cost and length, and how do tiles join?

## Hypothesis

The route search's node expansion and the functions around it test each
attribute with a fixed mask, and the London data obeys every such rule.
Falsifier: a rule read off the code that the factory tile breaks (for example
a "one-way" pattern that is not paired across a link's two ends).

## Method

1. **Sample and hash.** The EU2011 firmware head and factory London tile in the
   Sample bullet above (full hashes); build A `Navi.exe`, image start `0x200200`.

2. **Commands.** From the repo root (`$FAC` = extracted factory tree):

   ```bash
   python3 tools/ghidra/NaviDecomp.java --selftest
   python3 tools/cerom.py extract archive/head256.img Navi.exe --image-start 0x200200
   python3 tools/cerom.py decompress archive/head256.img Navi.exe --image-start 0x200200
   python3 tools/callgraph.py callers G.json 0x00363834
   python3 tools/sec2_fields.py $FAC/MAPAL001/B48R068R.DAT
   python3 tools/sec2_fields.py $FAC/MAPAL001/B48R068R.DAT --level2
   python3 tools/sh4dis.py archive/head256.img Navi.exe --image-start 0x200200 --va 0x003534d4 --count 60
   ```

   The original steps 1-5 (Ghidra import/decompile, the reader and caller set,
   pool constants, the whole-tile rule check and the forbidden-pattern controls)
   are the run recipe; every printed value is quoted in the tables above.

3. **Controls.** Each rule is tested against a pattern it forbids: one-way must
   be 1/2 across the two ends, never 1/1 or 0/2 (0 other patterns in 4,263,724
   inner links); a boundary link must sit on a mesh-edge node (688,178 all do);
   the 11 header pairs sum to the node and link counts (45,184/45,184). In L4
   the identical re-encode keeps the route (`3e885e8c…`), closing link `0x145`
   on the route detours (`fe37c845…`) and closing off-route `0x9c` does not.

4. **Scope.** EU2011 build A; the decompiled route-search functions and the
   whole London tile (45,184 level-1 records, 9,215,626 links; 3,214 level-2
   records), one L4 route per card. Excluded: the runtime cost tables (`w1`
   categories), turn-condition semantics beyond the layout, US2011. Decompiled
   C and screenshots stay outside the repository.

5. **Falsifier.** A rule read off the code that the factory tile breaks — for
   example a one-way pattern not paired across a link's two ends. London has 0
   other direction patterns, so the falsifier did not fire.

## Observations

Link = 7 halfwords `w0`…`w6` (+ extras), as M9.75. What the code does with
each field (EU2011 build A):

| Field | Code | Rule |
| --- | --- | --- |
| `w2 >> 14` | `0x00363834` (`& 0xc000`, skip when `== 0x8000` or `== 0xc000`) | leaving the node along this link is forbidden for 2 and 3 |
| `w2 & 0x3fc0 >> 6` | `0x00354018`, `0x003545f4` | number of turn words after the fixed words |
| turn word | `0x00354018` | top nibble = target link index at the node (`0xf` = condition record); low byte `0x00` allowed, `0xff` always banned, other = condition index |
| condition | `0x0035c478` (`*_DAT` table + low byte, entries of 3 words, `0x400` = chained) | time/vehicle condition; table pointer = the reply's `+24` pointer (unit 2) |
| `w2 & 0x3f` | `0x00363834` → `0x00354810` | second condition block, evaluated only when non-zero |
| `w3 & 0x1fff`, `w4 & 0xf` | `0x003582a4`, `0x003429fc` | link id and class (key to section 1, C-9915) |
| `w3 & 0x2000` | `0x003582a4` | which end of the drawn link the entry sits at; combined with the query side to pick a direction |
| `w3 >> 14`, `w1 & 1` | `0x003582a4` (copies word 7, and word 8 when `w3 >> 14 == 2`) | optional extra words |
| `w4 & 0x8000` | `0x003680e4` | boundary link: `w0 & 0x3fff` is a node index in the neighbouring mesh, not this one |
| `w4 & 0xf` | `0x00363834` (table `0x5618b0`, entries 12–15 = 1 in the image) | class filter: classes 12–15 are skipped when the table says so |
| `w5` | `0x003582a4` | `(w5 & 0xfff) × {1, 2, 4, 40}[w5 >> 12 & 3]` (table `0x55f20c`), split by position along the link: cost/time |
| `w6` | `0x00341094` | `(w6 & 0xfff) × {1, 2, 4, 20}[w6 >> 12 & 3]` (table `0x560664`): length |
| `w1 >> 12`, `w1 & 0x30`, `& 0xe00`, `& 0x1c0` | `0x00341980` (cost) | speed/penalty table index per class; `& 0x1c0 == 0x140` multiplies cost by about 1.43; `& 0xe00 == 0x400` subtracts a class penalty; `0x80`/`0x140` also gate a transition flag in `0x00363834` |
| `w0 & 0x4000` | `0x00341980` | multiplies cost by a runtime factor |
| node `w0 & 0x7ff`, `w1 & 0x7ff` | `0x003418a8`, `0x003534d4` | node x, y; used for the turn angle (U-turn test) and the mesh-edge flag |
| unit 0 words 4–25 | — | 11 (nodes, links) pairs; their sums are the node and link counts |
| header halfword 26 | `0x0040517e` | ISO 3166 country code (826, 250, 56, 528 in London) |

### Level 2 (second pass: the levels above the search)

Request kind `0x10` returns header pair 1 (unit 1) of a record
(`0x00405078`). Its only reader in the route code is `0x0036d530` (caller chain
`0x0036e1bc` ← `0x0036e51c` ← `0x00360f10`): it takes a count from
`entry[0] >> 12`, skips a self triple and walks that many triples of `2K+1`
words, comparing word 1 with the current level-1 record and keeping words 0
and 2. With that layout the London level-2 data parses with no remainder
(`sec2_fields.py --level2`):

| Rule | Count |
| --- | --: |
| level-2 records: unit 0 / unit 0 + unit 2 / unit 1 only | 2,655 / 559 / 3,214 |
| unit-0 records with a unit-1 record of the same key | 3,214 |
| unit 1: word 0 = paired node count; exact parse with a 2-word trailer = own key | 3,214 / 3,214 |
| unit 1: exactly one entry per level-2 node | 3,214 / 3,214 records |
| entry neighbour count = node link count | 430,438 / 430,438 |
| link triple names that link's target node (`w0 & 0x3fff`), in link order | 1,060,975 / 1,060,975 |
| self level-1 node lies on the level-2 node (level-1 x, y / 4 across 4 × 4 meshes, ±1) | 430,084 / 430,438 |
| same-record link triple names a direct level-1 neighbour of the self level-1 node | 1,001,209 / 1,001,209 |

Level-1 key of a triple = (`w0 & 0xfff0` + 12 + `sel >> 14`, `w1 & 0xfff0` +
12 + `(sel >> 6) & 3`); with the other assignment 0 records match. Levels 4
and 5 exist in the section table but have no records in `B48R068R`.

## Interpretation

- **FACT:** direction is `w2 >> 14` per link end: 0 free, 1 at the end you
  may leave from, 2 at the end you may not leave from, 3 closed. Every inner
  London link obeys the pairing (C-9930).
- **FACT:** turn restrictions are the `(w2 & 0x3fc0) >> 6` words after the
  fixed words, keyed by target link index at the node (C-9931). Conditions
  point into unit 2 (C-9932, OBSERVED for the table layout).
- **FACT:** `w5` is cost/time and `w6` length, each a 12-bit mantissa with a
  2-bit scale (C-9933).
- **FACT:** `w4 & 0x8000` marks a link to the neighbouring mesh, always from
  an edge node (C-9934). This is how tiles join.
- **FACT:** the unit-0 header's 11 pairs sum to the node and link counts;
  header halfword 26 is a country code (C-9935).
- **OBSERVED:** `w1` is a road attribute word read only by the cost function
  (speed index, penalties) (C-9936). Its exact categories need the runtime
  tables.
- **FACT:** level-2 unit 1 is the map from the level-2 graph down to level 1:
  each level-2 node gets its level-1 junction and, per level-2 link, the
  first level-1 node along it (C-9938). This is how the search descends from
  the coarse network to drivable streets.
- **UNKNOWN:** the meaning of `w4 & 0x30`, `w4 & 0x4000`, words 7–8, node
  `w2 & 0x2000`, unit-1 word 1 and the level-2 unit 2 (C-9937).
- **FACT (L4):** the running route search obeys `w2 >> 14` link by link.
  Closing one route link (`0x145`) gives a detour; closing its neighbour off
  the route (`0x9c`) and the identical re-encode keep the route; reversing
  every one-way gives "Could not find route" (C-9939). Making every one-way
  two-way does not change this short route. Reversal leaves the level-2 graph
  and unit 1 untouched, which may be why that search fails outright instead
  of finding another way (not tested).
- **No elevation field:** nothing in section 2 is read as a height, and node
  word 2 is only 0 or `0x2000` in London.

## Conclusion

Everything a writer needs for a basic routable tile is named and checked on
the factory data: framing, direction, turn bans, cost, length, the
section-1 key and the boundary links. A first OSM writer (M5.57) can set
direction from `oneway=*`, cost from length and highway class, and leave turn
words and conditions out. Level 2 is a 1:4 graph over 4 × 4 level-1 meshes,
tied to level 1 by unit 1, which a writer can build from its own level-1
graph. In L4 the firmware follows the field link by link: one closed link on
the route gives a detour. Still open: the runtime cost tables and the few
unnamed bits.
