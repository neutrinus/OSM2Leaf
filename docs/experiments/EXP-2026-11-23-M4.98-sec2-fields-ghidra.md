# EXP-2026-11-23-M4.98 — Section-2 link fields read off the decompiled route search (Ghidra)

- **Status:** partial. Direction, turn restrictions, cost, length, boundary
  links and header counts are named from firmware and checked on the whole
  London tile. The L4 mutation (flip one link's direction, see the route
  change) and the runtime cost tables are still open.
- **Date:** 2026-11-23
- **Sample:** `archive/head256.img` `92aa525d…a007f9` (EU 2011 build A
  `Navi.exe`, image start `0x200200`); factory tile `MAPAL001/B48R068R.DAT`
  `76aa5246…d3e60e`.
- **Tools:** Ghidra 11.4.2 headless (`SuperH4:LE:32:default`, JDK 21),
  `tools/ghidra/NaviDecomp.java` (new), `tools/cerom.py extract/decompress`,
  `tools/callgraph.py`, `tools/sec2_fields.py` (new), `tools/sh4dis.py`.
- **Claims:** C-9930–C-9937 (C-9938, C-9939 reserved)
- **Supersedes:** none. Builds on EXP-2026-11-23-M9.75-sec2-readers-l4 (the
  readers it located).
- **Superseded by:** none

## Question

M9.75 found which code reads section 2 but not what the link words mean.
With the code decompiled, which words carry direction (one-way), turn
restrictions, cost and length, and how do tiles join?

## Hypothesis

The route search's node expansion and the functions around it test each
attribute with a fixed mask, and the London data obeys every such rule.
Falsifier: a rule read off the code that the factory tile breaks (for example
a "one-way" pattern that is not paired across a link's two ends).

## Method

1. Import `Navi.exe` `.text` at `0x11000`, map the decompressed `.data` at
   `0x55d000`, create all 7,596 functions from `.pdata`, decompile
   (`tools/ghidra/README.md`). Decompiled C stays out of the repository.
2. Decompile the readers of M9.75 (`0x003534d4`, `0x003582a4`), the 39
   functions that load the link-size mask `0x3fc0`, and their callers and
   callees (`callgraph.py callers/callees`): the search expansion `0x00363834`,
   its heap `0x003641b0`/`0x00364294`, the link-to-node step `0x003680e4`, the
   turn parser `0x00354018`, the condition evaluator `0x0035c478`, the cost
   function `0x00341980`, the length decoder `0x00341094` and the turn-angle
   check `0x003418a8`.
3. Read each pool constant from the image (`_DAT_xxxxxxxx` in the C).
4. Check every rule on the whole tile: `python3 tools/sec2_fields.py
   B48R068R.DAT` (all 45,184 level-1 records).
5. Controls: each rule is tested against a pattern it forbids (one-way must be
   1/2 across the two ends, never 1/1 or 0/2; a boundary link must sit on a
   mesh-edge node; the header pair sums must equal the counts).

## Observations

Link = 7 halfwords `w0`…`w6` (+ extras), as M9.75. What the code does with
each field (EU2011 build A):

| Field | Code | Rule |
| --- | --- | --- |
| `w2 >> 14` | `0x00363834` (`& 0xc000`, skip when `== 0x8000` or `== 0xc000`) | leaving the node along this link is forbidden for 2 and 3 |
| `w2 & 0x3fc0 >> 6` | `0x00354018`, `0x003545f4` | number of turn words after the fixed words |
| turn word | `0x00354018` | top nibble = target link index at the node (`0xf` = condition record); low byte `0x00` allowed, `0xff` always banned, other = condition index |
| condition | `0x0035c478` (`*_DAT` table + low byte, entries of 3 words, `0x400` = chained) | time/vehicle condition; table pointer = the reply's `+24` pointer (unit 2) |
| `w2 & 0x3f` | `0x00363834` → `0x00354810` | second condition block, evaluated only when non-zero |
| `w3 & 0x1fff`, `w4 & 0xf` | `0x003582a4`, `0x003429fc` | link id and class (key to section 1, C-9915) |
| `w3 & 0x2000` | `0x003582a4` | which end of the drawn link the entry sits at; combined with the query side to pick a direction |
| `w3 >> 14`, `w1 & 1` | `0x003582a4` (copies word 7, and word 8 when `w3 >> 14 == 2`) | optional extra words |
| `w4 & 0x8000` | `0x003680e4` | boundary link: `w0 & 0x3fff` is a node index in the neighbouring mesh, not this one |
| `w4 & 0xf` | `0x00363834` (table `0x5618b0`, entries 12–15 = 1 in the image) | class filter: classes 12–15 are skipped when the table says so |
| `w5` | `0x003582a4` | `(w5 & 0xfff) × {1, 2, 4, 40}[w5 >> 12 & 3]` (table `0x55f20c`), split by position along the link: cost/time |
| `w6` | `0x00341094` | `(w6 & 0xfff) × {1, 2, 4, 20}[w6 >> 12 & 3]` (table `0x560664`): length |
| `w1 >> 12`, `w1 & 0x30`, `& 0xe00`, `& 0x1c0` | `0x00341980` (cost) | speed/penalty table index per class; `& 0x1c0 == 0x140` multiplies cost by about 1.43; `& 0xe00 == 0x400` subtracts a class penalty; `0x80`/`0x140` also gate a transition flag in `0x00363834` |
| `w0 & 0x4000` | `0x00341980` | multiplies cost by a runtime factor |
| node `w0 & 0x7ff`, `w1 & 0x7ff` | `0x003418a8`, `0x003534d4` | node x, y; used for the turn angle (U-turn test) and the mesh-edge flag |
| unit 0 words 4–25 | — | 11 (nodes, links) pairs; their sums are the node and link counts |
| header halfword 26 | `0x0040517e` | ISO 3166 country code (826, 250, 56, 528 in London) |

`0x00341980`'s speed and penalty tables (`0x61fad8`, `0x1200dc0`,
`0x61fb18`) are zero in the image: they are filled at run time.

## Interpretation

- **FACT:** direction is `w2 >> 14` per link end: 0 free, 1 at the end you
  may leave from, 2 at the end you may not leave from, 3 closed. Every inner
  London link obeys the pairing (C-9930).
- **FACT:** turn restrictions are the `(w2 & 0x3fc0) >> 6` words after the
  fixed words, keyed by target link index at the node (C-9931). Conditions
  point into unit 2 (C-9932, OBSERVED for the table layout).
- **FACT:** `w5` is cost/time and `w6` length, each a 12-bit mantissa with a
  2-bit scale (C-9933).
- **FACT:** `w4 & 0x8000` marks a link to the neighbouring mesh, always from
  an edge node (C-9934). This is how tiles join.
- **FACT:** the unit-0 header's 11 pairs sum to the node and link counts;
  header halfword 26 is a country code (C-9935).
- **OBSERVED:** `w1` is a road attribute word read only by the cost function
  (speed index, penalties) (C-9936). Its exact categories need the runtime
  tables.
- **UNKNOWN:** the meaning of `w4 & 0x30`, `w4 & 0x4000`, words 7–8, node
  `w2 & 0x2000`, and unit 1 (level-2 records only) (C-9937).
- **No elevation field:** nothing in section 2 is read as a height, and node
  word 2 is only 0 or `0x2000` in London.

## Conclusion

Everything a writer needs for a basic routable tile is named and checked on
the factory data: framing, direction, turn bans, cost, length, the
section-1 key and the boundary links. A first OSM writer (M5.57) can set
direction from `oneway=*`, cost from length and highway class, and leave turn
words and conditions out. Still open: the L4 mutation proof, the runtime
cost tables, and the few unnamed bits.
