## Question

What are the >6-/12-byte index cells, the exact `c0` vs `c8` grammar, the
subtypes `0x54`/`0x58`, the `40 XX YY` point encoding and the per-file
trailer table in `ADDRE0nn`?

## Hypothesis

`none / exploratory`. The working guesses were: the 12-byte table is a
name-initial directory, the 6-byte cells are a trie or offset table, the
`0x54/0x58` subtypes are the two sides of a street (odd/even house numbers),
`40 XX YY` is an offset from the record's coordinate id, and the trailer is a
random-access record index.

### 12-byte directory (`0x1108`)

`ADDRE001`, 24 rows:

```
'1' n=1    block=0 off=0x0096 len=72
'A' n=262  block=0 off=0x05b2 len=48
'B' n=90   block=0 off=0x08a0 len=60
...
'X' n=4    block=0 off=0x0000 len=0xffff   (sentinel)
```

- Every row id is a printable ASCII name initial: `1ABCDEFGHIJKLMNOPQRSTUVX`
  (001), `1ABCDEFGHIJKLMNOPQRSTUVW` (017), `123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ`
  (021), `'123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ` (033).
- `count` sums to 2621 (001) and 1616 (017), exactly the 22-byte index-record
  counts. On 003 the sum is 179,408 of 244,944 and on 021 689,827 of
  1,476,259.
- `block` is 0 on every row of 001/017; 003 uses 0,1,2,3,6 and 021/033 use
  several values.
- The last row keeps the `0xffff` length sentinel and still has a `count`
  (001 `'X'` n=4).

### 6-byte cells

`ADDRE001` directory runs hold 113 value cells and 20 pointer cells;
`ADDRE017` 99 value, 19 pointer and 1 empty; `ADDRE003` block-0 runs have 0
unknown cells.

```
value cell    (0x0000/0x0001/0x0002/0x0003, value, count)
pointer cell  (pointer, 0xff00, 0x0000)
```

Cell-base control on `ADDRE001` (`verify --cell-base`, number of unknown
cells):

| base | unknown cells |
| --- | --: |
| `0x2000` | **0** |
| `0x1000` | 121 |
| `0x1108` | 133 |
| `0x2010` | 32 |

Pointer control: 20/20 pointers are multiples of 6; 0/20 lands on a value
cell. Value control: 113/113 values are below the record-stream length, but
only 1 lands on a record start and 2 on a name start.

- Record size is exactly `2*L` for both tags, e.g. `c0 22` = 68 bytes and
  `c8 18` = 48 bytes. The last `ff` of a `c8` is inside that span.
- Name marker tag is `0x03` in 001/017 and `0x04` in 003; `LL` is
  `ceil(name_len/2)` in 100 % of 692/249/56,988 named records; the name is
  the last `2*LL` bytes of the record.
- Range token counts (`ADDRE001`):

```
06/54:220 06/58:196 06/64:8  06/68:11
07/54:258 07/58:244 07/64:9  07/68:6
08/54:15  08/58:17
```

- Parity per subtype slot (`0x54/0x64` = low nibble 4, `0x58/0x68` = low
  nibble 8):

| Shard | slot 4 even/odd | slot 8 even/odd |
| --- | --- | --- |
| 001 Andorra | 232 / 248 | 225 / 222 |
| 017 Monaco | 228 / 103 | 93 / 279 |

- `ADDRE001` point tags: `0x02:902 0x03:871 0x04:182 0x05:170 0x40:19
  0x50:16 0x60:1 0x70:7`; `ADDRE003` adds `0x80`, `0x88`, `0x90`, `0x98`,
  `0xb0`, `0xb8`.
- Every one of the 2,168/1,301/202,729 point tokens has marker byte `0x40`.
- `ADDRE021` and `ADDRE033` do **not** consist only of `c0`/`c8`: after
  28,187 records of `ADDRE021` the stream contains `c1 0f fe 00 a8 ed d7 4d`
  followed by ≈540 bytes of point tokens and then `49 00`. `L = 0x0f` is not
  the half-length there, so the record framing of `0xc1` is `UNKNOWN`.
  `verify` is therefore claimed for 001/017/003 only; `layout` works on all
  five shards (container, directory, trailer).

## Interpretation

- **FACT:** The 12-byte table at `0x1108` is a name-initial directory
  (`initial`, `count`, `block`, `offset`, `length`), terminated by the
  `0xffff` length sentinel; `count` is the number of 22-byte index records
  for that initial and matches exactly on the two single-block shards.
- **FACT:** The 6-byte cell array starts at `0x2000`; all runs decode as
  value cells `(0..3, value, count)` or pointer cells `(pointer, 0xff00, 0)`,
  and every pointer is 6-byte aligned. The base control fails at every nearby
  base.
- **FACT:** `c0` records always carry a name section and `c8` records never
  do (57,929/57,929 `c0` named, 0/39,154 `c8` named over three shards); both
  use `2*L` framing. The name section is `TT LL 00 ff` with `TT` per shard
  (0x03 or 0x04) and `LL = ceil(name_len/2)`.
- **FACT:** `0x54`/`0x58`/`0x64`/`0x68` are two slots selected by the low
  nibble (4 vs 8). Parity is not a format rule: Monaco's odd/even numbering
  gives a 69 %/75 % bias, Andorra's consecutive numbering gives none.
- **FACT:** The point token is `TT 40 XX YY`; `0x40` is constant. The two
  primary points share `XX` in 95–98 % of records.
- **FACT:** The trailer is a per-record-block TOC: one 12-byte
  `(start, length, value)` row per record zlib block, `value` = uncompressed
  size / 2 exactly, `length` = compressed size / 2 within 16-bit word
  rounding.
- **OBSERVED:** `count` in the directory under-covers the index count on
  multi-block shards (003: 73 %, 021: 47 %); why is unknown.
- **HYPOTHESIS:** `value`/`count` in the 6-byte cells describe name-trie or
  hash buckets; no tested interpretation (record offset, name offset, index
  offset) fits.
- **HYPOTHESIS:** `XX` is a per-record length/radius/cell and `YY` an
  endpoint selector inside a polar or cell-local encoding; neither is proven.
- **UNKNOWN:** the exact `(XX, YY)` → packed-coordinate arithmetic; the cell
  base for `block > 0`; the `prefix` 0x06/0x07/0x08 axis; the 22-byte index
  record fields.

## Conclusion

`docs/format/refer.md` now documents the 12-byte directory, the two 6-byte
cell shapes, the `c0`/`c8` grammar, the name section, the range subtypes, the
point-token frame and the trailer TOC. Two headline items stay explicitly
`UNKNOWN` with their methods and controls: the 6-byte cell payload and the
`(XX, YY)` point arithmetic. New tool: `tools/addre.py` with a synthetic
`--selftest` and a real-shard `verify` that passes 14/14 checks on 001, 017
and 003.
