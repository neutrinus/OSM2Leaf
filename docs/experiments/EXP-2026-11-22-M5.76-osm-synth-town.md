## Question

Can a deterministic, network-free generator produce a synthetic town in the exact JSONL form `tools/tilewriter.py` reads, with roads, Polish names, one-ways, turn restrictions, 50 POIs, water and house numbers, that the one-tile OSM pipeline accepts into a tile passing L1/L2 — and is its output byte-identical for a fixed seed?

## Hypothesis

A fixed seed, an explicit LCG and a fixed record order make the JSONL byte-identical across runs and across `PYTHONHASHSEED`; the town can be made to fit entirely inside one level-1 directory of cell `B50R058R`, so `one_tile_pipeline.py --factory-root ... --parcel 84,940` accepts it. Falsifier: two runs with the same seed differ, or the pipeline refuses the generated town, or the tile fails L1/L2.

## Interpretation

- **FACT:** `tools/osm_synth.py --selftest` passes 24/24, is auto-discovered by `tools/selftest.py`, pins the seed-1 SHA-256, and reproduces it under four `PYTHONHASHSEED` values; seed 2 differs.
- **FACT:** The seed-1 town validates under `imf_check --strict`, is read by `tilewriter.read_jsonl`, and contains every feature the scope names (grid, ring, motorway, Polish diacritics, one-ways, two restrictions, 50 POIs across all six categories, river, lake, 16 house numbers on two streets).
- **FACT:** The factory-backed `one_tile_pipeline.py --parcel 84,940` run exits 0, writes one tile in one section-1 directory, and that tile passes L1 `cardcheck` and targeted L2 `l2check`.
- **OBSERVED:** The first attempts failed for input placement (geometry in a different cell) and for host `/tmp` ENOSPC; both are diagnosed and corrected, and the negative controls show the checks can fail.
- **HYPOTHESIS:** Other generated seeds will also land in directory `(84,940)` because the jitter stays inside the town margin; seed 2's summary shows the same directory.
- **UNKNOWN:** Firmware acceptance (rule 13) remains unknown: `hdd_info_map_code` and `section4` are `CANNOT-VERIFY-OFFLINE`, and no L3/L4/L5 run was made.
