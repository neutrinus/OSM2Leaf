## Question

Can `mkcard --reconcile` make resize minimal-diff intent understandable and safe by (1) naming actual DRSTR index/value bytes in the reported envelope, (2) offering/documenting a stale-tail policy that preserves invariants, and (3) honestly measuring fresh-build contrast (uncapped range counts) against reconcile on the M5.20 same-length and resize cases?

## Hypothesis

(1) DRSTR index bytes can be named as `drstr:index <path>/<name> value before->after` at exact image offsets derived from DRSTR file-relative offsets + rewritten cluster chain; classification is explanatory and any DRSTR-cluster diff outside named index bytes is reported as `drstr_other`. (2) Preserving stale slack in existing factory-chain clusters does not break `cardcheck`/FAT/dir/DRSTR invariants (slack is after EOF); newly allocated clusters must remain zero-filled for determinism. Default remains zero-fill. (3) Fresh build produces far more diff ranges than reconcile on the same changed tree; counts must be measured with `diff_ranges(..., limit=1<<30)`, never the default cap.

**Falsifier:** any `drstr_other` hidden/mislabeled; `outside_ranges`/envelope gate weakened; uncapped contrast not measured (and Stop not honestly invoked); stale-tail preserve breaks cardcheck/FAT invariants but is kept; `--selftest` missing for chosen behavior; or any diff range outside the allowed envelope accepted.

## Interpretation

- **FACT:** On EU2011 eu-grow (resize 208→272), reconcile reported 246 uncapped ranges total: 1 dir_entry, 243 file_data, 2 `drstr:index` (named `TMC` and `TMC/reception.dat`, 208→272, image offsets `0x7a410d5c`/`0x7a412f9c`), `outside_count==0`, cardcheck PASS. `drstr_other` was absent (C-3170, C-3171).
- **FACT:** Default stale-tail policy is deterministic zero-fill on resize. Opt-in `--preserve-stale-tail` preserves slack only in clusters already in the factory chain; newly allocated last clusters are still zero-filled. Synthetic R8 (one variable) shows both modes read back correct bytes, stay inside the envelope, and produce no `drstr_other`; preserve keeps factory slack bytes in the existing cluster (C-3172, C-3173).
- **FACT:** On the same EU2011/cases (one variable each), fresh build produced 24,173,274 (eu-same) and 24,173,273 (eu-grow) uncapped diff ranges (~5.17 GB diff bytes) vs reconcile 1 and 246 ranges with `outside_count==0` and cardcheck PASS (C-3174).
- **OBSERVED:** Reconcile envelope remains complete/strict; classification is explanatory only (C-3175).
- **UNKNOWN:** L4/L5 acceptance; preserve-tail effect on all real image cluster-allocation patterns (new-cluster case intentionally zero-filled); multi-file/complex resize interactions.

## Conclusion

M5.31 makes resize reconcile reporting understandable by naming actual DRSTR index/value bytes and classifying diff ranges without weakening the strict envelope gate. Stale-tail behavior is explicit: zero-fill default for determinism, opt-in preserve for existing factory-chain slack only, tested one-variable with invariants preserved. Fresh-build contrast is measured uncapped for one same-length and one resize M5.20-equivalent case on EU2011 (24,173,274/24,173,273 fresh ranges vs 1/246 reconcile, one variable), so "minimal diff" is no longer an ambiguous capped summary.
