# EXP-2026-11-22-M4.92: TMC reception coverage — country / location table / services, EU2011 vs EU2014

- **Status:** done
- **Date:** 2026-11-22
- **Sample:** `TMC/reception.dat` from the EU2011 card
  (`LEAF_2011-2012_QSD-309-101_navi158_eu.img`, image SHA-256
  `105e2032e480e8ba162a2a9d4b6624cb1dafee380379a9908f3f101b15076307`),
  208 B, SHA-256 `09603f6b91359f5ab47dd29d18dbe37def6b54f7e74d2c8bb1eb293efc7b1590`;
  and from the EU2014 card (`LEAF_2014_EU_QSD-357-101.img`, image SHA-256
  `4a8a21f477e9fc511f94406976b8d67037842f9c043f49ab24e1adc82d6da89b`),
  208 B, SHA-256 `09603f6b91359f5ab47dd29d18dbe37def6b54f7e74d2c8bb1eb293efc7b1590`.
- **Tools:** Python 3.15.0 (stdlib only); repo tools `tools/tmc_reception.py`,
  `tools/tmc_fielddir.py`, `tools/lctbl_records.py` (read as inputs), new
  `tools/tmc_coverage.py`, and the committed read-only FAT walker

- **Superseded by:** none

## Question

Which countries, TMC location-table numbers (LTN) and services does
`TMC/reception.dat` list on the EU 2011 and EU 2014 cards, and is Poland among
them?

## Hypothesis

`reception.dat` is the receiver-side list of RDS-TMC services: each recognised
row carries an RDS country code (CC nibble, byte 2) and a location-table number
(LTN, byte 3), so coverage is decided by this file. Poland's CC is 3
(IEC 62106 Annex D; `tools/tmc_reception.py:44` maps ISO 3166 numeric 616 → 3).
Expected result: the 14 known European services are listed, CC 3 is not, so
Poland is **absent** on both cards. **Falsifier:** the rows carry no country or
table field at all (then coverage is decided elsewhere and this tool must say
so and stop). A second falsifier for the Poland claim: any row with CC = 3.

## Plan

- **Approach.** Decode `reception.dat` with the existing
  `tools/tmc_reception.py:parse_rows` (the tool's own decoder, not a new byte
  grammar). Group the decoded (CC, LTN) pairs by country using the RDS CC table
  imported from that tool plus the 14 (CC, LTN) → country pairs already
  established by C-2320–C-2322 / C-5400–C-5403 and `docs/format/rdstm.md`.
  Report one row per country with its CC, location tables (LTNs) and number of
  service rows, plus an explicit Poland present/absent row and the consequence.
- **Format source.** `tools/tmc_reception.py` (`parse_rows`, `code_cc_ltn`,
  `RDS_CC`) and `docs/format/rdstm.md` §"Table codes and `TMC/reception.dat`".
  The raw row grammar is taken from that decoder, not re-derived.
- **Files.** New `tools/tmc_coverage.py` (with `--selftest`); this EXP; one
  consequence line in `docs/research/data-coverage.md`; claim rows C-8180–C-8189.
- **Intended Done when.** One command generates the country → location table →
  services table for both cards, with a Poland present/absent row; the
  consequence is written into `docs/research/data-coverage.md`.

## Method

A **spec**, not a narrative.

1. **Sample and hash.** The two `TMC/reception.dat` files extracted from the
   named images; both are 208 B with SHA-256
   `09603f6b91359f5ab47dd29d18dbe37def6b54f7e74d2c8bb1eb293efc7b1590`.
   The extraction uses the committed read-only FAT walker (no vendor bytes are
   written to the repo).
2. **Commands.** Runnable as written, in one block:
   ```bash
   python3 tools/tmc_reception.py --selftest
   python3 tools/tmc_reception.py rows <eu2011-reception.dat>
   python3 tools/tmc_coverage.py --selftest
   python3 tools/tmc_coverage.py report \
     EU2011=archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img \
     EU2014=archive/sd-images/LEAF_2014_EU_QSD-357-101.img
   ```
3. **Controls.** *Positive*: a synthetic row with CC = 3 is added in the
   `--selftest` and must be reported as Poland present; the 14 known rows must
   map to the 14 countries named in `docs/format/rdstm.md`. *Negative*: the
   synthetic file with the CC = 3 row removed must report Poland absent, and a
   row with an out-of-range CC must not be assigned a country. A negative claim
   without these controls is not a result.
4. **Scope.** The two card images' `TMC/reception.dat` files only (26 × 8 B
   rows each). The US2011 image is *not* in scope: it has no `TMC` directory, so
   there is no such file to compare. Country attribution of the 14 services is
   inherited from the established C-2320–C-2322 / C-5400–C-5403 reading; this
   EXP does not re-derive it.
5. **Falsifier.** If the rows carry no country or table field (no CC/LTN pair),
   record that and stop. For the Poland conclusion, any decoded row with CC = 3
   or LTN assigned to Poland refutes "Poland absent".

## Observations

**O1 — decoder precheck.** `python3 tools/tmc_reception.py --selftest` prints
six `ok` lines and `selftest: PASS`. `python3 tools/tmc_reception.py rows
<eu2011-reception.dat>` prints 14 lines; the first is `03   CC c LTN 10` and the
last is `ff0f  CC 2 LTN 25`. None of the 14 lines has `CC 3`.

**O2 — raw file.** Both extracted `TMC/reception.dat` files are 208 B with
SHA-256 `09603f6b91359f5ab47dd29d18dbe37def6b54f7e74d2c8bb1eb293efc7b1590`;
`cmp` on the two files is silent (byte-identical). The 208 B are 26 rows of
8 B. Row bytes 2 and 3 are the CC and LTN fields (e.g. row at `0x78`:
`ff 0f 02 19 00 ff ff ff` → CC 2, LTN 25). Row `0x00`
(`01 3e 0f 1e 00 ff ff ff`) and row `0x08` (`02 32 0d 00 01 01 ff ff`) are not
decoded by `parse_rows` (they are neither `ff0f` nor `03`). The 10 rows from
`0x80` onward are `ff 00 00 00 ff ff ff ff` filler, also not decoded.

**O3 — new tool.** `python3 tools/tmc_coverage.py --selftest` prints
`selftest: OK` (14 service rows, 14 countries, Poland absent on the EU-like
file, positive CC 3 row present, falsifier case handled). `python3
tools/selftest.py --only tmc_coverage` prints `tool:tmc_coverage  PASS` and
`passed=1 failed=0 skipped=0 total=1`.

**O4 — one command, both cards.** `python3 tools/tmc_coverage.py report
EU2011=…eu.img EU2014=…2014.img` prints, for each card:
`size 208 B … row slots 26 … decoded service rows 14`, then this table
(identical on both cards):

| country | CC | location tables (LTN) | service rows |
| --- | --- | --- | --- |
| GB | c | 10 | 1 |
| AT | a | 1 | 1 |
| BE | 6 | 1 | 1 |
| DK | 9 | 9 | 1 |
| FI | 6 | 17 | 1 |
| FR | f | 32 | 1 |
| DE | d | 1 | 1 |
| IT | 5 | 1 | 1 |
| NL | 8 | 17 | 1 |
| NO | f | 49 | 1 |
| ES | e | 17 | 1 |
| SE | e | 33 | 1 |
| CH | 4 | 9 | 1 |
| CZ | 2 | 25 | 1 |
| PL | 3 | — | 0 |

It then prints `Poland (PL, CC 3): EU2011=absent EU2014=absent`,
`Note: the reception.dat files are byte-identical on all listed cards.`, and
the consequence line (quoted in the data-coverage edit).

**O5 — US2011 out of scope.** A FAT walk of `LEAF_2011-2012_US.img` finds one
partition (LBA 204802) with 12 top-level entries and no `TMC` directory, so no
`reception.dat` exists there to tabulate.

## Interpretation

- **FACT:** the row has a country field (CC, byte 2) and a table field (LTN,
  byte 3), so the task's falsifier ("no country field at all") does not fire;
  coverage is decided by this file's service list.
- **FACT:** Poland's RDS CC is 3 (`tools/tmc_reception.py:44`, ISO 3166 616 →
  3). No decoded row has CC 3, so Poland is **absent** on both EU2011 and
  EU2014. The two rows `parse_rows` does not decode have byte 2 = `0x0f` and
  `0x0d` (not `0x03`) and are not services in any case.
- **FACT:** the EU2014 `reception.dat` is byte-identical to the EU2011 one,
  therefore there is no Polish entry on the 2014 card either — the TODO scope's
  "what a Poland entry on the 2014 card looks like" has the answer "none".
- **OBSERVED:** 14 country/location-table services, one row each; 2 header rows
  and 10 all-`ff` filler rows in the 26-row file.
- **HYPOTHESIS:** because `reception.dat` is the receiver-side service list, a
  generated Polish `RDSTM001`/`LCTBL001` location table would never be
  requested without a CC 3 service entry. The firmware reader of
  `reception.dat` was not located in this EXP, so this remains a consequence of
  the file's established role (C-2320–C-2322), not an L3/L4 observation.
- **UNKNOWN:** whether adding a CC 3 row alone is sufficient, or whether other
  receiver-side tables also need a Polish entry.

## Conclusion

One command now produces the country → location table → services table for
EU2011 and EU2014 and reports Poland absent on both. The consequence line was
added to `docs/research/data-coverage.md`; claims C-8180–C-8189 record the
service list, the byte identity, the Poland absence and the consequence. The
falsifier did not fire. Still open: whether adding a CC 3 service entry is
sufficient (new task, not this one).
