## Question

Can `tilewriter` write section-1 **level 2** of `B50R050R` so that every parcel
it writes has an even (road) pair in the output, given that 1,313 parcels have
no factory even pair (M5.61, C-6257)? If it cannot, is the block the slot or
something else?

## Hypothesis

`none / exploratory`. The M5.61 record says the writer cannot create a missing
even slot, so the expectation was a slot-allocation defect. The **falsifier** for
that expectation: a splice into a null even pair and into an absent slot row
both succeed, and the real build fails on a *present* row whose pair the reader
stops finding. If that holds, the "even slot" framing is wrong.

## Method

   is in O1. The factory is read-only input; the build output goes to scratch.

2. **Commands.** `$S=~/projekty/leafre-work/scratch/m5.70`.
   ```bash

   python3 tools/tilewriter.py --l2-slot-census $S/factory-root/MAPAL001/B50R050R.DAT

     --cell B50R050R --l2-written-gate $S/rebased/B50R050R-L2.tile.DAT

   python3.13 tools/rebuild_manifests.py --root $S/rebasedroot

     --position 54.3,21.0 --file B50R050R --json $S/rebased/l3.json
   ```

3. **Controls.**
   - *Positive*: all 32 x 32 level-2 parcels of a synthetic factory built and
     checked (`--selftest`, the `_m570_created_slot` cases); and the real build,
     whose `--l2-written-gate` prints 0.
   - *Negative (created slot)*: a synthetic directory where one parcel is left
     out — the gate names that parcel (`selftest`).
   - *Negative (level filter, N2)*: a level-1 record at a `(row, pair)` that a
     level-2 write also touches, mutated — `verify_factory` rejects it
     (`selftest`).
   - *Negative (real tile)*: blanking one present-row even pair in the real
     output makes `--l2-written-gate` exit 1 and name `y=80 x=944 row=0 col=0`.
   - *Negative (old rule)*: `--drop-absent-slot` reproduces M5.61's drop and its
     `l2_unwritable_parcels` count.

4. **Scope.** Section-1 level 2 of one cell (`B50R050R`); levels 1 and 2 of the
   same tile for the L3 mount; no other cell, no section 2/4/`LEV3456R` content
   regenerated (copied). Every factory byte outside the 14 appended slot blocks

5. **Falsifier.** A build that reaches 0 "without a slot" by dropping the ways
   that need one is not a pass; the report prints `dropped_ways.no_slot` and it
   must be 0 while `l2_written_without_slot` is 0. A splice that passes
   `verify_factory` but leaves a written pair unreachable is a pass by mistake;

**O5 — the mechanism.** Before the fix the real build failed with
`tilewriter: check failed: section-1 record at (80, 944, 5, 25) changed but was
not regenerated` (and M5.61's `no record at dir y=80 x=944 slot 5 pair 6`).
The written parcels `(80,944,5,3)`, `(80,944,9,23)`, `(80,944,5,4)` build
records of **105,288 / 96,684 / 67,380 inflated words**. The directory stores a
record's inflated length in a **u16 word count**, and `clarion_tile.read_dir`
stops the pair table at any value `> 0x10000`. A 105,288-word record makes the
reader stop after that pair, so `(80,944,5,26)` (the parcel's own even pair) and
every later pair in the slot are unreachable. The splice itself is correct: it
appends the whole rebuilt slot block and repoints the tag, and `find_record`
reads the appended block; the reader simply stops early inside it.
`build_road_record` now refuses a record `> 0x10000` words, so the driver's drop
rule drops whole ways (counted: `dropped_ways.total` 3464) instead of writing an
unreadable slot.

## Interpretation

- **FACT:** the writer **can** create a level-2 even slot. It appends a whole
  rebuilt slot block and repoints the tag; null even pairs and absent slot rows
  both become readable records (synthetic all-32×32 build: 0 missing; real
  build: 0 written without a slot).
- **FACT:** on `B50R050R` the build failed because one OSM parcel is dense
  enough to exceed the 16-bit word count (`> 0x10000` inflated words) the
  directory pair table stores, so the reader stops the pair table before the
  parcel's own pair. The stop is the **record size**, not the slot.
- **OBSERVED:** M5.61's "1,313 parcels with no even slot" is a *census of the
  factory*, not the set of parcels a build writes. The Done-when "0 parcels
  left without a slot" is about written parcels; the real build writes 389 and
  leaves 0 without a pair.
- **HYPOTHESIS:** splitting the oversized records (or per-parcel density
  limiting before the record is built) would let the 3 oversize parcels carry
  their ways instead of dropping 3,464 ways; not attempted here (M5.70 scope is
  the slot, and a split changes the record grammar).
- **UNKNOWN:** whether the unit draws the level-2 tile (L5, no hardware).

## Conclusion

The M5.61 level-2 block was mis-labelled. `tilewriter` creates even slots; the
real stop was a single parcel whose record exceeds the 0x10000-word pair-table
bound, which made the reader stop the pair table and report the parcel's pair —
and later pairs — as missing. `build_road_record` now refuses such a record so
the driver drops whole ways (counted), `l2_written_without_slot` + `--l2-written-gate`
is the Done-when gate (0 on `B50R050R`), the census keeps M5.61's 1,313 and the
Done-when's 1,505 apart, and `verify_factory` compares per level (N2). The final
`B50R050R` level-2 tile (SHA `ffb1d5f4…`) passes `cardcheck`, `l2check
--semantic-tiles` and the L3 mount at 54.3,21.0 with both levels status `[0]`.
Claims C-6810–C-6819. Level 1 is unchanged by this (the level filter also fixes
its previous blindness at the 4,230 shared keys).
