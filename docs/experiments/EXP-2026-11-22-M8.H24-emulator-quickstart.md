## Question

Can a person with a clean checkout reach a screenshot file by following one
page (`docs/emulator/README.md`), with the commands that work today and the
known limits — and does every command on that page run?

## Hypothesis

The knowledge to run `-M ze0` is spread over thirteen EXP records and a long
`tools/qemu-ze0/README.md`; a single page can carry it. **Falsifier (from the
task):** a command on the page fails on a clean checkout.

## Method

Every command is copied from a run in this session; exit codes are quoted from
the shell, not typed.

1. **Sample and hashes.** `sha256sum archive/head256.img
   archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img` (values above).
2. **Clean build (the page's step 2).** The page's default `$QEMU` is
   `$HOME/.cache/qemu-ze0/build/qemu-system-sh4`. That cache existed but with
   an older binary (8.2.10, no 2DG interpreter), so the page's literal command
   was run to rebuild it in place:
   `bash tools/qemu-ze0/build.sh --jobs 8` (build log
   `leafre-work/scratch/m8.h24/build-default.log`).
3. **Alternative cache (also run).** A from-scratch build in a separate cache,
   to prove the page's `--srcdir` path and a clean extraction:
   `bash tools/qemu-ze0/build.sh --srcdir
   /home/marek/projekty/leafre-work/scratch/m8.h24/qemu-ze0 --jobs 8`
   (log `leafre-work/scratch/m8.h24/build.log`).
4. **Fetch (page step 3).** The ranged head download and the full card
   download, both into a scratch dir, then `sha256sum`.
5. **Prepare (page step 4).** `ze0_ipl.py patch` and `mkoverlay.py`.
6. **Boot and screenshot (page step 5).** `run.sh` in the background with the
   page's exact flags, then `ze0_screenshot.py screen` against
   `$W/run/hmp.sock`; once at ~2 s (black) and once at ~27 s (map).
7. **Controls.** Negative: stock `/usr/bin/qemu-system-sh4 -M help` must not
   list `ze0`. Positive: the built `-M help` must. A boot with the page's flags
   must reach `Store Mgr Ready! [DSK1:]`, `Navi.exe`/`AuiApp.exe`
   `Process Create!!!`, and a non-black screen.

```bash
cd /path/to/OSM2Leaf
QEMU=${XDG_CACHE_HOME:-$HOME/.cache}/qemu-ze0/build/qemu-system-sh4
W=$HOME/leafre-work/qemu-run; mkdir -p "$W"

# step 2 (page literal)
bash tools/qemu-ze0/build.sh --jobs 8
"$QEMU" --version | head -1
"$QEMU" -M help | grep ze0

# step 3
curl -fL --retry 3 --connect-timeout 20 -r 0-268435455 -o "$W/head256.img" \
  https://files.viaaq.eu/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img
curl -fL --retry 3 --connect-timeout 20 -o "$W/card.img" \
  https://files.viaaq.eu/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img
sha256sum "$W/head256.img" "$W/card.img"

# step 4
python3 tools/ze0_ipl.py patch archive/head256.img -o "$W/ipl.txt"
python3 tools/qemu-ze0/mkoverlay.py \
  archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img "$W/eu2011.qcow2"

# step 5
bash tools/qemu-ze0/run.sh --qemu "$QEMU" --image archive/head256.img \
  --verinf QSD-302-100 --mapdb 16-16 --ipl-patch "$W/ipl.txt" \
  --sd "$W/eu2011.qcow2" --icount shift=0,sleep=off --timeout 300 \
  --workdir "$W/run" &
python3 tools/ze0_screenshot.py screen --monitor "$W/run/hmp.sock" -o "$W/run/shot.png"
```

## Observations

**O1 — the build (page step 2).** `build.sh --jobs 8` on the default cache
exited **0**; it reused the previously extracted, already-patched source and
relinked the binary. `"$QEMU" --version | head -1` → `QEMU emulator version
11.1.3` (exit **0**); `-M help | grep ze0` → the `ze0` line (exit **0**). The
from-scratch build (`--srcdir …/scratch/m8.h24/qemu-ze0`, 2690 make targets)
exited **0** and printed `OK: ze0 …`.

**O2 — fetch (page step 3).** Ranged head download: curl exit **0**,
`268435456` bytes, SHA-256 `92aa525d…007f9` (matches). Full card: curl exit
**0**, `8057257984` bytes, SHA-256 `105e2032…76307` (matches). URLs are the
ones in `AGENTS.md`.

**O3 — prepare (page step 4).** `ze0_ipl.py patch` exit **0**, printed
`chain pointer var 0x89e43c90 … XIPCHAIN at phys 0x0e6f0000, RAM end
0x8c6e0000`, `kernel modules kept 81/91, image A modules kept 111/149`,
`wrote …/ipl.txt (8 lines)`; the file is 16170 B (a header comment + the 8
`PHYS HEXBYTES` lines). `mkoverlay.py` exit **0**, `qcow2 overlay, 8 GiB`,
backing the EU card raw image, 256 KiB on disk.

**O4 — boot (page step 5).** `run.sh` starts QEMU with `-M
ze0,kernel-off=0x3e00200,app-off=0x200200,dbgmsg=0x880404f4,verinf=QSD-302-100,mapdb=16-16,ipl-patch=…`,
`-drive if=sd,index=0,file=…eu2011.qcow2`, `-icount shift=0,sleep=off`, and an
HMP monitor on `$W/run/hmp.sock`. QEMU prints the unit record and
`4/3 ipl-patch line(s) applied`. The serial log (`serial.log`, 77167 B) has one
`Store Mgr Ready! [DSK1:]`, 36 `AppLch >> Process Create!!!` (including
`\windows\Navi.exe` and `\windows\AuiApp.exe`), 12 `Launch Process Not
Create` (modules absent on this card, expected), and 0 `Exception`.

**O5 — screenshot (page step 5).** At ~2 s the monitor socket exists and
`screen` exits **0** with `0 non-black pixels`. At ~27 s (25 s after the
socket appeared) it exits **0**, prints the two DU planes
(`plane 2: mode 0x1002 800x480 at 0x0e932800 stride 800 window (0,0)`,
`plane 4: mode 0x4002 800x480 at 0x0e9f2000 stride 2368 window (1376,193)`)
and `shot.png: 382721 non-black pixels`. `file shot.png` → `PNG image data,
800 x 480, 8-bit/color RGB, non-interlaced`, 61252 B. The image is the central
London map of the card (roads, shields, parks, street labels).

**O6 — controls.** Stock `/usr/bin/qemu-system-sh4 -M help | grep -w ze0`
→ no line, exit **1** (the distro 11.1.3 has no `ze0`); the built binary's
grep exits **0**. A boot that fails a wrong overlay path (`eu2011b.qcow2`
that was never created) makes QEMU print `Could not open … No such file or
directory` and `run.sh` still exit **0** — this is why the page says to read
the pixel count and the first lines of the run output, not `run.sh`'s exit.

**O7 — times on this host (8 cores).** Head download ~7 s (256 MiB,
~40 MB/s); full card ~3 min 15 s (7.5 GiB, ~40 MB/s); `ze0_ipl.py` ~1 s;
`mkoverlay.py` < 1 s; boot to a non-black screen ~20 s; `build.sh` from the
tarball 4 min 56 s here (10:23:13 → 10:28:09 on 8 cores), an incremental
relink ~1 s. `qemu.log` reached 373 MB in ~90 s of boot
(`-d unimp,guest_errors,int,invalid_mem`).

## Interpretation

- **FACT:** every command on `docs/emulator/README.md` was run from a clean
  shell and succeeded (O1–O5); the page's literal step 2 brings the default
  cache to the 11.1.3 + `ze0-0014` binary it documents, so a reader who starts
  from that cache gets the same map.
- **FACT:** a clean checkout that has the `archive/` links, or downloads the
  two images per step 3, reaches an 800 × 480 PNG in ~20 s (O2, O5).
- **OBSERVED:** `run.sh` exits 0 even when QEMU dies on a bad path (O6); the
  page's troubleshooting keys off the pixel count and the work-dir output for
  this reason.
- **UNKNOWN / limits, on the page's table:** touch, hard keys, GPS, CAN,
  Bluetooth, USB, second SD, NOR flash, a live host window and the UI plane
  are not there yet (O5 shows the map plane only; plane 2 stays keyed,
  EXP-2026-11-22-M8.C1f O6).

## Conclusion

`docs/emulator/README.md` is a validated quick start: prerequisites, build,
fetch, IPL patch + overlay, boot + screenshot, times, a device works/does-not
