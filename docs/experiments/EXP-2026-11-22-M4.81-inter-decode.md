## Question

Does a committed tool reproduce the big-endian 12-byte `INTER0nn` table decode
and explain more than half of every factory shard on both cards?

## Hypothesis

The 12-byte table at `0x1108` (M3.16, C-2215/C-2216) plus the validated zlib
pages and fill account for most bytes. The tool is a census, not a new field
hypothesis: unexplained bytes are reported with a histogram, never guessed.

**Falsifier:** any shard at **under 50 % bytes explained**, or a shard with no
terminating table (`u16@+2 == 0` failing) — then the claimed layout is wrong or
partial, and the unexplained region must be named.

## Method

1. **Sample and hash.** The two card trees above; every `INTER*.DAT.cmp` is
   decoded in memory with `cmpind.decode` (no extracted `.DAT` is committed).
   Hashes of the representative pair are listed above.
2. **Commands** (run from the repo root, as written):

   ```bash
   python3 tools/inter_decode.py --selftest
   python3 tools/inter_decode.py census \
     /home/marek/projekty/leafre-work/m5.4/card-factory/REFER001 \
     /home/marek/projekty/leafre-work/m5.12-us/root-factory/REFER001 \
     --labels EU US
   python3 tools/inter_decode.py census \
     /home/marek/projekty/leafre-work/m5.4/card-factory/REFER001 \
     --files INTER001 --mutate-byte 0x1112
   ```

3. **Controls.**
   *Positive:* `--selftest` builds a synthetic INTER file (CLARION header,
   8-byte block header, three big-endian records, `0xffff` terminator, one
   `4e20` index chain with a valid zlib stream). It must decode 3 records,
   reach 100 % coverage and report 0 unexplained bytes; all 44 factory shards
   must likewise yield a terminating table and > 50 % explained.
   *Negative:* `--mutate-byte 0x1112` flips the `u16@+2` zero invariant of the
   first EU `INTER001` record; the walk must stop immediately. The selftest
   additionally mutates a record (walk 3 → 1), corrupts a zlib byte (chain
   invalidated) and plants a stray byte (reported unexplained).
4. **Scope.** 33 EU shards (`303,629,312 B`) + 11 US shards (`225,175,552 B`) =
   **44 files / 528,804,864 B**, all `.cmp`/`.ind` pairs on these two cards.
   "Explained" = 512-byte header + table + validated `4e20` index chains +
   standalone zlib pages + zero/`0xff` fill; "unexplained" = every other byte.
   Excluded: the field semantics of the post-table 12-/6-byte locator region
   and FRWAY blobs 1/2 — M3.16 left these UNKNOWN (C-2217–C-2219); no firmware
   code was executed here (the matrix reader cells are unchanged).
5. **Falsifier.** A shard at < 50 % explained, a non-terminating table, or a
   negative control the census does not detect.

## Interpretation

- **FACT:** A committed tool (`tools/inter_decode.py`, `--selftest`) reproduces
  the M3.16 big-endian 12-byte table: `>HHBBHHH` = `key, zero(+2), id, flag,
  length, b8, offset`, terminator `key == 0xffff`, `zero(+2) == 0` on every
  record walked. It finds 976 EU and 385 US records, all shards terminate
  (C-7820, C-7822, C-7823).
- **FACT:** The census explains 87.416 % (EU) / 89.494 % (US) / 88.301 %
  (both) of the bytes — far above the 50 % falsifier; every individual shard
  is ≥ 80.62 % (C-7827). Header/table/chain/zpage/fill byte counts are quoted
  from the command (C-7821, C-7826).
- **OBSERVED:** Per-field ranges are listed above; `flag` and `b8` are the
  sparse variant fields (EU `flag` nonzero 23/976, `b8` 504/976; US 6/385 and
  281/385). `offset` never exceeds the file size (max `0xff60` EU, `0xfed8`
  US) (C-7824, C-7825).
- **OBSERVED:** The negative control is detected: flipping one invariant byte
  drops the EU `INTER001` walk from 21 records to 0 and table bytes 272 → 8
  (C-7828).
- **HYPOTHESIS:** The unexplained ~10–13 % is the post-table region of 12-byte
  locator records and 6-byte blob elements (`0x01/0x0c/0x02/0x12` dominate),
  i.e. exactly the part M3.16 left UNKNOWN; it is named, not decoded
  (C-7829).
- **UNKNOWN:** Which firmware instruction consumes `key/length/offset/b8/flag`
  (M3.16 content-reader search negative; C-2217–C-2219). The matrix reader
  cells are therefore left unchanged; only the Offline cell moves `claim →
  tool`.

## Conclusion

`tools/inter_decode.py` makes the `INTER0nn` field decode reproducible from a
committed tool with a synthetic `--selftest` and a `census ROOT` for both
cards; row 12's Offline cell is now `tool`, and `docs/format/refer.md` §INTER
records the measured ranges and the named unexplained part while keeping the
blob-field semantics as HYPOTHESIS. The content-reader VA and consumed fields
remain open (M3.16 blocked); no firmware cell was promoted.
