## Question

Can the firmware's own position → request → record → `LOC_map` shape walk be
run on the US2011 build (`archive/us256.img`) with the same method as M9.66's
EU2011 walk, and does it walk the served record's shape words with a non-zero
load count and a mutation-sensitive result table?

## Hypothesis

Yes: the four M9.66 EU2011 functions have US2011 twins that are content matches
(`fn_match` UNIQUE) with pdata `START` and identical lengths; adding a build
selector to `locmap_l3.py` and its mount client runs the same chain on US2011.
Falsifier (task, restated before the result): the US walk runs but the
EU-shaped record reads 0 shapes **and** a one-word mutation does not change the
count — then it is a different code path, not a port. Additional stop/falsifier
gates added by this Method: fewer than three of the four named VAs resolve
`START`, or the masked code stream of a twin differs from its EU counterpart in
an instruction (not just a relocated literal-pool word) → block, do not guess.

**Positive controls (must be found / must run):**
1. EU2011 positive control: `locmap_l3.py run $EUIMG --card-image $EU` →

2. `fn_match.py --fixture` → `13 rows, 0 mismatch` (quoted above) proves the
   matcher and the images are the pinned ones before any new VA is derived.
3. US twin positive: all four `fn_match match` results UNIQUE/`pdata START`

4. US mutation positive: `--patch 58=0x0010` must change the result table
   (`diff` DIFFERENT); this is the EU M9.66 reference word reused on the US run.
   If patch 58 does not change the count, the falsifier fired → block (rule 7).

1. `USIMG` without `--build` → exit 3 `BLOCKED … pass --build` (quoted above).
   This tests the BUILD_CHECK guard, **not** the correctness of the US VAs.
2. `EUIMG --build us2011` → exit 3 `BLOCKED … not the us2011 head …` (driver must
   quote the exact message from the run; M9.63 recorded the same guard).
3. `--patch 4=0x2aee` (word outside the copied record) and `--patch 59=0`
   (M9.66's unloaded word) → `diff` SAME; every number quoted from the run.
4. The masked-body check is a *positive* identity check; the raw byte diff of

### 5. Falsifier

Set before the result: (a) the US walk runs but the EU-shaped record reads 0
shapes and a one-word mutation does not change the count (task falsifier);
(b) fewer than three of the four named US VAs resolve pdata `START` (task Stop);
(c) a `fn_match bodies` pair differs in the masked instruction stream, i.e. the
"twin" is a different function, not a relocated copy; (d) the US run's load
count is `0` or the shapes table is empty while the EU control is non-zero.
Any of (a)–(d) → `Status: blocked` with the missing/mismatched function named
and a negative EXP; never a guessed VA or a fitted delta (rule 14). A SKIP from
`l3check.py` is never a pass; if the US `loc_map` row cannot be made runnable,
the EXP must name the exact absent flag/VA/target.
