# EXP-2026-11-22-M4.68-kiwi-parcel-id: KIWI parcel arithmetic vs the ZE0 grid

- **Status:** done
- **Date:** 2026-11-22
- **Sample:** EU2011 factory tree `/home/marek/projekty/leafre-work/m5.29-factory-root` (45 tiles), US2011 `/home/marek/projekty/leafre-work/m5.12-us/root-factory`; KIWI source `jharg/kiwiread` at `74741c5b` read only
- **Tools:** Python 3.15.0; `tools/coord.py`, `tools/mesh_grid.py`, `tools/point_census.py` (arithmetic only, no new tool)
- **Claims:** C-7670–C-7674
- **Supersedes:** none
- **Superseded by:** none

## Question

Do the KIWI parcel-ID rules (`pid_t`, 1.2.13, with 3-byte geonums at 1/8 arcsecond and two exponent fields) predict the ZE0 tile grid, the level sizes and the POI `11xx` nibble / fine-word split?

## Hypothesis

Arithmetic compatibility is expected (both are degree-based grids) but not a format match; in particular the ZE0 packed unit may not be an integer number of KIWI 1/8-arcsecond units. **Falsifier:** KIWI parcel sizes are not an integer multiple or divisor of ours at any level.

## Inputs

| Item | Value |
| --- | --- |
| KIWI rules | `geonum_t` 3 bytes, `geo_secs = v / (3600*8)` degrees; `pid_t = {lat, exp1, lng, exp2}` 8 bytes (C-8104) |
| ZE0 grid | tile 8×8 units = 5.333° lat / 8° lon; unit = 2/3° lat / 1° lon; 1024 packed units per unit; 2048 local units (C-566, `coord.py levels`) |
| Corpus | 45 EU tiles via `mesh_grid.py list`; POI fine position of M4.27/C-2679 |

3. **Controls.** `coord.py --selftest` passes, so the ZE0 arithmetic used here is the committed one. The falsifier is evaluated on level 6 (the only level whose cell size is documented).
4. **Scope.** Arithmetic only: grid sizes, geonum resolution and the POI fine-word unit. No firmware VA, no real KIWI disc (M4.77) and no specification text (M4.65), so the meaning of `exp1`/`exp2` is not assumed.
5. **Falsifier.** As stated above.

## Observations

```text
KIWI geonum: 1 unit = 1/(3600*8) deg = 0.125 arcsec
ZE0 level-6 tile: lat 5.3333 deg = 19,200 arcsec = 153,600 KIWI units
                  lon 8 deg = 28,800 arcsec = 230,400 KIWI units
ZE0 grid unit:    lat 2/3 deg = 2,400 arcsec = 19,200 KIWI units
                  lon 1 deg = 3,600 arcsec = 28,800 KIWI units
ZE0 packed unit:  lat (2/3)/1024 deg = 1.953125 arcsec = 15.625 KIWI units
ZE0 POI fine step: 1/512 packed unit = 0.0038147 arcsec (non-integer KIWI units)
mesh_grid: 45 EU tiles, B28R070R 26.67..32.00 N, -12..-4 E
coord.py selftest: OK
```

## Interpretation

- **FACT:** every coarse ZE0 grid size is an integer multiple of the KIWI 1/8-arcsecond unit (19,200 and 28,800), so the falsifier does **not** fire; the two grids are arithmetically compatible.
- **FACT:** the fine units are not: one packed latitude unit is 15.625 KIWI units and one POI fine step is 0.03052 KIWI units. A KIWI geonum therefore cannot express the ZE0 `11xx` nibble plus 11-bit fine word exactly; the M4.28/M4.27 residual is not explained by this reading.
- **UNKNOWN:** `exp1`/`exp2` in `pid_t` could describe a per-parcel division that would restore integrality, but without KIWI 1.2.x text (M4.65) this is a hypothesis, not a result.
- **OBSERVED:** US and EU tiles have the same 8×8 grid shape; no market-specific arithmetic difference was found.

## Conclusion

M4.68 is done with verdict `arithmetically compatible at tile/grid level, not a parcel-coordinate rule`: KIWI geonums explain neither the packed 11-bit coordinate nor the POI fine split, and no patch to `tools/coord.py` is warranted. No KIWI field name was promoted to the format docs.
