## Question

What is the record layout inside one decompressed `LCTBL001` stream, and how
many names does each field hold and how long is the longest name per field?

## Hypothesis

The earlier scan (`tools/lctbl_names.py`) only saw text runs because the name
area mixes binary and text. A fixed header with explicit length fields should
frame every record self-describingly, so a parser can walk a stream without
resynchronising on text.

## Interpretation

- **FACT:** each record is a 16-byte header, four fixed-size name slots and a
  footer; `size = 2 × u16be(header[0:2])` tiles every stream exactly.
  Header bytes `+3..+6` are four single-byte half-lengths; slot size is
  `2 × lenN`. `+2` is always `0x01`; `+14..+15` is a class/level `u16`.
- **FACT:** names are **padded to even length with `0x00`**, not
  NUL-terminated variable strings. An even-length name is followed
  immediately by the next slot/byte; only an odd-length name has one NUL.
  This is why a NUL scan reported 328,628 "strings" instead of 247,089
  records / 456,501 names.
- **FACT:** the decoder + encoder round-trip all 517 streams byte-identically
  (11,481,060 bytes), and the same framing tiles the 2014 and 2016 files
  without a gap.
- **OBSERVED:** field 3 is the primary name and is present in 98.7 % of
  records. Field 1 is a road-number field (54 % match `^[A-Z]{1,3}[ -]?\d`,
  e.g. `D5`, `I/34`). Fields 2 and 4 carry aliases/second names.
- **HYPOTHESIS:** fields 1–4 correspond to the catalog's road no / road name /
  first name / second name columns. The order is not established; field 3 is
  the primary name in every observed block.
- **OBSERVED:** each stream is a page of at most 500 records (487/517 full on
  2011). The footer is 0–22 bytes, always even, and starts with `0x00` in
  most records.
- **UNKNOWN:** the meaning of the seven attribute bytes `+7..+13`, the footer
  content, the class values beyond the hierarchy levels already known
  (100/200/300/700/10500), and any index that joins a record to `RDSTM001` or
  the tile files.

## Conclusion

`docs/format/rdstm.md` now documents the record layout, the four-field
counts/maxima and the cross-year control; C-1830–C-1839 record the result and
supersede the NUL-terminator wording. The new `tools/lctbl_records.py` parses,
dumps, round-trips and verifies streams; `--selftest` runs without vendor
data.

Still open: footer semantics, attribute bytes, field-to-column mapping, and
the join to `RDSTM001`/`MAPAL001`.
