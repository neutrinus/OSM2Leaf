## Question

Can `imgpatch.py` produce a real US S1 card (one variable: the `POINT010` pair,
unchanged) and S2 card (same-length POI rename, recompressed at L9) whose
byte differences lie only in the file's clusters or its directory entry, and
does `cardcheck.py --image` pass with the label present?

## Hypothesis

S1 is byte-identical to the factory image (no-op patch). S2 differs from S1
only in `POINT010.DAT.cmp` clusters, `POINT010.DAT.ind` cluster and the
`POINT010.DAT.cmp` directory entry size field. **Falsifier:** any byte
difference outside those ranges, or a `cardcheck` FAIL, or a label that is
missing.

## Method

1. **Sample and hash.** As in Sample. `sha256sum` matches the pinned value.
2. **Commands.**

   ```bash
   W=/home/marek/projekty/leafre-work/m5.13
   IMG=archive/sd-images/LEAF_2011-2012_US.img
   mkdir -p "$W/factory" "$W/s1-recomp" "$W/s2"
   7z x -y -o"$W/factory" "$IMG" REFER001/POINT010.DAT.cmp REFER001/POINT010.DAT.ind DRSTR001.DAT

   # S1 control: recompress the unchanged page, compare bytes
   ~/.venvs/ze0/bin/python tools/cmpind_writer.py recompress \
     "$W/factory/REFER001/POINT010.DAT.cmp" "$W/factory/REFER001/POINT010.DAT.ind" "$W/s1-recomp" POINT010.DAT
   cmp "$W/s1-recomp/POINT010.DAT.cmp" "$W/factory/REFER001/POINT010.DAT.cmp"
   cmp "$W/s1-recomp/POINT010.DAT.ind" "$W/factory/REFER001/POINT010.DAT.ind"

   # S2 host: same-length rename, L9 inner page
   python3 tools/mutate_refer_poi.py "$W/factory/REFER001/POINT010.DAT.cmp" \
     "$W/factory/REFER001/POINT010.DAT.ind" "$W/s2" \
     --page 0x840ba0 --old "HANA HEALTH CENTER" --new "OSM2LEAF TEST POI1"

   # S1 and S2 images
   python3 tools/imgpatch.py --image "$IMG" --file REFER001/POINT010.DAT.cmp \
     --from "$W/factory/REFER001/POINT010.DAT.cmp" -o "$W/us_S1.img" --allow-resize --json > "$W/s1-cmp.json"
   python3 tools/imgpatch.py --image "$W/us_S1.img" --file REFER001/POINT010.DAT.ind \
     --from "$W/factory/REFER001/POINT010.DAT.ind" --allow-resize --json > "$W/s1-ind.json"
   cp --reflink=auto "$W/us_S1.img" "$W/us_S2.img"
   python3 tools/imgpatch.py --image "$W/us_S2.img" --file REFER001/POINT010.DAT.cmp \
     --from "$W/s2/POINT010.DAT.cmp" --allow-resize --json > "$W/s2-cmp.json"
   python3 tools/imgpatch.py --image "$W/us_S2.img" --file REFER001/POINT010.DAT.ind \
     --from "$W/s2/POINT010.DAT.ind" --allow-resize --json > "$W/s2-ind.json"

   python3 tools/cardcheck.py --image "$W/us_S1.img" --hash
   python3 tools/cardcheck.py --image "$W/us_S2.img" --hash

   # diff ranges and classification
   python3 -c "import sys; sys.path.insert(0,'tools'); import mkcard; from pathlib import Path; \
     print(len(mkcard.diff_ranges(Path('$W/us_S2.img'), Path('$IMG'), limit=10**6)))"

   # M5.12b control: fresh build of the factory US tree
   # (tree extracted with 7z to leafre-work/m5.12-us/root-factory, 248 files)
   ~/.venvs/ze0/bin/python tools/mkcard.py --from-image "$IMG" \
     --tree /home/marek/projekty/leafre-work/m5.12-us/root-factory \
     -o "$W/us_fresh_mkcard.img" --verbose
   python3 tools/cardcheck.py --image "$W/us_fresh_mkcard.img"
   ```

3. **Controls.** Positive: the S1 no-op patch must reproduce the factory image
   byte for byte. Negative: `cardcheck` on the fresh build (control M5.12b).
   The S1 image is also the baseline for the S2 range check.
4. **Corpus.** One image (8.06 GB), one file pair (4.24 MB + 612 B = 9.7 MB
   logical), 149 chunks, 248 files in the extracted tree.
5. **Falsifier.** As in Hypothesis; stated before the run.

## Observations

- **Zlib deviation.** `cmpind_writer.py recompress` on the factory pair with
  zlib **1.3.2** (not the pinned 1.3.1) reproduces the factory `.cmp` and `.ind`
  byte for byte (149 chunks, 9,715,200 logical bytes). Stock 1.3.1 was not
  available without a source build, so this is recorded as a version
  difference, not a pin change. `cmpind_writer verify` on the factory pair
  reports `checked 1 ok 1`.
- **Bug found and fixed in `tools/imgpatch.py`.** The first S1 run changed
  2 bytes outside the payload: the FAT entry of the file's last cluster
  (`78257`) was rewritten from `0x0FFFFFFF` to `0x0FFFFFF8`. Both values are
  end-of-chain markers, but the write was not needed because the chain length
  did not change. Fix: write EOC on the last link only when the entry is not
  already `>= EOC` (`tools/imgpatch.py`, the end of the chain update).
  `imgpatch.py --selftest` passes (46 checks); `selftest.py --only imgpatch`
  passes. After the fix, S1 equals the factory image byte for byte.
- **S1.** `us_S1.img` == factory image (`cmp` silent); `cardcheck --image` PASS,
  `[sha256] OK`, label `QSD-301-103`.
- **S2.** `us_S2.img` `cardcheck --image` PASS (`[mmain] OK 11/11`, `[version]
  image_copy=identical`, label `QSD-301-103`, `[sha256]
  af4c9ff14e6b2749…`).
- **Byte differences.** S2 versus factory: 17,737 ranges; S2 versus S1: the
  same 17,737 ranges. Every range lies inside the POINT010 data clusters
  78193–78258 or inside the 32-byte directory entry at `0xb3bb7e80` (the
  `size` field, bytes `+28..+29` change: 4,240,574 → 4,233,336). The
  unexplained count is 0. The FAT changes planned by `imgpatch` for the S2
  `.cmp` are none (chain length unchanged), and the `.ind` write is one
  cluster (78258, 612 bytes).
- **Control M5.12b.** `mkcard.py` fresh build of the factory US tree: 0 warnings
  in `mkcard-fresh.log`, `cardcheck --image` RESULT PASS, label `QSD-301-103`.
  The fresh image is structurally valid but not byte-identical to the factory
  (expected: the fresh path does not reproduce FAT allocation, C-2035).

## Interpretation

S1 is a true no-op at the byte level, so the `imgpatch` write path, the FAT
handling and the directory entry logic reproduce the factory card. S2 changes
only the POINT010 pair and its directory size field, and `cardcheck` passes.
The M5.13 hardware precondition ("one variable, label present, diffs inside the
replaced files") is met on the real US image; the card is still not tested in
a car (M6.2). Limit of the range check: the cluster base used in the check is
derived from the `imgpatch` write offset for cluster 78193, not from an
independent BPB read.
