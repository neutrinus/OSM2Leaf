## Question

Do the factory EU2014 Poland map files decode with the **2011** offline
decoders, and do they expose a factory-made answer sheet (Polish names, the
LCTBL country/table code for Poland, POI naming) the compiler can target?

## Hypothesis

The ZE0-era container and record grammars are unchanged 2011→2014 (C-120,
EXP-2026-11-19-M4.41), so each 2011 decoder reads the EU2014 Poland files with
the same framing and reports strictly more Polish detail. **Falsifier** (set
before the result): if the four Poland tiles have the same sizes and the same
record counts in both editions, the 2014 card is not a richer oracle. A second
falsifier: a family whose 2011 decoder refuses the 2014 bytes is reported
`different format`, never converted or repaired.

## Interpretation

- **FACT:** all four Poland file families decode with the unchanged 2011 tools
  on EU2014. `LCTBL` framing, `POINT` page/tree grammar, tile container and
  `.cmp`/`.ind` container are the same; only counts and bytes change
  (O2, O5, O6, O7).
- **FACT:** the 2014 card is a richer Poland oracle. Polish-named LCTBL records
  grow `2139 → 6174`, Polish-letter name strings `1680 → 4451`, POI name lines
  `425826 → 552954`, section-4 name-index records `2640 → 7897` (directories
  `153 → 182`), and every Poland tile grows. The falsifier is refuted.
- **FACT:** the LCTBL code question is settled negatively for both factory
  cards: no `33xx` table and no TMC CC `3` (O4). A generated Poland file must
  write its own `0x33nn` table; there is no factory table to copy. This is the
  cross-year answer to M5.64's open item (M5.64 still owns the firmware lookup
  run).
- **FACT:** POI names in `POINT021` are ASCII-only on both cards, while LCTBL
  names retain diacritics. A compiler targeting POI text must transliterate
  Polish names; the font limit from C-7885/C-7886 applies to LCTBL text.
- **HYPOTHESIS:** the 2014 LCTBL table-count drop (30 → 14) reflects a TMC
  database consolidation, not a reader change; O4 shows only the codes, not
  the country mapping.
- **UNKNOWN:** whether EU2016 adds a Poland table or more Polish detail; it was
  out of scope (only pre-checked for pin identity). The 2011-vs-2014
  `diff_years_tiles.py` delta census was killed before completion; only the two
  clean self-census totals (O8) are used.

## Conclusion

The matrix is filled in `docs/research/image-versions.md` as a `Cross-year`
column. Family → verdict → Poland count (EU2011 → EU2014): `LCTBL001` decodes
with differences, `2139 → 6174` Polish-named records; `MAPAL001` Poland tiles
decode with differences, section-4 name-index records `2640 → 7897` (directories
`153 → 182`) and all four tile sizes grow; `POINT021` decodes with differences, `425826 → 552954`
name lines (ASCII-only); whole-card container/related families decode with
differences (`46` tiles, `11` MMAIN rows stable; `1180` field/tree differences
with a clean `RESULT: IDENTICAL` control). Three compiler facts are settled:
(1) the 2011 grammar reads 2014 Poland bytes unchanged; (2) there is no
factory LCTBL table for Poland — the compiler must generate table code
`0x33nn` (no `33xx` in either catalog, no CC `3` in `reception.dat`); (3) POI
names are ASCII-only while LCTBL names retain diacritics, so transliteration
is required for POI text. C-7900–C-7909 carry the evidence. Nothing from 2014
was committed; scratch is deleted.

(4) `scan_refer_names.py` prints Latin-1-decoded text, so a UTF-8 Polish-letter
grep finds nothing; the POI count uses line counting and a non-ASCII control.
