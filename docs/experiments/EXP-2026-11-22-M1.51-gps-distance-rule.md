## Question

Does US2011 `Navi.exe` contain a check between the GPS fix (`OBJ_GpsInfo` and
the receiver message path) and the car position (`OBJ_CarPos`) that would drop a
valid Wrocław fix while the car stays in Kentucky — a date comparison (H2a),
a distance/jump limit (H2b) or map matching (H2c)?

## Hypothesis

The premise of M1.50's update is that the block is inside the WinCE navigation:
the receiver has a 3D fix in Poland (U1), the navigation's stored positions stay
in Kentucky with rolled-over 2007 dates (U3). We expect to find a conditional
between the fix and the `OBJ_CarPos` write. **Falsifier:** the car position is
written from the fix unconditionally (only coordinate conversion gating), which
means H2a/H2b/H2c are not implemented in this path.

### 3. Controls

- **Positive.** The task Precheck itself: `--to 0x0346dd7c` finds the literal

## Interpretation

- **FACT (C-8250):** the US2011 receiver-message task `Navi.exe fn 0x0049ad30`
  decodes a position and calls `fn 0x00497db4`, which writes
  `OBJDLL!OBJ_CarPos_write` through import slot `0x00581490`
  (VAs from `cerom.py` module bases + `sh4xref`/`pdata`).
- **FACT (C-8251):** `fn 0x00497db4` has no date, distance, agreement-count or
  `OBJ_GpsInfo` comparison. It tests only `STD_PntData_setL1MeshXY`'s return;
  `STD_PntData_isValid`'s return is not tested. The task's falsifier fires, so
  H2a/H2b/H2c are refuted **for this path**.
- **OBSERVED (C-8252):** the coarse-grid mask `0xffff7700` and the 6-entry
  table at `0x00cc5ea0` live in `fn 0x0042b664`, which *reads* `OBJ_CarPos`
  and only updates the downstream display word `0x00cc1ce4`; it is not a gate
  on writing `OBJ_CarPos`. The `LAST`/`2D`/`3D` words are a debug formatter
  (`fn 0x0349a89c` in `OBJDLL.dll`), not an accept condition.
- **OBSERVED (C-8253):** `navdrv!SetFilterConfig` is the ASCII command name at
  `0x039e1bec`, dispatched in `navdrv.dll fn 0x039e3598` and implemented in
  `fn 0x039e7648`: a 32-bit caller word is stored at `+8` of the struct at
  `*0x01f3c118` after a state/`0x1388`/`0x0102` handshake. If a filter exists
  outside `Navi.exe`, the interface to name is the `NAV1:` stream-driver IOCTL
  named `SetFilterConfig` (and the `EVENT_NAV_CYCLE_DATA` message that carries
  fixes into `Navi.exe`, M8.H29); no distance/date rule was found in it in
