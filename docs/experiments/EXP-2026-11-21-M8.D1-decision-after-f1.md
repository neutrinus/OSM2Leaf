## Interpretation

- **FACT:** the gate is due (`grep -c` prints `1`; M8.A3 and M8.A6 are `[x]`)
  and no Marek decision is on record (`NEG A` exits `1`; the only `Marek
  decision:` text on the board is M6.14's bench scope).
- **FACT:** no task anywhere uses F3 as an `Unblock:` field (`rc=1`), so F3 by
  itself moves no map row; the only L4 stage that unblocks anything is F4
  (`M8.E4`, the first task of the `Depends:`/`Unblock:` field in three rows:
  M4.51, M4.48, M8.E3).
- **OBSERVED:** F2 = 11 `M8.C` rows, F3 = 3, F4 = 9 (19 distinct, 22 rows
  total). C10 and C1 are the F3 rows; C10 is done and C1 is a draft PR (#394).
- **HYPOTHESIS (the re-estimate, numbered):**
  1. **F2 — no change, do not start.** Eleven rows, none of them worked except
     C1 and C2 (SCIF) which the `ze0-0008` patch already touches for the SD
     path (C-1463). The `2–4 weeks` row stands, and it is the *least* useful
     stage for the map: F2 buys `device.exe` driver loads, not a file read.
  2. **F3 — 1–2 weeks on the model path after C1, not `~1 week` HLE.** The
     SD host identification already runs (C-1462: CMD0 … ACMD42), so the
     expensive half of the "undocumented Renesas SD host" risk is paid; what
     is left is the ACMD13 data transfer over the HPB DMAC, which is C1.
     Switching to HLE now would throw away `ze0-0008` to save one week.
  3. **F4 — no change, `1–3 months`.** Nine rows, two of them (C4 micon, C5
     CAN) are the "unknown protocol" risk, plus C18 display. This is the only
     stage that unblocks a map task, and it is the most expensive one.
- **UNKNOWN:** whether Marek wants an automatic regression loop without
  hardware. That is the second clause of the Goal and it is a value
  judgement, not a measurement: F3 would let a boot run a card through the
  firmware on every change, but no M9 task waits on it today, so nothing in
  the repo pays for it yet.

## Conclusion

The recommendation, to be written into the M8.D1 block and the critical path,
is: **do not open F2 or F3 now.** F3 is cheap to finish (C1 is in flight) but
buys no map task; F4 is the only stage that unblocks anything and it is
`1–3 months`. Keep C1 (#394) as the last L4 step because it is the F3 data
path *and* the shared HPB DMAC that `serial_scif`, `SDHC` and `wavessi*` all
need, then hold the decision at M8.D2. If Marek answers "continue", the cheap
order is **F3 on the model path first** (1–2 weeks after C1), **F2 only when a
driver blocks the F3 boot** (2–4 weeks), and **F4 only after M8.D2** shows the
micon/CAN handshake is scriptable (`1–3 months`). Five claims (C-1590–C-1594)
carry this; no code changed, and `M8.C1`/`M8.D2` are untouched.
