## Question

Does the firmware's own `DRSTR001.DAT` parser accept the factory file of the
EU and the US card and a file rebuilt by our writer, and reject a corrupted
one — on the build that ships with each card?

## Hypothesis

M9.44 runs the EU2011 parser inside the map-file layer's mount
(`vcard_l3.py boot`). The US2011 build is the same layer moved
(C-3487, C-3584 era `fn_match` pairs), so the same harness with US2011 VAs
mounts the US card. **Falsifier:** the US factory card is rejected or builds
a table whose directory/file counts differ from the file's own counts; a
truncated or bad-offset file is accepted; the derived US data addresses do
not follow from the US code (`port` mismatch).

## Interpretation

- **FACT (C-5940, C-5941):** the US2011 map-file layer is the EU2011 one
  moved: 13 functions pair with equal pdata lengths, and the five data
  addresses the harness needs are the pool values at the same load index;
  `vcard_l3.py --build us2011` runs the US layer.
- **FACT (C-5942):** the firmware's parser accepts the factory
  `DRSTR001.DAT` on both builds and builds a volume table with exactly the
  file's directory and file counts (EU 40/285, US 20/189).
- **FACT (C-5943):** a file written by our writer (`drstr_ze0.build`) is
  accepted on both builds: byte-identical, with a grown tile, and (US) with
  the writer's own child order. The table changes with the content, so the
  firmware read it (U8/U9).
- **FACT (C-5944):** a truncated file and a bad listing offset are rejected
  (state stays 1, two error-log calls) on US2011, as on EU2011.
- **OBSERVED:** without `DRSTR001.DAT` the US layer still mounts from the
  file system (as EU, C-4637), so "absent" is not a reject case.
- **INFERENCE:** a writer-order file is accepted but changes file ids
  (C-4649/C-4650); acceptance here is not proof that map clients open the
  right files — keep the reference order (M9.44 finding stands).

## Conclusion

M9.14's Done-when holds through the virtual card: the firmware's
`DRSTR001.DAT` parser accepts the factory EU and US files and our rebuilt
ones, and rejects two corrupted cases on each build (C-5940–C-5946).
`tools/vcard_l3.py` gains `--build us2011` (with a head SHA-256 check) and a
`port` check; the US2011 values are owned by `tools/build_targets.py` (roles of
tool `vcard_l3`, copied into the `docs/format/firmware.md` US table and
`fn_audit`'s US start set, now 33 entries; `build_targets.py check` → `TOTAL
only-in-*: 0`); `tools/drstr_rebuild.py` rebuilds a card's file from the image
without extracting it. `targets.json` keeps `drstr_parser` as a `blocked`
`runner.py` entry whose reason now names the command; `reader-coverage.md`
row 4 carries both builds.
