# EXP-2026-11-20-M5.55: `l2check` expects the M5.52 rename+field-5 edit, not the pre-M5.52 rename-only one

- **Status:** done
- **Date:** 2026-11-20
- **Sample:** EU2011 factory tree `/home/marek/projekty/leafre-work/m5.29-factory-root`
  (read-only), extracted from the EU 2011 SD image; firmware head
  `archive/head256.img` (`92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`).
  Fixture page: `REFER001/POINT032.DAT` inner zlib page `0x4200`, record 8.
- **Tools:** python3 3.13 / zlib 1.3; `tools/l2check.py` (this task),
  `tools/mutate_refer_poi.py` (unchanged, the writer under test),
  `tools/validate_mutation.py` (unchanged).
- **Claims:** C-5550–C-5552
- **Supersedes:** none
- **Superseded by:** none

## Question

Does `l2check.check_refer_rename_resize` build the expected record the way
`mutate_refer_poi.py --resize` actually writes it after M5.52, so a full
`l2check` run on EU trees can PASS instead of failing on every card?

## Hypothesis

Since M5.52 (`608f949`) `--resize` patches **two** bytes of the renamed
record: the record length byte (`len2`, `rec[1]`) and the field-5 length byte
(the name, in 16-bit words, at `layout["loc"] + NAME_FIELD`). The check still
builds the pre-M5.52 "rename-only" expectation (only `len2` patched), so its
`after != expected` test fails on every record that `--resize` correctly
edits. If the check's expected bytes include the field-5 length patch, the
`[refer_rename_resize]` row is OK and the run prints `RESULT: PASS` on the EU
factory tree; a rename-only edit (field 5 left stale, the pre-M5.52 writer)
must still fail.

**Falsifier:** after the fix the Precheck command still prints
`[refer_rename_resize] FAIL` or `RESULT: FAIL` on the EU factory tree; or the
correct M5.52 record does not equal the check's expected bytes; or the stale
field-5 record does equal them (then the check would accept the pre-M5.52
edit and the negative control would be missing).

## Method

1. **Sample and hash.** The EU factory tree above, page `0x4200` of
   `REFER001/POINT032.DAT`, found by `find_resize_fixture` (known
   `VATICAN MUSEUM` → `OSM2LEAF PROBE POI` fixture). The record 8 header is
   class 3, field-5 length 7 words, name 7 words, `lens=[3,1,1,0,0,7,8,0,1]`,
   `$+4` B delta over an equal-length page. No vendor bytes are committed.
2. **Commands.** The Done-when Precheck command; the check derives the
   expected bytes itself, and a negative rebuilds the pre-M5.52 record and
   compares it with the same helper:

   ```bash
   FAC=/home/marek/projekty/leafre-work/m5.29-factory-root
   # Precheck / Done-when; before the fix prints FAIL, after prints OK
   python3 tools/l2check.py --root "$FAC" --no-golden \
       --tiles B48R058R.DAT --semantic-tiles B48R058R.DAT --cmp-limit 20 | tail -3
   # negative: stale field-5 length byte must not equal the expected record
   python3 - "$FAC" <<'PY'
   import sys
   from pathlib import Path
   sys.path.insert(0, "tools")
   import l2check, mutate_refer_poi
   name, page, old, new, _ = l2check.find_resize_fixture(Path(sys.argv[1]))
   blob = l2check._refer_blob(Path(sys.argv[1])/"REFER001"/f"{name}.cmp")
   inner, _ = l2check._inner_page(blob, page)
   ob, nb = old.encode(), new.encode()
   mut, info = mutate_refer_poi.resize_name(inner, ob, nb)
   before = mutate_refer_poi.parse_page(inner)[info["index"]]["bytes"]
   good = mutate_refer_poi.parse_page(mut)[info["index"]]["bytes"]
   exp = l2check._expected_resize_record(before, before.find(ob), ob, new,
                                         len(nb)-len(ob))
   stale = bytearray(good)
   stale[info["name_len_offset"] - info["record_offset"]] = info["old_name_words"]
   assert good == exp, "M5.52 record != check expectation"
   assert bytes(stale) != exp, "stale field-5 record was accepted"
   print("positive: M5.52 record == expected; negative: stale != expected")
   PY
   ```
3. **Controls.** *Positive:* the real writer's record for the fixture must
   equal `_expected_resize_record` (84 B, field-5 9 words). *Negative:* the
   pre-M5.52 record, rebuilt by reverting only the field-5 length byte to its
   old 7 words, must differ from the expected bytes at the same length (so
   the check reports a FAIL there). The l2check self-test carries the same
   two assertions on a synthetic record (`M5.52 rename:` / `pre-M5.52
   rename-only`).
4. **Scope.** `check_refer_rename_resize` (one page, one record per run) plus
   the `--resize` expectation; the mutation tool, `validate_mutation.py`, the
   page/records fixtures and the resolver are unchanged. In scope: the EU
   fixture `POINT032` page `0x4200`. Excluded: other-name pages (the same
   helper applies to whatever `find_resize_fixture` returns), same-length
   renames (`refer_mutation`, unchanged), and the firmware reader (M5.52's
   C-5260–C-5265, rule 13).
5. **Falsifier.** Stated under Hypothesis, before the results.

## Observations

### Precheck on the unchanged worktree (before the fix)

```
[refer_rename_resize] FAIL (file=POINT032.DAT; page=0x4200; old=VATICAN MUSEUM; new=OSM2LEAF PROBE POI; delta=4; validate=PASS: same logical size, changes confined to one page, DRSTR untouched; records=39; changed_records=1)
  ERROR record 8 is not the rename-only edit (got 84 bytes, expected 84)
RESULT: FAIL
```

The mutation and `validate_mutation.py` already pass; only the record-level
expectation fails, at equal length (84 vs 84), so the difference is a byte
value (the field-5 length), not the record size.

### Fixture facts (record 8)

```
fixture=POINT032.DAT page=0x4200 page_used=655 page_gap=768
record=8 total 80->84 len2 40->42
name_len_offset(abs)=0x2c1 rel=0x21 words 7->9
old='VATICAN MUSEUM' (14 B) new='OSM2LEAF PROBE POI' (18 B) delta=+4
field5 start=+0x30 words=7 loc=+0x1c lens=[3, 1, 1, 0, 0, 7, 8, 0, 1]
```

The only byte the pre-fix expected record left stale is `rec+0x21` (field-5
length: 7 → 9 words).

### After the fix

Precheck command on the EU factory tree:

```
[refer_mutation] OK (file=POINT032.DAT; page=0x4200; old=VATICAN MUSEUM; new=OSM2LEAF PROBE; validate=PASS: ...)
[refer_rename_resize] OK (file=POINT032.DAT; page=0x4200; old=VATICAN MUSEUM; new=OSM2LEAF PROBE POI; delta=4; validate=PASS: same logical size, changes confined to one page, DRSTR untouched; records=39; changed_records=1)
RESULT: PASS
```

Negative control (stale field-5 byte):

```
fixture POINT032.DAT page 0x4200 record 8 old='VATICAN MUSEUM' new='OSM2LEAF PROBE POI' delta=+4
correct M5.52 record == check expectation: True
stale field-5 length byte reverted to 7 words (new name is 9 words)
stale record != check expectation (check reports FAIL): True
would report: record 8 is not the M5.52 rename+field-5 edit (got 84 bytes, expected 84)
```

Self-test (vendor-free):

```
  ok   M5.52 rename: expected record (len2 + field-5 length) == writer
  ok   pre-M5.52 rename-only (field 5 stale) is not the M5.52 edit
l2check selftest: PASS (0 failure(s))
```

## Interpretation

- **FACT:** the pre-M5.52 `l2check` expectation had exactly one stale byte,
  the field-5 length byte at `rec+0x21` (7 → 9 words) of record 8, and that
  is why `--resize`'s correct 84-byte record failed an 84-byte expectation.
- **FACT:** with the field-5 patch in the expected bytes the EU factory tree
  passes `[refer_rename_resize] OK` and `RESULT: PASS`, and a record that
  reverts only that byte still fails — the check is not relaxed to accept the
  pre-M5.52 edit.
- **OBSERVED:** `mutate_refer_poi.py` / `validate_mutation.py` were already
  green before the fix; only the l2check record comparison was wrong, which
  matches C-5543 (the only FAIL in the M5.54 pipeline runs).
- **UNKNOWN:** nothing new about the format; the check still trusts
  `mutate_refer_poi.name_field` (C-5115) rather than re-deriving the field
  layout, which is the shared model M5.52 established.

## Conclusion

`tools/l2check.py` now builds the expected renamed record the way M5.52's
`--resize` writes it: the record length byte **and** the field-5 length byte
(the name in words). `check_refer_rename_resize` uses `_expected_resize_record`
(both bytes, field 5 from `name_field`), and the l2check self-test asserts
that the writer's record equals the expectation and that the pre-M5.52
rename-only record does not. The Precheck command prints
`[refer_rename_resize] OK` and `RESULT: PASS` on the EU factory tree. This
closes the l2check gate of `one_tile_pipeline`/P1 runs that C-5543 recorded;
`docs/format/` is unchanged (no format fact moved). Claims C-5550–C-5552.
