## Question

Can a host program be built that answers the guest's `SCI1:` iNai frames as
`docs/firmware/anwdrv.md` requires — with valid framing and BCC — and that
refuses a frame whose checksum is wrong?

## Hypothesis

A stdlib peer with a shared frame codec and a table of request→reply rules
can replay the logged guest frame and emit a framed ACK. **Falsifier (from
the task):** the selftest accepts a frame with a wrong checksum.

## Method

1. **Sample and hash.** `sha256sum archive/head256.img` → the hash above;
   the peer itself is tool-only and never opens the image.
2. **Commands.** Runnable from the repo root as written.

```bash
python3 tools/anw_frames.py --selftest
python3 tools/ze0_peers/micon.py --selftest
python3 tools/selftest.py --list | grep micon
python3 tools/selftest.py --only ze0_peers.micon
python3 - <<'PY'
import sys
sys.path.insert(0, 'tools/ze0_peers')
import micon
peer = micon.MiconPeer()
print(peer.handle(bytes.fromhex('1002020800100319')).hex())
PY
```

3. **Controls.**
   - *Positive:* the logged frame `1002020800100319` must get a reply whose
     DLE STX/ETX, echo and XOR BCC all validate through
     `anw_frames.parse_frame`.
   - *Negative:* the same frame with its last byte flipped (`…18`) must be
     rejected with no reply; wrong STX and an unknown command must also be
     rejected. The task's falsifier is the negative control with the
     corrupted checksum.
4. **Scope.** One new tool (`tools/ze0_peers/micon.py`, 26 selftest checks),
   one shared codec (`tools/anw_frames.py`, unchanged), one registry entry
   via auto-discovery. No firmware execution, no QEMU boot, no card. The
   module-present reply body is a HYPOTHESIS from M8.H43 and is configurable
   in `RULES`, not claimed as accepted.
5. **Falsifier.** `selftest` reporting "corrupt BCC rejected" with a reply,
   or any reply failing `anw_frames.parse_frame`, would refute the peer.

## Observations

**O1 — codec reuse.** `micon.py` imports `anw_frames` from `tools/` and uses
`parse_frame`/`build_frame`/`bcc`; it does not re-derive the grammar.

**O2 — the logged frame.** `MiconPeer.handle(bytes.fromhex(
"1002020800100319"))` returned a frame beginning `10 02`, ending `10 03`
with BCC `0x1b`; `anw_frames.parse_frame(reply)` gave payload `02 02 08 00`
(control `0x02` ACK, command echo `0x02`, parameters `08 00`). Counters after
one frame: `requests=1 replies=1 bad=0`.

**O3 — table rules.** Five rules are installed (`ReqMo` with `02 08`, generic
`ReqMo`, `Audio` `04`, `ReqAIr` `01`, `GetSy` `09`); each rule's synthetic
request produced a parsed reply with control `0x02` and the matching command
echo. Longest prefix wins.

**O4 — negative controls.** A BCC-flipped frame returned `None`, incremented
`bad` to 1 and left `replies` at 0. A wrong-STX frame returned `None`. An
unknown command (`0x77`) was logged and not answered. A `fail 02` control
command produced a validly framed NAK (`0x15`) for testing; it is never sent
by default.

**O5 — streaming.** A frame split across two `recv()` chunks was reassembled
into one request; two frames in one chunk produced two requests; a
DLE-stuffed payload (`02 10 00` → wire `10 02 02 10 10 00 10 03 …`) was
extracted without confusing the doubled DLE for an end marker.

**O6 — control socket.** `status`, `reset`, `key NAME`/`key 0xNN`, `fail`,
`nofail` and unknown commands were exercised; `key` queues a future
interrupt-class event (`0x06` control, HYPOTHESIS) but sends no frame in this
task. VK values come from `docs/firmware/keys.md` §3.1.

**O7 — registry.** `tools/selftest.py --list` shows
`tool:ze0_peers.micon --selftest tools/ze0_peers/micon.py --selftest`;
`--only ze0_peers.micon` → `passed=1 failed=0`. Total 26/26 checks.

## Interpretation

- **FACT (C-7410, C-7411):** the peer reuses the M8.H43 codec and answers the
  logged frame with a framed, BCC-valid ACK (O1/O2).
- **FACT (C-7412, C-7413, C-7414):** the rule table, negative controls and
  streaming reassembly behave as specified (O3/O4/O5).
- **FACT (C-7415, C-7416):** the selftest is auto-discovered and the
  corrupted-checksum falsifier is met (O4/O7).
- **OBSERVED (C-7417):** the control-socket commands and their answers
  (O6).
- **HYPOTHESIS:** the module-present body `02 02 08 00` and the interrupt
  body for `key` are plausible but unproven in the guest; the peer isolates
  them in `RULES`/`pending` so M8.H45 can change them without touching the
  codec.
- **UNKNOWN:** whether the guest stops its `WaitModule` loops on this reply;
  that is M8.H45's measurement.

## Conclusion

`tools/ze0_peers/micon.py` is a stdlib host peer that validates incoming
iNai frames with the M8.H43 codec, answers known requests from a table with
correct DLE framing and BCC, logs unknown/corrupt requests, and exposes a
control socket for later key events. Its `--selftest` passes 26/26 and is
auto-discovered by `tools/selftest.py`; the corrupted-checksum frame is
rejected. Nothing was run against QEMU or a real unit (rule 13).
