## Question

After M8.C1n the AUI draws the consent screen and the map buttons into DU
plane 1, but `ze0_screenshot.py screen` shows only the map. Is the plane 1
window register (`+0x34`) a source row (page flip) or a screen position, what
is the mode `0x1002` transparency rule, and what must `compose()` do to show
the AUI?

## Hypothesis

`+0x34` is the first visible source row of a two-page buffer and the guest
flips it back to 0 when the page is shown, so the frame the hardware scans is
rows 0-479 and `compose()` read the empty second page. **Falsifier:** plane 1
rows 0-479 are a back buffer the hardware never shows (then the shown page
must hold the buttons after a flip).

## Method

1. **Sample and hash.** As above. Every run is the M8.C1n recipe (NK1 + US
   card + `--ui-start`, panel peer) on the anonymous flash.
2. **Commands.** `$Q` is the built `qemu-system-sh4`, `$W` a work directory
   outside the repository.

   ```bash
   python3 tools/unitflash_anon.py build --bare -o $W/bare.bin
   python3 tools/ze0_launch.py --card archive/sd-images/LEAF_2011-2012_US.img \
     --flash $W/bare.bin --qemu "$Q" --workdir $W/live2 --timeout 1500 \
     --gdb 1243 --ui-start --peer panel --peer micon
   # after the consent screen is up (~30 s of wall time), tap OK:
   printf 'tap 277 98\n' | socat - UNIX-CONNECT:$W/live2/panel.ctl
   python3 tools/ze0_screenshot.py plane --monitor $W/live2/mon.sock -n 1 -o $W/p1.png
   python3 tools/ze0_screenshot.py screen --monitor $W/live2/mon.sock -o $W/s.png
   printf 'xp /12wx 0x1ff80130\n' | socat - UNIX-CONNECT:$W/live2/mon.sock
   ```

   The register trace is the same boot plus `gfx-trace=on` and
   `-d unimp,invalid_mem -D $W/trace.log`; the writer is read back in the
   guest memory dump (`pmemsave 0x08000000 0x3000000`) and disassembled by
   `tools/sh4dis.py` (`Mem` over gdisubdrv sec0).

3. **Controls.** *Positive:* before the tap, `plane -n 1` shows the consent
   text, so the page holds what the AUI draws. *Negative 1 (falsifier):* if
   rows 0-479 were never scanned, the trace must not show a flip of `+0x34`
   back to 0 after the draw - it does not. *Negative 2:* the old strict
   composition is unchanged where the window band is non-empty (selftest
   case in `ze0_screenshot.py --selftest`).
4. **Scope.** One boot, one static consent screen and the map start screen;
   US card on NK1; the trace covers the guest writes to DU plane 1
   `+0x00..+0x48`. The map-only composition (EU 2011 head, no `--ui-start`)
   is unchanged.
5. **Falsifier.** Stated above.

## Observations

**O1 — plane 1 registers at the consent screen.** `xp` at `0x1ff80100`:
`+0x00 = 0x00001002` (mode, key on), `+0x04 = 0x320` (stride 800),
`+0x10/+0x14 = 800/480`, `+0x20 = 0x0ef6c400`, **`+0x30 = 0`,
`+0x34 = 0x1e0` (480)**, `+0x48 = 0x83ff` (key).

**O2 — rows 0-479 hold the AUI, rows 480-959 are empty.** The plane buffer
(800 x 960) read with `pmemsave`: rows 0-479 have **24,665** pixels that are
neither 0 nor the key (30 distinct 1555 values, e.g. `0x6f7f` 13,537 px,
`0xc64` 2,163, `0x4634` 2,126); rows 480-959 are `0x0000` only.
`plane -n 1` renders the consent text ("Touch OK to accept") from rows
0-479.

**O3 — the guest code writes `+0x34` from its surface descriptor.** The
trace has one writer for the plane registers, a copy loop in `gdisubdrv.dll`
NK1 sec0 at `0x03d73fe0`-`0x03d74004`: descriptor `+0x114` (height 480) is
stored to `+0x14`, `+0x120` (address) to `+0x20`, `+0x130` to `+0x30` (0) and
descriptor `+0x84` (480) to `+0x34` (`pc 0x03d74004`). The descriptor is
built at `0x03d73f60`-`0x03d73fba` from the DDI surface record (one 80-byte
entry per surface at `0x01fbc3f8`; width/height at `+8/+12`), and
`0x03d73cac` chooses the page.

**O4 — the value is a source row, and it is never put back.** In the boot the
trace shows two values for `+0x34`: `0` (plane 1 registered while empty) and
`480` once the AUI maps its page; sampled every 2 s for several minutes it
stays 480. The guest leaves the window on the second page while drawing into
the first. **This is the task's falsifier case**: the drawn page is real, but
the window is never flipped to it.

**O5 — mode `0x1002` rule.** Bits `0xf000 == 0x1000` mean keyed: a pixel is
transparent when bit 15 is clear or `px & 0x7fff == (+0x48)`. Plane 1 is
filled with `0x83ff`; the AUI text pixels (`0x6f7f`, `0xc64`, …) have bit 15
set, so they survive the key. Plane 2 has the same mode with key `0x3ff` and
is empty on this screen.

**O6 — `screen` after the fix, consent screen.** With the page fallback,
`screen` composes plane 1 from rows 0-479 when the window band is fully
keyed and prints the note `plane 1: window row 480 is empty; showing page
rows 0-479 (M8.C1t)`. The composited image is **the map only** (RGB
SHA-256 `be2e424e…` of live7): the fallback selected the right page, but the
colour key (`+0x48 = 0x83ff`, low 15 bits `0x03ff`) drops the text pixels
because they have bit 15 clear (`0x6f7f`, `0x6b5e`, `0x18c7`, `0x4634`). An
earlier draft of this EXP read the consent text in the `screen` output; that
was a `plane -n 1` render mistaken for `screen`, and it is corrected here.

**O7 — the display link, not the plane, gated the taps.** The earlier boots
(live/live2/live3/live6) logged
`SYS_DIAGLOG_F_DISP_CNCT(SYS_DIAGLOG_REG_ERROR)`, `uistart.log` stayed at
`waiting for the first touch to clear the key guard`, and only
`SK_OTH_SCREEN_UNLOCK` was handled at `SRT_COLD_I_AGREE_NAM`. live7 (same
recipe, anonymous flash `full.bin` from `tools/unitflash_anon.py build`)
logged `REG_OK`; after one tap at panel (277, 98) `uistart.log` printed
`75.6 s: kepdrv object 0x0005ee10 key control/guard 00f1 -> 0000 (touch
unlocked)` and the state moved.

**O8 — the map screen after the tap.** `serial.log` shows, in order,
`ScreenAction(SK_SCT_AGREE_CLICK)`, `ExecuteFunction ctrl[25]
function[TELEMA_NOTIFY_AGREE]`, `ForwardState [MAP_RELAY]`,
`ForwardState [MAP_MAPOPERATION_NORMAL_MAP]`. The DU plane 1 registers are
then `+0x00 = 0x1002`, `+0x04 = 0x320`, `+0x10/+0x14 = 800/480`,
`+0x20 = 0x0ef6c400`, **`+0x30 = 0`, `+0x34 = 0`** (the window moved to rows
0-479), `+0x48 = 0x03ff` (the consent screen read `0x83ff`); plane 2 is
`0x1002` at `0x0f25a400` key `0x03ff`; plane 4 is the map `0x4002`. So the
page fallback is not needed on the map screen - the guest's own write did it.

**O9 — what `screen` shows on the map screen.** `screen` now draws plane 1
from window rows 0-479 and shows the map with the AUI controls at the right
edge (`Map Menu`, `ZOOM OUT`, `1/16mi`, `ZOOM IN` area; opaque pixels bbox x
740-793, y 252-434). But the plane 1 page also holds the previous consent
text and the "XM NavTraffic is expired" popup in rows 100-434, and the AUI
labels are not drawn: `pmemsave` of the page gives 1,502 pixels with bit 15
set (opaque under the key: `0xaeac` 500, `0xa200` 303, `0x8200` 256,
`0xe000` 179) against 24,665 pixels that are neither 0 nor the key but have
bit 15 clear (the text). A non-key render of the page shows the consent
text, "Touch OK to accept", OK/Decline and the small map controls. The
screenshot (`live7/map.png`) and the raw page stay outside the repository.

## Conclusion

Plane 1 is a two-page surface: on the consent screen the guest draws into
rows 0-479 and leaves DU `+0x34` at 480, so a strict window composition reads
the empty page. `compose()` now uses the plane's page when the window band
holds no visible pixel (printed note plus a selftest), and after the tap the
guest writes `+0x34 = 0` so the window shows the page directly.

The AUI text and button labels are still not in `screen`: their pixels have
bit 15 clear and the colour key drops them; only the 1,502 opaque widget
pixels (small controls at the right edge) survive. The unit gets the text
opaque through a 2DG blit that `ze0-0014` does not render yet - the blocker,
handed to **M8.C1v**. The task's first Done-when branch ("shows the map
buttons over the map") is therefore **not met**, and M8.C1t is `blocked`.

The falsifier is confirmed: the window register is a source row, and the
guests's lazy redraw keeps the previous page in the buffer. The register rule
lives here and in `tools/ze0_screenshot.py`'s `compose()` docstring.
