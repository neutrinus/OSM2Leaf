## Question

Does any bit-packed (non-name, non-`0x60|0x68`) page of EU 2011
`POINT002/008/029` encode a coordinate pair, by a mechanical test with a
positive and a negative control? If not, does the non-stream ("raw") part
of the decoded `.DAT` (72.2 % of POINT002 in M4.27)?

## Hypothesis

H0: bit pages carry no coordinates (phone, index, keyword data; M4.27
C-2670–C-2673). **Falsifier:** one bit page that passes the bounds test
(>= 16 distinct pairs inside the shard's own COORD001 region box at one
alignment, those in-region pairs >= 50 % of that alignment's mask pairs) and
is not a grid-key lattice. The positive control (a `78 9c` name page) must
pass the same test and the negative control (a phone page) must fail it,
or the test result is invalid.

## Method

1. **Sample and hash.** As above. Shard *n* is tested against COORD001
   region *n* (C-3750 shows 100 % of copy-A ids fall in that box).
2. **Commands.**

```bash
python3 tools/point_bitpack_decode.py --selftest
# expected: point_bitpack_decode selftest: OK
python3 tools/point_bitpack_decode.py --coord-test /home/user/OSM2Leaf/archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img
# expected (9.6 min): controls: OK; verdict bit pages: NO COORDINATES (point-kind bounds-pass pages: 0)
python3 tools/point_bitpack_decode.py raw-index /home/user/OSM2Leaf/archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img POINT002 POINT008 POINT029
# expected: finer pairs equal copy A 100.0 / 97.7 / 92.6 %, shifted control 0.0 %
```

   The test (`coord_scan`): every page found by the `poi_icons.iter_streams`
   rule (zlib `78 xx`, inflated size 2k–400k) that is not a `0x60|0x68`
   name chain is scanned for word pairs `(x, y)` at a 2-byte step under 32
   alignments: big- and little-endian words × bit phase 0..15 (so a field
   that does not start on a byte boundary is still read whole).
   *Mask (C-2129):* both words `0x8000 <= w < 0xfc00` — absolute COORD001
   form and not the walker's `0xfc00` escape type. *Local:* both words
   `<= 0x7ff` (the 0..2047 bound), byte-aligned BE/LE only, reported but not
   used for the verdict (a 0..2047 pair has no geographic bound without a
   cell). *Bounds:* inside the shard's COORD001 box. Page verdicts as in the
   falsifier; a bounds-pass unit whose distinct pairs sit (>= 90 %) on a
   lattice of step >= 8 from `x = 32768`, `y = 52736 | 52742` is labelled
   `grid` (cell keys), otherwise `point`. The raw part (non-stream,
   non-zero 4 KiB windows of the decoded `.DAT`) gets the same test, and
   its `point` pairs are compared with the shard's name-record copy-A ids
   and with the same pairs shifted by (+37, +37) (negative control).
   `raw-index` counts the 16-byte raw records `00 08 | u32 | u16 | x | y |
   00 00 00 00` in the box outside every stream and joins their `(x, y)`
   with copy A/B.
3. **Controls.** *Positive:* the first `78 9c` name page of each shard
   (copy-A ids are known coordinates) must be bounds-pass, `point`.
   *Negative:* the first phone page of each shard must fail bounds.
   Synthetic (selftest): name page pass, phone page fail, the same pairs
   at bit phase 5 and in LE found, a q=16 key table labelled `grid`, raw
   records inside a stream skipped. *Join negative:* +37-unit shift.
4. **Scope.** EU 2011 only. 1,212 bit pages / 31.4 MB (POINT002 186 /
   4.58 MB, POINT008 580 / 14.03 MB, POINT029 446 / 10.74 MB) and 43,079
   raw 4 KiB windows / 176.4 MB. Excluded: US card; streams outside the
   2k–400k rule; pairs not adjacent (x and y in separate fields); a
   coordinate encoded as a delta or in another unit than the packed id;
   local 0..2047 pairs (no bound without a cell).
5. **Falsifier.** Stated in Hypothesis, before the result.

## Interpretation

- **FACT:** shard *n*'s copy-A ids all fall inside COORD001 region *n*
  (C-3750).
- **VERIFIED (scoped):** no bit page of EU 2011 POINT002/008/029 carries a
  coordinate pair in the COORD001 form at any of 32 alignments: 0 of 1,212
  bounds-pass, while the name-page positive control passes and the phone
  negative control fails in all three shards (C-3751). The bare C-2129 mask
  and the 0..2047 local mask pass every page including the phone control,
  so neither carries information alone (C-3752).
- **VERIFIED:** the raw region is a spatial index of 16-byte `0x0008`
  records whose finer `(x, y)` are the name-record copy-A ids — every
  distinct copy-A id of each shard occurs; a +37 shift gives 0 % — plus a
  coarser level on a 16-unit (and 128-unit) lattice from the tile origin
  52736 (C-3753).
- **OBSERVED:** the raw index adds no precision: no field finer than one
  packed unit (1/192° lat, 1/128° lon) and no 0..2047 tile-local field was
  found. POINT positions are copy A/B only (C-3754).
- **UNKNOWN:** the 1,134 (POINT008) and 1,684 (POINT029) finer raw pairs
  that are not copy A; the `u32`/`u16` fields of the raw record; any
  delta/separate-field encoding (out of scope).

## Conclusion

`COORDINATES FOUND` is false for the bit pages: the verdict is **NO
COORDINATES** with counts and passing controls. The raw part does hold
coordinates, but they are a spatial index of the copy-A ids already
decoded, not new or finer positions. So M4.8b's "within a few metres" and
"local scale 1 vs 2" checks cannot be met from POINT data: the format
carries nothing finer than copy A. M4.8b is re-blocked on that (format
carries no sub-unit coordinate). `docs/format/refer.md` gains a short
section; claims C-3750–C-3755.
