## Question

The `-M ze0` start screen is central London (M8.C1f). If the level-1
parcel under that screen is regenerated from OSM by our pipeline, does the
real `Navi.exe` draw our roads?

## Hypothesis

The tile writer's level-1 road records are read by the renderer like the
factory ones (L3 already walks a generated record, M9.58). Falsifier: the
screen shows the factory roads (the changed parcel is not read) or no
roads in the parcel (the records are rejected).

## Method

1. Parcel under the screen: `tilewriter.parcel_of(-0.1342, 51.5098, 1)` =
   directory `(77,923)`, parcel row 8, col 27, box lon −0.15625…−0.125,
   lat 51.5…51.5208. The whole start screen lies inside it.
2. Factory tree extracted from the card (480 files, `mkcard.img_walk_files`).
3. Build:

   ```bash
   python3 tools/one_tile_pipeline.py --factory-root FAC --cell B48R068R \
     --parcel 77,923 --level 1 --osm London.osm.pbf \
     --osm-bbox=-0.15625,51.5,-0.125,51.520833 --clip --out W/out --json W/report.json
   ```

4. Card: copy of the factory card; `imgpatch.py --file MAPAL001/B48R068R.DAT
   --from W/out/… --allow-resize`, `imgpatch.py --file DRSTR001.DAT`;
   `imgpatch.py --check-diff --allow-metadata`, `cardcheck.py --image`.
5. Boot as in M8.H70, screenshot after `Pow Off 1st Detect`, compare with
   the factory screenshot of the same position.

Screenshots show manufacturer data beside ours and are kept out of the
repository; they were given to Marek in the project thread.

## Observations

**O1 — Pipeline bug: a negative longitude broke `--osm-bbox`.**
`one_tile_pipeline.py` passed the box to `osm_ingest.py` as two arguments
(`--bbox`, `-0.156…`); argparse reads a value starting with `-` as an
option and `osm_ingest` exited 2 (`argument --bbox: expected one
argument`). Every earlier run was in Poland (positive longitudes). Fixed by
passing `--bbox=…` as one argument (line 1874).

**O2 — Build.** `osm_ingest` kept 2 610 ways / 14 634 nodes (134
relations dropped; ways that cross the box are kept whole). `tilewriter`
rc 0, `--no-names` (the pipeline writes roads only), classes
`provisional-v0`. Changed road pairs (directory 77,923; row, pair):
`(7,54) (8,52) (8,54) (8,56) (9,52) (9,54)`, i.e. parcel (8,27) and the
neighbours the kept ways reach; 3 records appended. Gates: manifests,
`drstr_mmain_cmplst_ind`, `tile_roundtrip_structure`,
`one_tile_one_directory` PASS; `hdd_info_map_code` and `section4`
CANNOT-VERIFY-OFFLINE (as for P0).

**O4 — The screen.** The generated card boots to the same position and
draws the map (384 000 non-black pixels; 56 671 differ from the factory
screenshot).

- The street network in the view is ours: more and finer streets (OSM
  detail), with the same shape where both have the street (the main
  streets meet at the Piccadilly Circus label as on the factory map; by
  eye, side by side). Parks, water and area fills (background records,
  untouched) line up with our roads.
- Road classes differ: `provisional-v0` draws more streets as wide brown
  main roads than the factory does.
- Street labels (`AIR STREET`, `KING STREET`, `RICHMOND MEWS`) and road
  shields (`A4`, `A400`, `A401`, `A3201`) are gone: the records carry no
  names (`--no-names`).
- Place labels (`SOHO`, `PICCADILLY CIRCUS`, `LEICESTER SQUARE`,
  `TROCADERO CENTRE`) stay: they come from data we did not change.

**O5 — Same log as the factory run.** The 1 039 error/fail lines of the
serial log are the same set as in the factory run (digits stripped, sorted
counts identical): no new error from the map client.

## Interpretation

- Level-1 road records written by `tilewriter` from OSM are accepted and
  drawn by the real `Navi.exe`: this is the first L4 result for generated
  map geometry (falsifier not met: neither factory roads nor an empty
  parcel).
- The London start screen is a usable test bench for the compiler before
  a GPS connector exists; the parcel `(77,923; 8,27)` covers the whole view.
- Names are the next visible gap: the pipeline's `--no-names` removes
  street labels and road numbers. `tilewriter` can write `1=NAME` / `2=REF`
  labels (M5.7) but the pipeline does not pass them; and long names will
  be dropped where they do not fit (C-8223).
