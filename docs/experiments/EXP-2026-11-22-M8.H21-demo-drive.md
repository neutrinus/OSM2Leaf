# EXP-2026-11-22-M8.H21: Is there a demo drive? Route simulation and other position sources inside `Navi.exe`

- **Status:** done
- **Date:** 2026-11-22
- **Sample:** EU 2011 256 MiB head `archive/head256.img` SHA-256 `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`; US 2011 256 MiB head `archive/us256.img` SHA-256 `70d945d823f93f04cae4e6c7113a723cae3a992ab7a6f9b24e94ce2e006a04da`
- **Tools:** Python 3.15.0 (stdlib only; zlib-ng 1.3.1 reported by `tools/zlibinfo.py` but no recompression in this task). Repo tools: `tools/cerom.py`, `tools/ce_strfind.py`, `tools/sh4xref.py`, `tools/sh4dis.py`, `tools/board.py`. SH-4 code is little-endian, pinned by `tools/sh4dis.py --selftest`.
- **Claims:** C-7180–C-7189
- **Supersedes:** none
- **Superseded by:** none

## Question

Do the EU 2011 and US 2011 application images (build A) contain a demo / simulation / dealer "drive a route" mode, and if so what are its strings, the code that feeds positions, and the switch that turns it on?

## Hypothesis

`Navi.exe` and its companion DLLs carry a hidden/dealer simulation path (the task is motivated by the chance of getting a moving position in the emulator with no sensor model). Expected: a menu label, a persistent shop setting or a maintenance interface, and position-feeding code with literal-pool references. **Falsifier:** a string hit with no code reference (dead resource), or only generic COM/ole32 strings with no navigation demo — either would give an `absent` verdict. The opposite falsifier (a live reference to a simulation string with a switch VA) makes the verdict `present`.

## Method

1. **Sample and hash.** `sha256sum` on the resolved symlink targets; both are 268435456 bytes. `tools/cerom.py --image-start 0x200200 IMG romhdr` locates the CE segment (ECEC/ROMHDR) and prints `nummods`; `modules | grep -c` counts the TOC rows. All addresses come from `tools/cerom.py`, never from fitted deltas.
2. **Commands.** Run from the repo root, in order:
   ```bash
   sha256sum /home/marek/projekty/OSM2Leaf/archive/head256.img /home/marek/projekty/OSM2Leaf/archive/us256.img
   python3 tools/cerom.py --image-start 0x200200 archive/head256.img romhdr
   python3 tools/cerom.py --image-start 0x200200 archive/head256.img modules | grep -c -E '^\s*[0-9]+\s'
   python3 tools/cerom.py --image-start 0x200200 archive/us256.img romhdr
   python3 tools/cerom.py --image-start 0x200200 archive/us256.img modules | grep -c -E '^\s*[0-9]+\s'
   VOCAB="Demo demo DEMO Simulat Simulation simulation ShopDemo Dealer dealer NAVI_ROUTE_SIMULATION DemoRoute Simulate simulated AutoDrive"
   python3 tools/ce_strfind.py archive/head256.img --encoding all $VOCAB      # EU census
   python3 tools/ce_strfind.py archive/us256.img --encoding all Demo demo Simulat Simulation simulation ShopDemo Dealer NAVI_ROUTE_SIMULATION DemoRoute Simulate   # US census
   python3 tools/ce_strfind.py archive/head256.img --encoding all --control "Simulation on/off" Demo
   python3 tools/ce_strfind.py archive/head256.img --encoding all ZZZZ_NO_SUCH_DEMO_NEEDLE_42
   python3 tools/cerom.py --image-start 0x200200 archive/head256.img exports OBJDLL.dll | grep -i shopdemo
   python3 tools/sh4xref.py archive/head256.img Navi.exe --image-start 0x200200 --to 0x001f07e0
   python3 tools/sh4xref.py archive/head256.img Navi.exe --image-start 0x200200 --to 0x0004c720
   python3 tools/sh4xref.py archive/head256.img Navi.exe --image-start 0x200200 --to 0x0018e028
   python3 tools/sh4xref.py archive/head256.img Navi.exe --image-start 0x200200 --to 0x00bcd208
   python3 tools/sh4dis.py archive/head256.img Navi.exe --image-start 0x200200 --va 0x004ffd40 --count 24
   python3 tools/sh4dis.py archive/head256.img Navi.exe --image-start 0x200200 --va 0x003daf5c --count 60
   python3 tools/sh4xref.py archive/head256.img NaviRouteCC.dll --image-start 0x200200 --to 0x02f4db80
   python3 tools/sh4xref.py archive/head256.img OBJDLL.dll --image-start 0x200200 --to 0x0348d60c
   python3 tools/sh4xref.py archive/head256.img OBJDLL.dll --image-start 0x200200 --calls 0x034b7b84
   ```
   The pointer-hunt for the embedded strings (the matched needle sits inside a longer string, so `--to` on the needle VA returns nothing) was a Python loop over every 2-byte aligned `u32` in the uncompressed code section, e.g. `struct.unpack_from('<I', data, base+i)` over `base=0x00c8f200`, `size=0x0054be00` for `Navi.exe`; the literal pool VAs it returned were then fed to `sh4xref --to`.
3. **Controls.** *Positive:* `ce_strfind --control "Simulation on/off" Demo` exited 0 (control matched) and printed 10 EU / 14 US `Demo` hits. *Negative:* the nonsense needle `ZZZZ_NO_SUCH_DEMO_NEEDLE_42` printed `hits 0` in both images (with `UNSUPPORTED` compressed sections listed), so a zero result is distinguishable from an unreadable image.
4. **Scope.** Build A only, `0x00200200`, the first 128 MiB of each image as read by `ce_strfind` (firmware occupies the first ~100 MB). EU: **149 modules** (`nummods 0x95`), US: **151 modules** (`nummods 0x97`). Vocabulary: the 14 needles above (EU) and their 10-needle subset (US), each searched in `ascii`, `utf-16le` and `utf-16be` (`--encoding all`). Excluded: compressed `.data`/resource sections (`ce_strfind` prints them `UNSUPPORTED`), builds B/C and image C's `TestMode.exe` (different scope, see EXP-2026-11-05-M2.10-testmode). Code searches cover the uncompressed executable sections only; SH-4 code is never compressed (C-530).
5. **Falsifier.** Before the result: a demo/simulation string without any literal-pool reference in an executable section would be a dead resource, and a search finding only ole32/SVOX "demo version" strings would be `absent`. Also, a big-endian-only search finding nothing is *not* a refutation (SH-4 is LE); both encodings were searched.

## Interpretation

- **FACT:** Both build-A images contain a navigation demo/simulation subsystem, not just generic COM "demo version" strings: the same six modules, the same `2: Simulation on/off` label, the same `RGD_DEMO_*` and `CRouteSimulation` strings and the same `NAVI_ROUTE_SIMULATION_*` event names appear in EU and US 2011.
- **FACT:** The simulation strings are *live*, not dead resources: each representative string has a literal-pool reference from an executable section with a `[pdata]`-identified enclosing function (20+ such xrefs listed). The falsifier (dead resource) did not fire.
- **FACT:** Three switches exist: (1) a debug menu in `Navi.exe` with item `'2'` = `Simulation on/off` handled at `fn 0x003daf5c` and a 20-item event menu at `fn 0x004b9fa4` that triggers `NAVI_ROUTE_SIMULATION_START/PAUSE/STOP`; (2) a persistent shop setting behind `OBJ_Setting_readShopDemo`/`writeShopDemo` (index 2) shown in the `[ Shop Setting ]` debug screen as `DemoRoute :%d` / `DemoVics :%d`; (3) a `MaintenanceCC.dll` COM automation interface with `StartSimlate` / `StopSimulate` / `SetSimSpeed`. The runtime demo flag `u16 0x00bcd208` gates `RGD_DEMO_Start` (`fn 0x005182e0`).
- **OBSERVED:** The position-feeding path is `RGD_DEMO_*` in `Navi.exe` (`RGD_DEMOSrch.GetSkipPoint`, `RGD_DEMO.Dest.Get`, `RGD_DEMO.Jmp`, `RGD_DEMO.Ferry.Get`) plus `CRouteSimulation` in `NaviRouteCC.dll` (`ControlRouteSimulation`, `ChangeRouteSimulationStatus`, `SetNoResponse`). The strings say the demo computes skip points and a destination from the map and drives guidance with them.
- **HYPOTHESIS:** Triggering `NAVI_ROUTE_SIMULATION_START` (or setting the demo flag/starting `RGD_DEMO`) under `-M ze0` will produce a moving position with no GPS/CAN model. This is an L4 experiment, not proven here.
- **UNKNOWN:** Which physical key sequence or service-menu path reaches `fn 0x003daf5c` in the retail build; the runtime value written to `0x00bcd208` by the shop setting; whether simulation needs the absent audio microcontroller/CAN input; the exact `iSimulationType` values accepted by `ControlRouteSimulation`.

## Conclusion

Verdict **present**. EU 2011 and US 2011 both carry a demo/route-simulation subsystem with code-referenced strings, three candidate switches and a position-feeding code path; the falsifier (a string with no code reference) did not fire, so the strings are not dead resources. Ten claims C-7180–C-7189 register the census, the menu, the flag, the position-feeding functions, the shop setting, the maintenance interface and the verdict. A follow-up task (M8.H72) is added to try the trigger under the ze0 emulator and obtain a moving position at L4. No tool change and no format-doc change in this static search.
