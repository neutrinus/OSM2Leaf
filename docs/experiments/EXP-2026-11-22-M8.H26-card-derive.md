## Question

Can the four inputs that a `-M ze0` card boot used to receive by hand
(`--verinf`, `--mapdb`, `--ipl-patch`, `--sd`) be derived from the card image
itself, so that one `run.sh --card IMG` command boots to the same stage as the
hand-built command of EXP-2026-11-22-M8.C1c without writing the card?

## Hypothesis

Yes. `HDD_INFO.TXT` line 1 supplies the map code, line 3 positions 5–7 supply
`MapDBVer`, line 4/5 and the FAT label identify the build, the MBR supplies
the FAT offset, and the patch/overlay are pure functions of the card bytes
(C-6881, C-7200). **Falsifier:** for the same card the derived values differ
from the hand-used `verinf QSD-302-100` / `mapdb 16-16` of EXP-2026-11-22-M8.C1c,
the `--card` boot stops at a different stage than the hand-built boot, or
`describe` prints the same values for the EU and US heads.

## Method

1. **Sample and hash.** The five images above, hashed with `sha256sum` and
   re-printed by `tools/ze0_card.py describe` (the tool hashes the whole file
   unless `--no-hash` is given). The synthetic cards are written by
   `mkcard.make_synthetic_image` + `mkcard.mkcard` in a temp directory and
   contain no vendor bytes.
2. **Commands.**
   ```bash
   python3 tools/ze0_card.py --selftest
   python3 tools/selftest.py --only ze0_card
   python3 tools/ze0_card.py describe archive/head256.img
   python3 tools/ze0_card.py describe archive/us256.img
   python3 tools/ze0_card.py describe archive/eu2014-256.img
   python3 tools/ze0_card.py describe archive/eu2016-256.img
   Q=/home/marek/.cache/qemu-ze0/build/qemu-system-sh4
   bash tools/qemu-ze0/run.sh --card archive/head256.img --machine ze0 --qemu "$Q" \
        --icount shift=0,sleep=off --timeout 150 --workdir Wc --log /dev/null --no-summary
   mkdir -p Wh Wc
   python3 tools/ze0_ipl.py patch archive/head256.img -o Wh/ipl.txt
   python3 tools/qemu-ze0/mkoverlay.py archive/head256.img Wh/card.qcow2 --size-gib 8
   bash tools/qemu-ze0/run.sh --image archive/head256.img --sd Wh/card.qcow2 \
        --verinf QSD-302-100 --mapdb 16-16 --ipl-patch Wh/ipl.txt --machine ze0 --qemu "$Q" \
        --icount shift=0,sleep=off --timeout 150 --workdir Wh --log /dev/null --no-summary
   python3 tools/ze0_sdhost.py serial Wc/serial.log
   python3 tools/ze0_sdhost.py serial Wh/serial.log
   sha256sum archive/head256.img
   CARD=archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img
   mkdir -p Whf Wfc
   python3 tools/qemu-ze0/mkoverlay.py "$CARD" Whf/card.qcow2 --size-gib 8
   python3 tools/ze0_ipl.py patch "$CARD" -o Whf/ipl.txt
   bash tools/qemu-ze0/run.sh --card "$CARD" --machine ze0 --qemu "$Q" \
        --icount shift=0,sleep=off --timeout 330 --workdir Wfc --log /dev/null --no-summary
   bash tools/qemu-ze0/run.sh --image "$CARD" --sd Whf/card.qcow2 \
        --verinf QSD-302-100 --mapdb 16-16 --ipl-patch Whf/ipl.txt --machine ze0 --qemu "$Q" \
        --icount shift=0,sleep=off --timeout 330 --workdir Whf --log /dev/null --no-summary
   python3 tools/ze0_sdhost.py serial Wfc/serial.log
   python3 tools/ze0_sdhost.py serial Whf/serial.log
   sha256sum "$CARD"
   bash tools/qemu-ze0/run.sh --card archive/head256.img --machine ze0 --qemu "$Q" \
        --verinf CUSTOM-123 --mapdb 5-9 --workdir Wdry --dry-run
   ```
3. **Controls.** *Positive:* the EU 2011 head must derive `verinf QSD-302-100`
   and `mapdb 16-16`, the values used by hand in EXP-2026-11-22-M8.C1c runs
   W/X/Y; the full-card `--card` boot must reach `applch_error 0` and
   `failsafe_start 0` (run-W stage). *Negative:* the US head must derive a
   different `verinf` and build name; the 2014/2016 heads must classify
   `other` with different `mapdb`; a synthetic non-2011 card classifies
   `other`; `--no-ipl` leaves no patch file; `materialize` leaves the card
   SHA-256 unchanged; explicit `--verinf/--mapdb` must override the derived
   values in the dry-run command line.
4. **Scope.** Four 256 MiB card heads and one full 7.5 GB EU 2011 card; the
   whole `HDD_INFO.TXT` (72 bytes) and the first partition's MBR entry; 16
   synthetic assertions in `ze0_card.py --selftest`, one discovered selftest
   suite; two 150 s and two 330 s `-M ze0` boots. Excluded: firmware code
   searches, other years' full cards, L5 (hardware unavailable).
5. **Falsifier.** Any derived value that disagrees with the hand-used one on
   the same card, a different marker count/stage between `--card` and the
   hand-built boot, or identical EU/US derive output.

## Interpretation

- **FACT (C-7230, C-7233):** `describe` derives the run inputs from
  `HDD_INFO.TXT` (the FAT file when the partition is inside the image, else
  the byte-identical 72-byte copy at `0x06000000`) and the MBR, and on
  `archive/head256.img` prints the hand-used `verinf QSD-302-100` /
  `mapdb 16-16`, `build EU2011`, `FAT offset 0x6400400` (O1).
- **FACT (C-7231, C-7232):** EU and US heads differ in `verinf` and build
  name; 2014/2016 heads classify `other` and derive different `mapdb`
  windows, so the classifier can fail loudly (O1).
- **FACT (C-7234, C-7239):** `run.sh --card` materializes the overlay and
  IPL patch into the work directory, passes the derived options to QEMU and
  lets explicit options override them (O3).
- **OBSERVED (C-7235, C-7236):** the `--card` boot and the hand-built boot
  reach the same stage with identical marker counts, and neither card image
  changes (O4, O5).
- **FACT (C-7237, C-7238):** the synthetic selftest (16 checks) and its
  `tools/selftest.py` discovery both pass (O2). The full-suite failures are
  host `/tmp` ENOSPC and two 60 s timeouts, shared with pre-existing tools.
- **UNKNOWN:** the real unit's map-DB window bounds are still unknown
  (C-2087); the derived `V-V` window is the least-slack window that passes
  the launcher check, not a reading of a unit record.

## Conclusion

`tools/ze0_card.py describe IMG` derives map code, map-DB window, build name
and FAT offset from a card image; on the EU 2011 head it reproduces the hand
values used in EXP-2026-11-22-M8.C1c and it separates EU from US. `run.sh
--card IMG` calls `materialize` to build the qcow2 overlay and IPL patch in
the work directory, passes the derived `verinf`/`mapdb`/`--sd`/`--ipl-patch`
to QEMU and reaches the same boot stage as the hand-built command without
writing the card. The tool is covered by a synthetic `--selftest` discovered
by `tools/selftest.py`. Still open: a US full-card boot and the real unit's
map-DB bounds.
