## Method

1. Generate memmap JSON for build A and B (full, and `--exclude-compressed`):
   - `python3 tools/cerom.py --image-start 0x200200 /tmp/opencode/img256.img memmap --out /tmp/opencode/memmap-a-full.json --pretty`
   - `python3 tools/cerom.py --image-start 0x200200 /tmp/opencode/img256.img memmap --exclude-compressed --out /tmp/opencode/memmap-a.json --pretty`
   - `python3 tools/cerom.py --image-start 0x3e00200 /tmp/opencode/img256.img memmap --out /tmp/opencode/memmap-b-full.json --pretty`
   - `python3 tools/cerom.py --image-start 0x3e00200 /tmp/opencode/img256.img memmap --exclude-compressed --out /tmp/opencode/memmap-b.json --pretty`
2. Run `rommap.py convert --report <memmap> --skip-compressed --module <name> --out <out>` then `rommap.py validate <out>` for every module in A and B (per-module: multiple EXEs share preferred VA `0x11000`, so a combined all-modules map overlaps).
3. Record counts per module from the full memmap JSON.

## Interpretation

- `cerom.py memmap` on IMG256 lists every A (149 modules, 527 sections) and B (91 modules, 307 sections) section with VA/file_offset/size/vsize/flags and compressed marking (C-1630).
- `rommap.py convert --skip-compressed` + `validate` **pass per module** for 239/240 A+B modules (C-1631). The only failure is B `nk.exe` sec1, a zero-stored-size BSS section (`CNT_UNINITIALIZED_DATA`, file_offset null, vsize 7168) that `rommap.py` rejects as `size must be positive` — a rommap size/representation limitation on this BSS form, recorded (C-1632). Not a compressed-section issue.
- A combined all-modules map cannot pass `rommap.py`'s overlap validation because EXEs share VA `0x11000`; this is inherent non-co-resident EXE address spaces, not a data error (C-1633). Per-module maps are the meaningful L3/Ghidra unit.
