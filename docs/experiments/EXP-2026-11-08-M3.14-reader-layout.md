## Question

Which VAs in build A read `ZCODE0nn`, `ICODE001` and `COORD001`, and which record
fields does each reader use (M3.14 done-when)?

## Hypothesis

The name strings are in plain `Navi.exe` sec0 data (`0x00179338` id table,
`0x0017933c` `ZCODE0`), so a literal-pool load of each name from plain code
should locate its opener, and the record reader is reached from that opener.

Falsifier: a `mov.l @(disp,PC)` load of the ZCODE0 or COORD001 name VA from
plain code, or of the id-table base, that leads to a function whose body in
plain bytes parses the file. Each family is tested and its result stated; the
M3.14 `Stop:` rule (two signature families fail, then `blocked`) applies.

## Interpretation

- **FACT:** The three name strings are ASCII in plain `Navi.exe` sec0 data and
  the probe's positive control passes (C-2190, C-2191, C-2192).
- **OBSERVED:** `ICODE001.DAT` is loaded by `fn 0x003f2cc0` (`0x003f2d70`). That
  function calls the volume lookup `0x0040b358` and six plain callees. It is the
  candidate opener for ICODE001; the record reader is not in it, and the callees
  were not decoded further in this EXP (C-2194).
- **OBSERVED:** `ZCODE0` (`0x0017933c`) is a word in four literal-pool slots
  (`0x00179328`…`0x00179334`) that `sh4xref.py` does not connect to any `mov.l`
  load. Either the slots are data read by index or the loader is outside the
  tool's prologue heuristic. The id-table base has no load (C-2193, C-2196).
- **FACT (negative with control):** `COORD001.DAT` (`0x00178e18`) has no
  plain-code literal load, and `ZCODE0` has none either. The method finds the
  ICODE001 load on the same run, so the absence is not a blind method (C-2195).
- **FACT:** Executable bytes are plain (sec0 only). The two compressed sections
  are not executable and hold no code by flag (C-2197). The M3.15 finding that
  calls reach sec1 (C-2206) is not re-tested here.
- **HYPOTHESIS:** The table-driven ZCODE and COORD readers sit behind the same
  shared compressed helpers as LCTBL (C-2199). Not tested; M1.2f would make sec1
  readable and test it.
- **UNKNOWN:** The record reader VA per file, and which fields each one uses.

## Conclusion

Done-when not met: `coord-zcode-icode.md` gets no reader VA for ZCODE0nn or
COORD001, and for ICODE001 only the opener `fn 0x003f2cc0` (C-2198). M3.14 is
`Status: blocked`, `Unblock: M1.2f`. The rule-14 `Stop:` (two signature families
fail) is reached for ZCODE0 and COORD001: families tested are direct literal-pool
loads of the name VA and loads of the id-table base. The format page gains a
short status note (not a layout change). Open: the record reader VA for all three
files; the ZCODE0 table consumer; the opener's callee tree.
