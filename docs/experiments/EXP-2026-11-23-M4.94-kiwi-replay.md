## Question

Can an agent re-run every KIWI +/- verdict of M4.67/68/69/70/72 from the repository plus an extracted card tree (or the card image), getting the same per-tile table the EXP quotes, without changing a check or a verdict?

## Hypothesis

Yes: the four committed probes already contain the check functions, so a thin source flag that resolves `--tree`/`--card` + `--tile` and prints an EXP-pinned `REPLAY` line should reproduce the quoted numbers while leaving the ordinary CLI byte-identical. **Falsifier:** a probe prints a different fit count on an unchanged factory tree while the printed SHA-256 equals the EXP SHA, or any pre-existing subcommand output changes by one byte, or a `--selftest` goes red.

## Interpretation

- **FACT:** All five quoted verdicts replay byte-for-byte from the factory trees: 0/4 checks, 0/6,000 road fits, 17,659 background records, `r=0.1035` over 130,212 links, and the 45-tile mesh list. Each `REPLAY` line carries the EXP's own SHA-256; the two 289 MB EU/US road tiles and the EU route tile print exactly the hashes quoted in the source EXPs.
- **FACT:** The nine vendor-free subcommand outputs are byte-identical before and after the patch and all four probe selftests stay green, so no check, verdict or selftest was changed — only a source-resolution path was added.
- **FACT:** Input identity is a hard falsifier: a one-byte mutant tile prints a different SHA and exits 1, and three wrong-source `--card` runs fail with named errors and no `OK` line.
- **OBSERVED:** A full EU2011 image is present at `archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img`; reading one file's cluster chain makes a positive `--card` replay cheap, and all five controls reproduce. The round-1 note that "no full EU2011 image exists" applied to the 256 MiB heads, not to `archive/sd-images/`; the 256 MiB heads indeed cannot replay. This is recorded as an additional positive control, not as the basis for Done when.
- **FACT (correction to M4.68):** the command `python3 -c "print((2/3)/1024*3600, (2/3)/1024*3600*8, (2/3)/1024/512*3600, (2/3)/1024/512*3600*8)"` prints `2.34375 18.75 0.00457763671875 0.03662109375`, not the `1.953125 15.625 0.0038147 0.03052` quoted in EXP-M4.68's Observations/Interpretation. Since 2/3° = 2400″ and one packed unit is 1/1024 of that (2400/1024 = 2.34375″), the EXP's packed/fine values are superseded by the command's output; the coarse values (19,200/28,800/153,600/230,400) stand. The M4.68 `## Reproduction` line now carries both the command and the correction. No verdict changes: the fine units are still non-integer in KIWI 1/8-arcsecond units (18.75 per packed unit, 0.0366 per POI fine step).
- **UNKNOWN:** a real KIWI disc (M4.77) is still the only positive control for the KIWI side of those negatives; no format field or firmware VA was added or attributed.
