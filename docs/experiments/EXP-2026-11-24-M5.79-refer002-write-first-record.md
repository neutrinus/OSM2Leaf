## Question

Can one new charging-station record, named after a synthetic OSM
`amenity=charging_station`, be added to a factory `REFER002/POINT016.DAT` so
that `refer002_census.py` reads it back and the factory tree still passes L1
and L2 — without changing any record length, field length, index row or
position word?

## Hypothesis

Yes: `REFER002` is a plain `.DAT`, its 15 shards hold only tag-`0x60`
facility records, and the 11-field dictionary places `facility name` at
`rec[68:88]`; a verbatim 114-byte record clone with only those 20 bytes
replaced (equal length) keeps every length and offset stable, so the census
counts one more record and no index needs an update. Falsifier: any length
byte, field boundary, index row or byte outside the single zlib page changes;
the census fails to read the new name; L1 or L2 fails; or the factory encoder
control cannot reproduce the original inner stream byte-for-byte.

## Method

### 1. Sample and hash

The input and output SHA-256 above come from `sha256sum` on the exact files;
the 24-byte index row before and after is quoted in O4. All counts below are
printed by the commands in (2) on those bytes.

### 2. Commands

```bash
S=/home/marek/projekty/leafre-work/scratch/m5.79
F=/home/marek/projekty/leafre-work/m5.4/card-factory
Z=/home/marek/projekty/leafre-work/scratch/m5.63-verify/zlib-1.3.1/libz.so.1.3.1

    --page 0x1a00 --name "OSM2LEAF CHARGING ST" --libz "$Z" --json "$S/add.json"

### 3. Controls

*Positive*: `refer002_census.py --selftest` passes 12 checks; the edited tool's
17-check synthetic selftest passes; `tools/selftest.py --only` reports
`tool:refer002_add_station PASS`; stock zlib 1.3.1 reproduces the original
112-B stream byte-for-byte (the tool refuses otherwise); the factory census
is 16 files / 880 records before and 881 after, and the new name is read back
verbatim; `cardcheck` and `l2check` PASS.

*Negative*: corrupting the cloned record's `len2` byte (114 → 115-byte record)
makes `walk_records` return **1** record instead of **2** (M5.52/C-5117 defect
class); a name whose byte length is not exactly 20 is refused with "exactly";
running without `--libz` is refused with `stock zlib 1.3.1 is required`; and
`cmpind.py verify` on a REFER002 tree errors with `no .ind files` (this layer
is plain `.DAT`, not a pair).

### 4. Scope

EU2011 `REFER002` only, one shard (`POINT016`), one added record and one
synthetic OSM station name. 15 POINT shards / 880 factory records were walked
to verify that all are tag `0x60`; the census covers all 16 files. Excluded:
the other 43 REFER001 shards, US/2014/2016 cards, the `INFORMATION`
subschema at `0x1b00` (unchanged), the 299-cell directory (unchanged), the
`0x1108` index stream (unchanged, see O4), L3/L4/L5 (row-24 opener not
located — M3.29), and any OSM coordinate write (body offsets UNKNOWN,
C-7866). The clone inherits the host's copy-A/fine words.

### 5. Falsifier

A changed length byte, index row, field boundary or byte outside `0x1a00`;
the census failing to count/read the new record; an L1/L2 failure; or a
factory-encoder control mismatch would refute the claim. The tool stops
before writing on all of those.

## Observations

O1. `refer002_census.py --selftest` prints `selftest: PASS` (12 checks);
`cmpind.py verify $F/REFER002` prints
`error: no .ind files in .../m5.4/card-factory/REFER002`. A census walk over
all 15 POINT shards prints `records 880 tags {'0x60': 880}`.
`field_layout(rec, 11)` on POINT016's record returns `loc=40`,
`starts[5]=68`, `lens[5]=10`, `starts[6]=88`, `lens[6]=11`, `end=114`:
field 5 = `LEASEPLAN LUXEMBOURG` (20 B), field 6 =
`7@RUE NICOLAS BROSIUS\0` (22 B); tag `0x60`, `len2=57`, 114 B.

O2. `refer002_add_station --selftest` prints
`refer002_add_station selftest: OK (17/17 checks)`; `selftest.py --only`
prints `tool:refer002_add_station  PASS`. The real edit prints:
```
page 0x1a00: records 1 -> 2; inner 114 -> 228 B
name 'LEASEPLAN LUXEMBOURG' -> 'OSM2LEAF CHARGING ST' at rec+0x44 (20 B)
stream 112 -> 137 B (limit 256); index 1 -> 1 row(s)
encoder 1.3.1 (ctypes .../libz.so.1.3.1); logical size unchanged: 7680 B
```
`add.json` records `position: inherited from host (no OSM coordinate written,
C-7866)`, encoder SHA-256 `3fb3376a…019` and `reference: true`.

O3. Before: `files 16  records 880  bytes 426496`. After:
`files 16  records 881  bytes 426496`. `record` on the edited POINT016:
```

@0x1a00 tag=0x60 bytes=114 text=b'\x02\x11OSM2LEAF CHARGING ST7@RUE NICOLAS BROSIUS'

Both records are 114 B with `len2=57`; the new name is field 5 only.

O4. Index audit table (all bytes quoted from the before/after files):

| Structure | Before | After | Changed? |
| --- | --- | ---: | --- |
| census records (POINT016) | 1 | 2 | yes (intended) |
| census records (tree) | 880 | 881 | yes (intended) |
| `0x1108` index stream | 24 B = 1 row | 24 B = 1 row | no |
| index row bytes | `000f0002000100060002ffff02110077ffff3f0000000000` | identical | no |
| 299-cell directory at `0x800` | cells `0x824`/`0x82a`/`0x85a` | identical | no |
| `len2` of both records | 57, 57 | 57, 57 | no |
| field-5 length byte | 10 words | 10 words | no |
| name page inner | 114 B | 228 B | yes (intended) |
| changed `.DAT` bytes | — | 30, all in `0x1a00..0x1a88` | confined to slot |

The index is **one 24-B row per record** (verified on all 15 shards: `idx
bytes / 24 == records`), so POINT016's single 24-B row encodes the count as
its length; after adding a record the row count is still 1. The falsifier
(census +1, stale count field) does not fire because there is **no separate
count field** in this layer — the index stream length *is* the count, and it
was not changed. This is a documented limitation, not a complete EV index
writer: the new record is present and named but has no new index row.

O5. L1 `cardcheck.py --root $S/tree`: `[tree] OK (files=480, dirs=39,
bytes=5173965667)`, `[cmp] OK (pairs=194, ...)`, `[drstr] OK`,
`[mmain] OK`, `RESULT: PASS`. L2 `l2check.py --root $S/tree --no-tiles
--cmp-limit 20`: `[files] OK (expected=17)`, `[cmp_roundtrip] OK (pairs=20)`,
`[refer_mutation] OK`, `[refer_rename_resize] OK`, `RESULT: PASS`.

O6. Negative: the edited page walks to 2 records; after `len2+1` on the
clone it walks to 1. A 21-byte or 19-byte name is refused; no `--libz` is
refused before reading the file.

## Interpretation

- **FACT:** one verbatim 114-byte tag-`0x60` record with an exactly 20-byte
  field-5 name swap can be appended to POINT016's inner page; the census
  reads 1 → 2 records and 880 → 881 tree-wide, L1 and L2 pass, and the only
  changed `.DAT` bytes (30) lie inside the `0x1a00` stream slot.
- **FACT:** no record-length byte, field-length byte, position word, index
  row or directory cell needed changing; the 24-B-per-record index has no
  separate count field (O4).
- **OBSERVED:** the manufacturer index stream still has one row while the
  census now sees two records. The task's falsifier is therefore avoided by
  the *absence* of a count field, not by a count update; a complete EV writer
  must add an index row (new M4 task).
- **UNKNOWN / HYPOTHESIS:** the OSM node's real position is not written —
  body offsets are C-7866; the clone inherits the host's copy-A/fine words.
  No L3/L4/L5 result is claimed (M3.29 opener not located; rule 13).
