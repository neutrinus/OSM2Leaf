## Question

What is in each region of the unit's 8 MiB flash, and does the unit run its
kernel from the card (C-5192) or from flash?

## Hypothesis

C-5192: flash is too small for the OS, so normal mode runs images A and B
from the card and the flash holds only a boot loader, `PROD` and user data.

Falsifier: a CE image in flash whose ROM header chains with card image A
(RAM end = start of A, DLL ranges that abut), while card B does not chain.

## Method

1. **Sample and hash.** As above. PIN (`0xA060`, `0xA100`) and serial bytes
   are never printed; `unitflash.py prod` masks them.
2. **Commands.**

   ```bash
   python3 tools/unitflash.py --selftest
   python3 tools/unitflash.py map DUMP
   python3 tools/unitflash.py images DUMP
   python3 tools/unitflash.py prod DUMP
   python3 tools/unitflash.py stores DUMP
   # controls for the image scan: a card slice with a known image, a card slice without
   python3 tools/unitflash.py images US --offset 0x3e00200 --length 0x800000
   python3 tools/unitflash.py images US --offset 0x6400000 --length 0x800000
   # the flash kernel as a CE image, and the card images it could chain with
   python3 tools/cerom.py --image-start 0x40000 DUMP romhdr
   python3 tools/cerom.py --image-start 0x40000 DUMP modules
   python3 tools/cerom.py --image-start 0x40000 DUMP files
   python3 tools/cerom.py --image-start 0x200200 US romhdr
   python3 tools/cerom.py --image-start 0x3e00200 US romhdr
   python3 tools/cerom.py --image-start 0x200200 EU64 romhdr
   xxd -s 0x200016 -l 12 US; xxd -s 0x200016 -l 12 EU64; xxd -s 0x6000000 -l 16 US
   grep -a -o "Navi Version : [A-Z0-9-]*" DUMP
   # launch table and the product-record reader of the flash kernel
   python3 tools/applaunch_table.py --image-start 0x40000 DUMP dump
   python3 tools/applaunch_table.py --image-start 0x40000 DUMP select --area 0x20 --name Navi.exe
   python3 tools/applaunch_table.py --image-start 0x40000 DUMP select --area 0x30 --name Navi.exe
   python3 tools/sh4xref.py DUMP nk.exe --image-start 0x40000 --to 0x01013208
   python3 tools/sh4xref.py DUMP nk.exe --image-start 0x40000 --to 0xa000a000
   python3 tools/sh4dis.py --image-start 0x40000 DUMP nk.exe --va 0x880485d4 --count 60
   python3 tools/sh4dis.py --image-start 0x40000 DUMP nk.exe --va 0x88048724 --count 60
   strings -n 5 DUMP | grep -E "^(IP|BS|EB|EH|OI|PS|UP|UE|W1|X1|W2|X2|PM|UT)FFFFFF.FFF$"
   strings -n 8 DUMP | grep -E "BOOTIPL|BOOTENHN|SUBTEST.pdb|Built Dec|NORMAL\(|SST(64|16)\(num"
   ```
3. **Controls.** Positive: the image scan on 8 MiB of the US card from
   `0x3E00200` must find exactly `UP10XXXX.500` with a valid `+0x30` sum.
   Negative: the same scan on 8 MiB of the card's FAT area (`0x6400000`) must
   find nothing; one flipped byte must break the sum (selftest). For the
   chain: card B is the image that must *not* fit.
4. **Scope.** All 135 blocks of the dump. Code read: two functions of
   `nk.exe` in the flash kernel. Not decoded: record formats of SRAM and
   VFlash, the boot loaders' control flow, `SUM4`.
5. **Falsifier.** As in Hypothesis.

## Interpretation

- **VERIFIED (C-5210):** the flash holds six images with valid header sums:
  IPL, BASE, EBOOT, ENHANCE, the kernel `X110NBNI.147` and the sub-test
  program (O2).
- **VERIFIED (C-5211):** the image header fields (`+0x20` label, `+0x30`
  byte sum, `+0x32` size, `+0x50` part number, `+0x60` `VerInf`, `+0x70`
  map-DB window, `+0x80` `SUM4` record); the byte-sum rule holds 7 of 7 and
  fails on a flipped byte.
- **VERIFIED (C-5212):** flash `X1` and card A are one system: `X1`'s RAM
  ends where A starts, `X1`'s DLL range starts where A's ends, the labels
  pair (`X1…NBNI.147` / `X2…NBNI.147`), and the unit's crash report names
  `X110NBNI-147` while running modules of A. Card B fails the same test: its
  DLL range overlaps A's and its RAM runs through A (O3, O4).
- **C-5213, verdict on C-5192:** half right. The applications (A, 24 MB) do
  run from the card. The kernel does not: normal mode runs the 2.9 MiB kernel
  in flash. Card B and C are for update and test mode. C-5192 is REFUTED as
  written and replaced by C-5213.
- **VERIFIED (C-5214):** `VerInf` and the map-DB window are constant header
  bytes of the flash kernel (inside its summed range): `QSD-301-100`,
  16..16. `QSD-301-100` is line 1 of the US card's `HDD_INFO.TXT`. The
  "written at boot by the IPL" hypothesis of C-6882 is not needed.
- **VERIFIED (C-5215):** the Target ID is `PROD +0x20..+0x23`, read by the
  kernel from flash at `0xA000A000`; the area byte is flash `0xA021`
  (`0x20` here). C-5201 becomes VERIFIED; C-078 (`0xA022`) is RETRACTED.
  Flash is at physical 0.
- **VERIFIED (C-5216):** the launch table that runs in the car is the one in
  flash. It starts `\windows\Navi.exe` for USA and for Euro through two
  records with the same path, and loads A through the `NK2` record.
- **OBSERVED (C-5217):** user data: four doubled `SMST` stores with
  generation counters in SRAM, a headerless VFlash with personal data, the
  `ASLG` crash log, the `VEUP` record.
- **OBSERVED / HYPOTHESIS (C-5218):** the EU card's image A has the same
  `physfirst` and `dlllast` as the US one, so it fits the US unit's kernel by
  address. Acceptance was unknown from this dump alone; M8.C1r found the
  build-name compare that refuses it (C-8401).
- **OBSERVED (C-5219):** the loader set and its vocabulary (O8). The order
  IPL → BASE → ENHANCE → kernel is a HYPOTHESIS from address literals.

**What follows for the region question:** an untouched EU card in this US
unit fails twice: the build-name compare (`X210ECNI.158` against
`X110NBNI.147`, C-8401) and `DIFFERENT MAP CODE` (`QSD-302-100` against
`QSD-301-100`). The map-DB window 16..16 accepts the EU card's value 16
(C-6884). Both compared values are on the card, so no flash write is needed;
M8.C1m/M8.C1r show the changed EU card starting in the emulator. On the real
unit this stays a HYPOTHESIS until a card test. The area stays USA:
`Navi.exe` starts either way, RDS and TMC drivers do not.

## Conclusion

`docs/hardware/unit-flash.md` is the new map. `docs/hardware/head-unit.md`
and `docs/research/us-eu-region.md` are corrected: the kernel is in flash,
`VerInf` is in its header, the market byte is `0xA021`. Claims C-5210–C-5219
added; C-5192 REFUTED (C-5213), C-5201 VERIFIED, C-078 RETRACTED, C-6882's
writer hypothesis closed by C-5214. Open: the `SUM4` formula, the EU
unit's kernel, the store formats.
