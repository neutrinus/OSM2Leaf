# EXP-2026-11-19-M1.33: committed commands for M1.22's census and relocated-body table

- **Status:** done

- **Sample:** `archive/head256.img` (EU2011 head, 256 MiB, SHA-256

## Question

Can C-3530–C-3532 (the EU2011/US2011 module census and the 12-row
relocated-body table of EXP-2026-11-17-M1.22) be re-derived from committed
commands, without the session script that first printed them?

## Hypothesis

The census is a set operation on `cerom.py modules` plus a SHA-256 over each
module's `MEM_EXECUTE` sections; the body table is a halfword compare after
zeroing the pool values that body loads point at. Both should print exactly
the M1.22 numbers. **Falsifier:** the committed census prints a module delta
other than C-3530 (only-EU `RDSCC.dll`; only-US `RBDS_CC.dll`, `XMCC.dll`,
`XMStatusCC.dll`; 148 common; 1 identical / 147 different), or one row of the
12-row table (body lengths, `NONE`) or the rewrite control (233/220, halfword
11) does not reproduce.

## Method

1. **Sample and hash.** The two 256 MiB heads above (first 128 MiB read by
   the census; the whole `Navi.exe` code section by `bodies`).
2. **Commands.**
   ```bash
   python3 tools/cerom.py --selftest
   python3 tools/fn_match.py --selftest
   python3 tools/cerom.py modules --census archive/head256.img archive/us256.img
   python3 tools/fn_match.py bodies archive/head256.img archive/us256.img \
     --fixture-rows tools/fixtures/fn_match_eu_us_2011.json \
     --negative 0x003fbed8:0x00424850
   python3 tools/cerom.py modules --census archive/head256.img archive/head256.img
   python3 tools/fn_match.py bodies archive/head256.img archive/us256.img \
     --pair 0x003f39c0:0x0041c370 --negative 0x003f5194:0x0041c370
   python3 tools/fn_match.py bodies archive/head256.img archive/us256.img \
     --pair 0x003fbed8:0x00424850
   ```
3. **Controls.** *Positive*: the EU head against itself must give 149 common,
   0 only-in-one, 149 identical; the US skip walker pair (EU2011 `0x003f39c0`
   → US2011 `0x0041c370`, from the dispatcher pools in the M1.22 EXP) must be
   identical. *Negative*: the known rewrite `0x003fbed8`/`0x00424850` must
   differ inside its body (both as `--negative`, exit 0, and as `--pair`,
   exit 1); the EU nth walker against the US *skip* walker
   (`0x003f5194`/`0x0041c370`) must differ inside the body. The selftests
   build synthetic module lists (common / only-A / only-B / identical /
   different / compressed-unreadable) and synthetic bodies (pool-value move
   = not a difference; opcode change, moved displacement, body-length change,
   no `rts` = difference).
4. **Scope.** Census: all modules of build A of both heads (149 EU2011, 151
   US2011), every `MEM_EXECUTE` o32 section, stored `psize` bytes; a
   compressed EXECUTE section would be counted as `unreadable`, never hashed
   (there are 0 in both builds). Bodies: 12 EU2011→US2011 `Navi.exe` pairs +
   3 control pairs, window 0x800 B from each body start. Not covered: the
   `fn_match match` verdicts (unchanged, C-3532's first half) and the L3 runs.
5. **Falsifier.** Stated in the Hypothesis.

## Interpretation

- **FACT:** `cerom.py modules --census` reproduces C-3530 and C-3531 exactly
  (148 common; only-EU `RDSCC.dll`; only-US `RBDS_CC.dll`, `XMCC.dll`,
  `XMStatusCC.dll`; 1 identical `atlce400.dll` / 147 different; 0 compressed
  EXECUTE sections in either build). The falsifier did not fire.
- **FACT:** `fn_match.py bodies` reproduces every row of the 12-pair table
  and the rewrite control; the controls separate (a same-source pair is
  `NONE`, two different walkers differ at halfword 0).
- **OBSERVED:** the past-body "first diff" index depends on the masking of
  bytes beyond the body; the 878 for the chunk engine came from a different
  (uncommitted) definition. It is not a verdict input: a past-body index only
  says the window agrees through the body end.
- **UNKNOWN:** which window/masking produced 878 and halfword 65; nothing
  depends on them.

## Conclusion

C-3530–C-3532 now cite committed commands (evidence cells updated); the
M1.22 Method block has no ellipsis (the POINT010 paths are a named
`US_REFER` variable) and gained the two new commands, plus a short M1.33 note
recording the two prose numbers that the committed definition does not
reproduce. New claims C-4230–C-4232.
