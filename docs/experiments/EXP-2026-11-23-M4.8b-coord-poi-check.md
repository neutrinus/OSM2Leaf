## Question

Does `coord.py`, given a real POINT name record's copy-A words and two masked fine fields, reproduce an independently known building position — and which longitude origin and tile-local scale does the result support?

## Hypothesis

The fine position model of C-2679, now implemented in `coord.decode_point_id` by M4.61 (tile origin 52736, 1/512 fine steps), should decode ≥ 10 discrete buildings to their Wikipedia/Wikidata coordinates with metre-scale error, while the legacy one-unit reading (bbox origin 52742) stays at kilometre scale. **Falsifier:** `refs` prints `VERDICT: FAIL` on the new table; `fine model` is not closer than the legacy reading in at least 8/10 rows; the swapped-fine or shuffled-reference control is as good as the real one; the new CLI disagrees with `point_census.fine_position` on any listed record; or fewer than 10 defensible building-level rows exist (then `blocked`, not a relaxed Done when).

## Method

1. **Sample and hash.** The two cards above; `sha256sum` in step 2 re-prints their hashes. `point_census.py extract` copies the 66 + 22 POINT `.cmp/.ind` files into `$W/eu` / `$W/us`; the concatenated hashes printed in step 2 match the sample. Already-extracted factory trees `/home/marek/projekty/leafre-work/m4.8b-eu/REFER001` and `/home/marek/projekty/leafre-work/m5.12-us/root-factory/REFER001` give the same `refs` output and were used as a cross-check. The new reference table `docs/experiments/EXP-2026-11-23-M4.8b-poi-refs-building.tsv` keeps the **exact eight tab-separated columns** `id, country, shard, stream_offset, record_index, ref_lat, ref_lon, reference` so `point_census.py refs --refs` runs on it unmodified; URL, retrieval date `2026-11-23`, Wikidata P625 precision and the building-level rationale are in `#` comment lines immediately above each row. Airport ARP, ship, park and estate-centroid references were rejected. Wikidata P625 declared precision (or the rounding of the Wikipedia decimal when P625 has no usable precision) is the uncertainty floor recorded in those comments; five of the 16 control titles have no Wikipedia coordinate today and several have P625 ≥ 1e-4 deg (~11 m), so precision is reported, not assumed. Defensible rows were counted **before** the run: 12.

2. **Commands.** Runnable in order from the repository root. `$W` is scratch in the home tree and is deleted after this EXP is written; `TMPDIR` is set short for tools that use sockets.

   ```sh
   cd /home/marek/projekty/OSM2Leaf
   W=$HOME/projekty/leafre-work/scratch/M4.8b
   mkdir -p "$W/eu" "$W/us"
   EU=archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img

   # negative control: rotate ref_lat/ref_lon in a COPY of the new table
   python3 - "$W" <<'PY'
   from pathlib import Path
   import sys
   w = Path(sys.argv[1])
   src = Path("docs/experiments/EXP-2026-11-23-M4.8b-poi-refs-building.tsv")
   lines = src.read_text().splitlines()
   hdr = [l for l in lines if l.startswith("#")]
   rows = [l.split("\t") for l in lines if l.strip() and not l.startswith("#")]
   refs = [(r[5], r[6]) for r in rows]
   for i, r in enumerate(rows):
       r[5], r[6] = refs[(i + 1) % len(refs)]
   out = w / "refs_shuffled.tsv"
   out.write_text("\n".join(hdr + ["\t".join(r) for r in rows]) + "\n")
   print(out)
   PY
   python3 tools/point_census.py refs --us "$W/us" --eu "$W/eu" --refs "$W/refs_shuffled.tsv"

   # reproducible name -> (shard, stream_offset, record_index) locator for the
   # four new POIs; selection aid only — all evidence numbers come from refs
   python3 - "$W/eu" <<'PY'
   import sys
   from pathlib import Path
   sys.path.insert(0, "tools")
   import point_census as pc
   import point_move_poi as pmp
   import point_pair_regen as regen
   DIR, TEXTS = Path(sys.argv[1]), ["BRANDENBURGER TOR", "DUOMO DI MILANO",
                                    "TORRE DI PISA", "KÖLNER DOM"]
   for shard, cmp_path, ind_path in pc.find_pairs(DIR):
       blob = pc.load(cmp_path, ind_path)
       chain = regen.chain_via_locator(blob, pmp.NAME_CHAIN)
       for page, _, inner in chain.pages:
           recs = regen.walk_records(inner)
           if recs is None:
               continue
           for ri, (off, size) in enumerate(recs):
               rec = inner[off:off + size]
               name = pmp.record_name(rec).upper()
               if any(t in name for t in TEXTS):
                   lat, lon = pc.fine_position(rec)
                   print(f"{shard}\t0x{page:x}\t{ri}\t{name}\t{lat:.6f},{lon:.6f}")
   PY
   ```

   `point_census.refs` takes `fine_fields(rec)` (`struct.unpack_from(">4H", rec, 2)`, both words masked to 11 bits, C-2678) and calls `coord.decode_point_id`, so the CLI and the census cannot disagree (C-6568). The `point` CLI accepts the **masked 11-bit** values printed by `fine_fields`; feeding a raw stored word (`0x800 | fine`) adds four packed units (~3 km) and is rejected by the CLI guard.

3. **Controls.** *Positive (known to exist):* `coord.py --selftest` prints `coord selftest: OK (27/27 checks)` here (the old C-6567 record says 22 and is not edited — outside this block); `point_census.py --selftest` prints `point_census selftest: OK`; `refs` on the unchanged 16-row table prints `rows: 16 … median 114.6 m … fine closer: 16/16` and `VERDICT: fine position model holds` (also EXP-2026-11-20-M4.27 lines 160–162). 4. **Scope.** The 44 POINT pairs of the EU 2011 and US 2011 cards (3,545,547,776 decoded bytes, C-2676), used only to address the 12 name records in the new table; 12 building-level references, 8 from the original 16 POIs and 4 new EU landmarks. ## Interpretation

- **FACT:** the 12-row table meets the written Done when: ≥ 10 POIs (12), decoded vs reference lat/lon and metre errors, an origin verdict, a local-scale statement, and `coord.py` selftest pins (27/27). No building-level or few-metres threshold was added to the Done when and none was used to declare `done`.
- **OBSERVED:** median 38.8 m, 10/12 ≤ 100 m, max 161.9 m; the fine model is closer than the legacy one-unit reading in 12/12 rows (median 3,706.7 m for the legacy). The three largest errors (P14 161.9 m, P20 103.1 m, P19 97.7 m) exceed their source precision floors, so each is reported with that floor rather than treated as a decoder accuracy figure.
- **OBSERVED:** longitude origin. The point-id form uses 52736: P08 decodes to -81.755096 against a reference of -81.75500, while the same copy-A word read with the bbox origin 52742 gives -81.804688 (about 4 km west); the selftest pins `point=52736, fine=512, bbox=52742`. This agrees with C-2679 and C-6563.
- **OBSERVED:** local scale. All 12 decoded positions are inside 0..2047 at both `--local-scale 1` and `--local-scale 2` (12/12 each), so POINT fine records do **not** discriminate the 1-vs-2 tile-local hypothesis. `coord.py` keeps scale 2 as the firmware-bound hypothesis; the point-id form itself is a global packed coordinate and does not depend on that scale.
- **HYPOTHESIS:** the residual spread (9.8–161.9 m) is dominated by reference precision and by the exact point the POI record stores (entrance, gate, tower) rather than by the fine-position formula; M4.28's entrance-vs-centroid question remains separate.
- **UNKNOWN:** the firmware code that converts (copy A, fine) to map units has not been located (M3.34); these results are structure plus an external reference fit, not a firmware (rule 13) reading.

## Conclusion

`tools/coord.py` gains a `point` CLI that delegates to the M4.61 decoder with the masked-fine contract documented in its help, and its selftest now pins origin 52736, 512 fine steps and five real POI records (27/27 checks). The new `docs/experiments/EXP-2026-11-23-M4.8b-poi-refs-building.tsv` supplies 12 building-level, non-OSM references; `refs` reports median 38.8 m, 10/12 ≤ 100 m, 12/12 closer than the legacy reading, with shuffled and swapped controls failing as required. The origin verdict is 52736 for POINT fine ids and 52742 for `COORD001`/`ADDRE` bboxes; local scale 1 vs 2 is not decidable from these records and `coord.py` retains scale 2. No format document changed; the claim rows C-9940–C-9949 record the measurements. Still open: the firmware reader (M3.34) and the residual/question of entrance vs centroid (M4.28).
