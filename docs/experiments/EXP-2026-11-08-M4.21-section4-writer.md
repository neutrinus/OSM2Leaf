- **Claims:** C-2390–C-2399

## Question

Can `tools/section4.py build` (which refused exit 3) produce a section-4 payload
for a changed parcel set that `verify` accepts and that is safe to use in a
generated tile?

## Hypothesis

Patch mode (overwrite only the documented u16 fields, keep all other bytes —
including 0x06..0x0f and the name area — verbatim from `payload_hex`) can rebuild
any parsed record, including records with names, without inventing unknown bytes.
For brand-new parcels with no source record, the nameless 56-byte factory template
(sec4_write / REPORT-section4-build.md) is the established generated-tile form.
M3.6 found no section-4 read in MAP_DATA/RGD_DATA/shared loader paths, so the
nameless/template form is safe for the traced render/router paths (a control for
the task's OR clause).

## Interpretation

- **FACT (tool):** `section4.py build` no longer refuses (exit 3) on parsed
  records with names when `payload_hex` is present; it patches only documented
  u16s and preserves 0x06..0x0f/names/opaque, so changed parcel/country
  assignments for an existing record set work without inventing unknown bytes.
  Unchanged builds are byte-identical to the source payload.
- **FACT (tool):** `generate` writes a verify-accepted nameless section-4 payload
  for an arbitrary changed parcel set (template records). `verify` accepts on
  EU2011/2014/2016 B30R048R payloads and on generated payloads.
- **VERIFIED (real, partial L2):** Payload-level build+verify and name/unknown-byte
  preservation hold on EU2011/2014/2016 B30R048R samples; EU2011 factory l2check
  baseline passes and harness round-trip passes on extracted 2014/2016 tiles.
  Full `l2check --root` on 2014/2016 with a regenerated section 4 in a complete
  extracted tree was not executed in-session (complete trees not present in
  writable scratch) — a residual integration check, not a format failure.
- **FACT (control, M3.6):** No section-4 read in traced render/router/loader paths
  (107 fns, Navi.exe build A); tiles without section 4 exist and EU2011 factory
  l2check passes. Nameless template/omission is safe for those paths; a reader
  outside the traced graph remains UNKNOWN (C-2393).
- **HYPOTHESIS:** `TEMPLATE56` undocumented bytes (0x06..0x0f = `0013 ffff0000
  ffff0000`, tail constants, last word 0) are accepted wherever sec4_write’s
  56-byte nameless form is accepted (OBSERVED on B68R058R/B50R060R via
  sec4_write); real named records use different 0x06..0x0f values.

## Conclusion

`section4.py build` works: patch mode preserves all unknown bytes (including
names and 0x06..0x0f) and only patches documented fields; `generate` produces a
verify-accepted nameless payload for a changed parcel set. `verify` accepts on
EU2011/2014/2016 samples, EU2011 factory l2check baseline passes, and M3.6
provides the no-reader control (section 4 untraced in render/router paths; tiles
without it pass). Full-root l2check on 2014/2016 regenerated tiles needs complete
extracted roots (documented). The nameless-template undocumented bytes remain
OBSERVED (sec4_write convention), preserved verbatim in patch mode.
