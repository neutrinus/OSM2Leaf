## Question

Can `mkcard.py` build a card from a tree with one changed file on top of the
factory image, so that the output differs from the factory only in that file's
clusters and its directory entry, while an unchanged tree still gives a
byte-identical image?

## Hypothesis

Same-length change: yes, the chain writer touches only the file's clusters
(16 bytes of payload differ) and leaves the directory entry alone (size,
cluster and timestamps are unchanged). Resize: the file's own clusters, FAT
links and directory entry change as in `imgpatch.py`, but cardcheck also
requires the DRSTR001.DAT entry values (file sizes and directory totals) to
follow the resize, so DRSTR must be rewritten too; the expected extra diff is
only those value bytes and DRSTR's own chain.

**Falsifier:** (a) a diff range outside the changed file's chain clusters, its
32-byte directory entry, its FAT links and FSInfo (resize only), or the DRSTR
value bytes and DRSTR chain; (b) a cardcheck FAIL on a reconciled image; (c) an
unchanged-tree build that is not byte-identical to the factory image.

## Inputs

| Item | Value |
| --- | --- |
| Image / file (same) | US `XMD/ltntbl.dat`, 320 B, 1 cluster; EU `TMC/reception.dat`, 208 B, 1 cluster |
| Image / file (grow) | US `XMD/ltntbl.dat` 320 → 384 B; EU `TMC/reception.dat` 208 → 272 B |
| Change content | same-length: 16 bytes `Z` at offset 100; grow: the factory bytes + 64 random bytes (XMD/TMC files are not content-checked by cardcheck) |
| Offset(s) | US: 16 B diff at `0x13bc25464` (`ltntbl` cluster); EU: cluster at `0x7a3e5400`, 16 B diff at `0x7a3e5464` |
| Tool / version | `tools/mkcard.py` at this branch; `tools/imgpatch.py` `patch_image`; `tools/cardcheck.py` |
| Repo tool | `tools/mkcard.py --reconcile` (the CLI used for the full-copy runs) |

## Method

1. **Sample and hash.** As in Sample. The EU hash was computed with
   `sha256sum` and equals `leaf2011.img` in `AGENTS.md`. The test trees were
   made with `cp -al` from the factory trees; each changed file was replaced with
   `cp --remove-destination` so the factory inode is never written (the factory
   files keep their 7316 / 16083 / 7456 / 320 / 208-byte sizes after the runs).

2. **Commands.** Full-copy CLI runs (each needs ≈ 8.1 GB of free space):

   ```bash
   cd /home/marek/projekty/OSM2Leaf          # the repo checkout (worktree)
   W=/home/marek/projekty/leafre-work/m5.20
   US=archive/sd-images/LEAF_2011-2012_US.img
   EU=archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img

   # controls: unchanged trees compare identical
   python3 tools/mkcard.py --from-image "$US" --tree /home/marek/projekty/leafre-work/m5.12-us/root-factory --compare-only
   python3 tools/mkcard.py --from-image "$EU" --tree "$W/eu-factory" --compare-only

   # one same-length change, one grow, per image
   python3 tools/mkcard.py --from-image "$US" --tree "$W/us-same" --reconcile -o "$W/us-same.img" --cardcheck
   python3 tools/mkcard.py --from-image "$US" --tree "$W/us-grow" --reconcile -o "$W/us-grow.img" --cardcheck
   python3 tools/mkcard.py --from-image "$EU" --tree "$W/eu-same" --reconcile -o "$W/eu-same.img" --cardcheck
   python3 tools/mkcard.py --from-image "$EU" --tree "$W/eu-grow" --reconcile -o "$W/eu-grow.img" --cardcheck

   # unchanged tree stays byte-identical (copy path): NOT re-run in this session
   # (no free space for a second 8.06 GB copy); the same copy path is C-1911 (real EU)
   python3 tools/mkcard.py --from-image "$EU" --tree "$W/eu-factory" --reconcile -o "$W/eu-same-unchanged.img"
   sha256sum "$W/eu-same-unchanged.img"       # expect 105e2032...76307

   # read-only: which DRSTR values a changed tree would move
   python3 tools/mkcard.py --selftest
   python3 tools/mkcard.py --reconcile --selftest
   ```

   Disk limit found during the run: the root filesystem had 7.8 GB free and
   each image is 8.06 GB, so the full-copy CLI runs were done one at a time
   and deleted after hashing. The CLI run for `eu-grow` finished with a
   `cardcheck PASS` but its envelope line was cut from the terminal, so the
   final envelope numbers below come from the same reconcile call on an
   XFS reflink clone (`cp --reflink=always`, which uses no extra space until
   written). The clone run calls `mkcard.reconcile_partition`, `diff_ranges`,
   `outside_ranges` and `run_cardcheck_image` in the order `mkcard(reconcile=True)`
   does after its copy; it is a scratch harness (not committed) and changes no
   code path.

3. **Controls.**
   - *Positive (unchanged):* `--compare-only` on the factory trees gives
     `tree_diffs=0 identical=True` for US and EU; the byte-copy output of the EU
     factory tree is SHA-256 identical (C-1911, real EU, earlier run).
   - *Positive (DRSTR):* the read-only plan (`_reconcile_drstr` rules, applied to
     the factory DRSTR001.DAT and the unchanged factory trees) gives 0 value changes
     on both images.
   - *Negative (no DRSTR rewrite):* the first US grow run, before DRSTR handling,
     gives `cardcheck FAIL: [drstr] XMD: DRSTR size 44256 != actual 44320`.
   - *Negative (case flags):* before the NT-flag fix, the unchanged US factory
     tree compares as `added XMD/ltntbl.dat` and `removed XMD/LTNTBL.DAT`.
   - *Negative (envelope):* a stray byte placed in an unrelated free cluster
     is reported by `outside_ranges` (synthetic self-test, R5).

4. **Scope.** Covered: the 4 changed-tree cases above (2 per image, 1 file each);
   the 2 unchanged trees; the factory DRSTR of both images. Not covered: changes to
   more than one file in one build, `.cmp`/`.ind` payloads (cardcheck's
   `.ind`/`.cmp` checks run on the untouched pairs only), `--label` (refused with
   `--reconcile`), and the fresh-build contrast (not re-measured: see Observations).
   Counted corpus: 2 real images, 4 changed-tree builds, 2 unchanged trees,
   2 DRSTR listings (208 and 324 entries), and 13 synthetic checks in
   `_selftest_reconcile`. The unchanged-tree copy on a real image was not run here.

5. **Falsifier.** As stated under Hypothesis. Recorded before the runs.

## Interpretation

- **FACT:** `--reconcile` writes a same-length change into the file's existing
  chain. On both real images the output differs from the factory by one 16-byte
  range inside the file's cluster; the directory entry is untouched (size, cluster
  and timestamps do not change), and cardcheck passes (C-2460, C-2461).
- **FACT:** a size change cannot be a chain write alone. cardcheck requires each
  DRSTR value to equal the logical size or recursive directory total, so a grow
  also rewrites those value bytes (2 entries here) in `DRSTR001.DAT`. The DRSTR
  rewrite is 2 to 3 small ranges, and the rest of the diff sits in the file's
  own clusters and their zero fill (C-2462, C-2463, C-2464).
- **FACT:** the factory DRSTR matches cardcheck's logical sizes on both
  unchanged trees (C-2465). The zero-fill range count on EU comes from stale
  bytes that the factory holds after the file's EOF (C-2467).
- **FACT:** NT case flags must be read. Without them the unchanged factory tree
  reports a phantom add/remove pair (C-2466).
- **OBSERVED:** unchanged trees take the byte-copy path, and the factory tree
  compares identical on both images (C-2468).
- **OBSERVED:** a structural change (added or removed file) falls back to the
  fresh build with the reason stated, and the envelope checker catches a stray byte
  (C-2469).
- **INTERPRETATION of the Done-when:** the strict wording is "only in that file's
  clusters and its directory entry". For a same-length change this holds exactly.
  For a size change it holds only if the DRSTR value bytes are counted as part of
  the file's directory entry (they are the DRSTR index entries for that file and its
  ancestors) and DRSTR's own cluster is allowed. Both are reported above with the
  byte counts. A reader who keeps the strict wording should treat the grow rows as
  an exception and the same-length rows as the pass.
- **UNKNOWN:** the fresh-build contrast is not re-measured. The 13-byte DRSTR
  prefix rule (`bsatbldata.da` style names) is covered by the read-only plan on
  the US factory only, not by a reconciled real image. Acceptance on a unit is
  M6 work, not this experiment.

## Conclusion

`tools/mkcard.py --reconcile` now builds a changed tree on the factory layout:
changed files go through the `imgpatch.py` chain writer, the DRSTR index values
follow any size change, and the diff is checked against an explicit envelope.
Same-length changes meet the M5.20 wording exactly on both images; size changes
meet it with the DRSTR value bytes counted as the file's directory entry, which
is stated above. Unchanged trees are unchanged. Added or removed files fall
back to the fresh build. Open: the fresh-build contrast number, a real-image
prefix-name (13-char DRSTR) run, and the zero fill, which rewrites stale bytes
after EOF (a minimal-diff variant that keeps them is possible but not done).
