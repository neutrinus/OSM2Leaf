## Question

Does the M5.29 factory-backed one-tile pipeline complete when the OSM test
geometry is routed into a spliceable `0x2046` directory of `B48R058R`
(`y=76 x=940`) instead of the `0x2146` directory (`y=76 x=941`) that PR #171
hit, and does it then pass `cardcheck` + applicable `l2check` while changing
only that directory of that one tile (plus the one manifest it rebuilds)?

## Hypothesis

`tilewriter` refuses `0x2146` because its record boundaries are unsafe (M5.22);
the same writer accepts `0x2046`, and M5.4 already spliced 18 parcels there with
L2 PASS. **Falsifier:** the run changes a directory other than `(76,940)`, or
changes a file other than `B48R058R.DAT` + the named manifest(s), or
`cardcheck`/applicable `l2check` fails for a reason other than the directory
kind. A second falsifier: a way that reaches a preserve-only directory is not
refused before the tile write.

## Interpretation

- **FACT:** `B48R058R` has 64 section-1 level-1 directories: 30 `0x2046`
  (spliceable) and 34 preserve-only, of which 13 are `0x2146` (`parcel_census`).
  `(76,940)` is `0x2046`; `(76,941)` — the PR #171 failure — is `0x2146`.
- **FACT:** routing the test geometry into `(76,940)` makes the factory-backed
  pipeline complete: `tilewriter`, `rebuild_manifests`, `cardcheck` and the
  targeted `l2check` all exit 0, with the generated tile
  `e33c4240…628df4`.
- **FACT:** the change is exactly one section-1 directory of one tile; the
  only other file that differs is `DRSTR001.DAT`, which carries the tile's
  on-disk size. `MMAIN001.DAT` and `CMP.LST` are byte-identical.
- **FACT:** a node that lands in a preserve-only directory is refused with the
  kind named, before any tree copy or tile write (exit 2, no `--out`).
- **OBSERVED:** `l2check --tiles` matches **file names** (`B48R058R.DAT`), not
  cell names; `--tiles B48R058R` silently checked 0 tiles and still printed
  PASS. The pipeline now asserts `tiles=1` and fails the gate otherwise
  (correction, see below).
- **HYPOTHESIS:** the 4.7 MB growth is the appended slot blocks for the parcels
  written (M5.4 saw +318 kB for 18 parcels; this run fills the directory).
- **UNKNOWN:** whether the unit reads the generated tile (rule 13); the class
  table (M5.3); whether the clipped boundary ways are acceptable at the
  directory edge (M5.5 joins across tiles).

## Corrections after navigator review

- **`l2check --tiles` takes file names.** The first run passed
  `--tiles B48R058R`, which matched nothing (`tile_roundtrip OK (tiles=0)`,
  WARN "not present on this card") and still exited 0. Fixed in the pipeline:
  it passes `<cell>.DAT` and requires `tiles=1` with no "not present" warning.
- **"One file differs" is wrong.** With a tile size change, `DRSTR001.DAT`
  changes too. The EXP and the pipeline report name **one tile + the manifests**
  and list `unexpected_differences: []`; `MMAIN001.DAT`/`CMP.LST` are
  byte-identical here.
- **Factory mode used to ignore `--osm`.** `build_factory_out()` defaulted to
  the inline `SYNTHETIC_OSM`; its node at `lon 17.00` maps into `(76,941)`.
  The factory path now takes the OSM path (and labels `fixture=real-osm` vs
  `synthetic`).
- **Clipping is explicit.** `osm_ingest --bbox` is inclusive and keeps every
  vertex of a way with one vertex inside, so it cannot by itself keep a way in
  a directory. The default refuses a crossing way (the navigator's negative
  control); `--clip` drops such ways, which is what the real extract needs.
- **`/tmp` is a 3.8 GB tmpfs.** A full factory root is 4.9 GB; the run must go
  to `/home/marek/projekty/leafre-work/`. A first attempt failed with
  `ENOSPC` mid-copy and is not evidence.

## Conclusion

M5.29's `Done when` is met on the factory root: `cardcheck` and applicable
`l2check` pass, the gate report is per file, exactly one `MAPAL001` tile differs
and inside it exactly one directory `(76,940)` kind `0x2046`, with
`DRSTR001.DAT` the only other changed file (the tile's on-disk size). The
`0x2146` directory `(76,941)` is untouched and its geometry is refused by
design. `mapping=provisional-v0`; firmware acceptance unknown (rule 13,
L3/L4/L5). The task text's "18 `0x2046` directories" is corrected to "18
parcels in one of 30 `0x2046` directories".
