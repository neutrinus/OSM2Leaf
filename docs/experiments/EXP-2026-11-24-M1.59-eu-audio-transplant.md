## Question

Can the EU card's image A get an `Audio.exe` that opens a tuner a USA unit
starts (M1.58: `TNR2:` is Euro-only), without moving any EU module, and
does NK1 still boot the card to the map?

## Hypothesis

(1) A one-character patch `TNR2:` -> `TNR4:` plus SUM4 is accepted. (2) The
US `Audio.exe` can be appended after the EU image A and the TOC entry
repointed: an EXE runs at process base `0x10000` in both builds, so its code
needs no relocation; NK1 already loads a longer image A (the US one).
**Falsifier:** `Sum Check NK2` fails, the launcher stops (`Error Proc`,
FailSafe), or the map never draws with the transplanted card.

## Inputs

| Item | Value |
| --- | --- |
| EU image A | NB00 `0x200000`, NB01 `0x2000000`, NKOK length `0x1752c88`, `physfirst 0x8cae1000`, `physlast 0x8e233c88` |
| US image A | NKOK length `0x17978e0` (loads on NK1: the US card boots on Marek's unit) |

## Method

1. **Sample and hash.** As above.
2. **Commands.**

   ```bash
   EU=eu.img                                      # whole EU card image (copy)
   US=LEAF_2011-2012_US.sys                       # first 100 MiB of the US card
   python3 tools/audio_tnr_patch.py --selftest
   python3 tools/audio_transplant.py --selftest
   python3 tools/audio_tnr_patch.py show $EU
   cp $EU tnr.img && python3 tools/audio_tnr_patch.py patch tnr.img --in-place
   cmp -l $EU tnr.img | wc -l
   python3 tools/card_mapcode.py set --image $EU --from-nk1 firmware/unit-flash/nk1-QY7200ND.bin --in-place
   cp $EU eu_tx.img && python3 tools/audio_transplant.py apply eu_tx.img $US --in-place
   python3 tools/audio_diff.py drivers eu_tx.img $US
   python3 tools/cerom.py modules --census eu_tx.img $US
   printf '0x081fb6f4 0b000900\n0x081fc428 0b000900\n' > extra.txt
   for v in ctl tx; do img=$EU; [ $v = tx ] && img=eu_tx.img
     python3 tools/ze0_launch.py --qemu $QEMU --card $img --flash nand_a0erased.bin \
       --workdir run/$v --peer panel --peer gps --gdb $([ $v = ctl ] && echo 1240 || echo 1250) \
       --ui-start --ipl-extra extra.txt --timeout 900 & done
   grep -a -E "OWNFIRSTMAPDRAW_END|Error Proc|FailSafe|Exception|Load To 8e1e" run/*/serial.log
   ```

3. **Controls.** *Positive:* run `ctl` = the same card with only
   `card_mapcode.py` (known to draw the map, M1.57 O8). *Negative:* the
   selftests refuse a copy with two tuner literals and EU copies that
   differ; `apply` refuses imports the EU image lacks.
4. **Scope.** Image A only; boot to the first map draw. The emulator has no
   audio microcontroller (M8.H45): `Audio.exe` stops at `AUD1:` in both
   runs, so tuner, equalizer and radio screen are not exercised.
5. **Falsifier.** Stated under Hypothesis.

## Observations

**O1 — TNR patch.** One `TNR2:` per copy (`0x789fd0`, `0x2589fd0`), SUM4
`0xcdf87db0` verified; after `patch` 4 bytes differ (2 literal bytes, 2
SUM4 bytes), SUM4 `0xcdfa7db0` verifies, `audio_diff.py drivers` lists
`TNR4:` for the EU `Audio.exe`.

**O2 — transplant plan.** Image A length `0x1752c88` -> `0x178b70c`
(below the US `0x17978e0`). US sections appended at `0x8e234000` (code,
page-aligned), `0x8e26ae00`, `0x8e26b284`; `e32` `0x8e26c654`, `o32`
`0x8e26c6c4`; TOC size 228,864 -> 241,152; `ulLoadOffset` kept
`0x8d64e000`. Imports the EU image lacks: none. SUM4 `0xe7a2b00c` in both
copies. Afterwards `cerom.py modules --census` reports 2 code-identical
modules (was 1: `atlce400.dll` + `Audio.exe`), and `audio_diff.py drivers`
lists `TNR3: TNR4:` for the EU card's `Audio.exe`.

**O3 — emulator, NK1 + Marek's flash (area 0 erased).**

| run | `Sum Check NK2` | last image-A chunk | `Error Proc` / FailSafe / Exception | `Audio.exe` | `OWNFIRSTMAPDRAW_END` |
| --- | --- | --- | --- | --- | --- |
| ctl (mapcode only) | passes | `Load To 8e1e1000h … SectorNum:00000297` | none | created; `AUD1: CreateError`, `Wait Modules Error LaunchId=[45] … ID=[6]` | yes |
| tx (mapcode + transplant) | passes | `… SectorNum:0000045C` | none | same lines | yes |

The two serial logs differ only in pointers and the sector count (sorted,
numbers masked: 12 lines, all addresses), plus one `RIF: AutoCrsList`
line in `ctl`.

## Interpretation

- **FACT:** NK1's loader reads the longer image A (`SectorNum` `0x297` ->
  `0x45C` for the last chunk) and `Sum Check NK2` accepts the recomputed
  SUM4; the launcher creates `Audio.exe` from the repointed TOC entry and
  Navi draws the EU map (O3).
- **FACT:** the transplanted `Audio.exe` is byte-identical in code to the US
  module and opens `TNR3:`/`TNR4:` (O2).
- **UNKNOWN:** everything after `AUD1:`: tuner, equalizer, radio screen. The
  EU radio screen binds `RDSCC.RDSCtrl` (COM, `RDSCC.dll` kept); whether
  it understands the US `Audio.exe`'s messages is open. `ulLoadOffset` was
  kept at the EU value although the US module's `vsize` is `0x2000`
  larger than the EU gap to `CameraCC.dll`; no effect seen in the boot.
- **HYPOTHESIS:** in the car the transplant removes the stall (equalizer
  works); the radio may still not show stations on the EU screen.

## Car test L5 (2026-11-24, Marek)

Patched EU 2011 card (audio patch from this EXP + consent patch
`ze0_consent.py`) on Marek's USA 2011 unit, NAND GPS patch as in M1.57.
Audio variant written: the full transplant (`audio_transplant.py`, US
`Audio.exe` appended; Marek, 2026-11-24).

- **FACT (car):** equalizer settings now change the sound (they did not in
  M1.58's test); screen button beeps work; Bluetooth audio plays (photo:
  source "Bluetooth Audio" in the status bar over the Wrocław map).
- **FACT (car):** the consent screen no longer blocks (consent patch worked).
- **FACT (car):** after a few kilometres the car position on the map moved
  to the real one (Wrocław, ul. Borowska); scale shown in miles (`1/8mi`).
- **FACT (car):** FM radio "does not fully work"; details (no stations,
  wrong steps, no RDS text, no sound) not yet reported.
- **HYPOTHESIS:** the US tuner path uses the US FM raster (200 kHz, odd
  decimals 87.9–107.9 MHz) and US AM raster (10 kHz); Polish stations on
  even decimals or 100 kHz steps (e.g. x.0, x.2) would be unreachable by
  seek/step. Follow-up M1.60.

Conclusion update: H1 of M1.58 (EU `Audio.exe` without a tuner stalls the
audio, equalizer dead) is supported: with the tuner device fixed the
equalizer works. Radio remains open (M1.60).
