## Question

What does the ZE0 head unit expect at power-up, what moves it from ACC-on to
ACC-off, and which data is flushed or protected — and in what order — when
the application layer acknowledges an ACC-off?

## Hypothesis

`PowerMonitor.dll` (build B) is a stream driver that converts CAN/GPIO ACC
events into a named event for the application layer, then serialises a fixed
flush/write-disable sequence. **Falsifier:** no code path leads from an ACC-off
input to a flash write *or to an application-layer save hand-off*; a second
falsifier is that the module is absent from build B (zero hits for its own
name) — either would refute this reading.

## Interpretation

- **FACT:** build B's `PowerMonitor.dll` owns the ACC-off notification; its
  code and `.pdata` are readable and all pinned checks pass. Details and VAs
  are in `docs/firmware/power.md`.
- **OBSERVED:** the ACC-off path uses interrupt id 17, a 40000 ms
  application-layer wait and a named event; the backup path uses interrupt
  id 16 and a 5000 ms `MUTEX_MCT_WRITEFILE` wait; the hardware-shutdown list
  is ordered Bolero ACC → I²C → SDC1 → SRM → FLM → FMD.
- **FACT (module-scope negative):** no flash-write instruction was located in
  the ACC-off path of `PowerMonitor.dll`. The hand-off to the application
  layer is the save trigger; the writes themselves are outside this module.
- **HYPOTHESIS:** the `MCT_WRITEFILE` mutex serialises a map/card write owned
  by another module on backup power; no owner was located here.
- **UNKNOWN:** runtime ordering, the exact CAN frames that assert ACC/IGN,
  and whether the 45 s SystemEXE watchdog (C-8200) expires before the
  40 s wait in the common no-application case.

## Conclusion

`docs/firmware/power.md` now records the inputs, the observed transitions
with VAs, the ordered flush/disable list and the timeouts; ten claims
C-7500–C-7509 back the ledger. The falsifier's first branch (no hand-off)
is refuted: `NOTIFY_ACC_OFF_EVENT` is created here and is also present in
AppLaunch.dll. The literal "flash write inside PowerMonitor" branch is a
module-scope negative, so the task's save-list question is answered as a
*hand-off plus flush/disable list*, with the actual writer left to M8.H54.
