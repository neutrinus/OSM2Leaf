## Question

Do the 132 uncompressed (non-`.cmp`/`.ind`) files of the US card hold any copy
of the names M5.12c renamed or searched (`HANA HEALTH CENTER`, `HANA HEALTH`,
`RAB ORCHARD`, `MCDONALD'S`, `HARDEE'S`, `WENDY'S`, `GODFATHER'S`, `BLIMPIE`),
and is any of them a POI record (name followed by `@`) that the rename missed?

## Hypothesis

The uncompressed files hold no POI record of these names; any hit is a street
or place label. **Falsifier:** a hit followed by `@`, or any `HANA HEALTH` hit.

## Inputs

| Item | Value |

| Names | the 8 above, Latin-1, UTF-16LE and UTF-16BE |
| Tool | `poi_copies.py --image … --inner` |

## Method

1. `sha256sum` of the image (matches Sample).
2. `python3 tools/poi_copies.py --image archive/sd-images/LEAF_2011-2012_US.img
   --inner --text "HANA HEALTH CENTER" --text "HANA HEALTH" --text "RAB ORCHARD"
   --text "MCDONALD'S" --text "HARDEE'S" --text "WENDY'S" --text "GODFATHER'S"
   --text "BLIMPIE" --json hits.json`. Every file is searched raw and inside
   every complete zlib stream it holds. A zlib-header candidate that starts
   inside a stream already inflated is skipped: it is compressed data, not a
   new stream. Without this skip M5.12c's run never finished (each tile byte
   pair that looks like a header was inflated).
3. For each hit: the byte after the name (`@` = POI record, as in M5.12c
   Method 4) and, for hits not followed by a space, the 6 bytes before it.
4. **Controls.** Positive: `poi_copies.py --selftest` (11/11 OK, including a
   name inside a zlib stream and two back-to-back streams that are both
   inflated); the same tool in tree mode on the decoded `POINT006/008.DAT`
   of M5.32 finds 1,254 hits, among them the `RAB ORCHARD`/`HARDEE'S` records
   M5.12c and M5.32 edited. Negative: absent-text selftest case (0 hits).

## Interpretation

- **FACT (C-2960):** the uncompressed-file scan that M5.12c Method 3 left
  running is complete over all 132 non-`.cmp` files of the US image; it has
  175 hits and none is followed by `@`, so the POINT pages hold every POI
  record of these names and the M5.12c + M5.32 rename missed none.
- **FACT (C-2961):** `HANA HEALTH CENTER` and `HANA HEALTH` occur nowhere
  outside the decoded `.cmp` payloads (M5.12c: one hit, `POINT010` inner
  `0x840ba0`); no uncompressed index or tile copy can shadow the M5.12 rename.
- **OBSERVED (C-2962):** 20 bare, length-prefixed `CRAB ORCHARD` labels sit in
  the name sections of 6 US tiles (map level files included). What Marek
  should expect: the map can still draw a `CRAB ORCHARD` label (the place, from
  the tile) even after the POI record is renamed; the POI list and POI name
  search read the POINT records and should show `OSM2 RAB 01`. Which screen draws the
  tile label is not verified (no car test).
- **FACT (C-2963):** skipping zlib-header candidates inside an already inflated
  stream makes the whole-image `--inner` scan finish in 97 min; the selftest
  shows two back-to-back streams are still both found.

Limits: only complete zlib streams whose compressed bytes end within 8 MiB of
their header are inflated (raw deflate without a zlib header, or a longer
stream, would be missed; none is known on this card), and only the 8 names
were searched.
