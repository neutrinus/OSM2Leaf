## Question

Can an L4 test be a scenario file — a list of steps against the QEMU monitor
and the peer control sockets — so that a tap, a key, a position, a screenshot
and an expected hash are reproducible without a shell history, and can a
failing expectation never exit 0?

## Hypothesis

A small runner over QMP (`human-monitor-command` for guest time and
screenshots), HMP (the screenshot composer of M8.C1f) and the per-peer control
sockets of `docs/research/qemu-connectors.md` makes each step a line of text.
The step kinds filter to "expectation failed" (exit 1) versus "endpoint
absent" (exit 3), so a wrong `expect-hash` fails and a missing peer is a SKIP
that is never a pass.

**Falsifier:** a scenario with a failing expectation exits 0. The selftest runs
exactly that case (`wrong hash exit == 1`) and the exit-3 cases
(`missing panel socket`, `missing qmp`, `missing log` all `== 3`).

## Method

1. **Sample and hash.** The synthetic selftest needs no sample (it is
   `none (tool-only task)` for its endpoints). The bonus real run boots
   `archive/head256.img` (hash above) with `-M ze0`.

2. **Commands.** The synthetic selftest, runnable as written:

   ```bash
   python3 tools/ze0_ui.py --selftest
   python3 tools/selftest.py --only ze0_ui
   ```

   The real boot, runnable as written (QEMU binary from
   `tools/qemu-ze0/build.sh`; no card needed for a silent screen):

   ```bash
   Q=~/.cache/qemu-ze0/build/qemu-system-sh4
   W=/home/marek/projekty/leafre-work/scratch/m8.h7
   mkdir -p "$W"
   "$Q" -M ze0,kernel-off=0x3e00200,app-off=0x200200,dbgmsg=0x880404f4 \
        -kernel archive/head256.img -nographic \
        -serial file:$W/serial.log \
        -monitor unix:$W/hmp.sock,server,nowait \
        -qmp unix:$W/qmp.sock,server,nowait \
        -d unimp,guest_errors,int,invalid_mem -D $W/qemu.log &
   printf 'wait-log Booting Windows CE version\nsleep-guest 2\nshot boot\n' > "$W/real.txt"
   python3 tools/ze0_ui.py run "$W/real.txt" \
       --qmp $W/qmp.sock --hmp $W/hmp.sock --log $W/serial.log \
       --shot-dir $W/shots --guest-clock 0x09e41888 --wait-timeout 60
   ```

3. **Controls.**
   - *Positive:* the synthetic "good" scenario (wait-log, gps, tap, key,
     sleep-guest, shot, expect-hash) exits 0 with all 7 steps, and a real boot
     runs `wait-log`/`sleep-guest`/`shot` against live sockets and exits 0.
   - *Negative:* a wrong `expect-hash` exits 1 and stops before the last step;
     `wait-log` timeout on an existing log exits 1; a malformed `tap` exits 1;
     an out-of-range `gps` exits 1. Missing panel socket, missing QMP and
     missing log each exit 3.

4. **Scope.** The selftest is fully synthetic: a fake QMP server (greeting,
   `qmp_capabilities`, `human-monitor-command`/`xp` with a monotonic clock), a
   fake peer server (one command line, one `OK` line) and a fake screenshot
   command. No real QEMU, no vendor data. The bonus real run covers
   `wait-log`/`sleep-guest`/`shot` on one EU 2011 head; it does not cover
   `tap`/`key`/`gps` (no peer exists yet — M8.H30, M8.H38) nor the rendered
   screen content (no display engine in this run, the boot was dead-ended at
   `FailSafe.exe`).

5. **Falsifier.** A scenario with a failing expectation exits 0 would refute
   the exit-code contract; the selftest's `wrong hash exit == 1` checks it.

## Interpretation

- **FACT:** the runner separates expectation failures (exit 1) from absent
  endpoints (exit 3); the selftest pins both directions.
- **FACT:** `shot` reuses `ze0_screenshot.py screen` unchanged; a live boot
  produced a 800 × 480 PNG through the runner.
- **OBSERVED:** with no card the live screen is all zero and the boot reaches
  `FailSafe.exe`; that is the expected no-card state, not a runner fault.
- **HYPOTHESIS:** once M8.H30 (GPS) and M8.H38 (panel) exist, `gps`/`tap`/`key`
  will drive them over the same control-socket protocol.
- **UNKNOWN:** whether a live `tap`/`key`/`gps` can be scripted end to end —
  no peer exists yet, so that path is only tested synthetically.

## Conclusion

`tools/ze0_ui.py` runs a scenario file of `wait-log`, `sleep-guest`, `tap`,
`key`, `gps`, `shot` and `expect-hash` steps against QMP/HMP, the log and the
peer control sockets. The step grammar is in `tools/README.md`; the exit codes
are 0 pass, 1 expectation failed, 2 usage error, 3 nothing runnable. The
synthetic selftest is auto-discovered by `tools/selftest.py` (`tool:ze0_ui
PASS`) with a wrong-hash negative and the exit-3 paths. A real EU 2011 boot
ran the `wait-log`/`sleep-guest`/`shot` path. `tap`/`key`/`gps` remain
synthetic until their peers merge (M8.H30, M8.H38).
