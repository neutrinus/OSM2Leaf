# EXP-2026-11-15-M1.29: `fn_audit` — a documented correction is `CORRECTED`, not `INSIDE`

- **Status:** done
- **Date:** 2026-11-15
- **Sample:** `archive/head256.img`, SHA-256 `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`
  (256 MiB firmware head; builds A `0x200200`, B `0x3e00200`, C `0x5200200`)
- **Tools:** `python3 3.15.0`; repo `tools/fn_audit.py` (M1.29 change),
  `tools/pdata.py` (records, M1.23), `tools/cerom.py` (TOC),
  `tools/selftest.py`, `tools/claims_check.py`, `tools/todo_check.py`.
  No vendor bytes are stored in the repo; `archive/head256.img` is outside
  the checkout.
- **Claims:** C-3790–C-3795 (C-3796–C-3799 reserved)
- **Supersedes:** none (extends EXP-2026-11-15-M1.25-fn-audit)
- **Superseded by:** none

## Question

Can `tools/fn_audit.py` stop counting *documented corrections* — a line that
pairs a wrong VA with its true start — as unresolved `INSIDE`, while a live
`fn 0x<mid>` label of the same VA still fails, and on the real head does that
remove exactly the correction-only set and nothing else?

## Hypothesis

The three `ctx`-only VAs M1.25 could never fix (`0x003f5fc2` →
`0x003f5f48`, `0x00413af4` → `0x00413a6c`, `0x00542256` → `0x00542250`) are the
only unique `INSIDE` VAs whose every citation already names its true start on
the same line or is pinned by the Stop-clause allowlist. If the audit resolves
a `ctx` citation only through its *own* pair, then:

* `--fix-list` drops from 12 to 9 unique lines (the three disappear),
* every other unique `INSIDE` VA stays and exit stays 1,
* the corpus size is unchanged (the pair parsing must not add citations).

**Falsifier:** any other unique `INSIDE` VA disappearing from `--fix-list`, any
of the three still present, the citation / unique counts changing, or a live
`fn 0xMID` becoming `CORRECTED`.

## Method

1. **Sample and hash.** `archive/head256.img`, first 256 MiB, SHA-256 above;
   builds selected by CE image start, not a fitted delta.
2. **Commands.** Run from the repo root:

   ```bash
   sha256sum archive/head256.img
   python3 tools/fn_audit.py --selftest
   python3 tools/fn_audit.py archive/head256.img --scope docs --fix-list
   python3 tools/fn_audit.py archive/head256.img --scope docs | grep -E '0x003f5fc2|0x00413af4|0x00542256'
   python3 tools/pdata.py fn archive/head256.img --module Navi.exe \
       0x003f5fc2 0x00413af4 0x00542256 0x0041c7e8
   python3 tools/selftest.py
   python3 tools/claims_check.py
   python3 tools/todo_check.py
   ```

3. **Controls.**
   * Positive (live mislabel still fails): `0x0041c7e8`, `0x00412bee`,
     `0x0040e4b2` are cited as `fn`/`const`/`target` labels and must stay
     `INSIDE` and in `--fix-list`; the tool must exit 1.
   * Negative (correction passes): `0x00542256` on `TODO.md:729`
     (`` `0x00542256 → fn 0x00542250` ``) resolves to `CORRECTED`, while
     the repeated bare `0x00542256` at the end of the same line — which
     matches no pair — stays `INSIDE`/`UNMAPPED` per the M1.25 rule.
   * Negative (wrong start): a pair naming a start that is not
     `pdata.locate`'s start (`0x401100` for `0x401048` in the selftest) stays
     `INSIDE`; a cross-build map (`0x0041c7dc→0x00444540`) is a pair shape,
     not a correction.
   * Synthetic (no image, so CI without vendor data runs it): all of the above
     and the `CORRECTION_ONLY` pin tests execute in `--selftest` on injected
     records.
   * Falsifier above.

4. **Scope.** `--scope docs` corpus: 17 files (`TODO.md`, 13
   `docs/format/*.md`, `tools/l3_harness/targets.json`,
   `tools/chunk_decoder_l3.py`, `tools/point_walk_l3.py`), **297 citations,
   112 unique VAs** — identical to the M1.25 baseline, so the change adds and
   removes no citation. Classification is unchanged (`pdata.locate` /
   `pdata.gaps`); only a `ctx` citation whose own pair names
   `pdata.locate`'s start, or whose scarce VA is on the explicit
   `CORRECTION_ONLY` allowlist with a matching pin, becomes `CORRECTED`.
   `--fix-list` and the exit code follow `is_failure`, so `CORRECTED` is never
   printed and never fails.

5. **Falsifier.** A different set of disappearing VAs, a changed
   citation/unique count, or a live label turning `CORRECTED`.

## Interpretation

- **FACT:** On `archive/head256.img` (`92aa525d…`) the `--scope docs` audit
  reports 297 citations / 112 unique VAs; 13 citations are `CORRECTED` and
  `--fix-list` drops from 12 to 9 unique VAs, exactly the three
  correction-only ones. Of the 13, 11 are the three correction-only VAs and
  2 are `0x0041c7e8`/`0x00412bee` on `TODO.md:512`, which stay `INSIDE` on
  their live-label citations.
- **OBSERVED:** The remaining nine unique `INSIDE` VAs
  (`0x003715a0`, `0x0040e4b2`, `0x00412bee`, `0x0041c7e8`, `0x0041c802`,
  `0x004e90c8`, `0x004ea402`, `0x005423e8`, `0x0054369e`) are live
  `fn`/`const`/`target` citations and still fail; exit stays 1.
- **OBSERVED:** A repeated bare VA on a correction line does not inherit the
  pair: on `TODO.md:729` the first `0x00542256` is `CORRECTED` and the second
  matches no pair and is not `CORRECTED` (it is an `UNMAPPED` bare address,
  dropped by the M1.25 rule), while the two `fn 0x00542250` labels on the same
  line are `START`.
- **HYPOTHESIS:** none needed; the falsifier did not fire.
- **UNKNOWN:** a correction whose start sits only on a *neighbouring* line
  (`0x00413af4`'s `jsr` site) is resolved by the explicit, commented
  `CORRECTION_ONLY` allowlist, which pins the true start and is re-checked by
  the selftest; it is not a general regex guarantee. Two wider extractors were
  measured and rejected: allowing a backtick between arrow and `fn` in the
  marker adds 11 citations / 5 unique VAs (seven on `TODO.md:884`), and
  scanning every pair line without a marker word adds 29 citations and four
  new `INSIDE` VAs (`0x03bb2c54`, `0x03bb2c64`, `0x00426128`, `0x004268ac`).
  The corpus was therefore left as M1.25 defined it.

## Conclusion

`tools/fn_audit.py` now distinguishes a correction the prose itself resolves
from a live mislabel: a `ctx` citation is `CORRECTED` when its own `→` pair
names the start `pdata.locate` reports (or when an explicit `CORRECTION_ONLY`
pin matches), and a live `fn 0x…`/`sub_…` label is never corrected. On the
real head this removes exactly the three correction-only VAs from the failing
set (12 → 9 unique, INSIDE occurrences 46 → 33, `CORRECTED 13`) while the
corpus stays at 297 citations / 112 unique VAs and exit stays 1 for the nine
live mislabels. `tools/README.md` documents the class; the claims ledger
registers C-3790–C-3795, with C-3796–C-3799 reserved. H52 (editing each live
citation) and M1.26 (`--scope l3`) remain open.
