## Hypothesis

M4.76's Precheck only requires `grep -c highway kiwiread/osm.c > 0` and a road-type table in M4.69's EXP. The **falsifier** is structural or empirical: `osm.c` is a render utility with no KIWI-code→tag assignments; the actual bridge (`osmtag()` in `kiwiread.c`) has exactly one road row; M4.69 is a negative result with no confirmed KIWI road codes; and `road_class_probe` returns fewer than ten OSM road classes with no significant `class_code` signal. Any one of these breaks the Done-when; all four are observed.

## Interpretation

- **FACT (source, negative):** `osm.c` is an OSM→BMP renderer: its one `highway` use is three `strcmp` render-colour choices; it performs zero KIWI-code→OSM-tag assignments. The task's Precheck passes but its Goal premise is false.
- **FACT (source, negative):** the only KIWI-code→OSM-tag emitter in the pinned commit is `osmtag()` (`kiwiread.c:1207–1227`): one road row `0x210 → highway=motorway` plus two background rows. KIWI road codes `0x211–0x218, 0x21b–0x21d` (`kiwiread.c:121–132`) are named but untagged. `key_t.osm_key/osm_value` are declared, never populated.
- **FACT (M4.69, negative):** 0/6000 road-frame fits; no display-class or road-type field was reached, so "codes M4.69 confirmed on our card" is the empty set.
- **FACT (tool, negative):** `road_class_probe` on the EU card yields **7** OSM road classes (not ten), 13 distinct LCTBL `class_code` values, and a `class_code` leave-one-road-out accuracy of **0.353** — below its shuffled-label null of **0.541**. The field does not carry a robust class signal; the probe was built to test that and returns a negative. Replication on the second IMF and at `--min-share 0.5` leaves the class count at 7.
- **UNKNOWN:** whether any factory-derived road-class semantics exist at all is M5.3's open question; this task cannot supply them without inventing a table. No rule-13 level is claimed: this is a source/tool negative, not a firmware read.
- **OBSERVED:** the navigator's round-1 read-only probe and the driver's empirical check agree; the pair converged on the blocked branch rather than manufacturing a ten-row table.

## Conclusion

M4.76 cannot be honestly completed from its named sources. No file in `docs/format/`, `profiles/` or `docs/research/osm-pipeline.md` was changed and no tool was added: the premise source is a render utility, the real bridge has one road row, M4.69's confirmed-code set is empty, and the worker tool returns 7 classes with no above-null class-code signal. The task is set to `blocked` with `Unblock: M5.3` (the open task that owns the OSM→Clarion class/speed table); when M5.3's semantics exist, a rewritten M4.76 can consume them. One claim C-7750 records the premise failure. No GPL code was copied; no vendor bytes entered the repo.
