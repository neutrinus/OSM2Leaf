# EXP-2026-11-15-M1.28-eu-us-fixture: a frozen EU→US `fn_match` control table

- **Status:** done
- **Date:** 2026-11-15
- **Sample:** EU2011 head `archive/head256.img` (256 MiB) SHA-256
  `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`;
  US2011 head `/tmp/opencode/us256.img` (256 MiB) SHA-256
  `70d945d823f93f04cae4e6c7113a723cae3a992ab7a6f9b24e94ce2e006a04da`
  (`head -c 268435456` of the US card)
- **Tools:** `python3 3.15`, repo tools `tools/fn_match.py` (this change),
  `tools/pdata.py` (via `fn_match`), stdlib only
- **Claims:** C-3740–C-3743
- **Supersedes:** none
- **Superseded by:** none

## Question

Can the five EU→US address pairs and eight `NOMATCH` VAs quoted in the M1.22
blocker be frozen into a committed, vendor-free fixture that replays against a
US head and fails loudly when the head or one mapping changes?

## Hypothesis

Yes. `fn_match.py` already reproduces `unique: 5 … nomatch: 8` on the 13 cited
EU VAs (M1.22 blocker, SE 2026-11-13); a table that pins those verdicts plus
the US head SHA-256 turns that one-off run into a regression command. The
**falsifier:** any of the 13 rows changes verdict or US address on the pinned
US head, or a one-byte head change is not reported as a hash failure (exit 2).

## Inputs

| Item | Value |
| --- | --- |
| EU head | `archive/head256.img` (256 MiB) |
| EU SHA-256 | `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9` |
| US head | `/tmp/opencode/us256.img` (256 MiB) |
| US SHA-256 | `70d945d823f93f04cae4e6c7113a723cae3a992ab7a6f9b24e94ce2e006a04da` |
| Module | `Navi.exe`, `--image-start 0x200200`, pdata index 2 |

| Repo tool | `tools/fn_match.py --fixture` |

## Method

1. **Sample and hash.** The two 256 MiB heads above. `check_head` hashes the
   first `bytes` bytes pinned by the fixture (so a 7.5 GB card image whose
   256 MiB prefix is the same is accepted), and fails with its size if the file
   is shorter than that prefix.
2. **Commands.**

   ```bash
   # baseline (M1.22 blocker): 13 VAs, EU -> US
   python3 tools/fn_match.py match archive/head256.img /tmp/opencode/us256.img \
       --module Navi.exe --va 0x003f5194 0x0041c7dc 0x0041c990 0x0041c044 \
       0x0041a438 0x00419350 0x004125a8 0x003fbed8 0x0040b358 0x003bc960 \
       0x003f632c 0x003f61bc 0x00542250

   # frozen replay (the task's done-when)
   python3 tools/fn_match.py --fixture tools/fixtures/fn_match_eu_us_2011.json \
       --us /tmp/opencode/us256.img --module Navi.exe

   # negative controls
   python3 tools/fn_match.py --fixture /tmp/opencode/m1.28-perturbed.json \
       --us /tmp/opencode/us256.img --module Navi.exe
   python3 tools/fn_match.py --selftest
   ```

   The perturbed fixture is the committed one with row `0x0041c7dc`'s `us_va`
   changed from `0x00444540` to `0x00444542` (a one-instruction shift).
3. **Controls.** *Positive:* the replay on the real US head exits 0 with
   `13 rows, 0 mismatch`; the same table on EU→EU is not run here because the
   fixture pins EU→US only. *Negative:* (a) one `us_va` changed by 2 exits 1
   and prints `MISMATCH US VA 0x00444540, fixture expects 0x00444542`;
   (b) a US head with one byte flipped (SHA-256
   `83b54ba2d66102c676a1aca8cb18047f64b559e2e08b0bd523adb1a2f3a4b101`) exits
   2 with `FAIL US SHA-256 …`; (c) a 1,000-byte truncated head exits 2 with
   `FAIL US is 1000 bytes, fixture needs at least 268435456`; (d) the selftest
   covers `UNIQUE→NOMATCH`, `NOMATCH→UNIQUE`, a moved US VA and a wrong hash.
4. **Scope.** The 13 EU VAs named in the M1.22b Precheck; `Navi.exe` build A
   in both images; 5 `UNIQUE` + 8 `NOMATCH` at the pinned head. Excluded: the
   full module census and the `build` field (M1.22b), and the leaf path
   (M1.27). No image bytes are committed; the fixture stores addresses only.
5. **Falsifier.** Stated above: a row transition, a wrong-head that does not
   exit 2, or a one-byte head change that still replays as `NOMATCH`.

- Replay: `# fixture replay: 13 rows, 0 mismatch`, exit 0 (~30 s).
- Perturbed `us_va`: `0x0041c7dc  MISMATCH  US VA 0x00444540, fixture expects

- Flipped-byte head: `FAIL US SHA-256 83b54ba2…4b101, fixture expects

- Truncated 1,000-byte head: `FAIL US is 1000 bytes, fixture needs at least
  268435456`, exit 2.
- `fn_match.py --selftest`: `OK (0 failed)`; `selftest.py --only fn_match`:
  `PASS`.
- A second US head (`/tmp/opencode/se-us256.img`, same SHA-256) replays the
  five `UNIQUE` rows identically.

## Interpretation

- **FACT:** the frozen table reproduces the M1.22 blocker's 5 `UNIQUE` / 8
  `NOMATCH` on the pinned US head (5 pairs exact to the instruction) and keeps
  them stable across a second copy of the same head.
- **FACT:** a changed mapping or a changed head fails loudly (exit 1 / exit 2),
  so the fixture is a regression guard, not a report.
- **OBSERVED:** the 8 `NOMATCH` are frozen with their reason; only
  `0x003f5194` is attributed to a matcher limitation (`.pdata` `GAP`/leaf);
  the other seven are recorded as "cause not established by this task".
- **UNKNOWN:** whether each of the seven is a genuine rewrite or a matcher gap —
  M1.22b decides that against this table.
- **UNKNOWN:** whether the five pairs hold on builds other than the pinned
  US2011 head.

## Conclusion

`tools/fixtures/fn_match_eu_us_2011.json` and `fn_match.py --fixture` turn the
M1.22 blocker's one-off EU→US run into a committed control: the pinned US head
replays 13 rows with 5 `UNIQUE` / 8 `NOMATCH` (exit 0), a one-instruction
change in a `us_va` exits 1, and a wrong or truncated head exits 2 with its
hash or size. `docs/format/firmware.md` now carries the five EU→US rows
(C-3740–C-3743). The fixture is also the regression table M1.27 runs before
reporting a `LEAF`/`DIFFERENT` result; this EXP does not claim any of the eight
`NOMATCH` is a real code difference.
