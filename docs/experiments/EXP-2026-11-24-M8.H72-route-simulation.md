## Interpretation

- **FACT:** the `-M ze0` EU 2011 boot reaches Navi.exe and draws the factory London map; the screenshot-hash oracle is live and can detect a changed view (positive control passed).
- **FACT:** the demo trigger value was written to the mapped demo-flag P1 address (`0x8e869cec`) and `RGD_DEMO_Start` was called with that flag set (trigger demonstrated at the byte level).
- **FACT (negative):** across three successive screenshot reads after the trigger the marker/view is byte-identical, the position word at the physical alias stays outside the grid, and the flag-check site is never reached by normal execution. The task's falsifier fired.
- **OBSERVED:** `CarPos_read is failed` and `rcv error(Gyro)` indicate the simulator has no car position to start from; the missing audio micom (M8.H45) and CAN/microcontroller input (M8.H49/M8.H75) leave the demo route without a moving position source.
- **HYPOTHESIS:** a moving L4 oracle needs either a route set through the UI (blocked behind the audio-micom UI join, M8.C1n) or a pin of `OBJ_CarPos` (the GPS/wheel path of M8.H32/M8.H73); the software-only demo switch alone is insufficient.
- **UNKNOWN:** whether `CRouteSimulation::ControlRouteSimulation` (NaviRouteCC.dll function at `0x02f69198`) with a preloaded route would move the marker without sensor input; not tried because no route can be set through the reachable UI.

## Conclusion

`blocked`. Under `-M ze0` neither the demo flag (`u16 0x00bcd208 → P1 0x8e869cec` set to 1) nor a direct call to `RGD_DEMO_Start` (`0x005182e0 → P1 0x8da772e0`) produced a moving position: three successive screenshots were byte-identical (`bab3eeb7…e1`), the position word at `xp 0x0cd940e4` stayed `0x00090009` (outside the grid), and the flag-check site `0x004ffd5e` had 0 hits. The serial log shows `CarPos_read is failed` and continuous `rcv error(Gyro)` — the car-position source the demo needs is absent in the emulator. No `docs/format/` change; ten claims C-8380–C-8389 register the boot recipe, the trigger VAs, the negative oracle result and the blocker. The task's falsifier fired, so a `done` verdict would be dishonest; `blocked` with `Unblock: M8.H45,M8.H49,M8.H32` is recorded.
