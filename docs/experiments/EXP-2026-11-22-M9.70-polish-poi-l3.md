## Question

When one EU2011 POI name is written with the Polish letters `ł`, `ó`, `ź`, `Ż`
as M4.13 stores them, do the firmware's own POINT walker and name accessor
return those bytes unchanged, or does a firmware function alter them?

## Hypothesis

The accessor returns the stored bytes unchanged. M4.13 established that the
name database stores Polish letters as **ISO-8859-2** single bytes (all Polish
letters occur; writer rule: encode as ISO-8859-2, reject what is outside it).
The M3.11c accessor returns a pointer and a length in words and reads that many
bytes from the file-order page; a byte-preserving read should therefore return
the exact ISO-8859-2 bytes. M9.10 proved the whole path for an ASCII name on
US2011; this task changes only the character set and the build.

**Falsifier:** the returned name equals the stored one for the ASCII part only,
or any non-ASCII byte differs (wrong byte, dropped byte, `0x00`-substituted
byte, high-bit stripped). A wrong-build or wrong-page run that still says PASS
also falsifies the method.

## Plan

1. **Source of the name encoding (data, not guessed).** M4.13
   (`EXP-2026-11-05-M4.13-strings.md`, claim rows in `claims.md`): name strings
   in `LCTBL001.DAT` decode 0 errors as ISO-8859-2, all Polish letters are
   present, and the writer rule is "encode as ISO-8859-2; reject characters
   outside that set". The replacement name is therefore encoded with
   `str.encode("iso-8859-2")`, never Latin-1 and never UTF-8. The selected bytes
   are `Ł=a3`, `ł=b3`, `ó=f3`, `ź=bc`, `Ż=af`, quoted from the command in Method
   §1.
2. **Files.** No tool owned by another task is edited. `mutate_refer_poi.py`
   accepts only Latin-1 on its CLI, so a small new helper
   `tools/rename_poi_latin2.py` maps each wanted ISO-8859-2 byte to the Latin-1
   code point of the same *value* and calls the existing `mutate_refer_poi.py`
   byte-level `--resize` path; this writes exactly the M4.13 bytes. The helper
   has a synthetic `--selftest` and is auto-discovered by `tools/selftest.py`.
3. **Run.** Extract the factory EU2011 `POINT010` pair from the card image.
   Positive control: the factory page passes the walker and the accessor
   (`NATIONAL TRANSPORT MUSEUM`, 1000/1000 records). Then rename two records of
   that one page to `Łódź Żabieniec.` (record 0, title name) and
   `łódź Żabieniec.` (record 1, lowercase `ł`), both 15 bytes so the delta is a
   whole number of 16-bit words and `--resize` can patch the record and field-5
   lengths. Run the same two tools on the edited pair and compare, byte for
   byte, the name the accessor returns with the ISO-8859-2 bytes written.
4. **Intended Done when.** The L3 run returns both names with every letter
   intact (hex of the non-ASCII bytes quoted from a printed command), or the
   EXP names the letter and the firmware function that changes it. Controls:
   an ASCII name still round-trips; a deliberately mangled non-ASCII name is
   detected by the wrong-expectation negative control. Hardware is
   unavailable: L3 firmware-fragment harness only, no L5.

## Method

1. **Sample and hash.** As in Sample. Quote the encoding of every Polish
   letter from a command:

   ```sh
   python3 - <<'PY'
   for s in ["ł", "Ł", "ó", "ź", "Ż", "Łódź Żabieniec.", "łódź Żabieniec.",
             "NATIONAL TRANSPORT MUSEUM", "NATIONAL WAX MUSEUM"]:
       b = s.encode("iso-8859-2")
       print(repr(s), len(b), b.hex())
   PY
   sha256sum archive/head256.img
   ```

2. **Commands.** Runnable as written from the repository root:

   ```sh
   IMG=archive/head256.img
   CARD=archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img
   S="$HOME/projekty/leafre-work/scratch/m9.70"
   mkdir -p "$S"
   python3 - "$CARD" "$S" <<'PY'
   import hashlib, sys, pathlib
   sys.path.insert(0, "tools")
   import cardcheck
   card = cardcheck.Fat32Image(sys.argv[1])
   out = pathlib.Path(sys.argv[2])
   for name in ("POINT010.DAT.cmp", "POINT010.DAT.ind"):
       data = card.read_range("REFER001/" + name, 0, 1 << 31)
       (out / name).write_bytes(data)
       print(name, len(data), hashlib.sha256(data).hexdigest())
   PY

   # positive control: factory page, ASCII name
   python3 tools/point_walk_l3.py walk "$IMG" --cmp "$S/POINT010.DAT.cmp" \
     --ind "$S/POINT010.DAT.ind" --page 0x6e06d0 --page-len 97158 --build eu2011 \
     --n 0,1,2,3,10,500,998,999
   python3 tools/point_name_accessor.py run "$IMG" --cmp "$S/POINT010.DAT.cmp" \
     --ind "$S/POINT010.DAT.ind" --build eu2011 --expect "NATIONAL TRANSPORT MUSEUM" --show 3

   # new helper: synthetic selftest, then the two ISO-8859-2 renames
   python3 tools/rename_poi_latin2.py --selftest
   python3 tools/rename_poi_latin2.py "$S/POINT010.DAT.cmp" "$S/POINT010.DAT.ind" "$S/out" \
     --page 0x6e06d0 \
     --rename "NATIONAL TRANSPORT MUSEUM=Łódź Żabieniec." \
     --rename "NATIONAL WAX MUSEUM=łódź Żabieniec."

   # firmware on the edited pair
   python3 tools/point_walk_l3.py walk "$IMG" --cmp "$S/out/POINT010.DAT.cmp" \
     --ind "$S/out/POINT010.DAT.ind" --page 0x6e06d0 --page-len 97158 --build eu2011 \
     --n 0,1,2,3,10,500,998,999
   python3 tools/point_name_accessor.py run "$IMG" --cmp "$S/out/POINT010.DAT.cmp" \
     --ind "$S/out/POINT010.DAT.ind" --build eu2011 --show 3

   # byte-for-byte comparison of the accessor result and the stored bytes
   python3 tools/rename_poi_latin2.py compare "$IMG" "$S/out/POINT010.DAT.cmp" \
     "$S/out/POINT010.DAT.ind" --page 0x6e06d0 --record 0 \
     --expect-hex a3f364bc20af616269656e6965632e
   python3 tools/rename_poi_latin2.py compare "$IMG" "$S/out/POINT010.DAT.cmp" \
     "$S/out/POINT010.DAT.ind" --page 0x6e06d0 --record 1 \
     --expect-hex b3f364bc20af616269656e6965632e
   ```

3. **Controls.** *Positive*: the factory page's ASCII name round-trips and all
   1,000 records pass; the helper's `--selftest` checks each letter's byte.
   *Negative (must fail)*: `compare` with a one-byte-mangled expectation (the
   ISO-8859-2 name is not the ASCII name with a substitution); the accessor's two
   built-in controls (no dictionary; a `db` not in the slot table); the wrong
   build/image pairing. A negative without the factory positive control is not
   a result.
4. **Scope.** One build (EU2011), one page of one file (`POINT010.DAT`
   `0x6e06d0`, 1,000 records), two renamed records of that page. The page is fed
   decoded: the `.cmp`/`.ind` layer and the page loader are not re-tested here
   (M9.11/M4.52). Not covered: the display path above the accessor, other pages
   or files, L4/L5. The corpus is 1 page / 1,000 records / 2 renamed names.
5. **Falsifier.** As in Hypothesis.
