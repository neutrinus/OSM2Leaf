## Question

Can the inline `hashlib.sha256(...).hexdigest()` calls in seven post-M8.H76
tools be replaced by `tools/hashutil.py` (`sha256_bytes`) without changing any
hex string, JSON key or CLI output?

## Hypothesis

Yes. M8.H76 established that all in-repo SHA-256 helpers compute the same
hex for the same bytes; the only real difference was path-vs-bytes splitting.
The seven later tools all hash a byte string inline, so aliasing their local
name to `hashutil.sha256_bytes` keeps every digest identical. The tool's
JSON keys and printed text are unchanged because only the expression that
computes the hex was replaced, not any field name or format string.

**Falsifier:** after the change, any call site returns different hex for the
same named fixture or short byte string, a JSON key changes, a per-tool
`--selftest` stops passing, or `hashutil --selftest` fails.

## Method

1. **Sample and hash.** Recreate the synthetic sample and print the
   independent reference digest:

   ```bash
   mkdir -p ~/projekty/leafre-work/scratch/m5.102
   python3 - <<'PY'
   from pathlib import Path
   import hashlib
   p = Path.home()/'projekty/leafre-work/scratch/m5.102/sample.bin'
   p.write_bytes(bytes(range(256)) * 4096)
   print(p.stat().st_size, hashlib.sha256(p.read_bytes()).hexdigest())
   PY
   ```

   Output: `1048576 fbbab289f7f94b25736c58be46a994c441fd02552cc6022352e3d86d2fab7c83`.

2. **Commands.** Precheck, before editing (Done-when form):

   ```bash
   grep -l 'import hashlib' tools/launch_area.py tools/point_add_poi.py \
     tools/tile_from_zero.py tools/tile_provenance.py tools/tile_relayout.py \
     tools/ze0_l3parity.py tools/ze0_uistart.py | wc -l
   grep -nE '^def (sha256_file|sha256_bytes)' tools/hashutil.py
   python3 tools/hashutil.py --selftest
   ```

   The per-call-site probe (`~/projekty/leafre-work/scratch/m5.102/callsite_probe.py`)
   evaluates the exact inline expression copied from each source line in
   `before` mode and calls the migrated helper in `after` mode, for the same
   named fixture. It prints one `file:line fixture hex` row per call site plus
   a `short-string` row:

   ```bash
   python3 ~/projekty/leafre-work/scratch/m5.102/callsite_probe.py before \
     > ~/projekty/leafre-work/scratch/m5.102/before_callsites.txt
   python3 ~/projekty/leafre-work/scratch/m5.102/callsite_probe.py after \
     > ~/projekty/leafre-work/scratch/m5.102/after_callsites.txt
   diff ~/projekty/leafre-work/scratch/m5.102/before_callsites.txt \
        ~/projekty/leafre-work/scratch/m5.102/after_callsites.txt
   ```

   Final checks, all run from the worktree root:

   ```bash
   grep -l 'import hashlib' tools/launch_area.py tools/point_add_poi.py \
     tools/tile_from_zero.py tools/tile_provenance.py tools/tile_relayout.py \
     tools/ze0_l3parity.py tools/ze0_uistart.py
   python3 tools/hashutil.py --selftest
   TMPDIR=~/projekty/leafre-work/scratch/m5.102/tmp python3 tools/selftest.py
   python3 tools/claims_check.py
   python3 tools/todo_check.py
   python3 tools/board.py lost --base origin/main
   ```

3. **Controls.** *Positive*: the reference `hashlib.sha256` digest of the
   synthetic sample (`fbbab289…`) and the published `b"abc"` digest
   (`ba7816bf…`, also asserted by `hashutil --selftest`) are the values every
   call site must print before and after. *Negative*: a short byte string
   (`b"abc"`) gives a different digest from the 1 MiB fixture, proving the
   probe hashes the named input rather than a constant; a wrong helper would
   break the `before`/`after` `diff`. *Environmental*: `TMPDIR` is redirected
   to the home-tree scratch for the full suite because `/tmp` is a 3.8 GiB
   tmpfs on this host (a 1 MiB fixture is small, but the suite builds card
   images).

4. **Scope.** The corpus is the `17` inline `hashlib.sha256(...).hexdigest()`
   call sites in the `7` tools named in the task: `launch_area.py` (1),
   `point_add_poi.py` (2), `tile_from_zero.py` (1), `tile_provenance.py` (4),
   `tile_relayout.py` (7), `ze0_l3parity.py` (1), `ze0_uistart.py` (1). All
   `7` `import hashlib` statements (one per file; `ze0_uistart.py`'s is inside
   `check_nk1`) were removed. `tools/hashutil.py` was **not** changed: both
   required helpers already existed. Not in scope: any other tool under
   `tools/` (the M8.H76 migration already handled its own set), any zlib
   recompression, and any format/gate/claim row.

5. **Falsifier.** Any call site's hex changes, a JSON key changes, a per-tool
   or full selftest that passed at baseline fails, or `hashutil --selftest`
   fails after the change.
