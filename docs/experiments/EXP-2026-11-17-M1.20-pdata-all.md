# EXP-2026-11-17-M1.20: one census command for every module's `.pdata`, and a `where` verdict for the index

- **Date:** 2026-11-17
- **Sample:** `archive/head256.img` = first 256 MiB of the EU 2011 card (builds A/B/C),
  SHA-256 `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`
- **Tools:** python3 3.15.0 (stdlib only, stock zlib), `tools/pdata.py`, `tools/cerom.py`,

## Question

Can one committed command print the `.pdata` record count of **every** module of builds
A/B/C, list a module without an exception directory as such (never guess), and prove that
the table is located by the e32 exception directory rather than by H51's section index?

## Hypothesis

`tools/pdata.py census IMG [--image-start S]` walks the CE TOC in order, prints
`module records section compressed` per module plus a totals line, and separates three
outcomes: `OK`, `NO-PDATA` (e32 exception directory `(0, 0)` only) and `ERROR` (a decode,
sort or TOC fault, exit non-zero, never rendered as "no pdata"). A `where` subcommand
prints, per o32 section, whether it holds the exception RVA and what its bytes parse to,
so a table in sec3 (`atlce400.dll` in A, `nk.exe` and the updaters in B/C) is shown to be
index-independent instead of assumed.

Falsifier (stated before the run): if any module of A/B/C that *has* an exception
directory fails to yield an ascending table, or if the by-index pick (sec2) for
`atlce400.dll`/`nk.exe` yields a table that is not visibly wrong, the "every module, by
the directory" claim is false for that module. A census that reports a corrupt table as
`NO-PDATA`, or exits 0 on it, also refutes the NO-PDATA/ERROR split.

## Interpretation

- **FACT:** One committed command, `census`, prints a record count for every module of
  build A (149), B (91) and C (88) of `archive/head256.img`; the totals are 87,530 /
  21,930 / 25,243 records, 0 `NO-PDATA` and 0 `ERROR` rows per build. This is the
  re-runnable form of the totals C-3612 registered from a heredoc loop.
- **FACT:** `NO-PDATA` means exactly the e32 exception directory `(0, 0)`. A corrupted
  compressed table is `ERROR`, counted in its own bucket, and exits 2; it is never
  rendered as `NO-PDATA`.
- **FACT:** The table's section is not derivable from an index: build A's sec2 pick for
  `atlce400.dll` decodes to an `UNSORTED` stream while the exact-RVA sec3 holds the 270
  records; build B's `nk.exe` table is plain sec3 and `aerhd.dll`'s exact plain sec2 wins
  over the shadowing compressed sec1 (also `UNSORTED`). 14 module/build pairs keep the
  table outside sec2 (A 1, B 10, C 3), and every one is chosen by the directory entry.
- **OBSERVED:** The cold census is expensive because it runs the kernel decompressor in
  PySh4: A 138.47 s, B 41.50 s, C 44.33 s cold; 0.35 / 0.31 / 0.31 s with the decoded
  slices cached. The counts-only fixture check is 0.38 s warm and exists as a CI
  speed-up, not as the evidence for any count (the live `census` run is).
- **OBSERVED:** The M1.23 wire-up is live and needed no change here: all four `--to`
  spot checks print a `[pdata]` holder, `sh4scan` tags the pdata START, and
  `reader_precheck` labels holders (it prints the same starts `pdata.py fn` gives, e.g.
  `0x003ebd44`/`0x003ebe70` for the anchor's loads).
- **HYPOTHESIS:** none.
- **UNKNOWN:** whether any module in the US 2011 build lacks an exception directory; that
  build is outside this sample (M1.22 owns its census).

## Conclusion

`tools/pdata.py` now carries the census in the repo: `census IMG [--image-start S]` walks
the TOC, prints `module records section compressed`, and separates `OK` / `NO-PDATA` /
`ERROR` so a broken table can never masquerade as "no pdata" (corrupt-head control: exit
2, `1 errors`, `0 without`). `where` shows why the index is not the locator: the sec2
pick decodes `UNSORTED`, the exact-RVA section is `sorted`. `--check-fixture` pins the
counts for CI in 0.4 s against `tools/fixtures/pdata_census_2011.json` (counts only), with
the live census as the recorded evidence. `docs/research/claims.md` gains C-3510–C-3519
scoped to the census/fixture/selftest; C-3610–C-3619 (M1.23) remain the wire-up claims and
are not restated. No code in `sh4xref`/`sh4scan`/`reader_precheck` changed: the spot checks
confirm the wire-up that M1.23 landed.

## Corrections after navigator review

Round 1 (navigator, 2026-11-17) changed seven things in this record and the tool, all
applied here:

1. **`census` did not exist** in the first plan's reading of the tool suite; it was added
   with the `OK`/`NO-PDATA`/`ERROR` split, and `gaps()`'s old conflation (a raised
   `PdataError` became `([], None)` and the caller's "no function table available") was
   fixed: only a new `NoPdata` (e32 `(0, 0)`) returns "no table", a decode/sort error now
   propagates and exits 2. The negative-control section above shows both.
2. **The four negative controls** (unsorted, synthetic `(0,0)` exit 0, corrupted
   compressed table non-zero and not `NO-PDATA`, fixture drift) are all present, three as
   commands and all four as selftest checks.
3. **Denominators and the split** are quoted from the census output (`149 with / 0
   without`, `91/0`, `88/0`), never typed.
4. **Index independence** is proven with `where --try-index 2` on `atlce400.dll` (sec2
   `UNSORTED`, sec3 `sorted`) and `--try-index 1` on `aerhd.dll` (B), not with a table
   print alone.
5. **Evidence order:** the live `census` run is the recorded command; `--check-fixture`
   appears in Method and in the fixture control, and no Done-when evidence cell cites it.
   Runtime was measured first (A cold 138.47 s, B 41.50 s, C 44.33 s; warm 0.35/0.31/0.31
   s, fixture check 0.38 s) and the fixture kept only as a CI speed-up, with the live
   census as the claim's evidence.
6. **Claims** are census/fixture/selftest only, explicitly scoped as supplying the
   re-runnable census C-3612/13/14 lack; C-3610–C-3619 (M1.23) are not restated, and
   neither M9.38 nor M3.23 is touched.
7. **Positive control** is the Navi.exe pin (7,596 / `0x0032ed9c` / last end
   `0x00558300`) plus `fn 0x004125a8` START; the record states per spot check which VA's
   start is asserted versus which holder the `--to` line prints (`0x004125a8` is a START,
   its holder is `0x00413a6c`).
