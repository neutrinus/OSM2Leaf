## Question

`mkcard.py`'s fresh-build path (used for any changed tree) rebuilt the FAT32
map partition but never wrote the attr-`0x08` root volume-label entry and
re-ordered the root with an ad-hoc `preferred` list. The factory EU root slot 0
is `QSD-309-101` (attr `0x08`, EXP-2026-11-06-H6) and the factory US root slot 0
is `QSD-301-103` (PM check 2026-11-06; the US BPB label is `NO NAME`). Can a
fresh build keep the source label entry and the source root order, report what
it preserved, and expose `--label` / `--preserve-root-order` controls?

## Hypothesis

If `build_fresh_partition` reads the source root directory before wiping the
partition, it can (a) copy the exact 32-byte attr-`0x08` label slot to root
slot 0, (b) emit live root entries in source order for names also present in
the tree, and (c) append new names after them alphabetically. The BPB label
(`BS_VolLab`) is copied with the reserved sectors and must stay independent of
the root label entry, because the US card has BPB `NO NAME` with root
`QSD-301-103`.

## Method

```bash
python3 -m py_compile tools/mkcard.py
python3 tools/mkcard.py --selftest
python3 tools/selftest.py --only mkcard

# synthetic fresh build (fixture created with mkcard.make_synthetic_image,
# files written in non-alphabetical order MMAIN001.DAT, BICON001, CMP.LST)
python3 tools/mkcard.py --from-image src.img --tree tree -o out.img --verbose
python3 tools/mkcard.py --from-image src.img --tree tree -o out2.img \
  --label QSD-999-999
python3 tools/mkcard.py --from-image src.img --tree tree -o out3.img \
  --no-preserve-root-order

# read back root slot 0 and live order with root_layout()
```

## Interpretation

- **FACT (synthetic):** `build_fresh_partition` now reads the source root before
  rebuilding and writes the source attr-`0x08` label slot byte-for-byte as root
  slot 0; the selftest reads back name and attr.
- **FACT (synthetic):** with `--preserve-root-order` (default), live root
  entries present in both tree and source are emitted in source order; names
  new to the tree are appended alphabetically. The report names the label and
  the preserved count.
- **FACT (synthetic):** `--label` writes a new attr-`0x08` root label entry and
  flags a mismatch against the source label; the BPB `BS_VolLab` stays the
  copied source value, matching the factory US case (root `QSD-301-103`, BPB
  `NO NAME`, PM check 2026-11-06).
- **OBSERVED (elsewhere, not re-measured here):** factory EU root slot 0 is
  `QSD-309-101` attr `0x08` (EXP-2026-11-06-H6); factory US is
  `QSD-301-103` attr `0x08`. No factory image exists on this machine, so the
  real-image fresh build was not run in M5.12b.
- **UNCHANGED:** the fresh path still re-lays out the FAT and does not
  reproduce factory allocation, LFN quirks, deleted slots or timestamps
  (EXP-2026-11-06-M5.10). For the hardware S1/S2 cards `imgpatch.py` (M5.13)
  remains the path; M5.12b only removes the label/order defect from the
  compiler path (M5.11).
