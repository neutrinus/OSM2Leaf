## Question

Do the motorway-pure/near-pure `LCTBL001` `class_code` values observed by M4.17 (C-1824/C-1825) co-vary, at better-than-null rates with a stable join key and corpus size, with any decodable RDSTM/LCTBL link attribute, so M4.2/M5.3 get a narrower, falsifiable hypothesis than "class_code is the class"?

## Hypothesis

Probe, with a falsifier and Stop. Hypothesis: pure `class_code` groups (notably `0x2775`, motorway-only in EU 2011 joined rows per M4.17 Table B) co-vary with a decodable routing/link attribute in RDSTM or tile section-2 data, suggesting a partial class hint. Falsifiers: (a) no stable join key exists between LCTBL records and RDSTM links on available samples (Stop: set `blocked`, name the missing join; do not guess by row order); (b) a tested attribute shows no better-than-null co-variation with pure groups under the stated join key and corpus; (c) an apparent co-variation is explained by record identity/format confounds rather than a link attribute.

## Interpretation

- **FACT (precheck):** M4.17 Table B is reproduced on the pinned EU 2011 sample (420 joined rows, 96 roads; `0x2775` motorway 23, `0x283c` mixed 225; selftests OK).
- **OBSERVED (join candidates):** No stable join key was found between LCTBL001 name records and RDSTM *links* (routing graph/section-2 entries) on available samples. LCTBL records lack coordinates/country/mesh/parcel/link identifiers (M4.18, C-1827); tile section-2 entries lack road-number/name/LCTBL identifiers (M4.23). The semantic road-number join to RDSTM001 TMC field 2 is not available because RDSTM001 C-884 record framing is not reproduced offline (C-2304) and RDSTM001 is TMC, not routing links (C-885/C-887). Fixed-row RDSTM001↔LCTBL is negative (C-901).
- **OBSERVED (bounded, within-LCTBL):** Under record-identity join (same record, n_pure=23, n_mixed=225, total 420), `0x2775` rows have constant `attrs=b'\x01\x00\x00\x00\x00\x00\x00'` and `footer_len=2`, differing from the mixed `0x283c` distribution on those fields. This is a decodable LCTBL-attribute co-variation, not an RDSTM/link-attribute correlation, and is confounded by code group, road identity, small n (4 roads), and M4.17's negative LORO/C-1823 evidence.
- **HYPOTHESIS (narrow, falsifiable):** `LCTBL001` `class_code` groups such as `0x2775` may correspond to a distinct record subtype/attribute bundle (attrs/footer profile), but this is not a routing-link class hint until (1) a stable join to decoded routing links exists and (2) the bundle separates by controlled road class rather than by code/numbering group. Not a generator encoding.
- **UNKNOWN:** The join from LCTBL road numbers/records to decoded RDSTM001 TMC records (needs C-884 directory reproduction or a validated parser) and from LCTBL records to MAPAL/tile routing links; whether tile section-2 `class word`/link attributes correspond to any LCTBL field; footer/attrs semantics (M4.18 follow-ups); non-Polish/EU-wide control for `0x2775` attr bundle.

## Conclusion

M4.31 is **blocked** by the task Stop condition: no stable join key exists between LCTBL001 records and RDSTM/routing links on available samples. The missing join is named as: (1) **LCTBL record → RDSTM001 TMC record/link field:** semantic by road number but unavailable because C-884 per-record directory framing is not reproduced offline (C-2304) and RDSTM001 is a TMC table, not a routing link table (C-885/C-887); (2) **LCTBL record → MAPAL tile section-2 routing link/entry:** no shared decoded identifier (LCTBL has no coordinates/country/mesh/parcel/link id; tile entries have no LCTBL/road-number ref). Row order was not used. M4.17 Table B was reproduced (precheck). A bounded within-LCTBL record-identity analysis found `0x2775` co-varies with an attr/footer profile, but this is not a decodable RDSTM link attribute and is confounded (small n, C-1821/C-1823/C-1827); it yields no generator hint for routing links. M4.2/M5.3 still lack a stable LCTBL↔routing-link join key.
