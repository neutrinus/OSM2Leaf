## Question

Can the engine run `rotcl Rn` (`0x4n24`) and `rotcr Rn` (`0x4n25`) so that the
firmware's own 32-bit divide routines in `nk.exe` run with no tool-local shim,
without changing any other instruction?

## Hypothesis

Manual: `ROTCL`: T ← Rn[31], Rn ← (Rn << 1) | old T; `ROTCR`: T ← Rn[0],
Rn ← (old T << 31) | (Rn >> 1). If transcribed right, `div1_l3.py run`
gives the M9.48 matches (srem/udiv/urem/sdiv) with the shim counters at 0.
**Falsifier:** any shim counter > 0, any of the four runnable routines
matching no oracle (or a different one than M9.48), `isolate` naming a form
other than `rotcl`/`rotcr`, or `compare` reporting a disagreement or drift.

## Method

1. **Sample and hash.** The two IMG256 files above; corpus = pdata-covered
   halfwords (M9.37 definition): EU2011 `Navi.exe` 1,092,177 instructions,
   EU2011 `nk.exe` 120,797, US2011 `Navi.exe` 1,071,258.
2. **Commands.**

   ```bash

   python3 tools/l3_harness/decode_audit.py --selftest

   python3 tools/l3_harness/div1_l3.py run archive/head256.img nk.exe --image-start 0x3e00200
   python3 tools/l3_harness/div1_l3.py run archive/head256.img nk.exe --image-start 0x3e00200 --mq-blind
   python3 tools/l3_harness/div1_l3.py run archive/us256.img   nk.exe --image-start 0x3e00200

   python3 tools/l3_harness/decode_audit.py census  archive/head256.img Navi.exe --image-start 0x200200 --engine-module /home/user/scratch/m9.50/engine.before.py
   ```

   (`census` with and without `--engine-module` on the other two corpora the
   same way.)
3. **Controls.**
   *Positive:* `engine.py --selftest` rows: `rotcl`/`rotcr` with Rn = r11,
   T in = 1 (carried-in bit visible, T out = 0) and with Rn = `0x80000001`,
   T in = 0, SR `0x40000300` (T out = 1, other SR bits kept); the manual's
   unsigned/signed divide sequences in `_divide_32` now run `rotcl` in the
   engine (before: on the host). On the image, `run` on 20 operand pairs.
   *Negative:* a scratch copy of the new engine with the two arms removed
   must fail the self-test; `run --mq-blind` must make every match disappear
   (the routines really go through `div1`).
   *Isolation:* `isolate` over 61,440 non-FPU halfwords, 4 register states.
4. **Scope.** `rotcl`/`rotcr` only. `rotl`/`rotr` (`0x4n04`/`0x4n05`) are
   not touched (not needed by these routines). FPU (`0x88041244` stops on
   `0xf04c`) and the divisor-zero path are not covered.
5. **Falsifier.** As in Hypothesis, stated before the runs.

`div0u/div0s + 32 x div1 divide like C …: system opcode 0x00004224 … is not
modelled`. `sh4dis.py --selftest` OK (new: `rotcl r3`, `rotcr r4`,
`operands(0x4324) == ("rotcl", 3, None)`); `decode_audit.py --selftest` OK;
`div1_l3.py --selftest` OK (new: synthetic udiv runs `rotcl` 33 × 20 times

## Interpretation

- **FACT:** the engine runs `rotcl`/`rotcr` per the manual; the firmware's
  `nk.exe` udiv/urem/sdiv/srem (EU2011, and the identical US2011 code) return
  the C result on 20 pairs with every instruction in the engine (shim 0).
- **FACT:** only `rotcl` (16) and `rotcr` (16 halfwords) change outcome
  against `cc15728`; `compare` stays 0 / 0 on the three corpora.
- **INFERENCE:** an L3 target that calls these divide helpers no longer
  stops at the first `rotcl`; it can still stop at `0x88041244`'s FPU form.

## Conclusion

`rotcl`/`rotcr` are modelled; `div1_l3.py run archive/head256.img nk.exe`
prints `4/4 runnable functions match` with `rotcl(shim)=0 rotcr(shim)=0`;
`isolate` lists only `rotcl`/`rotcr`; `compare` 0 / 0 on EU2011 Navi, EU2011
nk, US2011 Navi. Claims C-5310–C-5314.
