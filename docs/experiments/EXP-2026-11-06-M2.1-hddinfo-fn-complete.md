## Method

SH-4 listing by `rizin -e scr.color=0 -a sh -b 32 -m 0x004e7b8c` on a slice extracted at the `va2file` offset (`0x004e7b8c` → file `0x01165d8c`). Pool words and PC-relative loads decoded from raw bytes (SH-4 `mov.l @(disp*4,pc)` EA = `(PC & ~3)+4 + disp*4`; `mov.w @(disp*2,pc),r0` EA = `PC+4 + disp*2`). Cross-check: every COREDLL ordinal name matches the M1.9 `--resolve-with` / C-1710 result.

## Observations

### 1. Function, prologue, arguments, return

- **Function VA:** `0x004e7b8c` (prologue at `0x004e7b8c`; `rts` at `0x004e7cfa`, delay `mov.l @r15+,r8` at `0x004e7cfc`; frame unwind loads `mov.w @(0x034,pc),r1` from pool `0x004e7d20` = `0x0080` and restores pr/r13-r8). Range `0x004e7b8c..0x004e7cfc`.
- **Arguments (SH-4 calling convention, verified by use):** `r4` = caller-supplied object/device pointer, **saved nowhere and never read** before being overwritten (`r4` is set to `r10`/path/logger args at `0x004e7bcc`/`0x004e7bec`/`0x004e7bf2`/`0x004e7bfe`…). `r5` = **source selector** (`r9`, saved at `0x004e7b9e`; tested `tst r9,r9` at `0x004e7bde`, `cmp/eq #1,r0` at `0x004e7be4`). `r6` = **output struct base** (`r8`, saved at `0x004e7b9c`; `tst r8,r8` at `0x004e7bf4`, NUL-guard). `r7` unused.
- **Return:** `r0` = `r8` on the normal exit paths (1 = success after 6 lines parsed and file closed at `0x004e7ce0`-`0x004e7cea`; 0 = failure paths that set `r8=0` at `0x004e7c02`/`0x004e7c50`/`0x004e7d0c`/`0x004e7d1a`). The `bra 0x004e7ce8`/`bra 0x004e7d0a` paths converge on epilogue with `mov r8,r0` at `0x004e7cea`.
- **Frame/temps (base register = `r15` after `add 0x80,r15` at `0x004e7b9a`; i.e. a 0x80-byte local area below the saved regs):** `r10 = r15+0x40` (line buffer, set `0x004e7bb8`/`0x004e7bbc`), `r12 = r15+0x10` (dest-pointer descriptor table, `0x004e7ba0`/`0x004e7ba4`), `r13 = r15+0x28` (max-length descriptor table, `0x004e7bb0`/`0x004e7bb4`). `r11` = open `FILE*` handle after `_wfopen` (`0x004e7c44 mov r0,r11`).

### 3. Buffer layout (base register, offsets, lengths)

All base `r15` after the `add 0x80,r15` frame adjust (`0x004e7b9a`). `r10 = r15+0x40`, `r12 = r15+0x10`, `r13 = r15+0x28`, `r8` = output struct (arg `r6`).

**Line read buffer (stack, base `r10 = r15+0x40`, 0x40 bytes / 0x20 wchar):**
- `0x004e7bc8 mov #0x40,r0`; `0x004e7bdc` (delay of `jsr memset`) `mov.w r11,@(r0,r15)` with `r11=0` → stores `0x0000` at `r15+0x40` (first `wchar_t` NUL).
- `memset` at `0x004e7bda`: `r4 = r10` (`0x004e7bcc`) + `2` (`0x004e7bd6`) = **`r15+0x42`** (dest), `r5 = 0` (`0x004e7bd4`), `r6 = 0x3e` (`0x004e7bd0`). So `memset(r15+0x42, 0, 0x3e)` plus the leading word zero = the 0x40-byte line buffer at `r15+0x40` is cleared.
- `fgetws` at `0x004e7c5a`: `r4 = r10 = r15+0x40` (buffer), `r5 = 0x20` (`0x004e7c56`, 32 `wchar_t` count), `r6 = r11` (`FILE*`). `fgetws(r15+0x40, 0x20, file)`.
- `wcschr` at `0x004e7c8c`: `r4 = r10 = r15+0x40`, `r5 = 0x0d`; at `0x004e7c9e`: `r5 = 0x0a` — strips CR/LF in place.

**Output-field descriptor tables (stack):** 6 entries × 4 bytes, indexed by `r9` stepping `0,4,8,12,16,20` (loop compares `r9` to `0x18` at `0x004e7cda`). Dest pointers at `r12+r9` = `r15+0x10+r9`, filled from `r8` (`0x004e7c04`-`0x004e7c28`): `r15+0x10=r8+0x00`, `r15+0x14=r8+0x18`, `r15+0x18=r8+0x30`, `r15+0x1c=r8+0x4a`, `r15+0x20=r8+0x62`, `r15+0x24=r8+0x7a`. Max counts at `r13+r9` = `r15+0x28+r9` (`r2=0x0c` at `0x004e7c0a`, `r3=0x0d` at `0x004e7c2e`): `r15+0x28=0x0c`, `0x2c=0x0c`, `0x30=0x0d`, `0x34=0x0c`, `0x38=0x0c`, `0x3c=0x0d`.

**`wcsncpy` into the output struct (base `r8`, arg `r6`):** at `0x004e7cd4`, `r4 = mov.l @(r0,r12),r4` = dest `r8+{0,0x18,0x30,0x4a,0x62,0x7a}`, `r5 = r10 = r15+0x40` (source line buffer), `r6 = mov.l @(r0,r13),r6` = `0x0c` or `0x0d` (`wchar_t` count). `wcsncpy(dest_field, r15+0x40, max_count)`. The accept check requires measured line length `r2 < (max-1)` (`0x004e7cca add #0xff,r3` on max; `0x004e7ccc cmp/hs r2,r3`; `bf 0x004e7d0e` on too-long), so a copied line is at most `max-1` wide chars before the copy limit; `wcsncpy` is called with `max`. Prologue also clears `r8[0]` and `r8[1]` words (`mov.w r11,@r8` at `0x004e7c2a`, `mov.w r0,@(0x02,r8)` at `0x004e7c3e` with `r0=0`).

### 4. Callers (complete VA list)

`--to 0x004e7b8c` reports exactly one pool holder and two call sites:
- `pool 0x004dd1e4` holds `0x004e7b8c`
  - load `0x004dd15e` (`r3`) in `fn 0x004dd028`, `jsr 0x004dd160` → **calls `0x004e7b8c`**
  - load `0x004dd16c` (`r3`) in `fn 0x004dd028`, `jsr 0x004dd16e` → **calls `0x004e7b8c`**

No `bsr` caller exists (partial EXP). Exhaustive check: the LE dword `0x004e7b8c` appears exactly twice in `IMG256` (`92aa525d…`), at file `0x115b3e4` (build A, = pool `0x004dd1e4`) and `0x2f5b3e4` (build A duplicate copy). **Direct call-site VAs (complete): `0x004dd15e`, `0x004dd16c`**, both inside `fn 0x004dd028` (per M2.11: first call `r5=0` → `\SystemSD\VER_INFO\HDD_INFO.TXT` into stack struct at `r15+32`; second `r5=1` → `\UserSD\…` into struct at `r15+0xb8`). The only containing caller function is `fn 0x004dd028`; its callers/trigger are traced in EXP-2026-11-06-M2.11 (message `0x841000f7` from `NaviSetCC.dll`).

## Interpretation

`fn 0x004e7b8c` is a one-file, six-line wide-text reader: `HDD_INFO_read(selector r5, out r6)`. It selects `\SystemSD\…\HDD_INFO.TXT` (r5==0) or `\UserSD\…\HDD_INFO.TXT` (r5==1) via the literals at pool `0x004e7d2c`/`0x004e7d28`, opens with `_wfopen(..., mode @ 0x004e7d34)`, reads up to 6 lines with `fgetws` into a 32-`wchar_t` stack buffer at `r15+0x40`, strips CR/LF (`wcschr` `0x0d`/`0x0a`), and `wcsncpy`s each line into the 6 inline wide fields of the output struct at `r8+{0,0x18,0x30,0x4a,0x62,0x7a}` with per-field maxima `12,12,13,12,12,13` `wchar_t`. It rejects a null output, an unknown selector, open/read/length failures (logging via `sub_004dd1f0`, error codes passed in `r4`/`r5`), closes the file (`fclose`) on the success and handled-failure paths, and returns 1/0 in `r0`. The first argument `r4` is ignored (consistent with M2.11).

This resolves the M2.1 blockers: COREDLL ordinals are named (M1.9/C-1710, confirmed on `IMG256`), the line buffer is `r15+0x40` / 0x20 `wchar_t` for `fgetws` (cleared by `memset(r15+0x42,0,0x3e)` + leading word), the filled buffer is the caller's `r8` struct with the six dest offsets/`wcsncpy` maxima above, and the caller set is exactly the two `jsr` sites in `fn 0x004dd028` (no other in-image reference).
