## Question

Do the bytes that still elude `map_signals.py` after the M4.86/M4.93 wide-row
models belong to an unparsed record class, or are they a span-coverage artifact
of the metric? Which named block owns the next percentage point?

## Hypothesis

The post-s1/s4 residual consists of section-table words that
`clarion_tile.read_tile` already reads but `map_signals.tile_explained_percent`
excludes from its directory+slot span union; grading every residual range by
section/level/directory kind yields 0 B for the named record classes (a)–(c)
and the whole residual in a section-table span class (d).

**Falsifier, stated before the result (two levels).** *Baseline population:*
the unexplained 67,928,024 B / 53,155 B mass is an even scatter of padding dust,
with no dominant range. *Post-s4 residual:* no remaining range exceeds a few
hundred bytes **and** the bytes lie outside a section-table span or form a large
ungraded block — then the artifact reading is refuted and a new record block is
named. The 15,290,889 B top group is `modelled = s1_wide_dir`; it cannot refute a
falsifier about the residual, because it is already explained.

## Interpretation

- **FACT (scope):** grading covers only the post-s1/s4 `remaining` set —
  1,326 B / 2 ranges on B48 and 176 B / 3 ranges on B30. The M4.86 baseline
  populations (67,928,024 B / 71 ranges and 53,155 B / 5 ranges) are already
  attributed to `s1_wide_dir` and `section4_wide`; they are not re-graded here.
  The class sum is on **nonzero** bytes and equals `remaining_bytes` from the
  same run (`sum_ok True` in O5). The partition is deterministic: a gap
  overlapping more than one table span is assigned to the one with the largest
  inside nonzero count, tie-broken by `(section, taddr)`.
- **FACT:** every one of the five graded ranges overlaps exactly one section
  table span and has `inside_nz == bytes`, `outside_nz == 0` (O3–O5). The
  classes are a = 0, b = 0, c = 0, d = 1,326 / 176, other = 0. No unparsed
  section-3/5 record block, no leftover section-4 wide-row residual and no
  padding/slack was found in the residual.
- **FACT (trap):** the injected 4,096 B `0xa5` control has the section-4 /
  `0x1046` nearest-mark context and still lands in `other`, not (b) (O6). A
  section+kind-only rule would have silently absorbed it.
- **SCOPED NOTE:** class (a) = 0 B means only that no such block exists in
  these two grid tiles — not that no reader exists. `tools/lev3456.py` (M4.11,
  C-990–C-998) reads levels 3–5 of `LEV3456R.DAT`, a different file that is
  outside this corpus. No new reader VA is claimed (rule 13).
- **SCOPED NOTE:** class (d) is a **metric span artifact**, not a new record
  class and not a firmware-reader claim. `clarion_tile.read_tile` already reads
  those table words; `map_signals.tile_explained_percent` simply counts only
  directory+slot spans. No reader VA is asserted for it.
- **Falsifier resolution:** at the baseline level the even-scatter conjunct is
  refuted (rank 1 = 15,290,889 B in 13 ranges, `modelled = s1_wide_dir`), but
  that group is *already explained* and says nothing about the residual. At the
  residual level the "no range above a few hundred bytes" conjunct **is met**
  (686 B / 117 B) and the bytes are inside table spans, so the second conjunct
  ("outside a table span or a large ungraded block") is not met. The lead is
  therefore closed as a span-coverage artifact, not by naming a new class.
