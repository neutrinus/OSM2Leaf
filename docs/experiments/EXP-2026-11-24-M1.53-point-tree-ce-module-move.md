  SHA-256 `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`;
  factory POINT pairs

  Full-card SHA-256 `105e2032e480e8ba162a2a9d4b6624cb1dafee380379a9908f3f101b15076307`.
- **Tools:** `python3 3.15.0` (default); `python3.13 3.13.17` (default-argv

  `tools/nk_decomp.py`, `tools/cerom.py`, `tools/selftest.py`, `tools/l3check.py`.
  The byte-identity claim is an **invariant-blob anchor** (the two walkers map

## Question

Can `Firmware.__init__`'s hand-rolled `STDDLL.dll` section walk in
`tools/point_tree_l3.py` be moved onto `ce_module.module_sections` (the M1.47
falsifier) leaving the tool's output byte-identical on the factory image, with
the `nk_decomp` duplicate count in `*_l3.py` reduced from 3 to 2?

## Hypothesis

`ce_module.module_sections(image, 0x200200, "STDDLL.dll")` is eager at this
image start and decodes each compressed section through the same kernel routine
(`nk_decomp.section_bytes` / `section_init`) the hand-rolled loop calls via
`nk_decomp.decompress`. Its `blob` of length `vsize` is the hand-rolled
`data[:r0]` plus zero BSS; mapping it with the same 4 KiB page pad the
hand-rolled loop applies gives identical section bytes in the engine, so the run
is byte-identical. **Falsifier:** any `cmp` DIFF between before/after captures
on the same image/pairs/tree/argv, a section prefix DIFF or non-zero tail in
the blob anchor, a `point_tree_l3`/full `selftest` going red, `nk_decomp` in
`Firmware.__init__` not reaching 0, or the duplicate count not dropping 3→2.

## Method

### 1. Sample and hash

Use `archive/head256.img` and the named factory POINT010 pairs; confirm
`sha256sum archive/head256.img` equals `92aa525d…a007f9`. Set a fresh
`OSM2LEAF_DECOMP_CACHE` per capture (anchored under the task scratch) so the
decode cache cannot mask a difference (M1.47 method step 2).

### 2. Commands

BEFORE capture on the claim commit (`1378f610`), AFTER capture on the work
commit — same tree, same argv, same image, same pairs; fresh empty cache each
time. The **exact chosen argv is `--tree 0 --cells 30`** (an ACCEPT capture);
the literal Done-when default (`--tree 0 --cells 50`) BLOCKS before any change
— see Observations.

```bash
IMG=archive/head256.img
F=/home/marek/projekty/leafre-work/m5.13/factory/REFER001
S=/home/marek/projekty/leafre-work/scratch/m1.53

# BEFORE (claim commit) and AFTER (work commit), each with a fresh cache:
for tag in before_a after_a; do
  mkdir -p "$S/$tag"
  OSM2LEAF_DECOMP_CACHE="$S/$tag/cache" \
    python3 tools/point_tree_l3.py run "$IMG" --dir "$F" --file POINT010 \
      --tree 0 --cells 30 --json "$S/$tag/out.json" > "$S/$tag/stdout" 2>&1
done
cmp "$S/before_a/out.json" "$S/after_a/out.json"     # silent = identical
cmp "$S/before_a/stdout" "$S/after_a/stdout"         # silent = identical

# invariant-blob anchor (no zlib): hand-rolled data[:init_len] vs ce_module
# blob prefix, plus zero tail check:
OSM2LEAF_DECOMP_CACHE="$S/anchor-cache" python3 -c '
import hashlib, sys; sys.path.insert(0, "tools")
import ce_module, point_tree_l3 as pt
img = ce_module.load_image("archive/head256.img")
fw = pt.Firmware(img)
rich = ce_module.module_sections(img, 0x200200, "STDDLL.dll")
for (n, va, hand, p), (i, cva, vs, ps, comp, ex, il, blob) in zip(fw.std, rich):
    k = min(len(hand), len(blob))
    print(n, hex(va), "init", il, "comp", comp,
          "prefix", "OK" if hand[:k] == blob[:k] else "DIFF",
          "zero-tail", set(hand[k:]) <= {0},
          hashlib.sha256(blob[:k]).hexdigest()[:24])'

python3 tools/point_tree_l3.py --selftest                 # selftest OK (14 checks)
python3 tools/ce_module.py --selftest                     # selftest: OK
python3 tools/selftest.py                                 # full suite
grep -n 'nk_decomp\|IMAGE_SCN_COMPRESSED' tools/point_tree_l3.py   # no match after move
grep -c 'nk_decomp' tools/point_tree_l3.py                # 0 after move
grep -rln 'IMAGE_SCN_COMPRESSED' tools/*_l3.py | wc -l    # 3 -> 2
python3 tools/l3check.py --build-corpus                   # unchanged runnable count
```

### 3. Controls

- **Positive:** `--tree 0 --cells 30` twice with fresh caches gives `RESULT:
  ACCEPT`, identical JSON (SHA-256 `2b736cb2bdc336dacf1e6316ea7e0842c4952aebff4560f9206a6967929c6366`)
  and identical stdout (SHA-256
  `00770311cfba3fcfe0e60d80a8949b58c3b1a4d976e4295a2d03a058a6e7bdb4`).
  The invariant-blob anchor: all 4 STDDLL section prefixes compare `OK` and
  all four tails are zero.
- **Negative / mandatory mutation:** deliberately alter one byte in the
  captured JSON (`file` field) and run `cmp` against the BEFORE capture —
  `cmp` must fail (nonzero). Separately, flip one byte of a mapped STDDLL code
  section and confirm the blob changes (`differ True`), showing the anchor is
  sensitive to real byte differences. Both were run; commands and output in
  Observations.
- **Helper negative (M1.47):** `ce_module --selftest` covers a fake decoder
  raising `DecompError` (a failed decode raises, never a silent `None`).
- **Rule 11:** the real image is present; no vendor bytes are committed.

### 4. Scope

Only `Firmware.__init__`'s STDDLL walk in `tools/point_tree_l3.py`; one image
start (`0x200200`), one module (`STDDLL.dll`), 4 sections (1 uncompressed code,
2 compressed data, 1 uncompressed data), one POINT file (`POINT010`), one tree
(`--tree 0`). Out of scope: `vcard_l3.py:324` (loader total), `va_class.py`
(classifier), `ce_strfind.py` (different `module_sections` over `cecompress`
statuses). The helper's `init_len` is the stored byte count; `blob` is
`init + zero BSS` of `vsize` bytes, so `self.std` pads to
`(vsize + 0xFFF) & ~0xFFF` to keep the engine's mapped region byte-identical.
`ce_module` is extended/reused, not forked.

### 5. Falsifier

Any byte difference in the before/after JSON or stdout on the same argv; a
section prefix DIFF or non-zero tail in the blob anchor; `point_tree_l3.py
--selftest` or `tools/selftest.py` going red; `grep -c nk_decomp` in
`Firmware.__init__` not reaching 0; or duplicate count not dropping 3→2.

## Interpretation

- **FACT:** the new `Firmware.__init__` uses `ce_module.module_sections`,
  contains no `nk_decomp` reference (grep count 0), and the duplicate section
  walker count in `*_l3.py` drops from 3 to 2. An assertion keeps the
  `0x20000000` exec-flag citation that the removed direct flag test carried,
  so the frozen `fn_audit` docs corpus stays at `0 new / 0 gone`.
- **FACT:** before and after captures on the same image/pairs/tree/argv are
  byte-identical (JSON and stdout SHAs equal; `cmp` silent), and both are
  `RESULT: ACCEPT`.
- **FACT:** the four mapped STDDLL section byte prefixes are identical between
  the two walkers and all tails past the initialised bytes are zero, so the
  only structural difference (page-pad length of the data sections) carries no
  non-zero bytes.
- **OBSERVED:** the literal `--cells 50` default blocks the engine on this
  image before *and* independent of the move; the deterministic `--cells 30`
  capture is the valid byte-identity oracle and is unchanged by the move.
- **HYPOTHESIS:** the remaining two `IMAGE_SCN_COMPRESSED` sites
  (`chunk_decoder_l3.py`, `vcard_l3.py`) have different loader/classifier shapes
  and stay out of scope, as M1.47 found.
- **UNKNOWN:** the engine's `last pc 0x0346d1ae` infinite loop at higher cell
  counts was not diagnosed (out of scope; same before and after).

## Conclusion

Moved the `Firmware.__init__` STDDLL section walk in `tools/point_tree_l3.py`
onto `ce_module.module_sections`; the direct `nk_decomp` call and
`IMAGE_SCN_COMPRESSED` test are gone from that method. The tool's output on the
EU2011 factory image is byte-identical before and after (same JSON/stdout SHA
at `--tree 0 --cells 30`), `nk_decomp` count is 0 and the duplicate count is 2.
`ce_module` was reused, not forked. No format/claim rows beyond C-8270–C-8277
changed; the remaining two `*_l3.py` section walkers are a documented
follow-up, not a regression from this move.
