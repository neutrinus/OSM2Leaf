## Question

Does the S1 card (US factory card with a no-op recompressed `POINT010`) reach the same L4 launcher verdict as the factory US card, and does it cause the firmware to read a different set of files, on the same `-M ze0` recipe?

## Hypothesis

S1 is indistinguishable from factory at L4: same F0–F4 verdict, `ACCEPT`/`OPENED`, and an empty files-read diff. **Falsifier from the task:** the S1 card stops earlier than the factory card (a lower stage or a named reject marker). **Second falsifier:** a different set of files read between the two cards. **Gate-teeth control:** a card mutation that does *not* fail F4 voids the comparison.

## Interpretation

- **FACT:** the S1 card boots to exactly the same L4 verdict as factory: F0–F4 PASS, `ACCEPT`/`OPENED`, 0 map-data errors, 0 launcher reject markers, `Navi.exe` created on both (C-8070, C-8071). The task's falsifier (S1 stops earlier) is refuted.
- **FACT:** the two cards read the same 13 files with the same per-file ranges, counts and bytes (C-8072). The files-read diff is empty, as expected; this is a *no-op* control because the recompressed pair is byte-identical to factory (C-8073).
- **FACT:** the gate has teeth: the same card with a wrong declared unit map code fails at F4 with `VerInf mismatch`, `Error Proc` and `FailSafe.exe Start` (C-8074). The comparison is therefore not a vacuous pass.
- **OBSERVED:** F5 (`Finish Launch Threads`) is 0 on both cards; the US build never reaches it (M8.H12 O5), so it is NOT RUN and informational, not a card verdict (C-8075). `POINT010` is not read in this capture window — only `POINT001` — so this run does not exercise the changed file's bytes; it establishes that the change does not perturb the boot's file-read set or verdict (C-8076).
- **OBSERVED:** the custom 25-line IPL patch stalls the US boot equally on both cards; the minimal IPL recipe is required for the milestone capture (C-8077).
- **UNKNOWN:** L5/car acceptance (M6.5 hardware) and whether a *content-changing* S2 card would be accepted; out of scope here (C-8078, C-8079).

## Conclusion

Both the factory US card and the S1 no-op-recompression card pass F0–F4 with identical `ACCEPT`/`OPENED` verdicts and an empty files-read diff (13 files, same ranges) at L4; the negative control fails loudly at F4. The result is linked from M6.5's Input field. No format doc changed. This is L4 emulator evidence only; M6.5 on hardware remains the acceptance oracle. Claims C-8070–C-8079 record the verdicts, the file sets, the control and the scope.
