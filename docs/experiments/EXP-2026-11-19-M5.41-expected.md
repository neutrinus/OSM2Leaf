## Question

Does the report tell a reader the *one* expected-change-set of a correct
one-tile run, or do `changed_set_expected` and the tree gate disagree on
`DRSTR001.DAT`?

## Hypothesis

`build_factory_out` wrote `changed_set_expected = ["MAPAL001/<cell>.DAT"]`
while the run changes and the gate accepts two files (the tile and
`DRSTR001.DAT`). A reader that trusts `expected` would read a correct run as
wrong. **Falsifier:** on the M5.34 run `changed_set_expected` and the set the
gate accepted are not equal, or after the fix a correct run still has
`expected ⊉ actual`, or an unexpected out-only file survives a gate PASS.

3. **Controls.** *Positive:* the M5.34 report reproduces the defect —
   `changed_set_expected` has one path, `tree_diff.differing_files` has two,

## Interpretation

- **FACT:** before this change `changed_set_expected` was `['MAPAL001/B48R058R.DAT']`
  while the same run's `differing_files` were `['DRSTR001.DAT',
  'MAPAL001/B48R058R.DAT']` and the gate accepted both (the old report says
  `unexpected: []`, `tile_plus_manifests_only: true`).
- **FACT:** after this change `changed_set_expected` is the 2-path set
  `['DRSTR001.DAT', 'MAPAL001/B48R058R.DAT']`, `changed_set_actual` equals it,
  and `expected_superset_of_actual` is `true`; the run is byte-identical
  (same tile SHA and counts) to M5.34.
- **OBSERVED:** the informational union (`changed_set`) is still 198 paths
  (tile + 197 rebuilt) — wider than the expected set; the gate's allowlist is
  the separate 3-name `allowed_manifests` and did not grow (`allowed_but_unchanged`
  is 196, and a content-differing `.ind` still FAILs the gate in selftest).
- **HYPOTHESIS:** `DRSTR001.DAT` is expected because it carries the tile's
  size word and the `MAPAL001` directory value word; `MMAIN001.DAT` and
  `CMP.LST` are re-emitted identically and are only allowed. (C-3563 records
  the two differing files; M5.42 refines the 7-byte `DRSTR` diff.)
- **UNKNOWN:** whether any future card gate outside this module reads
  `changed_set_expected`; `grep -rn changed_set docs/ tools/` finds no other
  consumer on this branch.

## Conclusion

One `expected_changes(cell, rebuilt)` helper now defines the three sets in one
place: `expected` = the tile and `DRSTR001.DAT` (the 2-path Done-when literal),
`allowed_but_unchanged` = the rebuilt manifests that may be re-emitted
byte-identically (`MMAIN001.DAT`, `CMP.LST`, the `.ind` pairs), and
`allowed_manifests` = the gate's narrow 3-name allowlist. `build_factory_out`
and `build_synthetic_out` both use it, and the factory path passes
`allowed_manifests` — not `expected` — to `one_tile_gate`, so a differing
`.ind`/`MMAIN001.DAT` stays `unexpected` and FAILs. Gate PASS conditions are
unchanged. C-4600–C-4604 record the sets, the pre-fix disagreement and the
narrow-allowlist control.
