## Question

Can the default/quick `l3_harness` selftest path used by agent/main loops be bounded while preserving a complete, honest `--full` suite, without changing harness verdict semantics?

## Hypothesis

The dominant runtime is external Ghidra/QEMU parity/execution attempted when a back end is "available" but slow or unverified (SE review observed `runner.py --selftest` / harness aggregate timeout). Skipping that external *execution* in quick mode with an explicit `SKIPPED_IN_QUICK` reason (SKIP, never PASS), while keeping the attempt in `--full` with a wall-clock bound, preserves coverage and honesty.

**Falsifier:** quick mode still exceeds a small bound (seconds) on this host, or a quick/full path reports PASS where a check was not actually run/verified, or verdict semantics change (SKIP/BLOCKED treated as PASS).

## Interpretation

- **FACT:** Quick/default interfaces for `engine.py`, `runner.py` (`--selftest`/`selftest`), `l3_harness/selftest.py`, `dispatch.py`, and `ghidra/l3_run.py` accept `--quick`/`--full` and complete within a documented sub-second bound on this host.
- **FACT:** Quick mode skips external Ghidra/QEMU execution when the probe reports an available but unverified/slow back end, recording `SKIPPED_IN_QUICK`; it still records `MISSING_*` honestly when unavailable. SKIP is never PASS.
- **OBSERVED:** On this host, qemu-system-sh4 is present but the gdbstub adapter is unverified; engine full-mode QEMU parity timed out at the 60s bound and failed loudly. Runner full-mode QEMU execution completed in 45s with an honest non-pass contract outcome.
- **HYPOTHESIS:** Full-mode external parity will pass once Ghidra/QEMU adapters are verified/functional in an environment that supports them; until then, failures/timeouts are honest and bounded.
- **UNKNOWN:** Behavior on hosts without qemu-system-sh4 (should remain fast MISSING/SKIP) and on hosts with working pyghidra/QEMU adapters.

## Conclusion

M1.18 bounds the default `l3_harness` selftest path by skipping external Ghidra/QEMU *execution* in quick mode with explicit, honest SKIP reasons, while keeping complete coverage available behind `--full` with wall-clock bounds. `tools/l3_harness/README.md` documents the interface and bounds. Verdict semantics are unchanged. `--full` exercises external back ends but may fail honestly where adapters are unverified (engine QEMU parity on this host) — that is recorded, not hidden. H38 can wire the quick path into `tools/selftest.py` selectors and pass `--full` uniformly.
