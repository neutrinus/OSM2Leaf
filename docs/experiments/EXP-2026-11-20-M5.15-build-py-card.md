## Question

Can one command — `build.py --profile profiles/dolnoslaskie-test.json
--from-image IMG --osm EXTRACT -o out.img` — write a card image, report per
file family whether it is generated / rebuilt / copied / not yet generated,
report each check's verdict, and refuse success when any check fails?

## Hypothesis

Composing the merged M5.11 path inside `build.py` reproduces M5.11's card
exactly: same tile (`1927c3a9…`), same image (`b88a31f4…`), same 42,542 diff
bytes, and every check M5.11 ran by hand passes when `build.py` runs it.

**Falsifier:** `build.py` exits 0 with a different image hash than M5.11's
for the same inputs; any check fails on that image; a failing synthetic check
still prints `RESULT: BUILT` or leaves an image; a factory tree from another
card is accepted.

## Method

1. **Sample and hash** as above.

2. **Commands** (repository root; `S` is scratch outside the repo):

```bash
IMG=/home/user/OSM2Leaf/archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img

  --from-image $IMG --osm tools/fixtures/m5.37-splice.osm -o $S/out.img \
  --factory-root $F --firmware archive/head256.img --hash \
  --report $S/build-report.json

# negative: a factory tree that is not the image's (EU tree, US image) -> exit 1, no image
python3 tools/build.py --profile profiles/dolnoslaskie-test.json \
  --from-image $US --osm tools/fixtures/m5.37-splice.osm -o $S/neg-us.img \
  --factory-root $F
ls $S/neg-us.img                                                    # expect: no such file
```

   Without `--factory-root`, `build.py` extracts the tree from the image
   itself (stdlib FAT reader; covered by the selftest, not run here to keep
   one 4.9 GB tree on disk).

3. **Controls.**
   *Positive:* the image hash must equal M5.11's independently built
   `out.img` (`b88a31f4…`, EXP-2026-11-19-M5.11); `check_diff` must give
   M5.11's 164 ranges / 42,542 B; the L3 map-code compare must ACCEPT.
   *Negative (real data):* EU tree + US image must FAIL at `factory_tree`
   before any write. *Negative (synthetic, selftest W2–W8):* a failing
   `cardcheck` or `l2check` → exit 1, `RESULT: FAILED`, image removed
   (kept only with `--keep-failed`); a change in a copied family → FAIL; an
   `HDD_CHK.ATT` on the card → FAIL; an added file → exit 3; `-o` = image,
   an existing `-o`, OSM over two directories → exit 2; a 4-tile profile →
   exit 3.
4. **Scope.** One card (EU 2011), one tile (1 of 45), one section-1
   directory; 480 files classified into 24 families. Multi-tile builds, files
   that grow beyond their cluster chain, added files and the `mkcard` full
   rebuild are refused (exit 3), not built.
5. **Falsifier** as stated before the run.

## Observations

### First run: a contract bug, refused correctly

The first real run exited **3** (`stage pipeline FAIL files added or removed:
['MAPAL001/B48R058R.DAT']`) and wrote no image (5 min 34 s). Cause:
`build.py` expected the pipeline's diff state `changed`; `one_tile_pipeline.
_tree_differences` writes `differs` (other states `extra-in-out`,
`missing-from-out`, `hash-not-compared`). The selftest stub had used the same
wrong word, so it passed. Fixed: only `differs` is patchable, the stub now
emits the real state, and selftest W7b checks that `extra-in-out` exits 3.

## Interpretation

- **FACT (C-5360):** `build.py --profile profiles/dolnoslaskie-test.json
  --from-image EU2011 --osm m5.37-splice.osm -o out.img` exits 0 and writes
  `out.img` `b88a31f4…f95fe3`, byte-identical to M5.11's hand-built card;
  `check_diff` gives the same 164 ranges / 42,542 B, all in the tile.
- **FACT (C-5361):** on that image all 8 checks PASS (readback, check-diff
  strict, `cardcheck --image`, `l2check` with `--graph-tiles`, `7z t`, no
  `HDD_CHK.ATT`, HDD_INFO = factory, L3 map-code ACCEPT EU2011 build B); 5
  gates are reported CANNOT-VERIFY-OFFLINE, not PASS.
- **FACT (C-5362):** the report classifies the 480 files into 24 families: 1
  generated (1 file), 4 rebuilt byte-identical (197 files), 7 not yet
  generated (factory kept, 96 files), 12 copied (186 files); ladder step P0.
- **FACT (C-5363):** a failing check or stage never yields `RESULT: BUILT` or
  exit 0: the real EU-tree/US-image run fails at `factory_tree` before any
  write, and the selftest covers failing cardcheck/l2check, a changed copied
  family, an attestation file, an added file and a multi-tile profile.
- **OBSERVED (C-5364):** `one_tile_pipeline`'s tree-diff state for a changed
  file is `differs`; a consumer keyed on another word refused the real build
  (exit 3) while its stub-based selftest passed. The stub now emits the real
  word.
- **UNKNOWN:** whether the unit reads the generated tile (tile reader
  unlocated, M3.6/M9.13); SD lock and MapDBVer range (unit side).

## Conclusion

`tools/build.py` now has a write mode that meets M5.15's done-when for the
first milestone (one generated tile): it builds the card from the factory
image and an OSM file, lists every family's status, runs the checks, names the
ladder step, and refuses success (exit 1, image removed) when anything fails.
It refuses (exit 3) what no writer supports yet: several tiles, added files.
Every new writer (M5.16 LEV3456R, M5.17 LCTBL, M5.18 POINT/ADDRE, P1
multi-directory) adds its family by changing the pipeline stage and the
family table. Claims C-5360–C-5364 added.
