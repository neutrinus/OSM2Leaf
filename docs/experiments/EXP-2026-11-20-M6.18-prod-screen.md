## Question

What does the LeafSDTools start screen say about the unit, and does it fit
the firmware's market (area) logic in `us-eu-region.md`?

## Method

Read the photo; map each line to the PROD-block offset that
`GetProdSection` copies it from (PROD = flash block 5 = `0xA000`, first
`0x2D1` bytes).

## Observations

| Screen line | Value | PROD offset (flash) |
| --- | --- | --- |
| MODEL | `QY7200ND` | `+0x40` (`0xA040`), 8 B |
| Product ID / ID Code | `10 20 02 12` | `+0x20..+0x23` (`0xA020–0xA023`) |
| SERIAL | (not recorded) | `+0x50` |
| SD Card PIN | (not recorded, never commit) | `+0x60`, 4 B (unit half of the CMD42 password) |
| IMMO Code | `FF FF FF FF` | `+0xA0` |
| IMMO Check Enabled | `00` | `+0x193` |

## Interpretation

- **OBSERVED (C-5200):** the unit is a `QY7200ND` (QY7 = SH-4 family, the
  LeafSDTools `sh4` build), Product ID `10 20 02 12`.
- **HYPOTHESIS, strong (C-5201):** the 4-byte firmware Target ID
  (`KernelIoControl(0x01013208)`, us-eu-region.md) is PROD `+0x20..+0x23`.
  The firmware requires byte 0 to be non-zero and not `0xFF` (here `0x10`) and
  takes byte 1 as the area (here `0x20` = USA). So the market byte is at
  flash **`0xA021`**, not `0xA022` as the external lead C-078 says
  (`0xA022` holds `0x02` on this unit, which is no area value). Confirm on the
  M6.18 dump (M6.19).
- **OBSERVED (C-5202):** IMMO code `FF…` and check `00`: the immobiliser
  handshake is disabled on this unit (LeafSDTools "Disable IMMO / SECURE
  screen"), relevant to `card-test-plan.md` `SECURE` row.
- **C-5203:** the photo is not the flash dump: M6.18 stays open for
  Read NAND + SRAM/VFlash files.
