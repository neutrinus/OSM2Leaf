## Interpretation

- **FACT (OBSERVED, on-disk):** `REFER001/INDEX003.DAT` (plain or `.cmp`/`.ind`
  pair) is absent from the EU 2011 and US 2011 stock card images examined. It is
  not present in the FAT, not named in `DRSTR001.DAT`, and not present anywhere
  else in the FAT walk. The US image carries only `INDEX001.DAT.cmp/.ind` in
  `REFER001`; the EU `REFER001` carries no `INDEX*` files.
- **FACT (firmware reference, consistent with C-880/C-2122):** the ASCII string
  `INDEX003` occurs in both raw images at early offsets (US `14679280`,
  `46136560`; EU `14648088`, `46105368`), consistent with a firmware data
  reference, but no corresponding map-data file is present on these images.
- **FACT (core question, scoped to these images):** because `INDEX003` is absent
  on these stock images, POI lookup cannot go through a second copy of the POI
  name stored in an on-disk `INDEX003` file on these images. Therefore the M5.12
  S2-style POI rename on these images does **not** need to update an `INDEX003`
  file (there is none). No `INDEX003` entry referring to `HANA HEALTH CENTER`
  (`POINT010`, page `0x840ba0`, record 0) exists on these images.
- **HYPOTHESIS:** the `0x14e8` → `REFER001`+`INDEX003.DAT` mapping (C-880) may
  target an index file present on other image versions/regions, or be unused when
  the file is absent; M3.11 did not locate a page walker consuming it in
  decodable code.
- **UNKNOWN:** `INDEX003` on-disk record layout (header, entry size/count,
  name bytes vs `POINT`-page pointers) — cannot be determined without a sample
  that contains the file. Whether any other ZE0 image version ships `INDEX003`.
