## Question

What does the type label of a 2011 LEAF navigation unit carry, and which of
its fields are the PROD record fields the firmware uses (M2.25, M2.26)?

## Hypothesis

The label prints the identity fields that the factory writes into PROD
(model, serial, Unit ID, Nissan part number). Falsifier: a label number that
does not fit the PROD field width or encoding recorded in M2.25 (`+0x50`
serial 4 bytes BCD, `+0x140` `10 01` + serial, `+0xB0` 5 ASCII characters).

Comparison with the PROD layout (M2.25):

- `車載機 ID` `1001 0000 4058` = `10 01` + `00 00 40 58`, i.e. the bytes
  `10 01` followed by the serial as 4 bytes of packed BCD. This is the shape
  of PROD `+0x140` (`10 01` + serial, 6 bytes).
- `SERIAL NO.` `0004058` fits 4 BCD bytes (`00 00 40 58`, 8 digits; the label
  prints 7).
- `N #` suffix `3NA0B` is 5 ASCII characters, the shape of PROD `+0xB0`
  (`3NA0D` on Marek's `QY7200ND`). The last letter follows the model
  suffix in both units: `QY-7200N-B` ↔ `3NA0B`, `QY7200ND` ↔ `3NA0D`.
- `MODEL NO.` `QY-7200N-B` is the `+0x40` model string with dashes
  (Marek's PROD holds `QY7200ND` without them).
- The Bluetooth module model `BTU-3588`, QD ID and FCC/IC IDs have no PROD
  counterpart found (negative control: none forced).
- No PIN or password is printed.

## Interpretation

- **OBSERVED (C-10120):** the label's 12-digit `車載機 ID` is `1001` followed
  by the 8-digit serial; this matches the PROD `+0x140` field (`10 01` +
  serial BCD), so `+0x140` is the unit ID that Clarion prints on the label
  (in `unit-flash.md` it was "meaning unknown").
- **OBSERVED (C-10121):** PROD `+0xB0` is the suffix of the Nissan part number
  `25915-xxxxx` printed as `N #`; its last letter tracks the model letter
  (two units).
- **OBSERVED (C-10122):** a second 2011 unit: model `QY-7200N-B`, built March
  2011, serial `0004058`. The serials are low sequential-looking numbers.
- **OBSERVED (C-10123):** hardware leads: Bluetooth module `BTU-3588`
  (QD ID `B014872`); FCC grantee code `SJ2` (Clarion), FCC ID `SJ2QY7200`.
  FCC filings often include internal photos, which could settle the
  "chips on the board" question in `head-unit.md` — not checked yet.
- **UNKNOWN (C-10124):** the label gives a (serial, Unit ID) pair but no PIN,
  so it does not test C-8304/C-8334 (is the PIN a function of the serial?).
  It shows only that the serial-derived numbers a seller or owner can read
  off the label are the same family of fields already ruled out as the PIN
  on Marek's unit (C-8330). What `Z7`, `NCL` and `276-0925-00` mean is
  unknown.

## Conclusion

`docs/hardware/head-unit.md` gains the photo and a field-by-field reading;
`docs/hardware/unit-flash.md` now names PROD `+0x140` (unit ID on the label)
and `+0x0B0` (Nissan part-number suffix). The PIN rule stays open: the label
is a second serial sample without its PIN, so another owner's (serial, PIN)
pair is still what M2.25's follow-up needs.
