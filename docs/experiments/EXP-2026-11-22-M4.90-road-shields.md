## Question

Where does the EU 2011 factory map store a road's reference number (`A4`,
`E40`, `B6`), what field selects the shield the renderer draws, and which
shield types exist with what counts?

## Hypothesis

The road number is one of the `;`-separated parts of the road-name text in the
odd partner record's names section (`2=REF`), and the shield type is carried
by the *syntax* of that reference (a letter/number prefix), not by a separate
binary field and not by the road class alone. Falsifier: if the shield type
were derived from the road class alone (no reference-string type and no
independent field), all references of one class would share one type and no
`N:E###` vs national distinction would be observable within a class.

## Plan

- **Approach.** (1) Decode level-1 road pairs of EU 2011 tiles with the
  checked-in viewer decoder; read the odd partner's names section and tabulate
  the raw entry words (type/flags/x/y/length) against the parsed `1=NAME` /
  `2=REF` parts. (2) Join each name entry to the even road record's shape
  header (class word `w2>>12`, name-offset word `w4`) to test whether class
  alone can explain the shield. (3) Group distinct reference strings by
  syntax, count them and take one example road per group. (4) Check section 4
  only as a second, signpost-text location of road numbers. (5) Write the
  proposed Polish `ref` mapping into `docs/research/osm-pipeline.md`.
- **Signature / format source.** The name-entry grammar comes from the
  repository's own reader `tools/ze0-viewer/ze0_decode.py` (`parse_names_section`,
  `>HHHHH` word tuple, `typ == 0x00ff`, `1=` name / `2=` ref) and its writer
  inverse `tools/ze0-viewer/tools_ze0/fa_encode.py` (`names_section`); the
  shape-header class/name fields come from `fa_encode.parse_record` and
  `tools/ze0-viewer/ze0_roads.py`. This is the writer's inverse / a checked-in
  reader, not a guessed byte grammar.
- **Files.** Read `tools/name_strings.py`, `tools/section4.py`,
  `tools/tilewriter.py`, `docs/format/map-tiles.md`; write this EXP and the
  proposed mapping paragraph in `docs/research/osm-pipeline.md` only.
- **Intended Done when.** An EXP with the field layout and a shield-type table
  (value, count, example road), plus the proposed Polish `ref` mapping in
  `docs/research/osm-pipeline.md`; the falsifier test must be reported.

   `<complete script $S/m4_90_probe.py>`:

   ```python
   #!/usr/bin/env python3
   """M4.90 road-number / shield census on EU2011 factory tiles.
   Reads only committed repo tools. No GeoJSON is built (avoids OOM on B48R058R)."""
   import collections, re, struct, sys, zlib
   REPO = "/home/marek/projekty/OSM2Leaf.task-m4.90-road-shields"
   sys.path.insert(0, REPO + "/tools/ze0-viewer")
   sys.path.insert(0, REPO + "/tools/ze0-viewer/tools_ze0")
   import clarion_tile, clarion_bg, ze0_roads
   from ze0_decode import parse_names_section
   CAT = [
       ("motorway+E",  re.compile(r"^A\d+(?::E\d+)+$")),
       ("motorway",    re.compile(r"^A\d+$")),
       ("B+E",         re.compile(r"^B\d+(?::E\d+)+$")),
       ("B-road",      re.compile(r"^B\d+$")),
       ("digit:E",     re.compile(r"^\d+:E\d+(?::E\d+)*$")),
       ("E-route",     re.compile(r"^E\d+$")),
       ("S-road",      re.compile(r"^S\d+$")),
       ("L-road",      re.compile(r"^L\d+$")),
       ("numeric",     re.compile(r"^\d+$")),
       ("dash-code",   re.compile(r"^[A-Z]{1,3}-\d")),
       ("SP-province", re.compile(r"^SP\d+$")),
   ]
   def category(ref):
       if not ref: return "none"
       for name, rx in CAT:
           if rx.match(ref): return name
       return "other-alpha" if re.match(r"^[A-Z]", ref) else "other"
   def run(path):
       tile = clarion_tile.read_tile(open(path, "rb").read())
       cats = collections.Counter(); ex = {}
       raw = collections.Counter(); refs = collections.Counter()
       cls_kind = collections.defaultdict(collections.Counter)
       cls_w3 = collections.defaultdict(collections.Counter)
       pairs = refshapes = 0
       for sec in tile["sections"]:
           for lvl in sec["levels"]:
               if lvl["level"] != 1: continue
               for d in lvl["dirs"]:
                   for row, slot in d["slots"].items():
                       byk = {r["k"]: r for r in slot["recs"]}
                       for k, rec in byk.items():
                           if k % 2: continue
                           try:
                               pl = zlib.decompress(rec["raw"]) if clarion_tile.is_zlib(rec["raw"]) else rec["raw"]
                               if struct.unpack_from(">H", pl, 4)[0] != 0xfa: continue
                               p = byk.get(k+1)
                               if p is None: continue
                               bp = zlib.decompress(p["raw"]) if clarion_tile.is_zlib(p["raw"]) else p["raw"]
                               ns = clarion_bg.parse_record(bp)["sections"].get("names") or b""
                               names = parse_names_section(ns)
                               road = ze0_roads.parse_record(pl)
                           except Exception: continue
                           pairs += 1
                           i = 0
                           while i + 10 <= len(ns):
                               typ, flags, x, y, ln = struct.unpack_from(">HHHHH", ns, i)
                               if typ == 0x00ff and 0 < ln <= len(ns)-i-10:
                                   text = ns[i+10:i+10+ln].split(b"\x00")[0]
                                   raw[(hex(typ), hex(flags), hex(x), hex(y),
                                        any(pp.startswith(b"2=") for pp in text.split(b";")))] += 1
                                   i += 10+ln+(ln&1)
                               else: i += 2
                           for layer, shs in road["layers"].items():
                               for sh in shs:
                                   w = sh["words"]
                                   if len(w) < 5: continue
                                   cls = w[2] >> 12
                                   cls_w3[cls][hex(w[3])] += 1
                                   if w[4] == 0xffff or w[4] not in names: continue
                                   nm, ref = names[w[4]]
                                   refs[ref] += 1
                                   if not ref: continue
                                   refshapes += 1
                                   c = category(ref)
                                   cats[c] += 1
                                   cls_kind[c][cls] += 1
                                   ex.setdefault(c, (ref, nm, cls))
       print("FILE", path)
       print("PAIRS", pairs, "REF_BEARING_SHAPES", refshapes, "DISTINCT_REFS", len(refs))
       print("RAW_NAME_ENTRY (typ,flags,x,y,has_2=):", dict(raw))
       print("QUERY", {q: refs[q] for q in ("A4","A4:E40","E40","B6","S8","94","DK94","ZZZ999")})
       print("SHIELD_TYPE_TABLE category|count|example ref|example name|class")
       for c, n in cats.most_common():
           r, nm, cls = ex[c]
           print("  %-13s %8d  %-13s %-28s cls=%d" % (c, n, repr(r), repr(nm)[:28], cls))
       print("CLASS_BY_REF_KIND (named shapes)")
       for c, _ in cats.most_common(8):
           print("  %-13s %s" % (c, dict(cls_kind[c].most_common(6))))
       print("CLASS_WORD3 (all shapes, top class values)")
       for cls in (1, 2, 4, 5, 8, 9):
           print("  cls=%-2d %s" % (cls, dict(cls_w3[cls].most_common(4))))
   if __name__ == "__main__":
       for p in sys.argv[1:]: run(p)
   ```

4. **Scope.** EU 2011 level-1 road/background pairs of three named tiles
   (43,585 + 1,871 + 37 pairs; cross-border Central Europe, Spain, Italy), plus
   the EU 2011 `LCTBL001.DAT` name database (517 streams, 297,295 text strings).
   Section 4 is read only for the second (signpost-text) location of a road
   number. Excluded: levels 2–6, LEV3456R, US/2014/2016 cards, and the
   firmware renderer glyph tables (no VA claim is made).
5. **Falsifier.** If every reference of a given road-shape class carried the
   same shield syntax, and no `N:E###` European form occurred inside a class
   that also had national forms, then the shield type would be class-derived
   and the shield-type table hypothesis wrong; the class table would be
   reported instead. Result: the test fails to refute (see Interpretation).

## Interpretation

- **FACT:** a road's reference number is stored as the `2=` part of the
  `;`-separated text of a name entry in the odd partner background record's
  names section. The entry is `>HHHHH` = `00ff 2800 0000 0000 ln` followed by
  `ln` bytes of `1=NAME;2=REF` text (NUL-padded to even); the even road-shape
  record's shape word `w4` is that entry's word offset (`0xffff` = none). The
  same words occur with and without a ref (365,317 vs 109,988 on `B48R058R`),
  and the writer's inverse `fa_encode.names_section` uses `typ=0x00ff`.
- **FACT:** there is no separate binary shield-type field in the name entry:
  `flags=0x2800`, `x=0`, `y=0` in every one of the 475,305 entries on
  `B48R058R` (the other two tiles each show one constant tuple as well). The
  type is carried by the reference string's syntax.
- **FACT:** `A4` and `E40` are stored together, not separately: `A4:E40`
  occurs 129 times on the Polish part of `B48R058R` (country 0x268/616), while
  bare `A4` and bare `E40` each occur 0 times. `B6` (4), `S8` (4) and bare
  national `94` (19) occur; `DK94` does not (0). The nonsense key `ZZZ999`
  occurs 0 times (negative control).
- **OBSERVED:** the shield-type families on `B48R058R`, with counts and one
  example road each, are in **SHIELD_TYPE_TABLE** above: numeric 16,674
  (`1005`), other-alpha 9,121 (`EBE20`), `L#` 5,456 (`L501`), `A#:E#` 1,218
  (`A94:E552`), `B#` 885 (`B299`), `S#` 396 (`S33`), `#E#` 208 (`2:E77`),
  `A#` 184 (`A94`), `B#:E#` 30 (`B12:E552`), bare `E#` 16 (`E55`).
  Spain uses a dash code (`HI-4`, 1,125) and Italy a `SP#` (`SP54`, 27): the
  family is country-specific, while the storage field is not.
- **OBSERVED (falsifier):** road class alone does not determine the family.
  Class 5 carries numeric (1,881), `L#` (2,051), `S#` (380) and `#E#` (203)
  shapes; class 1 carries `A#:E#` (1,199) and `A#` (156) but the shape word
  `w3` is `0x1000` for 1,456/1,464 class-1 shapes and `0x6000` for 897/977
  class-2 shapes, i.e. `w3` tracks the road class, not the national/European
  distinction. The hypothesis survives: the European/national choice is a
  property of the `2=` string.
- **OBSERVED:** section 4 is a second, independent road-number location —
  459/1,492 records contain a parenthesised number in signpost text, sometimes
  with the route repeated in a trailing `2=` (e.g. `2=A8:E56:E552`,
  `2=B20:B388`). This is route guidance, not the per-road shield source.
- **HYPOTHESIS:** the renderer selects the shield glyph from the `2=` syntax
  (motorway `A#`, expressway/state `S#`/`L#`, bare national number, European
  suffix after `:`), with the road class as a secondary style input. The
  firmware consumer and glyph table were not located, so this is **not**
  firmware-confirmed (rule 13); no VA is claimed.
- **UNKNOWN:** which glyph is drawn for a given family, and whether the shape
  class/`w3` participates in the choice. The data-side field layout is
  established; the renderer mapping needs an L3/L4 run.

## Conclusion

The EU 2011 factory map stores road numbers only in the odd partner's names
section as `2=REF` inside `1=NAME;2=REF`; the even shape's `w4` points at the
entry. There is no separate shield-type binary field: the shield family is
read from the ref syntax, and the `A4`/`E40` pair is stored as one colon-joined
`2=A4:E40` string (`A4` alone 0, `E40` alone 0, `A4:E40` 129, all on Poland).
The shield-type table above gives counts and example roads for eleven
families. The proposed mapping for Polish `ref` values is written into
`docs/research/osm-pipeline.md`. Firmware glyph selection remains an L3/L4
question.
