## Question

What is in the 16-file `REFER002` EV layer — per-file container, record counts,
and the facility field schema, including the EV additions (`xy-coordinates`,
`point of arrival`, `tie-up parking`, `plug info`, `parking capacity`) that row
24 of `docs/research/reader-coverage.md` calls "undecoded"?

## Hypothesis

`REFER002/POINT0nn` are plain-`.DAT` files sharing the `REFER001` POINT
container (0x800 header, 299-cell directory, zlib `0x60`/`0x68` pages) but with
a *different field dictionary* per file: the EV schema adds three coded facility
fields in place of `icon code`, and `plug info` / `parking capacity` live in the
`INFORMATION` sub-schema. Falsifier: a file that is not the POINT container, a
dictionary that is missing/invalid, or EV fields that are not declared at all.
A writer is out of scope; the goal is the census and the schema, not a round
trip.

## Method

1. **Sample and hash.** The 16 EU files and the 2 US files at the SHA-256 above;
   `census --json` prints a hash-less summary, the per-file bytes are as
   listed in the Observation table.
2. **Commands.**

   ```bash
   # EU: 16 files, records, EV vocabulary, dictionary
   python3 tools/refer002_census.py census m5.4/card-factory/REFER002
   python3 tools/refer002_census.py schema m5.4/card-factory/REFER002/POINT002.DAT
   python3 tools/refer002_census.py table  m5.4/card-factory/REFER002
   python3 tools/refer002_census.py record m5.4/card-factory/REFER002/POINT002.DAT --n 4
   # US cross-market control
   python3 tools/refer002_census.py census m5.12-us/root-factory/REFER002
   # tool self-test (synthetic, no vendor bytes)
   python3 tools/refer002_census.py --selftest
   python3 tools/selftest.py --only refer002_census
   ```

3. **Controls.** *Positive*: the self-test builds a strict 11-field dictionary
   and two zlib record pages, and the census finds 2 pages / 7 records / 11
   fields and the EV names. The real EU files give exactly one strict dictionary
   each (the accessor's `find_dictionary`), 11 fields, and the same 16-file set
   the matrix already counts. *Negative*: an all-`ff` blob yields no
   dictionary; a page of `\\x00\\x01` walks to zero records.
4. **Scope.** `REFER002` of EU 2011 (16 files, 426,496 B) and US 2011 (2 files);
   the record *body* field positions are excluded (the POINT name-record grammar
   of 48/88-byte variants is still open for REFER001, `docs/format/refer.md`);
   `REFER002/COORD001` is treated as a projection companion only (C-152), and
   plug/operator code *meanings* stay out of scope (Stop clause).
5. **Falsifier.** A file that is not the POINT container, a missing or invalid
   dictionary, or EV fields not declared. Stated before the result.

Every POINT file has **one** strict field dictionary (`0x5000` in
`POINT002`, `0x3000` in `POINT010`, …) and declares the EV vocabulary
`xy-coordinates, point of arrival, tie-up parking, plug info, parking capacity,
installed facility, user limitation id`. The facility dictionary
(`POINT002`, 11 fields) is:

| id | field | type | length (words) |
| ---: | --- | --- | ---: |
| 0 | area code | 0x8000 | 5 |
| 1 | category | 0x8000 | 1 |
| 2 | sub-category | 0x8000 | 1 |
| 3 | detailed code | 0x8000 | 1 |
| 4 | index | 0x8000 | 0 |
| 5 | facility name | 0x6000 | 19 |
| 6 | address | 0x6000 | 14 |
| 7 | dndc-id | 0x2000 | 0 |
| 8 | xy-coordinates | 0x8000 | 0 |
| 9 | point of arrival | 0x8000 | 1 |

`record` shows the walker's per-record view: `POINT002` record 0 is
`tag=0x60 bytes=110 text=b'\\x02\\x11MCDONALD FROYENNES'`, then
`INTERPARKING ZAVENTEM`, `CMC-INET`, `CMC-INET` — real charging/parking
facilities, so the dictionary names the fields the EV layer actually uses.

US 2011 `census`: **2 files, 1 record, 12,032 B** (`COORD001` + `POINT001`
with one record) — the US 2011 card shipped almost no EV layer, the same
dictionary and EV vocabulary, so the schema is market-independent.

## Interpretation

- **FACT:** each EU `REFER002/POINT0nn` is the `REFER001` POINT container
  (0x800 header, 299-cell directory at `0x800`, zlib `0x60`/`0x68` pages) with
  one strict per-file field dictionary.
- **FACT:** the facility dictionary is 11 fields, and three of them are EV
  fields (`xy-coordinates`, `point of arrival`, `tie-up parking`) in place of
  REFER001's `icon code`; `plug info`/`parking capacity` are declared in the
  `INFORMATION` sub-schema.
- **OBSERVED:** EU 2011 has 880 EV records over 15 POINT shards; US 2011 has 1.
- **UNKNOWN:** the record-body field offsets (same open POINT grammar as
  REFER001) and the plug/operator code *meanings* (Stop clause).

## Conclusion

`docs/format/refer.md` gains a `REFER002` census table, the facility dictionary
and the EV-field note; row 24 of `docs/research/reader-coverage.md` moves from
"schema undecoded" to "facility schema documented, EV fields named, body
offsets open". The layout is claim-only: no writer and no firmware run (matrix
row 24 stays copy-only for M3.17). What is still open is the record-body field
split and the plug/operator code values — the next P4 step, not a blocker for a
Polish copy of the EU layer.
