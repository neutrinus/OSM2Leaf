## Question

Which firmware code reads the POINT chain locator (directory cell `0x82a` → field
dictionary → base reference `D+4`, M4.47), and does that code, run on a pair whose name
chain `relocate` moved, request the moved chain at its new base?

## Hypothesis

The POINT page loader decodes the base reference with the same block-address leaf the
header parser uses for the directory cells, adds the page's `start_w` from the chain
table, and issues the page read there. **Falsifier:** on a relocated pair the request
lands anywhere other than `new base + 2*start_w`, or record 1 of the requested page
differs from record 1 of the moved page. A pair whose reference was left at the old
base must then *not* read the moved page; if it did, the reference is not what the
loader uses.

   The `relocate` outputs were deleted after the runs. What one `run` does (all firmware code from `Navi.exe` sec0, PySh4):
   (a) the header parser on the file's first 0x1000 bytes (native u16 order) fills the
   header object; `+24` = block number of the dictionary record;
   (b) the dictionary record at that block is placed in header-table entry `+64`
   (`0x0040ee4c`'s table; the field `0x0040e9dc` returns for type 1), the chain table is
   put in memory through its *table* reference (`+0x19a`, independent of the base
   reference), `ctx+124 = 1`, `req+48 = 6*page`; then the page loader runs and its read
   request is recorded and served from the decoded `.DAT`;
   (c) the requested bytes are inflated on the host and the firmware walker returns
   record `n = 1` (0-based: the second record), compared with record 1 of that page
   from M4.47's locator walk on the pair's own (correct) reference.
   Hooks (logged): `memset`, `_divlu` (COREDLL thunks), sector-cache lookup (miss) and
   allocate (host buffer), debug log, read request (served), the parser's tail call
   `0x0040a8d0` / `0x004329d0` (returns 0).
3. **Controls.** *Positive*: factory pairs, both builds, pages 0/1/5 (EU) and 1 (US):
   the request must be at the factory base + `2*start_w`. *Negative*: each relocated
   pair with the 8-byte base reference copied back from the factory pair (`--stale`);
   wrong `--build` for the image.
4. **Scope.** POINT name chain (per_page 1000) only; EU POINT032 (1 page), EU POINT010
   (16 pages; pages 0, 1, 5, 15), US POINT010 (31 pages; page 1). Not run: the loader
   that puts the dictionary record into header-table `+64` (`0x003fc518`, flag `0x21`,
   EU2011) — the harness places it at the block the parser decoded; the completion-side
   inflate (host zlib instead); the 400 and 2000 chains; the card (L4).
5. **Falsifier.** Stated in §Hypothesis, before the results.

## Interpretation

- **FACT:** `fn 0x003fe2d4` (EU2011) / `fn 0x00426480` (US2011) read the base reference
  `D+4` of the dictionary record held in header-table `+64`, decode it with the
  block-address leaf `0x0040f00c` / `0x00436f58`, add `start_w` and request
  `2*comp_w` bytes. `fn 0x003f930c` / `fn 0x00421c3c` read directory cell `0x82a` with the
  same leaf (C-5397).
- **OBSERVED (L3):** on 6/6 relocated runs (5 EU2011, 1 US2011; pages 0, 1, 15) the
  request lands at `new base + 2*start_w` and record 1 of the inflated page equals record
  1 of the moved page; on 6/6 stale-reference runs it lands at the old base and nothing
  inflates there (C-5398). C-5396 holds for this path.
- **UNKNOWN:** whether another reader reaches a POINT chain without this loader; the
  loader of the dictionary record into the header table (`0x003fc518`) was not run
  (C-5399).

## Conclusion

The chain locator's reader is the POINT page loader `fn 0x003fe2d4` EU2011 /
`fn 0x00426480` US2011, called by `fn 0x003ffce0` / `fn 0x00427e1c`. Run in PySh4 on
`relocate` output it reads the moved name chain at its new base and record 1 matches;
with the reference left at the old base it requests the old, zeroed bytes. `refer.md`'s
locator section and `firmware.md` name the reader; `reader-coverage.md` row 10 drops the
"not located" note; claims C-5397–C-5399, C-5396 updated. Open: the header-table load
(`0x003fc518`) and the card run (L4).
