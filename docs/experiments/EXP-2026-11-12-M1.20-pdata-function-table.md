# EXP-2026-11-12-M1.20: `pdata.py` — the function table of every module, and `fn` labels that come from it

- **Status:** done
- **Date:** 2026-11-12
- **Sample:** `IMG256` = first 256 MiB of `LEAF_2011-2012_QSD-309-101_navi158_eu.img` (build A),
  SHA-256 `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`
  (task header; `ls` and `sha256sum` confirm size 268,435,456 B and this digest).
  US build (`US256`) not used: EU head only was supplied.
- **Tools:** python 3.14.4 / stock zlib 1.3.1 (stdlib only at runtime), `tools/pdata.py` (new here,
  `--selftest`), `tools/nk_decomp.py` (H51 PySh4 kernel decompressor), `tools/cerom.py`
  (exception-directory entry added to `e32()`), `tools/sh4dis.py`, `tools/sh4xref.py`,
  `tools/sh4scan.py` (`dump` now tags pdata STARTs), `tools/reader_precheck.py`.
- **Claims:** C-3510–C-3519 (proposed; not added to the ledger)
- **Supersedes:** none
- **Superseded by:** none

## Question

Where is each module's SH-4 function table (`.pdata`, the CE exception directory), and can it be
read mechanically for every module of every build in the image — so that `fn 0x…` labels stop
coming from the prologue heuristic?

## Hypothesis

Every module whose e32 header carries an exception directory has a pdata table at the directory's
RVA, and it is 8-byte records (`u32 begin`; `u32` with prologue length in bits 0–7 and function
length in bits 8–29, both in 2-byte instructions, bits 30/31 flags), sorted strictly ascending.
`Navi.exe` sec2 (compressed) is the known case (H51, C-3483). Falsifier: a module whose exception
directory RVA does not point at sorted 8-byte records with plausible lengths, or whose table is
not decodable by `nk_decomp`.

## Method

1. **Sample and hash.** `IMG256` as above; ranged reads and whole-file reads limited to the first
   128 MiB cover all three builds' code sections (the firmware is in the first ~100 MB). No vendor
   bytes were copied into the repo; decoded pdata slices are cached under
   `/tmp/opencode/work/m1.20/decomp/` (never committed).
2. **Commands.**
   ```bash
   python3 tools/pdata.py --selftest
   python3 tools/pdata.py table /tmp/opencode/img/IMG256.img --module Navi.exe | tail -1
   python3 tools/pdata.py fn    /tmp/opencode/img/IMG256.img --module Navi.exe 0x004125a8 0x0041c7e8 \
        0x003f5194 0x0041c7dc 0x0041c990
   python3 tools/pdata.py gaps  /tmp/opencode/img/IMG256.img --module Navi.exe | tail -1
   python3 tools/pdata.py table /tmp/opencode/img/IMG256.img --image-start 0x3e00200 --module nk.exe
   python3 tools/pdata.py table /tmp/opencode/img/IMG256.img --module OSMDLL.dll
   python3 tools/pdata.py table /tmp/opencode/img/IMG256.img --module NaviMapCC.dll
   python3 tools/pdata.py table /tmp/opencode/img/IMG256.img --module MAL_DataVol.dll   # absent
   python3 tools/selftest.py --only pdata
   python3 tools/sh4xref.py --selftest
   python3 tools/sh4scan.py --selftest
   python3 tools/reader_precheck.py --selftest /tmp/opencode/img/IMG256.img
   python3 tools/sh4xref.py /tmp/opencode/img/IMG256.img Navi.exe --image-start 0x200200 --to 0x0041c7dc
   python3 tools/sh4xref.py /tmp/opencode/img/IMG256.img Navi.exe --image-start 0x200200 --to 0x0041c990
   python3 tools/sh4xref.py /tmp/opencode/img/IMG256.img Navi.exe --image-start 0x200200 --to 0x00412ac0
   python3 tools/sh4xref.py /tmp/opencode/img/IMG256.img Navi.exe --image-start 0x200200 --to 0x003f5194
   python3 - <<'EOF'   # all-module census, build A/B/C — see "Census" below for the full text
   import sys; sys.path.insert(0, 'tools')
   import pdata, cerom
   data = open('/tmp/opencode/img/IMG256.img','rb').read(128<<20)
   for start, label in ((0x200200,'A'),(0x3e00200,'B'),(0x5200200,'C')):
       rom = cerom.CERom(data, start)
       for m in rom.modules():
           try:
               records, meta = pdata.load_table(data, start, m['name'],
                                                '/tmp/opencode/work/m1.20/decomp')
               print('%-28s %6d records  sec%d %s' % (m['name'], meta['record_count'],
                     meta['section'], 'compressed' if meta['compressed'] else 'plain'))
           except pdata.PdataError as exc:
               print('%-28s MISSING  %s' % (m['name'], exc))
   EOF
   ```
3. **Controls.**
   *Positive:* `Navi.exe` — 7,596 records, first `0x0032ed9c`, last ends `0x00558300`, matching H51
   exactly; `fn 0x004125a8` → START length `0x12c`; `fn 0x0041c7e8` → INSIDE fn `0x0041c7dc`;
   `sh4xref --to 0x0041c7dc` prints `fn 0x0041c990` as the holder (H51 verified the same chain).
   *Negative:* an unsorted table must fail loudly — covered by the selftest
   (`validate_sorted` raises `PdataError`); a module with no exception directory is listed as
   such with exit 3 (none exists in this image); `MAL_DataVol.dll` does not exist in any
   build of this image and is reported as "module not found" (exit 2), never guessed.
   *Self-test:* `python3 tools/pdata.py --selftest` — START / INSIDE / GAP / BEFORE / START-at-last
   / unsorted-fails / duplicate-begin-fails / exception-dir parse.
4. **Scope.** All 149 build-A modules, all 91 build-B modules and all 88 build-C modules of
   `IMG256`. Totals: build A 87,530 records; build B 21,930; build C 25,243
   (B before the aerhd.dll exact-match fix: 21,923 with aerhd.dll counted as MISSING). Uncompressed
   pdata sections are read directly; compressed ones decode via `nk_decomp.decompress` (PySh4
   against the firmware's own `DECOMP_SECT 0x88037464`), cached under `/tmp/opencode/work/m1.20/decomp/`.
5. **Falsifier.** If the e32 exception directory did not locate the pdata for some module — e.g.
   `atlce400.dll` (pdata in sec3, not sec2) — the directory lookup would land in the wrong
   section and `parse_pdata` would either yield no records or an unsorted list, and the census
   would show it. It does not: every module censused yields a strictly ascending table.

## Observations

**`.pdata` section location.** The e32 header's unit entries come in pairs (RVA, size); the
exception directory is units[6:8]. Verified on `Navi.exe` (RVA `0x153f000`, size `0xed60` =
7,596 × 8). `cerom.e32()` now exposes it as `e32()["exception"]` (additive change). `pdata.py`
locates the table by that directory entry — not by "the last compressed section" — with an
exact-match preference for plain sections at the same RVA (see "Odd modules" below).

## Interpretation

- **FACT:** Every module in builds A (149/149), B (91/91) and C (88/88) of `IMG256` has an
  exception directory that locates a strictly ascending pdata table of 8-byte records. Build A:
  87,530 records. Build B: 21,930. Build C: 25,243.
- **FACT:** pdata is located by the e32 header's exception directory entry (units[6:8]), not by
  section index; two modules-per-build families (updaters/atlce400.dll, B/C updaters) keep it in
  sec3 and `aerhd.dll` (B/C) needs the exact plain-match preference; all three cases validate.
- **FACT:** `Navi.exe` reproduces H51 exactly: 7,596 records, first `0x0032ed9c`, last ends
  `0x00558300`; `fn 0x004125a8` → START (prologue 14 B, length `0x12c`); `fn 0x0041c7e8` → INSIDE
  fn `0x0041c7dc` (PROLOGUE 30 B, length `0xe8`).
- **FACT:** Leaf functions have no records: e.g. `0x003f5194` (POINT walker) is a GAP; `pdata.py
  gaps` labels 635/677 Navi.exe executable gaps as call targets (`leaf`), consistent with H51's
  "leaf functions have no record".
- **OBSERVED:** the map modules' pdata is compressed, not plain; `MAL_DataVol.dll` is absent from
  this EU image entirely.
- **UNKNOWN:** whether the B/C `nk.exe`-adjacent modules (e.g. `anwdrv.dll`, `navdrv.dll`) carry
  SH-4 vs Thumb mixes (no ISA field in e32 was consulted — not needed here, all A/B/C code parsed
  as SH-4 halfwords consistently with H51).
- **HYPOTHESIS:** none.

## Conclusion

`tools/pdata.py` reads the function table of every module of every build straight from the e32
exception directory, decoding compressed sections with the in-repo PySh4 kernel routine.
`sh4xref`, `reader_precheck` and `sh4scan` print pdata-derived `fn` labels when an image and
module are supplied (old heuristic kept as fallback). Claims C-3510–C-3519 are proposed in this
record (text below); they are not added to `docs/research/claims.md`.

## Reproduction

```bash
python3 tools/pdata.py --selftest
python3 tools/pdata.py table /tmp/opencode/img/IMG256.img --module Navi.exe | tail -1
# expected: 7596 records, first 0x0032ed9c, last ends 0x00558300

```
