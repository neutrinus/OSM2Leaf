## Question

Does the decoded record directory (C-5131–C-5135) plus the M4.16e link-group rule (C-5137–C-5139) carry the TMC location records of **every** RDSTM location table to MAPAL tile/parcel/coordinates, with a named join key and near-zero random controls, and do the two link sets (level 2 and level 4) agree on where a record is?

## Hypothesis

If the location code is the join key and the ref → (parcel, node, link) rule is right, then for each of the 14 set-1 tables: (1) every joined record resolves to at least one node; (2) its nodes lie in parcels that list the table's country far more often than random refs; (3) a record and its TMC positive neighbour are adjacent (< 1 km) far more often than a shuffled pair; (4) the level-4 (set 0) refs of the same record land within a few km of its level-2 (set 1) nodes, far more often than for a shuffled record.

**Falsifier (written after the single-table run of row 0, before the 14-table and code-only runs):** any table where fewer than 99 % of joined records resolve; where fewer than 99 % of placed records are in the table's country; where (3) or (4) is not at least 10× above its control; or the code-only records (neg/pos disagree) failing (2)–(3), which would mean the join needs neg/pos and the code alone is not the key. The country control is the weakest by construction: for a large country random refs land in it often (it is a share, not a near-zero count), so its margin is reported per table, not tested against a fixed ratio.

## Method

1. **Sample and hash** as above (`sha256sum`).
2. **Commands** (repo root; `E=/home/user/scratch/factory-eu`):

   ```bash
   python3 tools/rdstm_place.py --selftest
   python3 tools/rdstm_place.py place-all $E/RDSTM001/LCTBL001.DAT $E/RDSTM001/RDSTM001.DAT $E/MAPAL001
   python3 tools/rdstm_place.py place-all $E/RDSTM001/LCTBL001.DAT $E/RDSTM001/RDSTM001.DAT $E/MAPAL001 --join code-only
   python3 tools/rdstm_links.py place $E/RDSTM001/LCTBL001.DAT $E/RDSTM001/RDSTM001.DAT $E/MAPAL001 --table-pair 0 --examples 30
   ```

   `place-all`, per set-1 table row `t` (pair `14+t`): pick the location table with the best neg/pos agreement (`tmc_fielddir.join_table`, M4.16b rule); a record is *with link* when its indexed location code has a link record in pair `14+t`, and *joined* when, in addition, its decoded (negative, positive) equals the triple of that code (`--join negpos`, default) or does not (`--join code-only`, the complement). Each ref of a joined record is resolved by `rdstm_links.resolve` in its set (set 1 → level-2 parcel in a grid tile, pair `14+t`; set 0 → level-4 parcel in `LEV3456R.DAT`, pair `t`, same code) and the node `(x, y)` is turned into lat/lon (`rdstm_links.node_latlon`).
3. **Controls.** *Positive:* the M4.16e examples (Plzeň-západ 49.71 N 13.28 E, Beroun 49.93 N 14.02 E, Saarbrücken 49.26 N 6.96 E) must come out of the same code path (`rdstm_links.py place --table-pair 0`); the selftest checks the helpers on synthetic input. *Negative:* (i) country — 2,000 refs per table drawn uniformly over all 1,877,891 set-1 entries (group, then entry), counted in the table's majority country; (ii) neighbour — the record against a randomly chosen placed record of the same table instead of its TMC positive neighbour; (iii) cross-level — the record's level-4 nodes against the level-2 nodes of a randomly chosen record of the same table.
4. **Scope.** EU 2011 only; all 14 set-1 tables (14 of the 30 location tables of `LCTBL001.DAT`, 243,838 records) and their 14 set-0 twins. Excluded: the 16 location tables without an RDSTM pair, the US 2011 card (offsets not parsed, M4.16b first pass), the firmware reader (M4.49), the drawn section-1 geometry (M4.39 route, not tested).
5. **Falsifier** as stated under Hypothesis.

## Interpretation

- **VERIFIED (placement, C-5400):** the TMC location code is the join key from decoded `LCTBL001.DAT` records to MAPAL: through `code → RDSTM link record (pair 14+t) → ref → group/entry → level-2 parcel/node/link`, 110,788 of 110,795 joined records of all 14 RDSTM tables (99.99 %) reach coordinates; all of them have a node in a parcel of the table's country (random refs 2,048/27,998 = 7.3 %; per table 0.75 % (BE, 15/2,000) to 15.4 % (SE, 307/2,000): the weakest control, a 6.5× to 130× margin); 94,551/95,176 (99.3 %) lie < 1 km from their TMC positive neighbour (shuffled 129, 0.14 %). The M4.16b done-when (≥ 20 records, named key, ~0 random control) is met with margin on every table, not just CZ/DE.
- **VERIFIED (cross-level, C-5401):** set 0 links the same codes to the level-4 graph: 60,321 records (the major-road subset) also resolve through pair `t`, and every one lies < 5 km from its own level-2 nodes (median 0.02–0.03 km per table), against 256/60,321 for a shuffled record. Two independent link sets agree on where each location is.
- **VERIFIED (C-5402):** the location code alone is the join key; the neg/pos agreement of C-5135 is a confirmation, not a condition. The 47,678 code-matched records whose neg/pos disagree place just as well (47,657 placed, all in their table's country vs random 1,876/26,050; 7,303/7,326 positive-neighbour pairs < 1 km vs shuffled 16; 13,424/13,424 level 4 < 5 km vs shuffled 216). 46,822 of them are road ends: the LCTBL record has no neg/pos field and the RDSTM triple holds `0`; 846 differ in one or both neighbours. With the code alone, 158,445 of 158,473 code-matched records (99.98 %) reach coordinates.
- **OBSERVED (C-5403):** role 1 is exactly the role-0 link list reversed in 24,948 of 66,443 records that carry both (37.5 %, per table 16 %–65 %). HYPOTHESIS: roles 0/1 are the same location in the two travel directions, roles 2/3 something else (both are present in most records). Not decoded; carried to M4.49. The entry flag bits `a` 0x4000/0x8000 and `b` 0x4000/0x8000 are not decoded in this pass (out of the done-when; M4.49 owns them).

## Conclusion

M4.16b is **done**: decoded TMC records join `RDSTM001.DAT` by location code and reach MAPAL coordinates for every one of the 14 RDSTM location tables (110,788 records, 14 countries), with the neighbour control (99.3 % vs 0.14 %) and the cross-level control (100 % vs 0.4 %) far above chance and the country control 6.5× (Sweden) to 130× (Belgium) above random refs. `docs/format/rdstm.md` gains a placement paragraph; claims C-5400–C-5403. Still open: the firmware reader and the role/flag bits (M4.49), the US 2011 card's `RDSTM001.DAT`, and the drawn section-1 geometry of a TMC location (M4.39 route).
