## Question

Can a scripted panel tap on the consent/map UI of a running `-M ze0` guest
change the AUI plane, repeat with the same after-tap hash in a second boot,
leave an untouched named region unchanged on an empty-area tap, and hit the
documented `kepdrv` VAs with time-stamped breakpoints?

## Hypothesis

Yes: with the M8.C1n `--ui-start` bridge (the UI leaves `INI_STARTUP` and the
key guard is cleared at the first touch), a panel peer tap on the map screen's
ZOOM IN button reaches `kepdrv`, changes the scale label and gives the same
after-tap pixels in a repeat run. **Falsifier:** the screen does not change
after a tap that hits the breakpoint, or the change is only animation (the
screen changes without a tap between two shots), or the empty-area tap also
changes the named region.

### 3. Controls

- *Positive, tap works:* after `tap 765 70`, `serial.log` logs one
  `HMI -> ZDP : ZOOM ILL EVENT`; the rendered scale label changes from
  `1/16mi` to `1/8mi` (viewed with the image tool); the full PNG hash changes
  from `8846b00c…` to `b64f1d55…` (run 1) and from `bb9ca4e8…` to `c082d944…`
  (run 2). The named scale-label hash changes from `985e3ddd…` to `c64ff230…`
  in BOTH runs.
- *Positive, breakpoints:* `bp-run1.txt` and `bp-run2.txt` each print
  `hits {'0x3d284e4': 4, '0x3d27450': 2}` with time stamps 9.9–11.1 s (run 1)
  and 10.1–11.3 s (run 2), all after the measured tap was injected. The two
  VAs were derived from NK1 `.text` with the prologue check printed above,
  not copied from a doc.
- *Negative, empty tap:* after `tap 400 350` the named scale-label hash stays
  `c64ff230…` (`neg2-idle-a`/`neg2-idle-b`/`neg2-after`) and the count of
  `ZOOM ILL EVENT` stays 1 — no UI reaction. The full-frame PNG hash changes
  only in the blinking ZOOM widget (x680–793), which is the documented
  animation confound (§5).
- *Negative, hash checker:* mutating `expect-hash` to 64 zeroes makes
  `ze0_ui.py run` exit 1; the correct hash exits 0.
- *Negative, EU card:* the EU attempt never printed `ANTITHEFT_CC_NTF_COMP_OK`
  or `ForwardState` (`grep -c` = 0 in both cases), and `uistart.log` had no
  `touch unlocked`; this is why the US card was used (§4).

### 4. Scope

Two boots of NK1 + ROM A from the US card, anonymous 8 MiB unit flash, one
panel peer on `sci3`, `--ui-start --touch-unlock`, one consent unlock tap, one
ZOOM IN tap per run, one empty-area tap, one hard key (`MAP`), three post-tap
screenshots per run, and two gdb breakpoint sessions. The EU card attempt is a
negative control for the region, not a second successful run:
`ze0_uistart.py find` lists EU join sites at `0x02bc3efa`/`0x02c21fa2`
(event 3279), but no `COMP_OK` arrived within the observation window (the EU
AppLaunch looped on `SD Card Security Unlocked!`, `grep -c` = 54), so the state
never left `INI_STARTUP`. TL approved the US fallback; the deviation from the
task's EU2011 wording is stated here. Excluded: SCI3 wire-frame decoding
(M8.H35), L3/L3-fragment and L5/car runs, generated cards, other UI screens,
and any commit of vendor screenshots. The screen view is DU plane 1 only
(`plane -n 1`, not `screen`), for all hashes, per C1t O6/O9.

### 5. Falsifier

The task's stated falsifier occurred: the full-frame PNG changes without any
tap between two shots because the ZOOM widget blinks. Diff of the full frames
`map-idle-a`→`map-after1b` is 1,310 pixels confined to x678–793, y199–433;
`neg2-idle-b`→`neg2-after` is 349 pixels confined to x680–793, y200–433.
Therefore the raw full-frame hash comparison is replaced by a named region:
the 272-pixel scale-label mask, which is stable under the empty tap and changes
only for the real tap. With that mask the Done when holds strictly: after-tap
hash equals across runs, idle differs, and the empty tap leaves it unchanged.
A genuine UI failure would have left the mask unchanged despite
`ZOOM ILL EVENT` and the breakpoint hits; that did not happen.

## Interpretation

- **FACT:** With the M8.C1n UI bridge, a scripted panel tap on US consent and
  map screens reaches `kepdrv` (time-stamped breakpoint hits at both NK1 VAs),
  changes the scale label from 1/16mi to 1/8mi and logs `ZOOM ILL EVENT`.
- **FACT:** The named scale-label region gives the same after-tap hash in two
  independent boots (`c64ff230…`), differs from the idle hash (`985e3ddd…`),
  and is unchanged by an empty-area tap. This is the task's Done when, with
  the falsifier handled by a named region.
- **FACT:** The full-frame PNG is not deterministic because of ZOOM widget
  animation; a full-frame hash alone would have falsely refuted the repeat
  check. This is recorded, not hidden.
- **OBSERVED:** The EU card did not reach `COMP_OK` in this environment; the
  successful runs used the TL-approved US fallback, an explicit scope
  deviation.
- **UNKNOWN:** Why the OK/Decline focus animation differs between boots; the
  underlying widget state was not traced (out of scope).

## Conclusion

M8.H39 is **done** on the US fallback with the named-region hash assertion:
after-tap named region equals across two boots, differs from idle, and is
unchanged by an empty-area tap; breakpoint hit counts are 4 and 2 in both
boots. Rule 13 level: L4 (full-system emulator) reads and reacts to the
injected tap; no car/bench run.
