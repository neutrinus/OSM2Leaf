## Question

Can `runner.py run drstr_parser` run the EU2011 `DRSTR001.DAT` parser
`fn 0x00419350` on the factory file and return a verdict (or a named
blocker with the faulting PC), and what is the parser's verdict map, decoded
from its return values rather than guessed?

## Hypothesis

With `vcard_l3`'s bound imports (every COREDLL/OSMDLL slot in decoded sec1
pointed at a host model, ordinals named by `cerom.py imports --resolve-with`,
H49), the caller's own sequence open wrapper `0x0041b3bc` → parser
`0x00419350` → close wrapper `0x0041b650` runs to `rts` on the factory file
and returns 0. The parser returns only `0` and `-1`. The error codes the
logger `0x0041bbec` receives (M3.10: 26/23/20/10) are reached by the matching
mutation. Falsifier: a fault or a missing import model on the factory file;
a return value other than 0/-1; a mutation aimed at one logged check that
does not log that code.

## Interpretation

- **FACT:** `runner.py run drstr_parser` runs the EU2011 parser on the
  factory file and returns the firmware's verdict ACCEPT (r0 0) through
  the shipped open/close wrappers and bound imports; no fault, no missing
  model.
- **FACT:** the parser returns `0` or `0xffffffff` only (three exits, one
  frame word with two writers); `verdict_map` `{0: ACCEPT, 0xffffffff:
  REJECT}` is that decode, and the runner refuses any other declared map.
- **FACT:** codes 20 and 10 are the first-node checks (`+36` a multiple of
  40, at most 200 entries); 26 is a logged size warning, not a rejection.
- **FACT:** a file of at most `0x77220` bytes is parsed from the buffer
  without a bound at the file size: a 32-byte file is accepted when the
  buffer past it is zero. In the unit that memory is whatever `OSM_Malloc`
  returns, so the verdict of a short file is not fixed by the file alone.
- **UNKNOWN:** why `+36 = 200·40` is rejected without a log code (an
  unlogged later check; not decoded here).

## Conclusion

M9.24's Done-when holds: `runner.py run drstr_parser` on the EU factory
`DRSTR001.DAT` returns `PASS`/ACCEPT, and the target's `verdict_map` is the
decoded return map (C-2640–C-2645). The import binding the task asked for
(stub VAs in the COREDLL slots, `fopen`/`fread`/`fseek`/`ftell`/`ferror`/
`clearerr`/`fclose`/`_modlu`/`strncat`) is `vcard_l3.Machine`'s, reused; no
stack-argument model is needed because the caller's sequence is called
directly.
