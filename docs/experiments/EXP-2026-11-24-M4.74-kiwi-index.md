## Question

Do the `REFER001` search-index families (`POINT`, `ADDRE`, `ZCODE`, `ICODE`,
`COORD`, and the absent `INDEX003`) share a KIWI chapter-11 index structure —
trie nodes, leaf pages, coordinate tables, category lists — well enough to adopt
a field or layout, or do they only share vocabulary?

## Hypothesis

After M4.63/M4.78 ("common concepts, different container") the expected outcome
is: every family maps to a KIWI concept (index frame, jump table, category code)
but **no** byte-level node format is portable, because the KIWI chapter-11 PDF was
not obtained in M4.65 and the ZE0 containers are per-family. **Falsifier (task):**
KIWI's index is one container while ours are five unrelated files with different
page formats — if a single KIWI node layout decoded two or more ZE0 families
byte-for-byte, the hypothesis would be refuted. **Falsifier (checker):** a verdict
that disagrees with its own byte-test counts/note, or a mutation accepted by the
selftest, must be rejected.

### 3. Controls

*Positive (tools):* each repo tool's `--selftest` builds a synthetic structure
and must pass — `point_census` (spatial-leaf and index-key joint walk, plus a
shifted-pointer / shifted-id negative), `addre` (schema/directory/cell decode and
M4.19 fractional candidate), `coord_zcode_icode` (COORD mask r1/r32/r33,
addr/unaddr roundtrip including `off=0x5d7800 enc=0xbaf00`), and the new
`kiwi_index_check` (canonical 6-row table). `selftest.py --only` prints PASS for
all four. *Positive (real bytes):* each census walk covers its whole file family
(POINT001 274,178,048 B `VERDICT: every byte reached by a walked structure`;
ADDRE001 2621/2621 directory-count sum; ZCODE018 record 0 at `0x5d7800`
reproduces the eight expected `u16`s; ICODE001 33-country chains). *Negative
(mandatory mutation control):* `kiwi_index_check --selftest` flips one cell at a
time and asserts FAIL — (1) POINT `partial`→`adopt` with 0/0 counts, (2) COORD
`unrelated`→`partial` with a non-concept note, (3) an invented ZCODE `1/1`
byte-test count. All 3 must be rejected (printed `3/3 mutations rejected`).
`shifted-ptr control 17`, `shifted-id control 18,033`, `phone shifted control 0`
are the real-data negatives that make the POINT joins non-trivial.

### 4. Scope

Covered: six on-disk families (`POINT001`, `ADDRE001`, EU `COORD001`, `ZCODE018`,
`ICODE001`, plus the on-disk-absent `INDEX001/003`) mapped to KIWI chapter-11 and
adjacent structure names; tree-node format, record-id width and record→parcel
pointer inspected per family. The census counts are per real EU2011 sample
(POINT001 274,178,048 B; ADDRE001 record chain 52,038 B; COORD001 4,608 B;
ZCODE018 9,792,768 B; ICODE001 111,378,432 B). Excluded: a real KIWI disc
(M4.77, unavailable — no synthetic control can refute a negative on real KIWI
bytes), the KIWI chapter-11 byte layout (PDF not retrieved in M4.65), the
`kiwiread` GPL source body, firmware reader VAs (rule 13) and any L3/L4 run. No
new decoder and no recompression were part of this task.

### 5. Falsifier

As stated: the task falsifier ("one KIWI container vs five unrelated file
formats") did not fire in the strong sense — the five on-disk families do each
have their own node/page format (12-u16 index records vs 6-B cells vs 12-B digit
entries vs 12-B name rows vs 14-B bbox), so no shared KIWI node layout was
found; the families match KIWI only at the concept level. For the checker: any
mutation accepted, or any verdict inconsistent with its quoted counts, would
have invalidated the table.

## Interpretation

- **FACT (tool):** all six families have a distinct on-disk node/page format —
  POINT 12-u16 index records with spatial leaves keyed by the low 11 bits of the
  name pointer, ADDRE 12-B initial directory + 6-B cells + 22-B index records,
  ZCODE 12-B digit-tag directory with `child = 0x1204 + offset*2`, ICODE 12-B
  name rows with chain-relative `roff`, COORD 14-B bbox records with a one-hot
  48-bit level mask, INDEX absent on these cards. No single KIWI node layout
  decodes two families; the task's "one container" falsifier does not fire in
  the strong sense.
- **FACT (tool):** the POINT joins are non-degenerate (1,001,835/1,001,835
  spatial leaves, 2,814,259/2,814,259 index keys, with shifted controls 17 and
  18,033), so the per-family structure is real; ADDRE's 2,621/2,621 directory
  sum, ZCODE's `0xbaf00 → 0x5d7800` sector decode and COORD's 33 one-hot masks
  are independent corroborations.
- **OBSERVED:** KIWI chapter 11 (`11.1 Index Data Frame`, `11.7 Category Codes`,
  `11.8 Jump Table`, `11.12 Search Method`) supplies the *concept* names and the
  plausible structure list, but the chapter-11 PDF was not retrieved (M4.65), so
  no KIWI byte layout is asserted and no field can be adopted. Five families get
  `partial` (concept-only); COORD stays `unrelated` (the 15.625-arcsec KIWI unit
  is not our fine step, matching C-7670–C-7674).
- **HYPOTHESIS (not tested here):** the shared index-frame vocabulary reflects
  Clarion/Xanavi design heritage (see `docs/format/kiwi-glossary.md`), not a
  common container; no causal or firmware-reader claim follows.
- **UNKNOWN:** the KIWI chapter-11 on-disk node format (a real `ALLDATA.KWI`
  volume, M4.77) is the only positive control that could re-open the
  concept-only verdicts on real KIWI bytes; our ICODE root-pointer index table
  and the `INDEX001` layout remain UNKNOWN and are not resolved here.

## Conclusion

the six-family structure list and the four UNKNOWN items it does/does not
explain; `docs/research/claims.md` gains C-7730–C-7737. The family → KIWI

positive control (M4.77) remains the only way to re-open the negatives. No GPL
