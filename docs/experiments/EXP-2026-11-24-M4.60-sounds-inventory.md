## Question

What sound sources does the ZE0 unit play, where is each one's data, and
which can be replaced as data (card file) rather than being code/microcontroller
generated? For guidance prompts, can a sample be decoded offline (duration,
codec), or why not?

## Hypothesis

Card `SPEECH/` holds the recorded prompts (GID), SVOX TTS and acoustic models
(AGM); beeps/chimes come from the audio microcontroller through
`CApi_GetSoundEffect` with no stored sample; ROM A contains only WAV-format
scaffolding, not playable prompts. The GID inner container is a proprietary
indexed-record format with no RIFF/WAVE, so it cannot be decoded with stdlib
alone and the reason is recordable.

**Falsifier:** a GID prompt that decodes to a standard RIFF/PCM/ADPCM stream
with a measurable duration; or beep samples stored on the card; or any quoted
number not printed by the commands in §2.

### 3. Controls

- **Positive:** `speech_years.py describe` finds the documented archive
  framing on the real SP GID/TTS/AGM files; `romscan` finds the expected
  WAV templates in `waveapi.dll`/`Speech.exe`; `cerom.py modules
  --image-start 0x3e00200` lists `BeepDrv.dll` size 10240; `ce_strfind`
  finds UTF-16 `CEN1:` in `commondll.dll`/`BeepDrv.dll`.
- **Positive (audio container):** the 44-byte `TSP00400.WAV` entry at
  `0x6218` in the SP TTS file starts with
  `524946462400000057415645...` and Python's `wave` module decodes
  `channels=1 rate=22050 width=16 bits frames=0`, proving the detector
  recognises a real RIFF/WAVE header.
- **Negative (mutation of a touched artifact):** a scratch copy of the SP
  GID had byte `0x20` changed from `S` to `X`. `speech_years.py compare`
  reported `DIFF entry names: ['SSP00000.GID'] -> ['XSP00000.GID']`,
  `DIFF first byte 0x20 (53 -> 58)`, `RESULT: different`, exit **1**; the
  unmutated file is not flagged. The mutated file was written only to
  `$S/SSP00000.GID.mut`, never into the repo.
- **Negative (synthetic):** `count_signatures(b'\x00'*4096)` yields
  `RIFF=0 WAVE=0 fmt=0 ADPCM=0 ima4=0`; the synthetic GID in the
  `--selftest` has zero signatures and is reported `decodable: NO`, while
  injecting `RIFF`/`WAVE` into its payload changes the verdict to
  `possible RIFF/WAVE`.
- **Wrong build corrected:** the task's Precheck
  `cerom.py --image-start 0x200200 ... imports BeepDrv.dll` raises
  `KeyError: 'BeepDrv.dll'`; the audio drivers are in build B
  (`--image-start 0x3e00200`). The EXP quotes the build-B command, never
  cites the failing build-A command as a pass.

## Interpretation

- **FACT:** the 27 card SPEECH files split cleanly into GID (guidance
  prompts, 1 self-entry archive, no RIFF/WAVE), TTS (SVOX vendor voice with
  one 44-byte WAV header positive control), and AGM (SVOX acoustic model)
  (C-6570, C-6571, C-6572).
- **FACT:** no GID payload contains RIFF/WAVE/fmt/ADPCM/ima4; the inner
  record grammar (payload head `0x1d4c 0x7580 … 0xabe0 0xa` on both cards) is
  a proprietary indexed format, so no duration/codec could be decoded
  offline. The reason is recorded, satisfying the Done-when's second branch
  (C-6573).
- **FACT:** beeps/chimes are generated by the audio microcontroller via
  `COMMONDLL!CApi_GetSoundEffect` (`BeepDrv.dll` imports it, `CEN1:`/`BEP1:`
  device paths, L4 `BeepDrv : Can't open 'CEN1:'`), with no sample file on
  the card; this closes the "beeps as stored samples" branch (C-6574). The
  task's Precheck build start is wrong (build A raises `KeyError`), corrected
  to build B (C-6578).
- **FACT:** ROM A's 6 RIFF / 13 WAVE / 6 fmt hits are code/format templates
  in `waveapi.dll`, `Speech.exe`, `wavessi1/2` — not playable prompt samples
  and not in the beep drivers (C-6575, C-6576).
- **OBSERVED:** voice choice is a runtime setting selecting among `SPEECH/`
  sets; where it is stored is not established (C-6577).
- **UNKNOWN:** runtime decode of GID/TTS/AGM by a 2011 `Speech.exe`
  (no L3/L4 run, no hardware) (C-6579).

## Conclusion

`docs/format/sounds.md` now inventories all eight sound sources with status,
location, size, container, sample rate where readable, opening module and a
`replaceable as data` line each; `docs/format/assets.md` points to it. New
printing tool `tools/sounds_inventory.py` (322+ lines, auto-discovered
`--selftest`, 14 checks) produces every number quoted here. Done-when is met:
the GID branch ends in a recorded reason (no RIFF, proprietary container)
rather than a decoded sample, and the beep branch is closed with
IOCTL/driver evidence. No card built, no vendor bytes committed. Still
open: the GID grammar/codec, the custom-voice setting location, and runtime
acceptance.
