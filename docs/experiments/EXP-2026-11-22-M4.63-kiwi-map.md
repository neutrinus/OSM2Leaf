## Question

Do the KIWI structures named by `jharg/kiwiread` (volume header, management-header directory, parcel management header, level management record, road/background frames) describe the bytes on our ZE0 cards, and can `kiwiread` be used as a reader or field-name oracle for them?

## Hypothesis

Exploratory, with the prior already recorded in `docs/research/sources.md` (2026-11-21): the two formats share a vocabulary (parcel, level, block, link) but not a container, so the expected result is negative. **Falsifier:** any KIWI structure whose field values match our bytes on two cards *and* behave like the KIWI field (e.g. a level count that stays valid per level, a lat/lng frame inside ±90/±180) would refute the prior and make `kiwiread` an oracle for that structure.

3. **Controls.** *Positive:* `kiwi_probe.py --selftest` builds synthetic buffers from the quoted field grammar (datavol C.64 string, 34 `mhr_t` with ASCII names, `pdmdh_t` geonums and counts, `lmr_t` level/flags/counts, an 8-byte `roadhdr_t`, a 12+2n `mingr_t`). All six positive controls PASS. *Negative:* the same selftest embeds real EU2011 bytes (`0xa0`, `0x800`, `0x184`, `0x1ac`) plus a factory road header and background shape; all six must FAIL, and a mutated synthetic field fails as expected. The real KIWI-disc positive control (M4.77) is **not** available here — no `ALLDATA.KWI` was fetched — so a synthetic grammar control is the only positive control in this record, and this record does not claim to have run `kiwiread` on a real KIWI volume.
4. **Scope.** Four files / two cards; six KIWI structures plus the two type definitions (`D`, `SWS`, `sectoraddress_t`, `geo_secs`). Covered bytes: four fixed header offsets on three files, one road record (22 words), one background shape (14 bytes), plus the documented directory/address formulas. Excluded: any KIWI disc (M4.77), firmware reader VAs (M3.39/M4.66 — no VA is attributed here), the KIWI specification PDF (M4.65), and copying GPL code. The task's Stop rule was applied after the first three structures produced 0 fits; the remaining three rows are cheap interpretations of bytes already emitted by the same tool in the same session, not a new line of research.
5. **Falsifier.** A field marked "pasuje" whose value on the second card or in a second tile does not behave like its KIWI definition; or a synthetic positive control that fails (the probe would be measuring nothing). Both would have made the result inconclusive rather than negative.

- **FACT:** All six synthetic positive controls PASS and all six embedded/real negative controls FAIL; the probe can distinguish the two grammars.
- **FACT:** 0/4 header checks fit on each of three files; the road and background checks fail too. The four EU/US samples are independent (different cards, one tile each plus US `MMAIN001.DAT`).
- **OBSERVED:** The only structural resemblance is the background shape: both KIWI `mingr_t` and the ZE0 shape carry a 2-byte type code, a point count and `int8` delta coordinates. The length rule, code set and header bytes disagree (`114 ≠ 560`, `0xffff` is not a KIWI type code).
- **HYPOTHESIS:** The shared vocabulary comes from a common problem domain (parcels, levels, links, display classes, background polygons) and from Clarion/Xanavi's KIWI lineage, not from a shared container. `kiwiread` is useful as a *glossary of field names and chapter numbers*; it cannot parse our files and is not an oracle for field values.
- **UNKNOWN:** No KIWI disc was available, so `kiwiread` was never run on a real `ALLDATA.KWI` (M4.77). No firmware reader VA is attributed to any of these structures (M3.39/M4.66). Whether the KIWI specification's *route-planning* concepts map to our section 2 remains open (M4.72).

## Conclusion

Task M4.63 closes as a **negative result**: "common KIWI concepts, different container". No field in `docs/format/` was renamed after a KIWI match, because none matched. `tools/kiwi_probe.py` is committed so the negative is reproducible; `docs/research/sources.md` now records the verdict on the existing kiwiread row. The Stop rule was triggered after the first three structures; the remaining three rows were interpreted from the same tool output and did not change the verdict. What remains open is owned by sibling tasks: M4.64 (firmware vocabulary), M4.65/M4.77 (specification and a real KIWI positive control), M4.66–M4.75 (per-structure checks), M4.78 (verdict page).
