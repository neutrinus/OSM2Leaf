## Question

Can the M1.22 EU/US reuse points (walker and chunk-engine starts, stubbed
helpers, data cells) be declared in one file, with every other copy derived
from it or checked against it, so that a one-halfword drift in any copy fails?

## Hypothesis

Before the change the five copies agree on the code side and the
`firmware.md` table is a subset; after it one command prints
`TOTAL only-in-*: 0`.
**Falsifier:** a planted `+2` in `targets.json`, in the doc table, in a
hand-written override of either tool's `BUILD_TARGETS`, or a helper added to
`fn_audit.US_BUILD_STARTS`, still reports `0 only-in-*`.

## Interpretation

`tools/build_targets.py` is the owner. The two L3 tools and `fn_audit` now
derive their sets from it (no hand copy left to drift), and the two copies
that must stay hand-written — the runner's `targets.json` and the prose table
— are diffed by `check`, which the selftest proves red on a one-halfword
drift. The eight missing doc rows were not a disagreement but an incomplete
table; they are now listed. `US_BUILD_STARTS` is built only from `start`
roles, the fixture's US side and the entry, so a helper cannot re-enter it.
The identical pdata class/length per role pair is independent support that
each owned pair names the same function in both builds.

## Conclusion

Owner: `tools/build_targets.py`; `python3 tools/build_targets.py check`
prints `TOTAL only-in-*: 0 across 8 copies`. Exceptions: the M1.22 EXP
(append-only record, not a live copy).
