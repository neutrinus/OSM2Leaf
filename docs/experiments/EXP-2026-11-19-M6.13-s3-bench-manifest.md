## Question

Can the S3 (one changed US tile) bench card be described as a complete package
— artifact SHA-256, size, diff ranges, base identity, gates passed, one-variable
relation to S0/S1/S2, pass/fail criteria — from recorded EXPs, with the base
identity and the ranges re-checked on the real base image?

## Hypothesis

Every manifest field is recorded in EXP-2026-11-08-M5.14 (C-2050–C-2054) and
EXP-2026-11-08-M5.13b / M5.24 (S1/S2), and an independent BPB+FAT read of the
real US base image resolves `MAPAL001/B18R100R.DAT` to the same directory entry
and cluster range M5.14 recorded. **Falsifier:** the base image hash differs
from `53342430…c5383`; the resolved dir entry is not `106124352`/32 B or the
chain is not the contiguous clusters 8–38 from `106189824`; or the S2 file
ranges overlap the S3 ranges (then S2 and S3 would not be separable cards).

## Interpretation

- **FACT:** the base image is the factory US 2011 image the S0/S1/S2/S3
  records name (`53342430…c5383`, 8,057,257,984 B).
- **FACT:** on that base, `B18R100R.DAT` (1,994,496 B) owns dir entry
  `[106124352, 106124384)` and the contiguous clusters 8–38
  `[106189824, 108221440)` — exactly C-2053's allowed ranges; the S2 pair
  owns clusters 78193–78258 and the entries at `0xb3bb7e80`/`+0x20`
  (C-2352), disjoint from them. S3 (built from the factory, not from S2)
  differs from S0/S1 in one file; versus S2 it also lacks the POI rename.
- **FACT:** no runnable L3 target reads a `MAPAL001` tile today (M3.25/M9.13
  open), so the package carries no L3 PASS; M9.31 is open.
- **OBSERVED:** the S3 image cannot be regenerated from the repo: M5.14's
  patch ran from `/tmp/m5_14_patch.py` (not committed), and `harness.py
  mutate` (`ze0_mutate.py`) rewrites the whole container from the first
  background record, a different edit.
- **OBSERVED:** the expected on-screen place is inconsistent. C-2054
  (HYPOTHESIS, `coord.py` scale 2) puts the vertex at 20.82→20.92°N (~11.6 km
  north). The level-1 grid fixed by M5.44 puts directory (30,65280) at
  20.0–20.667°N with parcel (8,8) at 20.167°N, 0.0208° tall; a 40-unit move in
  a 2048-unit parcel is then ~0.0004° (~45 m), and C-2054's latitude lies
  outside the directory. `clarion_bg.mesh_to_lon` gives `64356` for x0 =
  65280, i.e. it does not map a US (western-hemisphere) mesh, so the longitude
  is not checked. `ze0_mutate.py` itself calls 40 units "about 130 m".
- **HYPOTHESIS:** the move is tens of metres, not kilometres; the bench
  operator should not rely on C-2054's coordinates until M6.16 settles it.
