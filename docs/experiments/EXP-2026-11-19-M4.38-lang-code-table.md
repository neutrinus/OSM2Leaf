## Question

Which language does each byte of the `MMAIN001`/`BICON001` `0x18c` code list name, and which `SPEECH/<dir>` set goes with it?

## Hypothesis

Pre-registered after the first string search (Speech.exe holds the UTF-16 dir names `BE FR GE IT DU PT SP JP US CF XX`; Navi.exe holds a log string `LANG CONV ERROR` next to `sdl_com_hdl_get_lang`):

- **H1.** The codes are the values that a firmware language-conversion table returns for the user's language setting, and the same setting picks the `SPEECH/` dir in Speech.exe; joining the two on the setting gives `code -> dir` without the card.
- **H2.** Applied to each card's code list, the join names every `SPEECH/` dir on that card, and no code names a dir the card does not have.

**Falsifier (stated before the join was run on a card):** H1 falls if the two modules key on different settings, or if the Navi table's default is not the list's `3f` fill. H2 falls if any card `SPEECH/` dir is named by no card code, or a card code names only dirs that are absent, on any of the three cards (EU 2011, US 2011, EU 2014). The negative controls must fail: if the codes shifted by ±1, or read as Speech.exe's own language number without the Navi table, also cover every dir, then the method cannot tell a right map from a wrong one.

   How `firmware` finds the tables (no fitted addresses): Navi.exe — the module bytes that hold `LANG CONV ERROR`, the literal-pool word that points at that string, the function that loads it (pdata), and inside that function the literal whose target parses as rows `{u32 3001..3999; u16 code; u16 0}`, cut to the `mov #n,Rk; cmp/ge` loop bound. Speech.exe — every `braf Rn` in the executable sections is decoded as a jump-table switch (bias from `add #-b` or `mov.w L; sub`, count from `mov #n-1; cmp/hi; bt default`, byte or word table); the switch with bias 3001 and integer cases is exp→number, the one whose cases load two-letter UTF-16 strings is number→dir. `join` reads `MMAIN001.DAT` `0x18c` (`identity_fields.parse_header`) and the `SPEECH/` dir names (`cardcheck.Fat32Image`).

3. **Controls.**
   - *Positive, decoder:* `--selftest` (17 checks) assembles two synthetic switches (byte table with `add #-1` bias and string cases; byte table with `mov.w 3001; sub` bias and `bra`+`mov #imm` cases) and a row table, and decodes them; it rejects a non-`braf` word.
   - *Positive, same setting:* `sh4xref --calls` labels the thunks each lookup calls: Navi.exe `0x003d1a6c`/`0x003d20e4` and Speech.exe `0x0009cc68`/`0x000aaf74` (EU2011) are `OBJDLL!OBJ_Setting_getObjID` and `OBJDLL!OBJ_Setting_readExpLanguage`; the EU2014 thunks (Navi `0x00405d78`/`0x004063f0`, Speech `0x000a7a18`/`0x000b5c80`) are the same two imports.
   - *Positive, cross-build:* the same tool finds the same row shape and both switches in all four builds without per-build input.
   - *Negative (in `join`):* (a) the card codes shifted by −1 and +1; (b) the card codes read directly as Speech.exe's language number (no Navi table). Each must leave a dir uncovered or name an absent dir.
   - *Negative, other tables:* `rows` scans the raw 256 MiB of each head for any run of ≥4 rows of the same shape; any table elsewhere that named `14 17 18 19 1a` would show up here.

4. **Scope.** Four CE build-A images (EU 2011, US 2011, EU 2014, EU 2016): Navi.exe and Speech.exe uncompressed sections (both modules' code is in sec0; their compressed sec1/sec2 are not read). `rows` covers 4 × 268,435,456 raw bytes (stored bytes only, so a table inside a compressed section would be missed). Card side: three cards (EU 2011 and US 2011 full images; EU 2014 head + `SPEECH` cluster); EU 2016 card side not re-read (M4.22 found it equal to EU 2014). Not covered: the Navi.exe function that reads `MMAIN001` `0x18c` (the code list is joined by value, not by a traced read), the meaning of a code inside the map data.

5. **Falsifier.** As in §Hypothesis; it could fail on each card (one missing dir, one wrong code) and on each build (different setting import, different default).

## Interpretation

- **FACT (VERIFIED, firmware):** Navi.exe `sdl_com_hdl_get_lang` (EU2011 fn `0x003c0228`) converts the `OBJ_Setting_readExpLanguage` value into a one-byte language code through a row table and returns `0x3f` when no row matches; Speech.exe turns the same setting into the `SPEECH/<dir>` name. Joined on the setting, the codes are: `01` Japanese (JP), `02` English UK (BE), `03` English US (US), `04` French (FR on EU, CF on US), `05` German (GE), `06` Spanish (SP; MX in 2014), `07` Italian (IT), `08` Portuguese (PT), `0a` Dutch (DU), `0b` Russian (RU, 2014 speech), `0c` Swedish (SV), `0d` Danish (DA), `0e` Chinese (ZH, 2014 speech), `0f` Korean (KO, 2014 speech), `15` Finnish (FI), `16` Norwegian (NO).
- **FACT (VERIFIED, card):** on all three cards every `SPEECH/` dir is named by a card code and no code names a missing dir; all three negative controls fail on every card.
- **OBSERVED:** that the `0x18c` list is in this code space rests on the value join and the shared `0x3f` (Navi default = list fill), not on a traced read of `0x18c`. `09` = Greek is a cross-build reading: EU2011 Navi maps setting 3009 to `09`, and EU2014 Speech names setting 3009 `EL`; EU2014 Navi maps 3009 to `02` (English text) instead.
- **OBSERVED:** in 2014 five speech languages (EL, PL, CS, HU, SK) map to text code `02`; the 2014 list carries five codes no build's table returns besides `14`: `09 19 17 18 1a`. By count and grouping (they follow the four Nordic codes) these are the map data for those five languages, with `09` = Greek.
- **HYPOTHESIS:** `17 18 19 1a` are Polish, Czech, Hungarian and Slovak in some order. No anchor in four builds.
- **UNKNOWN:** `14`, on EU 2011 and EU 2014 but in no table; it is the "extra" EU code (C-2495) and selects no speech set. The first reading in C-2496 (`0x14` is an EU-only non-speech code) holds; the second (`04` is English) is refuted (`04` is French).

## Conclusion

The done-when is met: each `0x18c` code on the three cards has a language and a `SPEECH/` set with a firmware anchor (the Navi.exe row table and the Speech.exe switches, VAs per build), except `14 17 18 19 1a`, which no table in four builds names; for those the EXP states the negative with the `rows` scan and names the remaining step. Changes: `tools/lang_code_table.py` (new); `docs/format/file-header.md` (Identity fields code table), `docs/format/assets.md` (code per dir), `docs/research/open-questions.md` OQ-44, `docs/research/claims.md` C-3760–C-3769 (and notes on C-551, C-2496); M4.22's Blocker/Unblock in `TODO.md` now cite this EXP.

Still open: the Navi.exe reader that consumes `MMAIN001` `0x18c` (a traced read, or the L4 mutation: change `05` to `3f` on a copy, select German, and see German map text disappear); `17 18 19 1a` and `14`.
