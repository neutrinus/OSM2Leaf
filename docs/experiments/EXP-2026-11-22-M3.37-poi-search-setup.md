# EXP-2026-11-22-M3.37: POI search set-up, leaf code, and `*0x005638ec`

- **Status:** done
- **Date:** 2026-11-22
- **Sample:** firmware `archive/head256.img` (EU2011 build A, Navi.exe, image start `0x200200`) SHA-256 as in M3.35; US2011 `archive/us256.img` for twin comparison. Factory EU POINT pairs extracted to `/home/marek/projekty/leafre-work/scratch/m337/pt_eu` (scratch, not committed).
- **Tools:** Python 3.10 stdlib; `tools/sh4dis.py`, `tools/sh4xref.py`, `tools/point_tree_l3.py`, `tools/point_census.py`, `tools/point_pair_regen.py`, `tools/cerom.py`.
- **Claims:** C-6970–C-6979

## Question

M3.35 ran the nearest-POI child loader/step/walker/distance on factory trees with search state written by the tool. M3.37 asks: who writes `*0x005638ec` and what does the 6-bit leaf code mean; can root loader / one upper-level driver run in L3; where are US2011 twins; what writes `*0x0056389c`, `*0x00d5d7e4`, `*0x00d5d7dc`?

## Hypothesis

`*0x005638ec` is written by POI-search request/setup code and selects a non-63 leaf-code variant. Root loader `fn 0x0040f674` can be run in L3 with seeded request state. US2011 twins exist for the M3.35 functions but the code-filter writer/global may differ.

## Falsifier

No code writes `*0x005638ec` (then coded leaves are dead data for this build); or root loader cannot execute in engine on a factory tree; or US2011 has no matching nearest-POI walker twins.

## Method

1. **Static xrefs/disassembly (EU2011).**
   - `python3 tools/sh4xref.py archive/head256.img Navi.exe --image-start 0x200200 --to 0x003f2f98`
   - `python3 tools/sh4dis.py archive/head256.img Navi.exe --image-start 0x200200 --va 0x003f2f98 --count 80`
   - `python3 tools/sh4xref.py ... --to 0x005638ec --to 0x0056389c --to 0x00d5d7e4 --to 0x00d5d7dc`
   - pool-load/store scan over Navi.exe executable sections for `0x005638ec` (script in shell history; checks `mov.l @rn`, `@(r0,rn)`, `mov.l rm,@rn`, `mov.l rm,@(r0,rn)` through simple register copies/adds).
2. **Leaf-code census.** Host walk of EU POINT001–033 spatial leaves in `/home/marek/projekty/leafre-work/scratch/m337/pt_eu` using `point_tree_l3.host_leaves`/`leaf_code`.
3. **L3 root loader.** Added `point_tree_l3.py root-load` command; ran:
   - `PYTHONPATH=tools timeout 180 python3 tools/point_tree_l3.py root-load archive/head256.img --dir /home/marek/projekty/leafre-work/scratch/m337/pt_eu --file POINT010 --tree 0`
4. **US2011 twins.** Static disassembly/prologue comparison at checkpoint VAs and signature scan in `archive/us256.img`.

## Observations

### `*0x005638ec` writer

`sh4xref --to 0x003f2f98` gives literal pools at `0x0017804c/54/94` (data section). Disassembly of `fn 0x003f2f98` shows request-indexed stores:

```
0x003f3022  mov.l @(0x003f30a0,pc),r4 ; [0x003f30a0]=0x005638ec
0x003f302a  add r4,r3                    ; r3 = &0x005638ec[r8*4]
0x003f302e  mov.l @(12,r9),r4            ; request field +0x0c
0x003f3042  mov.l r4,@r3                 ; write 0x005638ec[r8]
...
0x003f305e  mov.l @(0x003f30a0,pc),r2    ; 0x005638ec
0x003f3064  mov.l r3,@(r0,r2)            ; write by index r8
```

The same function stores request `r9+0x10` into `0x005638f4/0x005638fc` indexed by `r8`. Pool-load scan over executable sections found no other `0x005638ec` write; loads in `fn 0x004114dc` and `fn 0x0040e20c` are reads.

### Leaf-code census

Total 2,653,215 leaves: `{63:2631890, 6:3414, 4:3356, 5:3064, 10:3061, 7:2866, 2:2803, 8:2761}`. Same-position leaves: 2,532,220 positions, 4,945 have multiple codes. No same-ordinal multi-code evidence was produced by this census; meaning remains HYPOTHESIS. Counter-examples to "dead data": 21,325 non-63/0 coded leaves exist.

### Root loader L3

`point_tree_l3.py root-load ... --file POINT010 --tree 0` output:

```
POINT010 tree 0: root_load r0=0xffffffff tree_base=0xd77 expected=0xd77 step0=err:UnmappedAccess
RESULT: BLOCKED
```

The root loader executed in the SH-4 engine and set `*0x00d5b858` to the expected tree base block (`0xd77`); it returned `-1` and the seeded follow-up `STEP` from a minimal context faulted with `UnmappedAccess`. This confirms the loader touched the tree-base global but the harness did not provide full search/request state required for a successful root descent.

### Upper drivers / globals

`fn 0x00411fd4` dispatches levels `0x1001/0x1002/0x1003`, reads `*0x00d5d7e4`, computes key masks, and drives step/cell descent. `fn 0x0041235c` is a companion driver reaching the same step/walk path. `*0x0056389c` written by `fn 0x0040b190:0x0040b1d0` (`header[0x182] & 0x0000f000`) and `fn 0x0040b258:0x0040b2fc`. `*0x00d5d7e4` written by `fn 0x00411df4:0x00411e2a/0x00411e42` (sets 4, conditionally 1). `*0x00d5d7dc` written by `fn 0x003f3140/0x003f3238`, read by `fn 0x0040f5ac` and `fn 0x004114dc`.

### US2011 twins

Located by disassembly/prologue: `LOAD_CHILD 0x00437774`, `STEP 0x00438f0c`, `WALK 0x0043930c`, `DISTANCE 0x00430fa4`, `ROOT_LOAD 0x004374a4`, `DRIVER_A 0x00439dac`, `DRIVER_B 0x0043a134`, `SETUP_338 0x00437168`, `SETUP_2FC 0x0043712c`, `WRITER_255c 0x0041aefc`. EU `fn 0x003f2f98` had no 16-byte signature hit in US; US `WALK` does not contain EU's `cmp/eq #63` / `*0x005638ec` filter sequence near the equivalent code path. US `*0x005638ec` writer/global not located by direct VA/value search.

## Interpretation

- `*0x005638ec` is written by `fn 0x003f2f98` as part of POI-search request/setup state (indexed by `r8*4`, together with `0x005638f4/0x005638fc`). The exact semantic label of the code remains HYPOTHESIS; census proves non-63/0 codes exist and are common enough to matter.
- Root loader `fn 0x0040f674` is executable in L3 and sets the expected tree base global on a factory tree, but full root descent needs more request/setup state than this harness seeded.
- US2011 has twins for the core walk/step/load/distance/root/driver functions; the EU code-filter writer/global is not directly reusable by address and the US walk lacks the same visible code filter.

## Limitations

- No full upper-level driver L3 run completed to ACCEPT; root-load returned BLOCKED after setting base.
- `fn 0x003f2f98` caller chain above request object not fully traced.
- Leaf-code meaning is not proven; only census/counter-examples recorded.
- US2011 analysis static only.
