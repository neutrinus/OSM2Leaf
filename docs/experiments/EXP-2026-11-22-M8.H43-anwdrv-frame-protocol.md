## Question

What is the wire frame grammar of the audio-microcontroller link that
`anwdrv.dll` drives on `SCI1:`, and what is the minimum a host peer must
reply during launch so `CApi_WaitModuleInitialize` stops timing out?

## Hypothesis

The 8 bytes logged by EXP-M8.C2a O4 (`10 02 02 08 00 10 03 19`) are a
DLE-framed message with a one-byte XOR block check, built by `CInaiFormat`.
**Falsifier (from the task):** the checksum rule fails on a second logged
frame. **Additional falsifier used here:** the XOR leaf does not reproduce
the last byte of the one logged frame, or a corrupted frame passes the
validator.

3. **Controls.**
   - *Positive:* the logged frame's last byte is recomputed from the other
     7 bytes by `tools/anw_frames.py frame` → `BCC=19`, and `build 020800`
     reproduces the whole frame byte for byte.
   - *Negative:* wrong BCC (`…18`), wrong ETX (`…04 19`), wrong STX
     (`10 05 …`) and an undoubled DLE body are all rejected by
     `parse_frame`; `--selftest` reports 12/12 PASS. A negative XOR leaf
     would fail the positive control, so the rule can fail loudly.
4. **Scope.** One module (`anwdrv.dll`, 3 sections, sec0 = 0x26400 stored B,
   sec1 + sec2 both decompress `OK`), 11 IOCTL handler VAs, 3 thread
   functions and 7 protocol helpers. Build B only; build C and the reader
   side of the launch handshake are excluded. No vendor bytes committed;
   scratch under `~/projekty/leafre-work/scratch/m8.h43/`.
5. **Falsifier.** A second logged frame whose BCC differs from
   `bcc(stuffed_body + 10 03)`, or a code path that stores a different
   value, would refute the rule. The second-frame condition could not be
   exercised: all 9 675 logged transmits were identical (O4).

## Observations

**O1 — module and section map.** `anwdrv.dll` is build-B module 42: load
`0x884c4000`, vbase `0x03b80000`, 80 exports (AUD/TNR/TMC/ANT/UPD/PDT/CEN/MMP
families), sec0 VA `0x03b81000` vsize `0x262db` stored `0x26400`; compressed
sec1 (`0x560` B) and sec2 (`0x1de0` B) both decode `OK`.

**O2 — the frame builder.** `fn 0x03ba23f4` stores `0x10` then `0x02` at
`packet[0..1]`, calls `AddPutDleData` at `0x03ba243a`, stores `0x10` at
`packet[len+2]` (`0x03ba2448`) and `0x03` at `packet[len+3]`
(`0x03ba2450`), calls the BCC leaf at `0x03ba2462` with `r5=packet+2`,
stores the result at `packet[len+4]` (`0x03ba246a`) and returns the frame
length in `r0`.

**O3 — BCC leaf.** `fn 0x03ba2138`: `xor r3,r1` at `0x03ba214e`,
`extu.b r1,r3` at `0x03ba2154`, loop `0x03ba2148…0x03ba2152`, returns the
accumulator. `BccCheck` `fn 0x03ba0860` reads `frame[size-1]` into `r8`
(`0x03ba0882`) and calls the leaf with `r5=frame+2`, `r6=size-3`
(`0x03ba0884`, `0x03ba0890`); mismatch logs the format error string at
`0x03b89568`.

**O4 — pinned vector.** `python3 tools/anw_frames.py frame
1002020800100319` → `payload=020800 control=0 (0x02) BCC=19`;
`build 020800` → `1002020800100319`. `02 ^ 08 ^ 00 ^ 10 ^ 03 = 19`.
`--selftest` → `selftest: 12/12 PASS`.

**O5 — stuffing.** `fn 0x03ba2260` loop `0x03ba22a4…0x03ba22ce`: each
input byte is written; if it equals `0x10` (`cmp/eq #16` at `0x03ba22b4`)
an extra `0x10` is appended (cap checked at `0x03ba22be`). `fn 0x03ba2334`
skips the second byte of a `10 10` pair (`0x03ba2392…0x03ba239a`); a
single DLE logs `Illegal DLE` (`0x03b8a870`). Constructed vector:
`build 02100300` → `10020210100300100312`, which round-trips.

**O6 — control byte.** `fn 0x03ba1f5c`: `cmp/eq #2` → 0, `#6` → 1,
`#21` (`0x15`) → 2, else logs `DT_TYPE_ERR` and returns 3.
`fn 0x03ba07b4` (`GetWriteResult`) compares the wait result with the literal
`0x0102` at `0x03ba07ce` and the response byte at `this+40` with `0x15` at
`0x03ba0810`, logging `recieve NAK!!!!` on match.

**O7 — start scanner.** `fn 0x03ba1f10` scans for `0x10` from index 0 and
returns its position, logging `not Find DLE` (`0x03b8a520`) on failure.

**O8 — launch message VAs.** IOCTL dispatcher `fn 0x03b909b8` uses base
`0x7ff2e000` (`0x03b90bac`), a `<0x90` bound and the table at `0x03b8333c`.
Command constants: `ReqMo` `fn 0x03b90bbc` cmd `0x02` (`0x03b90bf2`),
`Audio` `fn 0x03b90d40` cmd `0x04`, `ReqMIr` `fn 0x03b90e98` cmd `0x02`,
`ReqAIr` `fn 0x03b90fe4` cmd `0x01`, `GetSy` `fn 0x03b9117c` cmd `0x09`,
`GetLa` `fn 0x03b912c8` cmd `0x09`, `BeepC`/`SetFO`/`GetFO` cmd `0x01`.
`ConnectDiagCheck` `fn 0x03b9ee20` logs `detect ACC-DET`, `Audio connect OK`
and `Audio connect NG retry[%d]`; it calls `KernelIoControl(0x01013000)`.

**O9 — launcher boundary.** `anwdrv.dll` imports
`COMMONDLL!CApi_WaitModuleInitialize` (slot `0x03ba82d0`) and
`COMMONDLL!CApi_ModuleInitializeComplete` (slot `0x03ba82cc`); neither slot
VA occurs in a code literal pool. `tools/acm_id_scan.py ... --all` found
28 module-id calls in 4 build-B modules, **none in `anwdrv.dll`** — the
wait/signal calls live in `AppLaunch.dll` (`fn 0x03bcc904`/`0x03bcc974`)
and `commondll.dll` (`fn 0x03c035a4`/`0x03c03584`).

## Interpretation

- **FACT (C-7400, C-7401, C-7402):** module/section map, frame layout and
  DLE stuffing from O1/O2/O5.
- **FACT (C-7403, C-7404):** the BCC leaf and its check domain from O3; the
  rule reproduces the logged frame's last byte (O4).
- **FACT (C-7405):** control-byte classes and ACK/NAK constants from O6,
  start scanner from O7.
- **FACT (C-7406, C-7407):** the launch message table with VAs and the
  launcher-boundary observation from O8/O9.
- **OBSERVED (C-7408):** the minimal reply set — valid framing and BCC,
  ACK `0x02`, command echo — follows from the code; a wrong BCC or NAK is
  rejected/logged.
- **HYPOTHESIS:** the `ReqMo` response carries the active module mask that
  lets the launcher signal `CApi_ModuleInitializeComplete`; not executed.
- **UNKNOWN:** the `ReqMo` parameter mapping, the `0x06` control class,
  timeouts/retries, module IDs and the exact reply body. The task's
  second-frame falsifier remains unexercised because all logged frames were
  identical (O4 of the C2a record).

## Conclusion

`docs/firmware/anwdrv.md` now records the iNai frame grammar (DLE STX,
DLE-stuffed body, DLE ETX, XOR BCC), the checksum rule with a reproducible
snippet, the control-byte classes, a launch-phase message table with VAs and
the minimal reply set for a peer. `tools/anw_frames.py` pins the one logged
frame and four negative controls (12/12 PASS) and is auto-discovered by
`tools/selftest.py`. Nothing was injected into the guest: this is a static
map, not a rule-13 acceptance.
