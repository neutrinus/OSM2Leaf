- **Supersedes:** none
- **Superseded by:** none

## Question

What is the complete inventory of map images/archives on `files.viaaq.eu`, and
which fields change with the map code (as opposed to staying constant across the
ZE0 family)?

## Hypothesis

The ZE0-era family (2011–2016, EU and US) keeps the same engine
(`CLA-NAVI05-01` / `X08-02-00` / `V05.00.00`), 45 tile grid + `LEV3456R`,
and 194 `REFER001` pairs; only the map-code-dependent fields (HDD_INFO lines
2/3/5/6, the common-header `DATA VERSION` date, `MMAIN` record counts, tile
sizes/descriptors, `REFER002` shard set, `DRSTR` entry values) change. The 2019
image is a different engine.

## Method

```bash
python3 tools/cardcheck.py --image <img> --ignore-dump-artifacts
python3 tools/cardcheck.py --root <root> --ignore-dump-artifacts
```

## Observations

- `cardcheck` census:
  - 2011 EU: files=480 dirs=39 bytes=5,173,965,667; pairs=194; tiles=46; HDD_INFO 72 bytes.
  - 2014 EU: files=504 dirs=58 bytes=6,821,761,753; pairs=194; tiles=46; HDD_INFO 72 bytes.
  - 2016 EU: files=505 dirs=58 bytes=7,180,933,678; pairs=194; tiles=46; HDD_INFO 72 bytes.
  - 2011 US: files=248 dirs=19 bytes=5,182,407,132; pairs=58; tiles=113; HDD_INFO 72 bytes.
  - 2019 EU: files=14,828 dirs=101 bytes=14,432,981,729; pairs=200; tiles=53; `VER_INFO/DB_INFO.TXT` 156 bytes.
- Map archives: 504/503/504 files, 57 folders, 46 tiles, 194 `.cmp` pairs each.
- `diff_years` 2011 vs 2014: HDD_INFO lines 2/3/5/6 differ; line 1
  (`QSD-302-100`) and line 4 (`SDC08-EVEUR`) identical. All 50 common
  header-bearing files change `DATA VERSION` (`11/06/27/01` → `14/04/12/01`)
  and 10 bytes of the `0x180` binary block. `MMAIN` section/level record
  counts change. Tile sizes and descriptor counts/bboxes change; tile names do
  not. `REFER002` gains 13 `POINT` shards plus `ICODE001.DAT`. `DRSTR` entry
  values and directory set (`TFTBL001`, extra `SPEECH` languages) change.
- Header versions: ZE0 EU samples use `CLA-NAVI05-01` / `X08-02-00` /
  `V05.00.00`; 2019 uses `CLA-NAVI06-01` / `X08-03-00` / `V06.00.00` /
  `ZENRIN`. US 2011 uses `CLA-NAVI05-01` / `X08-02-00` / `V05.00.00` with
  `DATA VERSION 10/08/12/01`.

## Interpretation

- **FACT:** All eight files are inventoried with verified SHA-256 (C-1020).
- **FACT:** Within the ZE0 family, `FORMAT VERSION` (`X08-02-00`), model
  (`CLA-NAVI05-01`), engine string (`V05.00.00`) and the 45-tile grid + `LEV`
  are constant; only `DATA VERSION` changes with the map build (C-1021).
- **FACT:** `HDD_INFO.TXT` lines 1 (`QSD-302-100`) and 4 (`SDC08-EVEUR`)
  are constant across EU ZE0 samples; lines 2, 3, 5 and 6 track the map code,
  build, year-month and part number (C-1022).
- **FACT:** `REFER001` keeps 194 `.cmp`/`.ind` pairs in every ZE0 sample;
  logical byte totals grow with the map build (C-1024).
- **OBSERVED:** Tile names are stable (45 + `LEV3456R`) while sizes and
  descriptor counts/bboxes change (C-1023).
- **OBSERVED:** `REFER002` grows from 2 files / 15 POINT shards (2011) to
  16 files / 29 shards (2016); `ICODE001` appears from the 2013 map set
  (C-1025).
- **OBSERVED:** `MMAIN001.DAT` level-table record counts change with the map
  build (section 1/2/4, levels 1/2) (C-1026).
- **OBSERVED:** `DRSTR001.DAT` entry `value`s (file sizes) and directory set
  (`TFTBL001`, extra `SPEECH` languages) change with the map build (C-1027).
- **FACT:** The 2019 image is a different engine family (`CLA-NAVI06-01`,
  `X08-03-00`, `ZENRIN`, `DB_INFO.TXT`, 53 tiles, 200 `.cmp` pairs) and is
  not a ZE0 reference (C-1028).
- **FACT:** `diff_years.py` reproduces all of the above field-level differences
  on the 2011/2014/2016 roots (C-1029).
