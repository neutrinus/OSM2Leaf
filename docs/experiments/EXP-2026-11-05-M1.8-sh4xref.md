## Question

M1.8 done-when: `tools/sh4xref.py IMG MODULE --to VA` lists every instruction that
loads VA's literal with the enclosing function, `--calls FUNC` lists call
targets named through thunks and exports, it reproduces EXP-50's four call
sites, and it has a self-test on synthetic SH-4 bytes.

## Hypothesis

SH-4 literal loads are `mov.l @(disp,PC),Rn` (`0xDnnn`, address
`((addr+4) & ~3) + disp*4`), calls are `jsr @Rn` (`0x400B|n<<8`) or `bsr`
(`0xBnnn`, target `PC+4+disp*2`). Import stubs are the EXP-50 pattern. A
prologue heuristic can anchor functions on the nearest `rts`.

## Inputs

| Item | Value |
| --- | --- |
| Image A | `--image-start 0x200200` |
| Module | `Navi.exe` (vbase `0x00010000`), uncompressed `.text` `0x00011000`, size `0x54bd16` |
| Tool | `tools/sh4xref.py` (this commit) |

## Method

```bash
python3 tools/sh4xref.py --selftest
python3 tools/sh4xref.py IMG Navi.exe --image-start 0x200200 --to 0x003d1bb0
python3 tools/sh4xref.py IMG Navi.exe --image-start 0x200200 --to 0x003d1ba4
python3 tools/sh4xref.py IMG Navi.exe --image-start 0x200200 --to 0x004e7d28
python3 tools/sh4xref.py IMG Navi.exe --image-start 0x200200 --calls 0x004e7b8c
```

`--to VA` gives two readings: (a) loads whose literal address is VA (the code
reads the slot at VA), and (b) pool words equal to VA (the code reads a
word that is VA, e.g. a thunk address), each followed by the `jsr/jmp @Rn`
within 12 instructions and the enclosing function.

## Observations

Self-test (synthetic bytes, no vendor data): 17 checks OK (movl/bsr/jsr
decoding, function start, pool gap, thunk, labels, `--to` and `--calls`).

`--to 0x003d1bb0` (getOffset thunk):

```
pool 0x0037796c holds 0x003d1bb0
  load 0x003778ae (r3)  fn 0x00377870  jsr 0x003778b2
pool 0x00377dd0 holds 0x003d1bb0
  load 0x00377b42 (r3)  fn 0x00377ae0  jsr 0x00377b46
```

`--to 0x003d1ba4` (getSize thunk): `jsr 0x003778bc` and `jsr 0x00377b52`.
These are the four EXP-50 call sites.

`--to 0x004e7d28` (HDD_INFO slot):

```
slot 0x004e7d28 is read by:
  load 0x004e7bec (r4)  fn 0x004e7b8c
```

`--calls 0x004e7b8c` (9 register calls, `jsr @r3`):

```

0x004e7bfc -> 0x004dd1f0  sub_004dd1f0
0x004e7c3c -> 0x0053a564  IMPORT COREDLL.dll!#1145
0x004e7c4a -> 0x004dd1f0  sub_004dd1f0
0x004e7c5a -> 0x0053a558  IMPORT COREDLL.dll!#1143
0x004e7c8c -> 0x0053a54c  IMPORT COREDLL.dll!#59
```

Negative: the value `0x004e7d28` does not occur as a 32-bit word in any
uncompressed section of `Navi.exe` (`--to` reading (b) finds nothing). The
M1.8 task text calls it a "literal", but it is the address of the pool slot
that the code reads. That slot holds `0x001d51a8`, the pointer to the
UTF-16 string `\UserSD\VER_INFO\HDD_INFO.TXT` (EXP-50 notes, C-521).

Development notes (not claims): the first prologue heuristic (prologue word
preceded by `rts`) missed both EXP-50 functions, because a literal pool sits
between the `rts` and the function. The current heuristic anchors on the
`rts`, skips the delay slot, and takes the first prologue word within 64 bytes.
One self-test expectation was corrected (`bsr` is `PC+4+disp*2`).

## Interpretation

M1.8 done-when holds. Known limits:

- Function starts are a heuristic (nearest `rts` plus prologue). A function
  with no prologue and no preceding `rts` (not in this image) is reported as
  `fn ?` or at the wrong start.
- `--calls` only follows `bsr` and `mov.l`-literal-then-`jsr`. Calls through
  computed registers, or `jmp` tail calls, are not listed.
- COREDLL ordinals are shown as `#n` because `COREDLL.dll` exports are not
  loaded. Naming them needs COREDLL's export table (M1.6b / M9 territory).
- The seven COREDLL calls (six ordinals) and the two `sub_004dd1f0` calls are the first
  callees of the HDD_INFO function. Naming them is M2.1 work.
