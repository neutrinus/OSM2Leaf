## Question

Can `l3_harness/runner.py` run the firmware chunk reader
(`fn 0x0041c7e8`, `cmp_ind_reader`) with explicit memory setup and a declared,
sourced sec1 `inflate_mask[17]` input, so that the factory pair reports PASS
and the M9.11 controls (`corrupt-ind`, `swap-4-8`) report as controls through
the runner, without any silent default table?

## Hypothesis

A `firmware_call` entry kind that passes a declared `sec1_table` (VA + values +
provenance) to `chunk_decoder_l3.run_firmware` reproduces the M9.11 control
verdicts through the runner. **Falsifier:** (a) `runner.py run cmp_ind_reader`
on the factory pair exits non-zero or returns non-byte-identical output; (b)
`corrupt-ind`/`swap-4-8` do not report as the M9.11 controls; (c) the entry can
be registered/validated without a declared sec1 table or provenance (a silent
default path).

## Interpretation

- **FACT:** `runner.py` accepts `entry.kind = "firmware_call"` and validates a
  declared `sec1_table` (`va`, `values`, `provenance` required); entries missing
  sec1_table/provenance/values are rejected. No silent default table is used on
  the runner registration path (C-2941).
- **OBSERVED:** `targets.json` registers `cmp_ind_reader` as a `firmware_call`
  target (`Navi.exe fn 0x0041c7e8`, `cmp_ind_chunk_v1`) with the sec1
  `inflate_mask[17]` declared at `0x00574de0` and provenance naming the code
  index (`0x54369e`) and public zlib 1.1.3 source; the HYPOTHESIS that sec1
  bytes equal those values is disclosed (M1.2f open), consistent with M9.11
  (C-2940).
- **OBSERVED:** `runner.py run cmp_ind_reader` on the factory pair reports
  `ACCEPT`/`PASS` exit 0 with `r0=42848`, `insns=1057245`, `memcpy=11`, matching
  EXP-2026-11-08-M9.11-chunk-decoder. `--mutate corrupt-ind` reports PASS with
  `r0=-1`/638 insns (firmware rejects). `--mutate swap-4-8` reports PASS with
  `r0=65536`/1057219 insns (clean failure). All controls match M9.11 (C-2942).
- **HYPOTHESIS:** sec1 bytes at `0x574de0` equal `inflate_mask[17] = 2^n-1`
  (public zlib source); not verified against decompressed sec1 (M1.2f open).
- **UNKNOWN:** full `.ind` parser/file opener behavior; other chunks/pages/cards;
  decompressed Navi.exe sec1 contents.

## Conclusion

M9.11b fills `cmp_ind_reader`: `runner.py` now has a `firmware_call` entry kind
that runs `fn 0x0041c7e8` with explicit memory setup and a declared, sourced
sec1 `inflate_mask` table (no silent default). `targets.json` registers
`cmp_ind_reader`, and the runner reproduces the M9.11 factory PASS plus
`corrupt-ind`/`swap-4-8` controls on the same sample with matching counters.
This resolves M9.11's registration blocker; the sec1 byte equality remains a
HYPOTHESIS pending M1.2f. `l3check.py --card` integration is M9.12 (parallel;
not touched).
