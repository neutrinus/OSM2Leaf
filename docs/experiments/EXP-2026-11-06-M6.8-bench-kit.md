## Interpretation

- **FACT:** the parts list below covers every capability the dynamic guide
  names, and each row maps to one or more claims.
- **FACT:** the debug SCIF is known at register level (C-534) but its board
  pins are unknown; the USB-UART row is therefore conditional.
- **OBSERVED:** the card matrix (step 4 of the access plan) is the only step
  that needs no debugger; steps 2–3 need either a QEMU gdbstub breakpoint at
  the VA or an undocumented hardware debug header.
- **HYPOTHESIS:** a logic analyser is sufficient to find the debug TX pin
  during boot; a scope is optional and only needed for signal integrity and
  differential CAN.
- **HYPOTHESIS:** grounding `TEST_B1` through a switch is enough for the
  bench error screens, but this rests on external research (C-082) and may
  still need a VIN/CAN frame.
- **UNKNOWN:** the minimum CAN frame set the unit needs before it touches the
  SD card; the existence of a hardware debug header; whether retail firmware
  keeps the `0xffe46000` debug output enabled.
