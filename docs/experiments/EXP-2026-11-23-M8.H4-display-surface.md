## Question

`tools/ze0_screenshot.py` copies VRAM with HMP `pmemsave` and composes the DU
planes on the host, and `run.sh` always passes `-nographic`: QEMU has no
console, so `-display gtk/vnc`, VNC and HMP `screendump` have nothing to show.
Can `ze0-gfx` expose the same composed frame as a QEMU graphic console, so that
`screendump` (and therefore VNC/gtk) is pixel-identical to the host tool?

## Hypothesis

A graphic console that composes the DU planes exactly like
`ze0_screenshot.py compose()` will make `screendump` equal to the host PNG on a
static screen. **Falsifier:** the console image differs from the host-composed
one on a static screen.

## Method

1. **Sample and hash.** The EU 2011 head and card above, card behind a fresh
   qcow2 overlay; `tools/ze0_ipl.py patch` gives the IPL patch (8 lines).
2. **Commands.** Runnable as written:

   ```bash
   # build the machine with the new patch (incremental, seconds)
   TMPDIR=$HOME/scratch bash tools/qemu-ze0/build.sh --jobs 8
   Q=~/.cache/qemu-ze0/build/qemu-system-sh4
   W=$HOME/scratch/m8.h4/run2; mkdir -p "$W"
   python3 tools/ze0_ipl.py patch archive/head256.img -o "$W/ipl.txt"
   python3 tools/qemu-ze0/mkoverlay.py \
     archive/sd-images/LEAF_2011-2012_QSD-309-101_navi158_eu.img "$W/eu2011.qcow2"
   bash tools/qemu-ze0/run.sh --qemu "$Q" --image archive/head256.img \
     --verinf QSD-302-100 --mapdb 16-16 --ipl-patch "$W/ipl.txt" \
     --sd "$W/eu2011.qcow2" --icount shift=0,sleep=off --timeout 900 \
     --workdir "$W" --log /dev/null &
   # after ~45 s, same instant, two frames:
   printf 'screendump %s/s0.ppm ze0-gfx\n' "$W" | socat - UNIX-CONNECT:"$W/hmp.sock"
   python3 tools/ze0_screenshot.py screen --monitor "$W/hmp.sock" -o "$W/host.png"
   python3 tools/ze0_screencmp.py "$W/s0.ppm" "$W/host.png"
   ```

   The VNC control (item 3) uses `--display vnc=127.0.0.1:7` instead of the
   `--log /dev/null` headless run; the console-off control uses
   `-M ze0,gfx-display=off`.
3. **Controls.** *Positive:* the boot reaches the London map (plane 4
   `0x4002` at `0x0e9f2000`), so `screendump` must be non-black — 384,000
   non-black pixels. *Negative 1 (falsifier):* any differing pixel between the
   console frame and the host PNG would fail the Done-when. *Negative 2
   (console off):* `-M ze0,gfx-display=off` must leave no console at all
   (`screendump` → `There is no console`). *Negative 3 (VNC endpoint):* without
   `--display`, port 5900 is not listening.
4. **Scope.** One static frame per boot, EU 2011 card, QEMU 11.1.3 with the
   full `patches/` series (30 patches, `--check-version` 30/30). Only the four
   DU planes are compared; UI-layer blending beyond the key rule is M8.C1t.
   Screens are vendor data and stay outside the repository.
5. **Falsifier.** Stated above (negative 1): a differing pixel on a static
   screen.

## Observations

**O1 — the console exists and is addressable.** `info qtree` on the run prints
`dev: ze0-gfx, id "ze0-gfx"`, and `screendump FILE ze0-gfx` writes a
`P6 800 480` PPM of 1,152,015 bytes.

**O2 — the console frame is non-black and correct.** At ~45 s
(plane 4 at `0x0e9f2000`, still zero at that instant, plane 2 the keyed fill
`0x83ff…`): the PPM has **384,000 non-black pixels** of 384,000.

**O3 — equal to the host composition.** `ze0_screencmp.py s0.ppm host.png`:
`800x480: 0 differing pixels, 384000 non-black`. SHA-256 of the raw RGB bytes
of both images: `d2b7e70f20c54dba4900ba60100aeaa64eac3520d99b08b1e1cfdd040dde7a86`
(PPM `66b2cd8b…`, PNG `66387215…` — different containers, same pixels).

**O4 — VNC serves the frame.** With `--display vnc=127.0.0.1:7` the run answers
on TCP 5907 with the `RFB 003.008` greeting, and `info qtree` still shows
`ze0-gfx`; VNC is therefore a live view of the same console, not a still image.

**O5 — console off leaves no console.** `-M ze0,gfx-display=off` starts, and
`screendump` answers `Error: There is no console to take a screendump from`.
This is the control for the property.

**O6 — the default is unchanged.** `run.sh` without `--display` (or with
`--display none`) still emits `-nographic` with no `-display` and no
`gfx-display=on`; `--dry-run` shows the same QEMU line as before the change
apart from nothing added.

**O7 — the patch series still applies.** `build.sh --check-version 11.1.3`
prints `ze0-h04-display-surface.patch APPLIES` and
`30 applied, 0 failed, 0 unpinned-tarball` (exit 0).

## Interpretation

- **FACT (C-7010):** `ze0-gfx` registers a QEMU graphic console named
  `ze0-gfx` when its `display` property is on (machine property
  `gfx-display`, default on) and composes DU planes 1–4 with the rule of
  `ze0_screenshot.py compose()` (higher plane number first, keyed mode
  `0xf000 == 0x1000` drops bit-15-clear pixels and the colour key,
  (A)RGB1555 → x8r8g8b8).
- **FACT (C-7011):** HMP `screendump FILE ze0-gfx` and
  `ze0_screenshot.py screen` of the same instant are pixel-identical
  (0/384,000 differ; raw pixel SHA-256 equal, O3).
- **FACT (C-7012):** `run.sh --display SPEC` (`none|gtk|sdl|dbus|vnc=HOST:N`)
  and `--vnc` set the console; `--display vnc=127.0.0.1:7` answers the RFB
  greeting on 5907 (O4). `--display none` is the old `-nographic` line.
- **FACT (C-7013):** `gfx-display=off` removes the console
  (`screendump` → `There is no console`), the negative control (O5).
- **OBSERVED (C-7014):** `tools/ze0_screencmp.py` compares a P6 PPM with an
  8-bit RGB PNG pixel by pixel (0 equal, 1 differ, 2 bad input; synthetic
  `--selftest`). PNG output from `screendump` needs libpng
  (`CONFIG_PNG`), which the pinned build does not enable, so PPM is the
  format the EXP uses.
- **UNKNOWN:** whether a host window (`gtk`/`sdl`) and mouse-to-touch
  (M8.H40) work on a machine with those backends built; only VNC and
  `screendump` were run here. The UI plane (buttons) is still fully keyed
  (M8.C1t).

## Conclusion

`ze0-h04-display-surface.patch` gives the machine a real QEMU console:
`screendump`, VNC, gtk and sdl now show the emulated unit's screen, composed
exactly as `ze0_screenshot.py` does (0 differing pixels, C-7011).
`run.sh --display`/`--vnc` select it, and the headless default is unchanged.
The next step is M8.H40 (mouse → touch on the live window) and M8.C1t (the UI
plane alpha rule). `tools/qemu-ze0/README.md`, `docs/emulator/README.md` and
`docs/research/qemu-connectors.md` name the console and the new flags.
