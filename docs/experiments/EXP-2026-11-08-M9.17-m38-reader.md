# EXP-2026-11-08-M9.17-m38-reader: L3 run of the M3.8 MMAIN001 reader

- **Status:** done (negative: blocked before any run; control passes)
- **Date:** 2026-11-08

  `LEAF_2011-2012_QSD-309-101_navi158_eu.img`, `archive/head256.img`, SHA-256

## Question

Can `runner.py run` execute the M3.8 reader (`Navi.exe` `0x0041a438`, the
`MMAIN001.DAT` open/read path, C-1780–C-1789) as a named L3 target, returning
the `0x1000`-byte read for a factory file, rejecting a 4095-byte file, and is
there a `mmain_reader` row in `targets.json` and `corpus.py`?

## Hypothesis

The runner can declare a target whose entry is a module VA (`entry.kind =
"module"`, the M9.20 kind), so M9.17 is reachable from the M9.5 runner alone.
Falsifier: the validator accepts a module-kind entry on `origin/main`, or a
module-kind target runs. Negative expectation: it does not.

## Inputs

- `tools/l3_harness/targets.json` on `origin/main`: 6 targets (`probe-zlib-cmf`
  synthetic; `hddinfo_compare`, `cmp_ind_reader`, `tile_reader`,
  `drstr_parser`, `mapcode_comparator` blocked).
- `tools/l3_harness/corpus.py` on `origin/main`: no `MMAIN` row.
- Reader VA `0x0041a438` from EXP-2026-11-06-M3.8-mmain-read (not re-derived
  here; see Observations for the `cerom` check).
- Scratch targets file: `targets.json` plus one `mmain_reader` row with
  `"entry": {"kind": "module", "va": "0x0041a438"}`, written outside the repo.

Five-part record of what was run. Commands run from the worktree root.

1. Positive control (runner works end to end on PySh4):
   `python3 tools/l3_harness/runner.py run probe-zlib-cmf --engine pysh4
   --input <scratch zlib_head.bin: 78 9c 00 00> --json`.

4. Corpus row search: `grep -n -i mmain tools/l3_harness/corpus.py
   tools/l3_harness/targets.json`.
5. Engine hook search: `grep -rn engine_hook tools/`.
6. Repo checks: `python3 tools/selftest.py`.

Counted corpus: 6 targets in `targets.json`; 0 with the reader VA; 0
`MMAIN` corpus rows; 1 positive control run.

## Observations

- Control (step 1): `status: PASS`, `exit: 0`, `accepted: true`,
  `backend: pysh4`, `expect.verdict: ACCEPT`, `problems: []`. A run with no
  `--input` returns `INVALID` (exit 1); this is a usage error, not a verdict.
- Listing (step 2): `RESULT: PASS (6 target(s))`; `probe-zlib-cmf` is the only
  `synthetic` target; `hddinfo_compare`, `cmp_ind_reader`, `tile_reader`,
  `drstr_parser`, `mapcode_comparator` are `blocked`. No `mmain_reader`.
- Falsifier (step 3): with the module-kind row added to a scratch copy,
  `targets` reports `FAIL targets[6] (mmain_reader): entry.kind must be
  synthetic or blocked` and two further failures (`corpus must be an object`,
  `expect must be an object`). `RESULT: FAIL (3 problem(s))`.
- Corpus and targets (step 4): no `mmain` or `MMAIN` match in
  `corpus.py` or `targets.json` (grep exit 0 with no lines).
- Engine hook (step 5): no `engine_hook` string anywhere under `tools/`.
  M9.20 (PR #89, `[M9.20] L3 plumbing`) is open and unmerged.
- Address check: `python3 tools/cerom.py --image-start 0x200200 archive/head256.img
  romhdr` returns `image_start 0x00200200`, `va_base 0x8cae1000`, `ROMHDR` at
  file `0x01951b78`. `va2file 0x0041a438` returns file `0x01098638`; this
  was not checked against the M3.8 module attribution, so no claim rests on it.
- Selftest (step 6): `passed=50 failed=0 skipped=18 total=68`, `selftest: OK`.

## Interpretation

M9.17 cannot run on `origin/main`. The runner (M9.5) only knows two entry
kinds, `synthetic` and `blocked`; a module-VA entry, which is what the M3.8
reader needs (no hand-built `-device loader` map), is rejected by the
validator. The stub-argument hook (`engine_hook`, M9.20's second item) is also
absent. The task therefore falls under M9.20, not M9.5: the M9.5 dependency is
satisfied, the M9.20 plumbing is not. This is a result about the harness, not
about the firmware reader; it says nothing on whether `MMAIN001.DAT` is read
correctly, and no verdict is claimed.

## Conclusion

Blocked. Blocker: the runner accepts only `entry.kind` `synthetic`/`blocked`
and has no `engine_hook`, so the M3.8 reader VA cannot be declared (M9.20,
PR #89, open). Unblock: M9.20.
