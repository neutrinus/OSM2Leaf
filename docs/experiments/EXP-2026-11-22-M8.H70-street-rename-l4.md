## Question

M8.C1f draws the London map from the factory card. If one street name is
changed on the card, in place, does the real `Navi.exe` in the emulator
draw the new name?

## Hypothesis

Street labels come from the `1=NAME` text in the tile's zlib record
streams (`ze0_decode.parse_names_section`, C-1090). A same-length rename
recompressed to the same stream length changes only that label.
Falsifier: the label stays the old name (the renderer takes names from
another file) or the map stops drawing (a check the format docs do not
know).

## Method

1. Factory boot (run F1): `run.sh --image CARD --sd OVERLAY --ipl-patch
   ipl.txt --verinf QSD-302-100 --mapdb 16-16 --icount
   shift=0,sleep=off`, screenshot with `ze0_screenshot.py screen` once the
   serial log shows `Pow >> Pow Off 1st Detect!!!` (O5). The map shows
   `AIR STREET` near Piccadilly Circus (the street chosen).
2. `tile_rename.py find B48R068R.DAT --text "AIR STREET"`: 2 streams.
3. `tile_rename.py rename … --old "AIR STREET" --new NEW --only
   0x06f643a0 -o NEWTILE`, then `imgpatch.py --image CARD --file
   MAPAL001/B48R068R.DAT --from NEWTILE -o NEWCARD` and `imgpatch.py
   --check-diff --reference CARD`.
4. Boot each changed card the same way (runs R1–R3), screenshot at the
   same point, pixel diff against F1.

Screenshots show manufacturer map data. They are kept out of the
repository and were given to Marek in the project thread.

## Observations

**O1 — Two streams hold the name.** Both are level-1 record streams
(word 2 = `0x00fa`), the text is `…\0\0\x0c 1=AIR STREET\0 ff 28…`:

| stream offset | compressed | plain | key (A, B) | place |
| --- | --: | --: | --- | --- |
| `0x061d3260` | 7 490 | 48 372 | `a61f cdef` | lat ≈ 50.8 (south coast) |
| `0x06f643a0` | 16 326 | 97 572 | `a6ac cdef` | lat ≈ 51.6 (London) |

Only the London stream was changed (`--only 0x06f643a0`).

**O2 — The factory encoder is Python's zlib at level 6.** For both
streams, `compressobj(6, DEFLATED, 15, 8, Z_DEFAULT_STRATEGY)` reproduces
the factory bytes exactly. A renamed stream recompressed with the same
setting keeps the length only for some names: `OSM STREET`, `ARI STREET`,
`TIR STREET`, `LIR STREET`, `IIR STREET` and `AJR STREET` give 16 326
bytes; `AIS STREET`, `LIT STREET`, `AIM STREET` and `AIR STREEL` do not,
and no other level/memLevel/strategy gives exactly 16 326 for them. The
south-coast stream renamed to `OSM STREET` does not keep its length with
any setting. A future rename that must change the length needs the
directory slot sizes (not done here).

**O3 — The card diff is the one stream.** `imgpatch.py --check-diff`
reports 11 ranges, 6 177 bytes, all `file_data` of
`MAPAL001/B48R068R.DAT`, outside 0, metadata 0 (no FAT, directory or
size change). Cards:

| card | name | card SHA-256 | tile SHA-256 |
| --- | --- | --- | --- |
| F1 | `AIR STREET` (factory) | `105e2032…076307` | `76aa5246…d3e60e` |
| R1 | `OSM STREET` | `e4bd803e6d42a8549b0d6c385eabd2e008911d602bb4e3f448e43991f6318304` | `44f3a4fce45bf958a3b772962f702bf07493d2491937b93560efb7942aca0fdf` |
| R2 | `ARI STREET` | `7889da93afbcbe11b3fefbf8c66084349683d62c648bbc05bab9fdf7f75c24f8` | `839c062d4311220813b298c4f3e361466d9f8ce6e40b00e3ab40c302cc43c8f4` |
| R3 | `TIR STREET` | `f32d288a76d7b62ffa22fda0b92ffaf8e9627a8b102cab52b9fa1a6966e60f1a` | `30527ba31c49a7a49ef4ca4c7dd85cfa8a734ae6afe40d20bb252f4088648f0b` |

**O4 — The screen.** All four runs reach the same map position and draw
the same number of non-black pixels (382 721 of 384 000).

| run | label drawn | pixels that differ from F1 | where |
| --- | --- | --: | --- |
| R1 `OSM STREET` | none | 1 362 | the `AIR STREET` label (plus 5 px at the A40 shield, top left) |
| R2 `ARI STREET` | `ARI STREET`, same place and angle | 214 | inside the label: the three swapped letters |
| R3 `TIR STREET` | `TIR STREET`, same angle, shifted along the street | 1 106 | the label |

Every other label, road and area on the screen is identical. `ARI` uses
the same three glyphs as `AIR`, so its label has the same width and lands
on the same pixels except the letters. `TIR` is narrower and is centred
again along the street. `OSM` is wider (`O`, `M` against `A`, `I`) and
the label is dropped, not truncated or moved.

**O5 — The run shuts itself down after the map is drawn** (the 45 s AUI wait of C-8200, M8.C1g; `ze0_aui.py --no-aui-timeout` removes it). With the
audio network unanswered (`CInaiProtocol … write failed`, as in
M8.C1d), `CAuiMonitorCmn::ThreadProc::TIMEOUT` logs `ErrorLogMsg
[ERR_PRC_SYS] … [0x00000039]`, then `Pow >> Pow Off 1st Detect!!!`, the
ACC-off notice goes to Navi (`SYS_NOTIFY_SYSTEM_SHUTDOWN`) and `Pow >> No
Action at ACC-OFF? Timeout!! Force PowerOff!!!` follows. The DU planes
keep the last frame, so the screenshot taken after this line shows the
map (all runs here). This is a few minutes of host time on this sandbox,
not the ~15 minutes of the M8.C1f run.

## Interpretation

- The map label text is read from the `1=NAME` entries in the level-1
  record streams of `MAPAL001` and drawn without any other check: no
  checksum, no lookup in `LCTBL001`/`REFER001`, no comparison with a
  second copy. A same-length, same-stream-length edit is accepted by the
  real `Navi.exe` and shows on screen.
- A label wider than its street segment is not drawn (O4, R1 against R2
  and R3). This is a label-placement rule of the renderer, not a data
  check: the narrower and equal-width names on the same record are drawn.
  HYPOTHESIS (C-8223): the placer compares the label length with the length of the
  polyline it follows. It matters for generated cards: long OSM names on
  short segments will be missing on screen, as on the factory card.

## Conclusion

First visible change made by us on the real navigation software: the
EU 2011 card with `AIR STREET` renamed in place to `ARI STREET` (or `TIR
STREET`) boots in `-M ze0` and the London map shows the new name in the
same place; the rest of the screen is pixel-identical. `OSM STREET`
does not show because the label no longer fits the segment.
