## Question

When a generated POI name page is longer or shorter than the factory stream,
can the compiler know its slot before it writes, and either keep the page inside
it with a stated headroom or refuse the page, with no page written past its slot
and no neighbour touched?

## Hypothesis

A page's slot is its factory stream plus the zero bytes after it up to the next
0x100 boundary (the M5.12c rule). A per-page budget (slot, stream bytes, encoder,
decision) decides fit or refuse before any write. **Falsifier:** (1) a changed
byte outside every fitted page's slot; (2) a fitted page whose names do not read
back at their offsets; (3) a fitted page whose stream exceeds `slot - headroom`;
(4) a control or selftest that passes on a wrong result.


   The image-level diff is `mkcard.diff_ranges(factory image, card.img,
   limit=100000)`; the limit was reached (see Observations).

   Each `build` writes per pair `POINTnnn.DAT.cmp.budget.json` (one row per edited
   page: `page`, `stream` = factory stream bytes, `slot`, `headroom`, `limit`,
   `encoder`, `new_stream`, `decision`, `edits`) and `POINTnnn.DAT.cmp.refused.json`
   (refused pages with the reason).

3. **Rule (per page).** `slot` = factory stream + zero bytes up to the next 0x100
   boundary; if a non-zero byte comes first, `slot` = the stream length.
   `headroom = ceil(ratio × stream)`. An edit fits iff the smallest stock-zlib
   stream (factory encoder tried first) is `≤ slot − headroom`. Otherwise the
   page is refused and its bytes are not written.
4. **Edits.** `NAME@` runs: first character not in `[A-Z0-9' &.-]` before it,
   4–40 characters, followed by `@`. Replacement: same length, text `OSM2 ` +
   letters of SHA-256(`file:page:offset`), cut to length. Length-changing edits
   are not made: the record tables of POINT001–009 are not known to this tool
   (M5.12c Observations), so each name keeps its length and only its content
   changes. The applied set has name lengths 4–38.
5. **Verification.** `verify` decodes factory and built pair; every changed byte
   must lie in a fitted page's slot; every changed name must read back as the
   generator's output followed by `@`.
6. **Controls.** *Positive:* (a) rewriting POINT009 with no edits returns the
   factory `.cmp` and `.ind` byte-for-byte; (b) selftest: the factory encoder
   reproduces the synthetic stream, the no-op refit is byte-identical, a fitting
   same-length edit leaves the neighbour page intact. *Negative:* an incompressible
   same-length page (stream 3,022 B) into a 52 B slot is refused with the bytes
   unchanged; headroom 1.0 refuses a fitting edit; a name without `@` is refused.

   ```bash
   ~/.venvs/ze0/bin/python -I -c "import sys; sys.path.insert(0,'tools'); from pathlib import Path; import slot_budget as sb; p=Path('leafre-work/m5.14-poi/factory/REFER001/POINT009.DAT.cmp'); u,cs,o,pk,b=sb.read_pair(p,p.with_suffix('.ind')); c,i=sb.write_pair(pk,o,u,cs,b,b); print(c==pk, i==p.with_suffix('.ind').read_bytes())"
   ```

   Observed: `True True`.
7. **Scope.** Covered: all 11 POINT pairs of the US factory image: 31,371
   complete zlib pages, 5,891,589 `NAME@` matches. Excluded: `ADDRE`, `COORD`,
   the uncompressed files, and POINT page bodies that are not complete zlib
   streams. `NAME@` is a byte pattern; it is not checked as a POI record type
   (the M5.12c rule, unchanged).
8. **Falsifier.** As stated above.

## Interpretation

- **FACT (C-2580):** the slot rule holds in code and selftest. 8,113 of the 8,229
  edited pages (98.6 %) abut the next page with zero slack, so growth is refused.
  The packing is the main limit: even at 0 % headroom 7,943 of 8,229 pages are
  refused. Headroom matters at the margin (19 fitting pages at 4 %, 286 at 0 %).
- **Headroom 4 % (C-2582):** a portability margin, not a stock-zlib need. Stock
  zlib never re-encodes a page larger than the factory (C-2581); zlib-ng does,
  by up to 3.64 %. The build must give the same answer on a non-stock zlib, so a
  4 % free margin covers the measured cross-zlib excess. The 4 % build is the one
  to use; the 0 % build shows what the margin costs (267 pages and 138,336 names).
- **Result (C-2583):** with hash-derived same-length names, 19 pages (13,749
  names, above the 1,000 asked) apply inside their slots; 8,210 pages are
  refused, each left unchanged and listed in `*.refused.json`. Done-when (b) is
  met by its second branch ("lists each refused page"). The Stop condition
  ("no headroom keeps pages inside their slots") is not met: some pages fit.
- **Generator effect (HYPOTHESIS):** random-looking names grow a page more than
  real OSM names would. The refusal rate depends on the generator; this run
  measures the rule, not real names. Not measured: a real-name edit set.
- **Encoder (C-2588):** M1.13 (on `main`) reproduces the factory POINT001–009
  pages with stock zlib level 6, memLevel 8. The budget tries that encoder first,
  then the smallest of the 18 stock settings (levels 1–9 × memLevel 8/9). None of
  the 8,210 refused pages fits under any of them. Other zlib parameters (strategy,
  window bits) were not tried.

## Conclusion

`tools/slot_budget.py` gives a per-page budget before any write. On the real US
card it keeps every written byte inside its slot (decoded domain and image
check), lists every refused page, and the card passes `cardcheck`. The headroom
is 4 % of the factory stream, the measured cross-zlib excess. The factory POI
pages are nearly full: 98.6 % of the edited pages abut their neighbour, and the
encoder is not the limit (C-2588), so more names need page relocation (pointer
tables), a separate task.

## Scope limits

- Not verified in a car (no hardware, per AGENTS.md). The names are not checked
  on screen.
- No length-changing edits: M5.12c's `--resize` for POINT001–009 is not on
  `main`, and the record tables are not known to this tool.
- `mutate_refer_poi.py` on `main` has no `refit_page`/`FitError`; its M5.12c
  version is on the unmerged branch `claude/m5.12c-poi-copies`. This tool does
  not import it and does not change it. The two slot rules are the same rule,
  written twice; reconciling them belongs to the M5.12c owner.
