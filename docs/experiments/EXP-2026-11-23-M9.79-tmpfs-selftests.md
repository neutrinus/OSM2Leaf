## Question

Do `tools/identity_fields.py --selftest` and `tools/sdlock_pico_check.py --selftest` fail only because their scratch writes land on the 3.8 GiB `/tmp` tmpfs (where this host gets `OSError: [Errno 122] Disk quota exceeded` / `fatal error: error writing to /tmp/…: Przekroczony limit dyskowy`), so that re-pointing them at `~/projekty/leafre-work/scratch/<tool>/` restores a green gate with every assertion, CLI and expected value unchanged?

## Hypothesis

The two failures are host filesystem conditions, not code regressions. Redirecting the temp files and the compiler's temp dir to a home-tree scratch directory (created on demand, deleted on exit) makes both `--only` runs PASS and the full suite print `failed=0`, without disabling a selftest, widening a skip set or changing an assertion. **Falsifier:** a selftest still fails with EDQUOT after the change; a scratch directory remains after a green run; the compiler still writes its `.s` temp to `/tmp`; an assertion/CLI/expected value changes; or the reintroduced `/tmp` mutant still passes.

## Interpretation

- **FACT:** With `TMPDIR` unset, both `--only` runs fail (`OSError: [Errno 122]`; gcc's `Przekroczony limit dyskowy` on `/tmp/cc*.s`) while `df -h /tmp` reports `81%`; after redirecting writes to the home-tree scratch they PASS and `df -h /tmp` still reports `81%`. The full suite went from `failed=2` to `failed=0` and the gate reports `5 pass, 0 fail, 0 skip`, with no scratch directory left behind (`find` exit 1).
- **OBSERVED:** `skipped=21` is unchanged, so no skip set was widened. `total` rose 287 → 290 because other tasks merged new selftests into `origin/main` during this work. The 21 `ok` lines and 25 `expect(` calls of `identity_fields.py` are unchanged and `git diff` shows no changed assertion, CLI or expected value.
- **HYPOTHESIS:** The failures were host-only tmpfs conditions; the compiler's `TMPDIR` override is required because gcc's `.s` intermediate, not just the `-o` output, was the original EDQUOT source. The navigator's negative mutation (reintroducing `/tmp` in each tool) reproduced both errors, confirming the fix is causal.
- **UNKNOWN:** none in scope.

## Conclusion

Repointing the two selftests' scratch writes from the `/tmp` tmpfs to `~/projekty/leafre-work/scratch/<tool>/` makes both `--only` runs PASS, the full suite print `failed=0` and the gate report `5 pass, 0 fail, 0 skip`, with no assertion, CLI, expected value or skip set changed and no scratch left behind.
