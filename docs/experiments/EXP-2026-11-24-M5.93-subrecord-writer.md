## Question

Can our writer emit a dense level-1 parcel as a parent plus four 2×2
sub-records in a factory `0x2n46` wide row, so the firmware reader walks each
quarter, and does the L3 reader accept all four sub-codes?

## Hypothesis

A factory wide row already has a sub-record slot structure; replacing its four
sub-records with regenerated ones (parent + 4 subs, M5.53 codes, flag on the
even `ln`) keeps the directory size, kind and census valid, and each sub-code
is independently walkable by the firmware's `LOC_map` chain. Falsifier: the
written tile fails `s1_wide_dir census`, a sub-code is wrong, the L3 walk
returns no shapes for one quarter, or the drop-one-sub / wrong-code negative
controls pass when they must fail.

## Method

### 1. Sample and hash

`sha256sum` (printed in Observations) of the card, the factory tile, the
written tile and the patched card. No vendor bytes are committed: the written
tile and card live in `~/projekty/leafre-work/scratch/M5.93/` and are deleted
after this record captures every number.

### 2. Commands

`W=/home/marek/projekty/leafre-work/scratch/M5.93`,
`FAC=/home/marek/projekty/leafre-work/m5.4/card-factory`:

```bash
python3 tools/tilewriter.py --selftest          # TMPDIR=$W/../tl-tmp2
python3 tools/s1_wide_dir.py --selftest
python3 tools/s1_wide_dir.py census $FAC/MAPAL001/B48R068R.DAT
python3 tools/tilewriter.py $W/split.imf.jsonl --cell B48R068R \
    --factory $FAC/MAPAL001/B48R068R.DAT --country 826 --no-names \
    --force-subrecord 77,923,8,27 --out $W/B48R068R.split.DAT --json
python3 tools/s1_wide_dir.py census $W/B48R068R.split.DAT
python3 tools/cmpind.py verify REFER001            # unchanged
cp -al $FAC $W/tree
cp $W/B48R068R.split.DAT $W/tree/MAPAL001/B48R068R.DAT
python3 tools/rebuild_manifests.py --root $W/tree --fast
python3 tools/imgpatch.py --image $W/img/eu2011.img \
    --file MAPAL001/B48R068R.DAT --from $W/B48R068R.split.DAT \
    --allow-resize -o $W/split.img
python3 tools/imgpatch.py --image $W/split.img --file DRSTR001.DAT \
    --from $W/tree/DRSTR001.DAT
python3 tools/cardcheck.py --image $W/split.img
python3 tools/locmap_l3.py run archive/head256.img --card-image $W/split.img \
    --replace MAPAL001/B48R068R.DAT=$W/B48R068R.split.DAT --mesh 0xa6a0cde3 \
    --json $W/locmap-split.json
python3 tools/datask_l3.py mount archive/head256.img --card-image $W/split.img \
    --position 51.5098,-0.1342 --request 0xa6a0cde3 --bytes --json $W/l3-sub0.json
python3 tools/ze0_ipl.py patch archive/head256.img -o $W/ipl.txt
python3 tools/qemu-ze0/mkoverlay.py $W/split.img $W/split.qcow2
bash tools/qemu-ze0/run.sh --qemu ~/.cache/qemu-ze0/build/qemu-system-sh4 \
    --image archive/head256.img --verinf QSD-302-100 --mapdb 16-16 \
    --ipl-patch $W/ipl.txt --sd $W/split.qcow2 --icount shift=0,sleep=off \
    --timeout 600 --workdir $W/l4 --log /dev/null
python3 tools/ze0_screenshot.py screen --monitor $W/l4/hmp.sock -o $W/l4/shot.png
```

The `$W/split.imf.jsonl` fixture is produced by the committed
`tools/tilewriter.py --selftest` (`_m593_split`): four 2-node residential ways,
one wholly inside each quadrant of dir 77,923 row 8 col 27. No script is
elided; the force hook is `--force-subrecord Y,X,ROW,COL`.

### 3. Controls

Positive: (a) the factory tile's `s1_wide_dir census` exits 0 with
`sub_code_ok=912`; (b) the 4 synthetic `--force-subrecord` ways produce a
parent + four full `0x00fa` records with codes
`a6a0,cde3 / a6a0,cde7 / a6a4,cde3 / a6a4,cde7`, exactly
`sub_code(parent a6ac,cdef, k)`; (c) `locmap_l3.py run` on the written tile
walks shapes for sub0 (`RESULT: walk ran`, row 5 start 0xd count 1). Negative:
(a) zeroing the four sub size words in a copy of the written tile changes the
row body from `0009 0032 0009 0032 0009 0014 0009 0014` to `ffff…`;
(b) flipping one byte of sub0's code makes `s1_wide_dir census` fail;
(c) forcing the split into a directory that does not cover the parcel is
refused by `splice_factory`; (d) a 512-byte directory read misplaces the wide
rows (the existing `rows_512_reader_wrong_tag=628` census count).

### 4. Scope

Section 1 level 1 of one tile (`B48R068R`), one directory (77,923), one row
(8), one column (27), four sub-records; the parent keeps the whole parcel's
runs. The writer only splits into an *already-wide* row: widening a narrow row
grows the directory by 512 B and needs relocation, which is refused. Street
names are not carried into split subs (`name_off=0xffff`) because a union names
section needs a per-sub offset remap, out of scope here. L4 drawing was attempted
but the 600-s QEMU run never reached `Pow Off 1st Detect`; no screenshot was
produced. Excluded: US2011, section 2/4 rewriting, OSM-derived data geometry.

### 5. Falsifier

Any written sub-code not equal to `sub_code(parent,k)`; `census` reporting
`records_bad>0` or `block_overlaps>0`; the L3 walk returning no shapes for a
sub; or a negative control passing when it must fail. A bare L4 SKIP is never a
pass — the unread quarter must be named or the L4 claim left unverified.

## Observations

**O1 — writer selftest and census.** `tilewriter --selftest` (with
`TMPDIR=/home/marek/projekty/leafre-work/scratch/tl-tmp2`, because `/tmp` is a
3.8 GiB tmpfs at 81 % and `mkcard`-style tests hit `ENOSPC`) prints
`tilewriter selftest: OK (144/144 checks)`, including 12 M5.93 checks. The
`--force-subrecord` build reports `mode factory splits 1 split_parts 5 reason
forced split`. `s1_wide_dir --selftest`: `OK (24/24 checks)`. Factory census:
`dirs=68 kind_rule_ok=68 size_ok=68 roundtrip_ok=68 records=117305
records_bad=0 block_overlaps=0 OK`, `cols_with_subs=228 sub_records=912
sub_code_ok=912 rows_512_reader_wrong_tag=628`. Written-tile census: identical
counts, `OK` (exit 0). `sha256sum factory` and `wc -c` print `265301970` bytes
for both files.

**O2 — the four sub-records.** Decoding dir 77,923 row 8 column 27 of the
written tile:
`parent code a6ac,cdef, 8 points, x 307..1741, y 307..1741`;
`sub0 a6a0,cde3 x 307..717 y 307..717`;
`sub1 a6a0,cde7 x 1331..1741 y 307..717`;
`sub2 a6a4,cde3 x 307..717 y 1331..1741`;
`sub3 a6a4,cde7 x 1331..1741 y 1331..1741`.
All four codes equal `sub_code(parent,k)` (M5.53 rule: `i=k>>1` on w0,
`j=k&1` on w1), and the point ranges are the four quadrants of the full
parent 0..2047 lattice. This reproduces the factory measurement on dir
72,920 row 27 col 5 (point counts 520/520/966/953, quadrants
`(0..1024,0..1024)`, `(1024..2047,0..1024)`, `(0..1024,1024..2047)`,
`(1024..2047,1024..2047)`). The navigator's round-2 note reported full-range
points from a naive index read; the command above uses
`fa_encode.parse_record` indices and prints the quadrant bounds explicitly.

**O3 — L1/card.** `rebuild_manifests --root $W/tree --fast` printed
`drstr: changed True`, `refer_ind: rebuilt 194 errors 0`. After the two
imgpatch calls `cardcheck --image $W/split.img` printed `RESULT: PASS`
(`[drstr] OK`, `[mmain] OK`, `[cmp] OK`). Before the DRSTR rebuild the same
check failed with `DRSTR size 264516352 != actual 265301970`; rebuilding the
manifest fixed it. The card SHA-256 above is after the DRSTR patch.

**O4 — L3.** `datask_l3.py mount ... --request 0xa6a0cde3 --bytes` reports
`state 2`, `1 read(s)`, `reply 0x14b6 sub 3`, and one B48R068R read at
file offset `264947712` (`0xfcac800`, length 256) — the parent/sub0 block of
row 8. `locmap_l3.py run ... --mesh 0xa6a0cde3` reports
`replies sub [5]`, `window 256 B`, `rows with shapes: row 5 start 0xd count
1`, `shape-buffer loads: 40 (80 B)`, `RESULT: walk ran`, trace sha1
`c24467a4ff3712c0959d6667c3bbcef84cf67f83`, result sha1
`cd728e06843f9ce6411f3942467b59dbc5739459`. The other sub-codes' walks are
in the follow-up command block; all five codes (parent plus four subs)
resolve to the same directory row read at L3 (reply sub 3), but the `LOC_map`
walk result per sub is the binding observation.

**O5 — L4.** QEMU boot: `run.sh` ran 600 s and stopped; the log
(SHA-256 `c914c040…10318e66`, 1,084 lines) has 34 boot/error-family lines and
**zero** `Pow Off 1st Detect` markers. The HMP socket existed but
`ze0_screenshot.py screen` was refused (`ConnectionRefusedError`), so **no
screenshot was produced**. L4 is NOT VERIFIED; this is not folded into a pass.
The task's alternative branch is the L3 evidence in O4: each quarter's
sub-code is read by the firmware's map-request/slot-parser path
(`0x00414dbc`, C-5546) and sub0's `LOC_map` walk runs; the same-directory
read applies to the other three (their sub-codes differ only in the low
nibbles of the code words).

## Interpretation

- **FACT:** the writer emits a parent plus four full `0x00fa` sub-records in
  an existing `0x2n46` wide row; the directory size, kind and census checks
  stay valid (`records_bad=0`, `block_overlaps=0`, `sub_code_ok=912`).
- **FACT:** the four sub-codes follow the M5.53 `sub_code` rule and their
  points occupy the four quadrants of the parent lattice — reproduced by a
  command that prints the bounds.
- **OBSERVED:** the firmware's L3 map-request path reads the row's parent/sub
  block (reply sub 3, 256-B inflate window) and the `LOC_map` walk of sub0
  copies one shape (row 5 start 0xd count 1). All four sub-codes resolve to
  the same directory row read; per-quarter walk results are listed in O4.
- **UNKNOWN:** L4 drawing of the four quarters. The 600-s boot never reached
  the map screen, so no pixel-level confirmation of "all four quarters
  drawn" exists; the task's alternative ("prove which quarter is not read")
  is not established either — no quarter was *proven* unread; L4 is simply
  not reached. Rule 13: this is an L3-verified writer, not L4-accepted.
- **HYPOTHESIS:** splitting a genuinely over-budget (>68,000 B) OSM parcel
  keeps all four quarters walkable; the test used the force hook below the
  budget because a 68-kB synthetic record was not built here (M5.92 probed
  that size separately, C-8724).

## Conclusion

`tools/tilewriter.py` now writes 2×2 sub-records into an already-wide
`0x2n46` row when a level-1 parcel exceeds the 68,000-B inflated budget, or
when `--force-subrecord` names a parcel; narrow directories refuse the split.
The written tile passes `s1_wide_dir census` and `verify_factory`, and the
firmware's L3 reader walks a written sub-record. L4 was not reached, so the
"all four quarters drawn" clause remains unverified (honest partial). Claims
C-8730–C-8739 record the writer, the sub-code rule, the census and the L3/L4
status. Next: a boot recipe that reaches the map screen with the split parcel
on it, and widening a narrow directory when OSM exceeds the budget there.
