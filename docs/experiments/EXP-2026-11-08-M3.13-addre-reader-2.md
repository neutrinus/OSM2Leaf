## Question

Does `Navi.exe` (build A) contain a reader that consumes ADDRE `c0`/`c8`/`c1`
record headers, when searched with the **mask/stride signature the writer
implies** (native swapped `u16`, POINT lesson C-2129) rather than the M4.9 byte
grammar? Can the mapped `0x14e8`/`ADDRE0` path be probed? Can any C-970–C-979
grammar field be mapped to a consuming instruction?

## Hypothesis

Exploratory (re-opened ninth pass). Falsifier: if no `0xc000`-class header gate
(`*r & 0xe000` tested against `0xc000`, or equivalent) and no `2*L` native-word
stride walker exists in the 282 uncompressed build-A o32 sections (23.6 MB)
AND the `0x003f56bc`-area REFER buffer family shows no ADDRE-relevant behavior,
then the ADDRE record parser is not statically locatable in uncompressed code
by structural signature either.

## Observations

### O1. Writer-implied native `u16` / mask signature (derived, not guessed)

POINT (C-2129/C-2540): firmware reads swapped native `u16` `w`; `type=w&0xfc00`,
`len=w&0x03ff`, `2*len` byte advance (`fn 0x003f5194`: `mov.l #0xfc00,r7; and r7,r1;
cmp/eq r7,r1` escape; else `and #0x3ff; shll; add`). ADDRE file bytes `[tag,L]`
(`c0`/`c8`/`c1`, C-973) in the same swapped-native form give `w=(tag<<8)|L` =
`0xc000|L`, `0xc800|L`, `0xc100|L`. Structural class test implied: `w & 0xe000`
yields `0xc000` for all three (top 3 bits `110`), so `cmp/hs` of `(w & 0xe000)`
against `0xc000` accepts c0/c8/c1 — distinct from POINT's `w & 0xfc00 == 0xfc00`
escape test and from byte `cmp/eq #0xc0`.

### O2. Literal/mask search (Navi.exe sec0)

| --- | ---: | ---: | --- |
| `0xc000` | 82 | **1** | `0x003f56ec` (`fn 0x003f56bc`) |
| `0xc800` | 1 | 0 | `0x000826c6` (non-parser context) |
| `0xc100` | 2 | 0 | `0x0014fcf0`, `0x001a7f2e` |
| `0xa000` | 8 | 0 by `cmp/hs`; 1 exact `cmp/eq` class test | `0x003f57fa` (`*r5 & 0xe000 == 0xa000`) |
| `0x03ff` | 35 (point_walk_l3 consts) | — | includes POINT `0x003f51ae` |
| `0xfc00` | 13 | — | includes POINT `0x003f5196` |

`sh4scan stride --module Navi.exe`: `mov.b @(1,Rm),R0 586 / +doubling 0 / +cursor 0`

## Interpretation

- **FACT (refines C-2181):** Pass 1's byte-grammar search (`cmp/eq #0xc0/#0xc8`,
  `mov.b @(1)+cmp #0x40`, `mov.b @(1)+shll` 2*L) found no ADDRE record-stream
  walker — that negative stands for those signatures. Using the writer-implied
  native `u16`/class-mask signature (C-2129 lesson) finds **one** 0xc000-class
  header gate in Navi.exe sec0: `fn 0x003f56bc` at `0x003f56ec` loads literal
  `0xc000`, masks `*r5` with `0xe000`, and accepts headers with `(w & 0xe000) >=
  0xc000` (`cmp/hs`), which covers ADDRE `c0`/`c8`/`c1` native tags
  (`0xc000|L`/`0xc800|L`/`0xc100|L`). This is the only such gate among 82
  `0xc000` literal loads in sec0.
- **FACT:** `fn 0x003f56bc` resolves a REFER buffer via `fn 0x003f51e0` (shared
  `0x00d53500` table with POINT walker `0x003f5194`, C-2540 family), consumes the
  header class of `*r5`, advances by `2 * u16@(context+2)`, walks a sub-table
  (`u16` offsets/counts at `+24/+26`, entry compare at `+12`, 2-byte stride) to
  locate index `r6`, and dispatches on header/type bits to compute a return
  pointer. Called by `fn 0x003f5d98` and `fn 0x003f61bc` (xrefs verified).
- **OBSERVED:** `fn 0x003f56bc` consumes the C-973 record *tag class* (c0/c8/c1
  acceptance) of the header word at `*r5`. Its `2*u16@(context+2)` advance and
  `+24/+26/+12` sub-table walk address an indexed record/sub-record structure;
  mapping these to C-970–C-972/C-977 container/index/directory/cell/trailer
  fields or to C-974–C-976 token parsing (name/range/point) is **not established**
  by static inspection alone — the function returns/locates an entry rather than
  token-walking the M4.9 name/range/point grammar.
- **HYPOTHESIS:** `fn 0x003f56bc` (or `0x003f5d98`/`0x003f61bc` over it) is an
  ADDRE/REFER 0xc0xx record accessor for decoded `ADDRE0xx` data reached via the
  `0x14e8`/`0x00d53500` buffer path; confirming the buffer-slot→ADDRE binding
  needs an L3 trace with 0xd53500 + decoded ADDRE data (follow-up).
- **UNKNOWN:** A sequential `2*L` walker over the ADDRE *record stream* (C-973
  cursor framing, advancing by `2*L` per `[tag,L]` record) in uncompressed code;
  consumers of C-971 (12-byte directory), C-972 (6-byte cells), C-974 (`TT LL 00
  ff` name), C-975 (range tokens), C-976 (`TT 40 XX YY` point), C-977 (trailer
  TOC) — none mapped to instructions. C-970/C-979 unchanged.

## Conclusion

The pass-1 "not in uncompressed code" was a **signature** miss (C-2129 class):
searching byte immediates (`#0xc0`) found nothing, but searching the
writer-implied native `u16` class mask finds `fn 0x003f56bc` (`0x003f56ec`,
Navi.exe sec0, uncompressed) — the sole `0xe000`-masked `cmp/hs >= 0xc000`
header-class gate in sec0 — which accepts ADDRE `c0/c8/c1` tags and operates in
the REFER `0x00d53500` buffer family (`0x003f51e0`, alongside POINT). The
grammar-field mapping (C-970–C-979) remains **partial**: C-973 tag-class
acceptance is consumed at `0x003f56ec..0x003f56f0`; all other fields are not
mapped to consuming instructions (and, given 0 compressed executable sections,
absence in this signature family is meaningful but a different token-consumer
signature may still exist). Access path C-2180 stands; L3 probe of the access
functions faulted without COREDLL/state (negative, documented).
