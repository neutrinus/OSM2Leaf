## Question

Why does `cerom.py thunks` find no import stub on real image A (C-1714), and
can it be fixed so it labels the EXP-50 thunks correctly and reaches ≥95%
slot coverage on `IMG256`?

## Hypothesis

`thunks_report`/`scan_section_stubs` read PC-relative literals via ROM-linear
`va2file`. Navi.exe uses module-local process VAs (`vbase=0x00010000`,
`realaddr=0x00011000`, slot VAs `0x0055d000+`), not ROM VAs (`0x8cae1000+`),
so `va2file` returned out-of-range offsets and every literal read failed,
discarding all stub candidates. Mapping literals through the section's
`realaddr`/`dataptr` fixes detection.

## Observations

Navi.exe section layout (explains the VA spaces):

```
vbase=00010000 entry=0032edd0 import=00548328+104
sec0 rva=00001000 psize=0054be00 dataptr=8d570000 realaddr=00011000 flags=68000020 (uncompressed .text)
sec1 rva=0054d000 psize=0000457c dataptr=8e1f9ae4 realaddr=0055d000 flags=c8002040 COMPRESSED (IAT/data)
sec2 ... COMPRESSED
```

`realaddr`/slot VAs are module-local (`0x00011000`/`0x0055d000+`); `dataptr` is a
ROM VA. ROM-linear `va2file` = `va - 0x8cae1000 + 0x200200`, so
`va2file(0x003d1bb0)` = `0x-8c50f250` (out of range) and `read_u32_va` returned
`None`, causing `scan_section_stubs` to discard every candidate.

After the fix:

- `va2file 0x003d1bb0` → `0x0104fdb0` (resolved via section `realaddr`/`dataptr` mapping).
- `thunks Navi.exe --min-coverage 95` exits **0**.
- Counts (JSON, no resolver): `stubs=3728, resolved=3592, import_slots=846, covered_slots=845, errors=0`; coverage `slots 845/846 = 99.9%`, `stubs 96.4%`.
- Counts (JSON, `--resolve-with 0x3e00200`): `resolved=3728/3728` (100.0%), slots 99.9%.
- EXP-50 (both cases): `0x3d1ba4 slot 0x55d38c OBJDLL.dll!MAL_DataVol_getSize #4 4-insn resolved`; `0x3d1bb0 slot 0x55d390 OBJDLL.dll!MAL_DataVol_getOffset #3 4-insn resolved`.
- Uncovered slot (1/846): `0x55d910 OSMDLL.dll #7` — loaded by `mov.l @(pc),R9` at `0x32eff8` but no standard `mov.l @R9,Rm; jmp/jsr @Rm` deref+call window was found; it sits in a literal pool region and is not used as a direct IAT call-through in the detectable form.
- `realcheck.py IMG256` → **8 PASS, 0 FAIL, 0 SKIP** (thunks pin updated to `stubs=3728, import_slots=846, covered_slots=845, slot_coverage=99.9`).
- `cerom.py --selftest` → **367 checks OK** (includes `build_thunks_rom(local_va=True)` M1.6c regression: module-local VAs, `va2file` resolves, 3 stubs found/resolved, slot coverage 100%, CLI exit 0).
- `sh4xref.py --selftest` → OK. `tools/selftest.py` → **passed=32 failed=0 skipped=19 total=51**.

## Interpretation

- **FACT (root cause):** Navi.exe `realaddr`/slot VAs are module-local (`0x0001xxxx`), while `va2file` was ROM-linear (`va - 0x8cae1000 + 0x200200`). The scanner read section bytes via `dataptr` (correct) but computed PC-relative literal VAs in `realaddr` space and read them with `va2file` → out-of-range/negative → `read_u32_va` returned `None` → every stub candidate skipped → "no import stub matched" (C-1714). The 4-insn pattern also only matched register `R0` (hardcoded `mov.l @R0,R0`/`jmp @R0`), and `resolve_thunk` rejected non-mappable slot VAs before checking `imports_at`.
- **FACT (fix):** `scan_section_stubs` reads literals via section `realaddr`/`dataptr` (`read_u32_realaddr`); the 4-insn matcher is register-flexible and accepts cross-register deref; `scan_section_stubs`/`thunks_report` also detect inlined IAT call sites (load of a known import slot + deref + `jsr/jmp` within a window, with arg-setup interleaving); `resolve_thunk` consults `imports_at` before mappability; `va2file` falls back to `realaddr2file` (o32 `realaddr` ranges) with a recursion guard; `thunks` accepts `--resolve-with`/`--names` (M1.9); `--min-coverage` gates on slot coverage (the M1.6b primary measure). Non-IAT 2/3-insn false positives are suppressed.
- **FACT:** 845/846 Navi.exe import slots have a detected standalone stub or inlined call site (99.9%); 3728 call-site records total (many slots have multiple inlined sites). With B exports, all 3728 resolve to names.
- **OBSERVED:** 1 slot (`OSMDLL #7`, `0x55d910`) is loaded but not deref+called in a standard window; its use is atypical (literal-pool/table context). 99.9% satisfies the 95% done-when.
- **FACT (realcheck pin):** H7 pinned `stubs=846` aspirationally without a real-image run while C-1714 showed 0. The corrected, measured pin is `stubs=3728, import_slots=846, covered_slots=845, slot_coverage=99.9` (3728 records reflect per-call-site detection, not one-per-slot). Updated in `tools/realcheck.py` per task spec.

## Conclusion

C-1714 is resolved for Navi.exe: thunks are found, EXP-50 thunks label correctly,
and slot coverage is 99.9% (≥95%). `realcheck.py` is green (8/8) on `IMG256`.
