## Question

Does a committed tool reproduce the whole `ICODE001` field decode and explain
over half the file on both the EU and the US factory card — or is the claimed
layout wrong or partial?

## Hypothesis

`ICODE001` = ISO table at `0x1000` + per-language area-name trees whose
`roff`/`cnt` are halfword child offsets/sizes relative to each language's
country-chain root (the M4.12 layout). If the layout is right the decoder
explains nearly all bytes; the **falsifier** is that it explains **under half**
the file, i.e. the layout is wrong or partial and the unexplained part must be
named, not guessed.

## Method

1. **Sample and hash.** The four files above; decompression via `cmpind.decode`.
2. **Commands.** Decompress both images, then run the census (one command each),
   plus the synthetic self-test and the negative control:

   ```bash
   python3 -c "import sys; sys.path.insert(0,'tools'); import cmpind; \
     b,_=cmpind.decode('/home/marek/projekty/leafre-work/m4.8b-eu/REFER001/ICODE001.DAT.cmp', \
                       '/home/marek/projekty/leafre-work/m4.8b-eu/REFER001/ICODE001.DAT.ind'); \
     open('/home/marek/projekty/leafre-work/scratch/m4.80/eu-icode.dat','wb').write(b)"

   python3 tools/icode_decode.py --selftest
   python3 tools/icode_decode.py census /home/marek/projekty/leafre-work/m4.8b-eu
   python3 tools/icode_decode.py census /home/marek/projekty/leafre-work/m5.12-us/root-factory
   python3 tools/icode_decode.py census /home/marek/projekty/leafre-work/m5.12-us/root-factory --mutate-byte 0x1500
   ```

3. **Controls.**
   - *Positive:* the decoder must find each language's 33-row country chain and
     name it (EU first chain `ANDORRA, BELGIEN, BULGARIEN, DÄNEMARK`; US
     `CANADA, UNITED STATES`); the `--selftest` synthetic file must reach 100 %
     of its tree region and discover 2 roots.
   - *Negative:* `--mutate-byte 0x1500` flips the US root row's `rlen` byte; the
     census must notice (fewer rows/bytes). A byte inside a name field
     (`--mutate-byte 0x150c`) is expected **not** to change coverage — names are
     opaque to the walker — and is the limit of this negative control.
4. **Scope.** Both factory cards' `REFER001/ICODE001.DAT` in full (EU 111.4 MB,
   US 6.07 MB). Not covered: the unwritten bytes (zero padding and the
   `CLARION` header), the `REFER002/ICODE001` EV-layer file (2013+), and the
   firmware reader (no new run here; C-5762/C-5763 remain the reader evidence).
5. **Falsifier.** Explained share < 50 % on either card.

## Interpretation

- **FACT:** A committed tool (`tools/icode_decode.py`) explains 99.299 % of the
  EU file and 99.791 % of the US file. Rows are 12-byte header + name; `rlen` is
  the row size in halfwords, `roff` the child offset relative to the language
  root, `cnt` the child size in halfwords, `nlen==0` a redirect/container row,
  `roff==0xffffffff` a terminator.
- **FACT:** EU has 8 language chains, not 7; the missing one is French at
  `0xd4b200` (C-7811). All 8 have identical shape (695,098 rows).
- **FACT:** names and ISO tier labels are Latin-1, not UTF-8 (C-7813); the doc's
  "UTF-8 (per `icode_io`)" is wrong.
- **OBSERVED:** the residual is zero-fill (alignment to the next root / card
  block), the `0xff`-padded `CLARION` file header at `0x0–0xfff`, and a handful
  of bytes inside inter-chain gaps — no chain bytes are left unexplained (C-7815).
- **UNKNOWN:** the root-pointer index table the firmware uses to find the 8
  roots -- still not located (M4.12/Rule: roots recovered from data); the
  firmware reader VA map is unchanged (C-5762/C-5763), not re-run here.

## Conclusion

`ICODE001` is decoded and reproducible: the tool prints both languages' roots
with their names, 5.56 M EU / 0.28 M US rows, and 99.3 % / 99.8 % of the bytes,
so the falsifier (under half explained) does not fire. `docs/format/
coord-zcode-icode.md` is corrected in two places only where the census
contradicts it: the EU chain count is 8 with the French root `0xd4b200`, and the
name/tier charset is Latin-1, not UTF-8. The `reader-coverage.md` row 9 Offline
cell changes from `claim` to `tool`. The root-pointer table stays open
(unchanged).
