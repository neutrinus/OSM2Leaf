## Question

Can one stdlib command, with no gate change and no edits to the records, tell a reader which `docs/experiments/EXP-*.md` files fail the structural rules of `TEMPLATE.md`, and does it name the two records the SE pass found defective (M1.50, M8.H35)?

## Hypothesis

A lint whose heading set and five Method part labels are read from `TEMPLATE.md` at run time, whose Sample rule joins wrapped bullets, whose waiver is only a backticked `none (tool-only task)`, and whose `# ...` rule is scoped to Method part 2, will FAIL both defective records by name and PASS a fixture of three compliant records. Falsifier: it PASSes M1.50 or M8.H35, PASSes an elided command, FAILs the case/spacing record, or edits an EXP.

## Corrections after navigator review

Round-1 CHANGES, all applied before the build:

1. "no `## Scope` heading" was wrong terminology — TEMPLATE has no `## Scope`; the tool parses the five numbered bold part labels from the Method section (`grep -cE '^[0-9]+\. \*\*'` prints **5**).
2. The full TEMPLATE heading set (**10**, read at run time) is required, with case/whitespace normalisation so `##  method  ` passes.
3. `# ...` detection is scoped to Method part 2 **Commands** only, so M8.H35's abbreviated hash and H18's prose are not mis-attributed.
4. The Sample rule joins wrapped bullets, requires at least one full 64-hex hash, and accepts only a backticked `none (tool-only task)` waiver; output is `FAIL <basename>: <reason>` and `--json` carries the same verdict.
