- **STORE_WRITE (clear/init):** 14 sites (20–26, 28–33, partially 29) dominated by `fn 0x0040dfa8` (6 loads, many zero stores r3=0/r2=0 across slot ranges) and `fn 0x00415fe8` (6 loads, conditional zero stores) plus `fn 0x0040e4b2` (2 zero stores). - **No load site is address-only pass-through without memory access** in this classification: every site is READ or STORE_WRITE by opcode evidence.

## Interpretation

- **FACT:** `0x00d53500` is BSS in `Navi.exe` sec1 (`va_class`); `sh4xref` finds 33 loads in 20 functions. All 33 sites classified from SH-4 store/read opcodes against the derived base register: 11 READ, 22 STORE_WRITE.
- **FACT:** Store-through-derived-pointer exists (refutes "no static writer found"): e.g. `mov.l r2,@(28,r9)` at `0x003fb034`, multiple `mov.l r3,@(disp,r2)` clears in `fn 0x0040dfa8/0x00415fe8`, and data copies in `fn 0x00412bee` (`mov.l r4,@(12,r3)` etc.).
- **OBSERVED:** Writer families are (a) clear/init (zero constants) and (b) populate/copy (context fields, call results, handle words). `fn 0x00412bee` is the clearest populate/copy writer of handle/page metadata; `fn 0x0040dfa8`/`0x00415fe8` are dominant clearers.
- **HYPOTHESIS:** `0x00412bee` and `0x003fd390/0x003fcbf0` participate in binding REFER/RDSTM (or HDLMAP page-handle) state into `0x00d53500`, consumed by dispatchers like `fn 0x003f5cdc`/`0x003f51e0`; exact slot semantics per data family need runtime/state binding.
- **UNKNOWN:** Exact entry size/count/layout schema; definitive source file/field for each slot as schema bytes (table is BSS); end-to-end reproduced entry. No L3 run or writer-inverse reproduction achieved.
