## Question

M5.90 writes `1=NAME;2=REF` road names; the labels draw but no shield does
(C-8704). What makes the factory draw the A4/A400/A401/A3201 shields?

## Hypothesis

Candidates: (a) the odd record's `points` section (w15/w16), (b) the `2=REF`
text itself, (c) the road shape's class. Falsifier per candidate: removing
it from the factory tile leaves the shields, or adding it to ours draws none.

## Inputs

Factory tile; our M5.90 tile; London start position 51.5098 N, 0.1342 W.

## Method

1. **Sample and hash.** See the Sample bullet above.
2. **Commands.** Experiments (all tiles through `tile_relayout.write_model` + the M5.87
   card build; only counts and hashes are recorded):
   - A: factory tile, the start parcel's odd record rebuilt without its
     `points` section (`clarion_bg.build_record` of the parsed record,
     rebuild without change byte-identical first).
   - B: factory tile, every level-1 odd record without `points` (11,689
     records).
   - C: factory tile, every `;2=REF` / `2=REF` in every road-name entry
     overwritten with NUL bytes of the same length (251,604 refs in 36,000
     records; word offsets unchanged).
   - D: our tile with `trunk/primary/secondary` class 2.
   - E: our tile with `primary/secondary` class 4 and `tertiary` class 3.
   - F: our tile with `primary/secondary` class 4 (the new default
     `--class-override`).

   ```bash
   python3 tools/tile_from_zero.py --selftest
   python3 tools/tile_from_zero.py $W/z3/split.jsonl --template $FAC/MAPAL001/B48R068R.DAT --cell B48R068R \
       --class-table $W/z3/class.json --country 826 --areas $W/z5/areas.jsonl --urban-fill 0.1 --places \
       -o $W/m597/final.DAT
   python3 tools/tile_provenance.py $FAC/MAPAL001/B48R068R.DAT $W/m597/final.DAT --require-zero
   ```

3. **Controls.**
   Negative: M5.90's screen `a1b95d9a…9ce8a7` has none. Every run: `cardcheck`
   PASS and the factory's 1,043 error/fail log lines.
4. **Scope.**
5. **Falsifier.**

## Observations

| run | change | screen SHA-256 | shields |
| --- | --- | --- | --- |
| A | start odd record without `points` | `7e23cc73…259f74` (= factory) | all |
| B | all odd records without `points` | `7e23cc73…259f74` (= factory) | all |

| D | ours, class 2 | `08f48369…826574` | A400, A40, A401, A4, A3201; main roads red and wide |
| E | ours, class 4 (+ tertiary 3) | `2896f700…2d6d` | same five; brown roads, more brown side roads |
| F | ours, primary/secondary class 4 | `c5bae8aa…49550ba` | A400, A40, A401, A4, A3201; brown roads |

F: tile `c0616e76…321442`, `factory_records=0/1237`, card `133e2146…16b2bc`.

## Interpretation

- **FACT:** the `points` section does not draw anything on this screen
  (A, B pixel-identical to the factory).
- **FACT:** the shield text is the `2=REF` part of the road name (C).
- **FACT:** a shield is drawn only on roads of class 4 or lower; class 5
  (`provisional-v0` primary/secondary) draws the name instead (M5.90, F vs
  M5.90). Class 4 keeps the brown main-road style of the factory screen.
- **OBSERVED:** where a shape shows a shield the firmware does not draw its
  street name (C: names appear when the refs go).

## Conclusion

Shields are now drawn in the from-zero tile: `tile_from_zero.py` defaults to
`--class-override primary=4,…,secondary=4`. The full measured class table
stays M5.98.
