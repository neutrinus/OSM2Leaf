## Question

Can the pin move from QEMU 8.2.7 to 8.2.10 — the last release of the same
branch — without touching a single patch, and does the resulting binary boot
`head256.img` exactly as the 8.2.7 build does?

## Hypothesis

Yes on both counts: `hw/sh4` did not change between the two releases, so the
series is a byte-for-byte no-op, and the boot result is a function of the
patches, not of 8.2.7-specific behaviour.

**Falsifier:** any `diff -r` difference under `hw/sh4`,
`configs/devices/sh4-softmmu` or `include/hw/sh4`; any patch needing an edit;
any change in the stable boot observables (`exceptions`, the access list).

## Method

1. Download 8.2.10, verify the SHA-256 above.
2. Compare the three trees the patches touch, byte for byte (`diff -r`).
3. Apply all five `patches/*.patch` with `build.sh`'s own tool and order
   (`patch -p1 --forward --batch`, `LC_ALL=C` sort).
4. Build with `TMPDIR=/var/tmp bash tools/qemu-ze0/build.sh --force --jobs 8`
   (the bumped pin), and check `-M help`.
5. Boot with `run.sh --machine ze0|none --timeout 10`, three runs per machine,
   and compare the stable observables with C-4311.
6. Negative control: apply the *pre-fix* `ze0` patch from `main@{before
   #217}` and confirm 8.2.10 aborts with the same two messages (so a failure
   cannot be blamed on the version).
7. `build.sh --check-version 11.1.3` on a scratch tree, to record where the
   pin stops.

message as 8.2.7. The two bugs were in the patch, not the release.

## Interpretation

The bump is a no-op on the patches and on behaviour, which is what the
identical trees predict: `hw/sh4` did not change between 8.2.7 and 8.2.10,
and none of the 165 commits in that range touch `target/sh4`. What changes is
bookkeeping: the pin is no longer three releases stale, an unverified tarball
can no longer be compiled by accident, and `--check-version` turns "would a
newer QEMU take our patches?" into one command. That last part is the
precondition for M8.A9: without a cheap probe, every bump is a heroic edit.

## Verdict

Passes all four clauses. `hw/sh4` identical, 5/5 patches unchanged, 8.2.10
builds and lists `ze0`, boot observables identical to 8.2.7 (0 exceptions,
one `write 0x38`), `--selftest` 56/56, and `--check-version 11.1.3` reports
the stop without building.

## Reproduction

```bash

TMPDIR=/var/tmp bash tools/qemu-ze0/build.sh --force --jobs 8
~/.cache/qemu-ze0/build/qemu-system-sh4 -M help | grep ze0

# 2. the boot comparison
Q=~/.cache/qemu-ze0/build/qemu-system-sh4
S=~/projekty/leafre-work/scratch/m8.a10
for m in ze0 none; do for i in 1 2 3; do
  bash tools/qemu-ze0/run.sh --image archive/head256.img --machine $m \
    --timeout 10 --qemu "$Q" --workdir $S/$m-$i
done; done

# 3. where the pin stops (builds nothing)
tools/qemu-ze0/build.sh --check-version 11.1.3
```
