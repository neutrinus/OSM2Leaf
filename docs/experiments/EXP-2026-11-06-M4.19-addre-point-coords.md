## Question

Can the `TT 40 XX YY` point token be turned into a geographic coordinate (a
latitude/longitude or tile/mesh position), given the record's packed `coord`
id, the `02..05`/interior-vertex tags, `COORD001` region boxes and `POINT0nn`
coordinates — or is it not derivable from these fields alone?

## Hypothesis

Exploratory. Working guesses: `(XX,YY)` are a fine offset from the record's
packed `coord` id (`cx,cy`, COORD001/POINT origin 52742) in packed units or in
a 1/256 subdivision; or `(XX,YY)` are tile-local/sub-cell coordinates.

## Method

1. Decode ADDRE001/002/003/017 with `addre.load_blob`/`sections`/`split_records`/
   `parse_record`; collect per record `(coord cx,cy)` and point tokens
   `(tag, XX, YY)`. Confirm record coord-id decode (`06 ss x_hi x_lo y_hi y_lo`,
   e.g. ADDRE017 `ALLÉE DES BOULINGRINS` raw `0600 a0c7 d1b5` → `(41159,53685)`)
   and packed→lat/lon via `coord.xy_to_latlon(..., 52742)`.
2. Measure `XX`/`YY` ranges and the primary-pair (tags 2–5, len 2) same-`XX`
   rate; measure `XX` constancy across all points in multi-point (polyline)
   records. Shards: 001/002/003/017 (004+ stop at `0xc1` in `split_records`, as
   documented).
3. Test coordinate hypotheses against anchors with controls (Andorra = real
   COORD001 box control; Monaco = degenerate-box case; Bulgaria = large-shard
   control). Models: `M0 (cx,cy)` (ignores XX,YY), `M1 (cx+XX, cy+YY)` whole
   packed units (wrong-hypothesis control), `M2 (cx+XX/256, cy+YY/256)`
   candidate 1/256 fractional subdivision, `M3/M4` axis variants. Metrics:
   fraction inside the COORD001 region box (+2 margin, packed/52742) and median
   primary-segment length (packed units).
4. Inspect multi-point polylines for `XX` behaviour (spatial vs attribute).
5. Attempt POINT017 anchor (street-name/id join) — POINT names not plain-searchable
   in decoded bytes; the POINT body grammar/join is unresolved, so no
   independent 2D ADDRE point anchor was obtained from `POINT0nn`.
6. Encode the rule and a synthetic control in `tools/addre.py`
   (`point_fractional_candidate`, `assess_point_coords`, `--selftest`); update
   `docs/format/refer.md`.

## Interpretation

- **FACT (observed, C-1960):** `YY` uses the full 0–255 range (256 distinct) in
  every shard measured (001/002/003/017, 1.62M points total); `XX` is
  shard-capped (max 23/50/58, dense 0..max). `XX` is shared by both endpoints
  of a simple primary pair in 95.4/97.7/97.6 % of records but is constant
  across **all** vertices in only 2.6–11.1 % of multi-point polylines (it
  varies between sub-segment groups). (`tools/addre.py stats`/`assess_point_coords`.)
- **FACT (control, C-1961):** Whole-unit `cx+XX,cy+YY` (wrong hypothesis)
  places 14.0 % of Andorra points in the region box (+2, 304/2168) with median
  primary-segment length 7 packed units (~4 km). A 1/256 fractional candidate
  places 100 % in-box with ~0.027 packed units (~16 m). Andorra is the
  discriminating control (real box); Monaco's 14×1 degenerate box is
  non-discriminating (10.5 % for all models, ids spill). (C-1962.)
- **OBSERVED (C-1963):** `YY`'s 0–255 span is consistent with a
  1/256-packed-unit subdivision of one packed unit relative to the record's
  coarse `coord` id; same-`coord` segments chain in `YY` at fixed `XX`. This
  establishes scale/quantization plausibility only, not a 2D geographic
  mapping.
- **INTERPRETATION (C-1964):** A 2D geographic `(lat,lon)` is **not derivable
  from `(coord, XX, YY, tag)` alone**. No fixed assignment of `XX,YY` to
  orthogonal geographic (lat/lon packed) axes is supported: constant-`XX`
  simple segments (95–98 %) would be axis-aligned to ~2.3 m resolution, which
  is geographically implausible across Andorra/Belgium/Bulgaria/Monaco; a
  segment-local/rotated frame is not encoded in these fields. `XX` carries a
  sub-segment/attribute role in polylines (changes between groups) distinct
  from a per-endpoint 2D geographic offset, but its exact meaning is UNKNOWN.
- **FACT (anchor gap, C-1965):** ADDRE provides no independent 2D absolute
  position (`coord` is coarse/shared; C-972 payload unknown); `COORD001` boxes
  are too coarse and Monaco degenerate; `POINT017` street text is not plain
  ASCII in the decoded body (bit-packed/unresolved grammar), so a
  street-name+house-number 2D anchor to `(XX,YY)` was not obtained from these
  fields. (Scope of "not derivable from these fields alone".)
- **UNKNOWN:** the 2D frame / axis assignment and the semantic meaning of `XX`
  (length/radius/class/sub-segment index — none confirmed); the exact
  `(XX,YY)` arithmetic remains open, but its 2D geographic resolution is out of
  scope for `coord,XX,YY,tag` alone.

## Conclusion

`docs/format/refer.md` updated: point tokens now record the `YY` 0–255/`XX`
shard-capped asymmetry, the 1/256 scale consistency, the same-`XX`/polyline
behaviour, and the finding that 2D geographic `(lat,lon)` is not derivable from
`(coord,XX,YY,tag)` alone (with the whole-unit and fractional controls and the
Monaco-degenerate caveat); "still open" narrowed to the 2D frame/axis
assignment and `XX` meaning. `tools/addre.py` carries the rule
(`POINT_SUBDIV`, `point_fractional_candidate` marked non-verified-2D,
`assess_point_coords`, stats output, synthetic `--selftest` control). C-976 is
refined (frame VERIFIED retained; arithmetic resolved as "2D geographic not
derivable from these fields alone; 1/256 scale consistent; frame/`XX` UNKNOWN")
by C-1960–C-1965. C-979's `(XX,YY)` negative is narrowed/superseded in scope by
the same claims.
