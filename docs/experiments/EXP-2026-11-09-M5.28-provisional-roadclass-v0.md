## Question

Can a versioned provisional OSM `highway=*` (+`maxspeed`/access/`oneway` metadata where available) mapping to Clarion tile `(layer, cls_hi)` and speed/style metadata be produced that (a) covers every in-scope `highway=*` explicitly as mapped or `UNMAPPED`/`refuse_generate` (never a silent drop/default), (b) is consumable by `tilewriter.py --class-table` (`ze0-road-class-table/1`), and (c) produces a synthetic L2 tile build using the emitted table that passes existing tile checks — without making a firmware or M4.2 claim (rule 13)?

## Hypothesis

Yes, for in-scope `osm_ingest.DRIVABLE_HIGHWAYS` (17 values), using the M5.23-confirmed `(layer,cls_hi)` mechanism and `fa_encode.CLASSES` buckets as **provisional** values, plus explicit low-provisional placeholders for `busway`/`road` (navigator option a) where no safe semantic mapping is established.

**Falsifier:** any in-scope highway silently dropped/defaulted; unknown/OOS highway not refused; emitted table rejected by `tilewriter.load_class_table` or missing an in-scope mapped road causing a miss; synthetic L2 build with the emitted table fails existing tile checks; any output presented as firmware-confirmed or M4.2-resolved.

## Interpretation

- **OBSERVED (tool/synthetic):** `tools/roadclass_v0.py` accounts for all 17 in-scope `DRIVABLE_HIGHWAYS` with `mapping=provisional-v0`, emits `ze0-road-class-table/1` accepted by `tilewriter.load_class_table` covering all 17 mapped in-scope highways, and reports `busway`/`road` as `provisional-placeholder`/`low-provisional` (distinct `entry_kind`/confidence/rationale/alternatives including `UNMAPPED/refuse_generate`) while 15 entries are `mechanism-confirmed-bucket` traced to authoritative `fa_encode.CLASSES`. Unknown/OOS highways return `UNMAPPED` + `refuse_generate=true` and are excluded from `classes`.
- **OBSERVED (synthetic L2):** a factory-mode synthetic tile built via `tilewriter.build` with the **emitted** class table (IMF includes `busway` and `road`) passes existing checks: build completed with emitted-table provenance in report, `mode=factory`, `section4.preserved`, `unit_ready false`; `readback` reports `decoded_points=12, in_points_within_1m=12, input_points=12, parcels=2, worst_m=0.0`. This is L2-structural/geometry evidence on synthetic fixtures only.
- **FACT (scope/provenance):** mapping uses M5.23-confirmed `(layer,cls_hi)` mechanism via authoritative `fa_encode.CLASSES` for 15 buckets; OSM→value remains provisional/incomplete (C-2662, M5.3). M4.17 is negative for RDSTM/LCTBL road-class field establishment (`class_code` hypothesis only); no M4.2 row key claimed.
- **HYPOTHESIS/PROVISIONAL:** `(5,8)` placeholders for `busway`/`road` are compiler-unblocking choices, not semantic/firmware-confirmed mappings (option a; safer alternative UNMAPPED/refusal recorded). Speed/style metadata is mechanism-only and not firmware-confirmed (M4.2/M5.4 neutral style gap).
- **UNKNOWN (rule 13):** firmware acceptance of generated class/style/speed values, M4.2 semantics, M5.3 global mapping, and any L3/L4/L5 behavior.

## Conclusion

M5.28 done-when is met at L2-synthetic/provisional scope: `tools/roadclass_v0.py` produces a versioned, machine-auditable `provisional-v0` mapping where every in-scope `highway=*` is mapped or explicitly UNMAPPED/refused (never silent drop), `busway`/`road` are auditable low-provisional placeholders (not equivalent-confidence to 15 mechanism-confirmed buckets), the emitted `ze0-road-class-table/1` is consumable by `tilewriter.py --class-table`, and a synthetic tile build using that emitted table passes existing tile checks (`readback` 12/12 within 1m, 2 parcels). The result is **provisional and not firmware-confirmed** (rule 13); M4.2/M5.3 gaps and M4.17 negative remain open.
