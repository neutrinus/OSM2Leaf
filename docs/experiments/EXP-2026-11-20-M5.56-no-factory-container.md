## Question

Why does the firmware fail the first directory read of a tile written
without a factory container (C-3256), and what must the writer (or the
card) do so that the mount reads it?

## Hypothesis

The fresh tile is shorter than the length the firmware reads for its
directory (`0x8100` at `0x1100`, M3.31). Zero-padding the file so every
directory is backed by `0x100 * T[kind].n` bytes makes the read succeed.

**Falsifier:** the padded tile mounts, but so does a control with the
padding cut 0x100 bytes short (then the length is not what is tested); or
the padded tile still fails.

## Interpretation

- **FACT:** the firmware asks for `min(0x100 * T[kind].n, size - pos)`,
  where `size` is the file's size as `DRSTR001.DAT` records it (E1, E2, SD,
  SD1). A read fails (status -1) when the file holds fewer bytes than that
  (S, T9100, SD1).
- **FACT:** C-3256's failure is a property of the test card, not of the tile
  alone: `--replace` keeps the factory DRSTR001 entry (289,319,168 B), so the
  firmware asked for the full `0x8100` of a 22,272-byte file. With DRSTR001
  telling the true size, the unpadded fresh tile mounts (SD).
- **FACT:** the padded fresh tile mounts even with the stale DRSTR001 entry
  (P), and the comparison tests the length: 0x100 bytes less fails (T9100).
- **FACT:** the factory card itself relies on the clamp: its last section-4
  directories are read short and parsed (E1, E2; C-5826 answered).
- **OBSERVED:** the `--factory` path is unchanged (F / Gm SAME).
- **UNKNOWN:** which function reads the DRSTR001 size for the clamp.
- **Writer consequence:** a card is safe when DRSTR001 carries every
  tile's real size (`rebuild_manifests.py` does this) **or** every directory
  is backed by its read length. `tilewriter.py` now does the second for
  fresh tiles, so a fresh tile also survives a card whose DRSTR001 entry is
  stale or larger. The padding adds ≤ one read length of zeros at the end
  (15,104 B here).

## Conclusion

`tools/tilewriter.py` (fresh path only) zero-pads the file to the end of the
longest directory read (`pad_directory_reads`, rule from M3.31); the
selftest checks it. The Precheck run on the new tile has no negative
status; the one directory the tile declares is read and parsed; `l2check`
PASS; `--factory` F/G SAME. `docs/format/map-tiles.md` corrects the M9.13
statement ("must back every directory") with the DRSTR001 clamp. Claims
C-5830–C-5834.
