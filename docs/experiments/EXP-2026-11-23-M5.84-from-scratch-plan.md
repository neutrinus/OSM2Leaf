## Question

Marek (2026-11-23): we can rename streets and reshape roads in factory tiles;
can we build the tile structure ourselves, without replacing factory pieces,
given that OSM data will not always fit the factory records and blocks? What
does the London test tile (the emulator's start screen, M8.H71) consist of,
and which of its structures bind a writer?

## Hypothesis

The London tile has the same container shape as the Polish tiles measured
before (M5.53, M3.31): sections 1, 2 and 4, levels 1 and 2 only, wide-row
section-1 directories that parse with the M5.53 model. Falsifier: a section,
level or directory kind the existing readers do not parse, or a wide-row
directory that fails the M5.53 census.

## Inputs

The tile above; the plan page `docs/research/osm-from-scratch.md`.

## Method

1. Sample and hash: above.
2. Commands:

   ```bash
   T=FAC/MAPAL001/B48R068R.DAT
   sha256sum $T
   python3 tools/s1_wide_dir.py census $T
   python3 tools/dir_read_len.py predict $T
   (cd tools/ze0-viewer && python3 harness.py info $T)
   ```

3. Controls: positive — `s1_wide_dir.py census` re-encodes every directory and
   compares it byte for byte (`roundtrip_ok`), so a wrong model shows as a
   mismatch; the same census passed on `B48R058R` (M5.53/M5.54). Negative —
   `dir_read_len.py predict` flags directories that run past the file end; it
   names two here (below), so the check is live.
4. Scope: one tile, header tables and directories, record counts per family;
   no record content is interpreted beyond what `harness.py info` already
   decodes. No vendor bytes are quoted.
5. Falsifier: as in Hypothesis.

## Interpretation

- **FACT:** the London tile has the same container shape as the Polish tiles:
  three sections, levels 1/2 (+ section 4 level 1), and every section-1
  directory parses with the M5.53 wide-row model (68/68 round-trip). The
  falsifier did not fire.
- **FACT:** London is denser than `B48R058R` in the wide-row sense: up to 15
  wide rows in one directory (`0x2f46`), 84 wide rows, 912 sub-records in 228
  parcels. The factory itself splits these dense parcels 2 × 2 — that is the
  format's "does not fit" mechanism, and our writer drops sub-records today.
- **OBSERVED:** `rows_512_reader_wrong_tag=628`: the generic
  `clarion_tile.read_dir` reads wide directories with 512-byte rows and would
  misplace 628 row tags; a from-zero layout writer must use the wide-row model
  for section 1 level 1 (input for M5.85).
- **FACT:** the largest section-1 level-1 directory (24,204 B) is below its
  read length `0x8100` (33,024 B), so `0x2f46` is not the ceiling: by limit 2
  of the plan a directory can hold at most 31 wide rows.
- **UNKNOWN:** the largest record the firmware reads (plan limit 6, M5.92).
