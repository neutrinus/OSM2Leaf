## Question

Which field of a `MAPAL001` level-1 section-2 (router graph) entry can a displayed
road name, an `ADDRE` street record or a `LCTBL001` road be joined to, and does that
key beat a shuffled/null baseline on two tiles?

## Hypothesis

`rd_check.link_pairing` (writer-side) and `shape_index` state that a section-2 entry's
word 3 (`& 0x1fff`) is the drawn link id, unique per (parcel, class); so
`(parcel code, class, link id)` should join section 2 to the drawn shape (and through
the shape's word 4 to its label), and ADDRE point refs should reach the same triple.
LCTBL001 has no coordinates or ids (C-2971), so no numeric LCTBL field should join.

**Falsifier (stated before the run):** the link-id key scores no better than its
shuffled null, or works on `B48R058R` and not on the control tile; any other field
reaching a hit rate near the link key; an ADDRE ref that lands as often from a
rotated (wrong) parcel as from its own.

## Inputs

| Item | Value |
| --- | --- |
| Tiles | `B48R058R` (CZ/PL/DE/AT/SK area), `B38R068R` (ES/AD/FR area), `B30R060R` (IT, 37 records) |
| Section 2 | level 1 only, dir kind `0x1046`, unit 0 (part a); part b (M4.24) not used |
| Name layer | section-1 `0x00fa` even record shapes (`fa_encode.parse_record`), labels from the odd partner's names section (Latin-1) |

| LCTBL | all 517 pages, 247,089 records, four name slots indexed upper-case |
| Repo tool | `tools/route_link_join.py` |

## Method

1. **Sample and hash** as above.
2. **Commands** (repo root, `F=/home/user/scratch/factory-eu`):

   ```bash
   F=/home/user/scratch/factory-eu
   python3 tools/route_link_join.py --selftest
   python3 tools/route_link_join.py sec1 $F/MAPAL001/B48R058R.DAT
   python3 tools/route_link_join.py sec1 $F/MAPAL001/B38R068R.DAT
   python3 tools/route_link_join.py sec1 $F/MAPAL001/B30R060R.DAT
   python3 tools/route_link_join.py addre $F/MAPAL001/B38R068R.DAT $F/REFER001/ADDRE001.DAT.cmp
   python3 tools/route_link_join.py addre $F/MAPAL001/B48R058R.DAT $F/REFER001/ADDRE005.DAT.cmp --every 20
   python3 tools/route_link_join.py lctbl $F/MAPAL001/B48R058R.DAT $F/RDSTM001/LCTBL001.DAT --every 4
   python3 tools/route_link_join.py lctbl $F/MAPAL001/B38R068R.DAT $F/RDSTM001/LCTBL001.DAT --every 2
   ```

   `sec1`: each in-parcel section-2 entry (class word bit 15 clear) is turned into a key
   `(class & 0xf, F)` for seven candidate fields F (link id `w3 & 0x1fff`, w4, w5,
   travel time `a`, length `b`, far node index, own node index); a **hit** is a drawn
   link with that `(class, id)` whose first or last point equals the entry's node
   `(x, y)`. Plus the node-coordinate key (node `(x, y)` in the set of drawn link ends).
   `addre`: every ADDRE record whose parcel code is a level-1 parcel of the tile; each
   point ref `(tag, 0x40, v)` is followed (hops `0x40/0x50/0x60/0x70` move one parcel)
   to word `unit + v` of the parcel's shape record; outcomes: lands on a drawn point x
   word, the shape label names the street, the point's link `(class, id)` exists among
   the parcel's section-2 entries, and for start/end points the point is a section-2
   node. `lctbl`: for section-2 entries joined to a named shape, label parts (`1=`,
   `2=`, `:`-separated) are looked up in the LCTBL name slots; for each name-matched
   entry one matching LCTBL record is drawn and each of 10 section-2 numbers is compared
   with each LCTBL number (7 attr bytes, class, footer `u16`s).
3. **Controls.** *Positive:* the link key must reproduce `rd_check` pairing on
   `B30R060R` (pairing 37/37, 1,404 links, two entries each = 2,808), and the selftest
   fixture (6/6 hits, 0 for constant fields). *Negative (nulls):* (a) the field values
   **shuffled** among the record's own entries (same class mix, same nodes); (b) the
   **other-parcel** null: the same entries against the next parcel's shape record;
   (c) ADDRE refs applied to the **next record's (different) parcel**; (d) LCTBL
   pairs **re-drawn at random** from the matched pool. Second-tile control:
   `B38R068R` (different country set, different ADDRE shard).
4. **Scope.** `B48R058R`: 65,274 level-1 section-2 records, 43,585 with a `0x00fa`
   drawn partner (the rest have no even `0x00fa` record at the same parcel code — not
   analysed), 4,970,122 in-parcel entries; 44 even section-1 records do not inflate
   and are skipped. `B38R068R`: 36,573 records, 19,486 with a partner, 1,590,948
   entries (22 unreadable skipped). `B30R060R`: 37/37, 2,808 entries. ADDRE: Andorra
   (1,041 records, all) on `B38R068R`; Germany shard `ADDRE005`, every 20th record
   whose parcel is in `B48R058R`. LCTBL: every 4th (`B48R058R`) / 2nd (`B38R068R`)
   section-2 record. Levels 2/4/5, part b, edge (cross-parcel) entries and sub-parcel
   ADDRE codes are excluded.
5. **Falsifier** as stated under Hypothesis.

## Interpretation

- **VERIFIED (L2, 3 tiles):** `(parcel code, class & 0xf, w3 & 0x1fff)` of a section-2
  entry is a join key to exactly one drawn link whose end sits at the entry's node:
  99.9 % on both large tiles against 6.1 % shuffled and ~0 % other-parcel (C-5150).
  Misses are 3,629 entries (0.07 %) on `B48R058R`, 2,290 on `B38R068R`.
- **VERIFIED:** the node `(x, y)` is a second key — it names a drawn link end in the
  same parcel for 100.0 % of nodes vs ≤ 0.05 % from another parcel (C-5151). It names
  a node, not a link.
- **VERIFIED (negative):** w4, w5, `a`, `b`, far/own node index are not link keys:
  ≤ 7.9 % with nulls of 0.8–4.2 %. The small excess of the index fields and w4 over
  their shuffle comes from small integers colliding with small link ids (link ids
  restart at 1 per class), not from a join (C-5152).
- **VERIFIED:** ADDRE reaches the router edge through the drawn shape: on Andorra
  2,125/2,125 refs land on a point (null 406), 2,112 of them on a shape labelled with
  the street (null 2), and every landed point's `(class, id)` is a section-2 entry;
  start/end refs are section-2 nodes 2,124/2,124 (C-5153). Second tile, Germany shard on `B48R058R`: 44,631/44,631 land (null 7,741), 44,576 named (99.9 %, null 180), 44,616/44,616 start/end refs are section-2 nodes.
  The null's "link in section 2" equals its "lands" count because every drawn link has
  section-2 entries (C-5150); the discriminating null is the label match.
- **VERIFIED (negative):** no numeric `LCTBL001` field joins section 2: on 252,672 +
  35,442 name-matched pairs no (section-2 field, LCTBL field) pair beats its shuffled
  pairing by more than 1.43× and none above 2 % hit rate except the `w5`/attr cases,
  which equal their null (zero-valued words). The name string is the only bridge and
  is many-to-one (median 8 / 5 records per name), so it is not a key (C-5154).
- **OBSERVED:** C-887's router string `link[mesh(0x%x),no(%d),rdtype(%d)]` has the same
  shape as the key found here (mesh/parcel, link number, road type/class); not tested
  in firmware (C-5155).
- **UNKNOWN:** the 21,689 (`B48R058R`) / 17,087 (`B38R068R`) section-2 records with no
  even `0x00fa` record at the same parcel code; levels 2/4/5; edge entries' far ids.

## Conclusion

The route-link id exists and is not hidden: a section-2 entry's link id (word 3
`& 0x1fff`) with its class nibble and parcel code is the same triple that names a drawn
link in section 1, whose word 4 points at the label; ADDRE street records land on
points of those links. So the chain name → ADDRE / label → drawn link `(parcel, class,
id)` → router entry is closed at L2 on two tiles with nulls; `LCTBL001` stays joined by
name text only (negative for every numeric field). `docs/format/map-tiles.md` gains
the field table ("Route-link key"). M6.7 can aim at a chosen OSM way through the
writer's link ids; whether the firmware router uses the same triple is open (L3).
