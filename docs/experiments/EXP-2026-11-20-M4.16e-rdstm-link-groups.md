## Question

What does an `RDSTM001.DAT` link reference (`u32 ref`, `>>16` = group, `&0xffff` = entry) point at, and does it carry ≥20 TMC location records (code, name) to MAPAL tile/parcel/link coordinates with a named rule and a near-zero random-key control?

## Hypothesis

Exploratory at the start. After reading the `0x1000` header (see Observations) the working hypothesis was: the header names, per set of 14 location tables, a *group index*; each group lists MAPAL parcel codes with an entry count; and a group's 4-byte entries name a link in the section-2 (route graph) record of that parcel.

**Falsifier (fixed before the `check` and `place` runs):** (a) the group entry counts do not add up to the refs of the matching set, or refs point past a group's entries; (b) the entry's two halfwords are not (node, link) of the parcel record above the random-node control; (c) placed TMC records are not in the country of their location table, or a record and its TMC positive neighbour are no closer than a shuffled neighbour.

## Method

1. **Sample and hash** as above (`sha256sum`).
2. **Commands** (repo root; `E=/home/user/scratch/factory-eu`):

   ```bash
   python3 tools/rdstm_links.py --selftest
   python3 tools/rdstm_links.py header $E/RDSTM001/RDSTM001.DAT
   python3 tools/rdstm_links.py groups $E/RDSTM001/RDSTM001.DAT
   python3 tools/rdstm_links.py check $E/RDSTM001/RDSTM001.DAT $E/MAPAL001 --set 0
   python3 tools/rdstm_links.py check $E/RDSTM001/RDSTM001.DAT $E/MAPAL001 --set 1
   python3 tools/rdstm_links.py place $E/RDSTM001/LCTBL001.DAT $E/RDSTM001/RDSTM001.DAT $E/MAPAL001 --table-pair 0 --examples 30
   python3 tools/rdstm_links.py place $E/RDSTM001/LCTBL001.DAT $E/RDSTM001/RDSTM001.DAT $E/MAPAL001 --table-pair 9 --examples 5
   ```
3. **Controls.** *Positive:* the header rows must reproduce the 28 (link, triple) block addresses that `tmc_fielddir.rdstm_pairs` finds by walking the blocks (independent method); the selftest builds a synthetic header/index/data and resolves it. *Negative:* (i) random node: the entry's link with a random node index of the same record; (ii) wrong parcel: the entry resolved against another parcel's record (the one half the sorted key list away); (iii) country: random refs of the same set (uniform over all set-1 entries, 2,000 draws) against the table's main country; (iv) distance: a record against a randomly chosen placed record of the same table instead of its TMC positive neighbour.
4. **Scope.** EU 2011 only. Both sets: 33 + 3,132 groups, 263 + 32,240 parcels, 422,683 + 1,877,891 entries (every entry checked against its parcel record). Placement: two location tables, set-1 (level-2) refs only: table pair 0 (location table 0, Czech Republic, 16,634 records) and table pair 9 (location table 25, Germany, 42,550 records). Excluded: the US card (index/`RDSTM001.DAT` offsets differ, M4.16b); level-4 placement (set 0 is checked, not placed); the firmware reader (not searched in this task).
5. **Falsifier** as stated under Hypothesis, fixed before the `check`/`place` runs.

## Observations

**Header (`header`).** `u16 0x180` (header words), `u16 3`, `u16 122` (roles of the last two UNKNOWN), then two sets, each `u32 group_index_addr, u16 blocks, u16 ntables=14` + 14 rows `u16 table_code, u16 nlink, nlink × (u32 addr, u16 blocks), u32 triple_addr, u16 blocks`. Addresses decode as `(v >> 8) * 0x800 + (v & 0xff) * 0x100` (the same rule as MAPAL `tile_scan.addr_of`). Parse ends at `0x1224` (zeros follow). Set 0: index `0xcda000`, 9 blocks; set 1: index `0xe78500`, 989 blocks. Set 1 rows have 1, 2 or 4 link blocks per table (e.g. `4401`: 4). Rows vs walk: `pairs walked (tmc_fielddir) 28; header rows 28; equal True`. Table codes in both sets: `3219 3409 3501 3601 3611 3811 3909 4101 430a 4401 4511 4521 4620 4631`.

## Interpretation

- **VERIFIED (structure, C-5137):** the `0x1000` header is a two-set table directory; its rows give exactly the 28 block pairs M4.16b found by walking, plus the address of one group index per set. Addresses use the MAPAL container rule (`0x800` sectors + `0x100` sub-blocks).
- **VERIFIED (structure, C-5138):** set 0 (pairs 0–13) and set 1 (pairs 14–27) each have their own group numbering; a ref of pair `p` is `(group, entry)` in the set of `p`. Every group's entries are referenced, none past the end. Group keys are MAPAL parcel codes: level 4 in set 0 (one group ≈ one grid tile), level 2 in set 1 (one group = 4 × 4 level-2 parcels). The same 14 location tables are thus linked twice, once to the level-4 and once to the level-2 road graph.
- **VERIFIED (rule, C-5139):** entry `(a, b)` = node index `a & 0x1fff` and link id `b & 0x1fff` of the parcel's section-2 record, node `a` being an end of link `b`; `b & 0x2000` repeats the end flag of that link end. 99.96 % (level 2) and 98.8 % (level 4) of all entries fit, against 5.7 % / 0.4 % for a random node. Consecutive entries often share the link's other node (1,381,082 of 1,877,891), i.e. an entry list walks a road.
- **VERIFIED (placement, C-5370):** through `location code → RDSTM link record (pair 14+t) → ref → group/entry → level-2 parcel → node (x, y)`, every joined record of two tables lands on a node in a parcel of the table's country (8,532/8,532 CZ, 22,884/22,884 DE vs 5 % / 19 % for random refs), and a record and its TMC positive neighbour share a node or lie < 1 km apart in 99.9 % (shuffled: 0.1 %). Named places land where they are (Plzeň-západ 49.71 N 13.28 E, Beroun 49.93–49.98 N 14.0–14.1 E, Saarbrücken 49.26 N 6.96 E). The M4.16b done-when (≥ 20 records to tile/mesh/coordinates, named key, ~0 random control) is met.
- **OBSERVED / UNKNOWN (C-5371):** `a` bits 0x4000/0x8000 and `b` bits 0x4000/0x8000 and the link-record role `k & 3` are not decoded; the misses concentrate on entries with `a & 0x4000` (set 0 also `a & 0x2000`), which may point at a node held in a neighbouring parcel. Header words `3` and `122` are UNKNOWN. The level-4 placement is checked (rule) but not placed.
- **Context (M4.39, merged meanwhile, C-5150):** a section-2 entry's `(parcel, class & 0xf, link id)` names the drawn section-1 link; combined with this decode, a TMC location can reach drawn road geometry, not only graph nodes (not tested here; the M4.39 result is for level-1 records, these refs are level 2/4).
- **UNKNOWN (C-5372):** the firmware reader of the group index/data is not located; this is a data-side decode (rule 13: format not *confirmed* until the reader has a VA).

## Conclusion

The `RDSTM001.DAT` link groups are decoded: the file header gives two sets of 14 location tables and one group index per set; a ref `(group, entry)` names a 4-byte entry `(node, link)` in the section-2 record of a level-4 (set 0) or level-2 (set 1) MAPAL parcel listed in that group. The rule fits 2,294,594 of 2,300,574 entries, and it places every joined TMC record of the Czech and German tables on a node in its own country with neighbours adjacent, against near-zero shuffled controls. M4.16e is **done**; M4.16b is re-opened (rule 15) because its blocker is gone. The firmware reader is a follow-up (M4.48).
