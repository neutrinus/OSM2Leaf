## Question

Can an OSM tag expression be resolved to a single ZE0 `POINT` category code
for the POI writer, for at least the eleven required categories (fuel,
charging, parking, restaurant, hotel, pharmacy, supermarket, bank/ATM,
railway station, airport, hospital), without inventing a code that has zero
records on the factory card?

## Hypothesis

The generated M4.88 category table gives a code for the common generic and
brand categories (fuel, eateries, hotels, brand shops), so an ordered
tag→code rule set can resolve those; categories with no factory code must stay
explicitly UNMAPPED rather than use a guessed value. **Falsifier (task):** a
rule targets a code with zero records on the factory card. Concretely the
`validate` cross-check must fail if any non-null code is absent from the
M4.88 table or has count 0; a fabricated `0xffff` must be rejected.

## Method

1. **Sample and hash.** No image is read by this task; the only data input is
   the committed generated table `docs/format/poi-categories.md`. Its source
   card hash is recorded above and was verified in EXP-2026-11-22-M4.88 with
   `tools/fetch_image.py --verify`. The new tool parses the `## Table` section
   only (the later `## Ten codes` section reuses the code column with a
   different layout, which initially wrote a spurious count of 0 — fixed).
2. **Commands.** Runnable as written from the repo root:

   ```bash
   python3 tools/poi_category_profile.py --selftest
   python3 tools/poi_category_profile.py validate
   python3 tools/poi_category_profile.py map '{"amenity":"fuel"}'
   python3 tools/poi_category_profile.py map '{"amenity":"charging_station"}'
   python3 tools/poi_category_profile.py fixtures
   python3 tools/selftest.py --only poi_category_profile
   python3 tools/profile_validate.py profiles/dolnoslaskie-detail.json
   ```

3. **Controls.** *Positive:* (a) the selftest asserts `amenity=fuel` →
   `0x0190`, `amenity=restaurant` → `0x0391`, `tourism=hotel` → `0x0dac`,
   `shop=supermarket` + brand `CARREFOUR` → `0x01a1`, `tourism=hotel` + brand
   `HILTON` → `0x0db7`; (b) every non-null code is checked to exist in the
   M4.88 table with count > 0; (c) one synthetic fixture per rule resolves to
   the rule's own declared code. *Negative:* (a) `highway=residential`,
   unbranded `shop=supermarket`, `amenity=pharmacy`, `amenity=parking` and
   `amenity=charging_station` resolve to no code; (b) mutating a rule's code to
   `0xffff` makes `validate` report an error and the falsifier check fail.
4. **Scope.** All 19 rules of `profiles/poi-categories.json` (11 mapped, 8
   UNMAPPED) and all 276 rows of the M4.88 `## Table` section. Covers the
   eleven OSM categories named in the task. Excluded: firmware ROM and
   firmware reader code (no L3/L4 run; rule 13 leaves this data-side), the
   1,842,727 uncoded `ffff` records, `REFER002`'s decoded body offsets (M5.79),
   and any recompression/zlib byte-identical claim (none made, so no
   `zlibinfo.py` stamp needed). `tools/profile_validate.py` validates *build*
   profiles only (region/coverage/tiles) and is not applicable to a tag table;
   it already returns `E002` for the non-build `profiles/pl-glyphs.json`.
5. **Falsifier.** As in Hypothesis, evaluated before the result: any targeted
   code absent from M4.88 or with count 0, or a synthetic fixture resolving to
   the wrong code, fails the selftest. A rule using a guessed code for an
   uncovered category would be caught by the same check.

## Observations

All numbers below are quoted from the commands in Method 2.

1. **Selftest.** `python3 tools/poi_category_profile.py --selftest` →
   `checks: 17, failures: 0`, `poi_category_profile selftest: OK`.
   `python3 tools/selftest.py --only poi_category_profile` →
   `tool:poi_category_profile  PASS  0.20s`, `passed=1 failed=0 skipped=0
   total=1`, `selftest: OK`.
2. **Validate.** `python3 tools/poi_category_profile.py validate` →
   `{"rules": 19, "mapped": 11, "unmapped": 8, "table_codes": 276,
   "targeted_codes": 11, "duplicate_codes": [], "errors": [], "ok": true}`.
3. **Mapped codes and counts** (from `docs/format/poi-categories.md`, §Table):
   fuel generic `0x0190` 31,684, BP `0x0193` 5,531, Aral `0x01bc` 2,436;
   restaurant/cafe `0x0391` 31,660; hotel generic `0x0dac` 98,791, Best
   Western `0x0dad` 1,202, Hilton `0x0db7` 137, Holiday Inn `0x0db8` 265;
   supermarket brands Carrefour `0x01a1` 338, Intermarche `0x01be` 1,533,
   ASDA `0x0195` 174. All 11 targeted codes have count > 0.
4. **Unmapped categories.** The table has no code for charging station,
   parking, hospital/clinic, pharmacy, bank/ATM, railway station, airport, or
   a generic supermarket. The only `AIRPORT` string is `0x0dce`
   `card: CUMULUS AIRPORT` (a hotel brand name, count 25), not an airport
   category. `BICON001` has generic glyph 19 (pharmacy cross) and 20 (parking)
   but their codes are not isolated (OQ-20, `docs/format/assets.md`).
   Charging stations are a separate `REFER002` EV layer (C-143, C-2224,
   M5.79/C-10100–C-10109).
5. **Map commands.** `map '{"amenity":"fuel"}'` →
   `{"rule": "fuel-generic", "category": "fuel", "code": "0x0190", ...}`;
   `map '{"amenity":"charging_station"}'` →
   `{"rule": "charging-station", "category": "charging station", "code": null, ...}`;
   `map '{"tourism":"hotel","brand":"HILTON"}'` →
   `{"rule": "hotel-hilton", "category": "hotel", "code": "0x0db7", ...}`.
6. **Build profiles unchanged.** `python3 tools/profile_validate.py
   profiles/dolnoslaskie-detail.json` → `result OK (0 error(s), 0 warning(s))`.
   `python3 tools/profile_validate.py profiles/*.json` exits 1 on the
   pre-existing non-build `profiles/pl-glyphs.json` (`E002`); the new
   `poi-categories.json` is another non-build profile alongside it, and no
   standing gate uses that wildcard.

## Interpretation

- **FACT:** the ordered tag→code profile resolves the 4 covered categories
  (fuel, restaurant, hotel, brand-coded supermarket) to M4.88 codes that all
  have count > 0; 11 mapped rules and 8 UNMAPPED rules, 19 total.
- **FACT:** the task falsifier is implemented and fires on a fabricated code:
  `validate` reports an error for `0xffff`, so no unverifiable code can enter
  the profile silently.
- **OBSERVED:** 7 of the 11 requested categories have no factory category
  code. They are deliberately `code: null`; this is a real coverage limit of
  the card, not an omission from the profile.
- **UNKNOWN:** the category codes for the pharmacy cross (glyph 19) and
  parking (glyph 20), and any code for charging/hospital/bank/rail/airport;
  OQ-20 and M3/M9 remain open. No rule-13 `CONFIRMED` claim is made (C-988).
- **DECISION:** `tools/profile_validate.py` is for build profiles and cannot
  validate a tag table; the new tool's `--selftest` is the runnable gate.

## Conclusion

`profiles/poi-categories.json` and `tools/poi_category_profile.py` add a
data-side OSM tag→POI category rule set backed by the M4.88 table. The profile
covers all 11 requested categories: 4 resolve to factory codes (including
brand-specific fuel/hotel/shop codes), 7 are explicitly UNMAPPED. The 17-check
selftest and the `validate` cross-check pass; the falsifier (zero-record or
absent code) fails loudly. No vendor data, firmware reader claim, or
recompression is involved. Backed by C-10140–C-10149.
