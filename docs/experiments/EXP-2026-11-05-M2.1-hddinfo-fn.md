# EXP-2026-11-05-M2.1: HDD_INFO function in Navi.exe (partial, blocked)

Task: M2.1. Question: which `Navi.exe` function opens `\UserSD\VER_INFO\HDD_INFO.TXT`,
what file API it calls, which buffer it fills, and who calls it.

## Method

Image: the EU navi158 SD image (8,057,257,984 bytes), read locally, never committed.
Module `Navi.exe` at image start `0x200200` (cerom `modules`, index 101).
Tools: `tools/sh4xref.py` (M1.8) for literal pools and `jsr @Rn` sites; a scratch
scan (not committed) for `bsr` and pool words that hold a function VA.

## Observations

- Pool slot `0x004e7d28` holds `0x001d51a8`, the string pointer for
  `\UserSD\VER_INFO\HDD_INFO.TXT` (EXP-50, M1.8). Read at `0x004e7bec` in
  `fn 0x004e7b8c`.
- `fn 0x004e7b8c` makes 9 register calls (`jsr @r3`), this list is the same as M1.8:
  - `0x004e7bda` COREDLL ord 1047
  - `0x004e7bfc` sub_004dd1f0
  - `0x004e7c3c` COREDLL ord 1145
  - `0x004e7c4a` sub_004dd1f0
  - `0x004e7c5a` COREDLL ord 1143
  - `0x004e7c8c` COREDLL ord 59
  - `0x004e7c9e` COREDLL ord 59
  - `0x004e7cd4` COREDLL ord 66
  - `0x004e7ce4` COREDLL ord 1118
- The function's address `0x004e7b8c` appears once, as a pool word at `0x004dd1e4`.
  Two loads read it: `0x004dd15e` and `0x004dd16c`, both in `fn 0x004dd028`, each
  followed by `jsr` to `0x004e7b8c`.
- `fn 0x004dd028` is referenced only as a pool word at `0x004dd2e4`. No `bsr` reaches it.
  Its callees include `sub_004e787c`, `sub_004e7940`, `sub_004e7dd8`, `sub_004e7d4c`
  and COREDLL ord 496 and 65.
- `cerom.py exports` finds no `COREDLL.dll` module in this image (the module list has
  149 entries, none named coredll). The six COREDLL ordinals therefore cannot be named
  from this image.

## Result

- Function VA: `0x004e7b8c` (fn start is a heuristic, confirmed by the prologue and `rts` at `0x004e7cfa`).
- Callers: only through the function pointer in pool `0x004dd1e4`, from `fn 0x004dd028`.
  Direct `bsr` callers: none found.
- File API: not named. Ordinals 1047, 1145, 1143, 59, 66 and 1118 are unresolved.
- Buffer and arguments: not decoded yet. The function's register arguments are not traced.

## Negative and blocker

The done-when requires named file API calls. They cannot be named from this image,
because the COREDLL export table is missing. Blocker (one line): COREDLL export table
not present in the image module list, so ordinals 1047, 1145, 1143, 59, 66 and 1118 stay unnamed.

## Follow-up (suggested)

- Locate the COREDLL export table in the kernel ROM (`nk.exe` or the B/C ROM, see M1.7 and M1.2c).
- Decode arguments and the buffer in `fn 0x004e7b8c` once the ordinals are named.
- Trace `fn 0x004dd028`'s caller from pool `0x004dd2e4` (dispatch table).
