# EXP-2026-11-19-M9.37-decoder-audit: distinct-register forms and an sh4dis differential

- **Status:** done
- **Date:** 2026-11-19
- **Sample:** `archive/head256.img` (EU 2011 firmware head, SHA-256 `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`), `archive/us256.img` (US 2011 head, SHA-256 `70d945d823f93f04cae4e6c7113a723cae3a992ab7a6f9b24e94ce2e006a04da`)
- **Tools:** `python3` 3.13 (stdlib only), `tools/l3_harness/engine.py`, `tools/l3_harness/decode_audit.py`, `tools/sh4dis.py`, `tools/pdata.py`, `tools/cerom.py`. No external disassembler: `objdump` on this host has no SH target (`objdump -i` lists none), so the third opinion is unavailable and every comparison is the two in-repo tables.
- **Claims:** C-3590–C-3599
- **Supersedes:** none
- **Superseded by:** none

## Question

Does the PySh4 instruction table (form + operand registers) agree with an
independent SH-4 decode, for every distinct opcode the firmware actually
executes, and which opcodes can the engine not run at all?

## Hypothesis

Every form the engine models places its `Rn`/`Rm` in the manual-encoding
nibbles; the forms the engine rejects are only ones out of scope for a map
decoder (FPU, MMU, `trapa`, `div1`). **Falsifier:** a distinct opcode whose
engine form or operand registers differ from `tools/sh4dis.py`, or a modelled
form the executor rejects.

## Method

1. **Sample and hash.** Above. Corpus = pdata-covered halfwords only:
   `begin .. begin+length` of every record from `pdata.load_table`. Halfwords
   in a GAP between records (leaf code, no pdata record) are excluded and
   their count is printed by `census`/`compare`.
2. **Commands.**
   ```bash
   python3 tools/l3_harness/engine.py --selftest
   python3 tools/sh4dis.py --selftest
   python3 tools/l3_harness/decode_audit.py --selftest

   python3 tools/l3_harness/decode_audit.py compare archive/head256.img Navi.exe --image-start 0x200200
   python3 tools/l3_harness/decode_audit.py compare archive/head256.img nk.exe   --image-start 0x3e00200
   python3 tools/l3_harness/decode_audit.py compare archive/us256.img   Navi.exe --image-start 0x200200

   python3 tools/l3_harness/decode_audit.py census archive/head256.img Navi.exe --image-start 0x200200
   python3 tools/l3_harness/decode_audit.py census archive/head256.img nk.exe   --image-start 0x3e00200
   ```
   The **before** column is the same tool against a scratch engine:
   `python3 tools/l3_harness/decode_audit.py census archive/head256.img Navi.exe --image-start 0x200200 --engine-module /tmp/…/engine.before.py`, where `engine.before.py` is `git show 06e07e8:tools/l3_harness/engine.py` plus the new `DECODE_TABLE`/`decode_fields` block (so the *old executor* is classified by the *current* table).
3. **Controls.** Positive: `compare` on the EU corpus reports `disagreements 0` and `executor drift 0` for both modules, and the US build likewise (a decoder tuned to one build would differ). Negative: two deliberate mutants, each in a scratch engine passed through `--engine-module`:
   * **mutant (i)** restores the pre-H51 `mul.l` mask (`pattern == 0x0007`, matches only `Rm = r0`);
   * **mutant (ii)** restores `mov.b/mov.w R0,@(disp,Rn)` storing through `r0` as the base.
4. **Scope.** EU `Navi.exe` (1,092,177 pdata-covered instructions, 32,113 distinct), EU `nk.exe` (120,797 / 12,059), US `Navi.exe` (1,071,258 / 32,000). Excluded: GAP halfwords (printed), FPU (counted), MMU `ldtlb` (counted), `div1` (counted), and `objdump` (no SH target on this host).
5. **Falsifier.** One unexplained `DISAGREE` row, or one `DRIFT` row (a table form the executor rejects), among the MODELLED distinct opcodes.

### Defect found by the census

The old `_exec_misc` matched exact opcodes with `pattern = insn & 0xF0FF`,
which zeroes only bits 11–8, so `clrt`/`sett`/`clrmac`/`div0u`/`nop`/`rts`
executed even with a non-zero `n` nibble. Old engine: `_execute(0x0918)` sets
`sr = 0x1` (runs it as `sett`); new engine: `IllegalInstruction`, and
`decode_fields(0x0918)` is `unknown`. Fixed by full-word matches.

## Conclusion

The engine's form/operand table now agrees with an independent SH-4 table on
every MODELLED distinct opcode of three corpora (`0` disagreements, `0`
executor drift), and the census accounts for every other distinct opcode in a
named bucket. Against the engine at `06e07e8`, the census moves `MODELLED`
from 28,134 to 28,198 distinct (+3,471 instructions) and
`IN_SCOPE_UNMODELLED` from 2,382 to 2,318 (−3,471): mac.l/mac.w/div0s (4,223
EU Navi instructions present) become runnable, while an exact-opcode mask
defect that silently executed illegal `n != 0` encodings as `sett`/`clrt` is
fixed and 752 such instructions now fail loudly. `div1` (513) stays
`in-scope-unmodelled`. `docs/format/` is unchanged — this is an engine-honesty
result, not a format fact.

python3 tools/l3_harness/decode_audit.py compare archive/head256.img Navi.exe --image-start 0x200200

## Follow-ups

- `div1` (513 EU Navi instructions) is the only integer form still rejected;
  it needs M/DIV state, not just T. A later task (M9.48) can model it if a
  target needs it.
- MMU is effectively absent (`ldtlb` ×528, no `ldc/stc` to PTE registers in
  pdata code); no MMU work is justified by this corpus.
