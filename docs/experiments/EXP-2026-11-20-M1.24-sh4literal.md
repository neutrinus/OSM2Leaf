# EXP-2026-11-20-M1.24: `sh4literal` — one literal-pool scan, the M3.13 corpus re-run with decoded sec1/sec2

- **Status:** done
- **Date:** 2026-11-20
- **Sample:** `archive/head256.img` (IMG256, EU2011 firmware head), SHA-256
  `92aa525d0db2c167cf4288b82f9cb951865a53c3a9ab4ead84d11a6f19a007f9`
- **Tools:** Python 3.13.18; `tools/sh4literal.py` (new, this task);

## Question

Can "literal X appears in no pool" be a reproducible command, and does the
M3.13 pass-3 literal corpus (`:;:`, `01 f4 00 00`, `4e 20 00 00`,
`0x0000ff00`, `0x0000c000`, `0x0000a000`) still read the same once the
decoded `Navi.exe` sec1/sec2 (EU2011) are searched too?

## Hypothesis

The pass-3 counts were made over sec0 literal pools only. A committed scan of
every PC-relative load (`mov.l`/`mov.w`/`mova`) reproduces them, and adds a
sec1/sec2 column the pass-3 EXP lacked.

Falsifier: the tool finds a referenced pool word for `0x0000f401`,
`0x01f40000`, `0x0000204e`, `0x4e200000`, or a pool pointer to a `:;:`
occurrence (that would contradict M3.13); or it misses the known
`0x0000c000` load at `0x003f56ec` or the positive control `0x0017a1f8`
(`LCTBL001.DAT` address loaded by `fn 0x004125a8`); or `--parent-of
0x0041c7e8` does not print `0x0041c7dc`.

## Method

1. **Sample and hash.** `archive/head256.img`, SHA-256 above (the first
   128 MiB are read; `Navi.exe` sec0 is uncompressed, sec1/sec2 are decoded
   by `nk_decomp` with the build-B kernel routine and its content-addressed
   cache).
2. **Commands.**

   ```bash
   python3 tools/sh4literal.py --selftest
   python3 tools/sh4literal.py archive/head256.img Navi.exe find 0x0000f401 0x01f40000 0x0000204e 0x4e200000 0x0000ff00 0x0000c000 0x0000a000 0x000001f4 0x00004e20 0x0017a1f8
   python3 tools/sh4literal.py archive/head256.img Navi.exe find 0x0000f401 0x01f40000 0x0000204e 0x4e200000 0x0000ff00 0x0000c000 0x0000a000 0x000001f4 0x00004e20 --window 0x003f5000 0x003f7000
   python3 tools/sh4literal.py archive/head256.img Navi.exe bytes 3a3b3a
   python3 tools/sh4literal.py archive/head256.img Navi.exe bytes 3a003b003a00
   python3 tools/sh4literal.py archive/head256.img Navi.exe --range 0x00266000 0x00269000
   python3 tools/sh4literal.py archive/head256.img Navi.exe --unreferenced
   python3 tools/sh4literal.py archive/head256.img Navi.exe --parent-of 0x0041c7e8 0x00542256 0x00412bee 0x003f5fc2 0x00413af4 --parent-audit
   python3 tools/sh4literal.py archive/head256.img Navi.exe --no-decode find 0x0000a000
   ```

   Model (also in the tool docstring): every even halfword of every
   executable section is decoded as `mov.l @(disp,PC)` (`0xDndd`, 32-bit
   pool word), `mov.w @(disp,PC)` (`0x9ndd`, 16-bit half) or `mova`
   (`0xC7dd`, address only). A reference whose source halfword lies inside a
   *structural* pool word (one whose block, walking back over pool words and
   `0x0009`/`0x0000` pads, opens after the delay slot of `rts`/`rte`/`bra`/
   `braf`/`jmp`) is dropped as data, iterated to a fixed point. Negatives are
   stated over **all** remaining references (the superset); the
   `structural` flag only qualifies positives. `--parent-of` walks back from
   the VA to the first boundary (a read pool block, an `rts`+delay, or a push
   run after a pad) and accepts the instruction after it when it is a push
   (`mov.l Rm,@-r15`/`sts.l pr`), a called entry (bsr target, a pool value
   or data word pointing into code), or the first push run before the VA
   after an `rts`; otherwise it keeps walking. It never reads `.pdata`;
   `.pdata` is printed beside it as the check (`AGREE`/`DIFFER`).
3. **Controls.** Positive: `0x0017a1f8` (`LCTBL001.DAT`, known load from
   `fn 0x004125a8`, M3.12/M3.21 lineage) must be referenced; `0x0000c000`
   at pool `0x003f57a4` (pass-3 row C-973) must be found. Negative:
   `--no-decode` must print `NOT SEARCHED (section 1,2)` and drop the
   decoded column instead of reporting it as absent; synthetic `--selftest`
   cases: a false pool word (aligned, equal value, nobody reads it), a pool
   word whose low half decodes as `mov.l` (must not count as a reference),
   pool-in-data (value only in a data section), an early `rts` inside a
   function (must not become a start).
4. **Scope.** `Navi.exe` EU2011: sec0 `0x00011000` exec 5,553,430 B
   (uncompressed); sec1 `0x0055d000` 98,330 B INIT (decoded; vsize
   `0xff16ae`, the rest is BSS = zero, not stored); sec2 `0x0154f000`
   60,768 B INIT (decoded). 3 sections / 5,712,528 B. Not covered: other
   modules, the US2011 build, constants synthesised by `mov #imm`/`shll8`
   (pass-3 C-973's `0xe000` mask is built that way, `0x003f56e2`), and
   UTF-16 strings other than the `:;:` form listed.
5. **Falsifier.** As stated under Hypothesis, before the result.

## Interpretation

- **FACT:** M3.13 pass-3's literal rows reproduce: in sec0 no pool holds
  `0x0000f401`/`0x01f40000` (trailer, C-977) or `0x0000204e`/`0x4e200000`
  (index magic, C-970); `0x0000ff00` has 0 pool loads in the family window
  (C-974); `0x0000c000` has exactly 1 load in the window (`0x003f56ec`,
  C-973 tag class); no pool, `mova` or data word points at any `:;:`
  occurrence (C-975).
- **OBSERVED (new column):** decoded sec1/sec2 do not change any "never
  read" verdict: the trailer and index-magic words occur 0 times there
  either; `:;:` has a fifth occurrence in sec1 (`0x005621d5`) with no
  pointer to it. `0x0000a000` and `0x000001f4` occur as sec1 data words with
  no pool pointer.
- **OBSERVED:** the whole-module counts for `0x0000ff00` (42 refs) and
  `0x0000c000` (82 refs) are much larger than the window counts; pass-3's
  "0" and "1" are window-scoped, not module-wide.
- **OBSERVED:** `0x4e20` is loaded as a 16-bit `mov.w` literal 36 times in
  sec0, 2 in the window (`0x003f51c2`, the POINT walker constant, M1.14;
  `0x003f5bcc`). The pass-3 C-970 search tested only the 32-bit LE/BE forms
  of `4e 20 00 00`; a 16-bit read of `4e 20` after the read API's swap
  (C-5814/C-5815) would be a `mov.w 0x4e20`.
- **HYPOTHESIS:** the `0x003f5bcc` load is worth one look by the ADDRE reader
  task as a 16-bit index-magic candidate; nothing here shows it reads ADDRE.
- **UNKNOWN:** the 89 audit differences (1.17 %) are mostly leaf thunks
  reached only through tables the walker does not decode and functions after
  inline data; `--parent-of` prints `DIFFER` for them rather than hiding it.

## Conclusion

`tools/sh4literal.py` turns "literal X appears in no pool" into a command
with a positive control, a named NOT SEARCHED gap and a decoded sec1/sec2
column. The M3.13 corpus reproduces (0/0/0/0 for trailer and index magic,
0 `ff00` and 1 `c000` load in the window, `:;:` unreferenced); decoded
sec1/sec2 add no reference. `--unreferenced` counts 13,015 unread pool
words in `Navi.exe` sec0. `--parent-of 0x0041c7e8` prints `0x0041c7dc` and
`0x00542256` prints `0x00542250` from pool/boundary operand data, which is
the re-check H63's `Pin:` line names; the walker agrees with `.pdata` on
98.83 % of 7,596 functions. Claims C-5980–C-5986.
