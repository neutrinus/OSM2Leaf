- **Status:** done (first census; names, counts and code sizes only)
- **Date:** 2026-11-20
- **Sample:** first 256 MiB of each image from `files.viaaq.eu/sd-images/`:
  `IMG256` `92aa525d…07f9`, `US256` `70d945d8…04da`, EU 2014 head

- **Supersedes:** none
- **Superseded by:** none

## Question

Marek: the later EU cards carry newer binaries (e.g. Polish speech). What
differs between the builds, and could a newer binary be moved to an older
card?

## Method

```bash
for k in EU2011 EU2014 EU2016; do python3 tools/fetch_image.py --image $k --part 256M -o $S/$k.256; done
python3 tools/fetch_image.py --image US256 -o $S/us256.img
# for each image: every `ECEC` at a 0x200-aligned segment base + 0x40,
# cerom.CERom(d, seg).modules(); per module: name, bytes and SHA-1 of the
# uncompressed code sections (flags & 0x20, not 0x2000)
```

The script was a scratch one-off (`modcmp.py`, 30 lines over `tools/cerom.py`);
M1.36b turns it into a committed tool. The SHA-1 is over **unmasked** XIP
code, so "changed" below also counts modules that only moved in memory.

## Interpretation

- **VERIFIED (C-6280):** all four cards have the same container layout and are
  SH-4 CE ROMs readable by `tools/cerom.py`; a cross-year binary atlas needs no
  new parser.
- **VERIFIED (C-6281):** EU 2011 and US 2011 share kernel builds B and C byte
  for byte; they differ only in the application ROM A. So a 2011 EU card in
  the 2011 US unit brings the same kernel and drivers the unit already runs —
  the market difference is confined to A (radio: `RDSCC` vs `RBDS_CC` + XM).
- **OBSERVED (C-6282):** 2014/2016 are a different platform revision
  (`X212` vs `X210`): the kernel ROMs differ and gain a second flash manager
  and two `fmmdrv` variants, i.e. they expect (also) different flash hardware.
- **HYPOTHESIS (C-6283):** a whole 2014/2016 ROM set will not simply run on a
  2011 unit (kernel/BSP drivers); whether its two `fmmdrv` variants include
  the 2011 flash is the first thing to check. Moving single application
  modules (e.g. `Speech.exe` + `SPEECH/PL`) from 2014 A into a 2011 A is a
  ROM rebuild (imports by ordinal against that build's DLLs, fixed XIP
  addresses), not a file copy.
- **OBSERVED (C-6284):** `Audio.exe` grew 54 % and `Navi.exe` 4 % from 2011 to
  2014; `BT_FW.dll` kept its size, `BT_MGR`/`BT_ENG` changed by < 1 %. What
  changed is not known until a function-level diff (M1.36b/M1.37).
- **C-6285:** nothing here says a newer `Navi.exe` routes faster; that needs
  the function diff plus an L3 timing run.
