## Question

Can `tools/tilewriter.py`, given the real EU factory tile for the cell that covers
Wrocław and the mesh-split OSM roads for that area, write a tile that (a) keeps
every byte outside the regenerated road records identical to the factory, (b)
reads back to exactly the input geometry, and (c) passes the L2 check on a card
tree?

## Hypothesis

1. The synthetic fixture (EXP-2026-11-06-M5.4-tilewriter) models the real
   container: the directory header, the parcel key and the splice rules carry over
   unchanged. **Falsifier:** the real tile has a different directory model, or a
   key that does not match `parcel_code`, or the splice changes unchanged records.
2. Reading back the new road records with `fa_encode.parse_record` reproduces the
   clipped, quantised input geometry. **Falsifier:** any input lattice point that
   the decoder does not return within 1 m.
3. L2 passes when the card tree carries the generated tile and a rebuilt DRSTR.
   **Falsifier:** `drstr_roundtrip`, `cmp_roundtrip` or `tile_roundtrip` fails, or
   a corrupted copy of the tile still passes L2 (which would make the pass
   uninformative; see Observations 7).

```bash
python3.13 - $W/ex/MAPAL001/B48R058R.DAT <<'PY'
import sys, zlib, struct, collections
sys.path.insert(0, 'tools/ze0-viewer/tools_ze0'); sys.path.insert(0, 'tools')
import clarion_tile as ct, clarion_bg, fa_encode, tilewriter as tw
t = ct.read_tile(open(sys.argv[1], 'rb').read())
lv = [l for l in [s for s in t['sections'] if s['id'] == 1][0]['levels'] if l['level'] == 1][0]
stats = collections.Counter()
for D0 in lv['dirs']:
    D = dict(D0); D['x'] = tw.dir_x0(D0)
    for i, slot in D['slots'].items():
        for rec in slot['recs']:
            if rec['k'] % 2:
                continue
            if not ct.is_zlib(rec['raw']):
                stats['raw'] += 1; continue
            try:
                plain = zlib.decompress(rec['raw'])
            except zlib.error:
                stats['zlib_err'] += 1; continue
            if struct.unpack_from('>H', plain, 4)[0] != 0x00FA:
                stats['not_road'] += 1; continue
            row, col = i, rec['k'] // 2
            w0, w1 = struct.unpack_from('>HH', plain, 0)
            lon0, lat0, _, _ = clarion_bg.parcel_geo(1, D['y'], D['x'], row, col)
            doc_a = 32768 + round(lat0 * 192); doc_b = 52736 + round(lon0 * 128)
            pc = clarion_bg.parcel_code(1, D['y'] * 32 + row, D['x'] * 32 + col)
            try:
                _, _, shapes = fa_encode.parse_record(plain, 1)
            except Exception:
                stats['parse_err'] += 1; continue
            stats['road'] += 1
            stats['key==parcel_code'] += (w0, w1) == pc
            stats['hi-byte==doc'] += (w0 >> 8, w1 >> 8) == (doc_a >> 8, doc_b >> 8)
            stats['shapes_ok'] += bool(shapes) and all(s['ok'] for s in shapes)
print(dict(stats))
PY
```

## Observations

### 1. Compile, selftests and first real-tile splice (before fixes)

```text
$ python3.13 tools/tilewriter.py --selftest             (initial, before fixes)
tilewriter selftest: OK (48/48 checks)                  (synthetic only)

$ python3.13 tools/tilewriter.py …B48R058R.DAT …         (first real run, dir x via raw word)
tilewriter: factory tile has no level-1 directory at y=76 x=940
```

The first real splice found no directories at all. The raw directory word is
`x0 − 1024` (Obs. 2). After that fix, the first splice aborted in `verify_factory`:

```text
tilewriter: check failed: section-1 record at (74, 942, 18, 27) changed but was not regenerated
diff keys outside regenerated set: 21435 [(72, 938, 15, 0), …]
```

Byte-diff of the factory and the output shows the splice rewrote bytes at
`0x14c00` onward, inside other directories' blocks. Slot 23 of dir (76,941) has
tag `0x0bf4`, which the reader maps to block `0x14c00` (63 records, whose byte
range overlaps slots of other directories). Its block "fitted", so the writer
rewrote it in place. The same directory's slot 22 has tag `0x1a6` with no records;
after the new road pair was written, the reader produced a record at pair 3
(`(76,941,22,3)` changed). Our reading, not verified: the reader stops at the first
oversized body entry, and the new pair changed what it reads next (HYPOTHESIS).
Both directories are kind `0x2146`, not `0x2046` (Obs. 4).

Fixes made in `tools/tilewriter.py` (each is covered by a selftest or a control):

- **Fix 1, directory x word.** `x_field` / `dir_x0` (Obs. 2). Pinned by a selftest.
- **Fix 2, shared blocks.** `shared_slot_blocks(tile)` returns the block offsets
  whose byte range overlaps another slot's. A shared block is never rewritten in
  place; the slot's block is appended and its tag repointed. Pinned by a selftest.
- **Fix 3, modelled kinds.** `MODELLED_DIR_KINDS = {0x2046}`; a parcel in any other
  kind is refused with exit 2. Control: the kind-0x2146 refusal (Obs. 8).
- **Fix 4, section 4 in factory mode.** `check_section4(strict=False)` counts the
  44 empty payloads instead of aborting; section 4 stays byte-identical to the
  factory by `sector_fingerprint`. Pinned by the `section 4 preserve` selftest
  (`unparsed=0` on the synthetic fixture).

### 2. Directory header x word (Fix 1)

`x_field(x0) = (x0 − 1024) & 0xFFFF`; `dir_x0(D) = (D.x + 1024) & 0xFFFF`.
Level-1 directory words 65448…65455 = meshes 936…943 (cell `B48R058R`, `R = 0x58`,
`lon_max = 108 − 88 = 20`, columns `x0 = 1024 − R + k`). Level 2 (4-mesh
directories): words 65448, 65452 → 936, 940.

```text
section 1 level 2 dirs 4 y [72, 76] .. [76] x-word [65448, 65452] .. [65452] x0 [936] …
section 1 level 1 dirs 64 y [72, 73, 74] .. [79] x-word [65448, 65449, 65450] .. [65455] x0 [936] …
```

Selftest pins it: `directory x word is x0 - 1024 OK`.

## Interpretation

- **FACT:** the EU 2011 tile `B48R058R` has 64 level-1 directories whose header `x`
  is `x0 − 1024` mod 2¹⁶; kind `0x2046` is the only kind whose slots all read as
  clean blocks (960 / 960).
- **FACT:** the tool now splices 18 parcels of real OSM roads into that tile; the
  section-2, section-4, header and table bytes are identical to the factory, and
  the 50,470 quantised input points decode back exactly.
- **FACT:** L2 (`--no-golden`) passes on the card tree with the generated tile and
  a DRSTR rebuilt from the tree. This pass is structural: `tile_roundtrip` is
  byte-level and cannot see a flipped byte in a record, and it misses tail
  truncation if DRSTR is rebuilt. The content evidence is the geometry read-back
  and `harness.py verify` (bad 84 → 85 on a flipped record).

  models in kinds other than `0x2046` (575 of 1,023 non-`0x2046` slots are unclean).
  The writer refuses those kinds, so the Wrocław box is limited to mesh (76,940).
- **HYPOTHESIS:** directory kinds `0x2146` and the others carry a different slot

- **UNKNOWN:** whether the unit reads the generated records (rule 13); the country
