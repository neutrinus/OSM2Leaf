## Question

Can the rows left open by M1.39 — I2C slave addresses, GPIO pin roles, baud
rates, and users of `SCI0:`/`UAT4:` — be recovered from static firmware
evidence in build B/A?

## Hypothesis

Some I2C/GPIO client IOCTL codes and serial baud literals are recoverable as
immediates or literal-pool constants; concrete I2C slave addresses, GPIO bit
roles, and DCB framing may remain runtime-configured. Falsifier: if no I2C or
GPIO client IOCTL/literal evidence is found in uncompressed build-B driver
sections, the static map claim is wrong.

## Method

1. **Sample and hash.** `archive/head256.img` pinned head (symlinked in
   worktree). All commands use build B `--image-start 0x3e00200`.
2. **Commands.**

```bash
python3 tools/cerom.py --image-start 0x3e00200 archive/head256.img exports I2C.dll
python3 tools/cerom.py --image-start 0x3e00200 archive/head256.img exports GPIO.dll
python3 tools/sh4dis.py archive/head256.img GPIO.dll --image-start 0x3e00200 --va 0x03a32718 --count 40
python3 tools/sh4xref.py archive/head256.img GPIO.dll --image-start 0x3e00200 --to 0x800920b4
python3 tools/sh4xref.py archive/head256.img fmmdrv.dll --image-start 0x3e00200 --to 0x80052000
python3 tools/sh4xref.py archive/head256.img fmmdrv.dll --image-start 0x3e00200 --to 0x80052004
python3 tools/sh4xref.py archive/head256.img fmmdrv.dll --image-start 0x3e00200 --to 0x80052008
python3 tools/sh4xref.py archive/head256.img PowerMonitor.dll --image-start 0x3e00200 --to 0x8005200c
python3 tools/sh4dis.py archive/head256.img serial_scif.dll --image-start 0x3e00200 --va 0x03985c30 --count 40
python3 tools/sh4xref.py archive/head256.img I2C.dll --image-start 0x3e00200 --to 0x80052000
python3 tools/claims_check.py
python3 tools/todo_check.py
```

3. **Controls.** Positive: `GPIO.dll` `fn 0x03a32718` disassembles to IOCTL
   comparisons for `0x800920b4/b8/bc`; `sh4xref` finds literal-pool loads for
   each I2C/GPIO IOCTL. Negative: I2C slave address/bus index not found as
   immediate constants in scanned exec/literal-pool sites; `SCI0:`/`UAT4:` have
   no active open/use evidence beyond AppLaunch string presence.
4. **Scope.** Static, build B (+ selected A clients named in claims), EU2011
   head. Covered: uncompressed exec sections reachable by `cerom`/`sh4dis`/
   `sh4xref`. Not covered: compressed `.data` where runtime-configured GPIO
   masks or DCB values may live; no board, no L3/L4/L5. Counts are per-command
   evidence, not exhaustive image-wide proof except where explicitly stated.
5. **Falsifier.** If `GPIO.dll` did not validate `0x800920b4/b8/bc`, or I2C
   client literal pools did not load `0x8005200x`, the cited static map rows
   would be retracted.

## Observations

- `I2C.dll` exports include `I2C_IOControl` (rva `0x1e88`).
- `GPIO.dll` exports include `GPI_IOControl` (rva `0x2450`); `fn 0x03a32718`
  compares `r5` to `0x800920b4`, `0x800920b8`, `0x800920bc` and checks lengths
  8/8/4.
- `sh4xref GPIO.dll --to 0x800920b4` shows pool loads at `0x03a3271e`,
  `0x03a327a0`, `0x03a34890`.
- `fmmdrv.dll` literal pools load `0x80052000` (`fn 0x03a45434`),
  `0x80052004` (`fn 0x03a453c8`), `0x80052008` (`fn 0x03a454a8`).
- `PowerMonitor.dll` loads `0x8005200c` (`fn 0x039d6630`).
- `I2C.dll` loads `0x80052000` at `fn 0x03a2203c` (driver-side validation).
- `serial_scif.dll` `fn 0x03985c30` dispatches serial IOCTLs including
  `0x001b0004` (SET_BAUD_RATE).
- `SCI0:`/`UAT4:` UTF-16LE strings are present in `AppLaunch.dll` .text; no
  active open/use evidence recovered.

## Interpretation

- **FACT:** GPIO IOCTL codes `0x800920b4/b8/bc` are validated in `GPIO.dll`.
- **FACT:** I2C-related 0x8005200x literal-pool loads exist in `fmmdrv.dll`,
  `PowerMonitor.dll`, and `I2C.dll`.
- **OBSERVED:** Baud-rate literals exist for required ports; selected runtime
  DCB values are not fully proven statically.
- **HYPOTHESIS:** I2C 0x8005200x codes are bus/operation selectors; slave
  addresses/chip identities are not assigned from static evidence.
- **UNKNOWN:** Concrete GPIO bit roles/masks, I2C slave addresses, DCB
  framing, and active `SCI0:`/`UAT4:` users.

## Conclusion

M1.40 documents static I2C/GPIO/baud/SCI0/UAT4 evidence in
`docs/hardware/head-unit.md` and C-6420–C-6429. Rows that cannot be closed
without runtime/board evidence are marked as static limits, not guessed.
