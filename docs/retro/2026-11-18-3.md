## Judge (a): the map moved one rung; the process cost is the collisions

Cycle 14 closed **eight** tasks, the most in one cycle for weeks, and it did it
**without a single record-repair task**: rule 17 held (4 map + 1 H in batch 1,
3 map + 1 H in batch 2). The map moved: **P0** was already real (M5.34); this
cycle added the **level-2 splice** (M5.44), **tile-writer idempotence**
(M5.45), the **P1 containment census** (M5.46: one contained tile,
`B48R058R`), the **117-function map-file layer** (M3.26), a **wrong-build L3
verdict** (M9.42), a **reproducible mutant corpus** (M9.43), and the
`--check-version` verdict code (M5.43). None of the four rule-17 numbers moved
(readers 6/30, L3 1/30): the cycle deepened the card path and the firmware
map, it did not add reader rows.

**Pairing paid again, hard.** Every task was a pair and the navigators caught
**~27 defects across 9 tasks** (2–3 rounds each). The classes that recur:
- **the task text itself is wrong** — M5.46's `Hints` had containment inverted
  (the `Done when` contradicted the `Hints`); M5.43's premise said "traceback"
  where the tool printed a clean `exit 1`; M9.42's `Falsifier` required a
  negative control that the mutant page cannot be.
- **a number typed under the wrong runtime** — M9.43 pinned a zlib-ng hash
  under a `python3.13` header; M5.45's Method used an even-id subset that did
  not produce the headline size.
- **a gate that cannot fail** — M5.44's `prove_tile_change` filtered by level,
  so a level-1 change could pass a level-2 splice; M5.46's buffer half was
  untested; M5.45's mutant needed an append-always control, not a `KeyError`.
- **a mechanism asserted from one control** — M5.45's C-4463 said "shared
  key", the bytes say **physical aliasing** of the level-2 container at
  `[5120,21644)`.

That is the pairing rule earning its cost. No solo task was in this cycle.

**Two honest failures of my own (TL).**
1. **Ghost claims.** I squash-merged `task/m5.46` and `task/m9.43` from a tip
   that still read `in progress` (the driver's closing commit came after the
   PR was read). The branch is gone, the work is on `main`, and the board
   said someone owns it. Fixed in this SM pass (both `done` + `Result`), but
   the cause is a **merge procedure**, not an agent: a squash merge must land
   the final `done` commit, and `todo_check` cannot see a merged-but-not-done
   block. This is action 1.
2. **Role separation collapsed.** The subagent router failed this cycle
   (upstream protocol error, 4 rotations), so one agent played SM, SE, PO, QA
   and TL in sequence. The outputs exist and the gates are green, but the
   four-eyes property the role split exists for was lost for this pass. The
   retro is therefore written by the same agent that ran the TL: treat the
   review of cycle 14 as *self*-review, and let the next pass re-read the two
   record-heavy merges (M3.26, M5.45) first. Flagged, not hidden.

**Claim-block collisions are now the top process defect.** Three pairs in one
cycle took the same "next free block" and each needed a renumber commit, a
rebase and a second review round. The cause is structural: five agents start
from the same `TODO.md`, each takes `highest + 10`, and nothing reserves it.
PR #229's ID-allocation reservation addresses exactly this; it should merge.

## Prompt changes (before → after, with reason)

1. **`prompt_sm.txt`** — *Before:* `ghost claims: tasks in progress with no
   owner branch, no PR and no work log for >24h`. *After:* adds `… or whose
   branch is already merged on main (the squash-merge leak: the work landed,
   the status line did not)`. *Reason:* both ghosts this cycle had their
   branch *merged*, so the old definition (no branch, no PR) said zero while
   the board had two. The check that would have caught it is
   `git branch -r --merged origin/main | grep <owner>`.

No other prompt edit this pass. PR #229 already proposes the `prompt_tl.txt`
changes (15-session batch, capacity rule, stale-unblock sweep); they are
consistent with this cycle's evidence (9 tasks ran fine as two batches of
5 and 4 with pairs, so 15 sessions is a ceiling, not a target) and should be
merged as one process commit, not re-litigated.
