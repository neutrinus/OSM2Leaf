## Judge (a): did pairing pay off? Yes, but the *gate inside the pair* failed

Cycle 8 ran the most pairs yet and the navigators found real defects in every
one of them: M1.26's first draft was a **classifier false-positive storm**
(137 "INSIDE" → 21 genuine, by construction), M1.26's second round caught a
hand-typed count ("61 citations over 35 blocks" — 35 is the line count, the
cites come from 18 blocks), H74's path rule flagged 59 legitimate vendor-image
rows until it learned rule 11's classes, M1.31's denominator question
(598 vs 579) was settled by a counted command, and H76's relaxed assertion was
proved non-vacuous by a deleted-row mutation. **Pairing is not the cost centre
it looks like.**

The failure of the cycle is the other direction: **the one defect that reached
`main` came through a pair whose two gates could not see it.** H74's TODO edit
moved 51 l3 lines, so `fn_audit_l3_image` went from OK to `CORPUS DRIFT` and
the full suite to `passed=89 failed=1`. The driver reported `89/0/24` and the
navigator "approved"; both worked in fresh worktrees **without**
`archive/head256.img`, where that suite is `skip_unless` — it *skipped*, so
both saw green. Only the TL, in the main checkout that has the image, saw red.
This is a structural hole, not carelessness:

1. `skip_unless` turns a missing input into a pass on the reviewer's screen.
   A reviewer who cannot run the test must say **"SKIPPED — cannot verify"**,
   never "passes"; otherwise the suite's name overstates what was run.
2. The worktree setup for a navigator must symlink (or fetch) the image when
   the task touches a suite that needs it. The TL prompt already says the
   main session is the one with images; the navigator prompt does not.

Solo runs: H75 and H71 both produced self-inflicted defects that a navigator
would have caught *before push* — H75's first claim commit ran `sed` over 14
identical status lines and wiped 13 Owners (amended before push), H71's first
EXP put a literal `fn 0x…` in a fence and made the record itself a live l3
citation (caught by the full suite, fixed in a follow-up commit). Neither
escaped, both cost a round. The retro-4 verdict — pair by default, solo only
for a fully `--selftest`-covered byte/exit check — held; the edits that broke
were **in the record**, which is exactly the `Pair: solo` exception the
prompts now narrow.

## Judge (b): the fences, the counts, and the line numbers (three lessons)

- **Fenced commands are not exempt from the scanner.** H71's probe line lived
  in a fence — the documented place for a runnable command — and `fn_audit`
  read it as prose. New task **H77** (pair) makes the scanners fence-aware; the
  workaround (`$VA` placeholder) is recorded in H71's log until it lands.
- **Numbers move under the branch.** H72 typed `moved 124→125` (retro-4),
  M1.26 typed `35 blocks` where the count is 18 blocks / 35 lines, H71's
  `CORPUS STALE … 0 moved` was stale by 125 lines. The TL's review step (b)
  caught M1.26; the SM's own number rule (retro-8) is not enough because it
  applies to the *log*, not to the *claim*. Moved to `prompt_common.txt` so it
  binds every role and every task, not only TL review.
- **Line numbers in a task block are a crossing guard that rots.** H71's
  `sed -n '2802,2807p'` precheck pointed at the wrong rows within one cycle
  (rows now at 2824–2828). A Done-when that selects by *line range* must select
  by *claim/task ID* instead. Edited H71's Done-when on the branch; recorded
  here as a rule.
- **The trap catches the person documenting the trap.** While writing the H77
  block — whose whole subject is "a literal citation in prose becomes a live
  l3 citation" — the SM put `fn 0x0041c7e8` and `fn 0x0041c7dc` in the block's
  Goal/Scope/Precheck. The l3 gate immediately read them as open-block
  citations: `CORPUS STALE: L3 OVERLAY: 2 new / 0 gone` (exit 1) on a tree
  that had printed `0 new` minutes earlier. Caught by re-running the gate
  before commit and fixed with `<VA>`/`<start>` placeholders (`0 new / 0 gone /
  58 moved`, exit 0). This is not a hypothetical: the workaround must be in
  H77's own acceptance, and a driver writing about a VA must never paste the
  VA.
