## Judge (a): did pairing pay off? Yes — it caught two defects that would have shipped

Every pair found something a solo run had already missed, and two were not
cosmetic:

- **H85 (the standing gate)**: the navigator found that the new CI step read
  `tee`'s exit code (`rc=$?` after `… | tee gate.txt`), so a **failing gate
  would have exited 0 and passed CI**. That is the exact recurrence of the
  cycle-8 escape — a gate the whole cycle was built to make loud — and it was
  caught before merge. It also found the `SKIP_MARKERS` list forgiving the
  phrase `cannot verify`, which would have turned a real verification error
  into a `SKIP`; the markers were narrowed and a stub now pins it.
- **M1.22b (the EU→US census)**: the navigator refused to review uncommitted
  work (no SHA to bind an approve to), then independently re-disassembled all
  seven readers instead of trusting the matcher's own helper, and then in
  rounds 2–4 caught three typed-number classes: a census script that did not
  mirror `Matcher.verdict` (`3369/1319/303` vs the real `3214/1259/518`, and
  `38 %` vs `31.5 %`), a stale fixture hash, and "resolved-call count 8 vs 7"
  that was really the call-**sequence** length (both sides have 11 leaf call
  sites, 9 distinct callees).
- **H78**: round 3 caught a `Result:` that said "24 checks" when the tool
  printed 25 (a one-line number, but exactly the class the prompts ban).

**Solo runs in this cycle were clean**, and that is a change from retro-5: H79
(a scratch `/tmp` path made a fixed head re-creatable), H80 (a Precheck that
selected claim rows by a line range that no longer held them), H81 (five
"superseded" blocks still counted as work). H79 and H81 nevertheless each hit a
self-inflicted trap that the *task's own* Done-when caught before push: H79's
correction prose quoted the very `/tmp` path it was removing (the task's own
`grep` then stopped printing 0 — the H71 trap), and H81's block said a `grep`
"prints 11" when it prints 10. Both are recorded in the EXP as facts, not
hidden. The `Pair: solo` exception (fully runnable Done-when) held *because the
Done-when was the real oracle*; the lesson is that the Done-when must be the
thing that fails, which both were.

## Judge (b): the standing gate is the structural fix, and it is now on `main`

Cycle 8's retro named the hole (a `skip_unless` suite passing on a reviewer's
screen). Cycle 9 closed it with **H85**: `tools/gate.py` runs the four commands
under one policy and prints `PASS / FAIL / SKIP (reason)`, exiting 0 only when
every *runnable* gate passed. The CI step's `PIPESTATUS` fix is what makes it
mean something. The pre-existing gates agree with it on `main`:
`gate: 4 pass, 0 fail, 0 skip`, `selftest.py passed=91 skipped=23`,
`claims_check --strict` 0 with `--count-check` `0` mismatches, `todo_check`
OK (`--strict` 66 errors), `fn_audit` `0 new / 0 gone`.

Three smaller process lessons this cycle:

1. **A Done-when that a later edit can break is not a Done-when.** H79's own
   record re-cited the path it removed; the fix was to name the scratch *dir*,
   not the file, so the record cannot re-create the citation. H80 is the same
   rot one level up (a Precheck that names a line range). Both argue for the
   shared rule: **select by ID or by a property that survives edits, never by
   an offset**.
2. **A number in a record must be the one the tool printed *at that revision*.**
   M1.22b burned three navigator rounds on numbers that were plausible but
   measured with the wrong script (or quoted the 13-row share as the module
   share). The TL log now says at which revision a moving count was measured.
3. **The QA log `N` collision is real.** `2026-11-16-2331-2-qa.log` (committed
   as `0d53dea`) reuses `2`; the free `N` is `max+1`. `prompt_common.txt`
   already says so; the QA subagent ignored it. Same class as `0013-3-tl` vs
   `0334-3-se`. The fix is in the launch prompt ("N = max+1, and check the
   folder"), not the rule.

## Prompt edits (two, recorded)

**1. `prompt_common.txt`, the "select by a stable key" rule (new bullet under
"Editing TODO.md").** *Before:* nothing — the line-range trap was learned three
times (H71's Done-when, H79's self-citation, H80's Precheck). *After:* one
sentence under the concurrent-edit bullet: any command in a Done-when, Precheck
or evidence cell selects rows by claim ID (or by a property that survives row

it selects, the record must say at which revision it was measured. *Reason:*
three separate tasks spent a round on the same rot; a shared rule binds all
roles at once.

rounds." *After:* same limit, plus "when a round only fixes a typed number,
stop the round loop and run the record's numbers against the commands yourself

*Reason:* M1.22b's three number-only rounds would have been one audit; the
navigator is the right reviewer for *defects*, the TL for *arithmetic*.

Neither edit changes a role's scope; both are one sentence. The rest of the
prompts are unchanged.
