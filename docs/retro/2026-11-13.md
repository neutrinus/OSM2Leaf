## Where we got stuck / went in circles

1. **The 2026-11-12 “batch” is a ghost claim, 19 tasks wide.** Commit `0781945` sets 19 tasks to
   `Status: in progress · Owner: tasks/batch-2026-11-12` in one commit, under a branch that never
   got a PR (there is no PR for `tasks/batch-2026-11-12`; `gh pr list --head` is empty) and no work
   log. Six days later the same owner’s integration commit (`777fb68`) touches only **3** of the
   named tasks: M1.20 (`pdata.py` + EXP), M1.22 (`fn_match.py`, **no EXP**) and M3.13 (format docs
   + EXP that itself says “done (partial … done-when not met)”). M1.19, M1.21, M3.2b, M9.36,
   M9.37, M9.38 and the rest have no work on screen but are still claimed, so every other agent
   must treat them as taken. This is the exact failure mode retro `2026-11-09-2` named (“claim
   object no longer matches reality”), scaled up from 7 one-task PRs to 19 tasks in one invisible
   branch.
2. **Bulk claims defeat the claim mechanism.** The rule says “first commit claims *one* task, pushed
   at once, plus a draft PR”. A single commit that claims 19 tasks is unreviewable and cannot be
   released task-by-task; a TL cannot tell which of the 19 are live. The board now has 20
   `in progress` blocks but only one PR (#171, unrelated).
3. **TODO grew 10% in one pass.** H51 added ~240 lines and no archive followed (PO had no run since
   2026-11-09). Cheap-model developers read the top first; the board is drifting away from the
   1500-line target while the number of `in progress` blocks makes it look busy.
4. **Two high-impact runs left no log.** H51 (2026-11-11) and the 2026-11-12 batch commit have no
   `dev_process/` log, which is why this retro had to reconstruct the batch from `git show` instead
   of reading its decisions. The rule already requires a log for every run; it is not enforced.
5. **M1.22 landed halfway and its task line still says “in progress”.** `fn_match.py` exists with a
   selftest, but there is no EXP (the done-when requires a census EXP and ≥90% unique match), no
   `build` field in `targets.json`, and no US re-run. Under prompt SE this is a `blocked` or an
   open task, not a silent half-done.
6. **Workspace hygiene is eroding.** 30+ stale worktrees under `.claude/worktrees` and 5 branches
   ahead of `main` from 2026-11-08/09. None blocks work, but `git worktree list`/`git branch -r`
   are now noise for every agent that checks them.

## Prompt changes (recorded; no silent edits)

### 1) `prompt_common.txt` — forbid shared batch claims

**Before:** the hard-rules block ended at “When your task's commits are on `origin/main` … close
its draft PR and delete the remote branch. Do not open a second PR for the same task ID …”

**After:** added the bullet:

```text
- One task = one owner branch + one draft PR. Never set several tasks
  `in progress` under one shared batch branch: a claim with no PR and no work
  log is invisible and unreviewable (retro 2026-11-13).
```

**Reason:** the 2026-11-12 batch claimed 19 tasks on one PR-less branch, making all 19 invisible
and blocking pickups for six days. This is the only observed process failure large enough to
change shared text.

### 2) `prompt_tl.txt` — claim only what you launch

**Before:** “Launch the subagent(s) for each task, each task in its own git worktree / branch. Tell
every subagent …”

**After:** “Launch the subagent(s) for each task, each task in its own git worktree / branch.
Claim only tasks you launch in this run (rule 3 of TODO.md); a shared batch branch with several
`in progress` lines, or a claim for a task nobody is working on, is a ghost claim (retro
2026-11-13). Tell every subagent …”

**Reason:** the TL is the role most likely to pre-claim a batch before subagents exist. One
sentence stops the pattern at the source.

### 3) `prompt_sm.txt` — ask the retro to list ghost claims explicitly

**Before:** “Write a retro to docs/retro/YYYY-MM-DD.md … Look for places where we got stuck or
where someone is going around in circles.”

**After:** same sentence plus: “Also list ghost claims: tasks `in progress` with no owner branch,
no PR and no work log for >24h — they block pickups just as much as open PRs.”

**Reason:** this retro had to discover the 19 ghost claims by hand. Making it a standing retro
output keeps the next SM cheap and gives PO/TL a cleanup list.

No change to `prompt_po.txt`, `prompt_qa.txt` or `prompt_se.txt`: their observed runs followed
them (PO archived and cleaned refs on 2026-11-09; QA/SE added no duplicate tasks), and their length
is already small.
