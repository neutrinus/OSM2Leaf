## Pairing: first real verdict — it paid off, keep the rule

This is the first cycle where `Pair: required` ran as **two subagents** (driver
+ separate navigator), the question retro-2 left open.

| Run | Pair tasks | Solo | Navigator catches | Review rounds | Slipped |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2026-11-10 | 4 | 2 | 2 | n/r | 0 |
| 2026-11-15 cycle 3 | **2** | 0 | **6** | 2 + 2 | **0** |

**Answer:** yes. Two pair tasks produced **6 catches — 3 per task, vs 1 per task
in the best earlier sample**. The catches are not cosmetic: M1.28's three were
(a) negative controls written as prose recipes instead of runnable commands,
(b) a one-byte-flip SHA-256 cited but not derivable from the text, (c) a
`--fixture` accepting the wrong `--module`. M1.29's three were **evidence
integrity, not code** — a misstated 13-occurrence split, a claim that "three VAs
account for all 13" when it was 11, and a `VERIFIED (tool)` row resting on a
branch measurement. Code was correct in both tasks; every catch was in the
*record*. That is exactly what a separate navigator buys and what a driver
grading its own work misses.

No change to the pair rules. One consequence: 0 solo tasks this cycle means the
solo side of the metric is stale — H54 last cycle is still the only solo
reference. Next cycle should include at least one `Pair: solo` task so the
comparison stays two-sided.

## Where it wobbled

1. **A prompt contradiction that would have mis-run a task.** M1.26 is marked
   `Pair: solo`, but its scope rewrites a gate's pass/fail semantics and writes
   the evidence file every later reader PR passes through — the class
   `prompt_tl.txt` says must be `Pair: required`. The TL log did not notice
   because M1.26 wasn't taken this cycle. **Fixed** (edit below).
2. **The board number was never reproducible.** Every prior retro quoted
   `grep -c 'Status: open'`, which also counts the rules prose; the real block
   count is 84 open / 40 done / 27 blocked. This retro switches to a block
   parser. No decision changes, but future retros should use the same method.
3. **17 blocks have no Status line** (mostly M7/M8 `A/B` shorthand and M6.10).
   `progress_report` reports two of them as errors every run. Pre-existing, not
   caused by this cycle, and correctly kept `NOT RUN` — but a board with 17
   unstatused blocks cannot be counted by `todo_check` either. That is H60/H53
   territory, not a new task.
4. **The log-role caveat from retro-3 did not recur.** Both subagent logs this
   cycle are correctly labelled (`-se`, `-po`, `-qa`), and the TL log is the
   session's own. The convention holds without an edit; drop the caveat.

## Prompt edit (one, recorded)

**File:** `prompt_tl.txt`, "Solo (exception…)" line.

**Before:** `Solo (exception…): the task says Pair: solo, or …`
**After:** `…or the task says Pair: solo; a Pair: solo that edits a gate's pass/fail semantics is run as a pair — fix the field, not the rule.`

**Reason:** makes the existing "`Pair: required` is never run solo" and "`Pair:
solo` is low-risk" clauses resolve in the safe direction when a task's *field*
disagrees with its *content*, which is exactly M1.26's case. No other edit; the
other retro-3 convention (subagent logs under the task it ran) needs no change.
