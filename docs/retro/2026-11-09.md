## Where we got stuck / went in circles

1. **Draft PRs closed without merge while work landed on `main` directly or by another path.** Many task PRs in the 24h list are `CLOSED` (not merged) but the corresponding task IDs appear as commits on `origin/main` (e.g. M3.20, M3.2b, M4.25, M4.29, M5.16, M1.14–M1.17, M2.14, M2.17, M3.17, M4.21, M8.E1, M9.25, M5.24). This breaks traceability (rules 1–6 assume the draft PR is the claim/coordination surface), leaves open drafts behind (#140 still open while M3.20 work is on main), and makes "no open PR" checks ambiguous.
2. **Duplicate draft PRs / `-r2` branches for the same task ID.** `M4.27` has #146 and #152 open; `M9.12` has #142 and #154 open; several `task/*-r2` remote branches exist alongside original open drafts. Agents retrying or restarting are creating parallel coordination objects instead of updating one.
3. **TODO.md context bloat.** 4490 lines / 147 done tasks still present. PO prompt rule 5 requires archiving done tasks completed >24h ago, but the archive has not run since 2026-11-06. Developers and agents with small context pay for this on every read.
4. **Re-open churn is correct but noisy.** M9.14/M9.17 were legitimately reopened after M9.20 merged (rule 15) and then blocked again on sec1. The process worked; the board should make the new blocker obvious so the next agent does not pick up a reopened task without first checking whether the *new* unblock (M1.2f/sec1) is satisfied.
5. **The "compression blocks code search" assumption consumed effort until PM 9th pass.** Good correction, recorded in AGENTS/claims. The remaining risk is the symmetric mistake: treating compressed `.data`/sec1 as irrelevant when M1.2f is exactly the gate for L3 module-entry runs that touch globals/import tables.

## Process observations

- **L1/L2 are strong; L3 is gated by a small set of real blockers.** The project can build/check/patch cards and reason about formats, but firmware-function runs keep hitting M1.2f (compressed sec1/data) and module-entry argument/import plumbing. The critical path in practice is: M1.2f + L3 input/import setup → reader verdicts; parallel "try the reader again" tasks produce negative EXPs with low marginal value until those gates move.
- **Negative results are being recorded (good).** Many blocked tasks carry controls and EXPs. The cost is volume in TODO/PRs; archiving and PR cleanup would preserve the evidence while reducing active noise.
- **Verification levels are used, but "done on main with closed-unmerged PR" muddies the audit trail.** The code/evidence may be fine; the coordination artifact is inconsistent.

## Prompt changes (recorded; no silent edits)

### 1) `prompt_common.txt` — PR/branch hygiene

**Before:**
```text
17: - Never commit vendor data (images, .DAT, .cmp, .ind, …) — see AGENTS.md.
18: - Never force-push `main`. Never edit a task another agent has
19:   `in progress`, except to note a dependency in your own task.
```

**After:**
```text
17: - Never commit vendor data (images, .DAT, .cmp, .ind, …) — see AGENTS.md.
18: - Never force-push `main`. Never edit a task another agent has
19:   `in progress`, except to note a dependency in your own task.
20: - When your task's commits are on `origin/main` (done or blocked), close its
21:   draft PR and delete the remote branch. Do not open a second PR for the same
22:   task ID; update the existing draft or coordinate through the TL.
```

**Reason:** 10 open draft PRs, 27 remote non-main branches, and multiple task IDs with closed-unmerged PRs but commits on main show rule 5 cleanup is not happening. Duplicate `-r2` PRs (M4.27, M9.12) create competing claims.

### 2) `prompt_po.txt` — archive is mandatory when TODO is large

**Before:**
```text
18: 5. Archive: tasks that are done, block no one, and were completed more than 24h ago (commit date on origin/main) move out of TODO.md into docs/research/todo-history-YYYY-MM-DD.md (today's date; this is the existing archive convention — do not create TODO_archive.md). Leave a one-line pointer per moved workstream if a live task references it. The goal is a short TODO.md for developers with small context; report its line count before and after.
```

**After:**
```text
18: 5. Archive (run every pass): tasks that are done, block no one, and were completed more than 24h ago (commit date on origin/main) move out of TODO.md into docs/research/todo-history-YYYY-MM-DD.md (today's date; existing convention — do not create TODO_archive.md). Leave a one-line pointer per moved workstream if a live task references it. If TODO.md exceeds 1500 lines, archive is the first action before adding tasks. Report line count before and after.
```

**Reason:** TODO.md is 4490 lines with 147 done tasks; last archive was 2026-11-06. The rule existed but was not triggered; an explicit threshold makes it actionable for agents with small context.

### 3) `prompt_tl.txt` — TL closes PR/branch state after landing

**Before:**
```text
24: Then commit and push; merge to main one PR at a time: rebase onto the fresh origin/main, re-run the checks, merge, delete the branch, close leftover drafts. Apply rule 15 (re-open tasks the merge unblocks).
```

**After:**
```text
24: Then commit and push; merge to main one PR at a time: rebase onto the fresh origin/main, re-run the checks, merge, delete the branch, close the draft PR. If work lands on main by another path, still close the task's draft PR and delete its remote branch. Apply rule 15 (re-open tasks the merge unblocks).
```

**Reason:** Several tasks landed on main while their PRs were closed-not-merged or left as stale drafts/branches. TL is the right role to normalize PR state after integration.
