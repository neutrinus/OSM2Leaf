# Sounds of the ZE0 navigation unit — offline inventory

> **Evidence status:** `OBSERVED`/`VERIFIED (tool)` for the byte/structure
> facts below (EXP-2026-11-24-M4.60). No L3/L4 run played any of this data and
> no hardware was available; whether a 2011 binary actually *decodes* the
> prompt containers is `unknown`. Vendor audio bytes are never committed.

This page answers two questions: *where does each sound's data live*, and
*can we replace it as data*. Numbers are printed by
`tools/sounds_inventory.py` (and `tools/speech_years.py`), quoted verbatim in
`docs/experiments/EXP-2026-11-24-M4.60-sounds-inventory.md`.

Per-source detail and the printed numbers that back each `replaceable` verdict
follow.

## 1. Guidance prompts — `SPEECH/<lang>/GID/*.GID`

All 9 EU2011 GID files and both US2011 GID files share the same framing
(`tools/speech_years.parse_archive`, C-6320): 16 ASCII serial digits, then
`u32 total, u32 header_size, u32 flags, u32 entry_count`, then one 24-byte
entry (`name[12] + u32 offset + u32 size + u32 size2`). Each GID has exactly
**one** self-covering entry.

`tools/sounds_inventory.py gid <file>` reports for the Spanish EU2011 file:

```
size: 9729912 serial: 0000102020100524 count: 1
entry[0]: SSP00000.GID offset=0x38 size=9729856
payload head u32[6]: 0x1d4c 0x7580 0x1a60 0x1 0xabe0 0xa
payload signatures: RIFF=0 WAVE=0 fmt =0 ADPCM=0 ima4=0
decodable: NO — no RIFF/WAVE container in the GID payload; indexed vendor
records with an unknown codec (no L3/L4 firmware run), so not decodable offline
```

The US2011 `US` GID has the same shape (`size 14068600`, serial
`0000102620100823`, payload head `0x1d4c 0x7580 0x1ce0 0x1 0xabe0 0xa`,
zero for every audio signature). The `0x1d4c` / `0xabe0` / `0xa` words recur
in both, so the inner grammar is shared, but it is **not** a standard
RIFF/WAVE stream. No sample could be decoded (duration and codec remain
unknown): that is the explicit reason the Done-when accepts in place of a
decoded sample. Recorded prompts are the realistic target for a custom voice
*if* the vendor grammar and codec are reverse-engineered later; today the
verdict is `unknown`.

## 2. TTS / SVOX voice — `SPEECH/<lang>/TTS/*.TTS`

`tools/speech_years.py describe <file>` on the Spanish EU2011 TTS prints
`size 16716232, serial 0000200020100524, header_size 248, count 9`, with
entries `TSP00100.BIN`, `TSP00200.TXT`, `TSP00300.BIN`, `TSP00400.WAV`,
`TSP01000.BIN` (6.17 MB), `TSP02000.BIN`, `TSP03000.TXT`, `TSP04000.KEY`, …
and the SVOX stamp `MAJVERS 5 / MINVERS 0 / SOFTWID 41003 / TAVERS 4.3.0.0-2`.

The `TSP00400.WAV` entry (offset `0x6218`, 44 bytes) is a real RIFF/WAVE
header: `524946462400000057415645666d7420...`. Decoding it with Python's
`wave` prints `channels=1 rate=22050 width=16 bits frames=0` — a 0-frame
header-only placeholder, confirming the container grammar but not a playable
prompt. It is a *positive control* for the RIFF detector, not a voice sample.
SVOX TTS data is a vendor voice: `replaceable as data: no`.

## 3. Voice recognition acoustics — `SPEECH/<lang>/VR/*.AGM`

Spanish EU2011 `VSP00000.AGM` (`size 682824`, serial `0000108020100426`,
9 entries, first entry `RSPA0001.ACM`). The entries are SVOX acoustic-model
files (`.ACM`); no RIFF/WAVE signature appears in any of the seven EU AGM
files. Acoustic models are trained vendor data: `replaceable as data: no`.

## 4. Voice choice — code + settings, no data file

`tools/sounds_inventory.py strings` on build A prints
`CApi_GetCustomVoiceNo: 10 hit(s)`, `CApi_SetCustomVoiceNo: 10 hit(s)`,
`GuidanceVoiceAtt: 20 hit(s)`, across `Audio.exe`, `SystemCC.dll`,
`AuiMonitoringCC.dll`, `UsbAudioCC.dll` and others. The language list the
choice selects among is the UTF-16LE table in `Speech.exe` sec0
(VA `0x00032354`, 10 names on EU2011, C-6325). The voice choice is a
runtime setting selecting one of the `SPEECH/` sets above, not a sound file
of its own. `replaceable as data: unknown` (depends on how the setting is
stored).

## 5–7. Beeps, mute, DSP — microcontroller-generated, no samples on the card

`BeepDrv.dll`, `DspDrv.dll` and `MuteDrv.dll` live in **build B**
(`--image-start 0x3e00200`), not build A — the task's Precheck uses the wrong
image start and raises `KeyError: 'BeepDrv.dll'`; the EXP records the
correction. `tools/cerom.py ... imports BeepDrv.dll` prints
`commondll.dll CApi_GetSoundEffect slot=0x03b73054` (plus
`CApi_GetModelBaseType`, `ErrorLogMsg`), and its exports are the `BEP_*`
device-driver entry points (`BEP_Init/Open/Close/IOControl/Read/Write`,
rva `0x1a2c`–`0x22ec`). `ce_strfind` finds UTF-16 `CEN1:` and `BEP1:` device
paths in `commondll.dll` and a `BeepDrv : Mode synchronous…` error string in
`BeepDrv.dll`; the L4 log records `BeepDrv : Can't open 'CEN1:'` (C-6886).
`Audio.exe` waits 30 s for ACM module 6 from the audio microcontroller
(C-8237/C-7425). No WAV/PCM sample bytes for beeps exist on the card (the
`speech` inventory finds audio signatures only in `.TTS`); the tone is
produced on request by the audio microcontroller through
`CApi_GetSoundEffect`. **This closes the "beeps are stored samples" branch:**
beeps/chimes are generated by the audio microcontroller, so there is no
sample data to replace. `MuteDrv`/`DspDrv` are control/processing drivers
with no sound payload. `replaceable as data: no` for all three.

## 8. PCM output path — ROM code and WAV scaffolding

`tools/sounds_inventory.py romscan archive/head256.img --image-start 0x200200`
counts audio byte signatures in the uncompressed executable sections of ROM A
(`282 sections, 23,559,542 bytes` scanned):

```
TOTAL ADPCM=0 RIFF=6 WAVE=13 fmt =6 ima4=0
```

The 6 `RIFF` occurrences are **not** distinct assets: they are 6 code/data
templates in `waveapi.dll` sec0/sec3 and `Speech.exe` sec0 (the `Speech.exe`
ones are the adjacent magnitude strings `RIFF`, `WAVE`, `fmt `, `data`,
`.snd`, `AU`, `TTS ` — a container-name list around `*** GetSamples: too
many…`, not embedded WAV files). `waveapi.dll` sec3 holds one formatted
44-byte WAVE header template
(`RIFFx\x01\x00\x00WAVEfmt ... 01 00 01 00 11 2b 00 00 ... 01 00 08 00` —
11,025 Hz, mono, 8-bit). None of the hits are in `BeepDrv`/`DspDrv`/`MuteDrv`
(those are build B) and none are playable prompt samples. `replaceable as
data: no` (ROM code, not card data).

## How to reproduce

```bash
python3 tools/sounds_inventory.py speech <EU2011>/SPEECH <US2011>/SPEECH
python3 tools/sounds_inventory.py gid <EU2011>/SPEECH/SP/GID/SSP00000.GID
python3 tools/sounds_inventory.py romscan archive/head256.img --image-start 0x200200
python3 tools/sounds_inventory.py modules archive/head256.img --image-start 0x3e00200
python3 tools/sounds_inventory.py strings archive/head256.img --image-start 0x3e00200 'CEN1:' 'SCI1:'
python3 tools/sounds_inventory.py --selftest
```
